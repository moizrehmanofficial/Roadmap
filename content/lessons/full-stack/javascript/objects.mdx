<BigIdea>
<Tr>
<En>
An **object** keeps **related details together under names**. Instead of three loose variables for a user's name, email and age, you make **one** value: `{ name: "Sara", email: "sara@example.com", age: 28 }`. Each detail is a **property**: a **key** (the name) and a **value**. You read one with a dot: `user.name`. You can change, add and remove properties, put objects inside objects, and give an object functions of its own (**methods**). **Destructuring** is a shortcut for pulling properties out into variables: `const { name, age } = user;`. **Spread** (`{ ...user }`) copies an object so you can change the copy without touching the original. Nearly all real data in JavaScript, including everything an API sends you and every set of props in React, is objects and arrays of objects.
</En>
<Ur>
**Object** **aapas me juri tafseelat ko naamon ke saath ikattha** rakhta hai. User ke naam, email aur umar ke liye teen alag variables ke bajaye aap **ek** value banate hain: `{ name: "Sara", email: "sara@example.com", age: 28 }`. Har tafseel ek **property** hai: ek **key** (naam) aur ek **value**. Ise dot se parha jata hai: `user.name`. Aap properties badal, jor aur hata sakte hain, objects ke andar objects rakh sakte hain, aur object ko us ke apne functions (**methods**) de sakte hain. **Destructuring** properties ko variables me nikalne ka shortcut hai: `const { name, age } = user;`. **Spread** (`{ ...user }`) object ki copy banata hai taa ke asal ko chhere baghair copy badli ja sake. JavaScript ka taqreeban saara asli data, API se aane wali har cheez aur React ke har props samet, objects aur objects ki arrays hain.
</Ur>
</Tr>
</BigIdea>

## At a glance

<Glance>
<What>
<Tr>
<En>

Curly braces with `key: value` pairs, separated by commas:

```js
const user = {
  name: "Sara",        // key: name,  value: "Sara"
  age: 28,
  isMember: true,
};

user.name     // "Sara"
user.age      // 28
```

Read it like a form that has been filled in: **Name: Sara. Age: 28. Member: yes.**

</En>
<Ur>

Curly braces ke andar `key: value` ke jore, commas se alag:

```js
const user = {
  name: "Sara",        // key: name,  value: "Sara"
  age: 28,
  isMember: true,
};

user.name     // "Sara"
user.age      // 28
```

Ise bhare hue form ki tarah parhein: **Naam: Sara. Umar: 28. Member: haan.**

</Ur>
</Tr>
</What>
<Why>
<Tr>
<En>

- **Things in the real world have many details.** A product has a name, a price, a stock count. An object keeps them in one place.
- **One value to pass around.** A function can take one `user` instead of six separate arguments.
- **Names instead of positions.** `user.email` is clearer than `user[1]`.
- **It's the shape of all web data.** JSON from an API, rows from a database, settings files and React props are all objects.

</En>
<Ur>

- **Asli duniya ki cheezon ki kai tafseelat hoti hain.** Product ka naam, price aur stock hota hai. Object inhe ek jagah rakhta hai.
- **Idhar udhar bhejne ke liye ek value.** Function chhe alag arguments ke bajaye ek `user` le sakta hai.
- **Jagah ke bajaye naam.** `user.email` `user[1]` se zyada saaf hai.
- **Web ke saare data ki yahi shakal hai.** API ka JSON, database ki rows, settings files aur React props sab objects hain.

</Ur>
</Tr>
</Why>
<When>
<Tr>
<En>

| You have… | Use |
| --- | --- |
| **One thing** with named details (a user, a product, settings) | an **object** |
| **Many things** of the same kind, in order (all users, all products) | an **array** |
| Many things, each with details | an **array of objects** |

</En>
<Ur>

| Aap ke paas… | Lein |
| --- | --- |
| **Ek cheez** jis ki naam wali tafseelat hon (user, product, settings) | **object** |
| Ek hi qisam ki **kai cheezen**, tarteeb me (saare users, saare products) | **array** |
| Kai cheezen, har ek ki tafseelat ke saath | **objects ki array** |

</Ur>
</Tr>
</When>
<How>
<Tr>
<En>

```js
user.name                      // read
user.age = 29;                 // change
user.city = "Austin";          // add
const { name, age } = user;    // destructure into variables
const older = { ...user, age: 30 };   // copy with one change
```

</En>
<Ur>

```js
user.name                      // parhna
user.age = 29;                 // badalna
user.city = "Austin";          // jorna
const { name, age } = user;    // variables me nikalna
const older = { ...user, age: 30 };   // ek tabdeeli ke saath copy
```

</Ur>
</Tr>
</How>
</Glance>

## Picture it

<Tr>
<En>

An object is a **contact card** in your phone. One card is about one person. It has **labelled fields**: Name, Phone, Email, Birthday. You don't remember which line the phone number is on; you just look for the label "Phone". You can edit a field, add a new one ("Nickname") or delete one.

A field can hold another card: "Address" opens to show Street, City and ZIP. That's an object inside an object.

**Destructuring** is like copying two fields onto a sticky note so you don't have to open the card every time: "Name: Sara, Phone: 512-555-0147".

**Spread** is the phone's "duplicate contact" button: you get a second card with the same fields, and editing the duplicate doesn't change the first. One catch, which you'll see below: if the card has an Address sub-card, the duplicate **shares** that sub-card with the original.

</En>
<Ur>

Object aap ke phone ka **contact card** hai. Ek card ek shakhs ke baare me hota hai. Is me **label wale khaane** hain: Name, Phone, Email, Birthday. Aap ko yaad nahi rakhna parta ke phone number kaun si line par hai; aap bas "Phone" ka label dhoondte hain. Aap khaana badal sakte hain, naya jor sakte hain ("Nickname") ya hata sakte hain.

Khaane me doosra card bhi ho sakta hai: "Address" kholne par Street, City aur ZIP dikhte hain. Ye object ke andar object hai.

**Destructuring** aise hai jaise do khaane sticky note par utaar lena taa ke har dafa card na kholna pare: "Name: Sara, Phone: 512-555-0147".

**Spread** phone ka "duplicate contact" button hai: wahi khaanon wala doosra card milta hai, aur duplicate badalne se pehla nahi badalta. Ek baat ka khayal, jo neeche dekhenge: agar card me Address ka chhota card ho to duplicate wo chhota card asal ke saath **share** karta hai.

</Ur>
</Tr>

<Step title="Make an object and read from it">

<Tr>
<En>
Write `key: value` pairs inside curly braces. Read a value by writing the object's name, a dot, and the key.
</En>
<Ur>
Curly braces ke andar `key: value` ke jore likhein. Value parhne ke liye object ka naam, dot, aur key likhein.
</Ur>
</Tr>

```javascript
const user = {
  name: "Sara",
  age: 28,
  isMember: true,
};

console.log(user.name);
console.log(user.age + 1);
console.log(user);
console.log(typeof user);
```

```text output
Sara
29
{ name: 'Sara', age: 28, isMember: true }
object
```

<Happened>
<Tr>
<En>

- `user` is **one** variable holding three named details.
- `user.name` means "in the `user` object, give me what's under the label `name`".
- Each value keeps its own type: `user.age` is a number, so `+ 1` adds.
- Keys are written **without** quotes; text values are written **with** quotes.

</En>
<Ur>

- `user` **ek** variable hai jis me teen naam wali tafseelat hain.
- `user.name` ka matlab "`user` object me `name` ke label ke neeche jo hai wo do".
- Har value apni type rakhti hai: `user.age` number hai, isliye `+ 1` jorta hai.
- Keys quotes **ke baghair** likhi jati hain; text values quotes **ke saath**.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Square brackets: when the key is in a variable">

<Tr>
<En>
There's a second way to read a property: `object["key"]`. It looks clumsier, but it can do something the dot can't: use a key that is stored in a **variable**, or a key with spaces or dashes.
</En>
<Ur>
Property parhne ka doosra tareeqa bhi hai: `object["key"]`. Ye thora bhadda lagta hai, magar wo kaam kar sakta hai jo dot nahi kar sakta: aisi key istemal karna jo **variable** me rakhi ho, ya jis me spaces ya dashes hon.
</Ur>
</Tr>

```javascript
const product = {
  name: "Notebook",
  price: 5,
  "made-in": "USA",
};

console.log(product["name"]);
console.log(product["made-in"]);

const field = "price";
console.log(product[field]);
console.log(product.field);
```

```text output
Notebook
USA
5
undefined
```

<Happened>
<Tr>
<En>

- `product["name"]` is the same as `product.name`.
- `made-in` has a dash, so it needs quotes when created and brackets when read. (`product.made-in` would mean "product.made minus in".)
- `product[field]` first looks inside the variable `field`, finds `"price"`, and reads that property: `5`.
- `product.field` looks for a property literally called "field". There isn't one: `undefined`.
- Rule: use the dot normally; use brackets when the key comes from a variable.

</En>
<Ur>

- `product["name"]` aur `product.name` ek hi cheez hain.
- `made-in` me dash hai, isliye banate waqt quotes aur parhte waqt brackets chahiyen. (`product.made-in` ka matlab hota "product.made minus in".)
- `product[field]` pehle variable `field` ke andar dekhta hai, `"price"` milta hai, aur wo property parhta hai: `5`.
- `product.field` aisi property dhoondta hai jis ka naam hi "field" ho. Aisi koi nahi: `undefined`.
- Qaida: aam taur par dot lein; key variable se aaye to brackets lein.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Change, add and remove properties">

<Tr>
<En>
Assign to an existing key to change it. Assign to a **new** key to add it. `delete` removes one.
</En>
<Ur>
Maujooda key me value rakhein to wo badal jati hai. **Nayi** key me value rakhein to wo jur jati hai. `delete` ek ko hata deta hai.
</Ur>
</Tr>

```javascript
const user = { name: "Sara", age: 28, isMember: true };

user.age = 29;
user.city = "Austin";
delete user.isMember;

console.log(user);
console.log("city" in user);
console.log("isMember" in user);
```

```text output
{ name: 'Sara', age: 29, city: 'Austin' }
true
false
```

<Happened>
<Tr>
<En>

- `user.age = 29` replaced the old value.
- `user.city` didn't exist, so assigning to it **created** it. JavaScript doesn't complain, which also means a typo (`user.ciyt = …`) quietly creates a wrong property.
- `delete user.isMember` removed the property completely.
- `"city" in user` asks "does this object have a key called city?"
- `user` is a `const`, but its contents can change, just like with arrays.

</En>
<Ur>

- `user.age = 29` ne purani value badal di.
- `user.city` maujood nahi thi, isliye us me value rakhne se wo **ban** gayi. JavaScript shikayat nahi karta, jis ka matlab ye bhi hai ke typo (`user.ciyt = …`) chupke se ghalat property bana deta hai.
- `delete user.isMember` ne property poori tarah hata di.
- `"city" in user` poochta hai "kya is object me city naam ki key hai?"
- `user` `const` hai, magar us ke andar ki cheezen badal sakti hain, arrays ki tarah.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Objects inside objects, and reading safely">

<Tr>
<En>
A value can be another object or an array. You reach inside with more dots. But if a middle step is missing, the next dot crashes. **Optional chaining** (`?.`) stops safely and gives `undefined` instead. **`??`** then supplies a fallback.
</En>
<Ur>
Value doosra object ya array bhi ho sakti hai. Andar tak mazeed dots se pohancha jata hai. Magar agar beech ka koi qadam ghayab ho to agla dot program rok deta hai. **Optional chaining** (`?.`) mehfooz tareeqe se ruk kar `undefined` deta hai. Phir **`??`** mutabadil value de deta hai.
</Ur>
</Tr>

```javascript
const order = {
  id: 501,
  customer: {
    name: "Sara",
    address: { city: "Austin", zip: "78701" },
  },
  items: ["Pen", "Notebook"],
};

console.log(order.customer.address.city);
console.log(order.items[0], order.items.length);

const guestOrder = { id: 502, items: [] };
console.log(guestOrder.customer);

try {
  console.log(guestOrder.customer.name);
} catch (error) {
  console.log(error.name + ": " + error.message);
}

console.log(guestOrder.customer?.name);
console.log(guestOrder.customer?.name ?? "Guest");
```

```text output
Austin
Pen 2
undefined
TypeError: Cannot read properties of undefined (reading 'name')
undefined
Guest
```

<Happened>
<Tr>
<En>

- `order.customer.address.city` walks in step by step: order → customer → address → city.
- `guestOrder.customer` is `undefined` (no such key). That's fine by itself.
- `guestOrder.customer.name` asks `undefined` for its `name`, and **that** throws. This `TypeError` is the most common error in all of JavaScript.
- `customer?.name` means "if customer exists, read name; otherwise stop and give `undefined`".
- `?? "Guest"` means "if the left side is `null` or `undefined`, use this instead".

</En>
<Ur>

- `order.customer.address.city` qadam ba qadam andar jata hai: order → customer → address → city.
- `guestOrder.customer` `undefined` hai (aisi key nahi). Ye akela koi masla nahi.
- `guestOrder.customer.name` `undefined` se us ka `name` maangta hai, aur **ye** error deta hai. Ye `TypeError` poore JavaScript ka sab se aam error hai.
- `customer?.name` ka matlab "agar customer maujood hai to name parho; warna ruk jao aur `undefined` do".
- `?? "Guest"` ka matlab "agar baayen taraf `null` ya `undefined` ho to is ke bajaye ye lo".

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Methods: functions that belong to an object">

<Tr>
<En>
A property's value can be a function. Then it's called a **method**. Inside a method, the word **`this`** means "the object this method was called on".
</En>
<Ur>
Property ki value function bhi ho sakti hai. Tab use **method** kehte hain. Method ke andar lafz **`this`** ka matlab hai "wo object jis par ye method call hua".
</Ur>
</Tr>

```javascript
const cart = {
  items: [],
  addItem(name, price) {
    this.items.push({ name, price });
  },
  getTotal() {
    return this.items.reduce((sum, item) => sum + item.price, 0);
  },
};

cart.addItem("Pen", 2);
cart.addItem("Bag", 40);
console.log(cart.items.length);
console.log(cart.getTotal());
```

```text output
2
42
```

<Happened>
<Tr>
<En>

- `addItem(name, price) { … }` inside an object is the short way to write a method.
- We called `cart.addItem(…)`, so inside it `this` is `cart`, and `this.items` is `cart.items`.
- `getTotal` uses `reduce` (from the Arrays lesson) on the object's own items.
- You've been using methods all along: `console.log`, `list.push` and `text.toUpperCase` are methods on built-in objects.
- Write methods with this short form, not as arrow functions: arrows don't get their own `this`.

</En>
<Ur>

- Object ke andar `addItem(name, price) { … }` method likhne ka chhota tareeqa hai.
- Humne `cart.addItem(…)` call kiya, isliye us ke andar `this` `cart` hai, aur `this.items` `cart.items` hai.
- `getTotal` object ke apne items par `reduce` (Arrays lesson se) chalata hai.
- Aap shuru se methods istemal kar rahe hain: `console.log`, `list.push` aur `text.toUpperCase` built-in objects ke methods hain.
- Methods isi chhote form me likhein, arrow functions ki shakal me nahi: arrows ko apna `this` nahi milta.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Go through every property">

<Tr>
<En>
`Object.keys` gives an array of the keys, `Object.values` an array of the values, and `Object.entries` an array of `[key, value]` pairs. Once you have an array, you can use everything from the Arrays lesson.
</En>
<Ur>
`Object.keys` keys ki array deta hai, `Object.values` values ki array, aur `Object.entries` `[key, value]` ke joron ki array. Array milte hi Arrays lesson ki har cheez istemal ho sakti hai.
</Ur>
</Tr>

```javascript
const stock = { pens: 120, bags: 8, notebooks: 45 };

console.log(Object.keys(stock));
console.log(Object.values(stock));

for (const [item, count] of Object.entries(stock)) {
  console.log(item + ": " + count);
}

const total = Object.values(stock).reduce((sum, n) => sum + n, 0);
const low = Object.keys(stock).filter((item) => stock[item] < 10);
console.log(total, low);
```

```text output
[ 'pens', 'bags', 'notebooks' ]
[ 120, 8, 45 ]
pens: 120
bags: 8
notebooks: 45
173 [ 'bags' ]
```

<Happened>
<Tr>
<En>

- `Object.entries(stock)` is `[["pens", 120], ["bags", 8], …]`. The loop unpacks each pair into `item` and `count` (that's array destructuring).
- `Object.values(stock)` gave plain numbers, so `reduce` could add them up.
- `stock[item]` uses **bracket notation** because the key is in the variable `item`. This is exactly the case brackets exist for.

</En>
<Ur>

- `Object.entries(stock)` ye hai: `[["pens", 120], ["bags", 8], …]`. Loop har jore ko `item` aur `count` me kholta hai (ye array destructuring hai).
- `Object.values(stock)` ne saade numbers diye, isliye `reduce` unhe jor saka.
- `stock[item]` **bracket notation** leta hai kyun ke key variable `item` me hai. Brackets isi surat ke liye hain.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Destructuring: unpack properties into variables">

<Tr>
<En>
Instead of writing `user.name`, `user.age` again and again, pull the properties out once. The names in `{ }` on the **left** must match the keys.
</En>
<Ur>
Baar baar `user.name`, `user.age` likhne ke bajaye properties ek dafa nikal lein. **Baayen** taraf `{ }` ke andar ke naam keys se milne chahiyen.
</Ur>
</Tr>

```javascript
const user = { name: "Sara", age: 28, email: "sara@example.com" };

const { name, age } = user;
console.log(name, age);

const { email: contactEmail } = user;
console.log(contactEmail);

const { role = "customer", name: displayName } = user;
console.log(role, displayName);

const { name: n, ...others } = user;
console.log(others);
```

```text output
Sara 28
sara@example.com
customer Sara
{ age: 28, email: 'sara@example.com' }
```

<Happened>
<Tr>
<En>

- `const { name, age } = user;` is short for `const name = user.name; const age = user.age;`.
- `email: contactEmail` means "take `email`, but call the variable `contactEmail`" (**rename**).
- `role = "customer"` is a **default**: `user` has no `role`, so the default is used.
- `...others` gathers every property you didn't name into a new object. It's a neat way to make a copy **without** one property.
- Destructuring only reads. `user` is unchanged.

</En>
<Ur>

- `const { name, age } = user;` in do lines ka chhota roop hai: `const name = user.name; const age = user.age;`.
- `email: contactEmail` ka matlab "`email` lo, magar variable ka naam `contactEmail` rakho" (**naam badalna**).
- `role = "customer"` **default** hai: `user` me `role` nahi, isliye default laga.
- `...others` un tamam properties ko naye object me jama karta hai jin ka naam aap ne nahi liya. Ye ek property **ke baghair** copy banane ka achha tareeqa hai.
- Destructuring sirf parhta hai. `user` nahi badalta.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Destructuring in function parameters">

<Tr>
<En>
You can destructure right in a function's parameter list. The function then takes **one object** and unpacks what it needs. Callers pass named values in any order. Every React component is written this way.
</En>
<Ur>
Function ki parameter list me hi destructure kiya ja sakta hai. Phir function **ek object** leta hai aur apni zaroorat ki cheezen nikal leta hai. Call karne wale naam wali values kisi bhi tarteeb me dete hain. Har React component isi tarah likha jata hai.
</Ur>
</Tr>

```javascript
function createLabel({ name, price, currency = "$" }) {
  return name + ": " + currency + price;
}

console.log(createLabel({ name: "Pen", price: 2 }));
console.log(createLabel({ price: 40, name: "Bag", currency: "€" }));

const products = [
  { name: "Pen", price: 2 },
  { name: "Bag", price: 40 },
];
console.log(products.map(({ name }) => name.toUpperCase()));
```

```text output
Pen: $2
Bag: €40
[ 'PEN', 'BAG' ]
```

<Happened>
<Tr>
<En>

- The parameter `{ name, price, currency = "$" }` unpacks the object that's passed in, with a default for `currency`.
- The second call gave the properties in a different order. It doesn't matter: they are matched by **name**, not position.
- In `map(({ name }) => …)` each product is destructured as it arrives. Note the extra `( )` around `{ name }`.
- With many options, an object parameter is far easier to read than `createLabel("Pen", 2, "$", true, null)`.

</En>
<Ur>

- Parameter `{ name, price, currency = "$" }` diye gaye object ko kholta hai, `currency` ke default ke saath.
- Doosri call me properties alag tarteeb me di gayin. Farq nahi parta: ye **naam** se milayi jati hain, jagah se nahi.
- `map(({ name }) => …)` me har product aate hi destructure hota hai. `{ name }` ke gird izafi `( )` par dhyan dein.
- Zyada options hon to object parameter `createLabel("Pen", 2, "$", true, null)` se kahin zyada parhne ke qabil hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Shortcuts for building objects">

<Tr>
<En>
Two handy shortcuts. If a variable has the same name as the key you want, write it once (**shorthand**). To use a variable's **value** as the key, wrap it in `[ ]` (**computed key**).
</En>
<Ur>
Do kaam ke shortcuts. Agar variable ka naam wahi ho jo key ka chahiye to use ek dafa likhein (**shorthand**). Variable ki **value** ko key banana ho to use `[ ]` me likhein (**computed key**).
</Ur>
</Tr>

```javascript
const name = "Sara";
const age = 28;

const longWay = { name: name, age: age };
const shortWay = { name, age };
console.log(longWay, shortWay);

const field = "email";
const update = { [field]: "sara@example.com" };
console.log(update);

const scores = {};
for (const player of ["Sara", "Alex", "Sara"]) {
  scores[player] = (scores[player] ?? 0) + 1;
}
console.log(scores);
```

```text output
{ name: 'Sara', age: 28 } { name: 'Sara', age: 28 }
{ email: 'sara@example.com' }
{ Sara: 2, Alex: 1 }
```

<Happened>
<Tr>
<En>

- `{ name, age }` means `{ name: name, age: age }`. You'll see this constantly.
- `{ [field]: … }` used the **value** of `field` ("email") as the key. Without brackets the key would be the word "field".
- The last part **counts** things with an object: for each player, read the current count (or 0 if there isn't one yet) and add 1. Objects are often used like this, as a lookup table.

</En>
<Ur>

- `{ name, age }` ka matlab `{ name: name, age: age }` hai. Ye har jagah nazar aayega.
- `{ [field]: … }` ne `field` ki **value** ("email") ko key banaya. Brackets ke baghair key lafz "field" hota.
- Aakhri hissa object se cheezen **ginta** hai: har player ke liye maujooda ginti parho (ya abhi na ho to 0) aur 1 joro. Objects aksar isi tarah, lookup table ke taur par, istemal hote hain.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Objects are shared by link">

<Tr>
<En>
Like arrays, a variable doesn't hold the object itself. It holds a **link** to it. Copying the variable copies the link, so both names lead to the **same** object.
</En>
<Ur>
Arrays ki tarah variable me khud object nahi hota. Us me object ka **link** hota hai. Variable copy karne se link copy hota hai, isliye dono naam **ek hi** object tak le jate hain.
</Ur>
</Tr>

```javascript
const original = { name: "Sara", plan: "free" };
const sameThing = original;

sameThing.plan = "pro";
console.log(original.plan);
console.log(original === sameThing);

function upgrade(account) {
  account.plan = "enterprise";
}
upgrade(original);
console.log(original.plan);

console.log({ a: 1 } === { a: 1 });
```

```text output
pro
true
enterprise
false
```

<Happened>
<Tr>
<En>

- `sameThing = original` did **not** make a second object. Changing `sameThing.plan` changed the one and only object.
- Passing an object to a function passes the link too, so `upgrade` changed the caller's object. This surprises people in real code.
- Two separately written objects are never `===`, even with identical contents. `===` asks "is it the same object?", not "do they look alike?"

</En>
<Ur>

- `sameThing = original` ne doosra object **nahi** banaya. `sameThing.plan` badalne se wahi akela object badla.
- Function ko object dene se bhi link hi jata hai, isliye `upgrade` ne call karne wale ka object badal diya. Asli code me ye logon ko hairan karta hai.
- Alag alag likhe do objects kabhi `===` nahi hote, chahe andar se bilkul ek jaise hon. `===` poochta hai "kya ye wahi object hai?", ye nahi ke "kya ye ek jaise dikhte hain?"

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Copy and update with spread">

<Tr>
<En>
To change an object without touching the original, make a copy with `{ ...object }` and put your changes **after** the spread. Later keys win. Be aware that the copy is **shallow**: nested objects are still shared.
</En>
<Ur>
Asal ko chhere baghair object badalne ke liye `{ ...object }` se copy banayen aur apni tabdeeliyan spread ke **baad** likhein. Baad wali keys jeetti hain. Dhyan rahe ke copy **shallow** hoti hai: andar ke objects ab bhi mushtarak rehte hain.
</Ur>
</Tr>

```javascript
const user = { name: "Sara", plan: "free", address: { city: "Austin" } };

const upgraded = { ...user, plan: "pro" };
console.log(user.plan, upgraded.plan);

const defaults = { theme: "light", fontSize: 14 };
const settings = { ...defaults, ...{ theme: "dark" } };
console.log(settings);

const moved = { ...user };
moved.address.city = "Denver";
console.log(user.address.city);

const safeMove = { ...user, address: { ...user.address, city: "Boston" } };
console.log(user.address.city, safeMove.address.city);
```

```text output
free pro
{ theme: 'dark', fontSize: 14 }
Denver
Denver Boston
```

<Happened>
<Tr>
<En>

- `{ ...user, plan: "pro" }` copied every property, then overwrote `plan`. `user` still says `free`.
- Merging two objects works the same way: the right-hand one wins where keys clash. This is how defaults plus user settings are combined.
- **The shallow trap:** `{ ...user }` copied the *link* to `address`, not the address itself. Changing `moved.address.city` changed the original's city too.
- The fix is to spread at **each level** you change: a new outer object and a new `address` object. That's what `safeMove` does.

</En>
<Ur>

- `{ ...user, plan: "pro" }` ne har property copy ki, phir `plan` par nayi value rakh di. `user` me ab bhi `free` hai.
- Do objects ko milana bhi isi tarah hota hai: jahan keys takrayen wahan daayen wala jeetta hai. Defaults aur user ki settings isi tarah milayi jati hain.
- **Shallow ka phanda:** `{ ...user }` ne `address` ka *link* copy kiya, khud address nahi. `moved.address.city` badalne se asal ka city bhi badal gaya.
- Hal ye hai ke **har us satah** par spread karein jise aap badal rahe hain: naya bahar wala object aur naya `address` object. `safeMove` yahi karta hai.

</Ur>
</Tr>
</Happened>

</Step>

## Common mistakes

<Compare>
<Bad title="Reading through something that might be missing">

```javascript
const city = user.address.city;
// TypeError if user.address is undefined
```

</Bad>
<Good title="Optional chaining with a fallback">

```javascript
const city = user.address?.city ?? "Unknown";
```

</Good>
</Compare>

<Compare>
<Bad title="Dot notation with a variable key">

```javascript
const field = "price";
product.field;      // looks for a key named "field"
```

</Bad>
<Good title="Brackets read the variable's value">

```javascript
const field = "price";
product[field];     // looks for a key named "price"
```

</Good>
</Compare>

<Compare>
<Bad title="Thinking = makes a copy">

```javascript
const draft = user;
draft.name = "Alex";   // user.name is now "Alex" too
```

</Bad>
<Good title="Spread to copy">

```javascript
const draft = { ...user, name: "Alex" };   // user is unchanged
```

</Good>
</Compare>

<Compare>
<Bad title="Returning an object from a short arrow">

```javascript
const makeUser = (name) => { name: name };   // undefined
```

<Tr>
<En>JavaScript reads the `{ }` as a function body, not an object.</En>
<Ur>JavaScript `{ }` ko function ki body samajhta hai, object nahi.</Ur>
</Tr>

</Bad>
<Good title="Wrap the object in ( )">

```javascript
const makeUser = (name) => ({ name: name });
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Typos in keys.** `user.emial` is `undefined`, not an error. Check spelling when a value is unexpectedly missing.
- **Comparing objects with `===`** to see if their contents match. Compare the fields you care about.
- **Destructuring a name that isn't a key:** `const { username } = user` gives `undefined` if the key is `name`.
- **Forgetting spread is shallow.** Nested objects need their own spread.
- **Changing an object you were given as an argument.** Return a changed copy instead.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Keys me typos.** `user.emial` `undefined` hai, error nahi. Value ghair mutawaqqe taur par ghayab ho to spelling check karein.
- **Objects ka `===` se muqabla** ye dekhne ke liye ke andar ki cheezen milti hain. Jin khaanon se matlab ho un ka muqabla karein.
- **Aisa naam destructure karna jo key hi nahi:** key `name` ho to `const { username } = user` `undefined` deta hai.
- **Bhoolna ke spread shallow hai.** Andar ke objects ko apna spread chahiye.
- **Argument me mile object ko badalna.** Is ke bajaye badli hui copy return karein.

</Ur>
</Tr>

<Takeaways>
<Tr>
<En>

- An object groups named details: `{ key: value }`. One thing, many details.

<DeepDive title="More about how objects work">

**Keys are strings (or symbols).** `{ 1: "a" }` has the key `"1"`. Integer-like keys are listed first in ascending order, then other string keys in the order they were added.

**Shallow vs deep copy.** `{ ...obj }` and `Object.assign({}, obj)` copy one level. `structuredClone(obj)` makes a full deep copy (it handles dates, maps, sets and cycles, but not functions). `JSON.parse(JSON.stringify(obj))` is an older trick that loses `undefined`, functions and dates.

**Freezing.** `Object.freeze(obj)` stops properties being added, changed or removed, but only at the top level. `const` protects the variable; `freeze` protects the object.

**Own vs inherited.** Every object has a hidden link to a **prototype** from which it inherits methods such as `toString`. `"toString" in obj` is `true`, while `Object.hasOwn(obj, "toString")` is `false`. Use `Object.hasOwn` when checking keys that came from user data.

**Getters and setters.** `get fullName() { … }` defines a property that is calculated when read. `set` runs code when it's assigned.

**`this` depends on the call.** `const f = cart.getTotal; f();` loses `this`, because the function is no longer called *on* `cart`. Passing methods as callbacks (`button.onclick = cart.addItem`) has the same problem; wrap it in an arrow or use `bind`.

**Object vs Map.** For a lookup table with keys that come from users, or keys that aren't strings, or when you add and remove often, `Map` is safer and has a `size`. Plain objects are best for fixed, known shapes.

**JSON.** `JSON.stringify(obj)` turns an object into text; `JSON.parse(text)` turns it back. JSON keys need double quotes, and it can't hold functions or `undefined`.

**Nested destructuring.** `const { address: { city } } = user;` reaches inside, but throws if `address` is missing; add a default: `const { address: { city } = {} } = user;`.

</DeepDive>

<DeepDive title="Real world: the settings object everyone shared">

A team has a default configuration:

```javascript
const DEFAULTS = { retries: 3, headers: { "Content-Type": "application/json" } };

function createClient(options) {
  const config = { ...DEFAULTS, ...options };
  config.headers.Authorization = "Bearer " + options.token;
  return config;
}
```

It looks safe: `config` is a fresh object. But spread is shallow, so `config.headers` is the **same** object as `DEFAULTS.headers`. The first client to be created writes its token into the shared defaults, and every client created afterwards, for any user, starts with that token already in its headers. On a server this sends one user's credentials with another user's requests.

The fix is to copy the nested level too:

```javascript
const config = {
  ...DEFAULTS,
  ...options,
  headers: { ...DEFAULTS.headers, ...options.headers, Authorization: "Bearer " + options.token },
};
```

Many teams also `Object.freeze` their default objects (including nested ones) so that a mistake like this throws an error in development instead of leaking quietly in production.

</DeepDive>

<DeepDive title="Security lens">

Objects built from user input are a classic attack surface.

- **Mass assignment.** `const user = { ...req.body }` or `Object.assign(user, req.body)` copies **every** field the client sent, including `isAdmin: true` or `balance: 999999`. Pick the allowed fields explicitly: `const { name, email } = req.body;`.
- **Prototype pollution.** Merging untrusted JSON deeply, or writing `obj[key1][key2] = value` with user-controlled keys, lets an attacker use the key `__proto__` to add properties to **every** object in the program. Reject the keys `__proto__`, `constructor` and `prototype`, use `Object.create(null)` or `Map` for lookup tables, and keep merge libraries updated.
- **Dynamic keys from users.** `handlers[req.query.action]()` lets the user call inherited functions like `constructor` or `toString`. Check with `Object.hasOwn(handlers, action)` first.
- **Leaking fields.** `res.json(user)` sends the whole object, including `passwordHash` and internal flags. Build the response from named fields, or strip with rest: `const { passwordHash, ...safe } = user;`.
- **Logging whole objects.** `console.log(req.body)` writes passwords and tokens into log files. Log selected fields.
- **`in` vs own properties.** `"admin" in roles` is true for inherited keys too. Use `Object.hasOwn`.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What is the difference between dot notation and bracket notation?">
Dot notation uses a literal key that must be a valid identifier. Bracket notation takes any expression that evaluates to a string or symbol, so it works with keys held in variables and keys containing spaces or dashes.
</QA>

<QA q="What is destructuring?">
It is syntax for unpacking values from objects or arrays into variables. Object destructuring matches by key name and supports renaming, default values, nested patterns and collecting the remaining properties with rest. It is commonly used in function parameters.
</QA>

<QA q="What is the difference between a shallow copy and a deep copy?">
A shallow copy, made with spread or Object.assign, creates a new top-level object but shares any nested objects with the original. A deep copy duplicates every level; structuredClone does this for most data types.
</QA>

<QA q="How do you check whether an object has a property?">
The in operator returns true for own and inherited properties. Object.hasOwn returns true only for the object's own properties and is the safest choice. Comparing the value with undefined cannot tell a missing property from one that is set to undefined.
</QA>

<QA q="What do optional chaining and nullish coalescing do?">
Optional chaining, written question mark dot, stops evaluating and returns undefined if the value before it is null or undefined, instead of throwing. Nullish coalescing, written with two question marks, returns the right-hand value only when the left is null or undefined, unlike logical OR, which also replaces zero, empty strings and false.
</QA>

<QA q="Why are two objects with the same contents not equal?">
Objects are compared by reference. Triple equals is true only when both operands refer to the same object in memory. To compare contents you compare individual fields or use a deep-equality helper.
</QA>

<QA q="Why can you change the properties of a const object?">
const prevents the variable from being reassigned to a different value; it does not make the object immutable. To prevent changes to the object's properties, use Object.freeze, which is shallow.
</QA>

</DeepDive>
