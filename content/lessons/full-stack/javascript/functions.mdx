<BigIdea>
<Tr>
<En>
A **function** is a piece of code with a **name**. You write the steps once, and then **call** the function whenever you need those steps, as many times as you like. A function can take **inputs** (called **parameters**) and hand back an **answer** with **`return`**. There are a few ways to write one: a **function declaration** (`function greet() {}`), a **function expression** (`const greet = function () {}`) and the short **arrow function** (`const greet = () => {}`). In JavaScript a function is also a **value**: you can store it in a variable, pass it to another function (a **callback**) and even return it from a function. Almost everything you'll build later, including every React component, is a function.
</En>
<Ur>
**Function** code ka aisa tukra hai jis ka ek **naam** hota hai. Aap qadam ek dafa likhte hain, aur phir jab bhi un qadmon ki zaroorat ho function ko **call** karte hain, jitni dafa chahein. Function **inputs** le sakta hai (jinhe **parameters** kehte hain) aur **`return`** se **jawab** wapas de sakta hai. Ise likhne ke chand tareeqe hain: **function declaration** (`function greet() {}`), **function expression** (`const greet = function () {}`) aur chhota **arrow function** (`const greet = () => {}`). JavaScript me function ek **value** bhi hai: ise variable me rakh sakte hain, doosre function ko de sakte hain (**callback**) aur function se wapas bhi kar sakte hain. Aage aap jo kuch banayenge, har React component samet, taqreeban sab function hi hai.
</Ur>
</Tr>
</BigIdea>

## At a glance

<Glance>
<What>
<Tr>
<En>

A function has three parts: a **name**, **inputs** in `( )` and a **body** in `{ }`.

```js
function add(a, b) {
  return a + b;
}

add(2, 3);   // 5
```

Read it like a sentence: **"Make a function called `add`. It takes two inputs, `a` and `b`. It gives back `a + b`."** The last line **calls** it with 2 and 3.

</En>
<Ur>

Function ke teen hisse hote hain: **naam**, `( )` me **inputs** aur `{ }` me **body**.

```js
function add(a, b) {
  return a + b;
}

add(2, 3);   // 5
```

Ise jumle ki tarah parhein: **"`add` naam ka function banao. Ye do inputs leta hai, `a` aur `b`. Ye `a + b` wapas deta hai."** Aakhri line ise 2 aur 3 ke saath **call** karti hai.

</Ur>
</Tr>
</What>
<Why>
<Tr>
<En>

- **Write once, use many times.** Without functions you'd copy the same lines everywhere, and fix every bug in ten places.
- **Names make code readable.** `calculateTotal(cart)` tells you what happens without reading the steps.
- **Small pieces are easy to test.** You can check one function by itself.
- **Everything is built from them.** Button clicks, array methods like `map`, timers, server routes and React components all use functions.

</En>
<Ur>

- **Ek dafa likho, kai dafa istemal karo.** Functions ke baghair wahi lines har jagah copy karni partin, aur har bug das jagah theek karna parta.
- **Naam code ko parhne ke qabil banate hain.** `calculateTotal(cart)` qadam parhe baghair bata deta hai ke kya ho raha hai.
- **Chhote tukre test karna aasan hai.** Ek function ko akele jaancha ja sakta hai.
- **Sab kuch inhi se banta hai.** Button ke clicks, `map` jaise array methods, timers, server routes aur React components sab functions istemal karte hain.

</Ur>
</Tr>
</Why>
<When>
<Tr>
<En>

Make a function when:

- you are about to **copy and paste** some code,
- a group of lines does **one job** that deserves a name,
- something should happen **later** (on a click, after a delay, for each item in a list).

</En>
<Ur>

Function tab banayen jab:

- aap koi code **copy paste** karne wale hon,
- chand lines mil kar **ek kaam** karti hon jo naam ka haqdar ho,
- koi kaam **baad me** hona ho (click par, kuch der baad, list ke har item ke liye).

</Ur>
</Tr>
</When>
<How>
<Tr>
<En>

```js
function double(n) { return n * 2; }       // declaration
const double2 = function (n) { return n * 2; };  // expression
const double3 = (n) => { return n * 2; };  // arrow
const double4 = (n) => n * 2;              // short arrow
```

All four do the same thing. Today most code uses declarations for main functions and arrows for small ones.

</En>
<Ur>

```js
function double(n) { return n * 2; }       // declaration
const double2 = function (n) { return n * 2; };  // expression
const double3 = (n) => { return n * 2; };  // arrow
const double4 = (n) => n * 2;              // chhota arrow
```

Chaaron ek hi kaam karte hain. Aaj kal zyada tar code bare functions ke liye declarations aur chhote ke liye arrows leta hai.

</Ur>
</Tr>
</How>
</Glance>

## Picture it

<Tr>
<En>

A function is a **recipe card** in a kitchen. The card has a **name** on top ("Mango smoothie"). It lists what you must **bring** ("2 mangoes, 1 cup of milk"): those are the **parameters**. It has **steps**. And at the end you get something **back**: a smoothie. That's the **return value**.

Writing the card doesn't make a smoothie. Nothing happens until someone **follows** the card: that's **calling** the function. You can follow the same card every morning, with different fruit each time, and you never have to write the steps again.

You can also **hand the card to someone else** and say "follow this when the guests arrive". Giving a function to another piece of code to run later is called a **callback**.

</En>
<Ur>

Function kitchen ka **recipe card** hai. Card ke upar **naam** likha hai ("Mango smoothie"). Is par likha hai ke aap ko kya **lana** hai ("2 aam, 1 cup doodh"): ye **parameters** hain. Is par **qadam** likhe hain. Aur aakhir me aap ko kuch **wapas** milta hai: smoothie. Ye **return value** hai.

Card likhne se smoothie nahi banti. Jab tak koi card par **amal** na kare kuch nahi hota: ye function ko **call** karna hai. Aap wahi card har subah, har dafa alag phal ke saath, istemal kar sakte hain, aur qadam dobara likhne nahi parte.

Aap ye **card kisi aur ko bhi de** sakte hain aur keh sakte hain "mehmaan aayen to is par amal karna". Kisi doosre code ko function dena taa ke wo baad me chalaye, ise **callback** kehte hain.

</Ur>
</Tr>

## Words you'll see

<Tr>
<En>

| Word | What it means | Example |
| --- | --- | --- |
| **Function** | A named piece of code you can run | `function greet() {}` |
| **Call** | Run the function, by writing its name with `( )` | `greet()` |
| **Parameter** | An input's name, written when you make the function | `name` in `function greet(name)` |
| **Argument** | The real value you pass when you call it | `"Sara"` in `greet("Sara")` |
| **Return value** | The answer a function hands back | `return a + b;` |
| **Body** | The steps, inside `{ }` | |
| **Arrow function** | The short way to write a function | `(n) => n * 2` |

| **Higher-order function** | A function that takes or returns another function | `map`, `filter` |

<Tr>
<En>

</En>
<Ur>

<Walkthrough>

<Step title="Make a function and call it">

<Tr>
<En>
First we **make** the function. Then we **call** it by writing its name followed by `( )`.
</En>
<Ur>
Pehle hum function **banate** hain. Phir us ka naam aur `( )` likh kar use **call** karte hain.
</Ur>
</Tr>

```javascript
function sayHello() {
  console.log("Hello!");
}

sayHello();
sayHello();
sayHello();
```

```text output
Hello!
Hello!
Hello!
```

<Happened>
<Tr>
<En>

- Lines 1–3 **make** the function. Nothing is printed yet. It's a recipe card sitting in a drawer.
- `sayHello();` **calls** it: JavaScript jumps into the body, runs the steps, and comes back.
- We called it three times, so the steps ran three times. We wrote `console.log` only once.
- **The `( )` matter.** `sayHello` is the card. `sayHello()` is following the card.

</En>
<Ur>

- Lines 1–3 function **banati** hain. Abhi kuch print nahi hota. Ye daraaz me rakha recipe card hai.
- `sayHello();` ise **call** karta hai: JavaScript body me jata hai, qadam chalata hai, aur wapas aa jata hai.
- Humne ise teen dafa call kiya, isliye qadam teen dafa chale. `console.log` humne sirf ek dafa likha.
- **`( )` ahem hain.** `sayHello` card hai. `sayHello()` card par amal karna hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Give it inputs: parameters">

<Tr>
<En>
A function that always does exactly the same thing isn't very useful. **Parameters** are blanks that you fill in each time you call it.
</En>
<Ur>
Jo function hamesha bilkul ek hi kaam kare wo zyada kaam ka nahi. **Parameters** khaali jagahen hain jinhe aap har call par bharte hain.
</Ur>
</Tr>

```javascript
function greet(name, timeOfDay) {
  console.log("Good " + timeOfDay + ", " + name + "!");
}

greet("Sara", "morning");
greet("Alex", "evening");
```

```text output
Good morning, Sara!
Good evening, Alex!
```

<Happened>
<Tr>
<En>

- `name` and `timeOfDay` are **parameters**: variables that exist only inside the function.
- `"Sara"` and `"morning"` are **arguments**: the real values. They go into the parameters **in order**: first to first, second to second.
- The second call used different arguments, so the same steps gave a different result.

</En>
<Ur>

- `name` aur `timeOfDay` **parameters** hain: aise variables jo sirf function ke andar maujood hain.
- `"Sara"` aur `"morning"` **arguments** hain: asli values. Ye parameters me **tarteeb se** jati hain: pehli pehle me, doosri doosre me.
- Doosri call me arguments alag the, isliye wahi qadam alag nateeja de gaye.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Get an answer back: return">

<Tr>
<En>
`console.log` only **shows** something on the screen. To **give a value back** to the code that called the function, so it can be stored or used, you need **`return`**.
</En>
<Ur>
`console.log` sirf screen par kuch **dikhata** hai. Jis code ne function call kiya use **value wapas dene** ke liye, taa ke wo rakhi ya istemal ki ja sake, **`return`** chahiye.
</Ur>
</Tr>

```javascript
function add(a, b) {
  return a + b;
}

const sum = add(2, 3);
console.log(sum);
console.log(add(10, 20) * 2);

function isAdult(age) {
  return age >= 18;
}
console.log(isAdult(20), isAdult(12));
```

```text output
5
60
true false
```

<Happened>
<Tr>
<En>

- `add(2, 3)` runs the body and **becomes** the value `5`. It's as if the line said `const sum = 5;`.
- Because a call becomes a value, you can use it anywhere a value fits: `add(10, 20) * 2` is `30 * 2`.
- `isAdult` returns a boolean, the answer to a question.
- `return` also **ends** the function immediately. Lines after it in the same block never run.

</En>
<Ur>

- `add(2, 3)` body chalata hai aur khud value `5` **ban jata** hai. Goya line ye thi: `const sum = 5;`.
- Chunke call value ban jati hai, ise har us jagah rakh sakte hain jahan value aa sakti hai: `add(10, 20) * 2` yaani `30 * 2`.
- `isAdult` boolean wapas karta hai, yaani ek sawal ka jawab.
- `return` function ko foran **khatam** bhi kar deta hai. Usi block me is ke baad ki lines kabhi nahi chaltin.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="No return means undefined">

<Tr>
<En>
The most common beginner mistake with functions: printing the answer inside the function, but forgetting to `return` it.
</En>
<Ur>
Functions me naye seekhne walon ki sab se aam ghalti: jawab function ke andar print kar dena, magar use `return` karna bhool jana.
</Ur>
</Tr>

```javascript
function addAndShow(a, b) {
  console.log(a + b);
}

const result = addAndShow(2, 3);
console.log(result);
console.log(result * 10);
```

```text output
5
undefined
NaN
```

<Happened>
<Tr>
<En>

- The function **printed** `5`, but it didn't return anything.
- A function with no `return` gives back `undefined`. So `result` is `undefined`.
- `undefined * 10` is `NaN`. The bug shows up later, far from its cause.
- Rule of thumb: functions should **return** their answer. Let the caller decide whether to print it.

</En>
<Ur>

- Function ne `5` **print** to kiya, magar wapas kuch nahi kiya.
- `return` ke baghair function `undefined` wapas karta hai. Isliye `result` `undefined` hai.
- `undefined * 10` `NaN` hai. Bug baad me nazar aata hai, apni wajah se door.
- Aasan qaida: functions apna jawab **return** karein. Print karna hai ya nahi, ye call karne wale par chhorein.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Arrow functions: the short form">

<Tr>
<En>
An **arrow function** is a shorter way to write a function. You store it in a variable. If the body is a single expression, you can drop the `{ }` and the word `return`: the result is returned automatically.
</En>
<Ur>
**Arrow function** function likhne ka chhota tareeqa hai. Ise variable me rakha jata hai. Agar body sirf ek expression ho to `{ }` aur lafz `return` hata sakte hain: nateeja khud wapas ho jata hai.
</Ur>
</Tr>

```javascript
const double = (n) => {
  return n * 2;
};

const triple = (n) => n * 3;
const square = n => n * n;
const sayHi = () => "Hi!";
const makeUser = (name) => ({ name: name, active: true });

console.log(double(5), triple(5), square(5));
console.log(sayHi());
console.log(makeUser("Sara"));
```

```text output
10 15 25
Hi!
{ name: 'Sara', active: true }
```

<Happened>
<Tr>
<En>

- `double` is the long arrow form: `{ }` and `return`, just like a normal function.
- `triple` is the short form: no braces, so `n * 3` is returned automatically (an **implicit return**).
- With exactly one parameter, the `( )` around it are optional (`square`). With zero parameters you must write `()` (`sayHi`).
- To return an **object** from the short form, wrap it in `( )`, as in `makeUser`. Otherwise JavaScript thinks the `{ }` is the function body.

</En>
<Ur>

- `double` lamba arrow hai: `{ }` aur `return`, aam function ki tarah.
- `triple` chhota hai: braces nahi, isliye `n * 3` khud wapas hota hai (**implicit return**).
- Bilkul ek parameter ho to us ke gird `( )` ikhtiyari hain (`square`). Koi parameter na ho to `()` likhna lazmi hai (`sayHi`).
- Chhote form se **object** wapas karna ho to use `( )` me lapetein, jaise `makeUser` me. Warna JavaScript `{ }` ko function ki body samajhta hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Default values for parameters">

<Tr>
<En>
If the caller leaves an argument out, the parameter is `undefined`. You can give a parameter a **default value** to use in that case.
</En>
<Ur>
Agar call karne wala koi argument chhor de to parameter `undefined` hota hai. Aap parameter ko **default value** de sakte hain jo us surat me istemal ho.
</Ur>
</Tr>

```javascript
function greet(name = "friend", greeting = "Hello") {
  return `${greeting}, ${name}!`;
}

console.log(greet());
console.log(greet("Sara"));
console.log(greet("Sara", "Welcome back"));

function noDefault(name) {
  return "Hello, " + name;
}
console.log(noDefault());
```

```text output
Hello, friend!
Hello, Sara!
Welcome back, Sara!
Hello, undefined
```

<Happened>
<Tr>
<En>

- `greet()` got no arguments, so both defaults were used.
- `greet("Sara")` filled the first parameter; the second used its default.
- Without a default, a missing argument is `undefined`, and you get the embarrassing `Hello, undefined`.

</En>
<Ur>

- `greet()` ko koi argument nahi mila, isliye dono defaults istemal hue.
- `greet("Sara")` ne pehla parameter bhara; doosre ne apna default liya.
- Default ke baghair ghayab argument `undefined` hota hai, aur sharminda karne wala `Hello, undefined` milta hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Functions are values: callbacks">

<Tr>
<En>
This is the idea that makes JavaScript special. A function is a **value**, like a number or a string. You can pass it to another function, which will call it for you. The function you pass is a **callback**.
</En>
<Ur>
Yahi khayal JavaScript ko khaas banata hai. Function ek **value** hai, number ya string ki tarah. Ise doosre function ko diya ja sakta hai, jo ise aap ke liye call karega. Jo function aap dete hain wo **callback** hai.
</Ur>
</Tr>

```javascript
function repeat(times, action) {
  for (let i = 1; i <= times; i++) {
    action(i);
  }
}

function showStep(n) {
  console.log("Step", n);
}

repeat(3, showStep);
repeat(2, (n) => console.log("Round", n));

const prices = [10, 20, 30];
const withTax = prices.map((price) => price * 1.1);
console.log(withTax);
```

```text output
Step 1
Step 2
Step 3
Round 1
Round 2
[ 11, 22, 33 ]
```

<Happened>
<Tr>
<En>

- `repeat` takes a number and a **function**. Inside, it calls that function with `action(i)`.
- We passed `showStep` **without `( )`**. We are handing over the recipe card, not following it ourselves. `repeat` follows it, three times.
- The second call passes an arrow function written right on the spot. This is the most common style.
- `prices.map(…)` is a built-in function that works the same way: it calls your callback once for each item and collects the answers in a new list.

</En>
<Ur>

- `repeat` ek number aur ek **function** leta hai. Andar wo us function ko `action(i)` se call karta hai.
- Humne `showStep` **`( )` ke baghair** diya. Hum recipe card de rahe hain, khud us par amal nahi kar rahe. Amal `repeat` karta hai, teen dafa.
- Doosri call me wahin likha hua arrow function diya gaya. Yahi sab se aam andaaz hai.
- `prices.map(…)` isi tarah kaam karne wala built-in function hai: ye har item ke liye aap ka callback ek dafa call karta hai aur jawab nayi list me jama karta hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Any number of arguments: rest and spread">

<Tr>
<En>
Three dots `...` do two opposite jobs. In a **parameter list** they **collect** all remaining arguments into an array (**rest**). In a **call** they **unpack** an array into separate arguments (**spread**).
</En>
<Ur>
Teen nuqte `...` do ulte kaam karte hain. **Parameter list** me ye baqi tamam arguments ko array me **jama** karte hain (**rest**). **Call** me ye array ko alag alag arguments me **khol** dete hain (**spread**).
</Ur>
</Tr>

```javascript
function sum(...numbers) {
  let total = 0;
  for (const n of numbers) {
    total += n;
  }
  return total;
}

console.log(sum(1, 2));
console.log(sum(1, 2, 3, 4, 5));

const scores = [72, 95, 88];
console.log(Math.max(...scores));
console.log(sum(...scores));
```

```text output
3
15
95
255
```

<Happened>
<Tr>
<En>

- `...numbers` gathered every argument into one array, so `sum` works with 2 numbers or 5 or 50.
- `Math.max` wants separate numbers, not an array. `...scores` unpacked the array into `Math.max(72, 95, 88)`.
- Same three dots: **rest collects** (when making a function), **spread unpacks** (when calling one).

</En>
<Ur>

- `...numbers` ne har argument ek array me jama kar diya, isliye `sum` 2 numbers ke saath bhi chalta hai, 5 ya 50 ke saath bhi.
- `Math.max` ko alag alag numbers chahiyen, array nahi. `...scores` ne array ko khol kar `Math.max(72, 95, 88)` bana diya.
- Wahi teen nuqte: **rest jama karta hai** (function banate waqt), **spread kholta hai** (call karte waqt).

</Ur>
</Tr>
</Happened>

</Step>

<Step title="A function can make another function">

<Tr>
<En>
Since functions are values, a function can **return** a function. This lets you build custom functions from a template.
</En>
<Ur>
Chunke functions values hain, function doosra function **return** bhi kar sakta hai. Is tarah ek saanche se apni marzi ke functions banaye ja sakte hain.
</Ur>
</Tr>

```javascript
function makeMultiplier(factor) {
  return (number) => number * factor;
}

const double = makeMultiplier(2);
const triple = makeMultiplier(3);

console.log(double(10));
console.log(triple(10));
console.log(typeof double);
```

```text output
20
30
function
```

<Happened>
<Tr>
<En>

- `makeMultiplier(2)` doesn't return a number. It returns a **new function** that multiplies by 2.
- We stored that function in `double`, and then called it like any other function.
- The inner function **remembers** `factor` even after `makeMultiplier` has finished. That memory is called a **closure**; it's the subject of the next lesson.

</En>
<Ur>

- `makeMultiplier(2)` number wapas nahi karta. Ye ek **naya function** wapas karta hai jo 2 se zarb deta hai.
- Humne wo function `double` me rakha, aur phir use kisi bhi function ki tarah call kiya.
- Andar wala function `makeMultiplier` khatam hone ke baad bhi `factor` ko **yaad rakhta** hai. Is yaad dasht ko **closure** kehte hain; agla lesson isi par hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Declarations are ready early, arrows are not">

<Tr>
<En>
One real difference between the forms: a **function declaration** can be called **before** the line where it's written. A function stored in a `const` cannot.
</En>
<Ur>
In tareeqon ka ek asli farq: **function declaration** ko us line se **pehle** bhi call kiya ja sakta hai jahan wo likha hai. `const` me rakha function nahi.
</Ur>
</Tr>

```javascript
console.log(early(5));

function early(n) {
  return n + 1;
}

try {
  console.log(late(5));
} catch (error) {
  console.log(error.name + ": " + error.message);
}

const late = (n) => n + 1;
console.log(late(5));
```

```text output
6
ReferenceError: Cannot access 'late' before initialization
6
```

<Happened>
<Tr>
<En>

- Before running a file, JavaScript finds every `function` declaration and makes it ready. This is called **hoisting**. So `early(5)` works on line 1.
- `late` is a `const`. It doesn't exist until its line runs, so calling it early is an error. (`try`/`catch` is just here to show the error without stopping the program.)
- After its line has run, `late(5)` works normally.
- Simple habit: define functions before you use them and you never have to think about this.

</En>
<Ur>

- File chalane se pehle JavaScript har `function` declaration dhoond kar use tayyar kar leta hai. Ise **hoisting** kehte hain. Isliye `early(5)` pehli line par hi chal jata hai.
- `late` ek `const` hai. Jab tak us ki line na chale wo maujood nahi, isliye pehle call karna error hai. (`try`/`catch` yahan sirf isliye hai ke error dikh jaye aur program na ruke.)
- Us ki line chalne ke baad `late(5)` aam tarah chalta hai.
- Aasan aadat: functions ko istemal se pehle banayen, phir is ke baare me sochna hi nahi parta.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Pure functions: no surprises">

<Tr>
<En>
A **pure function** uses only its inputs and changes nothing outside itself. Same inputs, same answer, every time. An **impure** function reads or changes something outside, so it can surprise you.
</En>
<Ur>
**Pure function** sirf apne inputs istemal karta hai aur apne bahar kuch nahi badalta. Wahi inputs, wahi jawab, har dafa. **Impure** function bahar ki koi cheez parhta ya badalta hai, isliye hairan kar sakta hai.
</Ur>
</Tr>

```javascript
let total = 0;
function addToTotal(amount) {
  total += amount;
  return total;
}
console.log(addToTotal(10), addToTotal(10));

function add(a, b) {
  return a + b;
}
console.log(add(10, 10), add(10, 10));

function addItem(list, item) {
  return [...list, item];
}
const cart = ["milk"];
const newCart = addItem(cart, "bread");
console.log(cart, newCart);
```

```text output
10 20
20 20
[ 'milk' ] [ 'milk', 'bread' ]
```

<Happened>
<Tr>
<En>

- `addToTotal(10)` gave `10` the first time and `20` the second. Same input, different answers, because it changes the outside variable `total`. That's **impure**.
- `add(10, 10)` is `20` every time. **Pure.**
- `addItem` builds a **new** list with `[...list, item]` instead of changing the one it was given, so the original `cart` is untouched. This style matters a lot in React.
- You can't make everything pure (showing things on screen and saving data are changes), but keep as much logic as you can in pure functions. They're the easiest to test and trust.

</En>
<Ur>

- `addToTotal(10)` ne pehli dafa `10` aur doosri dafa `20` diya. Wahi input, alag jawab, kyun ke ye bahar ka variable `total` badalta hai. Ye **impure** hai.
- `add(10, 10)` har dafa `20` hai. **Pure.**
- `addItem` di gayi list ko badalne ke bajaye `[...list, item]` se **nayi** list banata hai, isliye asal `cart` waisa hi rehta hai. React me ye andaaz bohot ahem hai.
- Sab kuch pure nahi ban sakta (screen par dikhana aur data mehfooz karna tabdeeliyan hain), magar jitni logic ho sake pure functions me rakhein. Inhe test karna aur in par bharosa karna sab se aasan hai.

</Ur>
</Tr>
</Happened>

</Step>

</Walkthrough>

## Common mistakes

<Compare>
<Bad title="Forgetting return">

```javascript
function getTotal(price, qty) {
  price * qty;          // calculated, then thrown away
}
```

<Tr>
<En>The function works out the answer but never hands it back, so the caller gets `undefined`.</En>
<Ur>Function jawab nikalta hai magar wapas nahi deta, isliye call karne wale ko `undefined` milta hai.</Ur>
</Tr>

</Bad>
<Good title="Return the answer">

```javascript
function getTotal(price, qty) {
  return price * qty;
}
```

</Good>
</Compare>

<Compare>
<Bad title="Calling the callback instead of passing it">

```javascript
button.addEventListener("click", save());   // runs save right now
```

<Tr>
<En>`save()` runs immediately and passes its **result**. Nothing happens on click.</En>
<Ur>`save()` foran chal jata hai aur apna **nateeja** de deta hai. Click par kuch nahi hota.</Ur>
</Tr>

</Bad>
<Good title="Pass the function itself">

```javascript
button.addEventListener("click", save);     // runs save on click
```

</Good>
</Compare>

<Compare>
<Bad title="Braces in an arrow, but no return">

```javascript
const double = (n) => { n * 2 };   // undefined
```

<Tr>
<En>With `{ }` you must write `return`. Only the brace-free form returns automatically.</En>
<Ur>`{ }` ke saath `return` likhna lazmi hai. Sirf braces ke baghair wala form khud wapas karta hai.</Ur>
</Tr>

</Bad>
<Good title="Drop the braces, or add return">

```javascript
const double = (n) => n * 2;
```

</Good>
</Compare>

<Compare>
<Bad title="Arguments in the wrong order">

```javascript
function divide(total, people) { return total / people; }
divide(4, 100);   // 0.04
```

</Bad>
<Good title="Match the parameter order">

```javascript
function divide(total, people) { return total / people; }
divide(100, 4);   // 25
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Forgetting the `( )` when calling:** `console.log(getName)` prints the function itself, not its answer.
- **One function doing five jobs.** If you need the word "and" to describe it, split it.
- **Vague names** like `doStuff` or `handle`. Use a verb and a noun: `calculateTotal`, `sendEmail`.
- **Changing the arguments you were given** (pushing to an array parameter). Return a new value instead.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Call karte waqt `( )` bhoolna:** `console.log(getName)` function ko hi print karta hai, us ka jawab nahi.
- **Ek function jo paanch kaam kare.** Agar use bayan karne ke liye "aur" kehna pare to use taqseem kar dein.
- **Mubham naam** jaise `doStuff` ya `handle`. Fel aur ism lein: `calculateTotal`, `sendEmail`.
- **Diye gaye arguments ko badalna** (array parameter me push karna). Is ke bajaye nayi value return karein.

</Ur>
</Tr>

<Takeaways>
<Tr>
<En>

- A function is a named set of steps. Making it does nothing; **calling** it with `( )` runs it.
- **Parameters** are the blanks; **arguments** are the values that fill them, in order.

<DeepDive title="How the forms really differ">

| | Declaration | Function expression | Arrow function |
| --- | --- | --- | --- |
| Syntax | `function f() {}` | `const f = function () {}` | `const f = () => {}` |
| Hoisted (callable before its line) | Yes | No | No |
| Has its own `this` | Yes | Yes | **No**: uses the surrounding `this` |
| Has `arguments` object | Yes | Yes | No (use rest parameters) |
| Can be used with `new` | Yes | Yes | No |

**`this`.** In a regular function, `this` depends on **how the function is called** (`obj.method()` makes `this` the object; a bare call makes it `undefined` in strict mode). An arrow function has no `this` of its own; it uses the `this` of the place where it was written. That's why arrows are convenient for callbacks inside methods, and why you shouldn't use an arrow as an object method that needs `this`.

**First-class functions.** Functions can be stored in variables, arrays and objects, passed as arguments and returned from functions. A function that takes or returns a function is a **higher-order function**; `map`, `filter`, `reduce`, `addEventListener` and `setTimeout` are all examples.

**The call stack.** Each call adds a frame to the **call stack**; `return` removes it. A function that calls itself is **recursive**; without a stopping condition the stack fills up and you get `RangeError: Maximum call stack size exceeded`.

**IIFE.** `(function () { … })();` defines a function and calls it immediately. Before modules existed, this was how code kept its variables private. You'll see it in older code.

**Arguments are passed by value.** A primitive argument is copied. An object argument is a copied **link**, so the function can change the caller's object. That is the most common source of accidental impurity.

</DeepDive>

<DeepDive title="Real world: the event handler that fired too early">

A very common bug in front-end code:

```javascript
// Bug: deleteAccount() runs while the page is loading
button.addEventListener("click", deleteAccount(userId));
```

The developer wanted to pass an argument, so they added `( )`, which **calls** the function immediately and passes its return value (`undefined`) as the handler. The account is deleted on page load, and clicking the button does nothing. The same mistake appears in React as `onClick={deleteAccount(userId)}`, which runs on every render.

The fix is to pass a **function that will call it later**:

```javascript
button.addEventListener("click", () => deleteAccount(userId));
```

The lesson: `f` is the function, `f()` is its result. Whenever some code says "give me a function", check that you are not giving it a result.

</DeepDive>

<DeepDive title="Security lens">

Functions are where input meets logic, so they are where input must be checked.

- **Validate arguments at the boundary.** A function that receives data from a request, form or URL should check types and ranges before using them. Inner helper functions can then trust their inputs.
- **Never build functions from strings.** `eval(text)`, `new Function(text)` and `setTimeout("code as text", 100)` run text as code. If any part of that text comes from a user, they can run their own code on your page or server.
- **Callbacks from untrusted sources.** Old JSONP APIs let the caller choose a callback name in the URL; unvalidated names led to cross-site scripting. Don't let user input decide which function is called (`handlers[userInput]()`) without an allow-list.
- **Side effects hide in impure functions.** A function named `getUser` that also writes a log, changes a global or sends a request is hard to audit. Keep permission checks in clearly named functions and call them explicitly.
- **Default parameters aren't validation.** A default only applies to `undefined`. `null`, `""`, `0` and `NaN` pass straight through.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What is the difference between a function declaration and a function expression?">
A declaration starts with the function keyword and a name, and is hoisted with its body, so it can be called before the line where it appears. A function expression creates a function as a value and assigns it to a variable; the variable follows normal let, const or var rules, so the function cannot be called before the assignment runs.
</QA>

<QA q="How do arrow functions differ from regular functions?">
Arrow functions have a shorter syntax with an implicit return for single expressions. They do not have their own this, arguments object or prototype, and cannot be used as constructors with new. They take this from the enclosing scope, which makes them convenient for callbacks but unsuitable for object methods that rely on this.
</QA>

<QA q="What is the difference between a parameter and an argument?">
A parameter is the variable name listed in the function definition. An argument is the actual value supplied when the function is called. Arguments are assigned to parameters by position.
</QA>

<QA q="What is a higher-order function?">
A function that takes one or more functions as arguments, returns a function, or both. Array methods such as map, filter and reduce are higher-order functions, as are event listener registration and function factories.
</QA>

<QA q="What is a pure function and why is it useful?">
A pure function always returns the same output for the same inputs and has no side effects: it doesn't modify its arguments, outside variables, the DOM or anything else. Pure functions are easy to test, safe to reuse and cache, and are the basis of React's rendering model.
</QA>

<QA q="What is the difference between rest parameters and the spread operator?">
Both use three dots. Rest appears in a function's parameter list and collects the remaining arguments into an array. Spread appears in a call or a literal and expands an array or object into individual elements.
</QA>

</DeepDive>
