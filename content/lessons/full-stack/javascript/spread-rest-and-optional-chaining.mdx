<BigIdea>
<Tr>
<En>
Three dots, **`...`**, do two opposite jobs depending on where you put them. As **spread**, they **unpack**: `[...a, ...b]` pours the items of two arrays into a new one, and `{ ...defaults, ...saved }` pours the properties of two objects into a new object. As **rest**, they **gather**: `function total(...prices)` collects all the arguments into one array, and `const { password, ...safeUser } = user` collects "everything else". Spread makes **copies**, which lets you update data **without changing the original**, but only one level deep (a **shallow** copy). The third tool, **optional chaining** `?.`, reads nested data safely: `order.customer?.address?.city` gives `undefined` instead of crashing when something in the chain is missing.
</En>
<Ur>
Teen nuqte, **`...`**, jagah ke mutabiq do ulte kaam karte hain. **Spread** ki shakal me ye **kholte** hain: `[...a, ...b]` do arrays ke items ek nayi array me daal deta hai, aur `{ ...defaults, ...saved }` do objects ki properties ek naye object me. **Rest** ki shakal me ye **ikattha** karte hain: `function total(...prices)` tamam arguments ek array me jama karta hai, aur `const { password, ...safeUser } = user` "baqi sab" jama karta hai. Spread **copies** banata hai, jis se aap data ko **asal badle baghair** update kar sakte hain, magar sirf ek level gehra (**shallow** copy). Teesra auzaar, **optional chaining** `?.`, nested data mehfooz tareeqe se parhta hai: `order.customer?.address?.city` zanjeer me kuch ghayab ho to crash hone ke bajaye `undefined` deta hai.
</Ur>
</Tr>
</BigIdea>

## At a glance

<Glance>
<What>
<Tr>
<En>

```javascript
const combined = [...[1, 2], ...[3]];
const settings = { ...{ theme: "light", size: 16 }, ...{ size: 18 } };
function sum(...nums) {
  return nums.reduce((a, b) => a + b, 0);
}
const user = { profile: null };
console.log(combined, settings, sum(1, 2, 3), user.profile?.name);
```

```text output
[ 1, 2, 3 ] { theme: 'light', size: 18 } 6 undefined
```

| Syntax | Where | Job |
| --- | --- | --- |
| `[...arr]` | inside an array literal | **spread**: copy / combine arrays |
| `{ ...obj }` | inside an object literal | **spread**: copy / merge objects |
| `fn(...arr)` | in a function call | **spread**: pass items as separate arguments |
| `function f(...args)` | in parameters | **rest**: gather arguments into an array |
| `const [a, ...rest] = arr` | in destructuring | **rest**: gather remaining items |
| `a?.b`, `a?.[i]`, `a?.()` | reading | **optional chaining**: stop if `a` is null/undefined |

</En>
<Ur>

```javascript
const combined = [...[1, 2], ...[3]];
const settings = { ...{ theme: "light", size: 16 }, ...{ size: 18 } };
function sum(...nums) {
  return nums.reduce((a, b) => a + b, 0);
}
const user = { profile: null };
console.log(combined, settings, sum(1, 2, 3), user.profile?.name);
```

```text output
[ 1, 2, 3 ] { theme: 'light', size: 18 } 6 undefined
```

| Syntax | Kahan | Kaam |
| --- | --- | --- |
| `[...arr]` | array literal ke andar | **spread**: arrays copy / jorna |
| `{ ...obj }` | object literal ke andar | **spread**: objects copy / milana |
| `fn(...arr)` | function call me | **spread**: items alag arguments ki tarah dena |
| `function f(...args)` | parameters me | **rest**: arguments array me jama karna |
| `const [a, ...rest] = arr` | destructuring me | **rest**: baqi items jama karna |
| `a?.b`, `a?.[i]`, `a?.()` | parhte waqt | **optional chaining**: `a` null/undefined ho to ruk jao |

</Ur>
</Tr>
</What>
<Why>
<Tr>
<En>

- **Modern code is full of these.** React state updates, API handlers, config merging and utility functions all use `...` and `?.` constantly.
- **Not changing the original** (immutability) prevents a whole family of bugs where one part of the app silently edits data another part is using.
- **Real data has holes.** API responses miss fields, users skip optional steps. `?.` lets you read such data without a wall of `if` checks or crashes.

</En>
<Ur>

- **Jadeed code in se bhara hai.** React state updates, API handlers, config milana aur utility functions sab musalsal `...` aur `?.` istemal karte hain.
- **Asal na badalna** (immutability) bugs ke us poore khandan ko rokta hai jahan app ka ek hissa khamoshi se wo data badal deta hai jo doosra hissa istemal kar raha hai.
- **Asli data me khala hote hain.** API responses me fields ghayab hoti hain, users optional qadam chhor dete hain. `?.` aise data ko `if` checks ki deewar ya crashes ke baghair parhne deta hai.

</Ur>
</Tr>
</Why>
<When>
<Tr>
<En>

| You want to… | Use |
| --- | --- |
| Copy or combine arrays | `[...a, ...b]` |
| Add defaults, override some settings | `{ ...defaults, ...overrides }` |
| Change one field without touching the original | `{ ...item, price: 25 }` |
| Accept any number of arguments | `function f(...args)` |
| Remove a field from a copy | `const { secret, ...rest } = obj` |
| Copy nested data completely | `structuredClone(obj)` |
| Read a value that may be missing | `obj?.a?.b ?? fallback` |

</En>
<Ur>

| Aap chahte hain… | Lein |
| --- | --- |
| Arrays copy ya jorna | `[...a, ...b]` |
| Defaults dena, kuch settings badalna | `{ ...defaults, ...overrides }` |
| Asal ko chhue baghair ek field badalna | `{ ...item, price: 25 }` |
| Kitne bhi arguments lena | `function f(...args)` |
| Copy me se ek field hatana | `const { secret, ...rest } = obj` |
| Nested data poori tarah copy karna | `structuredClone(obj)` |
| Aisi value parhna jo ghayab ho sakti hai | `obj?.a?.b ?? fallback` |

</Ur>
</Tr>
</When>
<How>
<Tr>
<En>

1. To build something new from old pieces: write a new `[ ]` or `{ }` and **spread** the pieces into it.
2. Later properties win, so put defaults first and overrides last.
3. For nested updates, spread **each level** you change (or use `structuredClone`).
4. In parameters and destructuring, `...name` must be **last**.
5. Use `?.` only where a value is allowed to be missing, and pair it with `??` for a fallback.

</En>
<Ur>

1. Purane tukron se kuch naya banane ke liye: naya `[ ]` ya `{ }` likhein aur tukre us me **spread** karein.
2. Baad wali properties jeet-ti hain, isliye defaults pehle aur overrides aakhir me rakhein.
3. Nested updates ke liye **har wo level** spread karein jo aap badal rahe hain (ya `structuredClone` lein).
4. Parameters aur destructuring me `...name` **aakhir** me hona chahiye.
5. `?.` sirf wahan lein jahan value ka ghayab hona jaiz ho, aur fallback ke liye `??` saath lagayen.

</Ur>
</Tr>
</How>
</Glance>

## Picture it

<Tr>
<En>

Think of **packing and unpacking boxes** when you move house.

- **Spread** is **unpacking**: you open two boxes (`fruits`, `veg`) and pour everything into a new, bigger box (`[...fruits, ...veg]`). The old boxes are still there, untouched.
- Merging objects is like **filling in a form from two sources**: first copy the default answers, then write your own answers on top. Whatever is written **last** shows.
- But it's a **shallow** unpack: if a box contains a **smaller sealed box** (a nested object), you move that sealed box as-is. Both the old and new big boxes now hold **the same** small box.
- **Rest** is **packing**: "put these two on the table, and **everything else** in this box" (`const [first, second, ...others]`).
- **Optional chaining** is checking each room before walking in: "If there's a kitchen, and if it has a fridge, what's on the top shelf?" If any room is missing, you just say "nothing" instead of walking into a wall.

</En>
<Ur>

Ghar badalte waqt **dabbe bandhne aur kholne** ka sochein.

- **Spread** **kholna** hai: aap do dabbe (`fruits`, `veg`) kholte hain aur sab kuch ek naye, bare dabbe me daal dete hain (`[...fruits, ...veg]`). Purane dabbe wahin hain, be-chhue.
- Objects milana **do jaghon se form bharne** jaisa hai: pehle default jawab copy karo, phir un ke upar apne jawab likho. Jo **aakhir** me likha wahi nazar aata hai.
- Magar ye **shallow** kholna hai: agar dabbe me **chhota band dabba** (nested object) hai, to aap wo band dabba waise hi le jate hain. Ab purane aur naye dono bare dabbon me **wahi** chhota dabba hai.
- **Rest** **bandhna** hai: "ye do mez par rakho, aur **baqi sab** is dabbe me" (`const [first, second, ...others]`).
- **Optional chaining** andar jane se pehle har kamra check karna hai: "Agar kitchen hai, aur agar us me fridge hai, to upar wale shelf par kya hai?" Agar koi kamra ghayab ho to deewar se takrane ke bajaye aap bas "kuch nahi" keh dete hain.

</Ur>
</Tr>

## Words you'll see

<Tr>
<En>

| Word | What it means | Example |
| --- | --- | --- |
| **Spread** | `...` that unpacks items or properties | `[...a]`, `{ ...o }` |
| **Rest** | `...` that gathers the remaining items | `(...args)` |
| **Iterable** | Something you can loop over with `for…of` | arrays, strings, Sets |
| **Shallow copy** | Copies the top level; nested objects are shared | `{ ...user }` |
| **Deep copy** | Copies every level | `structuredClone(user)` |
| **Immutable update** | Making a changed copy instead of editing | `{ ...item, qty: 2 }` |
| **Merge** | Combining objects; later keys win | `{ ...a, ...b }` |
| **Optional chaining** | `?.` stops at `null`/`undefined` | `user?.name` |
| **Short-circuit** | Skipping the rest of an expression | `null?.a.b.c` |
| **Destructuring** | Unpacking values into variables | `const { id } = item` |

</En>

| Lafz | Matlab | Misaal |
| --- | --- | --- |

## Learn it step by step

<Walkthrough>

<Step title="Spreading arrays">

<Tr>
<En>
Inside square brackets, `...array` drops all of that array's items in place. Use it to copy an array, combine several, or add items at the start or end, all **without changing** the originals. It works with any iterable: strings and Sets too.
</En>
<Ur>
Square brackets ke andar `...array` us array ke tamam items wahin daal deta hai. Ise array copy karne, kai jorne, ya shuru ya aakhir me items jorne ke liye istemal karein, sab asal ko **badle baghair**. Ye har iterable ke saath chalta hai: strings aur Sets bhi.
</Ur>
</Tr>

```javascript
const fruits = ["apple", "pear"];
const veg = ["carrot"];
const basket = [...fruits, "banana", ...veg];
console.log(basket);

const copy = [...fruits];
copy.push("kiwi");
console.log(fruits, copy, copy === fruits);

console.log(Math.max(...[3, 9, 4]), [..."hey"], [...new Set([1, 1, 2])]);
```

```text output
[ 'apple', 'pear', 'banana', 'carrot' ]
[ 'apple', 'pear' ] [ 'apple', 'pear', 'kiwi' ] false
9 [ 'h', 'e', 'y' ] [ 1, 2 ]
```

<Happened>
<Tr>
<En>

- `basket` is a **new** array built from the pieces; `fruits` and `veg` are unchanged.
- `[...fruits]` made a copy, so pushing "kiwi" to `copy` didn't affect `fruits`. Compare with `const copy = fruits`, which would share the same array.
- In a **function call**, spread passes items as separate arguments: `Math.max(...[3, 9, 4])` is `Math.max(3, 9, 4)`.
- `[..."hey"]` splits a string into characters (emoji-safe); `[...new Set(list)]` is the classic one-liner to **remove duplicates**.

</En>
<Ur>

- `basket` tukron se bani **nayi** array hai; `fruits` aur `veg` nahi badle.
- `[...fruits]` ne copy banayi, isliye `copy` me "kiwi" daalne se `fruits` par asar nahi hua. `const copy = fruits` se muqabla karein, jo wahi array share karta.
- **Function call** me spread items ko alag arguments ki tarah deta hai: `Math.max(...[3, 9, 4])` matlab `Math.max(3, 9, 4)`.
- `[..."hey"]` string ko characters me torta hai (emoji ke liye mehfooz); `[...new Set(list)]` **dohre hatane** ki mashhoor ek line hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Spreading objects: copy and merge">

<Tr>
<En>
Inside curly braces, `...object` copies its properties into the new object. When the same key appears twice, **the last one wins**. That makes defaults + overrides and "copy with one change" one-liners.
</En>
<Ur>
Curly braces ke andar `...object` us ki properties naye object me copy karta hai. Jab ek hi key do dafa aaye to **aakhri jeet-ti hai**. Is se defaults + overrides aur "ek tabdeeli ke saath copy" ek line me ban jate hain.
</Ur>
</Tr>

```javascript
const defaults = { theme: "light", fontSize: 16, sidebar: true };
const saved = { fontSize: 18 };
const settings = { ...defaults, ...saved };
console.log(settings);

const product = { id: 7, name: "Lamp", price: 30 };
const updated = { ...product, price: 25 };
console.log(product.price, updated.price, updated === product);

const withTag = { ...product, tags: ["sale"] };
console.log(withTag);

const flipped = { ...saved, ...defaults };
console.log(flipped.fontSize);
```

```text output
{ theme: 'light', fontSize: 18, sidebar: true }
30 25 false
{ id: 7, name: 'Lamp', price: 30, tags: [ 'sale' ] }
16
```

<Happened>
<Tr>
<En>

- `settings` took every default and replaced `fontSize` with the saved 18.
- `{ ...product, price: 25 }` made a new object with one change. `product` still costs 30: that's an **immutable update**.
- Adding a new key works the same way (`tags`).
- **Order matters**: in `flipped`, the defaults came last and overwrote the user's 18 with 16. Put the thing that should win **last**.

</En>
<Ur>

- `settings` ne har default liya aur `fontSize` ko mehfooz 18 se badal diya.
- `{ ...product, price: 25 }` ne ek tabdeeli ke saath naya object banaya. `product` ab bhi 30 ka hai: ye **immutable update** hai.
- Nayi key jorna bhi aise hi hota hai (`tags`).
- **Tarteeb ahem hai**: `flipped` me defaults aakhir me aaye aur user ke 18 ko 16 se badal diya. Jo cheez jeetni chahiye use **aakhir** me rakhein.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Shallow copies share nested objects">

<Tr>
<En>
Spread copies **one level**. Nested objects and arrays inside are **not** copied; the new object points to the same ones. Changing them through the copy changes the original. Use `structuredClone` for a full deep copy, or spread each level you change.
</En>
<Ur>
Spread **ek level** copy karta hai. Andar ke nested objects aur arrays copy **nahi** hote; naya object unhi ki taraf ishara karta hai. Copy ke zariye inhe badalna asal ko badal deta hai. Poori deep copy ke liye `structuredClone` lein, ya har wo level spread karein jo aap badal rahe hain.
</Ur>
</Tr>

```javascript
const user = { name: "Alex", address: { city: "Denver" }, tags: ["vip"] };

const clone = { ...user };
clone.name = "Sam";
clone.address.city = "Austin";
clone.tags.push("new");
console.log(user.name, user.address.city, user.tags);

const deep = structuredClone(user);
deep.address.city = "Boston";
console.log(user.address.city, deep.address.city);

const safer = { ...user, address: { ...user.address, city: "Seattle" } };
console.log(user.address.city, safer.address.city);
```

```text output
Alex Austin [ 'vip', 'new' ]
Austin Boston
Austin Seattle
```

<Happened>
<Tr>
<En>

- Changing `clone.name` didn't affect `user` (top level was copied). But `clone.address.city = "Austin"` and `clone.tags.push(…)` **did** change `user`: `address` and `tags` are the same objects in both.
- `structuredClone(user)` copied every level, so editing `deep.address` left `user` alone.
- `safer` spread the top level **and** the `address` level: a new address object with the new city. This is the pattern React state updates use.
- `structuredClone` can't copy functions, DOM nodes or class methods; for plain data it's perfect. (The Immutability and Copying lesson goes deeper.)

</En>
<Ur>

- `clone.name` badalne se `user` par asar nahi hua (upar ka level copy hua tha). Magar `clone.address.city = "Austin"` aur `clone.tags.push(…)` ne `user` **badal diya**: `address` aur `tags` dono me wahi objects hain.
- `structuredClone(user)` ne har level copy kiya, isliye `deep.address` badalne se `user` nahi badla.
- `safer` ne upar ka level **aur** `address` ka level spread kiya: nayi city ke saath naya address object. React state updates yahi pattern istemal karte hain.
- `structuredClone` functions, DOM nodes ya class methods copy nahi kar sakta; saade data ke liye behtareen hai. (Immutability and Copying lesson aur gehrai me jata hai.)

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Rest parameters and rest in destructuring">

<Tr>
<En>
In a function's parameters, `...name` **gathers** all remaining arguments into a real array. In destructuring, it gathers the remaining items or properties. It must always be **last**.
</En>
<Ur>
Function ke parameters me `...name` baqi tamam arguments ek asli array me **jama** karta hai. Destructuring me ye baqi items ya properties jama karta hai. Ise hamesha **aakhir** me hona chahiye.
</Ur>
</Tr>

```javascript
function total(...prices) {
  return prices.reduce((sum, p) => sum + p, 0);
}
console.log(total(), total(5), total(5, 10, 2.5));

function log(level, ...messages) {
  console.log(`[${level}]`, messages.join(" "));
}
log("info", "Server", "started", "on", "port", 3000);

const [first, second, ...others] = ["gold", "silver", "bronze", "4th", "5th"];
console.log(first, second, others);

const { password, ...safeUser } = { id: 1, email: "a@example.com", password: "hunter2" };
console.log(safeUser);
```

```text output
0 5 17.5
[info] Server started on port 3000
gold silver [ 'bronze', '4th', '5th' ]
{ id: 1, email: 'a@example.com' }
```

<Happened>
<Tr>
<En>

- `total` works with zero, one or many arguments; `prices` is always an array (empty when nothing is passed).
- `log` takes the first argument as `level` and gathers the rest into `messages`.
- Array destructuring took two medal winners and gathered the rest.
- Object rest is a clean way to **remove fields**: `safeUser` has everything except `password`, perfect before sending a user object to the browser.
- Before rest parameters, functions used the `arguments` object, which isn't a real array and doesn't exist in arrow functions. Prefer rest.

</En>
<Ur>

- `total` zero, ek ya bohot se arguments ke saath chalta hai; `prices` hamesha array hai (kuch na diya jaye to khaali).
- `log` pehla argument `level` ki tarah leta hai aur baqi `messages` me jama karta hai.
- Array destructuring ne do medal jeetne wale liye aur baqi jama kiye.
- Object rest **fields hatane** ka saaf tareeqa hai: `safeUser` me `password` ke siwa sab hai, user object browser ko bhejne se pehle behtareen.
- Rest parameters se pehle functions `arguments` object istemal karte the, jo asli array nahi aur arrow functions me hota hi nahi. Rest ko tarjeeh dein.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Updating lists without changing them">

<Tr>
<En>
Combine spread with array methods to add, change and remove items in a **new** array. Untouched items are reused, and only the changed item is a new object. This is how React and many state libraries detect changes.
</En>
<Ur>
Spread ko array methods ke saath mila kar **nayi** array me items jorein, badlein aur hatayen. Be-chhue items dobara istemal hote hain, aur sirf badla hua item naya object hota hai. React aur bohot si state libraries tabdeeliyan isi tarah pehchanti hain.
</Ur>
</Tr>

```javascript
const cart = [
  { id: 1, qty: 1 },
  { id: 2, qty: 3 },
];

const added = [...cart, { id: 3, qty: 1 }];
const changed = cart.map((item) => (item.id === 2 ? { ...item, qty: item.qty + 1 } : item));
const removed = cart.filter((item) => item.id !== 1);

console.log(cart);
console.log(added.length, changed, removed);
console.log(changed[0] === cart[0], changed[1] === cart[1]);
```

```text output
[ { id: 1, qty: 1 }, { id: 2, qty: 3 } ]
3 [ { id: 1, qty: 1 }, { id: 2, qty: 4 } ] [ { id: 2, qty: 3 } ]
true false
```

<Happened>
<Tr>
<En>

| Action | Pattern |
| --- | --- |
| Add | `[...list, newItem]` (or `[newItem, ...list]` at the start) |
| Change one | `list.map(x => x.id === id ? { ...x, field: value } : x)` |
| Remove | `list.filter(x => x.id !== id)` |

- `cart` itself never changed.
- `changed[0] === cart[0]` is **true**: the untouched item is the same object, reused. `changed[1]` is a new object. A quick `===` check tells React exactly which items changed.

</En>
<Ur>

| Kaam | Pattern |
| --- | --- |
| Jorna | `[...list, newItem]` (ya shuru me `[newItem, ...list]`) |
| Ek badalna | `list.map(x => x.id === id ? { ...x, field: value } : x)` |
| Hatana | `list.filter(x => x.id !== id)` |

- Khud `cart` kabhi nahi badla.
- `changed[0] === cart[0]` **true** hai: be-chhua item wahi object hai, dobara istemal hua. `changed[1]` naya object hai. Ek jaldi wala `===` check React ko bilkul batata hai ke kaun se items badle.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Spread and rest in function signatures">

<Tr>
<En>
Rest in object destructuring is great for components and helpers that take **options**: pick out what you use and pass "everything else" along. Spread in calls turns an array into arguments.
</En>
<Ur>
Object destructuring me rest un components aur helpers ke liye behtareen hai jo **options** lete hain: jo istemal karna hai wo nikaal lein aur "baqi sab" aage bhej dein. Calls me spread array ko arguments me badalta hai.
</Ur>
</Tr>

```javascript
function createButton({ label, variant = "primary", ...rest }) {
  return { label, variant, attributes: rest };
}
console.log(createButton({ label: "Save", disabled: true, "aria-label": "Save profile" }));

const args = [2026, 10, 12];
console.log(new Date(Date.UTC(...args)).toISOString());

const withGetter = { x: 1, get y() { return 2; } };
console.log({ ...withGetter });
console.log({ ...null }, { ...undefined }, { ...[10, 20] });
```

```text output
{
  label: 'Save',
  variant: 'primary',
  attributes: { disabled: true, 'aria-label': 'Save profile' }
}
2026-11-12T00:00:00.000Z
{ x: 1, y: 2 }
{} {} { '0': 10, '1': 20 }
```

<Happened>
<Tr>
<En>

- `createButton` used `label` and `variant` (with a default) and passed the rest (`disabled`, `aria-label`) along. React components do exactly this: `function Button({ variant, ...props }) { return <button {...props} /> }`.
- `Date.UTC(...args)` passed the three numbers as separate arguments (months start at 0, so `10` is November).
- Object spread runs getters and copies their **values** (`y: 2`), not the getter itself.
- Spreading `null` or `undefined` into an object gives nothing (no error). Spreading an array into an object uses its indexes as keys.

</En>
<Ur>

- `createButton` ne `label` aur `variant` (default ke saath) istemal kiye aur baqi (`disabled`, `aria-label`) aage bhej diye. React components bilkul yahi karte hain: `function Button({ variant, ...props }) { return <button {...props} /> }`.
- `Date.UTC(...args)` ne teen numbers alag arguments ki tarah diye (mahine 0 se shuru hote hain, isliye `10` November hai).
- Object spread getters chalata hai aur un ki **values** copy karta hai (`y: 2`), khud getter nahi.
- Object me `null` ya `undefined` spread karna kuch nahi deta (error nahi). Array ko object me spread karna us ke indexes ko keys bana deta hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Optional chaining with ?.">

<Tr>
<En>
Reading a property of `null` or `undefined` throws a `TypeError`. `?.` checks the value on its left: if it's `null` or `undefined`, the whole chain **stops and returns `undefined`**. It has three forms: `a?.b` (property), `a?.[key]` (bracket/index) and `a?.()` (call).
</En>
<Ur>
`null` ya `undefined` ki property parhna `TypeError` phenkta hai. `?.` apne baayen ki value check karta hai: agar wo `null` ya `undefined` ho to poori zanjeer **ruk kar `undefined` wapas karti** hai. Is ki teen shaklen hain: `a?.b` (property), `a?.[key]` (bracket/index) aur `a?.()` (call).
</Ur>
</Tr>

```javascript
const order = {
  id: 1042,
  customer: { name: "Sam", address: null },
  items: [{ name: "Mug", options: { color: "red" } }],
  notify: undefined,
};

console.log(order.customer?.name);
console.log(order.customer?.address?.city);
console.log(order.items?.[0]?.options?.color);
console.log(order.items?.[5]?.name);
console.log(order.notify?.("shipped"));
console.log(order.coupon?.code ?? "no coupon");

try {
  console.log(order.customer.address.city);
} catch (error) {
  console.log(error.message);
}
```

```text output
Sam
undefined
red
undefined
undefined
no coupon
Cannot read properties of null (reading 'city')
```

<Happened>
<Tr>
<En>

- `address` is `null`, so `address?.city` stopped and gave `undefined` instead of crashing.
- `items?.[0]?.options?.color` walked through an array index and two nested objects safely.
- `notify?.("shipped")` called the function only if it existed; here it didn't, so nothing ran.
- `?? "no coupon"` turned the `undefined` into a friendly default.
- Without `?.`, the same read threw "Cannot read properties of null". (Note it says `null` here, because `address` was `null`, not `undefined`.)

</En>
<Ur>

- `address` `null` hai, isliye `address?.city` crash hone ke bajaye ruk kar `undefined` diya.
- `items?.[0]?.options?.color` array index aur do nested objects se mehfooz guzra.
- `notify?.("shipped")` ne function sirf tab call kiya jab wo maujood ho; yahan nahi tha, isliye kuch nahi chala.
- `?? "no coupon"` ne `undefined` ko dostana default me badla.
- `?.` ke baghair wahi parhna "Cannot read properties of null" phenk gaya. (Ghaur karein yahan `null` likha hai, kyun ke `address` `null` tha, `undefined` nahi.)

</Ur>
</Tr>
</Happened>

</Step>

<Step title="How far ?. stops">

<Tr>
<En>
When `?.` finds `null`/`undefined`, it **short-circuits** the whole rest of the chain: nothing to its right is evaluated, not even function calls in brackets. But `?.` only protects the spot where you wrote it: a later plain `.` after a value that **exists** can still crash.
</En>
<Ur>
Jab `?.` ko `null`/`undefined` mile to ye zanjeer ka poora baqi hissa **short-circuit** kar deta hai: is ke daayen kuch bhi evaluate nahi hota, brackets ke andar function calls bhi nahi. Magar `?.` sirf us jagah ki hifazat karta hai jahan aap ne use likha: kisi **maujood** value ke baad ka saada `.` ab bhi crash kar sakta hai.
</Ur>
</Tr>

```javascript
let calls = 0;
const getId = () => {
  calls++;
  return 1;
};

const missing = null;
console.log(missing?.[getId()], calls);

const obj = { a: null };
console.log(obj?.a?.b.c.d);

const profile = { settings: {} };
try {
  console.log(profile?.settings.theme.color);
} catch (error) {
  console.log(error.message);
}
```

```text output
undefined 0
undefined
Cannot read properties of undefined (reading 'color')
```

<Happened>
<Tr>
<En>

- `getId()` was never called: once `missing` was `null`, everything after `?.` was skipped.
- `obj?.a?.b.c.d`: `a` is `null`, so the `?.` before `b` stopped the chain; the plain `.c.d` after it were never reached.
- `profile?.settings.theme.color` crashed: `settings` exists, `theme` is `undefined`, and the `.color` after it had no `?.`. Put `?.` **after every part that may be missing**: `settings.theme?.color`.

</En>
<Ur>

- `getId()` kabhi call nahi hua: `missing` ke `null` hote hi `?.` ke baad sab chhor diya gaya.
- `obj?.a?.b.c.d`: `a` `null` hai, isliye `b` se pehle wale `?.` ne zanjeer rok di; us ke baad ke saade `.c.d` tak pohancha hi nahi gaya.
- `profile?.settings.theme.color` crash hua: `settings` maujood hai, `theme` `undefined` hai, aur us ke baad ke `.color` par `?.` nahi tha. **Har us hisse ke baad** `?.` lagayen jo ghayab ho sakta hai: `settings.theme?.color`.

</Ur>
</Tr>
</Happened>

</Step>

## Common mistakes

<Compare>
<Bad title="Thinking spread makes a deep copy">

```javascript
const original = { prefs: { dark: false } };
const copy = { ...original };
copy.prefs.dark = true;
console.log(original.prefs.dark);
```

```text output
true
```

</Bad>
<Good title="Spread every level you change (or structuredClone)">

```javascript
const original = { prefs: { dark: false } };
const copy = { ...original, prefs: { ...original.prefs, dark: true } };
console.log(original.prefs.dark, copy.prefs.dark);
```

```text output
false true
```

</Good>
</Compare>

<Compare>
<Bad title="Defaults placed last">

```javascript
const userChoice = { currency: "EUR" };
const options = { ...userChoice, currency: "USD", decimals: 2 };
console.log(options.currency);
```

```text output
USD
```

</Bad>
<Good title="Defaults first, overrides last">

```javascript
const userChoice = { currency: "EUR" };
const options = { currency: "USD", decimals: 2, ...userChoice };
console.log(options.currency);
```

```text output
EUR
```

</Good>
</Compare>

<Compare>
<Bad title="Mutating, then expecting a change to be noticed">

```javascript
const state = { items: ["Mug"] };
const next = state;
next.items.push("Lamp");
console.log(next === state, state.items);
```

```text output
true [ 'Mug', 'Lamp' ]
```

</Bad>
<Good title="New object, new array">

```javascript
const state = { items: ["Mug"] };
const next = { ...state, items: [...state.items, "Lamp"] };
console.log(next === state, state.items, next.items);
```

```text output
false [ 'Mug' ] [ 'Mug', 'Lamp' ]
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Putting rest anywhere but last**: `function f(...a, b)` and `const [...a, b] = x` are SyntaxErrors.
- **Using `?.` on the left of an assignment**: `user?.name = "x"` is a SyntaxError. Check first, then assign.
- **Sprinkling `?.` on required data**, which turns a clear crash into a silent `undefined` deep inside your UI.
- **Spreading huge arrays into function calls** (`Math.max(...millionItems)`) can exceed the argument limit. Use a loop or `reduce`.
- **Using `{ ...obj }` to copy class instances**: you get a plain object without the class's methods.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Rest ko aakhir ke siwa kahin rakhna**: `function f(...a, b)` aur `const [...a, b] = x` SyntaxErrors hain.
- **Assignment ke baayen `?.` lagana**: `user?.name = "x"` SyntaxError hai. Pehle check karein, phir value dein.
- **Zaroori data par `?.` chhirakna**, jo saaf crash ko UI ke andar gehre khamosh `undefined` me badal deta hai.
- **Bohot bari arrays function calls me spread karna** (`Math.max(...millionItems)`) arguments ki hadd paar kar sakta hai. Loop ya `reduce` lein.
- **Class instances copy karne ke liye `{ ...obj }`**: aap ko class ke methods ke baghair saada object milta hai.

</Ur>
</Tr>

## Remember

<Takeaways>
<Tr>
<En>

- **Spread** `...` unpacks: `[...a, ...b]`, `{ ...a, ...b }`, `fn(...args)`. It works with any iterable for arrays and any object for objects.
- In object spread, **later keys win**: defaults first, overrides last.
- Spread copies are **shallow**: spread every nested level you change, or use `structuredClone`.
- Immutable updates: add `[...list, x]`, change `map` + `{ ...x, … }`, remove `filter`.
- **Rest** `...` gathers: `function f(...args)`, `const [a, ...others]`, `const { secret, ...safe }`. Always last.
- **`?.`** stops at `null`/`undefined` and returns `undefined`: `a?.b`, `a?.[i]`, `a?.()`. Pair it with `??`.
- Use `?.` only where data is allowed to be missing; place it after each part that may be missing.

</En>
<Ur>

- **Spread** `...` kholta hai: `[...a, ...b]`, `{ ...a, ...b }`, `fn(...args)`. Arrays ke liye har iterable aur objects ke liye har object ke saath chalta hai.
- Object spread me **baad wali keys jeet-ti hain**: defaults pehle, overrides aakhir me.
- Spread copies **shallow** hain: har wo nested level spread karein jo badal rahe hain, ya `structuredClone` lein.
- Immutable updates: jorna `[...list, x]`, badalna `map` + `{ ...x, … }`, hatana `filter`.
- **Rest** `...` jama karta hai: `function f(...args)`, `const [a, ...others]`, `const { secret, ...safe }`. Hamesha aakhir me.
- **`?.`** `null`/`undefined` par ruk kar `undefined` deta hai: `a?.b`, `a?.[i]`, `a?.()`. Ise `??` ke saath lein.
- `?.` sirf wahan lein jahan data ka ghayab hona jaiz ho; har us hisse ke baad lagayen jo ghayab ho sakta hai.

</Ur>

<DeepDive title="More about spread, rest and ?.">

**What object spread copies.** Own, enumerable properties only (including symbol keys). It **doesn't** copy the prototype (so class methods are lost), property attributes, getters/setters (it copies their current values), or non-enumerable properties.

**`Object.assign` vs spread.** `Object.assign(target, a, b)` copies into an **existing** object (mutating it) and triggers setters; `{ ...a, ...b }` always creates a new object. Prefer spread unless you need to mutate.

**Array spread uses the iterator protocol**, so it works on strings, Maps (`[...map]` gives `[key, value]` pairs), Sets, generator results and `arguments`. Object spread doesn't use iterators.

**Performance.** Spreading a big object or array is a full copy, O(n). In hot loops (thousands of times per second) or with huge collections, mutate a local copy once instead of spreading on every step.

**`structuredClone` vs JSON.** `JSON.parse(JSON.stringify(x))` loses dates (become strings), `undefined`, `Map`, `Set`, `BigInt` (throws) and circular references (throws). `structuredClone` handles all of those, but not functions or class prototypes.

**Optional chaining vs `&&`.** Older code wrote `user && user.address && user.address.city`. `?.` is shorter and only stops on `null`/`undefined`, while `&&` also stops on `0`, `""` and `false`.

</DeepDive>

<DeepDive title="Real world: the cart that wouldn't update">

A React shopping cart kept its items in state. To change a quantity, a developer wrote:

```text
function increase(id) {
  const item = cart.find((i) => i.id === id);
  item.qty += 1;
  setCart(cart);
}
```

Clicking "+" did nothing on screen. Then, after clicking something unrelated, the quantity suddenly jumped by 3. The bug: `setCart(cart)` passed the **same array** React already had. React compares old and new state with `Object.is`; it saw "no change" and skipped the re-render. The mutations were still happening in memory, so the next unrelated re-render revealed all of them at once.

The fix was an immutable update:

```text
setCart((cart) => cart.map((i) => (i.id === id ? { ...i, qty: i.qty + 1 } : i)));
```

A new array and a new object for the changed item meant React saw the change immediately, and memoised rows for unchanged items didn't re-render.

Lesson: in React (and Redux, Zustand and similar), **never mutate state**. Create new objects with spread, `map` and `filter`.

</DeepDive>

<DeepDive title="Security lens">

- **Mass assignment.** `const user = { ...defaults, ...req.body }` lets a client add **any** field, such as `role: "admin"` or `isVerified: true`. Pick allowed fields explicitly or validate with a schema before spreading.
- **Prototype pollution.** Deep-merge helpers that walk user JSON can be tricked by keys like `__proto__`. Object spread itself is safe here (it creates a normal own property), but custom recursive merges and old library versions aren't. Validate input and keep libraries updated.
- **Leaking fields.** Use rest to strip secrets before sending data: `const { passwordHash, resetToken, ...publicUser } = user`. Better still, build the public object from an **allow-list** of fields.
- **`?.` can hide missing authorisation data.** `if (session?.user?.isAdmin)` safely denies when data is missing, but `if (!session?.user?.isBanned)` allows access when the field is missing. Write checks so that missing means "deny".

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What is the difference between spread and rest syntax?">
Both use three dots. Spread expands an iterable or object into individual elements or properties, in array literals, object literals and function calls. Rest collects multiple elements into one array or object, in function parameters and destructuring patterns, and must be last.
</QA>

<QA q="Does object spread create a deep copy?">
No. It copies own enumerable properties one level deep, so nested objects and arrays are shared references. Use structuredClone for a deep copy of plain data, or spread each nested level that needs to change.
</QA>

<QA q="How do you update an item in an array immutably?">
Map over the array and return a new object for the matching item using spread, for example with a map callback that returns a spread copy with the changed field for the matching id, leaving other items as the same references.
</QA>

<QA q="How does optional chaining short-circuit?">
If the value before ?. is null or undefined, the entire remaining member access, call or index chain is skipped and the expression evaluates to undefined; expressions inside skipped brackets or call arguments are not evaluated.
</QA>

<QA q="When would you avoid spreading request data into an object?">
When the data comes from a client, because it allows mass assignment of fields the client shouldn't control, such as roles or flags. Validate and copy only allowed fields instead.
</QA>

</DeepDive>
