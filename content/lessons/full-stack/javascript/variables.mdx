<BigIdea>
A **variable is a box with a name on it.** You put a value inside the box. Later, you use the name to get the value back.
</BigIdea>

## At a glance

<Glance>
<What>
A name that holds a value, like `total` holding `430`.
</What>
<Why>
Programs need to **remember** things: the user's name, the items in a cart, a score.
</Why>
<When>
Almost every line of code. Any value you will need again goes in a variable.
</When>
<How>
`const name = value;` for values that stay the same. `let name = value;` for values that will change.
</How>
</Glance>

## Picture it

Think of a shopkeeper adding up a bill on paper. He writes **Total: 0**. The customer buys bread for 150, so he crosses it out and writes **150**. Then milk for 280, so he writes **430**. He needed a place to **write a number**, give it a **name**, **change** it and **read** it later. That place is a variable.

<Boxes caption="Each variable is a labelled box. The label is the name, the inside is the value.">
<Box name="shopName">"Alex General Store"</Box>
<Box name="total" note="changed twice: 0 → 150 → 430">430</Box>
<Box name="isOpen">true</Box>
</Boxes>

## Learn it step by step

Press **Run** on any example to see it work. Press **Edit** to change the code and run your own version.

<Walkthrough>

<Step title="Make your first variable">

Write a keyword (`const`), a name, `=`, and a value. After that, the name gives you the value.

```javascript
const city = "Austin";
const temperature = 31;
console.log("City:", city);
console.log(city + " is " + temperature + " degrees today");
```

```text output
City: Austin
Austin is 31 degrees today
```

<Happened>

- `const city = "Austin";` makes a box named `city` and puts the text `"Austin"` in it. **Text goes inside quotes.**
- Numbers like `31` don't use quotes.
- `console.log(...)` prints things so you can see them.
- `+` joins pieces of text into one sentence.

</Happened>

</Step>

<Step title="Change a value with let">

Some values must change: a score, a counter, a running total. Make them with `let`.

```javascript
let score = 10;
console.log(score);
score = score + 5;
console.log(score);
score += 5;
console.log(score);
```

```text output
10
15
20
```

<Happened>

- `score = score + 5` means: **take the old score, add 5, put the result back in the box.**
- `score += 5` is the short way to write the same thing.

</Happened>

<Callout type="warning" title="= does not mean 'equals'">
In maths, `x = x + 5` is impossible. In code, `=` means **"work out the right side, then store it in the left side"**. To *compare* two values, JavaScript uses `===`.
</Callout>

</Step>

<Step title="Lock a value with const">

`const` makes a box you **can't refill**. If you try, JavaScript stops you with an error. That protects you from changing something important by mistake.

```javascript
const TAX_RATE = 0.17;
const price = 1000;
console.log("Total with tax:", price + price * TAX_RATE);

try {
  TAX_RATE = 0.2;
} catch (error) {
  console.log("Error:", error.message);
}
```

```text output
Total with tax: 1170
Error: Assignment to constant variable.
```

<Happened>

- The tax rate should never change while the program runs, so it's a `const`.
- Trying to change it gives the error **"Assignment to constant variable."**
- `try { … } catch { … }` means "try this, and if it fails, run the second part instead of crashing". It's only here so you can see the message.

</Happened>

</Step>

<Step title="Which one should I use?">

Ask yourself one question: **"Will I put a different value in this box later?"**

<Flow caption="Start with const. Switch to let only if you really need to change the value.">
<FlowStep>New variable</FlowStep>
<FlowStep>Will the value change later?</FlowStep>
<FlowStep>No → **const** (most of the time)</FlowStep>
<FlowStep>Yes → **let**</FlowStep>
</Flow>

| Keyword | Can you change the value? | Use it? |
| --- | --- | --- |
| `const` | No | **Yes, by default** |
| `let` | Yes | When the value must change |
| `var` | Yes | **No.** It's the old way, with surprising bugs |

You will still see `var` in old code and tutorials. Read it, but don't write it. (The "Go deeper" section at the end shows exactly what goes wrong with `var`.)

</Step>

<Step title="A box can hold any kind of value">

Numbers, text, true/false, lists and more. The kind of value is called its <Def tip="The kind of value: number, string (text), boolean (true/false), array (list), object (record) and a few more.">type</Def>.

```javascript
const age = 24;                              // number
const name = "Sam";                          // string (text)
const isLoggedIn = true;                     // boolean (true or false)
const cart = ["bread", "milk"];              // array (a list)
const user = { name: "Sam", role: "admin" }; // object (a record)
let notSetYet;                               // undefined (empty box)

console.log(typeof age, typeof name, typeof isLoggedIn);
console.log(cart[0], "and", cart.length, "items");
console.log(user.name, "is", user.role);
console.log(notSetYet);
```

```text output
number string boolean
bread and 2 items
Sam is admin
undefined
```

<Happened>

- `typeof` tells you the type of a value.
- `cart[0]` is the **first** item in the list. Counting starts at 0.
- `user.name` reads the `name` part of the object.
- `notSetYet` was made with no value, so it's `undefined`: an empty box.

</Happened>

Each type has its own lesson next: **Data Types**.

</Step>

<Step title="A variable only lives inside its { }">

A variable made inside curly braces `{ }` only exists **inside those braces**. That area is its <Def tip="The part of the code where a variable name can be used. For let and const, it's the nearest pair of curly braces.">scope</Def>.

<Callout type="analogy">
Think of a house. Something kept in the **living room** can be seen from every room. Something kept in **your bedroom** can't be seen from the living room. You can look out of your room, but nobody can look in.
</Callout>

```javascript
const appName = "DevGuide";          // living room: visible everywhere

if (true) {
  const badge = "★";                 // bedroom: only inside these braces
  console.log(appName, badge);       // inside: both work
}

console.log(typeof badge);           // outside: badge doesn't exist
```

```text output
DevGuide ★
undefined
```

<Happened>

- Inside the braces, the code can see `badge` **and** the outer `appName`.
- After the closing `}`, `badge` is gone. `typeof` reports `"undefined"` instead of crashing.
- This keeps different parts of a program from accidentally changing each other's variables.

</Happened>

</Step>

<Step title="const with lists and objects: the label is glued, the box can still be filled">

`const` stops you **swapping the box**. It does **not** stop you changing what's **inside** a list or object.

```javascript
const cart = ["bread"];
cart.push("milk");                 // allowed: adding inside the same box
console.log(cart);

try {
  cart = ["eggs"];                 // not allowed: a different box
} catch (error) {
  console.log("Error:", error.message);
}
```

```text output
[ 'bread', 'milk' ]
Error: Assignment to constant variable.
```

<Happened>

- `push` adds an item to the **same** list, so it's allowed.
- `cart = [...]` would put a **new** list in the box, which `const` forbids.
- This surprises almost every beginner, so remember: **const = the label stays on this box**.

</Happened>

</Step>

<Step title="Copying: numbers get a photocopy, objects share one copy">

When you copy a number or text into another variable, you get a **separate copy**. When you copy an object or list, both names point to the **same** object.

<Callout type="analogy">
A number is like a **photocopy**: scribble on your copy and the original stays clean. An object is like a **shared Google Doc link**: if someone edits through their link, you see the change too.
</Callout>

```javascript
let a = 10;
let b = a;              // a photocopy of 10
b = 20;
console.log("numbers:", a, b);

const original = { qty: 1 };
const sameObject = original;        // the same object, a second name
sameObject.qty = 99;
console.log("original:", original.qty);

const realCopy = { ...original };   // a brand-new object
realCopy.qty = 5;
console.log("original:", original.qty, "copy:", realCopy.qty);
```

```text output
numbers: 10 20
original: 99
original: 99 copy: 5
```

<Happened>

- Changing `b` didn't touch `a`.
- Changing `sameObject` **also** changed `original`, because they are one object with two names.
- `{ ...original }` makes a real copy, so changing it leaves the original alone.

</Happened>

</Step>

<Step title="Give variables good names">

Good names explain your code. Bad names hide bugs.

| Rule (code breaks if you ignore it) | Good | Bad |
| --- | --- | --- |
| Letters, digits, `_` and `$` only | `user_1` | `user-name`, `total amount` |
| Can't start with a digit | `user1` | `1user` |
| Not a special word | `className` | `class`, `let` |
| Capitals matter | `total` and `Total` are **different** | |

| Habit (what professionals do) | Example |
| --- | --- |
| `camelCase` for normal variables | `cartTotal`, `userName` |
| `UPPER_CASE` for fixed settings | `TAX_RATE`, `MAX_RETRIES` |
| `is` / `has` / `can` for true/false | `isLoggedIn`, `hasAccess` |
| Plural names for lists | `users`, `orderIds` |

Name a value by **what it means**: `daysUntilExpiry`, not `d`.

</Step>

</Walkthrough>

## Common mistakes

<Compare>
<Bad title="Using var in new code">

```javascript
var total = 0;
```

`var` ignores `{ }` and lets you create the same name twice without warning.

</Bad>
<Good title="Use const, or let if it changes">

```javascript
let total = 0;
```

Clear rules, and JavaScript warns you about mistakes.

</Good>
</Compare>

<Compare>
<Bad title="let for everything">

```javascript
let price = 1000;
let name = "Kent";
```

Nobody can tell which values are meant to change.

</Bad>
<Good title="const unless it changes">

```javascript
const price = 1000;
const name = "Kent";
```

Readers instantly know these stay the same.

</Good>
</Compare>

<Compare>
<Bad title="Forgetting the keyword (typo)">

```javascript
let total = 100;
totl = 500;   // ReferenceError: totl is not defined
```

</Bad>
<Good title="Always declare with const or let">

```javascript
let total = 100;
total = 500;
```

If you see "X is not defined", check the spelling.

</Good>
</Compare>

<Compare>
<Bad title="Editing a 'copy' of an object">

```javascript
const copy = original;
copy.qty = 0;   // original changes too!
```

</Bad>
<Good title="Make a real copy first">

```javascript
const copy = { ...original };
copy.qty = 0;   // original is safe
```

</Good>
</Compare>

## Try it yourself

<Challenge title="Replace every var with const or let">

This code works, but it uses the old `var` everywhere. Press **Edit**, change each `var` to `const` or `let`, then press **Run**. The output should still be `Total: 4095`.

```javascript
var TAX_RATE = 0.17;
var items = [{ price: 1000 }, { price: 2500 }];
var subtotal = 0;
for (var k = 0; k < items.length; k++) {
  subtotal += items[k].price;
}
var total = subtotal + subtotal * TAX_RATE;
console.log("Total:", total);
```

```text output
Total: 4095
```

<Hint>
Ask "will this box get a new value later?" for each one. Look for `=` or `+=` after the first line, and remember that the loop counter goes up every round.
</Hint>

<Solution>

`subtotal` and the loop counter `k` change, so they need `let`. Everything else is set once, so it's `const`.

```javascript
const TAX_RATE = 0.17;
const items = [{ price: 1000 }, { price: 2500 }];
let subtotal = 0;
for (let k = 0; k < items.length; k++) {
  subtotal += items[k].price;
}
const total = subtotal + subtotal * TAX_RATE;
console.log("Total:", total);
```

```text output
Total: 4095
```

</Solution>

</Challenge>

<Challenge title="Predict the output, then run it">

Write down what you think each line prints. Then press **Run** and compare.

```javascript
const fruits = ["mango"];
fruits.push("apple");
let count = fruits.length;
count = count + 1;
console.log(fruits.length, count);
```

```text output

```

<Hint>
`push` adds to the same list. `count` is a separate number copied from the list's length.

<Solution>
The list has 2 items, so `fruits.length` is 2. `count` started as a copy of 2 and then became 3. Changing `count` doesn't change the list.

## Remember

<Takeaways>

- A variable is a **named box** for a value.
- Use **`const` by default**, **`let`** only when the value changes, and **never `var`** in new code.
- `=` means **store**, not "equals".
- `let` and `const` only live **inside their `{ }`**.
- `const` lists and objects can still have their **contents** changed.
- Copying an object **doesn't** make a new object; use `{ ...obj }`.
- Pick names that say **what the value means**.

</Takeaways>

## Go deeper

These are optional. Open them when you're comfortable with the basics, or when preparing for interviews.

<DeepDive title="Why var leaks out of { } (and the famous setTimeout puzzle)">

`var` ignores `if` and loop braces; only a **function** contains it. That's the main reason `let` and `const` were added in 2015.

```javascript
if (true) {
  var leaked = "var escaped the block";
  let contained = "let stays inside";
}
console.log(leaked);
console.log(typeof contained);
```

```text output
var escaped the block
undefined
```

The classic interview puzzle caused by this:

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log("var:", i), 0);
}
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log("let:", j), 0);
}
```

```text output
var: 3
var: 3
var: 3
let: 0
let: 1
let: 2
```

- `setTimeout(…, 0)` means "run this a moment later, after the current code finishes".
- With `var` there is **one** `i` for the whole loop. By the time the delayed code runs, the loop is over and `i` is 3.
- With `let`, every round gets its **own** `j`, so each delayed function remembers its own number.

</DeepDive>

<DeepDive title="Hoisting and the Temporal Dead Zone">

Before running your code, JavaScript scans it and notes every variable name. This is called **hoisting**. What a name holds before its line runs depends on the keyword:

```javascript
console.log(oldStyle);            // var: no error, just undefined
var oldStyle = "var value";

try {
  console.log(modern);            // let: in the Temporal Dead Zone
} catch (error) {
  console.log(error.name + ":", error.message);
}
let modern = "let value";

console.log(sayHi());             // function declarations work early
function sayHi() { return "hi from a hoisted function"; }
```

```text output
undefined
ReferenceError: Cannot access 'modern' before initialization
hi from a hoisted function
```

- `var` gives a silent `undefined`, which hides bugs.
- `let`/`const` give a clear error. The time between the start of the block and their line is called the **Temporal Dead Zone (TDZ)**.
- The loud error is a **good thing**: using a value before it's set is almost always a mistake.

</DeepDive>

<DeepDive title="Same name twice, and shadowing">

`var` lets you create the same name twice without any warning. `let` and `const` refuse with `SyntaxError: Identifier 'y' has already been declared`.

Making the same name in an **inner** block is allowed. It's called **shadowing**: the inner name hides the outer one inside those braces.

```javascript
var x = 1;
var x = 2;                   // var: silently allowed
console.log("x is", x);

const level = "outer";
{
  const level = "inner";     // a different variable with the same name
  console.log("inside:", level);
}
console.log("outside:", level);
```

```text output
x is 2
inside: inner
outside: outer
```

</DeepDive>

<DeepDive title="Forgetting the keyword creates a global (in old code)">

In old JavaScript, writing `totl = 500` without a keyword silently created a **global** variable, usually because of a typo. Modern code (modules, React, Next.js, Node.js modules, TypeScript) runs in **strict mode**, which throws an error instead:

```javascript
"use strict";
let total = 100;
try {
  totl = 500;               // typo, never declared
} catch (error) {
  console.log(error.name + ":", error.message);
}
console.log("total is still", total);
```

```text output
ReferenceError: totl is not defined
total is still 100
```

</DeepDive>

<DeepDive title="Freezing objects and deep copies">

To stop the **contents** of an object from changing, use `Object.freeze`:

```javascript
const settings = Object.freeze({ theme: "dark" });
try {
  settings.theme = "light";       // frozen: an error in strict mode
} catch (error) {
  console.log("Frozen:", error.name);
}
console.log(settings.theme);
```

```text output
Frozen: TypeError
dark
```

- `Object.freeze` is **shallow**: objects inside the object can still change.
- `{ ...obj }` copies only the top level. For a full copy of nested data, use `structuredClone(obj)`.

</DeepDive>

<DeepDive title="Variables and memory">

While a value can be reached through some variable, it stays in memory (RAM). When nothing points to it any more, JavaScript's **garbage collector** frees that memory automatically.

**Memory leaks** happen when a long-living variable (a global, a module-level array, a cache) keeps pointing to data that should have been thrown away. Memory use grows until the app slows down or crashes. Keep variables in the smallest scope that works, and give caches a size limit.

</DeepDive>

<DeepDive title="Real-world bug: one variable shared by every user">

A Next.js API route keeps a list of "recent searches" in a variable at the top of the file:

```javascript
// app/api/search/route.js — BUG: module-level state
let recentSearches = [];                  // lives as long as the server process

export async function GET(request) {
  const q = new URL(request.url).searchParams.get("q");
  recentSearches.push(q);                 // every user's searches go into ONE array
  return Response.json({ recent: recentSearches.slice(-5) });
}
```

It "works" on a laptop. In production:

1. **Privacy leak:** user A sees user B's searches, because every request shares the same variable.
2. **Memory leak:** the array grows forever.
3. **Inconsistency:** with several server instances, each has its own copy, so results jump around.

The fix is about **scope**: per-request data lives in variables **inside** the handler, per-user data lives in a database keyed by user ID, and only shared read-only things (a database client, settings) belong at the top of the file, as `const`.

```javascript
// Fixed
import { db } from "@/lib/db";            // shared client: module-level const is correct

export async function GET(request) {
  const userId = await getUserId(request);           // per request
  const q = new URL(request.url).searchParams.get("q");
  await db.search.create({ data: { userId, q } });
  const recent = await db.search.findMany({ where: { userId }, take: 5, orderBy: { id: "desc" } });
  return Response.json({ recent: recent.map((r) => r.q) });
}
```

</DeepDive>

<DeepDive title="Security lens">

Variables decide **where** data lives and **who** can reach it.

- **Shared state across requests** (module-level `let` in Node.js/Next.js) can leak one user's data to another.
- **Secrets in front-end variables are public.** Anything in browser JavaScript, including `NEXT_PUBLIC_*` and `VITE_*` environment variables, is visible to every visitor in DevTools. Real API keys must stay on the server.
- **Accidental globals** (old non-strict code) can be read or overwritten by any other script on the page, including injected attacker scripts.
- **Logging whole objects** (`console.log(user)`) can write passwords and tokens into logs. Log specific, safe fields.
- **Prototype pollution:** merging untrusted JSON into objects (`Object.assign(config, req.body)`) can change the behaviour of every object in the app. Validate input and copy only known fields.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What are the differences between var, let and const?">
var is function-scoped, can be re-declared, and is hoisted with the value undefined; at the top level of a classic script it also becomes a property of the global object. let and const are block-scoped, cannot be re-declared in the same scope, and are in the temporal dead zone until their declaration runs, so early access throws a ReferenceError. const must be initialized and cannot be reassigned, though objects it refers to can still be mutated.
</QA>

<QA q="What is hoisting?">
Before executing a scope, JavaScript registers all declarations in it. var declarations are initialized to undefined, so they can be read early without an error. Function declarations are hoisted with their full body. let, const and class declarations are registered but left uninitialized until their line runs; accessing them earlier throws a ReferenceError (the temporal dead zone).
</QA>

<QA q="If const means constant, why can I change a const array?">
const prevents rebinding the variable name to a different value; it does not make the value itself immutable. A const array or object still refers to the same object, whose contents can change. To prevent changes to the value, use Object.freeze (shallowly) or immutable update patterns.
</QA>

<QA q="Why does a for loop with var and setTimeout print 3, 3, 3, while let prints 0, 1, 2?">
var creates one function-scoped variable shared by every iteration; the callbacks run after the loop finishes, when i is already 3. let creates a new binding for each iteration, so each callback keeps its own value.
</QA>

<QA q="What is the difference between primitive and reference values?">
Primitives (string, number, boolean, null, undefined, bigint, symbol) are copied by value: assigning one variable to another makes an independent copy. Objects, arrays and functions are copied by reference: both variables point to the same object, so changes through one are visible through the other. Copying needs spread, Object.assign or structuredClone.
</QA>

</DeepDive>
