<BigIdea>
<Tr>
<En>
An `if` needs a yes or no. When you give it something that isn't a boolean, like a number, some text or an object, JavaScript converts it: values that act like `false` are called **falsy**, and everything else is **truthy**. There are only **eight falsy values**: `false`, `0`, `-0`, `0n`, `""` (empty text), `null`, `undefined` and `NaN`. **Everything else is truthy**, including `"0"`, `"false"`, `" "`, `[]` and `{}`. Two of the falsy values, **`null` and `undefined`**, are special: together they're called **nullish**, and they mean "**no value here**". The `??` and `?.` operators only react to nullish values, which lets you treat `0` and `""` as real data. Choosing between "is it truthy?" and "is it nullish?" is one of the small decisions that prevents a lot of bugs.
</En>
<Ur>
`if` ko haan ya nahi chahiye. Jab aap use aisi cheez dete hain jo boolean nahi, jaise number, text ya object, to JavaScript use badalti hai: jo values `false` jaisa bartao karti hain unhe **falsy** kehte hain, aur baqi sab **truthy**. Sirf **aath falsy values** hain: `false`, `0`, `-0`, `0n`, `""` (khaali text), `null`, `undefined` aur `NaN`. **Baqi sab truthy hai**, `"0"`, `"false"`, `" "`, `[]` aur `{}` samet. Falsy values me se do, **`null` aur `undefined`**, khaas hain: dono ko mila kar **nullish** kehte hain, aur in ka matlab hai "**yahan koi value nahi**". `??` aur `?.` operators sirf nullish values par react karte hain, jis se aap `0` aur `""` ko asli data maan sakte hain. "Kya ye truthy hai?" aur "kya ye nullish hai?" me se chunna un chhote faislon me se hai jo bohot se bugs rokte hain.
</Ur>
</Tr>

<Why>
<Tr>
<En>

- **Short checks are everywhere**: `if (user)`, `if (items.length)`, `name || "Guest"`. You need to know exactly what passes them.
- **Treating 0 or "" as missing is a classic bug**: a free item ($0) can't be added, a score of 0 shows as "no score", an empty search clears a filter.
- **`null` and `undefined` come from many places** (missing properties, API fields, function results). Handling them safely prevents "Cannot read properties of undefined" crashes, the most common JavaScript error.

</En>
<Ur>

- **Chhote checks har jagah hain**: `if (user)`, `if (items.length)`, `name || "Guest"`. Bilkul pata hona chahiye ke in se kya guzarta hai.
- **0 ya "" ko ghayab samajhna mashhoor bug hai**: muft item ($0) shamil nahi hota, 0 ka score "koi score nahi" dikhta hai, khaali search filter mita deti hai.
- **`null` aur `undefined` bohot si jaghon se aate hain** (ghayab properties, API fields, function ke nataij). Inhe mehfooz tareeqe se sambhalna "Cannot read properties of undefined" crash rokta hai, JavaScript ka sab se aam error.

</Ur>
</Tr>
</Why>

| "Is the text non-empty?" | `text.trim() !== ""` |
| "Does the array have items?" | `arr.length > 0` |
| "Does the object have keys?" | `Object.keys(obj).length > 0` |

</En>

| --- | --- |

| "Kya text khaali nahi?" | `text.trim() !== ""` |
| "Kya array me items hain?" | `arr.length > 0` |
| "Kya object me keys hain?" | `Object.keys(obj).length > 0` |
| "Kya ye waqai boolean true hai?" | `x === true` |

</Ur>

<How>
<Tr>
<En>

1. Learn the eight falsy values; everything else is truthy.
2. Ask yourself: should `0`, `""` or `false` count as "present"? If yes, use a **nullish** check (`??`, `?.`, `!= null`).
3. Check arrays and objects by their size, never by truthiness.
4. Convert with `Boolean(x)` (or `!!x`) when you need a real boolean.

</En>
<Ur>

2. Khud se poochein: kya `0`, `""` ya `false` ko "maujood" ginna chahiye? Agar haan to **nullish** check lein (`??`, `?.`, `!= null`).
3. Arrays aur objects ko un ke size se check karein, kabhi truthiness se nahi.
4. Asli boolean chahiye to `Boolean(x)` (ya `!!x`) se badlein.

</Ur>

## Picture it

<Tr>
<En>

Think of a **mailbox**.

- **`undefined`** is **no mailbox at all**: nothing was ever set up here.
- **`null`** is an **empty mailbox someone put up on purpose**: "there's a box, and it's deliberately empty".
- **`0`, `""` and `false`** are **letters that say "zero", "(blank page)" and "no"**. They're real mail. Throwing them away because they're "empty-looking" would be wrong.
- A **truthy check** (`if (x)`) is a careless mail sorter who throws out the blank pages and the "no" letters along with the missing mailboxes.
- A **nullish check** (`??`, `?.`) is a careful sorter who only says "nothing here" when there's no mail at all.

</En>
<Ur>

Ek **mailbox** ka sochein.

- **`undefined`** matlab **koi mailbox hi nahi**: yahan kabhi kuch lagaya hi nahi gaya.
- **`null`** matlab **jaan boojh kar lagaya gaya khaali mailbox**: "dabba hai, aur irade se khaali hai".
- **`0`, `""` aur `false`** wo **khat hain jin par "zero", "(khaali safha)" aur "nahi" likha hai**. Ye asli daak hai. Inhe "khaali lagne" ki wajah se phenkna ghalat hoga.
- **Truthy check** (`if (x)`) lapparwah daak chhaantne wala hai jo ghayab mailboxes ke saath khaali safhe aur "nahi" wale khat bhi phenk deta hai.
- **Nullish check** (`??`, `?.`) mohtaat chhaantne wala hai jo sirf tab "yahan kuch nahi" kehta hai jab daak bilkul na ho.

</Ur>
</Tr>

## Learn it step by step

<Walkthrough>

<Step title="The eight falsy values">

<Tr>
<En>
Put any value in an `if` and JavaScript asks "is it truthy?". These eight are the **only** falsy values. Learn them once and you can predict every condition.
</En>
<Ur>
Kisi bhi value ko `if` me rakhein aur JavaScript poochti hai "kya ye truthy hai?". Ye aath **hi** falsy values hain. Ek dafa yaad kar lein to har shart ka andaza laga sakte hain.
</Ur>
</Tr>

```javascript
const values = [false, 0, -0, 0n, "", null, undefined, NaN];

for (const value of values) {
  if (value) {
    console.log(String(value), "is truthy");
  } else {
    console.log(JSON.stringify(String(value)), "is falsy");
  }
}
```

```text output
"false" is falsy
"0" is falsy
"0" is falsy
"0" is falsy
"" is falsy
"null" is falsy
"undefined" is falsy
"NaN" is falsy
```

<Happened>
<Tr>
<En>

- Every one went to the `else` branch.
- The list: `false`, the zeros (`0`, `-0`, BigInt `0n`), the empty string `""`, `null`, `undefined` and `NaN`.
- (`String(-0)` and `String(0n)` both print as `"0"`, which is why three lines say `"0"`.)
- Note: `""` is falsy, but a string with a space `" "` is not; see the next step.

</En>
<Ur>

- Har ek `else` wali shaakh me gaya.
- List: `false`, zeros (`0`, `-0`, BigInt `0n`), khaali string `""`, `null`, `undefined` aur `NaN`.
- (`String(-0)` aur `String(0n)` dono `"0"` print hote hain, isi liye teen lines `"0"` kehti hain.)
- Note: `""` falsy hai, magar space wali string `" "` nahi; agla qadam dekhein.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Truthy surprises">

<Tr>
<En>
Everything that isn't on the falsy list is truthy. That includes some values that **look** empty or negative to a human.
</En>
<Ur>
Jo kuch falsy list me nahi wo truthy hai. Is me kuch aisi values bhi hain jo insaan ko khaali ya manfi **lagti** hain.
</Ur>
</Tr>

```javascript
const surprises = ["0", "false", " ", [], {}, -1, Infinity, function () {}, new Date(0)];

for (const value of surprises) {
  console.log(Boolean(value), Object.prototype.toString.call(value), JSON.stringify(value) ?? "(function)");
}
```

```text output
true [object String] "0"
true [object String] "false"
true [object String] " "
true [object Array] []
true [object Object] {}
true [object Number] -1
true [object Number] null
true [object Function] (function)
true [object Date] "1970-01-01T00:00:00.000Z"
```

<Happened>
<Tr>
<En>

- The **strings** `"0"` and `"false"` are truthy: they're non-empty text. Values from forms, URLs, environment variables and `localStorage` are always strings, so `if (process.env.DEBUG)` is true even when `DEBUG=false`.
- A string with just a space is truthy. Use `text.trim()` before checking.
- An **empty array `[]` and empty object `{}` are truthy**. They're objects, and all objects are truthy. Check `arr.length` or `Object.keys(obj).length`.
- Negative numbers and `Infinity` are truthy; only zero is falsy. (`JSON.stringify(Infinity)` prints `null`, a JSON quirk.)
- Functions and dates are objects, so they're truthy too, even the date at time 0.

</En>
<Ur>

- **Strings** `"0"` aur `"false"` truthy hain: ye ghair khaali text hain. Forms, URLs, environment variables aur `localStorage` ki values hamesha strings hoti hain, isliye `DEBUG=false` hone par bhi `if (process.env.DEBUG)` true hai.
- Sirf space wali string truthy hai. Check se pehle `text.trim()` lein.
- **Khaali array `[]` aur khaali object `{}` truthy hain.** Ye objects hain, aur tamam objects truthy hain. `arr.length` ya `Object.keys(obj).length` check karein.
- Manfi numbers aur `Infinity` truthy hain; sirf zero falsy hai. (`JSON.stringify(Infinity)` `null` print karta hai, JSON ki ek ajeeb baat.)
- Functions aur dates objects hain, isliye ye bhi truthy hain, waqt 0 wali date bhi.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Converting to a real boolean">

<Tr>
<En>
Sometimes you need an actual `true` or `false`, for example to store a flag or send it as JSON. Use `Boolean(x)` or the shorter `!!x` (the first `!` flips to the opposite boolean, the second flips it back).
</En>
<Ur>
Kabhi asli `true` ya `false` chahiye hota hai, maslan flag mehfooz karne ya JSON me bhejne ke liye. `Boolean(x)` ya mukhtasar `!!x` lein (pehla `!` ulte boolean me badalta hai, doosra wapas palat deta hai).
</Ur>
</Tr>

```javascript
const user = { name: "Alex", avatarUrl: "", orders: 3 };

const hasAvatar = Boolean(user.avatarUrl);
const hasOrders = !!user.orders;
console.log(hasAvatar, hasOrders);

console.log(JSON.stringify({ hasAvatar, hasOrders, raw: user.orders && "yes" }));

// Strings that mean true/false need a real comparison
const fromUrl = "false";
console.log(Boolean(fromUrl), fromUrl === "true");
```

```text output
false true
{"hasAvatar":false,"hasOrders":true,"raw":"yes"}
true false
```

<Happened>
<Tr>
<En>

- `Boolean("")` is `false`, so `hasAvatar` is false; `!!3` is `true`.
- `user.orders && "yes"` returned `"yes"`, not `true`: `&&` returns one of its values. Wrap it in `Boolean(…)` when you need a real boolean in JSON.
- `Boolean("false")` is **true**: it's non-empty text. To read a "true"/"false" string from a URL, form or environment variable, compare the text: `fromUrl === "true"`.

</En>
<Ur>

- `Boolean("")` `false` hai, isliye `hasAvatar` false hai; `!!3` `true` hai.
- `user.orders && "yes"` ne `"yes"` wapas kiya, `true` nahi: `&&` apni values me se ek wapas karta hai. JSON me asli boolean chahiye to `Boolean(…)` me lapetein.
- `Boolean("false")` **true** hai: ye ghair khaali text hai. URL, form ya environment variable se "true"/"false" string parhne ke liye text compare karein: `fromUrl === "true"`.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="undefined and null: two kinds of nothing">

<Tr>
<En>
**`undefined`** means "**not set**": JavaScript gives it to you automatically when something doesn't exist yet. **`null`** means "**empty on purpose**": you (or an API) set it deliberately. Here are the places `undefined` appears on its own.
</En>
<Ur>
**`undefined`** ka matlab "**set nahi**": jab koi cheez abhi maujood na ho to JavaScript khud ye deti hai. **`null`** ka matlab "**irade se khaali**": aap (ya koi API) ise jaan boojh kar rakhte hain. Ye rahi wo jaghen jahan `undefined` khud aata hai.
</Ur>
</Tr>

```javascript
let notSet;
const product = { name: "Mug", discount: null };
function greet(name) {
  return name;
}
function noReturn() {}
const list = [1, , 3];

console.log(notSet, product.color, product.discount, greet(), noReturn(), list[1], list[5]);
console.log(typeof undefined, typeof null);
console.log(JSON.stringify({ a: undefined, b: null }));
```

```text output
undefined undefined null undefined undefined undefined undefined
undefined object
{"b":null}
```

<Happened>
<Tr>
<En>

| Where | Result |
| --- | --- |
| A variable declared without a value | `undefined` |
| A property that doesn't exist (`product.color`) | `undefined` |
| A property set to `null` on purpose (`product.discount`) | `null` |
| A missing function argument (`greet()`) | `undefined` |
| A function with no `return` | `undefined` |
| An array hole or an index past the end | `undefined` |

- `typeof null` is `"object"`, a famous bug from 1995 that can't be fixed without breaking the web. Check null with `x === null`.
- `JSON.stringify` **drops** properties whose value is `undefined` but keeps `null`. If an API must receive "clear this field", send `null`.
- A good habit: let `undefined` mean "not provided" and use `null` when you deliberately store "no value" (like "no discount").

</En>
<Ur>

| Kahan | Nateeja |
| --- | --- |
| Baghair value ke declare hua variable | `undefined` |
| Jo property maujood nahi (`product.color`) | `undefined` |
| Jaan boojh kar `null` rakhi property (`product.discount`) | `null` |
| Ghayab function argument (`greet()`) | `undefined` |
| Baghair `return` wala function | `undefined` |
| Array ka khala ya aakhir ke baad ka index | `undefined` |

- `typeof null` `"object"` hai, 1995 ka mashhoor bug jo web tore baghair theek nahi ho sakta. null ko `x === null` se check karein.
- `JSON.stringify` jin properties ki value `undefined` ho unhe **gira deta** hai magar `null` rakhta hai. Agar API ko "ye field mita do" milna chahiye to `null` bhejein.
- Achhi aadat: `undefined` ka matlab "diya nahi gaya" rehne dein aur jab jaan boojh kar "koi value nahi" rakhni ho (jaise "koi discount nahi") to `null` lein.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="?. stops safely at null or undefined">

<Tr>
<En>
Reading a property of `undefined` or `null` crashes with a `TypeError`. **Optional chaining** `?.` checks first: if the value on its left is nullish, the whole expression becomes `undefined` instead of crashing. Pair it with `??` for a fallback.
</En>
<Ur>
`undefined` ya `null` ki property parhna `TypeError` ke saath crash karta hai. **Optional chaining** `?.` pehle check karta hai: agar us ke baayen ki value nullish ho to poora expression crash hone ke bajaye `undefined` ban jata hai. Fallback ke liye ise `??` ke saath lein.
</Ur>
</Tr>

```javascript
const order = { id: 1, customer: { name: "Sam" }, items: [] };

console.log(order.customer?.name, order.shipping?.city, order.items?.[0]?.name);
console.log(order.coupon?.code ?? "no coupon");

const api = { notify: undefined };
console.log(api.notify?.("sent"));

try {
  console.log(order.shipping.city);
} catch (error) {
  console.log(error.name + ":", error.message);
}
```

```text output
Sam undefined undefined
no coupon
undefined
TypeError: Cannot read properties of undefined (reading 'city')
```

<Happened>
<Tr>
<En>

- `order.shipping?.city`: `shipping` is undefined, so `?.` stopped and gave `undefined`.
- `order.items?.[0]?.name`: `?.[ ]` works for array indexes; the array is empty, so `[0]` is undefined and the next `?.` stops.
- `api.notify?.("sent")` calls a function only if it exists.
- Without `?.`, `order.shipping.city` threw the most common error in JavaScript: "Cannot read properties of undefined".
- Use `?.` where a value is **allowed** to be missing (optional API fields). Where it must exist, a crash may be better than silently continuing with `undefined`. The Spread, Rest and Optional Chaining lesson goes deeper.

</En>
<Ur>

- `order.shipping?.city`: `shipping` undefined hai, isliye `?.` ruk gaya aur `undefined` diya.
- `order.items?.[0]?.name`: `?.[ ]` array indexes ke liye chalta hai; array khaali hai, isliye `[0]` undefined hai aur agla `?.` ruk jata hai.
- `api.notify?.("sent")` function sirf tab call karta hai jab wo maujood ho.
- `?.` ke baghair `order.shipping.city` ne JavaScript ka sab se aam error phenka: "Cannot read properties of undefined".
- `?.` wahan lein jahan value ka ghayab hona **jaiz** ho (optional API fields). Jahan zaroor honi chahiye, wahan crash `undefined` ke saath khamoshi se chalte rehne se behtar ho sakta hai. Spread, Rest and Optional Chaining lesson aur gehrai me jata hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Default parameters and ??">

<Tr>
<En>
A **default parameter** (`function f(x = 50)`) is used when the argument is **`undefined`**, either missing or passed as `undefined`. It is **not** used for `null` or `0`. When you also want `null` to get the default, use `??` inside the function.
</En>
<Ur>
**Default parameter** (`function f(x = 50)`) tab istemal hota hai jab argument **`undefined`** ho, ya to ghayab ya `undefined` ki shakal me bheja gaya. Ye `null` ya `0` ke liye istemal **nahi** hota. Agar `null` ko bhi default dena ho to function ke andar `??` lein.
</Ur>
</Tr>

```javascript
function setVolume(level = 50) {
  return level;
}
console.log(setVolume(), setVolume(undefined), setVolume(null), setVolume(0));

function label(text) {
  return text ?? "Untitled";
}
console.log([label(), label(null), label(""), label("Report")]);
```

```text output
50 50 null 0
[ 'Untitled', 'Untitled', '', 'Report' ]
```

<Happened>
<Tr>
<En>

- Missing and `undefined` got the default 50; `null` stayed `null`, and `0` stayed `0`.
- `label` used `??`, so both `undefined` and `null` became "Untitled", while `""` stayed empty.
- If an empty title should also be "Untitled", that's a different rule: `text?.trim() || "Untitled"`. Decide which one you mean.

</En>
<Ur>

- Ghayab aur `undefined` ko default 50 mila; `null` `null` raha, aur `0` `0` raha.
- `label` ne `??` istemal kiya, isliye `undefined` aur `null` dono "Untitled" bane, jabke `""` khaali raha.
- Agar khaali title bhi "Untitled" hona chahiye to ye alag qaida hai: `text?.trim() || "Untitled"`. Tay karein aap ka matlab kaun sa hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="filter(Boolean) and its catch">

<Tr>
<En>
`arr.filter(Boolean)` is a popular shortcut to remove "empty" items: it keeps only truthy values. It's handy, but it also removes `0` and `""`, which may be real data. Pick the filter that matches what "empty" means for your data.
</En>
<Ur>

<Compare>
<Bad title="Truthy check for a number that can be 0">

- **`{count && <Badge />}` in React**: when `count` is 0, React renders the number `0`. Use `{count > 0 && <Badge />}`.

</En>

<DeepDive title="More about truthiness">

**ToBoolean** is the spec operation behind every condition. It's simple: the eight falsy values return false; every other value, including every object, returns true.

**Wrapper objects.** `new Boolean(false)` is an **object**, so it's truthy. Never create primitives with `new`; use `Boolean(x)` without `new` for conversion.

**`document.all`.** For historical web compatibility, this one browser object is falsy. It's the only falsy object, and you'll never need it.

**Where truthiness is used:** `if`, `while`, `for` conditions, `!`, `&&`, `||`, the ternary `? :`, `Array.prototype.filter` callbacks, and `Array.prototype.find`/`some`/`every` results.

**TypeScript helps.** With `strictNullChecks`, TypeScript forces you to handle `null`/`undefined` before using a value, and it narrows types after checks like `if (x != null)`.

**Optional chaining short-circuits the rest of the chain.** In `a?.b.c.d`, if `a` is nullish, none of `.b.c.d` is evaluated.

</DeepDive>

<DeepDive title="Real world: the free plan that charged everyone">

A SaaS app had three plans: Free ($0), Pro ($12) and Team ($40). The checkout code picked a price like this:

```text
const price = plan.price || DEFAULT_PRICE;   // DEFAULT_PRICE = 12
```

The default existed because, early on, some old plans in the database had no price. When the Free plan launched with `price: 0`, the `||` treated 0 as "no price" and charged **$12** to every "free" signup. Because the payment form showed the plan name ("Free") and not the amount, it took a weekend and hundreds of support emails to notice.

The fix:

1. Replace `||` with `??` so only `null`/`undefined` prices fall back.
2. Remove the default entirely: a plan without a price became a **validation error**, because guessing a price is worse than refusing.
3. Show the exact amount on the payment button: "Pay $0.00".
4. Add a test for every plan, including the $0 one.

Lesson: `0` is often the most important value in a system (free, none, disabled, first). **Never use a truthy check where 0 is a valid answer.**

</DeepDive>

<DeepDive title="Security lens">

- **Fail closed.** `if (!user.isAdmin) deny()` is safe if `isAdmin` is missing (undefined is falsy → deny). `if (user.isBlocked) deny()` lets a user through when `isBlocked` is missing. Write checks so that missing data means "no access".
- **Don't trust truthy strings from clients**: a JSON body with `"isAdmin": "false"` is truthy. Validate types (`typeof x === "boolean"`) or use a schema.
- **Environment flags are strings**: `if (process.env.DISABLE_AUTH)` is true for `"false"` and `"0"`. Compare explicitly and default to the safe setting.
- **`?.` can hide missing authorisation data**: `if (session?.user?.role === "admin")` is fine (missing → false), but `if (session?.user?.banned)` lets banned users through when the field is missing.
- **Empty objects pass truthiness checks**: `if (permissions)` is true for `{}`; check the specific permission.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="List the falsy values in JavaScript.">
false, 0, negative zero, 0n, the empty string, null, undefined and NaN. Every other value, including all objects, empty arrays and the string "0", is truthy.
</QA>

<QA q="What is the difference between null and undefined?">
undefined means a value was never assigned or does not exist, such as a missing property, argument or return value, and is produced automatically. null is an intentional empty value assigned by code. typeof undefined is "undefined" while typeof null is "object", and JSON.stringify keeps null but omits undefined properties.
</QA>

<QA q="What does the double bang !! do?">
It converts any value to its boolean equivalent: the first NOT converts and negates, the second negates again, giving the same result as Boolean(value).
</QA>

<QA q="When would you use ?? instead of ||?">
When valid values can be falsy, such as 0, an empty string or false, and you only want a fallback for null or undefined. OR would replace those valid values with the fallback.
</QA>

<QA q="Why can rendering count && something in React show a 0?">
Logical AND returns its first falsy operand, so when count is 0 the expression evaluates to 0, which React renders as text. Use a boolean condition such as count > 0.
</QA>

</DeepDive>
