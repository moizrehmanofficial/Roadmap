<BigIdea>
<Tr>
<En>
In plain HTML, an input keeps its own value and the browser submits the form by reloading the page. In React there are two styles. **Controlled** inputs: the value lives in **React state** (`value={email}`) and every keystroke goes through your code (`onChange={(e) => setEmail(e.target.value)}`). React is the single source of truth, so you can validate as the user types, format input, or enable the submit button only when the form is valid. **Uncontrolled** inputs: the DOM keeps the value, and you read everything at submit time with `new FormData(form)`. It's simpler for big forms that only need the data once. Either way, you handle `onSubmit`, call `event.preventDefault()`, validate, send the data (with `fetch`), and show **loading**, **errors** next to the right fields, and **success**. React 19 adds **form actions**: pass a function to `<form action>` and use `useActionState` to get the result and a pending flag with less code. For large or complex forms, most teams use **React Hook Form** with a **zod** schema.
</En>
<Ur>
Saade HTML me input apni value khud rakhta hai aur browser page reload kar ke form submit karta hai. React me do andaaz hain. **Controlled** inputs: value **React state** me rehti hai (`value={email}`) aur har key aap ke code se guzarti hai (`onChange={(e) => setEmail(e.target.value)}`). React sach ka akela zariya hai, isliye aap type karte waqt validate kar sakte hain, input ko format kar sakte hain, ya submit button sirf form ke jaiz hone par chalu kar sakte hain. **Uncontrolled** inputs: DOM value rakhta hai, aur aap submit ke waqt `new FormData(form)` se sab parhte hain. Ye bare forms ke liye aasan hai jinhen data sirf ek dafa chahiye. Dono tarah aap `onSubmit` sambhalte hain, `event.preventDefault()` call karte hain, validate karte hain, data bhejte hain (`fetch` se), aur **loading**, sahi fields ke saath **errors**, aur **kamyabi** dikhate hain. React 19 **form actions** jorta hai: `<form action>` ko function dein aur kam code ke saath nateeja aur pending flag lene ke liye `useActionState` istemal karein. Bare ya pecheeda forms ke liye zyada tar teams **zod** schema ke saath **React Hook Form** istemal karti hain.
</Ur>
</Tr>

## Picture it

<Tr>
<En>

Think of filling in a **form at a bank counter**.

- **Controlled**: a clerk sits beside you and copies every letter you write into the official system **as you write it**. They can stop you immediately ("that account number has too many digits") and they always know what's on the form.
- **Uncontrolled**: you fill in the paper form alone and hand it over at the end. The clerk reads it once and only then tells you what's wrong.
- **Validation** is the clerk pointing at the exact box that's wrong, not saying "something on this page is incorrect".
- **Submitting** is the clerk sending the form to head office. While you wait, the "Submit" stamp is put away (button disabled) so you can't submit it twice. If head office rejects it, you get your form **back with your writing intact**, plus a note on the wrong field.

</En>
<Ur>

**Bank ke counter par form bharne** ka sochein.

- **Controlled**: clerk aap ke saath baith kar aap ka har harf **likhte hi** sarkari nizaam me copy karta hai. Wo aap ko foran rok sakta hai ("is account number me hindse zyada hain") aur hamesha janta hai ke form par kya hai.
- **Uncontrolled**: aap kaghaz ka form akele bharte hain aur aakhir me de dete hain. Clerk ise ek dafa parhta hai aur tab hi batata hai ke kya ghalat hai.
- **Validation** clerk ka bilkul us khane ki taraf ishara karna hai jo ghalat hai, ye nahi kehna ke "is safhe par kuch ghalat hai".
- **Submit karna** clerk ka form head office bhejna hai. Intezar ke dauran "Submit" ki muhar rakh di jati hai (button band) taa ke aap do dafa submit na kar sakein. Agar head office radd kare to aap ko form **aap ki likhai samet** wapas milta hai, ghalat field par note ke saath.

</Ur>
</Tr>

## Learn it step by step

<Walkthrough>

<Step title="A controlled input">

<Tr>
<En>
Put the value in state, show it with `value`, and update it in `onChange`. Now React always knows the current text, so you can use it anywhere: a live preview, a counter, a disabled button.
</En>
<Ur>
Value state me rakhein, `value` se dikhayen, aur `onChange` me update karein. Ab React hamesha maujooda text janta hai, isliye aap ise kahin bhi istemal kar sakte hain: live preview, counter, band button.
</Ur>
</Tr>

```jsx preview h=200
import { useState } from "react";

export default function App() {
  const [username, setUsername] = useState("");
  const clean = username.trim().toLowerCase().replace(/[^a-z0-9_]/g, "");
  const tooShort = clean.length < 3;

  return (
    <div>
      <label htmlFor="username">Username</label>{" "}
      <input id="username" value={username} onChange={(e) => setUsername(e.target.value)} maxLength={20} />
      <p>Your profile: <code>shop.example.com/@{clean || "…"}</code></p>
      <p>{username.length} / 20 characters</p>
      <button disabled={tooShort}>Claim username</button>
    </div>
  );
}
```

<Happened>
<Tr>
<En>

- Typing "Sara Lee!" shows the profile URL `shop.example.com/@saralee` and "9 / 20 characters"; the button enables once the cleaned name has 3+ characters.
- Every keystroke: `onChange` fires → `setUsername` → React re-renders → the input shows the new `value`. The cleaned version is **derived** during render, not stored.
- React's `onChange` fires on **every** edit (like the native `input` event), not only on blur like the native `change` event.
- `htmlFor` connects the `<label>` to the input (`for` is a reserved word in JavaScript). Clicking the label focuses the input, and screen readers announce its name.

</En>
<Ur>

- "Sara Lee!" likhne par profile URL `shop.example.com/@saralee` aur "9 / 20 characters" dikhta hai; saaf naam ke 3+ huroof hote hi button chalu ho jata hai.
- Har key: `onChange` chalta hai → `setUsername` → React dobara render karta hai → input nayi `value` dikhata hai. Saaf version render ke dauran **nikala** jata hai, mehfooz nahi hota.
- React ka `onChange` **har** tabdeeli par chalta hai (native `input` event ki tarah), native `change` event ki tarah sirf blur par nahi.
- `htmlFor` `<label>` ko input se jorta hai (`for` JavaScript me mahfooz lafz hai). Label par click input par focus lata hai, aur screen readers us ka naam bolte hain.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="The frozen input trap">

<Tr>
<En>
If you give an input a `value` but no working `onChange`, React keeps forcing the value back on every render: the user **can't type**. Try typing in both inputs.
</En>
<Ur>
Agar aap input ko `value` dein magar chalta hua `onChange` na dein, React har render par value wapas lagata rehta hai: user **type nahi kar sakta**. Dono inputs me type karne ki koshish karein.
</Ur>
</Tr>

```jsx preview h=150
import { useState } from "react";

export default function App() {
  const [city, setCity] = useState("Boston");
  return (
    <div>
      <p><label>Frozen: <input value={city} /></label></p>
      <p><label>Uncontrolled: <input defaultValue={city} /></label></p>
      <p><label>Controlled: <input value={city} onChange={(e) => setCity(e.target.value)} /></label></p>
      <p>State: {city}</p>
    </div>
  );
}
```

<Happened>
<Tr>
<En>

- **Frozen** won't change, however you type: `value` is fixed to `city` and nothing updates `city`. In development React also warns: "You provided a `value` prop to a form field without an `onChange` handler".
- **Uncontrolled** starts as "Boston" (`defaultValue` is only the **starting** value) and then the DOM owns it; state doesn't change.
- **Controlled** updates the state, and because the frozen input shows `city` too, it follows along: one source of truth, two views.
- A controlled input's `value` must never be `undefined` (use `""`), or React will warn about switching from uncontrolled to controlled.

</En>
<Ur>

- **Frozen** jitna bhi type karein nahi badalta: `value` `city` par jama hai aur koi `city` update nahi karta. Development me React warning bhi deta hai: "You provided a `value` prop to a form field without an `onChange` handler".
- **Uncontrolled** "Boston" se shuru hota hai (`defaultValue` sirf **shuruati** value hai) aur phir DOM us ka malik hai; state nahi badalti.
- **Controlled** state update karta hai, aur chunke frozen input bhi `city` dikhata hai, wo bhi saath chalta hai: sach ka ek zariya, do nazare.
- Controlled input ki `value` kabhi `undefined` nahi honi chahiye (`""` lein), warna React uncontrolled se controlled me badalne ki warning dega.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Many fields with one state object">

<Tr>
<En>
For forms with several fields, keep one object in state and one change handler that uses each input's `name`. Checkboxes use `checked`, everything else uses `value`.
</En>
<Ur>
Kai fields wale forms ke liye state me ek object aur ek change handler rakhein jo har input ka `name` istemal kare. Checkboxes `checked` istemal karte hain, baqi sab `value`.
</Ur>
</Tr>

```jsx preview h=330
import { useState } from "react";

export default function App() {
  const [form, setForm] = useState({
    name: "",
    plan: "pro",
    billing: "monthly",
    notes: "",
    newsletter: true,
  });

  function handleChange(e) {
    const { name, type, value, checked } = e.target;
    setForm((prev) => ({ ...prev, [name]: type === "checkbox" ? checked : value }));
  }

  return (
    <form onSubmit={(e) => e.preventDefault()} style={{ display: "grid", gap: 6, maxWidth: 320 }}>
      <label>Name <input name="name" value={form.name} onChange={handleChange} /></label>
      <label>Plan{" "}
        <select name="plan" value={form.plan} onChange={handleChange}>
          <option value="free">Free</option>
          <option value="pro">Pro</option>
          <option value="team">Team</option>
        </select>
      </label>
      <fieldset style={{ margin: 0 }}>
        <legend>Billing</legend>
        {["monthly", "yearly"].map((b) => (
          <label key={b} style={{ marginRight: 10 }}>
            <input type="radio" name="billing" value={b} checked={form.billing === b} onChange={handleChange} /> {b}
          </label>
        ))}
      </fieldset>
      <label>Notes <textarea name="notes" value={form.notes} onChange={handleChange} rows={2} /></label>
      <label><input type="checkbox" name="newsletter" checked={form.newsletter} onChange={handleChange} /> Send me product news</label>
      <pre style={{ background: "#f1f5f9", padding: 6, margin: 0 }}>{JSON.stringify(form, null, 1)}</pre>
    </form>
  );
}
```

<Happened>
<Tr>
<En>

- The JSON at the bottom updates as you type, choose, click radios and tick the box: everything is in one object.
- `[name]: …` is a **computed property name**: the input's `name` decides which key changes. Using the updater form `setForm((prev) => …)` keeps other fields intact even with fast typing.
- **Radios** share one `name` and are controlled by comparing: `checked={form.billing === b}`. **Select** and **textarea** use `value` in React (not `selected` or children text).
- Checkbox values come from `checked` (a boolean), not `value`.

</En>
<Ur>

- Neeche ka JSON type karte, chunte, radios dabate aur box tick karte waqt update hota hai: sab kuch ek object me hai.
- `[name]: …` **computed property name** hai: input ka `name` tay karta hai ke kaun si key badle. Updater wala `setForm((prev) => …)` tez typing me bhi doosre fields mehfooz rakhta hai.
- **Radios** ek `name` baant'te hain aur muqable se control hote hain: `checked={form.billing === b}`. **Select** aur **textarea** React me `value` istemal karte hain (`selected` ya children text nahi).
- Checkbox ki values `checked` (boolean) se aati hain, `value` se nahi.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Uncontrolled forms with FormData">

<Tr>
<En>
If you only need the values when the form is submitted, skip state entirely. Give inputs `name`s (and `defaultValue`s), then read them with `FormData` in `onSubmit`. Fill it in and press **Save**.
</En>
<Ur>
Agar values sirf form submit hone par chahiyen to state bilkul chhor dein. Inputs ko `name` (aur `defaultValue`) dein, phir `onSubmit` me `FormData` se parhein. Bhar kar **Save** dabayen.
</Ur>
</Tr>

```jsx preview h=230
import { useState } from "react";

export default function App() {
  const [saved, setSaved] = useState(null);

  function handleSubmit(e) {
    e.preventDefault();
    const data = Object.fromEntries(new FormData(e.currentTarget));
    data.age = Number(data.age);
    data.terms = data.terms === "on";
    setSaved(data);
  }

  return (
    <form onSubmit={handleSubmit}>
      <p><label>Full name <input name="fullName" defaultValue="Emma Stone" required /></label></p>
      <p><label>Age <input name="age" type="number" min="13" defaultValue="29" /></label></p>
      <p><label><input name="terms" type="checkbox" /> I accept the terms</label></p>
      <button>Save</button>
      {saved && <pre>{JSON.stringify(saved, null, 2)}</pre>}
    </form>
  );
}
```

<Happened>
<Tr>
<En>

Pressing **Save** with the defaults (terms unticked) shows:

```text
{
  "fullName": "Emma Stone",
  "age": 29,
  "terms": false
}
```

- No state per field and no re-render per keystroke. React only re-renders once, to show the result.
- `FormData` values are **strings** (`"29"`), and an unticked checkbox is **missing** entirely, so we converted both. With zod you'd do this with `z.coerce.number()` (zod lesson).
- Native attributes (`required`, `min`, `type="email"`) still work: the browser blocks submission and shows its own message if they fail.
- `e.currentTarget` is the form (the element with the listener), the right thing to pass to `FormData`.

</En>
<Ur>

Defaults ke saath (terms bina tick) **Save** dabane par ye dikhta hai:

```text
{
  "fullName": "Emma Stone",
  "age": 29,
  "terms": false
}
```

- Har field ki state nahi aur har key par dobara render nahi. React sirf ek dafa, nateeja dikhane ke liye, dobara render karta hai.
- `FormData` ki values **strings** hain (`"29"`), aur bina tick checkbox bilkul **ghayab** hota hai, isliye humne dono badle. zod ke saath ye `z.coerce.number()` se hota (zod lesson).
- Native attributes (`required`, `min`, `type="email"`) ab bhi kaam karte hain: fail hone par browser submission rokta aur apna paighaam dikhata hai.
- `e.currentTarget` form hai (listener wala element), `FormData` ko dene ki sahi cheez.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Validation: errors at the right time, in the right place">

<Tr>
<En>
Good validation shows errors **next to the field**, **after** the user has had a chance (on blur or on submit, not on the first keystroke), and clears them as soon as the field is fixed. Try submitting the empty form, then fix each field.
</En>
<Ur>
Achhi validation errors **field ke saath** dikhati hai, user ko mauqa milne ke **baad** (blur ya submit par, pehli key par nahi), aur field theek hote hi unhen saaf kar deti hai. Khaali form submit kar ke dekhein, phir har field theek karein.
</Ur>
</Tr>

```jsx preview h=330
import { useState } from "react";

function validate({ email, password, confirm }) {
  const errors = {};
  if (!email) errors.email = "Email is required";
  else if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) errors.email = "Enter a valid email";
  if (password.length < 8) errors.password = "Use at least 8 characters";
  if (!confirm) errors.confirm = "Confirm your password";
  else if (confirm !== password) errors.confirm = "Passwords don't match";
  return errors;
}

function Field({ label, name, type = "text", value, error, show, onChange, onBlur }) {
  const errorId = name + "-error";
  return (
    <p style={{ margin: "6px 0" }}>
      <label>{label}<br />
        <input name={name} type={type} value={value} onChange={onChange} onBlur={onBlur}
               aria-invalid={show && !!error} aria-describedby={show && error ? errorId : undefined}
               style={{ borderColor: show && error ? "#dc2626" : undefined }} />
      </label>
      {show && error && <span id={errorId} style={{ color: "#dc2626", display: "block", fontSize: 13 }}>{error}</span>}
    </p>
  );
}

export default function App() {
  const [values, setValues] = useState({ email: "", password: "", confirm: "" });
  const [touched, setTouched] = useState({});
  const [submitted, setSubmitted] = useState(false);
  const errors = validate(values);

  const onChange = (e) => setValues({ ...values, [e.target.name]: e.target.value });
  const onBlur = (e) => setTouched({ ...touched, [e.target.name]: true });
  const show = (name) => submitted || touched[name];

  function handleSubmit(e) {
    e.preventDefault();
    setSubmitted(true);
    if (Object.keys(errors).length === 0) alert("Account created for " + values.email);
  }

  return (
    <form onSubmit={handleSubmit} noValidate>
      <Field label="Email" name="email" value={values.email} error={errors.email} show={show("email")} onChange={onChange} onBlur={onBlur} />
      <Field label="Password" name="password" type="password" value={values.password} error={errors.password} show={show("password")} onChange={onChange} onBlur={onBlur} />
```

<Step title="Submitting: loading, server errors and keeping input">

<Tr>
<En>
Submitting is asynchronous. Disable the button while it's in flight, show progress, then either success or the **server's** errors on the right fields. Never clear the form on failure. This preview uses a pretend API: the email `taken@example.com` is already registered.
</En>
<Ur>
Submit karna asynchronous hai. Chalte waqt button band karein, pesh raft dikhayen, phir ya kamyabi ya **server ke** errors sahi fields par. Nakami par form kabhi saaf na karein. Ye preview naqli API istemal karta hai: email `taken@example.com` pehle se registered hai.
</Ur>

```jsx preview h=260
import { useState } from "react";

// Pretend server: returns { ok } or { ok: false, fieldErrors } after 800 ms
function fakeSignupApi({ email }) {
  return new Promise((resolve) =>
    setTimeout(() => {
      if (email === "taken@example.com") resolve({ ok: false, fieldErrors: { email: "This email is already registered" } });
      else resolve({ ok: true });
    }, 800)
  );
}

export default function App() {
  const [email, setEmail] = useState("taken@example.com");
  const [status, setStatus] = useState("idle"); // idle | submitting | success
  const [serverErrors, setServerErrors] = useState({});

  async function handleSubmit(e) {
    e.preventDefault();
    setStatus("submitting");
    setServerErrors({});
    const result = await fakeSignupApi({ email });
    if (result.ok) setStatus("success");
    else {
      setServerErrors(result.fieldErrors);
      setStatus("idle");
    }
  }

  if (status === "success") return <p>Check your inbox at {email} to confirm your account.</p>;

  return (
    <form onSubmit={handleSubmit}>
      <label>Email <input type="email" value={email} onChange={(e) => setEmail(e.target.value)}
        aria-invalid={!!serverErrors.email} aria-describedby="email-err" /></label>
      {serverErrors.email && <p id="email-err" role="alert" style={{ color: "#dc2626" }}>{serverErrors.email}</p>}
      <button disabled={status === "submitting"}>
        {status === "submitting" ? "Creating account…" : "Create account"}
      </button>
    </form>
  );
}
```

<Step title="React 19 form actions and useActionState">

<Tr>
<En>
React 19 lets you pass a **function** to `<form action>`. React calls it with the form's `FormData` when the form submits (no `preventDefault` needed). `useActionState` wraps that function and gives you its latest **result**, the **action** to put on the form, and an **isPending** flag.
</En>
<Ur>
React 19 aap ko `<form action>` ko **function** dene deta hai. Form submit hone par React ise form ke `FormData` ke saath call karta hai (`preventDefault` ki zaroorat nahi). `useActionState` us function ko lapet kar aap ko us ka taaza **nateeja**, form par lagane wala **action**, aur **isPending** flag deta hai.
</Ur>
</Tr>

```jsx preview h=200
import { useActionState } from "react";

async function subscribe(prevState, formData) {
  await new Promise((r) => setTimeout(r, 600)); // pretend network
  const email = String(formData.get("email") ?? "").trim();
  if (!email.includes("@")) return { error: "Enter a valid email address", email };
  return { message: "Subscribed " + email + " to the newsletter" };
}

export default function App() {
  const [state, formAction, isPending] = useActionState(subscribe, {});

  return (
    <form action={formAction}>
      <label>Email <input name="email" defaultValue={state.email ?? ""} /></label>{" "}
      <button disabled={isPending}>{isPending ? "Subscribing…" : "Subscribe"}</button>
      {state.error && <p role="alert" style={{ color: "#dc2626" }}>{state.error}</p>}
      {state.message && <p>{state.message}</p>}
    </form>
  );
}
```

<Happened>
<Tr>
<En>

- Type "emma" and press **Subscribe**: "Subscribing…" for a moment, then "Enter a valid email address", with "emma" still in the box.
- Type `emma@example.com`: the success message appears and the input is **cleared**, because React **resets** uncontrolled form fields after a successful action. On the error path we returned the email and used it as `defaultValue`, so the user's input came back.
- No `useState` for the input, no `onSubmit`, no `preventDefault`, no manual pending flag: the action's return value **is** the new state.
- In Next.js, the same function can be a **server action** (`"use server"`) that runs on the server, and the form even works before JavaScript loads. Inside nested components, `useFormStatus()` from `react-dom` reads the pending state of the surrounding form (useful for a reusable submit button).

</En>
<Ur>

- "emma" likh kar **Subscribe** dabayen: lamhe bhar "Subscribing…", phir "Enter a valid email address", aur "emma" ab bhi dabbe me.
- `emma@example.com` likhein: kamyabi ka paighaam aata hai aur input **saaf** ho jata hai, kyun ke React kamyab action ke baad uncontrolled form fields **reset** kar deta hai. Error wale raaste par humne email wapas ki aur use `defaultValue` banaya, isliye user ka input wapas aa gaya.
- Input ke liye na `useState`, na `onSubmit`, na `preventDefault`, na haath ka pending flag: action ki wapas ki hui value **hi** nayi state hai.
- Next.js me yahi function **server action** (`"use server"`) ho sakta hai jo server par chale, aur form JavaScript load hone se pehle bhi chalta hai. Nested components ke andar `react-dom` ka `useFormStatus()` ghere hue form ki pending halat parhta hai (dobara istemal hone wale submit button ke liye kaam ka).

</Ur>
</Tr>
</Happened>

<Step title="Bigger forms: React Hook Form and zod">

<Tr>
<En>

For forms with many fields, dynamic rows ("add another address") or complex rules, writing all the state and validation by hand gets repetitive. **React Hook Form** keeps inputs uncontrolled (fast, few re-renders) and plugs into a **zod** schema, so the client and the server can share the same rules:

```text
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { z } from "zod";

const Signup = z.object({
  email: z.email("Enter a valid email"),
  password: z.string().min(8, "Use at least 8 characters"),
});
type Signup = z.infer<typeof Signup>;

export function SignupForm() {
  const { register, handleSubmit, formState: { errors, isSubmitting } } =
    useForm<Signup>({ resolver: zodResolver(Signup) });

  async function onSubmit(data: Signup) {          // data is already validated and typed
    await fetch("/api/signup", { method: "POST", headers: { "content-type": "application/json" }, body: JSON.stringify(data) });
  }

  return (
    <form onSubmit={handleSubmit(onSubmit)} noValidate>
      <input {...register("email")} aria-invalid={!!errors.email} />
      {errors.email && <p role="alert">{errors.email.message}</p>}
      <input type="password" {...register("password")} aria-invalid={!!errors.password} />
      {errors.password && <p role="alert">{errors.password.message}</p>}
      <button disabled={isSubmitting}>Create account</button>
    </form>
  );
}
```

</En>
<Ur>

Bohot se fields, badalti rows ("ek aur address jorein") ya pecheeda qawaid wale forms ke liye tamam state aur validation haath se likhna dohrao ban jata hai. **React Hook Form** inputs uncontrolled rakhta hai (tez, kam re-renders) aur **zod** schema se jurta hai, taa ke client aur server wahi qawaid baant sakein:

```text

type Signup = z.infer<typeof Signup>;

export function SignupForm() {

    useForm<Signup>({ resolver: zodResolver(Signup) });

  async function onSubmit(data: Signup) {          // data pehle se validated aur typed hai
    await fetch("/api/signup", { method: "POST", headers: { "content-type": "application/json" }, body: JSON.stringify(data) });
  }

  return (
    <form onSubmit={handleSubmit(onSubmit)} noValidate>
      <input {...register("email")} aria-invalid={!!errors.email} />

```

</Ur>

<En>

- For simple forms, the hand-written approaches above (or React 19 actions) are perfectly fine; add a library when the form's complexity calls for it.

</En>

## Common mistakes

<Compare>
<Bad title="Clearing the form when the server says no">

```text
const res = await fetch("/api/signup", …);
setForm(emptyForm);                // runs even when res is 400!
if (!res.ok) setError("Failed");   // user has to retype everything
```

</Bad>
<Good title="Clear only on success, and show field errors">

```text
const res = await fetch("/api/signup", …);
const body = await res.json();
if (!res.ok) { setServerErrors(body.errors); return; }   // input kept
setForm(emptyForm);
setStatus("success");
```

</Good>
</Compare>

<Compare>
<Bad title="Validation that shouts on the first keystroke">

```text
// shows "Enter a valid email" the moment the user types "s"
{!isValidEmail(email) && <p>Enter a valid email</p>}
```

</Bad>
<Good title="Show errors after blur or submit">

```text
{(touched.email || submitted) && errors.email && <p id="email-error">{errors.email}</p>}
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **`value` without `onChange`** (frozen input), or `value={undefined}` switching between uncontrolled and controlled.
- **Forgetting `preventDefault()`** in `onSubmit`: the page reloads and your state is lost.
- **Using `onClick` on the submit button** instead of `onSubmit` on the form (Enter key and native validation are bypassed).
- **Inputs without labels**, or placeholder text used as the only label.
- **Not disabling the button** during submission, so double clicks send duplicate orders.
- **Trusting client-side validation** for security.
- **Treating `FormData` values as numbers/booleans**: they're strings, and unticked checkboxes are missing.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **`onChange` ke baghair `value`** (jama hua input), ya uncontrolled aur controlled ke darmiyan badalne wala `value={undefined}`.
- `onSubmit` me **`preventDefault()` bhoolna**: page reload hota hai aur aap ki state kho jati hai.
- Form par `onSubmit` ke bajaye **submit button par `onClick` istemal karna** (Enter key aur native validation chhoot jate hain).
- **Bina labels ke inputs**, ya akele label ke taur par placeholder text.
- Submission ke dauran **button band na karna**, taa ke double clicks dohre orders bhejein.
- Security ke liye **client-side validation par bharosa karna**.
- **`FormData` values ko numbers/booleans samajhna**: ye strings hain, aur bina tick checkboxes ghayab hote hain.

</Ur>
</Tr>

```jsx preview h=330
import { useState } from "react";

const rules = {
  fullName: (v) => (v.trim().length < 2 ? "Enter your full name" : ""),
  street: (v) => (!v.trim() ? "Street is required" : ""),
  city: (v) => (!v.trim() ? "City is required" : ""),
  zip: (v) => (/^\d{5}$/.test(v) ? "" : "ZIP must be 5 digits"),
};

export default function App() {
  const [form, setForm] = useState({ fullName: "", street: "", city: "", zip: "", sameAsBilling: true });
  const [touched, setTouched] = useState({});
  const [submitted, setSubmitted] = useState(false);
  const [status, setStatus] = useState("idle");

  const errors = Object.fromEntries(Object.entries(rules).map(([k, rule]) => [k, rule(form[k])]).filter(([, e]) => e));
  const change = (e) => {
    const { name, type, value, checked } = e.target;
    setForm((f) => ({ ...f, [name]: type === "checkbox" ? checked : value }));
  };

  async function submit(e) {
    e.preventDefault();
    setSubmitted(true);
    if (Object.keys(errors).length) return;
    setStatus("saving");
    await new Promise((r) => setTimeout(r, 600));
    setStatus("saved");
  }

  if (status === "saved") return <p>Address saved: we'll ship to {form.city}.</p>;

  return (
    <form onSubmit={submit} noValidate>
      {["fullName", "street", "city", "zip"].map((name) => (
        <p key={name} style={{ margin: "4px 0" }}>
          <label>{name}<br />
            <input name={name} value={form[name]} onChange={change}
                   onBlur={() => setTouched((t) => ({ ...t, [name]: true }))}
                   aria-invalid={(touched[name] || submitted) && !!errors[name]} />
          </label>
          {(touched[name] || submitted) && errors[name] && <small style={{ color: "#dc2626", display: "block" }}>{errors[name]}</small>}
        </p>
      ))}
      <label><input type="checkbox" name="sameAsBilling" checked={form.sameAsBilling} onChange={change} /> Same as billing</label>
      <p><button disabled={status === "saving"}>{status === "saving" ? "Saving…" : "Save address"}</button></p>
    </form>
  );
}
```

<Takeaways>
<Tr>
<En>

- Disable submit while pending; on failure keep the input and show server errors; clear only on success.

<DeepDive title="More about forms in React">

**`useFormStatus`.** From `react-dom`; inside a component rendered within a `<form>`, it returns `{ pending, data, method, action }` for that form, so a `SubmitButton` can disable itself without props.

**`useOptimistic`.** Show the expected result immediately (a new comment appears instantly) while the action runs, and roll back automatically if it fails.

**Server actions (Next.js).** `async function createPost(formData) { "use server"; … }` passed to `<form action>` runs on the server. Validate with zod inside it, check authorization, and return field errors for `useActionState`.

**Progressive enhancement.** Forms with server actions submit even if JavaScript hasn't loaded yet, which helps on slow connections.

**Field arrays.** Dynamic lists of inputs ("add another phone number") need stable ids as keys (Lists lesson); React Hook Form's `useFieldArray` handles this.

**Formatting inputs.** Masking (phone numbers, card numbers) is easier with controlled inputs; prefer `inputMode="numeric"` and `autocomplete` attributes over fighting the user's keyboard.

**Autofill and password managers.** Correct `name`, `type` and `autocomplete` values (`email`, `new-password`, `one-time-code`, `street-address`) let browsers fill forms for users.

**Accessibility extras.** Move focus to the first invalid field on submit; for long forms, show an error summary at the top with links to each field.

</DeepDive>

<DeepDive title="Real world: the checkout that charged twice">

An online shop's checkout form had a "Place order" button with an `onClick` handler that called the payment API. On slow mobile connections, nothing visible happened for two or three seconds after tapping, so many customers tapped again. Each tap sent a new payment request. Support saw dozens of double charges a week.

The redesign applied this lesson's patterns:

1. The form used **`onSubmit`** (so Enter and native validation also worked) and a single `status` state: `idle | submitting | success | error`.
2. The button was **disabled** with "Placing order…" text the moment the request started.
3. The client generated an **idempotency key** once per checkout and sent it with the request; the payment server ignored repeats with the same key.
4. On a declined card, the form kept every field and showed the provider's message next to the card field, with focus moved there.
5. The server validated the cart and totals again with zod, so tampered prices in the browser were rejected.

Double charges dropped to zero, and the conversion rate on mobile improved because customers now saw immediate feedback.

</DeepDive>

<DeepDive title="Security lens">

- **Never trust client validation**: validate and authorise every submission on the server (zod + permission checks).
- **Don't use the client's prices, totals, roles or user ids**; look them up on the server from trusted data.
- **CSRF**: cookie-authenticated form posts need protection (`SameSite` cookies, CSRF tokens, `Origin` checks). Next.js server actions check the origin for you.
- **Passwords**: use `type="password"` and `autocomplete="new-password"` / `"current-password"`; never log form data containing secrets.
- **Rate-limit** sign-up, login, password reset and contact forms, and consider bot protection (CAPTCHA, honeypot fields) on public forms.
- **Render user input as text** when echoing it back (`{state.email}`), never with `dangerouslySetInnerHTML`.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What is the difference between controlled and uncontrolled components?">
In a controlled component, React state holds the input's value, which is passed via value, and every change goes through onChange to update state. In an uncontrolled component, the DOM holds the value, typically with defaultValue, and the code reads it when needed, for example via FormData or a ref on submit.
</QA>

<QA q="How do you handle a form with many fields efficiently?">
Store the values in one state object and use a single change handler that reads the input's name to update the matching key, using checked for checkboxes. Alternatively, use uncontrolled inputs with FormData, or a library such as React Hook Form for large forms.
</QA>

<QA q="When should validation errors be shown?">
After the user has interacted with the field, typically on blur, or when they try to submit, and they should disappear as soon as the field becomes valid. Errors should appear next to the relevant field and be connected with aria-invalid and aria-describedby for accessibility.
</QA>

<QA q="What do form actions and useActionState do in React 19?">
A function can be passed to a form's action prop; React calls it with the FormData on submission. useActionState wraps that function to track its latest returned state and a pending flag, returning the state, an action to pass to the form and isPending, which reduces boilerplate for submissions and works with server actions.
</QA>

<QA q="Why must forms be validated on the server even if the client validates?">
Because anything in the browser can be bypassed: users can modify JavaScript, disable validation or send requests directly. The server must enforce validation and authorization to protect data integrity and security.
</QA>

</DeepDive>

<Terms>
  <Term name="Controlled component">An input whose value is driven by React state.</Term>
  <Term name="Uncontrolled component">An input whose value is managed by the DOM.</Term>
  <Term name="onChange">React's event fired on every edit of a form field.</Term>
  <Term name="defaultValue">The initial value of an uncontrolled input.</Term>
  <Term name="FormData">An object holding a form's named field values.</Term>
  <Term name="Validation">Checking that input satisfies rules before accepting it.</Term>
  <Term name="Touched field">A field the user has focused and left.</Term>
  <Term name="aria-invalid">An attribute marking a field as invalid for assistive technology.</Term>
  <Term name="aria-describedby">An attribute linking a field to its description or error.</Term>
  <Term name="Form action">A function passed to a form's action prop in React 19.</Term>
  <Term name="useActionState">A hook tracking an action's result and pending state.</Term>
  <Term name="useFormStatus">A hook reading the pending status of the enclosing form.</Term>
  <Term name="React Hook Form">A library for building performant forms with validation.</Term>
  <Term name="Idempotency key">A unique token preventing duplicate processing of a repeated request.</Term>
