<BigIdea>
<Tr>
<En>
**React** is a JavaScript library for building user interfaces out of **components**. A component is just a **function that returns what should appear on the screen**. You describe that with **JSX**, which looks like HTML but lives inside JavaScript: `return <h1>Hello, Sara!</h1>;`. Inside JSX, curly braces `{ }` let you drop in any JavaScript value: `<h1>Hello, {name}!</h1>`. Components can use other components, like LEGO bricks: a `Page` contains a `Header` and several `ProductCard`s. Data is passed **into** a component through **props**, which look like HTML attributes: `<ProductCard name="Pen" price={2} />`. With these few ideas, plus showing things **conditionally** and turning arrays into lists with `map`, you can build almost any screen. React's job is to turn your components into real page elements and keep them up to date.
</En>
<Ur>
**React** JavaScript ki library hai jo user interfaces ko **components** se banati hai. Component bas aisa **function hai jo batata hai ke screen par kya dikhna chahiye**. Ye **JSX** se likha jata hai, jo HTML jaisa dikhta hai magar JavaScript ke andar rehta hai: `return <h1>Hello, Sara!</h1>;`. JSX ke andar curly braces `{ }` me koi bhi JavaScript value rakhi ja sakti hai: `<h1>Hello, {name}!</h1>`. Components doosre components istemal kar sakte hain, LEGO ki eenton ki tarah: `Page` ke andar `Header` aur kai `ProductCard` hote hain. Data component ke **andar** **props** ke zariye bheja jata hai, jo HTML attributes jaise dikhte hain: `<ProductCard name="Pen" price={2} />`. In chand khayalat ke saath, aur cheezen **shart ke mutabiq** dikhane aur `map` se arrays ko lists banane ke saath, aap taqreeban har screen bana sakte hain. React ka kaam aap ke components ko page ke asli elements me badalna aur unhe taaza rakhna hai.
</Ur>
</Tr>
</BigIdea>

## At a glance

<Glance>
<What>
<Tr>
<En>

A component is a function with a **Capitalised** name that returns JSX:

```jsx
function Greeting({ name }) {
  return <h1>Hello, {name}!</h1>;
}

// using it, like an HTML tag:
<Greeting name="Sara" />
```

Read it like this: **"`Greeting` is a piece of screen. Give it a `name`, and it shows a heading that says hello to that name."**

</En>
<Ur>

Component aisa function hai jis ka naam **bare harf** se shuru ho aur jo JSX wapas kare:

```jsx
function Greeting({ name }) {
  return <h1>Hello, {name}!</h1>;
}

// istemal, HTML tag ki tarah:
<Greeting name="Sara" />
```

Ise aise parhein: **"`Greeting` screen ka ek tukra hai. Ise `name` do, aur ye us naam ko hello kehne wali heading dikhata hai."**

</Ur>
</Tr>
</What>
<Why>
<Tr>
<En>

- **Reuse.** Write a `ProductCard` once and show it 50 times with different data.
- **Small pieces are easy to understand.** A big page becomes a tree of small, named parts.
- **The screen follows the data.** You describe *what* should be shown for the current data; React works out *how* to update the page.
- **It's everywhere.** React (and Next.js, built on it) is the most common way to build web front ends, and React Native uses the same ideas for phone apps.

</En>
<Ur>

- **Dobara istemal.** `ProductCard` ek dafa likhein aur alag data ke saath 50 dafa dikhayen.
- **Chhote tukre samajhna aasan hai.** Bara page chhote, naam wale hisson ka darakht ban jata hai.
- **Screen data ke peechhe chalti hai.** Aap batate hain ke maujooda data ke liye *kya* dikhna chahiye; page *kaise* update ho ye React tay karta hai.
- **Ye har jagah hai.** React (aur us par bana Next.js) web front ends banane ka sab se aam tareeqa hai, aur React Native phone apps ke liye yahi khayalat istemal karta hai.

</Ur>
</Tr>
</Why>
<When>
<Tr>
<En>

Make a new component when a part of the screen:

- **repeats** (cards, list rows, buttons with the same style),
- has **its own job** (header, search box, cart summary),
- or makes the parent component **too long to read**.

</En>
<Ur>

Naya component tab banayen jab screen ka koi hissa:

- **dohraya jaye** (cards, list ki rows, ek hi style ke buttons),
- **apna alag kaam** kare (header, search box, cart ka khulasa),
- ya parent component ko **parhne ke liye bohot lamba** bana de.

</Ur>
</Tr>
</When>
<How>
<Tr>
<En>

1. Write a function with a Capitalised name.
2. Return JSX from it (one outer element).
3. Use `{ }` for JavaScript values inside the JSX.
4. Use the component like a tag, `<ProductCard … />`, passing data as props.

</En>
<Ur>

1. Bare harf wale naam ka function likhein.
2. Us se JSX wapas karein (ek bahar wala element).
3. JSX ke andar JavaScript values ke liye `{ }` lein.
4. Component ko tag ki tarah istemal karein, `<ProductCard … />`, aur data props ke taur par dein.

</Ur>
</Tr>
</How>
</Glance>

## Picture it

<Tr>
<En>

Think of **LEGO**. You don't build a castle from raw plastic; you build it from **bricks**. Some bricks are tiny (a window), some are made of other bricks (a tower made of walls and windows), and the castle is made of towers and walls. The same window design is used dozens of times.

A React page is the castle. Each **component** is a brick design: `Button`, `ProductCard`, `Header`. Bigger components are made by snapping smaller ones together.

**Props** are the options you choose for one copy of a brick: "this window is **blue**, that one is **red**". The design is the same; only the options differ.

**JSX** is the instruction booklet: a drawing of what the finished piece should look like. React reads the booklet and builds (or updates) the real thing on the page.

</En>
<Ur>

**LEGO** ka sochein. Aap qila kachche plastic se nahi banate; **eenton** se banate hain. Kuch eenten bohot chhoti hain (khirki), kuch doosri eenton se bani hain (deewaron aur khirkiyon se bana minaar), aur qila minaaron aur deewaron se bana hai. Wahi khirki ka design darjanon dafa istemal hota hai.

React page qila hai. Har **component** eent ka ek design hai: `Button`, `ProductCard`, `Header`. Bare components chhote components ko jor kar bante hain.

**Props** wo options hain jo aap eent ki ek copy ke liye chunte hain: "ye khirki **neeli** hai, wo **laal**". Design wahi hai; sirf options alag hain.

**JSX** hidayat ki kitab hai: tayyar hisse ki tasveer ke wo kaisa dikhe. React kitab parh kar page par asli cheez banata (ya update karta) hai.

</Ur>
</Tr>

<Step title="Your first component">

<Tr>
<En>
A component is a function that returns JSX. That's all. React calls the function and puts what it returns on the screen.
</En>
<Ur>
Component aisa function hai jo JSX wapas kare. Bas itna hi. React function call karta hai aur jo wo wapas kare use screen par rakh deta hai.
</Ur>
</Tr>

```jsx preview h=110
export default function App() {
  return <h1>Hello, React!</h1>;
}
```

<Happened>
<Tr>
<En>

- `App` is an ordinary JavaScript function. Its name starts with a capital letter, which is how React tells components apart from HTML tags like `h1`.
- It returns `<h1>Hello, React!</h1>`. That's **JSX**, not a string: there are no quotes around it.
- React called `App()` and turned the returned JSX into a real `<h1>` on the page.
- Try it: press **Edit** and change the text, or change `h1` to `h2` in both places.

</En>
<Ur>

- `App` aam JavaScript function hai. Is ka naam bare harf se shuru hota hai, isi se React components ko `h1` jaise HTML tags se alag pehchanta hai.
- Ye `<h1>Hello, React!</h1>` wapas karta hai. Ye **JSX** hai, string nahi: is ke gird quotes nahi.
- React ne `App()` call kiya aur wapas aane wale JSX ko page par asli `<h1>` bana diya.
- Aazmayen: **Edit** dabayen aur text badlein, ya dono jagah `h1` ko `h2` karein.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="JSX looks like HTML, with a few rules">

<Tr>
<En>
JSX is close to HTML, but it's JavaScript underneath, so a few things differ. These four rules cover almost every beginner error.
</En>
<Ur>
JSX HTML ke qareeb hai, magar neeche JavaScript hai, isliye chand cheezen alag hain. Ye chaar qawaid naye seekhne walon ke taqreeban har error ka ahata karte hain.
</Ur>
</Tr>

```jsx preview h=200
export default function App() {
  return (
    <>
      <h2 className="title">Kent mangoes</h2>
      <hr />
      <label htmlFor="qty">Quantity</label>
      <input id="qty" type="number" defaultValue={1} />
      <p style={{ color: "#b45309", fontWeight: 600 }}>$9 per 5 kg box</p>
    </>
  );
}
```

<Happened>
<Tr>
<En>

1. **One outer element.** A component returns **one** thing. To return several siblings without adding an extra `<div>`, wrap them in a **fragment**: `<>` … `</>`.
2. **`className`, not `class`; `htmlFor`, not `for`.** `class` and `for` are reserved words in JavaScript.
3. **Every tag must be closed.** `<hr>`, `<input>` and `<img>` become `<hr />`, `<input />` and `<img />`.
4. **Attributes are camelCase, and `style` takes an object:** `fontWeight`, not `font-weight`. The double braces are one `{ }` for "JavaScript here" and one `{ }` for the object itself.

- The `( )` around the multi-line JSX just lets it start on a new line after `return`.

</En>
<Ur>

1. **Ek bahar wala element.** Component **ek** cheez wapas karta hai. Izafi `<div>` jore baghair kai saath wale elements wapas karne hon to unhe **fragment** me lapetein: `<>` … `</>`.
2. **`class` nahi, `className`; `for` nahi, `htmlFor`.** `class` aur `for` JavaScript ke mehfooz alfaaz hain.
3. **Har tag band hona chahiye.** `<hr>`, `<input>` aur `<img>` `<hr />`, `<input />` aur `<img />` ban jate hain.
4. **Attributes camelCase hain, aur `style` object leta hai:** `font-weight` nahi, `fontWeight`. Dohre braces me ek `{ }` "yahan JavaScript" ke liye hai aur ek `{ }` khud object ke liye.

- Kai lines wale JSX ke gird `( )` bas is liye hain ke ye `return` ke baad nayi line se shuru ho sake.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="JavaScript inside JSX with { }">

<Tr>
<En>
Curly braces switch from "JSX" back to "JavaScript". Inside them you can put any **expression**: a variable, maths, a function call, a ternary. The result is shown on the page.
</En>
<Ur>
Curly braces "JSX" se wapas "JavaScript" par le aate hain. In ke andar koi bhi **expression** rakha ja sakta hai: variable, hisaab, function call, ternary. Nateeja page par dikhaya jata hai.
</Ur>
</Tr>

```jsx preview h=170
const user = { firstName: "Sara", lastName: "Lee", points: 1250 };

function formatPoints(points) {
  return points.toLocaleString("en-US") + " pts";
}

export default function App() {
  const today = "Tuesday";
  return (
    <div>
      <h2>Welcome back, {user.firstName}!</h2>
      <p>Full name: {user.firstName + " " + user.lastName}</p>
      <p>Points: {formatPoints(user.points)}</p>
      <p>Status: {user.points >= 1000 ? "Gold member" : "Member"}</p>
      <p>Today is {today}. 2 + 3 = {2 + 3}</p>
    </div>
  );
}
```

<Happened>
<Tr>
<En>

- `{user.firstName}` showed the value of that property.
- `{formatPoints(user.points)}` called a normal function and showed what it returned.
- `{… ? "Gold member" : "Member"}` picked one of two texts.
- You **can't** put statements like `if` or `for` directly inside `{ }`: only things that produce a value. Do the work above the `return`, then show the result.

</En>
<Ur>

- `{user.firstName}` ne us property ki value dikhayi.
- `{formatPoints(user.points)}` ne aam function call kiya aur jo us ne wapas kiya wo dikhaya.
- `{… ? "Gold member" : "Member"}` ne do me se ek text chuna.
- `{ }` ke andar `if` ya `for` jaise statements seedha **nahi** rakh sakte: sirf wo cheezen jo value banayen. Kaam `return` se upar karein, phir nateeja dikhayen.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="JSX is just JavaScript objects">

<Tr>
<En>
Before the browser runs your code, a tool turns every JSX tag into a function call that creates a plain object describing the element. Here's a tiny imitation, so you can see there's no magic.
</En>
<Ur>
Browser aap ka code chalane se pehle ek tool har JSX tag ko aisi function call me badal deta hai jo element bayan karne wala saada object banati hai. Ye ek chhoti si naqal hai, taa ke aap dekh saken ke koi jaadu nahi.
</Ur>
</Tr>

```javascript
function createElement(type, props, ...children) {
  return { type: type, props: { ...props, children: children } };
}

const name = "Sara";

// What <div className="card"><h1>Hello, {name}!</h1></div> becomes:
const element = createElement(
  "div",
  { className: "card" },
  createElement("h1", null, "Hello, ", name, "!")
);

console.log(JSON.stringify(element, null, 2));
```

```text output
{
  "type": "div",
  "props": {
    "className": "card",
    "children": [
      {
        "type": "h1",
        "props": {
          "children": [
            "Hello, ",
            "Sara",
            "!"
          ]
        }
      }
    ]
  }
}
```

<Happened>
<Tr>
<En>

- Each tag became a call with a **type** (`"div"`, `"h1"`), its **props** (attributes) and its **children** (what's inside).
- The result is just nested objects. React's real version is called `jsx()` (older code: `React.createElement`), and it works the same way.
- This explains the JSX rules: a component returns **one** object (so one outer element), attributes are object keys (so `className`), and `{name}` is simply a value placed among the children.

</En>
<Ur>

- Har tag aisi call ban gaya jis me **type** (`"div"`, `"h1"`), us ke **props** (attributes) aur us ke **children** (andar ki cheezen) hain.
- Nateeja bas ek doosre ke andar objects hain. React ka asli version `jsx()` kehlata hai (purane code me `React.createElement`), aur isi tarah kaam karta hai.
- Isi se JSX ke qawaid samajh aate hain: component **ek** object wapas karta hai (isliye ek bahar wala element), attributes object ki keys hain (isliye `className`), aur `{name}` bas children ke darmiyan rakhi gayi value hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Components inside components">

<Tr>
<En>
You use your own component exactly like an HTML tag: `<Header />`. This is how big screens are built from small pieces.
</En>
<Ur>
Apna component bilkul HTML tag ki tarah istemal hota hai: `<Header />`. Bari screens chhote tukron se isi tarah banti hain.
</Ur>
</Tr>

```jsx preview h=230
function Header() {
  return (
    <header style={{ borderBottom: "1px solid #e5e7eb", marginBottom: 12 }}>
      <strong>Fresh Mart</strong>
    </header>
  );
}

function Banner() {
  return <p style={{ background: "#fef3c7", padding: 8 }}>Free delivery over $50</p>;
}

function Footer() {
  return <footer style={{ color: "#6b7280", fontSize: 13 }}>© Fresh Mart</footer>;
}

export default function App() {
  return (
    <div>
      <Header />
      <Banner />
      <Banner />
      <Footer />
    </div>
  );
}
```

<Happened>
<Tr>
<En>

- `App` is built from `Header`, `Banner` and `Footer`. This parent-and-children structure is called the **component tree**.
- `<Banner />` is used twice, so it appears twice. Write once, use many times.
- The capital letter matters: `<Banner />` means "my component"; `<banner />` would mean an HTML tag called "banner", which doesn't exist.
- Define components at the **top level** of the file, never inside another component.

</En>
<Ur>

- `App` `Header`, `Banner` aur `Footer` se bana hai. Is parent aur children wale dhaanche ko **component tree** kehte hain.
- `<Banner />` do dafa istemal hua, isliye do dafa nazar aata hai. Ek dafa likho, kai dafa istemal karo.
- Bara harf ahem hai: `<Banner />` ka matlab "mera component"; `<banner />` ka matlab "banner" naam ka HTML tag hota, jo maujood hi nahi.
- Components file ki **sab se upar ki satah** par banayen, kabhi doosre component ke andar nahi.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Props: passing data into a component">

<Tr>
<En>
A component that always shows the same thing isn't very useful. **Props** let the parent pass data in. They're written like HTML attributes, and the component receives them as **one object**, usually destructured right in the parameter list.
</En>
<Ur>
Jo component hamesha ek hi cheez dikhaye wo zyada kaam ka nahi. **Props** parent ko andar data bhejne dete hain. Ye HTML attributes ki tarah likhe jate hain, aur component unhe **ek object** ki shakal me leta hai, aam taur par parameter list me hi destructure kar ke.
</Ur>
</Tr>

```jsx preview h=260
function ProductCard({ name, price, inStock }) {
  return (
    <div style={{ border: "1px solid #e5e7eb", borderRadius: 8, padding: 10, marginBottom: 8 }}>
      <strong>{name}</strong> — ${price}
      <div style={{ color: inStock ? "#15803d" : "#b91c1c" }}>
        {inStock ? "In stock" : "Sold out"}
      </div>
    </div>
  );
}

export default function App() {
  return (
    <div>
      <ProductCard name="Notebook" price={5} inStock={true} />
      <ProductCard name="Desk lamp" price={30} inStock={false} />
      <ProductCard name="Pen" price={2} inStock />
    </div>
  );
}
```

<Happened>
<Tr>
<En>

- One `ProductCard` design, three different cards, because each got different props.
- **Text** props use quotes: `name="Notebook"`. **Any other value** uses braces: `price={5}`, `inStock={false}`.
- Writing just `inStock` (no value) means `inStock={true}`.
- `function ProductCard({ name, price, inStock })` destructures the props object. Without destructuring you'd write `function ProductCard(props)` and use `props.name`.
- The `$` before `{price}` is plain text in JSX, so it's displayed as a dollar sign.
- Props flow **one way**: parent to child. A child must never change the props it receives.

</En>
<Ur>

- `ProductCard` ka ek design, teen alag cards, kyun ke har ek ko alag props mile.
- **Text** props quotes istemal karte hain: `name="Notebook"`. **Baqi har value** braces: `price={5}`, `inStock={false}`.
- Sirf `inStock` likhna (baghair value) ka matlab `inStock={true}` hai.
- `function ProductCard({ name, price, inStock })` props object ko destructure karta hai. Destructuring ke baghair aap `function ProductCard(props)` likhte aur `props.name` istemal karte.
- `{price}` se pehle `$` JSX me saada text hai, isliye dollar ka nishaan dikhta hai.
- Props **ek taraf** behte hain: parent se child. Child ko milne wale props kabhi nahi badalne chahiyen.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="children: whatever goes between the tags">

<Tr>
<En>
Whatever you put **between** a component's opening and closing tags arrives as a special prop called **`children`**. It's how you build wrapper components such as cards, panels and layouts.
</En>
<Ur>
Component ke kholne aur band karne wale tags ke **darmiyan** jo kuch rakhein wo **`children`** naam ke khaas prop ki shakal me pohanchta hai. Cards, panels aur layouts jaise wrapper components isi tarah bante hain.
</Ur>
</Tr>

```jsx preview h=250
function Card({ title, children }) {
  return (
    <section style={{ border: "1px solid #e5e7eb", borderRadius: 10, padding: 12, marginBottom: 10 }}>
      <h3 style={{ margin: "0 0 6px" }}>{title}</h3>
      {children}
    </section>
  );
}

export default function App() {
  return (
    <div>
      <Card title="Delivery">
        <p>Orders before 2 pm arrive the next day.</p>
      </Card>
      <Card title="Returns">
        <p>Return any item within 30 days.</p>
        <button>Start a return</button>
      </Card>
    </div>
  );
}
```

<Happened>
<Tr>
<En>

- `Card` draws the border and the title; it doesn't care what's inside.
- The first card's `children` is one paragraph; the second's is a paragraph **and** a button.
- `{children}` marks where the inside content goes.
- This pattern keeps styling in one place: change `Card`, and every card on the site updates.

</En>
<Ur>

- `Card` border aur title banata hai; use is se gharz nahi ke andar kya hai.
- Pehle card ke `children` ek paragraph hain; doosre ke ek paragraph **aur** ek button.
- `{children}` batata hai ke andar ka mawad kahan aayega.
- Ye namoona styling ko ek jagah rakhta hai: `Card` badlein, aur site ka har card update ho jata hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Show something only sometimes">

<Tr>
<En>
Because JSX is JavaScript, you choose what to show with ordinary JavaScript: a **ternary** (`a ? b : c`) to pick between two things, **`&&`** to show something or nothing, or an `if` **before** the `return`.
</En>
<Ur>
Chunke JSX JavaScript hai, kya dikhana hai ye aam JavaScript se chunte hain: do cheezon me se ek chunne ke liye **ternary** (`a ? b : c`), kuch ya kuch nahi dikhane ke liye **`&&`**, ya `return` se **pehle** `if`.
</Ur>
</Tr>

```jsx preview h=260
function CartSummary({ items, isLoggedIn }) {
  if (items.length === 0) {
    return <p>Your cart is empty.</p>;
  }
  return (
    <div style={{ marginBottom: 12 }}>
      <p>{items.length} item(s) in your cart.</p>
      {items.length >= 3 && <p style={{ color: "#15803d" }}>You get free delivery!</p>}
      {isLoggedIn ? <button>Checkout</button> : <button>Log in to checkout</button>}
    </div>
  );
}

export default function App() {
  return (
    <div>
      <CartSummary items={[]} isLoggedIn={true} />
      <CartSummary items={["Pen", "Notebook"]} isLoggedIn={false} />
      <CartSummary items={["Pen", "Notebook", "Lamp"]} isLoggedIn={true} />
      <p>Messages: {0 && "You have messages"}</p>
    </div>
  );
}
```

<Happened>
<Tr>
<En>

- **Empty cart:** the `if` returned early with a different message.
- **Two items:** the free-delivery line was skipped, because `items.length >= 3` was `false`, and `false` shows nothing. Not logged in, so the ternary picked "Log in to checkout".
- **Three items:** both conditions were true.
- **The trap, last line:** `{0 && "…"}` showed a **`0`**. `&&` gives back the left side when it's falsy, and React shows numbers, including 0. Use `count > 0 && …` instead of `count && …`.

</En>
<Ur>

- **Khaali cart:** `if` ne jaldi alag paighaam ke saath return kar diya.
- **Do items:** free delivery wali line chhor di gayi, kyun ke `items.length >= 3` `false` tha, aur `false` kuch nahi dikhata. Login nahi tha, isliye ternary ne "Log in to checkout" chuna.
- **Teen items:** dono shartein sach thin.
- **Phanda, aakhri line:** `{0 && "…"}` ne **`0`** dikhaya. `&&` baayen taraf ki value wapas deta hai jab wo falsy ho, aur React numbers dikhata hai, 0 samet. `count && …` ke bajaye `count > 0 && …` lein.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Lists: map an array to elements">

<Tr>
<En>
To show a list, turn an array of data into an array of JSX with **`map`**. Each item in the list needs a **`key`**: a value that's unique among its siblings and stays the same for that item, usually its id.
</En>
<Ur>
List dikhane ke liye data ki array ko **`map`** se JSX ki array me badlein. List ke har item ko **`key`** chahiye: aisi value jo apne saathiyon me unique ho aur us item ke liye wahi rahe, aam taur par us ki id.
</Ur>
</Tr>

```jsx preview h=230
const products = [
  { id: 101, name: "Notebook", price: 5 },
  { id: 102, name: "Pen", price: 2 },
  { id: 103, name: "Desk lamp", price: 30 },
];

export default function App() {
  const cheap = products.filter((p) => p.price < 10);
  return (
    <div>
      <h3>All products</h3>
      <ul>
        {products.map((product) => (
          <li key={product.id}>
            {product.name} — ${product.price}
          </li>
        ))}
      </ul>
      <p>Under $10: {cheap.map((p) => p.name).join(", ")}</p>
    </div>
  );
}
```

<Happened>
<Tr>
<En>

- `products.map(product => <li …>…</li>)` produced an array of three `<li>` elements, and React showed them in order.
- `key={product.id}` lets React tell the items apart. When the list changes (an item is added, removed or moved), React uses keys to update only what changed and to keep each item's state with the right item.
- Don't use the array **index** as the key if the list can be reordered or filtered; use a real id.
- Everything from the Arrays lesson works here: `filter`, `sort`, `join`.

</En>
<Ur>

- `products.map(product => <li …>…</li>)` ne teen `<li>` elements ki array banayi, aur React ne unhe tarteeb se dikhaya.
- `key={product.id}` React ko items alag pehchanne deta hai. Jab list badle (item jure, hate ya jagah badle), React keys se sirf wahi update karta hai jo badla aur har item ki state sahi item ke saath rakhta hai.
- Agar list ki tarteeb badal sakti ho ya filter ho sakti ho to array ka **index** key na banayen; asli id lein.
- Arrays lesson ki har cheez yahan chalti hai: `filter`, `sort`, `join`.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Responding to clicks">

<Tr>
<En>
To react to the user, pass a **function** to an event prop such as `onClick`, `onChange` or `onSubmit`. Pass the function itself, without `( )`; React calls it when the event happens.
</En>
<Ur>
User ko jawab dene ke liye `onClick`, `onChange` ya `onSubmit` jaise event prop ko **function** dein. Function khud dein, `( )` ke baghair; event hone par React use call karta hai.
</Ur>
</Tr>

```jsx preview h=150
function LikeButton({ label }) {
  function handleClick() {
    alert("You liked " + label);
  }
  return <button onClick={handleClick}>Like {label}</button>;
}

export default function App() {
  return (
    <div style={{ display: "flex", gap: 8 }}>
      <LikeButton label="Notebook" />
      <LikeButton label="Pen" />
      <button onClick={() => alert("Saved!")}>Save</button>
    </div>
  );
}
```

<Happened>
<Tr>
<En>

- Click a **Like** button: an alert names the product. Each button's `handleClick` remembers its own `label` (a closure, from the Scope lesson).
- `onClick={handleClick}` passes the function. `onClick={handleClick()}` would call it **while drawing the page** and pass its result (`undefined`), so nothing would happen on click.
- For a quick one-liner, write an arrow right in place: `onClick={() => alert("Saved!")}`. This is also how you pass arguments: `onClick={() => remove(item.id)}`.
- Event names are camelCase: `onClick`, not `onclick`.
- The page doesn't change after a click yet. Making the screen update is what **state** is for, the next lesson.

</En>
<Ur>

- Kisi **Like** button par click karein: alert product ka naam leta hai. Har button ka `handleClick` apna `label` yaad rakhta hai (closure, Scope lesson se).
- `onClick={handleClick}` function deta hai. `onClick={handleClick()}` use **page banate waqt** call kar deta aur us ka nateeja (`undefined`) deta, isliye click par kuch na hota.
- Jaldi wali ek line ke liye wahin arrow likhein: `onClick={() => alert("Saved!")}`. Arguments bhi isi tarah diye jate hain: `onClick={() => remove(item.id)}`.
- Events ke naam camelCase hain: `onclick` nahi, `onClick`.
- Click ke baad page abhi nahi badalta. Screen update karna **state** ka kaam hai, agla lesson.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Components must be pure">

<Tr>
<En>
React may call your component function **many times**: whenever something changes, and sometimes twice in development to catch mistakes. So a component should behave like a **pure function**: same props in, same JSX out, and no changing things outside itself while rendering.
</En>
<Ur>
React aap ke component function ko **kai dafa** call kar sakta hai: jab bhi kuch badle, aur development me ghaltiyan pakarne ke liye kabhi do dafa. Isliye component ko **pure function** ki tarah hona chahiye: wahi props andar, wahi JSX bahar, aur render karte waqt apne bahar kuch na badle.
</Ur>
</Tr>

```jsx preview h=150
let guestCount = 0;

function BadGuest() {
  guestCount = guestCount + 1;          // changes something outside: impure
  return <li>Guest #{guestCount}</li>;
}

function GoodGuest({ number }) {
  return <li>Guest #{number}</li>;      // only uses its props: pure
}

export default function App() {
  return (
    <div style={{ display: "flex", gap: 32 }}>
      <ul><BadGuest /><BadGuest /><BadGuest /></ul>
      <ul><GoodGuest number={1} /><GoodGuest number={2} /><GoodGuest number={3} /></ul>
    </div>
  );
}
```

<Happened>
<Tr>
<En>

- Both lists happen to show 1, 2, 3 **this time**. But `BadGuest`'s numbers depend on how many times React has called it. In development (Strict Mode) React renders twice on purpose, and the list would show 2, 4, 6; after any re-render they'd keep climbing.
- `GoodGuest` gets its number as a prop. However many times React calls it, the answer is the same.
- Rule: while rendering, only **calculate** from props (and state). Changing variables outside, fetching data or touching the page directly belong in event handlers or effects (later lessons).

</En>
<Ur>

- Dono lists **is dafa** ittefaq se 1, 2, 3 dikhati hain. Magar `BadGuest` ke numbers is par munhasir hain ke React ne use kitni dafa call kiya. Development (Strict Mode) me React jaan boojh kar do dafa render karta hai, aur list 2, 4, 6 dikhati; har dobara render ke baad ye barhte rehte.
- `GoodGuest` apna number prop ki shakal me leta hai. React use jitni dafa bhi call kare, jawab wahi.
- Qaida: render karte waqt props (aur state) se sirf **hisaab** karein. Bahar ke variables badalna, data mangwana ya page ko seedha chhuna event handlers ya effects ka kaam hai (agle lessons).

</Ur>
</Tr>
</Happened>

</Step>

</Walkthrough>

## Common mistakes

<Compare>
<Bad title="Lowercase component name">

```jsx
function productCard() { return <div>…</div>; }
<productCard />   // treated as an unknown HTML tag
```

</Bad>
<Good title="Capitalise components">

```jsx
function ProductCard() { return <div>…</div>; }
<ProductCard />
```

</Good>
</Compare>

<Compare>
<Bad title="Two elements side by side">

```jsx
return (
  <h1>Title</h1>
  <p>Text</p>
);   // syntax error
```

</Bad>
<Good title="Wrap them in a fragment">

```jsx
return (
  <>
    <h1>Title</h1>
    <p>Text</p>
  </>
);
```

</Good>
</Compare>

<Compare>
<Bad title="HTML habits">

```jsx
<div class="card" style="color: red">
  <img src="a.png">
</div>
```

</Bad>
<Good title="JSX versions">

```jsx
<div className="card" style={{ color: "red" }}>
  <img src="a.png" alt="" />
</div>
```

</Good>
</Compare>

<Compare>
<Bad title="List without keys, or with index keys on a changing list">

```jsx
{todos.map((todo, i) => <li key={i}>{todo.text}</li>)}
```

</Bad>
<Good title="A stable id as the key">

```jsx
{todos.map((todo) => <li key={todo.id}>{todo.text}</li>)}
```

</Good>
</Compare>

<Compare>
<Bad title="Calling the handler while rendering">

```jsx
<button onClick={deleteItem(item.id)}>Delete</button>
```

<Tr>
<En>This deletes the item as soon as the button is drawn.</En>
<Ur>Ye button bante hi item delete kar deta hai.</Ur>
</Tr>

</Bad>
<Good title="Pass a function">

```jsx
<button onClick={() => deleteItem(item.id)}>Delete</button>
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **`{count && …}` when `count` can be 0** shows a stray `0`. Use `count > 0 && …`.
- **Putting `if` or `for` inside `{ }`.** Use a ternary, `&&` or `map`, or compute the value above the `return`.
- **Defining a component inside another component.** It's recreated on every render and loses its state.
- **Changing props inside a child** (`props.price = 0`). Props are read-only; ask the parent to change them.
- **Forgetting `alt` on images**, which hurts accessibility.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Jab `count` 0 ho sakta ho to `{count && …}`** ek faltu `0` dikhata hai. `count > 0 && …` lein.
- **`{ }` ke andar `if` ya `for` rakhna.** Ternary, `&&` ya `map` lein, ya value `return` se upar nikalein.
- **Ek component ke andar doosra component banana.** Ye har render par naya banta hai aur apni state kho deta hai.
- **Child ke andar props badalna** (`props.price = 0`). Props sirf parhne ke liye hain; parent se badalwayen.
- **Images par `alt` bhoolna**, jo rasai ko nuqsan deta hai.

</Ur>
</Tr>

## Remember

<Takeaways>
<Tr>
<En>

- A component is a **function with a Capitalised name** that returns JSX.
- JSX rules: one outer element (use `<>…</>`), `className`, close every tag, camelCase attributes, `style={{ … }}`.
- `{ }` puts any JavaScript **expression** into JSX. Do statements (`if`, loops) above the `return`.
- JSX becomes plain objects describing elements; React turns them into the real page.
- **Props** pass data from parent to child, like attributes; text in quotes, everything else in braces. Props are read-only.
- `children` is whatever sits between a component's tags.
- Show things conditionally with `if`, `? :` or `&&` (watch out for `0 &&`).
- Render lists with `map` and give each item a stable `key`.
- Pass functions to `onClick` and friends, without calling them. Keep components pure.

</En>
<Ur>

- Component **bare harf wale naam ka function** hai jo JSX wapas karta hai.
- JSX ke qawaid: ek bahar wala element (`<>…</>` lein), `className`, har tag band karein, camelCase attributes, `style={{ … }}`.
- `{ }` JSX me koi bhi JavaScript **expression** rakhta hai. Statements (`if`, loops) `return` se upar karein.
- JSX elements bayan karne wale saade objects ban jata hai; React unhe asli page me badalta hai.
- **Props** attributes ki tarah parent se child ko data dete hain; text quotes me, baqi sab braces me. Props sirf parhne ke liye hain.
- `children` wo hai jo component ke tags ke darmiyan ho.
- Cheezen shart ke saath `if`, `? :` ya `&&` se dikhayen (`0 &&` se hoshiyar).
- Lists `map` se banayen aur har item ko pakki `key` dein.
- `onClick` waghaira ko functions dein, unhe call kiye baghair. Components pure rakhein.

</Ur>
</Tr>

<DeepDive title="How React puts components on the page">

**Starting React.** A plain React app has one HTML element (often `<div id="root">`) and a few lines that hand it to React:

```text
import { createRoot } from "react-dom/client";
import App from "./App";

createRoot(document.getElementById("root")).render(<App />);
```

Frameworks such as Next.js do this for you.

**Render and commit.** When React renders, it calls your components to get a new tree of element objects, compares it with the previous tree (**reconciliation**), and then **commits** only the differences to the real DOM. That's why you describe the whole UI for the current data, and React works out the minimal changes.

**Keys and identity.** During reconciliation React matches children by **type and position**, or by **key** in lists. Changing a key tells React "this is a different item", so it throws away the old one (and its state) and creates a new one. You can use this on purpose: `<Profile key={userId} />` resets the profile when the user changes.

**Strict Mode.** `<StrictMode>` in development renders components twice and runs effects twice, to expose impure code. It has no effect in production.

**JSX compiles away.** With the modern "automatic runtime", `<div className="a">Hi</div>` becomes `jsx("div", { className: "a", children: "Hi" })`, imported automatically from `react/jsx-runtime`, which is why modern files don't need `import React`.

**What can be rendered.** Strings and numbers are shown as text. `null`, `undefined`, `true` and `false` render nothing. Arrays render each item. Plain objects can't be rendered directly ("Objects are not valid as a React child"); show one of their properties instead.

**Props are just an object.** You can spread one in: `<ProductCard {...product} />` passes every property of `product` as a prop. Convenient, but it hides which props are used.

**TypeScript.** In `.tsx` files you type props like any object: `function ProductCard({ name, price }: { name: string; price: number })`, or with a named `type ProductCardProps`.

</DeepDive>

<DeepDive title="Real world: the list that showed the wrong checkbox">

A to-do app rendered items with the array index as the key:

```jsx
{todos.map((todo, index) => <TodoRow key={index} todo={todo} />)}
```

Each `TodoRow` had its own "editing" state (a checkbox showing whether the row was in edit mode). Users reported a strange bug: they'd start editing the **third** item, delete the **first** item, and suddenly the edit box was open on a **different** task.

When the first item was deleted, every item moved up one position. With index keys, the row that used to have key `2` now had key `1`, so React thought "key 2 is gone, key 1 still exists" and kept row 1's state (including "editing: true") for whatever task now sat at index 1. The data moved, but the state stayed with the position.

Switching to `key={todo.id}` fixed it instantly: React now followed each task by its id, so its state moved with it. The same bug appears with form inputs inside lists (typed text jumps to another row) and with animations. If a list can be reordered, filtered, or have items inserted or removed, the key must come from the data.

</DeepDive>

<DeepDive title="Security lens">

React protects you from the most common front-end attack by default, as long as you don't switch the protection off.

- **Automatic escaping.** Text in `{ }` is always inserted as **text**, never as HTML. If a user's name is `<img src=x onerror=alert(1)>`, React shows those characters literally, so it can't run. This blocks most cross-site scripting (XSS).
- **`dangerouslySetInnerHTML` turns escaping off.** `<div dangerouslySetInnerHTML={{ __html: comment }} />` inserts raw HTML. Only use it with HTML you trust or have sanitised with a library such as DOMPurify. The long, scary name is deliberate.
- **Dangerous URLs.** React escapes text, not the meaning of URLs. `<a href={user.website}>` with a value like `javascript:…` can run code when clicked. Allow only `http:` and `https:` links from users. (Newer React versions block `javascript:` URLs with a warning, but don't rely on it.)
- **Spreading untrusted props.** `<div {...userControlledObject} />` lets data set any attribute, including event handlers or `dangerouslySetInnerHTML`. Pass named props instead.
- **Secrets in components.** Everything in client components is sent to the browser. API keys, admin flags and internal data shown "only to admins" through conditional rendering are still in the JavaScript bundle; real access control must happen on the server.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What is JSX?">
JSX is a syntax extension that lets you write HTML-like markup inside JavaScript. A compiler turns each element into a function call, jsx or React.createElement, that returns a plain object describing the element. Curly braces embed JavaScript expressions, and attributes use JavaScript naming such as className.
</QA>

<QA q="What is the difference between props and state?">
Props are inputs passed from a parent component and are read-only inside the child. State is data owned by a component that can change over time, usually through a setter from useState, and changing it causes a re-render. Props flow down the tree; state lives in the component that owns it.
</QA>

<QA q="Why do lists need keys?">
Keys give each element in a list a stable identity among its siblings. During reconciliation React uses them to match old and new items, so it can update, move, add or remove only what changed and keep each item's state attached to the right item. Keys should be unique and stable, typically an id from the data; using the index causes bugs when the list is reordered or filtered.
</QA>

<QA q="Why must component names start with a capital letter?">
JSX treats lowercase tags as built-in HTML elements and capitalised tags as references to components in scope. A lowercase component name would be rendered as an unknown HTML tag.
</QA>

<QA q="What is a fragment?">
A fragment groups several elements without adding an extra node to the DOM. It is written as empty angle brackets or React.Fragment, and the long form accepts a key, which is useful when mapping a list to groups of elements.
</QA>

<QA q="What does it mean that components should be pure?">
Given the same props and state, a component should return the same JSX and must not change anything outside itself while rendering, such as global variables or the DOM. React may render components more than once, and in development Strict Mode deliberately does so to surface impure code. Side effects belong in event handlers or effects.
</QA>

<QA q="How does React prevent cross-site scripting?">
Values inserted with curly braces are escaped and rendered as text, so markup in user data is not interpreted as HTML. The protection is bypassed by dangerouslySetInnerHTML and does not cover dangerous URL schemes in attributes such as href, which must be validated.
</QA>

  <Term name="React">A JavaScript library for building user interfaces from components.</Term>
