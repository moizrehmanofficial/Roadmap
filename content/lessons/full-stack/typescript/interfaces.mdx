## What is it?

Interfaces and type aliases define the SHAPE of objects — what properties they must have and their types. Think of them as contracts that objects must fulfill.

## Why does it matter?

Ensures every object of that 'shape' has required fields, catching missing or wrongly-typed data instantly. Makes APIs self-documenting.

## When and where do you use it?

For any object with multiple properties: component props, API responses, function parameters, database row shapes.

## How does it work?

Use interface for object shapes (extensible, can be merged). Use type for unions, primitives, tuples, or when you need advanced type features.

## Examples

### interface — object contracts

```typescript
// Basic interface
interface User {
  id: number;           // required
  name: string;         // required
  email: string;        // required
  role?: "admin" | "user"; // ? = optional, literal union type
  readonly createdAt: Date; // readonly = cannot change after creation
}

// Using the interface
function greetUser(user: User): string {
  return `Hello, ${user.name} (${user.role ?? "user"})`;
}

const u: User = {
  id: 1,
  name: "Ali",
  email: "ali@example.com",
  createdAt: new Date(),
  // role is optional so we can omit it
};

// u.createdAt = new Date(); // ❌ Error: cannot assign to 'createdAt' — readonly

// Extending interfaces
interface AdminUser extends User {
  permissions: string[];
  lastLogin: Date;
}

// Implementing multiple interfaces
interface Serializable {
  toJSON(): string;
}

interface Printable {
  print(): void;
}

interface Document extends Serializable, Printable {
  title: string;
  content: string;
}
```

### type aliases — more flexible

```typescript
// Type alias for primitives and unions
type ID = string | number;
type Status = "active" | "inactive" | "pending";
type Direction = "up" | "down" | "left" | "right";

// Type alias for objects (similar to interface)
type Point = {
  x: number;
  y: number;
};

// Intersection types — combine types
type Employee = {
  employeeId: number;
  department: string;
};

type UserEmployee = User & Employee; // must have ALL fields from both

// Conditional types (advanced)
type IsString<T> = T extends string ? "yes" : "no";
type Result = IsString<string>; // "yes"

// Key differences: interface vs type
// ✅ interface: can be extended with 'extends', can be merged
// ✅ type: can use unions (|), intersections (&), computed types

// Best practice:
// → Use 'interface' for object shapes you'll extend/implement
// → Use 'type' for unions, primitives, tuples, computed types

// Function types
type Formatter = (value: string) => string;
const uppercase: Formatter = (s) => s.toUpperCase();

// Callback type
type OnChange = (event: React.ChangeEvent<HTMLInputElement>) => void;
```

## Key terms

<Terms>
  <Term name="Optional property (?)">Property that may or may not exist: name?: string</Term>
  <Term name="Readonly">Property that cannot be changed after creation: readonly id: number</Term>
  <Term name="Union type (|)">Value can be one of several types: string | number</Term>
  <Term name="Intersection type (&)">Value must satisfy ALL types: TypeA & TypeB</Term>
  <Term name="Literal type">Exact value as a type: 'admin' | 'user' instead of just string</Term>
</Terms>
