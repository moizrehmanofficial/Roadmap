<BigIdea>
<Tr>
<En>
The `<head>` holds **information about the page** (metadata) that browsers, search engines and social apps read. The essentials are `<meta charset="utf-8">`, the **viewport** tag, a unique **`<title>`** (the blue link in search results and the tab name) and a **meta description** (often the snippet below it). **SEO** means helping search engines **crawl** (find), **index** (store and understand) and **rank** (order) your pages. The technical basics: one **canonical URL** per page, **robots.txt** and **sitemap.xml**, `noindex` for pages that shouldn't appear, **Open Graph** for social previews, **structured data** (JSON-LD) for rich results, semantic HTML and **fast, mobile-friendly** pages. The biggest factor is still content that answers what people search for.
</En>
<Ur>
`<head>` me **page ke baare me maloomat** (metadata) hoti hai jo browsers, search engines aur social apps parhte hain. Zaroori cheezen: `<meta charset="utf-8">`, **viewport** tag, munfarid **`<title>`** (search results ka neela link aur tab ka naam) aur **meta description** (aksar us ke neeche ka snippet). **SEO** ka matlab search engines ki madad karna hai ke wo aap ke pages **crawl** (dhoondhna), **index** (mehfooz karna aur samajhna) aur **rank** (tarteeb dena) karen. Takneeki bunyaden: har page ka ek **canonical URL**, **robots.txt** aur **sitemap.xml**, na dikhne wale pages par `noindex`, social previews ke liye **Open Graph**, rich results ke liye **structured data** (JSON-LD), semantic HTML aur **tez, mobile-friendly** pages. Sab se bari cheez ab bhi wo mawad hai jo logon ke sawal ka jawab de.

## Learn it step by step

<Walkthrough>

<Step title="How search engines work">

<Tr>
<En>

Three stages, each with different fixes:

1. **Crawling:** bots fetch URLs from links, sitemaps and earlier crawls, respecting `robots.txt`. Never crawled? Add links or a sitemap.
2. **Indexing:** the engine renders the page (Google runs JavaScript, later and with limits), extracts text, links, headings, metadata and structured data, picks a canonical and stores it. Crawled but not indexed? It may be a duplicate, thin, or `noindex`.
3. **Ranking:** hundreds of signals order the results: relevance, quality and trust, links, page experience (mobile, speed, HTTPS), freshness, location and language. Indexed but low? Improve the content.

**Google Search Console** and **Bing Webmaster Tools** (both free) show crawl and index status per URL, queries and clicks. `site:yourdomain.com` shows roughly what's indexed.

</En>
<Ur>

Teen marhale, har ek ke alag hal:

1. **Crawling:** bots `robots.txt` ka khayal rakhte hue links, sitemaps aur pichhli crawls se URLs laate hain. Kabhi crawl nahi hua? Links ya sitemap joren.
2. **Indexing:** engine page render karta hai (Google JavaScript chalata hai, der se aur hadon ke saath), text, links, headings, metadata aur structured data nikalta hai, canonical chunta hai aur mehfooz karta hai. Crawl hua magar index nahi? Shayad dohra, kamzor, ya `noindex` hai.
3. **Ranking:** saikron isharat natijon ki tarteeb tay karte hain: mutabiqat, mayaar aur bharosa, links, page ka tajurba (mobile, raftar, HTTPS), taazgi, maqam aur zaban. Index hai magar neeche? Mawad behtar karein.

**Google Search Console** aur **Bing Webmaster Tools** (dono muft) har URL ki crawl aur index halat, queries aur clicks dikhate hain. `site:yourdomain.com` taqreeban dikhata hai kya index hai.

</Ur>
</Tr>

<Step title="The essential meta tags">

<Tr>
<En>

- **`<meta charset="utf-8">`:** encoding, within the first 1024 bytes, so first.
- **`<meta name="viewport" content="width=device-width, initial-scale=1">`:** use the device width instead of a pretend 980 px desktop. Never add `user-scalable=no` or `maximum-scale=1` (blocks zoom).
- **`<title>`:** required on every page: tabs, bookmarks, history and the search headline.
- **`<meta name="description">`:** a summary search engines often (not always) use as the snippet.
- **`<html lang="en">`:** the page language.

Frameworks generate them from config (Next.js `metadata`, Astro/Nuxt head helpers, WordPress SEO plugins). Below, a script parses a head and prints each tag with its length.

</En>
<Ur>

- **`<meta charset="utf-8">`:** encoding, pehle 1024 bytes ke andar, isliye sab se pehle.
- **`<meta name="viewport" content="width=device-width, initial-scale=1">`:** device ki asli chaurai, naqli 980 px desktop nahi. `user-scalable=no` ya `maximum-scale=1` kabhi nahi (zoom rokta hai).
- **`<title>`:** har page par lazmi: tabs, bookmarks, history aur search ki surkhi.
- **`<meta name="description">`:** khulasa jise search engines aksar (hamesha nahi) snippet banate hain.
- **`<html lang="en">`:** page ki zaban.

Frameworks ye config se banate hain (Next.js `metadata`, Astro/Nuxt head helpers, WordPress SEO plugins). Neeche ek script head parh kar har tag aur us ki lambai chhaapti hai.

</Ur>
</Tr>

```bash
python3 - <<'PY'
from html.parser import HTMLParser
page = """<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Kent Mangoes, 5 kg Box | Mango Shop</title>
  <meta name="description" content="Fresh Kent mangoes from Florida, delivered in 2 days across the US. $9 per 5 kg box.">
  <link rel="canonical" href="https://mangoshop.example/products/kent">
  <meta property="og:title" content="Kent Mangoes, 5 kg Box">
  <meta property="og:image" content="https://mangoshop.example/img/kent-1200x630.jpg">
  <meta name="robots" content="index, follow">
</head><body></body></html>"""

class HeadReader(HTMLParser):
    def __init__(self):
        super().__init__()
        self.in_title = False
        self.found = []
    def handle_starttag(self, tag, attrs):
        a = dict(attrs)
        if tag == "title":
            self.in_title = True
        elif tag == "meta":
            key = a.get("name") or a.get("property") or ("charset" if "charset" in a else "?")
            self.found.append((key, a.get("content", a.get("charset"))))
        elif tag == "link" and a.get("rel") == "canonical":
            self.found.append(("canonical", a["href"]))
    def handle_data(self, data):
        if self.in_title:
            self.found.append(("title", data))
            self.in_title = False

reader = HeadReader()
reader.feed(page)
for key, value in reader.found:
    print(f"{key:14} {len(value):3}  {value}")
PY
```

```text output
viewport        35  width=device-width, initial-scale=1
title           35  Kent Mangoes, 5 kg Box | Mango Shop
description     84  Fresh Kent mangoes from Florida, delivered in 2 days across the US. $9 per 5 kg box.
canonical       39  https://mangoshop.example/products/kent
og:title        22  Kent Mangoes, 5 kg Box
og:image        47  https://mangoshop.example/img/kent-1200x630.jpg
robots          13  index, follow
```

For `<meta>`, the key is `name`, `property` (Open Graph) or `charset`. The second column is the length: a 35-character title and 84-character description fit comfortably in what Google shows (titles cut at ~600 px, about 50–60 characters; descriptions at ~150–160). Audit tools (Lighthouse, Screaming Frog, Ahrefs) run these checks across thousands of pages: missing, duplicate, too long, too short.</En>
<Ur>`HTMLParser` (Python ki standard library) har khulne wale tag par `handle_starttag` aur text par `handle_data` bulata hai, taqreeban wahi jo SEO crawler pehle karta hai. `<meta>` ke liye key `name`, `property` (Open Graph) ya `charset` hai. Doosra column lambai hai: 35 character ka title aur 84 ki description aaram se Google ke dikhaye hisse me aati hain (titles ~600 px par kat te hain, taqreeban 50–60 characters; descriptions ~150–160 par). Audit tools (Lighthouse, Screaming Frog, Ahrefs) ye checks hazaron pages par chalate hain: gum, dohre, bohot lambe, bohot chhote.</Ur>

<Step title="Writing good titles and descriptions">

<Tr>
<En>

**Title:** unique per page, main topic first, brand last (`Primary topic | Brand`), about 50–60 characters. **Description:** a one- or two-sentence pitch with the facts the searcher cares about (price, delivery, what they'll learn), about 120–160 characters; not a direct ranking factor, but it drives clicks. Engines rewrite missing, stuffed, duplicated or misleading ones. The `<h1>` and `<title>` should agree in meaning.

| Bad | Why | Better |
| --- | --- | --- |
| `Home` | Says nothing; duplicated everywhere | `Fresh Mangoes Delivered Across the US \| Mango Shop` |
| `Mango Shop \| Mango Shop \| Buy Mangoes` | Repetition, brand first | `Kent Mangoes, 5 kg Box \| Mango Shop` |
| `mangoes, buy mangoes, cheap mangoes, mango Houston` | Keyword stuffing | Write for humans |
| Same description on 200 product pages | Duplicate, useless snippet | Generated from each product's name, origin and price |

The old **`<meta name="keywords">`** is **ignored** by Google and Bing (abused in the 1990s): skip it.

</En>
<Ur>

**Title:** har page ka munfarid, asal mauzoo pehle, brand aakhir me (`Primary topic | Brand`), taqreeban 50–60 characters. **Description:** ek do jumlon ki pesh-kash un baaton ke saath jo talash karne wale ke liye ahem hain (qeemat, delivery, kya seekhenge), taqreeban 120–160 characters; seedha ranking factor nahi, lekin clicks laati hai. Engines gum, thoonse, dohre ya gumrah kun wale dobara likh dete hain. `<h1>` aur `<title>` ka matlab ek hona chahiye.

| Bura | Kyun | Behtar |
| --- | --- | --- |
| `Home` | Kuch nahi kehta; har jagah dohra | `Fresh Mangoes Delivered Across the US \| Mango Shop` |
| `Mango Shop \| Mango Shop \| Buy Mangoes` | Dohrao, brand pehle | `Kent Mangoes, 5 kg Box \| Mango Shop` |
| `mangoes, buy mangoes, cheap mangoes, mango Houston` | Keywords thoonsna | Insanon ke liye likhein |
| 200 product pages par ek description | Dohri, bekaar snippet | Har product ke naam, maqam aur qeemat se bani |

Purana **`<meta name="keywords">`** Google aur Bing **nazar andaz** karte hain (1990s me ghalat istemal hua): chhor dein.

</Ur>
</Tr>

</Step>

<Step title="Controlling indexing: robots meta and robots.txt">

<Tr>
<En>Two different tools. **`robots.txt`** (at `/robots.txt`) says which URLs bots may **crawl**. **`<meta name="robots" content="noindex">`** (or the `X-Robots-Tag` header) says not to **index** a crawled page; other values include `nofollow`, `noarchive` and `max-snippet`. To keep a page **out of results**, use `noindex` and **allow** crawling so the bot can see it: a page blocked in robots.txt can still appear (with no description) if others link to it. Use robots.txt to save crawl effort on useless URL sets and to list sitemaps. It's **public and advisory**: malicious bots ignore it, so never use it to hide secrets. Below, Python's built-in parser tests rules exactly as a polite bot would.</En>
<Ur>Do alag tools. **`robots.txt`** (`/robots.txt` par) batata hai bots kaun se URLs **crawl** kar sakte hain. **`<meta name="robots" content="noindex">`** (ya `X-Robots-Tag` header) batata hai crawl hue page ko **index** na karo; doosri values me `nofollow`, `noarchive` aur `max-snippet` hain. Page ko **results se bahar** rakhne ke liye `noindex` lagayen aur crawling ki **ijazat** dein taa ke bot use dekh sake: robots.txt me band page phir bhi (bina description) aa sakta hai agar doosre link karen. robots.txt bekaar URLs par crawl mehnat bachane aur sitemaps batane ke liye. Ye **public aur mashwara** hai: bure bots nazar andaz karte hain, isliye raaz chhupane ke liye kabhi nahi. Neeche Python ka andaruni parser qawaid waise hi test karta hai jaise sharif bot.</Ur>
</Tr>

```bash
python3 - <<'PY'
from urllib.robotparser import RobotFileParser
rules = """User-agent: *
Disallow: /cart
Disallow: /account/
Allow: /

User-agent: GPTBot
Disallow: /

Sitemap: https://mangoshop.example/sitemap.xml"""
rp = RobotFileParser()
rp.parse(rules.splitlines())
checks = [("Googlebot", "/products/kent"), ("Googlebot", "/cart"),
          ("Googlebot", "/account/orders"), ("GPTBot", "/products/kent")]
for agent, path in checks:
    ok = rp.can_fetch(agent, "https://mangoshop.example" + path)
    print(f"{agent:10} {path:20} {'allowed' if ok else 'blocked'}")
print(rp.site_maps())
PY
```

```text output
Googlebot  /products/kent       allowed
Googlebot  /cart                blocked
Googlebot  /account/orders      blocked
GPTBot     /products/kent       blocked
['https://mangoshop.example/sitemap.xml']
```

<Happened>
<Tr>
<En>`User-agent: *` is the group for all bots without a more specific one: it blocks `/cart` (and anything starting with it) and everything under `/account/`, and allows the rest. `User-agent: GPTBot` is a separate group blocking OpenAI's crawler from the whole site; a bot uses the **most specific** matching group, so GPTBot ignores the `*` rules. Googlebot can fetch products but not the cart or account. `Sitemap:` lines tell every bot where the sitemap is. Many sites add groups like this for AI crawlers, but robots.txt is not access control.</En>
<Ur>`User-agent: *` un sab bots ka group hai jin ka khaas group nahi: ye `/cart` (aur us se shuru hone wala sab) aur `/account/` ke neeche sab band karta hai, baqi ki ijazat. `User-agent: GPTBot` alag group hai jo OpenAI ke crawler ko poori site se rokta hai; bot **sab se khaas** milne wala group istemal karta hai, isliye GPTBot `*` ke qawaid nazar andaz karta hai. Googlebot products la sakta hai magar cart ya account nahi. `Sitemap:` lines har bot ko sitemap ka pata batati hain. Kai sites AI crawlers ke liye aise groups jorti hain, lekin robots.txt rasai ka qaboo nahi.</Ur>

<Step title="Canonical URLs and duplicate content">

<Tr>
<En>The same content is often reachable at many URLs: `http` and `https`, with and without `www`, trailing slashes, tracking parameters (`?utm_source=whatsapp`), sort orders, print versions. `<link rel="canonical" href>` names the **main** one. Without it, engines guess, link signals split across copies, and the wrong URL may appear. Every indexable page should have a **self-referencing** canonical with an **absolute** URL; duplicates point to the original. Combine with **301 redirects** where you control the duplicates (http → https): the canonical is a strong hint, a redirect is a rule. So `.../products/kent?utm_source=whatsapp&sort=price` still declares `https://mangoshop.example/products/kent`.</En>
<Ur>Ek hi mawad aksar kai URLs par milta hai: `http` aur `https`, `www` ke saath aur baghair, aakhri slash, tracking parameters (`?utm_source=whatsapp`), sort ki tarteeb, print versions. `<link rel="canonical" href>` **asal** wala batata hai. Is ke baghair engines andaza lagate hain, link ke isharat nuskhon me bant jate hain, aur ghalat URL aa sakta hai. Har index hone wale page ka **absolute** URL ke saath **apni taraf ishara karta** canonical ho; dohre asal ki taraf ishara karen. Jahan dohre aap ke qaboo me hon wahan **301 redirects** bhi (http → https): canonical mazboot ishara, redirect qaida hai. Isliye `.../products/kent?utm_source=whatsapp&sort=price` phir bhi `https://mangoshop.example/products/kent` batata hai.</Ur>
</Tr>

<Step title="Social previews: Open Graph and Twitter cards">

<Tr>

<Step title="Sitemaps">

<Tr>
<En>A sitemap is an XML file (usually `/sitemap.xml`) listing URLs you want indexed, with optional `lastmod`. List only **canonical, indexable** URLs (no redirects or `noindex`), reference it from robots.txt and submit it in Search Console. `lastmod` must be real (Google ignores it if it's always today); `priority` and `changefreq` are ignored.</En>
<Ur>Sitemap XML file hai (aam taur par `/sitemap.xml`) jo index karwane wale URLs list karti hai, ikhtiyari `lastmod` ke saath. Sirf **canonical, index hone wale** URLs (redirects ya `noindex` nahi), robots.txt se hawala aur Search Console me jama. `lastmod` asli ho (hamesha aaj ho to Google nazar andaz karta hai); `priority` aur `changefreq` nazar andaz hote hain.</Ur>

<Step title="Multiple languages: hreflang">

<Tr>

<Step title="On-page SEO and page experience">

<Tr>
<En>

What's in the body matters more than the head:

- **Content** that fully answers the searcher's question, written for people.
- **Semantic HTML:** one `<h1>`, a logical outline, descriptive link text, alt text, lists and tables.
- **Clean URLs** (`/products/kent`, not `/p?id=8172&cat=3`) and **internal links** between related pages.

Accessibility and SEO overlap heavily. Google can render client-side JavaScript, but later, and many crawlers and social apps don't run it at all, so put important content and **all meta tags** in the server-rendered HTML. Lighthouse has an SEO audit; PageSpeed Insights and Search Console show real-user data.

</En>

- **Missing or duplicate titles and descriptions** across many pages.

<DeepDive title="Real world: the noindex that shipped to production">

A common and expensive launch mistake: developers add `<meta name="robots" content="noindex">` (or `Disallow: /` in robots.txt) to staging so it doesn't appear in Google, then deploy the same configuration to production. Within days pages drop out of the index and organic traffic falls sharply, and recovery can take weeks after the fix. Teams that avoid this generate robots rules from the environment (production allows; staging blocks **and** requires a password), add a CI or monitoring check that fails if the production home page contains `noindex`, and watch Search Console's indexing report after every launch.

</DeepDive>

<DeepDive title="Security lens">

Metadata is public and parsed by many systems: treat it as both an information leak and an injection surface.

- **robots.txt reveals paths:** `Disallow: /admin-backup-2024/` advertises what you want hidden. Protect private areas with authentication.
- **Staging and preview sites** need a password, not just `noindex`, or they leak unreleased features.
- **Escape user content in meta tags:** a product name in `<title>`, `og:title` or JSON-LD without escaping can enable XSS; in JSON-LD a value containing `</script>` breaks out of the block, so serialise with a function that escapes `<`.
- **Link previews** are fetched by servers. If your app previews user-supplied URLs, that's an **SSRF** risk: block internal addresses.
- **No secrets** (internal IDs, API keys, staff emails) in meta tags, comments or JSON-LD.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What is the difference between crawling, indexing and ranking?">
Crawling is when a search engine's bot discovers and downloads pages by following links and sitemaps, within the rules of robots.txt. Indexing is processing a crawled page, rendering it, understanding its content and choosing a canonical URL, then storing it. Ranking is ordering indexed pages for a specific query using relevance, quality, links and page-experience signals.
</QA>

<QA q="How do you keep a page out of search results?">
Add a robots meta tag with noindex, or an X-Robots-Tag noindex HTTP header, and make sure the page is not blocked in robots.txt so the crawler can actually see that instruction. Blocking with robots.txt alone only stops crawling, and the URL can still be indexed from external links. For private content, require authentication.
</QA>

<QA q="What is a canonical URL and why does it matter?">
It is the preferred URL for content reachable at several addresses, declared with a link element with rel canonical. It tells search engines which version to index and show, and consolidates ranking signals onto it instead of splitting them across duplicates created by tracking parameters, protocols, trailing slashes or sorting options.
</QA>

<QA q="What are Open Graph tags?">
Meta tags with properties such as og:title, og:description, og:image and og:url that social networks and messaging apps read to build link previews. The image should be an absolute URL, typically 1200 by 630 pixels, and the tags must be in the server-rendered HTML because preview bots usually don't run JavaScript.
</QA>

<QA q="What is structured data and how is it added?">
Machine-readable information about a page's content using the schema.org vocabulary, such as a product's price and availability or an article's author and publish date. The recommended format is JSON-LD in a script element of type application/ld+json. It can make pages eligible for rich results, must match visible content, and is tested with the Rich Results Test.
</QA>
