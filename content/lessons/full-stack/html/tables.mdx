<Callout type="tip" title="In one minute">
Use a **`<table>`** for **tabular data**: information with rows and columns where each value relates to a row and a column header (price lists, timetables, invoices, comparisons, reports). Build it from **rows** (`<tr>`) of **cells**: `<td>` for data and **`<th>`** for headers. Give the table a **`<caption>`** (its title), group rows into **`<thead>`**, **`<tbody>`** and **`<tfoot>`**, and mark header direction with **`scope="col"`** or **`scope="row"`**. Then screen readers can announce "Keitt, Price per kg, Rs 1,100" instead of just "Rs 1,100". Merge cells with `colspan`/`rowspan` sparingly. **Never use tables for page layout**; that's CSS Grid and Flexbox's job.
</Callout>

## Start from zero

<Callout type="analogy">
A table is like a **school result card**: subjects run down the left, the terms run across the top, and every mark sits where a subject row meets a term column. A mark of "78" means nothing alone; it means something because you can see it's "Mathematics, First term". HTML table headers (`<th>`) are those printed subject and term labels. They let a screen reader say "Mathematics, First term, 78" so a blind student can read the card too.
</Callout>

### Words you need first

| Word | Simple meaning | Example |
| --- | --- | --- |
| **Tabular data** | Data naturally arranged in rows and columns | price list, timetable |
| **Row** | One horizontal line of cells | `<tr>` |
| **Cell** | One box in the table | `<td>Rs 900</td>` |
| **Header cell** | A cell that labels a row or column | `<th>Price</th>` |
| **Caption** | The table's title | `<caption>Mango prices</caption>` |
| **Row group** | `thead` (headers), `tbody` (body), `tfoot` (totals) | |
| **scope** | Whether a header labels its column or its row | `scope="col"` |
| **colspan / rowspan** | A cell spanning several columns / rows | `colspan="2"` |

## What is it?

```text
<table>
  <caption>Mango prices, November 2026</caption>      ← title
  <thead>                                              ← header rows
    <tr> <th scope="col">Variety</th> <th scope="col">Price</th> </tr>
  </thead>
  <tbody>                                              ← data rows
    <tr> <th scope="row">Kent</th> <td>Rs 900</td> </tr>
  </tbody>
  <tfoot> ... totals ... </tfoot>                      ← summary rows
</table>
```

## Why does it matter?

- **Data is everywhere:** admin dashboards, invoices, order histories, timetables, pricing plans, reports, comparison pages.
- **Accessibility:** a sighted user scans a table visually; a screen-reader user depends completely on correct headers to know what each value means.
- **History lesson:** in the early 2000s, whole page layouts were built with nested tables. That made pages slow, impossible to make responsive and confusing for assistive technology. CSS layout replaced it, and "tables for data only" became a core rule.
- **Copy and paste, export, scraping and search:** real tables paste cleanly into spreadsheets and can be read by tools and search engines.

## When and where do you use it?

| Use a table | Don't use a table |
| --- | --- |
| Price list, invoice line items | Page layout (columns, sidebars) |
| Timetables, schedules | A list of products shown as cards |
| Comparison of plans | A form layout |
| Reports and statistics | A single list of items (use `<ul>`) |
| Admin data grids | Key–value pairs of one item (consider `<dl>`) |

## Concepts one by one

### 1. Rows, cells and header cells

<Explain>
<What>
`<table>` contains rows (`<tr>`); each row contains cells: `<th>` for headers, `<td>` for data.
</What>
<Why>
`<th>` isn't just bold text: it's the structure that connects each data cell to its labels.
</Why>
<When>
Every table needs headers, almost always in the first row and often in the first column.
</When>
<Where>
Every row should have the same number of columns (counting spans), or cells end up under the wrong headers.
</Where>
<How>
Browsers make `<th>` bold and centred by default. Change that with CSS, never by switching to `<td>` with `<b>`.
</How>
</Explain>

```html preview h=150 noqa
<table>
  <tr>
    <th>Variety</th>
    <th>Price per kg</th>
  </tr>
  <tr>
    <td>Kent</td>
    <td>Rs 900</td>
  </tr>
  <tr>
    <td>Keitt</td>
    <td>Rs 1,100</td>
  </tr>
</table>
```

Line by line:

- The first `<tr>` holds two `<th>` header cells: the column labels.
- Each following `<tr>` is one mango variety with two `<td>` data cells.
- Without any CSS, the browser draws a minimal table with no borders; styling comes later (concept 7).

### 2. Caption, thead, tbody and tfoot

<Explain>
<What>
`<caption>` is the table's title (the first child of `<table>`). `<thead>`, `<tbody>` and `<tfoot>` group header rows, data rows and summary rows.
</What>
<Why>
The caption becomes the table's **accessible name** ("table, Mango prices, November 2026"). Row groups help assistive tech, let CSS style parts separately, repeat headers on every printed page, and make it easy to scroll only the body.
</Why>
<When>
Every data table should have a caption (it can be visually hidden if the page heading already describes it). Use `<tfoot>` for totals.
</When>
<Where>
Even if you don't write `<tbody>`, browsers insert one automatically, which matters when CSS or JavaScript selects rows.
</Where>
<How>
Below, a real invoice with all four parts.
</How>
</Explain>

```html preview h=230
<table>
  <caption>Invoice #1042: order items</caption>
  <thead>
    <tr><th scope="col">Item</th><th scope="col">Qty</th><th scope="col">Price</th><th scope="col">Total</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">Kent, 5 kg box</th><td>2</td><td>Rs 900</td><td>Rs 1,800</td></tr>
    <tr><th scope="row">Keitt, 5 kg box</th><td>1</td><td>Rs 1,100</td><td>Rs 1,100</td></tr>
  </tbody>
  <tfoot>
    <tr><th scope="row" colspan="3">Grand total</th><td>Rs 2,900</td></tr>
  </tfoot>
</table>
```

Line by line:

- `<caption>` names the table: "Invoice #1042: order items".
- `<thead>` holds the column headers, each with `scope="col"` (concept 3).
- In `<tbody>`, each row starts with a `<th scope="row">`: the item name labels its row.
- `<tfoot>` holds the summary row. Its header spans the first three columns (`colspan="3"`, concept 4), so "Grand total" lines up with the Total column.

### 3. `scope`: telling cells which headers they belong to

<Explain>
<What>
`scope="col"` says "this header labels the cells below it"; `scope="row"` says "this header labels the cells to its right".
</What>
<Why>
Screen readers use these relationships to announce headers as users move through cells. In simple tables, browsers can often guess, but `scope` removes the guesswork, especially when a table has both row and column headers.
</Why>
<When>
On every `<th>`.
</When>
<Where>
For very complex tables (multiple header levels), the `headers` attribute on `<td>` can list the exact header `id`s, but it's better to simplify or split such tables.
</Where>
<How>
Below, a real browser shows the accessibility tree of a properly built table and of a "fake" table where headers are just bold data cells.
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
good = """<table><caption>Mango prices, November 2026</caption>
<thead><tr><th scope="col">Variety</th><th scope="col">Price per kg</th><th scope="col">In stock</th></tr></thead>
<tbody><tr><th scope="row">Kent</th><td>Rs 900</td><td>Yes</td></tr>
<tr><th scope="row">Keitt</th><td>Rs 1,100</td><td>No</td></tr></tbody></table>"""
fake = """<table><tr><td><b>Variety</b></td><td><b>Price per kg</b></td></tr>
<tr><td>Kent</td><td>Rs 900</td></tr></table>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    for label, html in [("PROPER TABLE", good), ("FAKE HEADERS", fake)]:
        page.set_content("<!DOCTYPE html><title>t</title><body>" + html)
        print(f"--- {label}:")
        print(page.locator("table").aria_snapshot())
    browser.close()
PY
```

```text output
--- PROPER TABLE:
- table "Mango prices, November 2026":
  - caption: Mango prices, November 2026
  - rowgroup:
    - row "Variety Price per kg In stock":
      - columnheader "Variety"
      - columnheader "Price per kg"
      - columnheader "In stock"
  - rowgroup:
    - row "Kent Rs 900 Yes":
      - rowheader "Kent"
      - cell "Rs 900"
      - cell "Yes"
    - row "Keitt Rs 1,100 No":
      - rowheader "Keitt"
      - cell "Rs 1,100"
      - cell "No"
--- FAKE HEADERS:
- table:
  - rowgroup:
    - row "Variety Price per kg":
      - cell "Variety"
      - cell "Price per kg"
    - row "Kent Rs 900":
      - cell "Kent"
      - cell "Rs 900"
```

Line by line:

- **Proper table:** the table is named by its caption; there are `columnheader`s ("Variety", "Price per kg", "In stock") and a `rowheader` for each variety. When a screen-reader user lands on "Rs 1,100", it can announce "Keitt, Price per kg, Rs 1,100".
- **Fake headers:** bold text in `<td>` looks like headers but is just a `cell`. The table has no name, and "Rs 900" can only be announced as "Rs 900", with no context.
- Notice the browser created a `rowgroup` in the fake table too: it inserted a `<tbody>` automatically.

### 4. Merging cells: `colspan` and `rowspan`

<Explain>
<What>
`colspan="n"` makes a cell span n columns; `rowspan="n"` makes it span n rows.
</What>
<Why>
Timetables, grouped headers ("Price" over "per kg" and "per box") and totals often need merged cells.
</Why>
<When>
Only when the merge carries meaning. Every merge makes the table harder to navigate with assistive tech and harder to make responsive.
</When>
<Where>
When a cell spans, the cells it covers must be **removed** from the following markup, or the row gets too many columns.
</Where>
<How>
Draw the table on paper first and count columns per row.
</How>
</Explain>

```html preview h=230
<table>
  <caption>Delivery timetable</caption>
  <thead>
    <tr><th scope="col">Day</th><th scope="col">Morning</th><th scope="col">Evening</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">Monday</th><td>Austin</td><td>Seattle</td></tr>
    <tr><th scope="row">Tuesday</th><td colspan="2">Chicago (all day)</td></tr>
    <tr><th scope="row">Wednesday</th><td rowspan="2">Houston</td><td>Dallas</td></tr>
    <tr><th scope="row">Thursday</th><td>Fort Worth</td></tr>
  </tbody>
</table>
```

```text
              Morning          Evening
Monday        Austin       Seattle
Tuesday       Chicago (all day) ─────────     ← colspan="2": one cell over two columns
Wednesday     Houston          Dallas
Thursday      │ (same cell)    Fort Worth        ← rowspan="2": Houston covers two rows
```

Line by line:

- Tuesday's cell has `colspan="2"`, so that row has only **one** `<td>` after the row header.
- Wednesday's "Houston" has `rowspan="2"`, covering Wednesday and Thursday mornings. Thursday's row therefore has only **one** `<td>` (the evening).
- Each row still adds up to three columns: header + two time slots.

### 5. Numbers, alignment and readability

<Explain>
<What>
Conventions that make data tables easy to read: right-align numbers (so digits line up), left-align text, use consistent units and formats, and keep headers short and clear.
</What>
<Why>
Comparing prices and totals is far faster when the digits line up.
</Why>
<When>
Any table with numbers: invoices, reports, financial data.
</When>
<Where>
Alignment belongs in CSS (`text-align: right`, `font-variant-numeric: tabular-nums` for equal-width digits). The old `align` attribute on cells is obsolete.
</Where>
<How>
Put units in the header ("Price (Rs)") rather than repeating them in every cell, when space is tight.
</How>
</Explain>

```html preview h=210 noqa
<style>
  table { border-collapse: collapse; font-family: system-ui, sans-serif; }
  th, td { padding: 6px 12px; border-bottom: 1px solid #ddd; }
  .num { text-align: right; font-variant-numeric: tabular-nums; }
</style>
<table>
  <caption>Monthly sales (Rs)</caption>
  <thead><tr><th scope="col">Month</th><th scope="col" class="num">Orders</th><th scope="col" class="num">Revenue</th></tr></thead>
  <tbody>
    <tr><th scope="row">June</th><td class="num">1,204</td><td class="num">1,325,500</td></tr>
    <tr><th scope="row">July</th><td class="num">987</td><td class="num">1,098,300</td></tr>
    <tr><th scope="row">August</th><td class="num">312</td><td class="num">402,000</td></tr>
  </tbody>
</table>
```

Line by line:

- `border-collapse: collapse` merges neighbouring cell borders into single lines; padding gives cells room.
- `.num` right-aligns numeric columns and uses `tabular-nums` so every digit has the same width: the thousands line up, making it easy to see July's revenue is lower than June's.
- The unit (Rs) is in the caption, not repeated in every cell.

### 6. Responsive tables

<Explain>
<What>
Wide tables don't fit on phones. Common solutions: let the table **scroll horizontally** inside a container, hide less important columns on small screens, or transform rows into stacked "cards" with CSS.
</What>
<Why>
A table wider than the screen otherwise makes the **whole page** scroll sideways.
</Why>
<When>
Any table with more than three or four columns.
</When>
<Where>
The simplest robust approach: wrap the table in a scrollable region that keyboard users can focus, with a label.
</Where>
<How>
Below, the wrapper scrolls; the rest of the page doesn't.
</How>
</Explain>

```html preview h=210 noqa
<style>
  .table-scroll { overflow-x: auto; max-width: 320px; border: 1px solid #ccc; }
  .table-scroll table { border-collapse: collapse; white-space: nowrap; }
  .table-scroll th, .table-scroll td { padding: 6px 10px; border-bottom: 1px solid #eee; }
</style>
<div class="table-scroll" role="region" aria-labelledby="orders-cap" tabindex="0">
  <table>
    <caption id="orders-cap">Recent orders</caption>
    <thead><tr><th scope="col">Order</th><th scope="col">Customer</th><th scope="col">City</th><th scope="col">Items</th><th scope="col">Status</th><th scope="col">Total</th></tr></thead>
    <tbody>
      <tr><th scope="row">#1042</th><td>Olivia Brown</td><td>Seattle</td><td>3</td><td>Delivered</td><td>Rs 2,900</td></tr>
      <tr><th scope="row">#1043</th><td>Jack Wilson</td><td>Austin</td><td>1</td><td>On the way</td><td>Rs 1,100</td></tr>
    </tbody>
  </table>
</div>
```

Line by line:

- `.table-scroll` limits the width (320 px here, to simulate a phone) and adds `overflow-x: auto`, so only this box scrolls horizontally.
- `white-space: nowrap` keeps each cell on one line instead of squeezing columns.
- `role="region"` with `aria-labelledby` (pointing to the caption) and `tabindex="0"` make the scroll box focusable and named, so keyboard users can scroll it with arrow keys and screen readers announce "Recent orders, region".

### 7. Sortable and interactive tables

<Explain>
<What>
Data grids often let users sort by clicking a column header.
</What>
<Why>
Users need to find the largest order or the latest date quickly.
</Why>
<When>
Admin panels, reports, dashboards.
</When>
<Where>
Make the sort control a `<button>` inside the `<th>` (so it's keyboard-accessible), and set `aria-sort="ascending"` / `"descending"` on the currently sorted header so screen readers announce the sort order.
</Where>
<How>
Below, a small script sorts by order total.
</How>
</Explain>

```html preview-js h=220 noqa
<table id="orders">
  <caption>Orders (click Total to sort)</caption>
  <thead>
    <tr><th scope="col">Order</th><th scope="col">Customer</th>
        <th scope="col" aria-sort="none"><button type="button" id="sort-total">Total</button></th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">#1042</th><td>Olivia</td><td data-value="2900">Rs 2,900</td></tr>
    <tr><th scope="row">#1043</th><td>Jack</td><td data-value="1100">Rs 1,100</td></tr>
    <tr><th scope="row">#1044</th><td>Grace</td><td data-value="5400">Rs 5,400</td></tr>
  </tbody>
</table>
<script>
  const button = document.getElementById("sort-total");
  button.addEventListener("click", () => {
    const th = button.parentElement;
    const descending = th.getAttribute("aria-sort") !== "descending";
    const body = document.querySelector("#orders tbody");
    [...body.rows]
      .sort((a, b) => (a.cells[2].dataset.value - b.cells[2].dataset.value) * (descending ? -1 : 1))
      .forEach((row) => body.appendChild(row));
    th.setAttribute("aria-sort", descending ? "descending" : "ascending");
  });
</script>
```

Line by line:

- The Total header contains a real `<button>`, so it works with Tab and Enter.
- Each total cell stores the raw number in `data-value` (sorting "Rs 2,900" as text would put "Rs 1,100" and "Rs 5,400" in the wrong order).
- On click, the script sorts the body rows by that number, re-appends them in order, and updates `aria-sort` so the new order is announced. Click again to flip the direction.

### 8. Styling basics

<Explain>
<What>
A few CSS rules make tables much more readable: collapsed borders, padding, a header background, zebra stripes, and a sticky header for long tables.
</What>
<Why>
Default browser tables are cramped and hard to scan.
</Why>
<When>
Every visible data table.
</When>
<Where>
Keep styles in CSS; avoid obsolete attributes like `border="1"`, `cellpadding` and `bgcolor`.
</Where>
<How>
`position: sticky; top: 0` on `thead th` keeps headers visible while scrolling.
</How>
</Explain>

```css
table { border-collapse: collapse; width: 100%; }
caption { text-align: left; font-weight: 600; padding-bottom: 0.5rem; }
th, td { padding: 0.5rem 0.75rem; border-bottom: 1px solid #e2e2e2; text-align: left; }
thead th { background: #f5f3ee; position: sticky; top: 0; }
tbody tr:nth-child(even) { background: #fafafa; }     /* zebra stripes */
tbody tr:hover { background: #fff7d6; }
td.num, th.num { text-align: right; font-variant-numeric: tabular-nums; }
```

## Hands-on

Build an accessible product comparison table with a caption, header groups, row headers, a grouped header using `colspan`, numbers aligned, and a footer note.

```html preview h=330 noqa
<style>
  table { border-collapse: collapse; font-family: system-ui, sans-serif; font-size: 14px; }
  caption { text-align: left; font-weight: 600; margin-bottom: 6px; }
  th, td { padding: 6px 10px; border: 1px solid #ddd; }
  thead th { background: #f5f3ee; }
  .num { text-align: right; font-variant-numeric: tabular-nums; }
</style>
<table>
  <caption>Mango varieties compared (2026 season)</caption>
  <thead>
    <tr>
      <th scope="col" rowspan="2">Variety</th>
      <th scope="colgroup" colspan="2">Price (Rs)</th>
      <th scope="col" rowspan="2">Season</th>
    </tr>
    <tr>
      <th scope="col" class="num">per kg</th>
      <th scope="col" class="num">per 5 kg box</th>
    </tr>
  </thead>
  <tbody>
    <tr><th scope="row">Kent</th><td class="num">200</td><td class="num">900</td><td>June – July</td></tr>
    <tr><th scope="row">Keitt</th><td class="num">240</td><td class="num">1,100</td><td>July – August</td></tr>
    <tr><th scope="row">Ataulfo</th><td class="num">280</td><td class="num">1,300</td><td>June – July</td></tr>
  </tbody>
  <tfoot>
    <tr><td colspan="4"><small>Prices include delivery in Austin and Seattle.</small></td></tr>
  </tfoot>
</table>
```

Line by line:

- The caption names the table.
- The header has **two rows**: "Variety" and "Season" span both rows (`rowspan="2"`), and "Price (Rs)" spans two columns (`colspan="2"`) with `scope="colgroup"`, meaning it labels a **group** of columns. The second header row names those two price columns.
- Each body row starts with a row header (`scope="row"`), so every price is announced with its variety and its column, for example "Keitt, per 5 kg box, 1,100".
- Numbers are right-aligned with tabular digits.
- The footer note spans all four columns.
- Try it with a screen reader, or inspect it in DevTools → Accessibility: each cell lists its headers.

## Real-world example

A government services portal published its fee schedules as **images of tables** (scanned PDFs turned into PNGs). Blind citizens couldn't read them, nobody could copy the fees into a spreadsheet, search engines couldn't index them, and on phones users had to pinch and zoom. An accessibility audit flagged them as critical. The team rebuilt each schedule as a real HTML table: `<caption>` with the department and year, `<th scope="col">` headers, row headers for each service, numbers right-aligned in a scrollable region on mobile, and a "Download as CSV" link generated from the same data. Search traffic to the fee pages rose (queries like "passport fee 2026" now found the actual table), support calls asking for fees dropped, and the pages passed the WCAG audit.

## Common mistakes

- **Tables for page layout** (columns, sidebars, aligning forms).
- **Bold `<td>` instead of `<th>`** for headers, or no headers at all.
- **No `<caption>`** (or a separate heading not connected to the table).
- **Missing `scope`** on tables with both row and column headers.
- **Too many merged cells,** or spans that leave rows with the wrong number of columns.
- **Images or PDFs of tables** instead of real HTML tables.
- **Tables wider than the screen** without a scroll container, breaking the whole page on mobile.
- **Obsolete attributes** (`border`, `cellpadding`, `align`, `bgcolor`) instead of CSS.
- **Sorting numbers as text** ("Rs 1,100" before "Rs 900").

## Security lens

<Callout type="security">
Tables often display data from databases and users. Escape every value, show only the data users are allowed to see, and be careful with exports.
</Callout>

- **Escape cell contents:** order notes, names and addresses typed by users must be escaped when rendered (templates and React do this by default); never build table rows with `innerHTML` and raw user data.
- **Authorisation, not hiding:** don't send all customers' data to the browser and hide some rows or columns with CSS or client-side filters. Anyone can read the full HTML or the JSON response. Filter on the server.
- **Exports:** "Export to CSV" buttons need the formula-injection protection from the **CSV** lesson.
- **Pagination and limits:** large admin tables should be paginated on the server, so one request can't dump the entire database (and so pages stay fast).

## Interview questions

<QA q="When should you use an HTML table?">
For tabular data, where values relate to both a row and a column, such as price lists, schedules, invoices, comparisons and reports. Tables should not be used for page layout; CSS Grid and Flexbox are the right tools for that.
</QA>

<QA q="How do you make a data table accessible?">
Give it a caption, use th elements for header cells with scope col or row, group rows with thead, tbody and tfoot, keep the structure simple with minimal merged cells, use the headers attribute only for unavoidable complex tables, and make wide tables scroll inside a focusable labelled region on small screens.
</QA>

<QA q="What do colspan and rowspan do?">
colspan makes a cell extend across several columns and rowspan across several rows. The cells they cover must be omitted from the following markup so every row still adds up to the same number of columns. They should be used only where the merge carries meaning, because they complicate navigation and responsiveness.
</QA>

<QA q="Why were table-based layouts abandoned?">
They mixed presentation into the document structure, produced heavy nested markup that loaded slowly, were very hard to make responsive, and confused assistive technologies, which announced layout cells as data. CSS layout separates presentation from content and works across screen sizes.
</QA>
