<BigIdea>
<Tr>
<En>
Use a **`<table>`** for **tabular data**: information where each value relates to a row and a column header (price lists, timetables, invoices, comparisons, reports). Build it from **rows** (`<tr>`) of **cells**: `<td>` for data and **`<th>`** for headers. Give it a **`<caption>`**, group rows into **`<thead>`**, **`<tbody>`** and **`<tfoot>`**, and mark header direction with **`scope="col"`** or **`scope="row"`**. Then screen readers announce "Keitt, Price per kg, $11.00" instead of just "$11.00". Merge cells with `colspan`/`rowspan` sparingly, and **never use tables for page layout**: that's CSS Grid and Flexbox's job.
</En>
<Ur>
**Tabular data** ke liye **`<table>`** istemal karein: aisi maloomat jahan har value ek row aur ek column header se mutalliq ho (qeemat ki fehrist, timetables, invoices, muqable, reports). Ise **cells** ki **rows** (`<tr>`) se banayen: data ke liye `<td>` aur headers ke liye **`<th>`**. Ise **`<caption>`** dein, rows ko **`<thead>`**, **`<tbody>`** aur **`<tfoot>`** me group karein, aur header ki simt **`scope="col"`** ya **`scope="row"`** se batayen. Phir screen readers sirf "$11.00" ke bajaye "Keitt, Price per kg, $11.00" bolte hain. `colspan`/`rowspan` se cells kam hi milayen, aur **page layout ke liye tables kabhi nahi**: wo CSS Grid aur Flexbox ka kaam hai.
</Ur>
</Tr>

<Tr>
<En>

A mark of "78" means nothing alone; it means something because you can see it's "Mathematics, First term". HTML header cells (`<th>`) are those printed subject and term labels. ## Learn it step by step

<Walkthrough>

<Step title="Rows, cells and header cells">

<Tr>
<En>`<table>` contains rows (`<tr>`) of cells: `<th>` for headers, `<td>` for data. `<th>` isn't just bold text: it's the structure that connects each data cell to its labels. Almost every table has headers in the first row and often the first column. Every row must have the same number of columns (counting spans), or cells land under the wrong headers. Browsers make `<th>` bold and centred; change that with CSS, never by switching to `<td><b>`.</En>
<Ur>`<table>` me cells ki rows (`<tr>`) hoti hain: headers ke liye `<th>`, data ke liye `<td>`. `<th>` sirf bold text nahi: ye wo dhaancha hai jo har data cell ko us ke labels se jorta hai. Taqreeban har table ki pehli row me, aur aksar pehle column me, headers hote hain. Har row me columns barabar hon (spans gin kar), warna cells ghalat headers ke neeche aate hain. Browsers `<th>` ko bold aur beech me karte hain; ye CSS se badlein, `<td><b>` par jaa kar kabhi nahi.</Ur>
</Tr>

```html preview h=150 noqa
<table>
  <tr>
    <th>Variety</th>
    <th>Price per kg</th>
  </tr>
  <tr>
    <td>Kent</td>
    <td>$9.00</td>
  </tr>
  <tr>
    <td>Keitt</td>
    <td>$11.00</td>
  </tr>
</table>
```

<Happened>
<Tr>
<En>The first `<tr>` holds two `<th>` column labels; each following `<tr>` is one variety with two `<td>` cells. Without CSS the browser draws a minimal table with no borders; styling comes later.</En>
<Ur>Pehli `<tr>` me do `<th>` column labels hain; har agli `<tr>` ek variety hai jis me do `<td>` cells hain. CSS ke baghair browser bina borders ka saada table banata hai; styling baad me aati hai.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Caption, thead, tbody and tfoot">

<Tr>
<En>`<caption>` is the table's title (first child of `<table>`) and becomes its **accessible name** ("table, Mango prices, November 2026"). `<thead>`, `<tbody>` and `<tfoot>` group header, data and summary rows: they help assistive tech, let CSS style parts separately, repeat headers on printed pages and let only the body scroll. Every data table needs a caption (it can be visually hidden if a heading already describes it). Even if you don't write `<tbody>`, browsers insert one, which matters for CSS and JavaScript selectors.</En>
<Ur>`<caption>` table ka unwan hai (`<table>` ka pehla bachcha) aur us ka **accessible name** banta hai ("table, Mango prices, November 2026"). `<thead>`, `<tbody>` aur `<tfoot>` header, data aur khulasa rows ko group karte hain: assistive tech ki madad, CSS ko hisse alag style karne dena, print par har safhe par headers dohrana aur sirf body ko scroll karna. Har data table ko caption chahiye (agar heading pehle hi bayan kare to nazar se chhupa sakte hain). Aap `<tbody>` na likhein to bhi browser khud daal deta hai, jo CSS aur JavaScript selectors ke liye ahem hai.</Ur>
</Tr>

```html preview h=230
<table>
  <caption>Invoice #1042: order items</caption>
  <thead>
    <tr><th scope="col">Item</th><th scope="col">Qty</th><th scope="col">Price</th><th scope="col">Total</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">Kent, 5 kg box</th><td>2</td><td>$9.00</td><td>$18.00</td></tr>
    <tr><th scope="row">Keitt, 5 kg box</th><td>1</td><td>$11.00</td><td>$11.00</td></tr>
  </tbody>
  <tfoot>
    <tr><th scope="row" colspan="3">Grand total</th><td>$29.00</td></tr>
  </tfoot>
</table>
```

<Happened>
<Tr>
<En>`<caption>` names the table. `<thead>` holds column headers with `scope="col"`. In `<tbody>`, each row starts with a `<th scope="row">`: the item name labels its row. `<tfoot>` holds the summary, whose header spans the first three columns (`colspan="3"`) so "Grand total" lines up with Total.</En>
<Ur>`<caption>` table ka naam rakhta hai. `<thead>` me `scope="col"` wale column headers hain. `<tbody>` me har row `<th scope="row">` se shuru hoti hai: item ka naam apni row ka label hai. `<tfoot>` me khulasa hai, jis ka header pehle teen columns par phaila hai (`colspan="3"`) taa ke "Grand total" Total ke saamne aaye.</Ur>
</Tr>
</Happened>

</Step>

<Step title="scope: which headers each cell belongs to">

<Tr>
<En>`scope="col"` means "this header labels the cells below"; `scope="row"` means "the cells to its right". Screen readers use these links to announce headers as users move through cells. Browsers can often guess in simple tables, but `scope` removes the guesswork, especially with both row and column headers. Put it on every `<th>`. For truly complex tables, `headers` on `<td>` can list header `id`s, but splitting the table is usually better. Below, a real browser shows the accessibility tree of a proper table and of a "fake" one with bold data cells.</En>
<Ur>`scope="col"` ka matlab "ye header neeche ke cells ka label hai"; `scope="row"` ka matlab "daayen ke cells ka". Screen readers in rishton se headers bolte hain jab users cells me chalte hain. Saade tables me browsers aksar andaza laga lete hain, lekin `scope` andaza khatam karta hai, khaas kar row aur column dono headers ke saath. Har `<th>` par lagayen. Waqai pecheeda tables me `<td>` par `headers` header `id`s list kar sakta hai, lekin table taqseem karna aam taur par behtar hai. Neeche asli browser sahi table aur bold data cells wale "naqli" table ka accessibility tree dikhata hai.</Ur>
</Tr>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
good = """<table><caption>Mango prices, November 2026</caption>
<thead><tr><th scope="col">Variety</th><th scope="col">Price per kg</th><th scope="col">In stock</th></tr></thead>
<tbody><tr><th scope="row">Kent</th><td>$9.00</td><td>Yes</td></tr>
<tr><th scope="row">Keitt</th><td>$11.00</td><td>No</td></tr></tbody></table>"""
fake = """<table><tr><td><b>Variety</b></td><td><b>Price per kg</b></td></tr>
<tr><td>Kent</td><td>$9.00</td></tr></table>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    for label, html in [("PROPER TABLE", good), ("FAKE HEADERS", fake)]:
        page.set_content("<!DOCTYPE html><title>t</title><body>" + html)
        print(f"--- {label}:")
        print(page.locator("table").aria_snapshot())
    browser.close()
PY
```

<Step title="Merging cells: colspan and rowspan">

<Tr>
<En>`colspan="n"` makes a cell span n columns; `rowspan="n"` spans n rows. Timetables, grouped headers and totals often need them, but use them only when the merge means something: each one makes the table harder to navigate and to make responsive. The cells a span covers must be **removed** from the following markup, or the row gets too many columns. Draw the table on paper and count columns per row.</En>
<Ur>`colspan="n"` cell ko n columns par aur `rowspan="n"` n rows par phailata hai. Timetables, group headers aur majmooe ko aksar inki zaroorat hoti hai, lekin sirf tab jab milana koi matlab rakhe: har ek table me chalna aur responsive banana mushkil karta hai. Jin cells ko span dhaanpta hai wo agle markup se **hatane** lazmi hain, warna row me zyada columns ho jate hain. Kaghaz par table bana kar har row ke columns ginein.</Ur>
</Tr>

```html preview h=230
<table>
  <caption>Delivery timetable</caption>
  <thead>
    <tr><th scope="col">Day</th><th scope="col">Morning</th><th scope="col">Evening</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">Monday</th><td>Austin</td><td>Seattle</td></tr>
    <tr><th scope="row">Tuesday</th><td colspan="2">Chicago (all day)</td></tr>
    <tr><th scope="row">Wednesday</th><td rowspan="2">Houston</td><td>Dallas</td></tr>
    <tr><th scope="row">Thursday</th><td>Fort Worth</td></tr>
  </tbody>
</table>
```

<Happened>
<Tr>
<En>

Tuesday's cell has `colspan="2"`, so that row has only **one** `<td>` after its header. Wednesday's "Houston" has `rowspan="2"`, covering Wednesday and Thursday mornings, so Thursday's row has only the evening `<td>`. Each row still adds up to three columns:

```text
              Morning          Evening
Monday        Austin           Seattle
Tuesday       Chicago (all day) ────────     ← colspan="2": one cell over two columns
Wednesday     Houston          Dallas
Thursday      │ (same cell)    Fort Worth    ← rowspan="2": Houston covers two rows
```

</En>
<Ur>

Tuesday ke cell par `colspan="2"` hai, isliye us row me header ke baad sirf **ek** `<td>` hai. Wednesday ka "Houston" `rowspan="2"` ke saath Wednesday aur Thursday ki subah dhaanpta hai, isliye Thursday ki row me sirf shaam ka `<td>` hai. Har row phir bhi teen columns banati hai:

```text
              Morning          Evening
Monday        Austin           Seattle
Tuesday       Chicago (all day) ────────     ← colspan="2": one cell over two columns
Wednesday     Houston          Dallas
Thursday      │ (same cell)    Fort Worth    ← rowspan="2": Houston covers two rows
```

</Ur>
</Tr>
</Happened>

<Step title="Numbers, alignment and readability">

<Tr>
<En>Right-align numbers so digits line up, left-align text, keep units and formats consistent and headers short. Alignment belongs in CSS (`text-align: right`, `font-variant-numeric: tabular-nums` for equal-width digits); the old `align` attribute is obsolete. When space is tight, put the unit in the header or caption ("Revenue ($)") instead of every cell.</En>
<Ur>Numbers daayen taraf rakhein taa ke hindse seedhe aayen, text baayen, units aur format yaksan aur headers chhote. Alignment CSS ka kaam hai (`text-align: right`, barabar chaurai ke hindson ke liye `font-variant-numeric: tabular-nums`); purana `align` attribute mansookh hai. Jagah kam ho to unit har cell ke bajaye header ya caption me rakhein ("Revenue ($)").</Ur>
</Tr>

```html preview h=210 noqa
<style>
  table { border-collapse: collapse; font-family: system-ui, sans-serif; }
  th, td { padding: 6px 12px; border-bottom: 1px solid #ddd; }
  .num { text-align: right; font-variant-numeric: tabular-nums; }
</style>
<table>
  <caption>Monthly sales ($)</caption>
  <thead><tr><th scope="col">Month</th><th scope="col" class="num">Orders</th><th scope="col" class="num">Revenue</th></tr></thead>
  <tbody>
    <tr><th scope="row">June</th><td class="num">1,204</td><td class="num">13,255</td></tr>
    <tr><th scope="row">July</th><td class="num">987</td><td class="num">10,983</td></tr>
    <tr><th scope="row">August</th><td class="num">312</td><td class="num">4,020</td></tr>
  </tbody>
</table>
```

<Happened>
<Tr>
<En>`border-collapse: collapse` merges neighbouring borders into single lines and padding gives cells room. `.num` right-aligns numbers with `tabular-nums`, so the thousands line up and you can instantly see July's revenue is lower than June's. The unit is in the caption, not repeated in every cell.</En>
<Ur>`border-collapse: collapse` pados ke borders ek line me milata hai aur padding cells ko jagah deti hai. `.num` numbers ko `tabular-nums` ke saath daayen karta hai, isliye hazaar seedhe aate hain aur fauran dikhta hai ke July ki aamdani June se kam hai. Unit caption me hai, har cell me dohrayi nahi.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Responsive tables">

<Tr>
<En>Wide tables don't fit on phones, and a table wider than the screen makes the **whole page** scroll sideways. Options: scroll the table horizontally in a container, hide less important columns on small screens, or restyle rows as stacked cards. The simplest robust approach is a scrollable wrapper that keyboard users can focus, with a name. Use it for any table with more than three or four columns.</En>
<Ur>Chauri tables phones par fit nahi hotin, aur screen se chaura table **poore page** ko side me scroll karata hai. Options: table ko dabbe me aafqi scroll karein, chhoti screens par kam ahem columns chhupayen, ya rows ko upar neeche cards bana dein. Sab se saada mazboot tareeqa naam wala scroll hone wala wrapper hai jis par keyboard users focus kar saken. Teen chaar se zyada columns wali har table ke liye.</Ur>
</Tr>

```html preview h=210 noqa
<style>
  .table-scroll { overflow-x: auto; max-width: 320px; border: 1px solid #ccc; }
  .table-scroll table { border-collapse: collapse; white-space: nowrap; }
  .table-scroll th, .table-scroll td { padding: 6px 10px; border-bottom: 1px solid #eee; }
</style>
<div class="table-scroll" role="region" aria-labelledby="orders-cap" tabindex="0">
  <table>
    <caption id="orders-cap">Recent orders</caption>
    <thead><tr><th scope="col">Order</th><th scope="col">Customer</th><th scope="col">City</th><th scope="col">Items</th><th scope="col">Status</th><th scope="col">Total</th></tr></thead>
    <tbody>
      <tr><th scope="row">#1042</th><td>Olivia Brown</td><td>Seattle</td><td>3</td><td>Delivered</td><td>$29.00</td></tr>
      <tr><th scope="row">#1043</th><td>Jack Wilson</td><td>Austin</td><td>1</td><td>On the way</td><td>$11.00</td></tr>
    </tbody>
  </table>
</div>
```

<Happened>
<Tr>
<En>`.table-scroll` limits the width (320 px, to simulate a phone) with `overflow-x: auto`, so only this box scrolls. `white-space: nowrap` keeps each cell on one line. `role="region"` with `aria-labelledby` (the caption) and `tabindex="0"` make the box focusable and named: keyboard users scroll it with arrow keys, and screen readers say "Recent orders, region".</En>
<Ur>`.table-scroll` `overflow-x: auto` ke saath chaurai mehdood karta hai (phone jaisi 320 px), isliye sirf ye dabba scroll hota hai. `white-space: nowrap` har cell ek line me rakhta hai. `aria-labelledby` (caption) wala `role="region"` aur `tabindex="0"` dabbe ko focus hone wala aur naam wala banate hain: keyboard users arrow keys se scroll karte hain, aur screen readers "Recent orders, region" bolte hain.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Sortable tables">

<Tr>
<En>Data grids often sort when you click a column header, so users can find the largest order or latest date fast. Make the sort control a `<button>` inside the `<th>` (keyboard-accessible), and set `aria-sort="ascending"`/`"descending"` on the sorted header so screen readers announce it. Store raw numbers in `data-value`: sorting "$11.00" and "$9.00" as text puts them in the wrong order.</En>
<Ur>Data grids aksar column header par click se sort hoti hain, taa ke users sab se bara order ya taaza tareekh jaldi dhoondhen. Sort control `<th>` ke andar `<button>` banayen (keyboard se chalne wala), aur sorted header par `aria-sort="ascending"`/`"descending"` lagayen taa ke screen readers batayen. Kacche numbers `data-value` me rakhein: "$11.00" aur "$9.00" ko text ki tarah sort karna ghalat tarteeb deta hai.</Ur>
</Tr>


## Common mistakes

<Compare>
<Bad title="Looks like a table, isn't one">

```text
<table>
  <tr><td><b>Variety</b></td><td><b>Price</b></td></tr>   <!-- fake headers -->
  <tr><td>Kent</td><td align="right">$9.00</td></tr>       <!-- obsolete align -->
</table>
<img src="fee-schedule.png" alt="Fee schedule">          <!-- picture of a table -->
```

</Bad>
<Good title="A real, named, structured table">

```text
<table>
  <caption>Mango prices, November 2026</caption>
  <thead><tr><th scope="col">Variety</th><th scope="col" class="num">Price</th></tr></thead>
  <tbody><tr><th scope="row">Kent</th><td class="num">$9.00</td></tr></tbody>
</table>
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Tables for page layout** (columns, sidebars, aligning forms).
- **Missing `scope`** on tables with both row and column headers.
- **Too many merged cells**, or spans that leave rows with the wrong number of columns.
- **Tables wider than the screen** without a scroll container.
- **Sorting numbers as text** ("$11.00" before "$9.00").

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Page layout ke liye tables** (columns, sidebars, forms seedhe karna).
- Row aur column dono headers wali tables me **`scope` gum**.
- **Bohot zyada mile cells**, ya aise spans jo rows me ghalat columns chhoren.
- Scroll dabbe ke baghair **screen se chauri tables**.
- **Numbers ko text ki tarah sort karna** ("$11.00" pehle, "$9.00" baad me).

</Ur>
</Tr>

## Remember

<Takeaways>
<Tr>
<En>

- Tables are for data with rows and columns, never for layout.
- `<th>` for headers, `<td>` for data; `scope="col"`/`"row"` on every `<th>`.
- Every table gets a `<caption>`; use `thead`/`tbody`/`tfoot`.
- `colspan`/`rowspan` only when meaningful; remove covered cells.
- Right-align numbers with `tabular-nums`; units in headers or caption.
- Wide tables scroll inside a focusable, labelled region.
- Sort with buttons in headers, `aria-sort` and raw values in `data-value`.
- Style with CSS, not obsolete attributes.

<DeepDive title="Real world: fee schedules as pictures">

A government services portal published its fee schedules as **images of tables** (scanned PDFs turned into PNGs). Blind citizens couldn't read them, nobody could copy fees into a spreadsheet, search engines couldn't index them, and phone users had to pinch and zoom. An accessibility audit flagged them as critical. The team rebuilt each schedule as a real HTML table: a `<caption>` with department and year, `<th scope="col">` headers, row headers per service, right-aligned numbers in a scrollable region on mobile, and a "Download as CSV" link generated from the same data. Search traffic to the fee pages rose (queries like "passport fee 2026" now found the actual table), support calls asking for fees dropped, and the pages passed the WCAG audit.

</DeepDive>

<DeepDive title="Security lens">

Tables often display data from databases and users. Escape every value, show only data users may see, and be careful with exports.

- **Escape cell contents:** user-typed order notes, names and addresses must be escaped (templates and React do it by default); never build rows with `innerHTML` and raw user data.
- **Authorisation, not hiding:** don't send all customers' data and hide rows or columns with CSS or client-side filters; anyone can read the full HTML or JSON. Filter on the server.
- **Exports:** "Export to CSV" needs the formula-injection protection from the **CSV** lesson.
- **Pagination and limits:** paginate large admin tables on the server so one request can't dump the whole database.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="When should you use an HTML table?">
For tabular data, where values relate to both a row and a column, such as price lists, schedules, invoices, comparisons and reports. Tables should not be used for page layout; CSS Grid and Flexbox are the right tools for that.
</QA>

<QA q="How do you make a data table accessible?">
Give it a caption, use th elements for header cells with scope col or row, group rows with thead, tbody and tfoot, keep the structure simple with minimal merged cells, use the headers attribute only for unavoidable complex tables, and make wide tables scroll inside a focusable labelled region on small screens.
</QA>

<QA q="What do colspan and rowspan do?">
colspan makes a cell extend across several columns and rowspan across several rows. The cells they cover must be omitted from the following markup so every row still adds up to the same number of columns. They should be used only where the merge carries meaning, because they complicate navigation and responsiveness.
</QA>

<QA q="Why were table-based layouts abandoned?">
They mixed presentation into the document structure, produced heavy nested markup that loaded slowly, were very hard to make responsive, and confused assistive technologies, which announced layout cells as data. CSS layout separates presentation from content and works across screen sizes.
</QA>

</DeepDive>
