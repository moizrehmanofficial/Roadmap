<BigIdea>
<Tr>
<En>
**Tailwind CSS** is a tool that gives you thousands of tiny CSS classes, each doing **one job**: `p-4` adds padding, `text-white` makes text white, `rounded-lg` rounds corners, `flex` turns on Flexbox. Instead of inventing a class name and writing CSS for it in another file, you **combine these utility classes in your HTML**: `class="rounded-lg bg-blue-600 px-4 py-2 text-white"`. Prefixes add conditions: `hover:` for hover, `md:` for medium screens and wider, `dark:` for dark mode. Tailwind **scans your files** and generates CSS **only for the classes you actually used**, so the final CSS stays small. It's still normal CSS underneath, so everything you learned about the box model, Flexbox, Grid and media queries still applies; Tailwind just gives it short names.
</En>
<Ur>
**Tailwind CSS** ek tool hai jo aap ko hazaron chhoti CSS classes deta hai, har ek **ek kaam** karti hai: `p-4` padding deti hai, `text-white` text safed karti hai, `rounded-lg` kone gol karti hai, `flex` Flexbox on karti hai. Class ka naam soch kar doosri file me us ki CSS likhne ke bajaye, aap **ye utility classes apne HTML me jor dete hain**: `class="rounded-lg bg-blue-600 px-4 py-2 text-white"`. Prefixes sharten jorte hain: hover ke liye `hover:`, medium aur bari screens ke liye `md:`, dark mode ke liye `dark:`. Tailwind **aap ki files scan karta hai** aur **sirf unhi classes** ki CSS banata hai jo aap ne asal me istemal kin, isliye aakhri CSS chhoti rehti hai. Neeche ye aam CSS hi hai, isliye box model, Flexbox, Grid aur media queries ke baare me jo seekha sab lagu hai; Tailwind bas inhe chhote naam deta hai.
</Ur>
</Tr>

<Why>
<Tr>
<En>

- **No switching files and no naming.** You style the element right where it is; no more inventing names like `.card-header-inner-wrapper`.
- **Consistent design.** Spacing, colors and font sizes come from a fixed scale, so pages don't end up with 37 slightly different greys.
- **Small CSS.** Only used classes are generated. Unused styles never ship.
- **Safe to change.** Deleting a class from one element can't break another page, unlike editing a shared CSS rule.
- **Very popular** with React and Next.js, so you'll meet it in most modern codebases and job posts.

</En>
<Ur>

- **Files badalna aur naam sochna nahi.** Element ko wahin style karte hain jahan wo hai; `.card-header-inner-wrapper` jaise naam ghaarne ki zaroorat khatam.
- **Yaksaan design.** Spacing, rang aur font sizes ek tay shuda scale se aate hain, isliye pages me 37 thore thore mukhtalif grey nahi bante.
- **Chhoti CSS.** Sirf istemal hui classes banti hain. Ghair istemal styles kabhi nahi jate.
- **Badalna mehfooz.** Ek element se class hatane se doosra page nahi toot sakta, jaise shared CSS rule badalne se ho sakta hai.
- React aur Next.js ke saath **bohot maqbool**, isliye zyada tar jadeed codebases aur job posts me milega.

## Picture it

<Tr>
<En>

Normal CSS is like **cooking every dish from scratch**: for each new dish you write a recipe (a CSS rule with a name), store it in a recipe book (a `.css` file), and the cook has to flip to the right page.

Tailwind is a **spice rack with labelled jars**: "salt 2", "pepper 1", "chili 3". You season each dish **right at the stove** by grabbing jars: `p-4 text-white rounded-lg`. The jars are always the same sizes (the **scale**), so every dish tastes consistent.

And at the end of the day, a helper looks at what you **actually used** and only restocks those jars. That's Tailwind scanning your files and generating CSS just for those classes.

</En>
<Ur>

Aam CSS **har dish shuru se pakane** jaisi hai: har nayi dish ke liye recipe likhte hain (naam wala CSS rule), use recipe book (`.css` file) me rakhte hain, aur cook ko sahi safha palatna parta hai.

Tailwind **label lage martabanon wala masala rack** hai: "namak 2", "kaali mirch 1", "laal mirch 3". Aap har dish ko **choolhe par hi** martaban utha kar masala lagate hain: `p-4 text-white rounded-lg`. Martaban hamesha ek jaise naap ke hote hain (**scale**), isliye har dish ka zaiqa yaksaan rehta hai.

Aur din ke aakhir me ek madadgar dekhta hai ke aap ne **asal me kya istemal kiya** aur sirf wahi martaban dobara bharta hai. Ye Tailwind ka aap ki files scan kar ke sirf unhi classes ki CSS banana hai.

</Ur>
</Tr>

## Words you'll see

<Tr>
<En>

| Word | What it means | Example |
| --- | --- | --- |
| **Utility class** | A class that does one small thing | `p-4`, `text-center` |
| **Scale** | The fixed set of sizes or colors to pick from | `p-1`, `p-2`, `p-4` |
| **Shade** | A color's lightness, from 50 (light) to 950 (dark) | `blue-100`, `blue-900` |
| **Variant / prefix** | A condition in front of a class | `hover:`, `md:`, `dark:` |
| **Breakpoint** | A screen width where a responsive prefix starts | `md` = 48rem (768px) |
| **Mobile-first** | Unprefixed classes apply everywhere; prefixes add rules for wider screens | `text-sm md:text-lg` |
| **`@theme`** | Where you define your own colors, fonts and sizes | `--color-brand-500` |
| **Arbitrary value** | A one-off value in square brackets | `w-[327px]` |
| **Preflight** | Tailwind's reset that removes browser default styles | headings lose their big sizes |
| **`@apply`** | Uses utilities inside your own CSS rule | `@apply px-4 py-2;` |

</En>

| Lafz | Matlab | Misaal |

<Step title="Your first Tailwind button">

<Tr>
<En>
Each class adds one small piece of styling. Read the classes left to right like a sentence: rounded corners, blue background, horizontal padding 4, vertical padding 2, semi-bold, white text, darker blue on hover.
</En>
<Ur>
Har class styling ka ek chhota hissa jorti hai. Classes ko baayen se daayen jumle ki tarah parhein: gol kone, neela background, horizontal padding 4, vertical padding 2, semi-bold, safed text, hover par gehra neela.
</Ur>
</Tr>

```html preview-tw h=90
<button class="rounded-lg bg-blue-600 px-4 py-2 font-semibold text-white hover:bg-blue-700">
  Buy now
</button>
```

```text
Tailwind generated (utilities part):

  .rounded-lg { border-radius: var(--radius-lg); }
  .bg-blue-600 { background-color: var(--color-blue-600); }
  .px-4 { padding-inline: calc(var(--spacing) * 4); }
  .py-2 { padding-block: calc(var(--spacing) * 2); }
  .font-semibold { --tw-font-weight: var(--font-weight-semibold); font-weight: var(--font-weight-semibold); }
  .text-white { color: var(--color-white); }
  @media (hover: hover) {
    .hover\:bg-blue-700:hover { background-color: var(--color-blue-700); }
  }

and the theme values it used:

  --color-blue-600: oklch(54.6% 0.245 262.881);
  --color-blue-700: oklch(48.8% 0.243 264.376);
  --color-white: #fff;
  --spacing: 0.25rem;
  --font-weight-semibold: 600;
  --radius-lg: 0.5rem;
```

<Happened>
<Tr>
<En>

- Every class became **one ordinary CSS rule**. There's no magic: Tailwind is a fast way to write CSS you already know.
- The values come from **CSS variables** (CSS Variables lesson). `--spacing` is `0.25rem`, so `px-4` = 4 × 0.25rem = **1rem** (16px).
- The colon in `hover:bg-blue-700` is escaped as `\:` in the selector; you just type the class normally.
- Tailwind wraps hover styles in `@media (hover: hover)`, so tapping on a phone doesn't leave the button "stuck" in its hover color.
- Only the 6 theme values actually used were output. That's the "only what you use" promise.

</En>
<Ur>

- Har class **ek aam CSS rule** ban gayi. Koi jaadu nahi: Tailwind wo CSS likhne ka tez tareeqa hai jo aap pehle se jaante hain.
- Values **CSS variables** se aati hain (CSS Variables lesson). `--spacing` `0.25rem` hai, isliye `px-4` = 4 × 0.25rem = **1rem** (16px).
- `hover:bg-blue-700` ka colon selector me `\:` ki shakal me escape hota hai; aap class aam tarah likhte hain.
- Tailwind hover styles ko `@media (hover: hover)` me lapet-ta hai, taa ke phone par tap karne se button hover rang me "atka" na rahe.
- Sirf wahi 6 theme values bani jo asal me istemal huin. Yahi "sirf jo istemal karo" ka waada hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="The spacing scale">

<Tr>
<En>
Padding (`p`), margin (`m`), width (`w`), height (`h`) and gap (`gap`) all use the same scale: **number × 0.25rem**. Add a side letter for one direction: `t` top, `b` bottom, `l` left, `r` right, `x` left and right, `y` top and bottom.
</En>
<Ur>
Padding (`p`), margin (`m`), width (`w`), height (`h`) aur gap (`gap`) sab ek hi scale istemal karte hain: **number × 0.25rem**. Ek taraf ke liye taraf ka harf jorein: `t` upar, `b` neeche, `l` baayen, `r` daayen, `x` baayen aur daayen, `y` upar aur neeche.
</Ur>
</Tr>

```html preview-tw h=200
<div class="bg-slate-100 p-4">
  <div class="mb-2 w-64 bg-amber-200 p-2">p-2, w-64, mb-2</div>
  <div class="mt-8 w-32 bg-emerald-200 px-6 py-1">mt-8, w-32, px-6 py-1</div>
</div>
```

```text
Tailwind generated for p-4 mt-8 w-64 h-10 gap-2:

  --spacing: 0.25rem;

  .mt-8 { margin-top: calc(var(--spacing) * 8); }
  .h-10 { height: calc(var(--spacing) * 10); }
  .w-64 { width: calc(var(--spacing) * 64); }
  .gap-2 { gap: calc(var(--spacing) * 2); }
  .p-4 { padding: calc(var(--spacing) * 4); }
```

<Happened>
<Tr>
<En>

| Class | Math | Result |
| --- | --- | --- |
| `p-2` | 2 × 0.25rem | 0.5rem (8px) |
| `p-4` | 4 × 0.25rem | 1rem (16px) |
| `mt-8` | 8 × 0.25rem | 2rem (32px) |
| `w-64` | 64 × 0.25rem | 16rem (256px) |

- One rule for every size means you never have to remember a table.
- Other useful sizes: `w-full` (100%), `w-1/2` (50%), `max-w-md`, `min-h-screen`, `mx-auto` (centre a block), `size-10` (width and height together).
- Negative margins take a minus: `-mt-2`.

</En>
<Ur>

| Class | Hisaab | Nateeja |
| --- | --- | --- |
| `p-2` | 2 × 0.25rem | 0.5rem (8px) |
| `p-4` | 4 × 0.25rem | 1rem (16px) |
| `mt-8` | 8 × 0.25rem | 2rem (32px) |
| `w-64` | 64 × 0.25rem | 16rem (256px) |

- Har size ke liye ek hi qaida, isliye koi table yaad rakhne ki zaroorat nahi.

<Step title="Colors and shades">

<Tr>
<En>
Colors are written as **property-color-shade**: `text-slate-700`, `bg-sky-100`, `border-sky-500`. Shades go from `50` (very light) to `950` (very dark). Add `/50` for 50% opacity.
</En>
<Ur>
Rang **property-rang-shade** ki shakal me likhe jate hain: `text-slate-700`, `bg-sky-100`, `border-sky-500`. Shades `50` (bohot halka) se `950` (bohot gehra) tak hain. 50% opacity ke liye `/50` jorein.
</Ur>
</Tr>

```html preview-tw h=170
<div class="space-y-2 p-4">
  <p class="border-2 border-sky-500/50 bg-sky-100 p-3 text-slate-700">Info: your order has shipped.</p>
  <p class="border-2 border-rose-500/50 bg-rose-100 p-3 text-rose-800">Error: card was declined.</p>
</div>
```

```text
Tailwind generated for text-slate-700 bg-sky-100 border-sky-500/50:

  --color-sky-100: oklch(95.1% 0.026 236.824);
  --color-sky-500: oklch(68.5% 0.169 237.323);
  --color-slate-700: oklch(37.2% 0.044 257.287);

  .border-sky-500\/50 {
    border-color: color-mix(in srgb, oklch(68.5% 0.169 237.323) 50%, transparent);
    @supports (color: color-mix(in lab, red, red)) {
      border-color: color-mix(in oklab, var(--color-sky-500) 50%, transparent);
    }
  }
  .bg-sky-100 { background-color: var(--color-sky-100); }
  .text-slate-700 { color: var(--color-slate-700); }
```

<Happened>
<Tr>
<En>

- Prefixes say **what** gets the color: `text-` (text), `bg-` (background), `border-` (border), also `ring-`, `outline-`, `fill-`, `stroke-`.
- `/50` was turned into `color-mix(…)`: the color mixed 50% with transparent. Tailwind wrote a fallback first for older browsers.
- Tailwind v4 colors use **OKLCH**, a modern color format where shades with the same number look equally bright across colors.
- Pair light backgrounds (`100`) with dark text (`700`–`900`) for readable contrast.

</En>
<Ur>

- Prefixes batate hain rang **kis** ko milega: `text-` (text), `bg-` (background), `border-` (border), saath `ring-`, `outline-`, `fill-`, `stroke-`.
- `/50` `color-mix(…)` me badla: rang 50% transparent ke saath mila. Tailwind ne purane browsers ke liye pehle fallback likha.
- Tailwind v4 ke rang **OKLCH** istemal karte hain, ek jadeed format jahan ek hi number wale shades har rang me barabar roshan lagte hain.
- Parhne me aasaan contrast ke liye halke backgrounds (`100`) ke saath gehra text (`700`–`900`) lein.

</Ur>
</Tr>
</Happened>

</En>
<Ur>
Flexbox aur Grid ki classes seedha us CSS se milti hain jo aap ne seekhi: `flex` = `display: flex`, `items-center` = `align-items: center`, `justify-between` = `justify-content: space-between`, `grid grid-cols-3` = teen column wala grid.
</Ur>

<Step title="Responsive design with md: and lg:">

<Step title="The dynamic class name trap">

<Tr>
<En>
Tailwind finds classes by **reading your files as plain text**. It does not run your JavaScript. So a class name **built from pieces** at runtime is never seen, and no CSS is generated for it.
</En>
<Ur>
Tailwind aap ki files ko **saada text ki tarah parh kar** classes dhoondta hai. Ye aap ki JavaScript nahi chalata. Isliye runtime par **tukron se bana** class naam kabhi nazar nahi aata, aur us ki CSS nahi banti.
</Ur>
</Tr>

```text
File content:   el.className = `bg-${color}-500`;

Tailwind generated:
  @layer utilities;            ← empty: no bg-red-500 was found
```

```text
File content:   const colors = { danger: "bg-red-500", success: "bg-green-500" };

Tailwind generated:
  .bg-green-500 { background-color: var(--color-green-500); }
  .bg-red-500 { background-color: var(--color-red-500); }
```

<Happened>
<Tr>
<En>

- In the first file, the text `bg-red-500` never appears, so the button would show **no background** at all, with no error.
- In the second, both **complete** class names appear in the file, so both are generated. Then pick one with `colors[type]`.
- Rule: **always write full class names** in your code. Map from your data to complete class strings.

</En>
<Ur>

- Pehli file me `bg-red-500` ka text kabhi nazar nahi aata, isliye button par **koi background** nahi hoga, aur koi error bhi nahi.
- Doosri me dono **poore** class naam file me hain, isliye dono bante hain. Phir `colors[type]` se ek chunein.
- Qaida: **code me hamesha poore class naam likhein.** Apne data se poori class strings ki taraf map karein.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Reusing styles: components, not copy-paste">

<Tr>
<En>
Long class lists repeated on 20 buttons are hard to change. The Tailwind way is to **make a component** (React, or a template partial) and use it everywhere. `@apply` exists for rare cases like styling HTML you don't control.
</En>
<Ur>
20 buttons par dohrayi gayi lambi class lists badalna mushkil hai. Tailwind ka tareeqa hai **component banana** (React, ya template partial) aur use har jagah istemal karna. `@apply` kam hi aane wale moqon ke liye hai, jaise aisa HTML style karna jo aap ke qaboo me nahi.
</Ur>
</Tr>

```tsx
// components/Button.tsx
type Props = React.ComponentProps<"button"> & { variant?: "primary" | "secondary" };

const styles = {
  primary: "bg-blue-600 text-white hover:bg-blue-700",
  secondary: "bg-white text-slate-900 ring-1 ring-slate-300 hover:bg-slate-50",
};

export function Button({ variant = "primary", className = "", ...props }: Props) {
  return (
    <button
      className={`rounded-lg px-4 py-2 font-semibold disabled:opacity-50 ${styles[variant]} ${className}`}
      {...props}
    />
  );
}
```

```css
/* Only when you can't add classes yourself, e.g. HTML from a CMS: */
.cms-content a {
  @apply text-blue-600 underline hover:text-blue-800;
}
```

<Happened>
<Tr>
<En>

- Now `<Button variant="secondary">Cancel</Button>` is all you write. Changing the design means editing **one file**.
- If two classes conflict (`px-4` from the component and `px-8` passed in `className`), the winner depends on CSS order, not the order in the string. The **tailwind-merge** library (often wrapped in a `cn()` helper) removes the conflicting one for you.

</En>
<Ur>

- Ab bas `<Button variant="secondary">Cancel</Button>` likhna hai. Design badalne ka matlab **ek file** badalna.
- Agar do classes takrayen (component ki `px-4` aur `className` me bheji gayi `px-8`), to jeet CSS ki tarteeb se tay hoti hai, string ki tarteeb se nahi. **tailwind-merge** library (aksar `cn()` helper me lipti) aap ke liye takrane wali class hata deti hai.

</Ur>
</Tr>
</Happened>

</Step>

## Common mistakes

<Compare>
<Bad title="Building class names from pieces">

```tsx
<span className={`text-${color}-600`}>Status</span>
```

</Bad>
<Good title="Full class names, chosen from a map">

```tsx
const textColor = { red: "text-red-600", green: "text-green-600" };
<span className={textColor[color]}>Status</span>
```

</Good>
</Compare>

<Compare>
<Bad title="Desktop-first thinking">

```html
<!-- "md: means medium only" -- wrong: it also applies on large screens -->
<div class="grid-cols-3 md:grid-cols-1">
```

</Bad>
<Good title="Mobile-first">

```html
<div class="grid grid-cols-1 md:grid-cols-3">
```

</Good>
</Compare>

<Compare>
<Bad title="Removing focus with nothing in its place">

```html
<button class="outline-none">Save</button>
```

</Bad>
<Good title="Visible keyboard focus">

```html
<button class="focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-blue-600">Save</button>
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Copy-pasting long class lists everywhere** instead of making a component.
- **Using arbitrary values for everything** (`p-[13px]`, `text-[#333]`): you lose the consistency that makes Tailwind useful. Add tokens to `@theme`.
- **Writing `class` in React** instead of `className`.
- **Being surprised that headings and lists look plain**: that's Preflight. Add sizes yourself, or use the Typography plugin (`prose`) for article content.
- **Mixing v3 and v4 instructions**: v4 uses `@import "tailwindcss"` and `@theme`; v3 used `@tailwind base;` and `tailwind.config.js`.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Component banane ke bajaye lambi class lists har jagah copy paste karna.**
- **Har cheez ke liye arbitrary values** (`p-[13px]`, `text-[#333]`): wo yaksaaniyat kho jati hai jo Tailwind ko kaam ka banati hai. Tokens `@theme` me daalein.
- **React me `class` likhna** `className` ke bajaye.
- **Headings aur lists ke saade lagne par hairan hona**: ye Preflight hai. Sizes khud dein, ya article content ke liye Typography plugin (`prose`) lein.
- **v3 aur v4 ki hidayat mila dena**: v4 `@import "tailwindcss"` aur `@theme` istemal karta hai; v3 `@tailwind base;` aur `tailwind.config.js`.

</Ur>
</Tr>

<DeepDive title="More about Tailwind">

**How it works.** Tailwind's engine scans your project files for anything that looks like a class name, then generates CSS for the ones that match a utility. It runs during development (with fast incremental rebuilds) and during `next build`.

**Layers.** Output is organised into cascade layers: `theme` (variables), `base` (Preflight), `components` and `utilities`. Utilities come last, so they win over component styles without needing `!important`.

**Custom utilities and variants.**

```text
@utility content-auto {
  content-visibility: auto;
}
@custom-variant pointer-coarse (@media (pointer: coarse));
```

**Container queries.** Mark a parent with `@container`, then use `@md:` on children to respond to the **parent's** width instead of the screen's.

**Important modifier.** `bg-red-500!` adds `!important` for the rare case you must beat another stylesheet.

**Plugins.** `@tailwindcss/typography` (`prose` classes for articles) and `@tailwindcss/forms` (nicer default form controls) are the most common; enable them with `@plugin "@tailwindcss/typography";`.

**Component libraries.** **shadcn/ui** gives you copy-in React components built with Tailwind and Radix UI; you own the code and can change any class.

</DeepDive>

<DeepDive title="Real world: the invisible error banner">

A team built a `Toast` component that took a `variant` prop and set `` className={`bg-${variant}-50 border-${variant}-500`} ``. In development everything looked fine, because other pages happened to use `bg-red-50` and `border-red-500` directly, so Tailwind had generated those classes anyway.

Months later, someone cleaned up those other pages. The next build stopped generating the red classes. Error toasts in production became **transparent with no border**, and customers missed "payment failed" messages for two days. There was no error in the console and no failing test, because the class names were still "there"; they just had no CSS.

The fix:

1. Replace string building with a map of full class names for each variant.
2. Add a lint rule (the Tailwind ESLint plugin) that flags dynamic class names.
3. Add a visual regression test (screenshots of each toast variant) so missing styles show up as a diff.

Lesson: Tailwind's "only what you use" is a feature, but it means **the scanner must be able to read every class name in your source code**.

</DeepDive>

<DeepDive title="Security lens">

- **Never put user input into class names.** A class string built from user data can't run scripts, but it can break layouts or hide warnings; map user choices to a fixed list of class strings.
- **Don't render untrusted HTML** to "use Tailwind on it". If you must display HTML from a CMS or users, sanitize it (DOMPurify) and style it with `prose` instead of trusting its classes.
- **Clickjacking and fake overlays.** Utilities like `fixed inset-0 z-50` make full-screen overlays easy. Make sure only your code can render them, and set `frame-ancestors` in your Content-Security-Policy so other sites can't frame yours.
- **Third-party CDN builds.** Loading Tailwind's browser build from a public CDN in production adds a script you don't control; build CSS at deploy time instead.
- **Accessibility is security for some users**: keep visible focus states and sufficient color contrast so everyone can see warnings and confirmations.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What is utility-first CSS?">
An approach where you style elements by combining small single-purpose classes, such as padding, color and layout utilities, directly in the markup instead of writing custom named classes in separate stylesheets.
</QA>

<QA q="How does Tailwind keep its production CSS small?">
It scans source files for class names and generates CSS only for the utilities it finds, including their variants, so unused utilities are never output.
</QA>

<QA q="Why should you avoid constructing Tailwind class names dynamically?">
The scanner reads files as plain text and does not execute code, so partial names built at runtime are never detected and no CSS is generated for them. Use complete class names, for example in a lookup object.
</QA>

<QA q="What does mobile-first mean for Tailwind's responsive prefixes?">
Unprefixed utilities apply at all widths, and prefixes like md and lg apply at that minimum width and above, so you design the small-screen layout first and add overrides for larger screens.
</QA>

<QA q="How do you avoid duplicating long class lists?">
Extract a reusable component or template partial, use variant maps for differences, and use a helper such as tailwind-merge to resolve conflicting classes. @apply is reserved for cases where you cannot edit the markup.
</QA>

</DeepDive>
