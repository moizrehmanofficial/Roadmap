<Callout type="tip" title="In one minute">
CSS has two motion tools. A **transition** animates a property **between two states** when it changes (on hover, focus, a class toggle): `transition: background-color 200ms ease-out;`. An **animation** uses **`@keyframes`** to run a sequence of steps by itself, any number of times: `animation: spin 1s linear infinite;`. Both use a **duration**, a **timing function** (easing: `ease`, `linear`, `ease-in-out`, `cubic-bezier()`, `steps()`) and an optional **delay**. Animate **`transform`** (translate, scale, rotate) and **`opacity`** whenever possible: browsers can run them on the GPU without recalculating layout, so they stay smooth at 60fps; animating `width`, `height`, `top` or `margin` triggers layout on every frame and can stutter. Keep UI transitions short (about 150–300ms), use motion to **explain** changes rather than decorate, and always respect **`prefers-reduced-motion`**.
</Callout>

## Start from zero

<Callout type="analogy">
A **transition** is like a **dimmer switch**: you change the light from off to on, and instead of jumping, it fades over half a second. You only decide the start and end; the dimmer handles the in-between. An **animation** is like a **flip book**: you draw the key pages (0%, 50%, 100%), and the book plays them in order, as many times as you like, without anyone touching the switch. **Easing** is how a car moves: it doesn't jump to full speed; it accelerates, cruises and brakes. Motion that eases feels natural; motion at constant speed feels mechanical.
</Callout>

### Words you need first

| Word | Simple meaning | Example |
| --- | --- | --- |
| **Transition** | Smooth change between two values when a property changes | hover colour fade |
| **Animation** | Keyframe sequence that runs by itself | spinner |
| **@keyframes** | Named list of steps (0% … 100%) | `@keyframes spin {…}` |
| **Duration** | How long it takes | `200ms`, `1s` |
| **Timing function / easing** | How speed changes over time | `ease-out` |
| **Delay** | Wait before starting | `100ms` |
| **Transform** | Move, scale, rotate or skew without affecting layout | `translateY(-4px)` |
| **Interpolation** | Calculating in-between values | 50% between 0 and 100 = 50 |
| **Frame** | One screen update; 60fps = one every 16.7ms | |
| **Compositing** | GPU combining layers without redoing layout or paint | transform, opacity |

## What is it?

```css
/* Transition: animate when the value changes */
.btn {
  background-color: #f59e0b;
  transition: background-color 200ms ease-out, transform 150ms ease-out;
}
.btn:hover { background-color: #d97706; transform: translateY(-2px); }

/* Animation: runs by itself */
@keyframes spin {
  from { rotate: 0deg; }
  to   { rotate: 360deg; }
}
.spinner { animation: spin 1s linear infinite; }
```

## Why does it matter?

- **Feedback:** a button that reacts on hover and press feels responsive.
- **Continuity:** a menu that slides from its button, or an item that fades out when deleted, shows users **where things came from and went**, so changes aren't confusing.
- **Attention:** a subtle pulse on a new notification draws the eye.
- **Perceived performance:** skeleton loaders and spinners make waiting feel shorter.
- **Risks:** too much or too slow motion annoys users, hurts performance on cheap phones, and can make people with vestibular disorders feel ill. Getting it right is part of professional frontend work.

## When and where do you use it?

- **Transitions:** state changes such as hover, focus, active, open/closed, selected, theme changes.
- **Animations:** loading indicators, attention cues, entrance effects, looping illustrations.
- **JavaScript (Web Animations API or libraries like Motion/GSAP):** sequences that depend on logic, physics-based motion, interruptible gestures.

## Concepts one by one

### 1. Transitions

<Explain>
<What>
The `transition` shorthand: **property**, **duration**, **timing function**, **delay**. Several transitions are separated by commas.
```css
transition: opacity 200ms ease-out 50ms, transform 300ms ease;
```
Longhands: `transition-property`, `transition-duration`, `transition-timing-function`, `transition-delay`.
</What>
<Why>
Without a transition, property changes are instant. With one, the browser interpolates between old and new values over time.
</Why>
<When>
Put the `transition` on the **base** state (not only on `:hover`), so it runs both when entering and leaving the state.
</When>
<Where>
Avoid `transition: all`: it animates properties you didn't intend (including layout ones), and makes future changes surprising. List the properties.
</Where>
<How>
Sampling the computed colour at points during a 1-second transition. The script pauses the transition at specific times with the Web Animations API, which is how the browser exposes CSS transitions to JavaScript:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>
.box { width: 100px; height: 20px; background-color: rgb(0, 0, 0); transition: background-color 1000ms linear; }
.box.on { background-color: rgb(200, 100, 0); }
</style><div class="box" id="b"></div>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    page.eval_on_selector("#b", "e => { e.classList.add('on'); window.anim = e.getAnimations()[0]; anim.pause(); }")
    print("animation created:", page.evaluate("anim.constructor.name + ' of ' + anim.transitionProperty"))
    for t in [0, 250, 500, 750, 1000]:
        colour = page.eval_on_selector("#b", f"e => {{ anim.currentTime = {t}; return getComputedStyle(e).backgroundColor }}")
        print(f"t = {t:4}ms  background {colour}")
    browser.close()
PY
```

```text output
animation created: CSSTransition of background-color
t =    0ms  background rgb(0, 0, 0)
t =  250ms  background rgb(50, 25, 0)
t =  500ms  background rgb(100, 50, 0)
t =  750ms  background rgb(150, 75, 0)
t = 1000ms  background rgb(200, 100, 0)
```

Line by line:

- Adding the `on` class changes the background colour, which starts a 1000ms transition. The browser creates a `CSSTransition` object for it, and the script immediately pauses it.
- Setting `currentTime` jumps to a moment in the transition; `getComputedStyle` then shows the in-between value.
- With `linear` timing, each channel moves at a constant rate: at 250ms (25%), red is 25% of 200 = 50, green 25% of 100 = 25.
- Every CSS transition and animation is a real `Animation` object (`CSSTransition` or `CSSAnimation`) that JavaScript can inspect, pause or reverse.


### 2. What can be animated

<Explain>
<What>
A property can transition if the browser knows how to **interpolate** it: numbers, lengths, percentages, colours, transforms, shadows, `opacity`, `filter`, gradients' positions (not the gradient itself, unless you use `@property` variables), `clip-path`, and many more. Properties with discrete values (`display`, `visibility`, `font-family`) switch at a single moment instead.
</What>
<Why>
Knowing this avoids "my transition doesn't work" surprises: `height: 0` → `height: auto` doesn't animate (classic problem), and `display: none` → `block` jumps.
</Why>
<When>
- Height to auto: use `grid-template-rows: 0fr` → `1fr` (which does animate), or `interpolate-size: allow-keywords` in newer browsers, or `<details>` with `::details-content`.
- Showing/hiding: animate `opacity` and `transform`, and see concept 7 for `display`.
</When>
<Where>
`visibility` is discrete but switches at the right end of the transition when combined with opacity, which is useful for fade-outs that also hide content from screen readers when finished.
</Where>
<How>
The grid trick for expanding sections:
</How>
</Explain>

```html preview-js h=230 noqa
<style>
  body { font-family: system-ui, sans-serif; }
  .panel { display: grid; grid-template-rows: 0fr; transition: grid-template-rows 300ms ease-out; }
  .panel.open { grid-template-rows: 1fr; }
  .panel > div { overflow: hidden; }
  .panel p { margin: 8px 0; }
</style>
<button type="button" id="toggle" aria-expanded="false" aria-controls="details">Show delivery details</button>
<div class="panel" id="details">
  <div>
    <p>Kent mangoes ship from Florida every morning.</p>
    <p>Orders before 2 pm arrive the next day; boxes are insulated and recyclable.</p>
    <p>Free delivery on orders over Rs 3,000.</p>
  </div>
</div>
<script>
  const btn = document.getElementById("toggle"), panel = document.getElementById("details");
  btn.addEventListener("click", () => {
    const open = panel.classList.toggle("open");
    btn.setAttribute("aria-expanded", open);
  });
</script>
```

Line by line:

- The panel is a one-row grid. A `0fr` row is as small as possible (and `overflow: hidden` on the child clips the content); `1fr` is its full natural height.
- `grid-template-rows` can be interpolated between `0fr` and `1fr`, so the panel smoothly expands to whatever height the content needs, without knowing that height.
- The button's `aria-expanded` is updated so screen readers know the state.

### 3. Easing: timing functions

<Explain>
<What>
A timing function maps **time progress** (0 → 1) to **value progress** (0 → 1):
- `linear`: constant speed.
- `ease` (default): quick start, gentle end.
- `ease-in`: starts slow, ends fast (things leaving).
- `ease-out`: starts fast, ends slow (things arriving, UI responses).
- `ease-in-out`: slow, fast, slow (moving between two places on screen).
- `cubic-bezier(x1, y1, x2, y2)`: custom curves; y values outside 0–1 create overshoot ("bounce back").
- `steps(n)`: jumps in n equal steps (sprite animations, typewriter effects, clocks).
- `linear(...)`: a newer function that approximates complex curves like springs and bounces with many points.
</What>
<Why>
Real objects accelerate and decelerate; easing makes interfaces feel natural and responsive. `ease-out` is the usual choice for UI: the response starts immediately and settles gently.
</Why>
<When>
- Hover/press feedback, menus opening: `ease-out`, 100–200ms.
- Elements moving across the screen: `ease-in-out`, 200–400ms.
- Exits: `ease-in`, a bit faster than entrances.
- Spinners and progress: `linear`.
</When>
<Where>
Durations matter as much as curves: most UI transitions should be **150–300ms**; anything over ~500ms feels slow for interface feedback.
</Where>
<How>
Where each timing function is at 25%, 50% and 75% of the time, sampled from real transitions of `opacity` from 0 to 1:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
easings = ["linear", "ease", "ease-in", "ease-out", "ease-in-out", "cubic-bezier(0.34, 1.56, 0.64, 1)", "steps(4)"]
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    print(f"{'timing function':36} 25%    50%    75%  of the time")
    for e in easings:
        page.set_content(f"""<!DOCTYPE html><title>t</title><style>
          .b {{ opacity: 0; transition: opacity 1000ms {e}; }} .b.on {{ opacity: 1; }}</style><div class="b" id="b"></div>""")
        values = page.eval_on_selector("#b", """e => { e.classList.add('on'); const a = e.getAnimations()[0]; a.pause();
            return [250, 500, 750].map(t => { a.currentTime = t; return Number(getComputedStyle(e).opacity).toFixed(2) }) }""")
        print(f"{e:36} " + "   ".join(values))
    browser.close()
PY
```

```text output
timing function                      25%    50%    75%  of the time
linear                               0.25   0.50   0.75
ease                                 0.41   0.80   0.96
ease-in                              0.09   0.32   0.62
ease-out                             0.38   0.68   0.91
ease-in-out                          0.13   0.50   0.87
cubic-bezier(0.34, 1.56, 0.64, 1)    0.82   1.00   1.00
steps(4)                             0.25   0.50   0.75
```

Line by line:

- **linear:** value progress equals time progress.
- **ease:** already 80% done at half-time: fast start, long gentle finish.
- **ease-in:** only 9% done after a quarter of the time: a slow start.
- **ease-out:** 38% done after a quarter: an immediate response that slows down at the end.
- **ease-in-out:** symmetric, exactly 50% at half-time.
- **The custom "back" curve** (`cubic-bezier(0.34, 1.56, 0.64, 1)`) overshoots: it's already at 82% after a quarter of the time, and in-between it goes **above** 1 (opacity can't, so it shows 1.00; with `transform: scale` you'd see the element grow slightly too big and settle back).
- **steps(4):** jumps in four steps, holding each value: 0.25, 0.50, 0.75, then 1.

### 4. Transforms

<Explain>
<What>
`transform` (and the individual properties `translate`, `scale`, `rotate`) visually moves, resizes or rotates an element **without changing layout**: other elements don't move.
- `translate: 0 -4px` / `transform: translateY(-4px)`: move.
- `scale: 1.05`: grow by 5%.
- `rotate: 45deg`: rotate.
- `transform: skewX(10deg)`, and 3D functions (`rotateY`, `perspective`).
- `transform-origin` sets the pivot point (default: the centre).
Percentages in `translate` refer to the element's **own** size.
</What>
<Why>
Transforms are the main tool for motion: they're cheap to animate and don't disturb surrounding content.
</Why>
<When>
Hover lifts, press effects (`scale: 0.97`), slide-ins (`translate: 0 100%` → `0 0`), flipping cards, spinners.
</When>
<Where>
The individual `translate`, `rotate` and `scale` properties (supported everywhere since 2022) can be transitioned independently and don't overwrite each other, unlike several `transform` declarations, where the last one replaces the whole list. Remember that a transform creates a stacking context and a containing block for fixed elements (see the Positioning lesson).
</Where>
<How>
Proof that a transform doesn't move neighbours, while a margin does:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>body{margin:0} div{height:40px}
#t { translate: 0 30px; } #m { margin-top: 30px; }
</style>
<section id="s1"><div>a</div><div id="t">transformed</div><div id="after1">next</div></section>
<section id="s2"><div>a</div><div id="m">margin</div><div id="after2">next</div></section>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    for el, nxt in [("#t", "#after1"), ("#m", "#after2")]:
        y = page.evaluate(f"""[document.querySelector('{el}'), document.querySelector('{nxt}')].map(e =>
            Math.round(e.getBoundingClientRect().y - e.parentElement.getBoundingClientRect().y))""")
        print(f"{el}: element drawn at y={y[0]}, next element at y={y[1]}")
    browser.close()
PY
```

```text output
#t: element drawn at y=70, next element at y=80
#m: element drawn at y=70, next element at y=110
```

Line by line:

- Both elements are moved down by 30px, so both are drawn at y=70 (instead of 40).
- With `translate`, the next element stays at y=80, its normal position: the layout didn't change (the moved element now overlaps it).
- With `margin-top`, the next element is pushed down to y=110: the whole layout below was recalculated. Animating margins forces this calculation on every frame.

### 5. Performance: what's cheap and what's expensive

<Explain>
<What>
Each frame, the browser may need to: **style** (calculate CSS) → **layout** (sizes and positions) → **paint** (draw pixels) → **composite** (combine layers on the GPU).
- Changing **`transform`** or **`opacity`** usually only needs **compositing**: cheap.
- Changing `color`, `background`, `box-shadow` needs **paint**: moderate.
- Changing `width`, `height`, `top`, `left`, `margin`, `padding`, `font-size` needs **layout**, then paint: expensive, and it can affect the whole page.
</What>
<Why>
At 60fps the browser has about **16.7ms per frame** (8.3ms at 120Hz) for everything, including your JavaScript. Layout-heavy animations on large pages or cheap phones miss frames and look janky.
</Why>
<When>
- Move with `translate`, not `top`/`left`.
- Resize visually with `scale` where possible.
- Fade with `opacity`.
- For an expensive shadow change on hover, fade a pseudo-element's opacity that already has the bigger shadow.
</When>
<Where>
`will-change: transform` hints that an element will animate, so the browser can prepare a layer. Use it sparingly (on the element just before animating, or on a few known elements); too many layers waste memory. DevTools' **Performance** panel and the **Rendering → Paint flashing** option show what's being repainted.
</Where>
<How>
A cheap shadow hover:
</How>
</Explain>

```css
.card { position: relative; transition: translate 200ms ease-out; }
.card::after {
  content: ""; position: absolute; inset: 0; border-radius: inherit; z-index: -1;
  box-shadow: 0 12px 32px rgb(0 0 0 / 0.18);
  opacity: 0; transition: opacity 200ms ease-out;      /* animate opacity, not box-shadow */
}
.card:hover { translate: 0 -4px; }
.card:hover::after { opacity: 1; }
```

### 6. Keyframe animations

<Explain>
<What>
`@keyframes name { from {…} 50% {…} to {…} }` defines steps; `animation` applies them:
```css
animation: name duration timing-function delay iteration-count direction fill-mode play-state;
animation: pulse 2s ease-in-out 0s infinite alternate both running;
```
- `animation-iteration-count`: a number or `infinite`.
- `animation-direction`: `normal`, `reverse`, `alternate` (forwards then backwards), `alternate-reverse`.
- `animation-fill-mode`: `none` (default: the element returns to its own styles before and after), `forwards` (keep the last keyframe's values after the end), `backwards` (apply the first keyframe during the delay), `both`.
- `animation-play-state`: `running` or `paused`.
- Missing `from`/`to` keyframes use the element's current values.
</What>
<Why>
Animations run without any state change: loaders, attention cues, entrance effects, decorative loops.
</Why>
<When>
Loading spinners and skeletons, a notification badge pulse, an entrance effect when an element appears.
</When>
<Where>
A common bug: an entrance animation that ends and then "jumps back" to the original state, because `fill-mode` is `none`. Use `forwards` or `both`, or make the element's normal styles equal the final keyframe.
</Where>
<How>
Sampling a 1-second animation with `alternate` direction and different fill modes:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>
@keyframes slide { from { translate: 0px; } to { translate: 100px; } }
.a { animation: slide 1000ms linear 2 alternate; }
.none { animation: slide 1000ms linear 500ms 1 none; }
.both { animation: slide 1000ms linear 500ms 1 both; }
</style><div class="a" id="alt"></div><div class="none" id="none"></div><div class="both" id="both"></div>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    # keep a reference to each animation: a finished animation with fill "none" disappears from getAnimations()
    page.evaluate("window.A = {}; document.querySelectorAll('div').forEach(e => { A[e.id] = e.getAnimations()[0]; A[e.id].pause(); })")
    def at(el, t):
        return page.eval_on_selector(el, f"e => {{ A[e.id].currentTime = {t}; return getComputedStyle(e).translate }}")
    print("alternate, 2 iterations:", [at("#alt", t) for t in [0, 500, 1000, 1500, 1999]])
    print("fill none (500ms delay):", [at("#none", t) for t in [0, 250, 1000, 1500, 2000]])
    print("fill both (500ms delay):", [at("#both", t) for t in [0, 250, 1000, 1500, 2000]])
    browser.close()
PY
```

```text output
alternate, 2 iterations: ['0px', '50px', '100px', '50px', '0.1px']
fill none (500ms delay): ['none', 'none', '50px', 'none', 'none']
fill both (500ms delay): ['0px', '0px', '50px', '100px', '100px']
```

Line by line:

- **alternate:** the first iteration goes 0 → 100px, the second goes back 100 → 0 (at 1500ms it's halfway back at 50px; at 1999ms it's almost at 0).
- **fill none:** during the 500ms delay, the element shows its own style (`translate: none`). At 1000ms (500ms into the animation) it's at 50px. After the end (1500ms and later) it jumps back to `none`.
- **fill both:** during the delay it already shows the first keyframe (0px), and after the end it **keeps** the last keyframe (100px).

### 7. Entering and leaving: display: none, @starting-style, transition-behavior

<Explain>
<What>
Transitions don't run when an element first appears (there's no "before" value), and `display` is discrete. Two newer features (supported in all major browsers since 2024) fix this:
- **`@starting-style { … }`** defines the values to transition **from** when an element is first rendered or goes from `display: none` to visible.
- **`transition-behavior: allow-discrete`** (or `allow-discrete` in the shorthand) lets `display` (and `overlay` for top-layer elements) take part in a transition, so the element stays visible until the exit animation finishes.
</What>
<Why>
Fading in and out dialogs, popovers, toasts and menus previously required JavaScript timers to add and remove classes.
</Why>
<When>
`<dialog>`, `popover`, toasts, any element toggled with `display: none` or the `hidden` attribute.
</When>
<Where>
Browsers without support simply show and hide without animation, which is a fine fallback.
</Where>
<How>
A popover that fades and scales in and out, with no JavaScript:
</How>
</Explain>

```html preview h=220 noqa
<style>
  body { font-family: system-ui, sans-serif; }
  [popover] {
    padding: 12px 16px; border: 1px solid #e5e7eb; border-radius: 10px;
    opacity: 0; scale: 0.95;
    transition: opacity 200ms ease-out, scale 200ms ease-out,
                display 200ms allow-discrete, overlay 200ms allow-discrete;
  }
  [popover]:popover-open { opacity: 1; scale: 1; }
  @starting-style {
    [popover]:popover-open { opacity: 0; scale: 0.95; }
  }
</style>
<button type="button" popovertarget="info">Delivery info</button>
<div id="info" popover>Orders before 2 pm arrive tomorrow.</div>
```

Line by line:

- Closed state: transparent and slightly smaller. Open state (`:popover-open`): fully visible at normal size.
- `@starting-style` says "when the popover first opens, start from opacity 0 and scale 0.95", so the opening animates.
- `display … allow-discrete` and `overlay … allow-discrete` keep the popover displayed and in the top layer until the closing transition ends, so closing animates too.

### 8. Animation events and the Web Animations API

<Explain>
<What>
- Events: `transitionstart`, `transitionend`, `transitioncancel`, `animationstart`, `animationiteration`, `animationend`, `animationcancel`.
- **Web Animations API (WAAPI):** `element.animate(keyframes, options)` creates animations from JavaScript with the same engine as CSS, returning an `Animation` object with `play()`, `pause()`, `reverse()`, `finish()`, `cancel()`, `currentTime`, `playbackRate` and a `finished` promise.
</What>
<Why>
Run code after an animation (remove an element after it fades out), or create animations with values computed at runtime (from a click position to a target).
</Why>
<When>
Removing elements after exit animations, chaining steps, dynamic motion. Libraries like Motion (Framer Motion) build on these APIs.
</When>
<Where>
`transitionend` fires once **per property**, and not at all if the transition is interrupted or the value didn't change; prefer `element.getAnimations()` with `finished` promises for reliable sequencing.
</Where>
<How>
A WAAPI animation in a real browser, sampled and then awaited:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content("<!DOCTYPE html><title>t</title><div id='toast'>Saved</div>")
    result = page.evaluate("""async () => {
        const el = document.getElementById('toast');
        const anim = el.animate(
            [{ opacity: 1, translate: '0 0' }, { opacity: 0, translate: '0 -20px' }],
            { duration: 300, easing: 'ease-in', fill: 'forwards' });
        anim.pause(); anim.currentTime = 150;
        const mid = { opacity: Number(getComputedStyle(el).opacity).toFixed(2), translate: getComputedStyle(el).translate.replace(/[\\d.]+px/g, m => parseFloat(m).toFixed(1) + 'px') };
        anim.play();
        await anim.finished;          // resolves when the animation ends
        const end = getComputedStyle(el).opacity;
        el.remove();
        return { mid, end, stillInPage: document.getElementById('toast') !== null };
    }""")
    print(result)
    browser.close()
PY
```

```text output
{'mid': {'opacity': '0.68', 'translate': '0.0px -6.3px'}, 'end': '0', 'stillInPage': False}
```

Line by line:

- `el.animate()` takes keyframes (an array, like `@keyframes`) and options (duration, easing, fill).
- Halfway through the time (150ms), both properties have made the same progress along the `ease-in` curve: about 32% (see the easing table in concept 3). So opacity is 1 − 0.32 ≈ 0.68, and the element has moved 32% of 20px ≈ 6.3px up.
- `anim.finished` is a promise that resolves when the animation ends, so the code can wait for it and then remove the element. The final opacity is 0 because of `fill: 'forwards'`.
- This is how toasts and list items are removed after an exit animation, without guessing timings with `setTimeout`.

### 9. Scroll-driven animations and view transitions

<Explain>
<What>
Two newer features:
- **Scroll-driven animations:** `animation-timeline: scroll()` (progress of scrolling a container) or `view()` (progress of an element crossing the viewport) drives a normal `@keyframes` animation by scroll position instead of time. Examples: a reading progress bar, elements fading in as they enter.
- **View transitions:** `document.startViewTransition(() => updateTheDOM())` (and `@view-transition { navigation: auto; }` for multi-page sites) animates between two states of the page, with cross-fades and elements morphing between positions (`view-transition-name`).
</What>
<Why>
Effects that needed scroll listeners or heavy libraries can now be pure CSS, running off the main thread.
</Why>
<When>
Progress indicators, reveal-on-scroll, page and list transitions in apps.
</When>
<Where>
Scroll-driven animations are supported in Chrome and Edge (since 2023) and Safari (2025), with Firefox behind a flag at the time of writing; view transitions for same-document updates are in all major browsers. Use them as progressive enhancements, and respect reduced motion.
</Where>
<How>
A reading progress bar with no JavaScript (scroll inside the box):
</How>
</Explain>

### 10. Reduced motion and good motion design

<Explain>
<What>
`@media (prefers-reduced-motion: reduce)` is true when users have asked their OS to minimise motion. Guidelines:
- Remove or replace large movements, parallax, zooms, spinning and auto-playing animations; cross-fades are usually fine.
- Never flash content more than three times per second (seizure risk, WCAG 2.3.1).
- Provide pause/stop controls for anything that moves for more than 5 seconds (WCAG 2.2.2), like carousels.
- Keep UI motion short and purposeful.
</What>
<Why>
For people with vestibular disorders, motion can cause dizziness, nausea and headaches. Many others simply find constant movement distracting.
</Why>
<When>
Every site with animations.
</When>
<Where>
Two approaches: add motion only when there's no preference (`@media (prefers-reduced-motion: no-preference) { … }`), or remove it under `reduce`. The first is safer by default.
</Where>
<How>
```css
.card { transition: opacity 200ms ease-out; }                  /* always: subtle fade */
@media (prefers-reduced-motion: no-preference) {
  .card { transition: opacity 200ms ease-out, translate 200ms ease-out; }  /* movement only if OK */
  .card:hover { translate: 0 -4px; }
}
```
</How>
</Explain>

## Real-world example

Apple's iOS 7 (2013) introduced heavy parallax and zooming transitions, and many users reported motion sickness; Apple added a "Reduce Motion" setting in response, and browsers later exposed it to websites as `prefers-reduced-motion`. On the web, motion design systems now publish explicit rules: Google's Material Design specifies durations (for example around 200–300ms for most UI changes) and standard easing curves, and IBM's Carbon distinguishes "productive" motion (quick, subtle, for everyday UI) from "expressive" motion (for important moments). Performance matters as much as style: many sites have improved their interaction responsiveness by replacing JavaScript scroll handlers and `top`/`left` animations with transforms, opacity and, more recently, scroll-driven animations.

## Common mistakes

- **`transition: all`,** animating unintended properties.
- **Putting the transition only on `:hover`,** so it animates in but snaps back.
- **Animating layout properties** (`width`, `height`, `top`, `left`, `margin`) instead of transforms.
- **Durations that are too long** (500ms+) for everyday UI.
- **Trying to transition `height: auto` or `display`** without the grid trick, `@starting-style` or `allow-discrete`.
- **Entrance animations that jump back** because of the default `fill-mode: none`.
- **Overusing `will-change`.**
- **Ignoring `prefers-reduced-motion`,** or auto-playing motion without pause controls.
- **Relying on `transitionend`** that never fires when the transition is interrupted.

## Security lens

<Callout type="security">
Motion can be used to mislead users, and animation timing can interact with security-sensitive actions.
</Callout>

- **Moving targets:** a button that moves or appears with a delay just as the user clicks can redirect the click to a different action (a pattern abused in clickjacking and in dark patterns that trick users into subscriptions). Keep confirm/cancel buttons stable, and ignore clicks on elements that became visible only milliseconds earlier for sensitive actions.
- **Hidden content during animations:** content with `opacity: 0` or translated off-screen is still in the page and focusable. Make sure hidden menus and dialogs are truly hidden (`display: none`, `hidden`, or `inert`) when closed, so keyboard users can't tab into invisible controls.
- **Timing-based UI deception:** countdown animations and fake "only 2 left!" pulses are manipulative patterns that consumer-protection regulators increasingly treat as deceptive.
- **Seizure safety:** rapidly flashing animations (more than three flashes per second) can trigger seizures; there have been real attacks that posted flashing images to epilepsy support communities. Never allow user-generated content to auto-play flashing animations.

## Interview questions

<QA q="What is the difference between a CSS transition and a CSS animation?">
A transition animates a property between its old and new value when that value changes, for example on hover or when a class is added, so it needs a trigger and has only a start and an end. An animation uses keyframes to define any number of intermediate steps and runs by itself, with control over iteration count, direction, fill mode and play state.
</QA>

<QA q="Why should you animate transform and opacity instead of top, left, width or height?">
Changes to transform and opacity can usually be handled by the compositor on the GPU without recalculating layout or repainting, so they stay smooth. Changing geometric properties like top, left, width, height or margin forces layout and paint on every frame, which can affect large parts of the page and cause dropped frames, especially on slower devices.
</QA>

<QA q="What does animation-fill-mode do?">
It controls which styles apply outside the animation's active period. None, the default, uses the element's own styles before and after. Forwards keeps the final keyframe's values after the animation ends, backwards applies the first keyframe during the delay, and both does both.
</QA>

<QA q="How do you animate an element appearing from display none?">
Use the starting-style at-rule to define the initial values the element should transition from when it is first displayed, and set transition-behavior to allow-discrete for the display property, and for overlay with dialogs and popovers, so the element stays rendered until the exit transition finishes. Older approaches toggled classes with JavaScript timers.
</QA>

<QA q="How do you make animations accessible?">
Respect the prefers-reduced-motion media query by removing or reducing large movements, parallax and auto-playing animations, keep durations short and motion purposeful, avoid flashing more than three times per second, provide controls to pause anything that moves for more than five seconds, and make sure content hidden by animation is also hidden from keyboard and screen-reader users.
</QA>

## Key terms

<Terms>
  <Term name="Transition">Interpolation of a property between two values over time.</Term>
  <Term name="Animation">Keyframe-based motion that runs by itself.</Term>
  <Term name="@keyframes">Named set of animation steps.</Term>
  <Term name="Timing function">Curve mapping time progress to value progress.</Term>
  <Term name="cubic-bezier()">Custom easing curve defined by two control points.</Term>
  <Term name="steps()">Easing that jumps in discrete steps.</Term>
  <Term name="Transform">Visual move, scale or rotation without affecting layout.</Term>
  <Term name="Compositing">GPU combining layers without layout or paint.</Term>
  <Term name="Fill mode">Styles applied before and after an animation runs.</Term>
  <Term name="@starting-style">Initial values for entry transitions.</Term>
  <Term name="Web Animations API">JavaScript API for creating and controlling animations.</Term>
  <Term name="prefers-reduced-motion">User preference to minimise motion.</Term>
