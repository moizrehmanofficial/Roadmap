<BigIdea>
<Tr>
<En>
**CSS Grid** is a **two-dimensional** layout system: you define **columns and rows** on a container and place items into the cells. `display: grid` plus **`grid-template-columns: 200px 1fr 1fr`** makes three columns: one fixed and two sharing the rest (**`fr`** = a fraction of free space). **`repeat(3, 1fr)`** repeats tracks, **`minmax(200px, 1fr)`** sets a min and max, and **`repeat(auto-fit, minmax(200px, 1fr))`** builds a responsive gallery that adds and removes columns by itself, **with no media queries**. **`gap`** spaces tracks. Items can span cells (`grid-column: 1 / 3`, `span 2`), and **`grid-template-areas`** lets you draw a page with names. Use Grid for page layouts, galleries, dashboards and forms; Flexbox for single rows or columns of content-sized items.
</En>
<Ur>
**CSS Grid** **do-simti** layout nizaam hai: aap container par **columns aur rows** tay karte hain aur items khanon me rakhte hain. `display: grid` aur **`grid-template-columns: 200px 1fr 1fr`** teen columns banata hai: ek muqarrar aur do baqi jagah baant te hue (**`fr`** = khaali jagah ka hissa). **`repeat(3, 1fr)`** tracks dohrata hai, **`minmax(200px, 1fr)`** kam se kam aur zyada se zyada tay karta hai, aur **`repeat(auto-fit, minmax(200px, 1fr))`** aisi responsive gallery banata hai jo khud columns jorti aur hatati hai, **bina media queries ke**. **`gap`** tracks ke beech faasla deta hai. Items kai khanon par phail sakte hain (`grid-column: 1 / 3`, `span 2`), aur **`grid-template-areas`** naamon se page ka naqsha banane deta hai. Page layouts, galleries, dashboards aur forms ke liye Grid; mawad ke size wale items ki ek row ya column ke liye Flexbox.
</Ur>
</Tr>
</BigIdea>

<Why>
<Tr>
<En>

- Grid is the first CSS system designed **for layout**; before it came tables, floats, then Flexbox (one-dimensional, so rows don't align with each other).
- Responsive galleries, card grids, dashboards, magazine and form layouts become a few lines, often with **no media queries**.
- Supported in all browsers since 2017, subgrid since 2023.
- Tailwind's `grid`, `grid-cols-3` and `col-span-2` are Grid.

</En>
<Ur>

- Grid pehla CSS nizaam hai jo **layout ke liye** bana; is se pehle tables, floats, phir Flexbox (ek-simti, isliye rows aapas me seedhi nahi hotin).
- Responsive galleries, card grids, dashboards, magazine aur form layouts chand lines ban jate hain, aksar **bina media queries**.
- 2017 se har browser me, subgrid 2023 se.
- Tailwind ke `grid`, `grid-cols-3` aur `col-span-2` Grid hi hain.

</Ur>
</Tr>

## Picture it

<Tr>
<En>

Grid is like a **spreadsheet** or a **car park with painted lines**. First you paint the lines: how many columns and how wide, how many rows and how tall. Then you park items in the spaces. A small car takes one space; a bus takes two or three in a row (**span**). You can name areas ("VIP area", "loading bay") and tell each vehicle where to go. Flexbox is more like **people in a queue**: they line up one after another, each taking the room they need. Grid draws the structure first; Flexbox lets the content decide.

</En>
<Ur>

Grid **spreadsheet** ya **rangi lakeeron wali parking** jaisa hai. Pehle lakeeren banate hain: kitne columns aur kitne chaure, kitni rows aur kitni oonchi. Phir cheezen khanon me park karte hain. Chhoti gaari ek khana leti hai; bus ek row me do teen (**span**). Hisson ko naam bhi de sakte hain ("VIP area", "loading bay") aur har gaari ko batate hain kahan jaye. Flexbox **qatar me khare logon** jaisa hai: ek ke baad ek, har koi jitni jagah chahiye utni leta hai. Grid pehle dhaancha banata hai; Flexbox mawad ko faisla karne deta hai.

</Ur>
</Tr>

## Learn it step by step

<Walkthrough>

<Step title="Defining columns and rows">

<Tr>
<En>`grid-template-columns` and `grid-template-rows` list each track's size: lengths, percentages, `fr`, `auto` (fit content, then share leftover space), `min-content`, `max-content`, `minmax()`, `fit-content()`. Items fill cells in order (left to right, top to bottom) unless placed. Most grids only define columns; rows are created as needed and are `auto` (as tall as their tallest item). Below, a mixed column template in a 600px container, measured.</En>
<Ur>`grid-template-columns` aur `grid-template-rows` har track ka size list karte hain: lambaiyan, percentages, `fr`, `auto` (mawad jitna, phir bachi jagah baant na), `min-content`, `max-content`, `minmax()`, `fit-content()`. Items tarteeb se khane bharte hain (baayen se daayen, upar se neeche) jab tak rakhe na jayen. Zyada tar grids sirf columns tay karte hain; rows zaroorat par banti hain aur `auto` hoti hain (sab se oonche item jitni). Neeche 600px container me mila jula column template naapa gaya.</Ur>
</Tr>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
templates = ["200px 1fr 1fr", "1fr 2fr 1fr", "25% auto 100px", "repeat(4, 1fr)", "150px 1fr"]
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content("""<!DOCTYPE html><title>t</title><style>body{margin:0; font: 16px sans-serif}
      #g { display: grid; width: 600px; }</style>
      <div id="g"><div>a</div><div>b</div><div>c</div><div>d</div><div>e</div><div>f</div></div>""")
    for t in templates:
        cols = page.eval_on_selector("#g", "(e, t) => { e.style.gridTemplateColumns = t; return getComputedStyle(e).gridTemplateColumns }", t)
        rows = page.eval_on_selector("#g", "e => getComputedStyle(e).gridTemplateRows")
        print(f"{t:18} -> columns {cols:28} rows {rows}")
    browser.close()
PY
```

```text output
200px 1fr 1fr      -> columns 200px 200px 200px            rows 18px 18px
1fr 2fr 1fr        -> columns 150px 300px 150px            rows 18px 18px
25% auto 100px     -> columns 150px 350px 100px            rows 18px 18px
repeat(4, 1fr)     -> columns 150px 150px 150px 150px      rows 18px 18px
150px 1fr          -> columns 150px 450px                  rows 18px 18px 18px
```

<Happened>
<Tr>
<En>`getComputedStyle(...).gridTemplateColumns` returns each column's **actual pixels**, handy for checking a grid. `200px 1fr 1fr`: 400px left after the fixed column, split into two 200s. `1fr 2fr 1fr`: 4 fractions of 150, the middle takes two. `25% auto 100px`: 150 + 100, and `auto` takes the remaining 350. `repeat(4, 1fr)` is four equal columns. Six items in four columns need two rows, in two columns three rows, each sized to one line of text (18px).</En>
<Ur>`getComputedStyle(...).gridTemplateColumns` har column ke **asli pixels** lautata hai, grid check karne ke liye mufeed. `200px 1fr 1fr`: muqarrar column ke baad 400px bache, do 200 me bant gaye. `1fr 2fr 1fr`: 150 ke 4 hisse, beech wala do leta hai. `25% auto 100px`: 150 + 100, aur `auto` baqi 350 leta hai. `repeat(4, 1fr)` chaar barabar columns hain. Chaar columns me chhe items ko do rows, do columns me teen rows chahiyen, har ek text ki ek line (18px) jitni.</Ur>
</Tr>
</Happened>

</Step>

<Step title="The fr unit">

<Tr>
<En>`fr` divides the **free space** left after fixed tracks, content-sized tracks and gaps: `1fr 1fr 1fr` gives equal shares, `2fr 1fr` two-thirds and one-third. Unlike percentages it accounts for gaps automatically, so columns never overflow because of a gap. Trap: `1fr` really means `minmax(auto, 1fr)`, so a column won't shrink below its content's minimum width; a long URL or wide image can make one "equal" column wider. Use **`minmax(0, 1fr)`** for truly equal columns.</En>
<Ur>`fr` muqarrar tracks, mawad ke size wale tracks aur gaps ke baad bachi **khaali jagah** baant ta hai: `1fr 1fr 1fr` barabar hisse, `2fr 1fr` do tihai aur ek tihai. Percentages ke bar khilaf ye gaps ka khud hisaab rakhta hai, isliye gap ki wajah se columns bahar nahi nikalte. Jaal: `1fr` asal me `minmax(auto, 1fr)` hai, isliye column apne mawad ki kam se kam chaurai se chhota nahi hota; lamba URL ya chauri tasveer ek "barabar" column ko chaura kar sakti hai. Sach me barabar columns ke liye **`minmax(0, 1fr)`**.</Ur>
</Tr>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content("""<!DOCTYPE html><title>t</title><style>body{margin:0; font: 16px sans-serif}
      .g { display: grid; width: 600px; gap: 20px; }
      #pct { grid-template-columns: 50% 50%; }
      #fr { grid-template-columns: 1fr 1fr; }
      #trap, #fixed { grid-template-columns: repeat(3, 1fr); }
      #fixed { grid-template-columns: repeat(3, minmax(0, 1fr)); }
      .url { overflow-wrap: normal; }</style>
      <div class="g" id="pct"><div>a</div><div>b</div></div>
      <div class="g" id="fr"><div>a</div><div>b</div></div>
      <div class="g" id="trap"><div class="url">https://mangoshop.example/products/kent-mangoes-5kg</div><div>b</div><div>c</div></div>
      <div class="g" id="fixed"><div class="url">https://mangoshop.example/products/kent-mangoes-5kg</div><div>b</div><div>c</div></div>""")
    for g in ["#pct", "#fr", "#trap", "#fixed"]:
        cols, sw = page.eval_on_selector(g, "e => [getComputedStyle(e).gridTemplateColumns, e.scrollWidth]")
        print(f"{g:7} columns {cols:32} content width {sw}px")
    browser.close()
PY
```

```text output
#pct    columns 300px 300px                      content width 620px
#fr     columns 290px 290px                      content width 600px
#trap   columns 302.391px 128.797px 128.812px    content width 600px
#fixed  columns 186.656px 186.672px 186.672px    content width 600px
```

<Happened>
<Tr>
<En>**`50% 50%`** plus a 20px gap needs 620px: 20px of overflow. **`1fr 1fr`** subtracts the gap first: (600 − 20) / 2 = 290 each, an exact fit. **`repeat(3, 1fr)`** with an unbreakable URL: the first column refuses to be narrower than the URL, giving about 302 / 129 / 129. **`minmax(0, 1fr)`** lets columns go below content size: three truly equal ≈186.7px columns (the URL then overflows its own cell, fixed with `overflow-wrap: anywhere`).</En>
<Ur>**`50% 50%`** aur 20px gap ko 620px chahiye: 20px bahar. **`1fr 1fr`** pehle gap ghatata hai: (600 − 20) / 2 = 290 har ek, bilkul fit. Na tootne wale URL ke saath **`repeat(3, 1fr)`**: pehla column URL se patla hone se inkaar karta hai, taqreeban 302 / 129 / 129. **`minmax(0, 1fr)`** columns ko mawad se chhota hone deta hai: teen sach me barabar ≈186.7px columns (URL phir apne khane se bahar nikalta hai, `overflow-wrap: anywhere` se theek).</Ur>
</Tr>
</Happened>

<Step title="repeat(), minmax() and responsive grids without media queries">

<Tr>
<En>`repeat(count, tracks)` repeats (`repeat(3, 1fr)`); `minmax(min, max)` bounds a track (`minmax(200px, 1fr)`). **`repeat(auto-fill, minmax(200px, 1fr))`** creates **as many columns as fit** (each at least 200px) and stretches them. **`auto-fit`** is the same, but **empty** columns collapse to zero, so a few items stretch across the row. One line gives 1 column on phones, 2–3 on tablets and 4–6 on desktops. Add `min()` against overflow on tiny screens: `minmax(min(200px, 100%), 1fr)`. Below, one gallery at four widths, plus `auto-fill` vs `auto-fit` with two items.</En>
<Ur>`repeat(count, tracks)` dohrata hai (`repeat(3, 1fr)`); `minmax(min, max)` track ki had tay karta hai (`minmax(200px, 1fr)`). **`repeat(auto-fill, minmax(200px, 1fr))`** **jitne fit hon utne columns** (har ek kam se kam 200px) bana kar phailata hai. **`auto-fit`** bhi yahi, magar **khaali** columns sifar ho jate hain, isliye chand items poori row par phail jate hain. Ek line phones par 1, tablets par 2–3 aur desktops par 4–6 columns deti hai. Bohot chhoti screens par bahar nikalne se bachne ko `min()`: `minmax(min(200px, 100%), 1fr)`. Neeche ek gallery chaar chauraiyon par, aur do items ke saath `auto-fill` vs `auto-fit`.</Ur>
</Tr>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>body{margin:0}
.gallery { display: grid; gap: 16px; padding: 16px; grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)); }
.few { display: grid; gap: 16px; width: 1000px; }
#fill { grid-template-columns: repeat(auto-fill, minmax(200px, 1fr)); }
#fit { grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)); }
</style>
<div class="gallery">""" + "<div>card</div>" * 8 + """</div>
<div class="few" id="fill"><div>a</div><div>b</div></div>
<div class="few" id="fit"><div>a</div><div>b</div></div>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    for width in [375, 768, 1024, 1440]:
        page = browser.new_page(viewport={"width": width, "height": 800})
        page.set_content(html)
        cols = page.eval_on_selector(".gallery", "e => getComputedStyle(e).gridTemplateColumns.split(' ')")
        print(f"screen {width:4}px: {len(cols)} columns of {cols[0]}")
        page.close()
    page = browser.new_page(viewport={"width": 1440, "height": 800})
    page.set_content(html)
    for g in ["#fill", "#fit"]:
        widths = page.eval_on_selector_all(g + " > div", "els => els.map(e => Math.round(e.getBoundingClientRect().width))")
        print(f"{g:5} two items in 1000px: item widths {widths}")
    browser.close()
PY
```

```text output
screen  375px: 1 columns of 343px
screen  768px: 3 columns of 234.656px
screen 1024px: 4 columns of 236px
screen 1440px: 6 columns of 221.328px
#fill two items in 1000px: item widths [238, 238]
#fit  two items in 1000px: item widths [492, 492]
```

<Happened>
<Tr>
<En>With **no media queries** the gallery had 1, 3, 4 and 6 columns, each at least 200px with leftover space shared; at 375px the content box is 343px, so one stretched column. **auto-fill** with two items in 1000px still made four columns (a fifth would need 1064px), each 238px, two left empty. **auto-fit** collapsed the empties so the two items share the row (492 each). Rule: `auto-fit` to fill the row, `auto-fill` for consistent column sizes.</En>
<Ur>**Bina media queries** gallery me 1, 3, 4 aur 6 columns aaye, har ek kam se kam 200px aur bachi jagah baanti hui; 375px par content box 343px hai, isliye ek phaila column. 1000px me do items ke saath **auto-fill** ne phir bhi chaar columns banaye (paanchwe ko 1064px chahiye), har ek 238px, do khaali. **auto-fit** ne khaali wale samet diye, isliye do items row baant te hain (har ek 492). Qaida: row bharni ho to `auto-fit`, yaksan column size chahiye to `auto-fill`.</Ur>
</Tr>
</Happened>

</Step>

<Step title="gap">

<Tr>
<En>`gap` (or `row-gap` and `column-gap`, or `gap: 24px 16px` for rows then columns) sets space between tracks, never at the outer edges, so no margin hacks are needed. Old code uses `grid-gap` and `grid-row-gap`; they're aliases. Every example in this lesson uses it.</En>
<Ur>`gap` (ya `row-gap` aur `column-gap`, ya pehle rows phir columns ke liye `gap: 24px 16px`) tracks ke beech jagah deta hai, bahar ke kinaron par kabhi nahi, isliye margin ke jugaad nahi chahiyen. Purana code `grid-gap` aur `grid-row-gap` istemal karta hai; ye doosre naam hain. Is sabaq ki har misaal ise istemal karti hai.</Ur>
</Tr>

</Step>

<Step title="Placing items by line numbers and spans">

<Tr>
<En>`grid-column: 1 / 3` places an item from column line 1 to 3 (two columns); `grid-row: 2 / 4` spans rows 2–3. `grid-column: span 2` spans two columns from wherever it would be placed. `grid-column: 1 / -1` spans **all** columns: very common for full-width headers and banners. Longhands are `grid-column-start`/`-end` and `grid-row-start`/`-end`; `grid-area: row-start / column-start / row-end / column-end` sets all four. Unplaced items fill the remaining cells in order. Below, a 4-column grid with a featured item and a banner, positions read back from the browser.</En>
<Ur>`grid-column: 1 / 3` item ko column line 1 se 3 tak rakhta hai (do columns); `grid-row: 2 / 4` rows 2–3 par phailata hai. `grid-column: span 2` jahan rakha jata wahan se do columns. `grid-column: 1 / -1` **saare** columns par: poori chaurai ke headers aur banners ke liye bohot aam. Lambi shaklen `grid-column-start`/`-end` aur `grid-row-start`/`-end`; `grid-area: row-start / column-start / row-end / column-end` chaaron set karta hai. Na rakhe items baqi khane tarteeb se bharte hain. Neeche featured item aur banner wala 4-column grid, positions browser se wapas parhi gayin.</Ur>
</Tr>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>body{margin:0}
.grid { display: grid; grid-template-columns: repeat(4, 100px); grid-auto-rows: 50px; gap: 10px; }
.feature { grid-column: span 2; grid-row: span 2; }
.banner { grid-column: 1 / -1; }
</style>
<div class="grid">
  <div class="feature" id="feature">feature</div>
  <div id="i1">1</div><div id="i2">2</div><div id="i3">3</div><div id="i4">4</div>
  <div class="banner" id="banner">banner</div>
  <div id="i5">5</div>
</div>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    for id_, x, y, w, h in page.eval_on_selector_all(".grid > div", "els => els.map(e => { const r = e.getBoundingClientRect(); return [e.id, r.x, r.y, r.width, r.height] })"):
        col, row = int(x // 110) + 1, int(y // 60) + 1
        print(f"{id_:8} column {col}, row {row}, size {w:.0f}x{h:.0f}")
    browser.close()
PY
```

```text output
feature  column 1, row 1, size 210x110
i1       column 3, row 1, size 100x50
i2       column 4, row 1, size 100x50
i3       column 3, row 2, size 100x50
i4       column 4, row 2, size 100x50
banner   column 1, row 3, size 430x50
i5       column 1, row 4, size 100x50
```

<Happened>
<Tr>
<En>`.feature` spans 2 × 2: 210 × 110 (two tracks plus a 10px gap each way). Items 1–4 fill the cells to its right. `.banner` with `1 / -1` takes the whole row (4 × 100 + 3 × 10 = 430). <Step title="Named grid areas">

<Step title="The implicit grid and auto-placement">

<Tr>
<En>With more items than cells, or an item placed outside the explicit grid, the browser creates **implicit** tracks sized by `grid-auto-rows`/`grid-auto-columns`; `grid-auto-rows: minmax(150px, auto)` gives rows a minimum while letting them grow. `grid-auto-flow` controls placement: `row` (default), `column`, and `dense` (backfill earlier holes with later small items). `dense` suits image mosaics, but it makes visual order differ from DOM order, so avoid it when order matters (articles, steps, results).</En>
<Ur>Khanon se zyada items hon, ya koi item explicit grid se bahar rakha jaye, to browser **implicit** tracks banata hai jin ka size `grid-auto-rows`/`grid-auto-columns` se; `grid-auto-rows: minmax(150px, auto)` rows ko kam se kam had deta hai magar barhne deta hai. `grid-auto-flow` rakhne ka tareeqa: `row` (default), `column`, aur `dense` (pehle ke khalon ko baad ke chhote items se bharna). `dense` tasveeron ke mosaic ke liye theek, lekin nazar aane wali tarteeb DOM se alag kar deta hai, isliye jahan tarteeb ahem ho (articles, qadam, natije) wahan na lagayen.</Ur>
</Tr>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>body{margin:0}
.g { display: grid; grid-template-columns: repeat(3, 100px); grid-auto-rows: 50px; }
.wide { grid-column: span 2; }
#dense { grid-auto-flow: dense; }
</style>
<div class="g" id="normal"><div>1</div><div>2</div><div class="wide">3 (wide)</div><div>4</div><div>5</div></div>
<div class="g" id="dense"><div>1</div><div>2</div><div class="wide">3 (wide)</div><div>4</div><div>5</div></div>"""

        print(f"{g:7}", " ".join(cells))
    browser.close()
PY
```

<Step title="Alignment in Grid">

<Tr>
<En>Two levels. **Items in their cells:** `justify-items` (horizontal) and `align-items` (vertical) on the container, or `justify-self`/`align-self` on one item: `stretch` (default), `start`, `end`, `center`; `place-items` sets both. **The whole grid in the container** (when tracks don't fill it): `justify-content` and `align-content` (`start`, `center`, `space-between`…); `place-content` sets both. In Grid, `justify-*` is always the inline axis and `align-*` the block axis; there's no direction switch like Flexbox. The shortest centring: `display: grid; place-items: center;`.</En>
<Ur>Do darje. **Khanon me items:** container par `justify-items` (aafqi) aur `align-items` (amoodi), ya ek item par `justify-self`/`align-self`: `stretch` (default), `start`, `end`, `center`; `place-items` dono set karta hai. **Container me poora grid** (jab tracks use na bharen): `justify-content` aur `align-content` (`start`, `center`, `space-between`…); `place-content` dono. Grid me `justify-*` hamesha inline axis aur `align-*` block axis hai; Flexbox jaisa simt ka badlao nahi. Beech me karne ka sab se chhota tareeqa: `display: grid; place-items: center;`.</Ur>
</Tr>

<Step title="Subgrid">

<Tr>
<En>`grid-template-rows: subgrid` (or columns) makes a nested grid reuse its **parent's tracks**. Cards in a row often hold a title, text and button; without subgrid each card sizes its parts alone, so titles of different lengths push the text to different heights. With subgrid the parts align **across** cards. Useful for card rows and form rows; supported in all major browsers since late 2023. Below, each card spans three parent rows and uses them as its own.</En>
<Ur>`grid-template-rows: subgrid` (ya columns) nested grid ko **parent ke tracks** dobara istemal karne deta hai. Row me cards aksar title, text aur button rakhte hain; subgrid ke baghair har card apne hisse akele naapta hai, isliye alag lambai ke titles text ko alag oonchaiyon par dhakelte hain. Subgrid ke saath hisse cards ke **aar paar** seedhe aate hain. Card rows aur form rows ke liye mufeed; 2023 ke aakhir se har bare browser me. Neeche har card parent ki teen rows par phail kar unhen apni banata hai.</Ur>
</Tr>

## Common mistakes

<Compare>
<Bad title="Percentages, gaps and growing columns">

```text
.grid { display: grid; gap: 20px; grid-template-columns: 50% 50%; }   /* overflows by 20px */
.cards { grid-template-columns: repeat(3, 1fr); }                     /* a long URL widens one column */
.banner { grid-column: 1 / 4; }                                      /* breaks when columns change */
```

</Bad>
<Good title="fr, minmax(0, 1fr) and -1">

```text
.grid { display: grid; gap: 20px; grid-template-columns: 1fr 1fr; }
.cards { grid-template-columns: repeat(3, minmax(0, 1fr)); }
.banner { grid-column: 1 / -1; }
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Flexbox for two-dimensional layouts**, fighting misaligned rows.
- **Confusing `auto-fill` and `auto-fit`.**
- **Grid properties on the wrong element:** `grid-template-*` on the container, `grid-column`/`grid-area` on items; only direct children are grid items.
- **Area names that aren't rectangles**, invalidating the whole `grid-template-areas`.
- **Reordering with areas or `dense`** so screen-reader and Tab order differ from what users see.
- **Fixed row heights for text**; use `auto` or `minmax(100px, auto)`.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Do-simti layouts ke liye Flexbox**, aur na seedhi rows se larai.
- **`auto-fill` aur `auto-fit` me ulajhna.**
- **Grid properties ghalat element par:** `grid-template-*` container par, `grid-column`/`grid-area` items par; sirf seedhe bachche grid items hain.
- **Mustateel na banane wale area naam**, jo poora `grid-template-areas` ghalat kar dete hain.
- **Areas ya `dense` se tarteeb badalna** taa ke screen-reader aur Tab ki tarteeb nazar aane wali se alag ho.
- **Text ke liye muqarrar row oonchai**; `auto` ya `minmax(100px, auto)` lein.

</Ur>
</Tr>

<DeepDive title="Real world: from 12-column frameworks to native Grid">

Before Grid, layout meant the "12-column grid system" in Bootstrap and Foundation: rows of floated or flex columns with classes like `col-md-4`, plus nested rows for anything complex. Each row was independent, so items in different rows only aligned if every row used the same numbers. With CSS Grid the browser provides the grid itself: a 12-column layout is one line (`grid-template-columns: repeat(12, minmax(0, 1fr))`) and items choose spans. Analytics dashboards and admin panels use named areas so rearranging widgets for mobile is CSS-only. Firefox DevTools, whose team helped specify Grid, draws lines, numbers and area names over the page; Chrome shows the same via the "grid" badges in the Elements panel.

</DeepDive>

<DeepDive title="Security lens">

Grid separates visual position from document order: good for design, but care is needed where information matters.

- **Reading order:** screen readers, keyboards, search engines, copy-paste and automated checks follow the DOM. Keep prices, fees, legal terms and warnings in a logical DOM order even if the layout differs.
- **Overlapping layers:** placing items in one cell is legitimate, but also a way to cover content. If users can supply HTML or CSS, sanitise it so they can't overlay fake buttons or hide warnings.
- **Invisible cells:** collapsed tracks (`auto-fit`, zero-sized rows) can hide elements visually while they stay in the page; never rely on layout to hide sensitive data.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="When would you choose CSS Grid over Flexbox?">
Grid is for two-dimensional layouts where items must align in rows and columns at the same time, or where you define the structure before the content, such as page layouts, galleries, dashboards and form grids. Flexbox is for one-dimensional rows or columns where item sizes come from content, such as navbars and toolbars. They are often combined.
</QA>

<QA q="What is the fr unit?">
It represents a fraction of the free space in the grid container after fixed and content-sized tracks and gaps are subtracted. For example, one fr and two fr gives one third and two thirds of the remaining space. A one fr track has an automatic minimum of its content size, so minmax zero one fr is used for strictly equal columns.
</QA>

<QA q="What is the difference between auto-fill and auto-fit?">
Both create as many tracks as fit in the container when used with repeat and minmax. Auto-fill keeps the empty tracks, so a few items keep the column size and leave empty columns. Auto-fit collapses empty tracks to zero, so the existing items stretch to fill the row.
</QA>

<QA q="How do you make a responsive grid without media queries?">
Use grid-template-columns with repeat auto-fit or auto-fill and minmax, for example a minimum of 200 pixels and a maximum of one fr. The browser creates as many columns as fit at the minimum size and stretches them to fill the row, so the column count changes with the container width. Wrapping the minimum in min with 100 percent avoids overflow on very narrow screens.
</QA>

<QA q="What are grid-template-areas and implicit tracks?">
Grid-template-areas defines named rectangular areas with strings that visually describe the layout, and items are placed with grid-area set to a name. Implicit tracks are rows or columns the browser creates automatically when items are placed outside the explicitly defined grid or there are more items than cells; their size is controlled with grid-auto-rows and grid-auto-columns.
</QA>

</DeepDive>
