<Callout type="tip" title="In one minute">
**CSS Grid** is a **two-dimensional** layout system: you define **columns and rows** on a container, and place items into the resulting cells. `display: grid` plus **`grid-template-columns: 200px 1fr 1fr`** creates three columns: a fixed one and two that share the remaining space equally (**`fr`** = a fraction of free space). **`repeat(3, 1fr)`** repeats tracks, **`minmax(200px, 1fr)`** sets a minimum and maximum, and **`repeat(auto-fit, minmax(200px, 1fr))`** creates a responsive gallery that adds or removes columns by itself, **with no media queries**. **`gap`** spaces tracks. Items can span cells (`grid-column: 1 / 3` or `span 2`), and **`grid-template-areas`** lets you draw a page layout with names ("header header", "sidebar main"). Use Grid for page layouts, galleries, dashboards and forms; use Flexbox for single rows or columns of content-sized items.
</Callout>

## Start from zero

<Callout type="analogy">
Grid is like a **spreadsheet** or a **car park with painted lines**. First you paint the lines: how many columns, how wide; how many rows, how tall. Then you park items into the spaces. A small car takes one space; a bus can take two or three spaces in a row (**span**). You can also give areas names ("VIP area", "loading bay") and tell each vehicle which area to use. Flexbox is more like **people standing in a queue**: they line up one after another, each taking as much room as they need. Grid draws the structure first; Flexbox lets the content decide.
</Callout>

### Words you need first

| Word | Simple meaning | Example |
| --- | --- | --- |
| **Grid container** | Element with `display: grid` | `.gallery` |
| **Grid item** | Direct child of a grid container | each photo |
| **Track** | A column or a row | the second column |
| **Grid line** | The dividing lines, numbered from 1 | line 1 is the left edge |
| **Cell** | One column × one row intersection | |
| **Area** | A rectangle of one or more cells | "header" spanning 3 columns |
| **fr** | Fraction of the free space | `1fr 2fr` |
| **Explicit grid** | Tracks you define with `grid-template-*` | |
| **Implicit grid** | Tracks the browser adds for extra items | `grid-auto-rows` |
| **gap** | Space between tracks | `gap: 16px` |

## What is it?

A three-column grid with six items:

```css
.grid {
  display: grid;
  grid-template-columns: 200px 1fr 1fr; /* three columns */
  grid-template-rows: auto auto;        /* two rows, sized by content */
  gap: 16px;
}
```

The lines, tracks and cells:

```text
line: 1        2              3              4
      │ 200px  │     1fr      │     1fr      │
      ├────────┼──────────────┼──────────────┤ ← row line 1
      │ item 1 │   item 2     │   item 3     │   row 1
      ├────────┼──────────────┼──────────────┤ ← row line 2
      │ item 4 │   item 5     │   item 6     │   row 2
      ├────────┴──────────────┴──────────────┤ ← row line 3
(gaps of 16px between all tracks)
```

Three columns means **four** column lines, numbered 1 to 4 from the start, and also **−1 to −4** from the end (−1 is always the last line).

## Why does it matter?

- Grid is the first CSS system designed **for layout**. Before it, page layouts were built with tables, floats, then Flexbox (which is one-dimensional, so rows don't align across each other).
- Responsive galleries, card grids, dashboards, magazine layouts and form layouts become a few lines, often with **no media queries**.
- It's fully supported in all browsers since 2017, and subgrid since 2023.
- Tailwind's `grid`, `grid-cols-3`, `col-span-2` and similar utilities are Grid.

## When and where do you use it?

- **Grid:** the page's overall structure, galleries and card lists with aligned columns, dashboards, form layouts with aligned labels, anything where items must line up in **both** directions or where you design the structure before the content.
- **Flexbox:** a row of buttons, a navbar, items whose size comes from their content, one-direction stacks.
- Mixing is normal: a grid page whose header uses flex.

## Concepts one by one

### 1. Defining columns and rows

<Explain>
<What>
`grid-template-columns` and `grid-template-rows` list the size of each track, separated by spaces. Sizes can be lengths (`200px`, `10rem`), percentages, `fr`, `auto` (fit content, then share leftover space), `min-content`, `max-content`, `minmax()` or `fit-content()`.
</What>
<Why>
You decide the structure up front; items fill the cells in order (left to right, top to bottom) unless you place them.
</Why>
<When>
Most grids only define columns; rows are created automatically as needed.
</When>
<Where>
`grid-template-rows` is optional; without it, rows are `auto` (as tall as their tallest item).
</Where>
<How>
Measuring a mixed column template in a 600px container:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
templates = ["200px 1fr 1fr", "1fr 2fr 1fr", "25% auto 100px", "repeat(4, 1fr)", "150px 1fr"]
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content("""<!DOCTYPE html><title>t</title><style>body{margin:0; font: 16px sans-serif}
      #g { display: grid; width: 600px; }</style>
      <div id="g"><div>a</div><div>b</div><div>c</div><div>d</div><div>e</div><div>f</div></div>""")
    for t in templates:
        cols = page.eval_on_selector("#g", "(e, t) => { e.style.gridTemplateColumns = t; return getComputedStyle(e).gridTemplateColumns }", t)
        rows = page.eval_on_selector("#g", "e => getComputedStyle(e).gridTemplateRows")
        print(f"{t:18} -> columns {cols:28} rows {rows}")
    browser.close()
PY
```

```text output
200px 1fr 1fr      -> columns 200px 200px 200px            rows 18px 18px
1fr 2fr 1fr        -> columns 150px 300px 150px            rows 18px 18px
25% auto 100px     -> columns 150px 350px 100px            rows 18px 18px
repeat(4, 1fr)     -> columns 150px 150px 150px 150px      rows 18px 18px
150px 1fr          -> columns 150px 450px                  rows 18px 18px 18px
```

Line by line:

- `getComputedStyle(...).gridTemplateColumns` returns the **actual pixel size** of each column, which is a handy way to check a grid.
- `200px 1fr 1fr`: 400px remain after the fixed column, split into two equal fractions of 200px.
- `1fr 2fr 1fr`: 4 fractions of 600px = 150px each; the middle takes 2 of them.
- `25% auto 100px`: 25% of 600 = 150px, 100px fixed, and `auto` takes the remaining 350px.
- `repeat(4, 1fr)` is shorthand for four equal columns.
- Six items in four columns need two rows; in two columns, three rows. Rows are created automatically and sized to their content (one line of text, 18px).

### 2. The fr unit

<Explain>
<What>
`fr` divides the **free space**: what's left after fixed tracks, content-sized tracks and gaps. `1fr 1fr 1fr` gives equal shares; `2fr 1fr` gives two-thirds and one-third.
</What>
<Why>
Unlike percentages, `fr` automatically accounts for gaps and fixed tracks, so columns never overflow because of a gap.
</Why>
<When>
Flexible columns and rows.
</When>
<Where>
`1fr` actually means `minmax(auto, 1fr)`: a column won't shrink below its content's minimum width. A long URL or a wide image in a `1fr` column can make it wider than the others, like the Flexbox `min-width: auto` trap. Use **`minmax(0, 1fr)`** for truly equal columns.
</Where>
<How>
Percentages vs `fr` with a gap, and the min-content trap:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content("""<!DOCTYPE html><title>t</title><style>body{margin:0; font: 16px sans-serif}
      .g { display: grid; width: 600px; gap: 20px; }
      #pct { grid-template-columns: 50% 50%; }
      #fr { grid-template-columns: 1fr 1fr; }
      #trap, #fixed { grid-template-columns: repeat(3, 1fr); }
      #fixed { grid-template-columns: repeat(3, minmax(0, 1fr)); }
      .url { overflow-wrap: normal; }</style>
      <div class="g" id="pct"><div>a</div><div>b</div></div>
      <div class="g" id="fr"><div>a</div><div>b</div></div>
      <div class="g" id="trap"><div class="url">https://mangoshop.example/products/kent-mangoes-5kg</div><div>b</div><div>c</div></div>
      <div class="g" id="fixed"><div class="url">https://mangoshop.example/products/kent-mangoes-5kg</div><div>b</div><div>c</div></div>""")
    for g in ["#pct", "#fr", "#trap", "#fixed"]:
        cols, sw = page.eval_on_selector(g, "e => [getComputedStyle(e).gridTemplateColumns, e.scrollWidth]")
        print(f"{g:7} columns {cols:32} content width {sw}px")
    browser.close()
PY
```

```text output
#pct    columns 300px 300px                      content width 620px
#fr     columns 290px 290px                      content width 600px
#trap   columns 302.391px 128.797px 128.812px    content width 600px
#fixed  columns 186.656px 186.672px 186.672px    content width 600px
```

Line by line:

- **`50% 50%`** with a 20px gap needs 620px: the grid overflows its 600px container by 20px.
- **`1fr 1fr`** subtracts the gap first: (600 − 20) / 2 = 290px each, fitting exactly.
- **`repeat(3, 1fr)`** with a long unbreakable URL: the first column refuses to be narrower than the URL, so the "equal" columns become about 302 / 129 / 129px.
- **`minmax(0, 1fr)`** allows columns to go below their content size, giving three truly equal columns of (600 − 40) / 3 ≈ 186.7px (the URL then overflows its own cell, which you'd fix with `overflow-wrap: anywhere`).

### 3. repeat(), minmax() and responsive grids without media queries

<Explain>
<What>
- `repeat(count, tracks)`: `repeat(3, 1fr)`, `repeat(2, 100px 1fr)`.
- `minmax(min, max)`: a track at least `min` and at most `max`: `minmax(200px, 1fr)`.
- `repeat(auto-fill, minmax(200px, 1fr))`: create **as many columns as fit** (each at least 200px), then stretch them to fill the row.
- `auto-fit` is the same, except that **empty** columns collapse to zero, so a few items stretch across the whole row instead of leaving empty columns.
</What>
<Why>
This one line makes a gallery or card list with 1 column on phones, 2–3 on tablets and 4–6 on desktops, automatically.
</Why>
<When>
Card grids, product listings, photo galleries, dashboards of tiles.
</When>
<Where>
Combine with `min()` to avoid overflow on very narrow screens: `repeat(auto-fit, minmax(min(200px, 100%), 1fr))`.
</Where>
<How>
The same gallery at four screen widths, plus `auto-fill` vs `auto-fit` with only two items:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>body{margin:0}
.gallery { display: grid; gap: 16px; padding: 16px; grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)); }
.few { display: grid; gap: 16px; width: 1000px; }
#fill { grid-template-columns: repeat(auto-fill, minmax(200px, 1fr)); }
#fit { grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)); }
</style>
<div class="gallery">""" + "<div>card</div>" * 8 + """</div>
<div class="few" id="fill"><div>a</div><div>b</div></div>
<div class="few" id="fit"><div>a</div><div>b</div></div>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    for width in [375, 768, 1024, 1440]:
        page = browser.new_page(viewport={"width": width, "height": 800})
        page.set_content(html)
        cols = page.eval_on_selector(".gallery", "e => getComputedStyle(e).gridTemplateColumns.split(' ')")
        print(f"screen {width:4}px: {len(cols)} columns of {cols[0]}")
        page.close()
    page = browser.new_page(viewport={"width": 1440, "height": 800})
    page.set_content(html)
    for g in ["#fill", "#fit"]:
        widths = page.eval_on_selector_all(g + " > div", "els => els.map(e => Math.round(e.getBoundingClientRect().width))")
        print(f"{g:5} two items in 1000px: item widths {widths}")
    browser.close()
PY
```

```text output
screen  375px: 1 columns of 343px
screen  768px: 3 columns of 234.656px
screen 1024px: 4 columns of 236px
screen 1440px: 6 columns of 221.328px
#fill two items in 1000px: item widths [238, 238]
#fit  two items in 1000px: item widths [492, 492]
```

Line by line:

- The gallery uses **no media queries**, yet it has 1 column on a phone, 3 on a tablet, 4 on a laptop and 6 on a large screen. Each column is at least 200px and the leftover space is shared.
- At 375px: the content box is 343px (375 − 2 × 16px padding), only one 200px column fits, and it stretches to 343px.
- **auto-fill** with two items in 1000px still creates the four columns that fit (4 × 200 + 3 × 16 = 848px; a fifth would need 1064px), stretches them to 238px each, and leaves two of them empty.
- **auto-fit** collapses the empty columns, so the two items stretch to share the row (492px each).
- Rule of thumb: `auto-fit` when items should fill the row; `auto-fill` when you want consistent column sizes even with few items.

### 4. gap

<Explain>
<What>
`gap` (or `row-gap` and `column-gap`, or `gap: 24px 16px` for rows then columns) sets space between tracks, never at the outer edges.
</What>
<Why>
Same as Flexbox: no margin hacks.
</Why>
<When>
Every grid.
</When>
<Where>
You'll see the old names `grid-gap`, `grid-row-gap` in older code; they're aliases.
</Where>
<How>
Already used in every example above.
</How>
</Explain>

### 5. Placing items by line numbers and spans

<Explain>
<What>
- `grid-column: 1 / 3` puts an item from column line 1 to line 3 (two columns wide). `grid-row: 2 / 4` spans rows 2–3.
- `grid-column: span 2` spans two columns starting wherever the item would be auto-placed.
- `grid-column: 1 / -1` spans **all** columns (from the first line to the last). Very common for full-width headers and banners.
- Longhands: `grid-column-start`, `grid-column-end`, `grid-row-start`, `grid-row-end`. `grid-area: row-start / column-start / row-end / column-end` sets all four.
</What>
<Why>
Feature cards that are twice as big, full-width rows in a gallery, a sidebar spanning several rows.
</Why>
<When>
When items need different sizes in the same grid.
</When>
<Where>
Items not explicitly placed fill the remaining cells in order.
</Where>
<How>
A 4-column grid with a big featured item and a full-width banner, positions read back from the browser:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>body{margin:0}
.grid { display: grid; grid-template-columns: repeat(4, 100px); grid-auto-rows: 50px; gap: 10px; }
.feature { grid-column: span 2; grid-row: span 2; }
.banner { grid-column: 1 / -1; }
</style>
<div class="grid">
  <div class="feature" id="feature">feature</div>
  <div id="i1">1</div><div id="i2">2</div><div id="i3">3</div><div id="i4">4</div>
  <div class="banner" id="banner">banner</div>
  <div id="i5">5</div>
</div>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    for id_, x, y, w, h in page.eval_on_selector_all(".grid > div", "els => els.map(e => { const r = e.getBoundingClientRect(); return [e.id, r.x, r.y, r.width, r.height] })"):
        col, row = int(x // 110) + 1, int(y // 60) + 1
        print(f"{id_:8} column {col}, row {row}, size {w:.0f}x{h:.0f}")
    browser.close()
PY
```

```text output
feature  column 1, row 1, size 210x110
i1       column 3, row 1, size 100x50
i2       column 4, row 1, size 100x50
i3       column 3, row 2, size 100x50
i4       column 4, row 2, size 100x50
banner   column 1, row 3, size 430x50
i5       column 1, row 4, size 100x50
```

Line by line:

- `.feature` spans 2 columns and 2 rows: 2 × 100 + 10 gap = 210px wide, 2 × 50 + 10 = 110px tall.
- Items 1–4 fill the remaining cells to its right, in order.
- `.banner` with `1 / -1` takes the whole row: 4 × 100 + 3 × 10 = 430px.
- Item 5 continues on the next row.
- The script works out column and row numbers from each item's position (each column is 110px including the gap, each row 60px).

### 6. Named grid areas

<Explain>
<What>
`grid-template-areas` lets you draw the layout with names, one string per row, one word per column. Items are assigned with `grid-area: name`. A `.` means an empty cell. Each area must be a rectangle.
</What>
<Why>
The CSS reads like a picture of the page, and rearranging the layout for mobile means just redrawing the strings in a media query.
</Why>
<When>
Page layouts (header, sidebar, main, footer), dashboards, complex components.
</When>
<Where>
Rearranging areas changes only the visual position; keep the HTML in a sensible reading order for screen readers and keyboard users.
</Where>
<How>
A classic page layout, then the same HTML on a phone:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>body{margin:0}
.page {
  display: grid; min-height: 100vh; gap: 0;
  grid-template-columns: 220px 1fr;
  grid-template-rows: 60px 1fr 40px;
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
}
header { grid-area: header; } aside { grid-area: sidebar; } main { grid-area: main; } footer { grid-area: footer; }
@media (max-width: 600px) {
  .page { grid-template-columns: 1fr; grid-template-rows: 60px auto 1fr 40px;
          grid-template-areas: "header" "main" "sidebar" "footer"; }
}
</style>
<div class="page"><header>Header</header><aside>Sidebar</aside><main>Main</main><footer>Footer</footer></div>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    for width in [1000, 375]:
        page = browser.new_page(viewport={"width": width, "height": 600})
        page.set_content(html)
        print(f"screen {width}px:")
        for tag, x, y, w, h in page.eval_on_selector_all(".page > *", "els => els.map(e => { const r = e.getBoundingClientRect(); return [e.tagName.toLowerCase(), r.x, r.y, r.width, r.height] })"):
            print(f"  {tag:7} x={x:<4.0f} y={y:<4.0f} {w:.0f}x{h:.0f}")
        page.close()
    browser.close()
PY
```

```text output
screen 1000px:
  header  x=0    y=0    1000x60
  aside   x=0    y=60   220x500
  main    x=220  y=60   780x500
  footer  x=0    y=560  1000x40
screen 375px:
  header  x=0    y=0    375x60
  aside   x=0    y=78   375x482
  main    x=0    y=60   375x18
  footer  x=0    y=560  375x40
```

Line by line:

- On the desktop, the header and footer span both columns, the sidebar is 220px and the main area takes the remaining 780px. The middle row is `1fr`, so it fills the height left over (600 − 60 − 40 = 500px).
- On a phone, the media query redraws the areas as one column with **main above the sidebar**, without touching the HTML. Main is `auto` (its content, one line = 18px) and the sidebar takes the remaining `1fr`.

### 7. The implicit grid and auto-placement

<Explain>
<What>
If there are more items than cells in the explicit grid, or an item is placed outside it, the browser creates **implicit** tracks. Their size is set by `grid-auto-rows` (and `grid-auto-columns`). `grid-auto-flow` controls auto-placement: `row` (default: fill row by row), `column` (fill column by column), and `dense` (backfill earlier holes with later small items).
</What>
<Why>
You usually only define columns; every new row is implicit. `grid-auto-rows: minmax(150px, auto)` gives all rows a minimum height while letting them grow.
</Why>
<When>
`dense` for image mosaics with mixed sizes where order doesn't matter.
</When>
<Where>
`dense` changes visual order vs DOM order, so avoid it when the order is meaningful (articles, steps, results).
</Where>
<How>
Without and with `dense`, where a wide item doesn't fit at the end of a row:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>body{margin:0}
.g { display: grid; grid-template-columns: repeat(3, 100px); grid-auto-rows: 50px; }
.wide { grid-column: span 2; }
#dense { grid-auto-flow: dense; }
</style>
<div class="g" id="normal"><div>1</div><div>2</div><div class="wide">3 (wide)</div><div>4</div><div>5</div></div>
<div class="g" id="dense"><div>1</div><div>2</div><div class="wide">3 (wide)</div><div>4</div><div>5</div></div>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    for g in ["#normal", "#dense"]:
        top = page.eval_on_selector(g, "e => e.getBoundingClientRect().y")
        cells = page.eval_on_selector_all(g + " > div", "(els, top) => els.map(e => { const r = e.getBoundingClientRect(); return `${e.textContent.split(' ')[0]}@r${Math.round((r.y - top) / 50) + 1}c${Math.round(r.x / 100) + 1}` })", top)
        print(f"{g:7}", " ".join(cells))
    browser.close()
PY
```

```text output
#normal 1@r1c1 2@r1c2 3@r2c1 4@r2c3 5@r3c1
#dense  1@r1c1 2@r1c2 3@r2c1 4@r1c3 5@r2c3
```

Line by line:

- **Normal flow:** items 1 and 2 fill row 1. Item 3 needs two columns, but only one is left in row 1, so it moves to row 2, **leaving a hole** at row 1, column 3. Item 4 goes after item 3, and 5 starts row 3.
- **dense:** the browser backfills: item 4 jumps into the hole at row 1, column 3, and item 5 fits next to item 3. Fewer holes, but the visual order (1, 2, 4, 3, 5) no longer matches the HTML.

### 8. Alignment in Grid

<Explain>
<What>
Grid has two levels of alignment:
- **Items inside their cells:** `justify-items` (horizontal) and `align-items` (vertical) on the container, or `justify-self` / `align-self` on one item. Values: `stretch` (default), `start`, `end`, `center`. `place-items: center` sets both.
- **The whole grid inside the container** (when the tracks don't fill it): `justify-content` and `align-content`, with values like `start`, `center`, `space-between`. `place-content` sets both.
</What>
<Why>
Centring content in cells, aligning icons, centring a fixed-width grid.
</Why>
<When>
`place-items: center` is the shortest way to centre one child in a container: `display: grid; place-items: center;`.
</When>
<Where>
In Grid, `justify-*` is always the inline (horizontal in English) axis and `align-*` the block (vertical) axis; there's no direction switch like in Flexbox.
</Where>
<How>
Centring with Grid:
</How>
</Explain>

```html preview h=170 noqa
<style>
  body { margin: 0; font-family: system-ui, sans-serif; }
  .center { display: grid; place-items: center; min-height: 170px; background: #f3f4f6; }
  .badge { padding: 12px 20px; background: #1f2937; color: white; border-radius: 999px; }
</style>
<div class="center"><span class="badge">Centred with two lines of Grid</span></div>
```

### 9. Overlapping items and layering

<Explain>
<What>
Several items can be placed in the **same** cells; they overlap, with later items on top (or controlled with `z-index`).
</What>
<Why>
Text over images (hero banners, cards with captions) without `position: absolute`, so the container still sizes to its content.
</Why>
<When>
Hero sections, image captions, badges on cards.
</When>
<Where>
Make sure text over images has enough contrast (a dark overlay or gradient).
</Where>
<How>
A hero with text over a picture:
</How>
</Explain>

```html preview h=230 noqa
<style>
  body { margin: 0; font-family: system-ui, sans-serif; }
  .hero { display: grid; max-width: 520px; }
```

### 10. Subgrid

<Explain>
<What>
`grid-template-rows: subgrid` (or columns) makes a nested grid use its **parent's tracks** instead of defining its own.
</What>
<Why>
Cards in a row often contain a title, text and a button. Without subgrid, each card's parts are sized independently, so titles of different lengths push the text in different cards to different heights. With subgrid, the parts align **across** cards.
</Why>
<When>
Card rows, form rows with aligned labels, any nested content that must line up with siblings.
</When>
<Where>
Supported in all major browsers since late 2023.
</Where>
<How>
Each card spans three rows of the parent and uses them as its own:
</How>
</Explain>

```bash
python3 - <<'PY'

html = """<!DOCTYPE html><title>t</title><style>body{margin:0; font: 16px/20px sans-serif}

#sub .card { grid-template-rows: subgrid; }
.card h3, .card p { margin: 0; }
</style>
<div class="cards" id="plain">
  <div class="card"><h3>Kent</h3><p>Sweet.</p><button type="button">Add</button></div>

  <div class="card"><h3>Ataulfo</h3><p>Creamy and small with a golden skin.</p><button type="button">Add</button></div>
```

## Real-world example

Before Grid, the dominant layout tool was the "12-column grid system" in frameworks like Bootstrap and Foundation: rows of floated or flex columns with classes like `col-md-4`, plus nested rows for anything complex. Each row was independent, so items in different rows didn't align unless every row used the same numbers. With CSS Grid, the browser itself provides the grid: a 12-column layout is one line (`grid-template-columns: repeat(12, minmax(0, 1fr))`) and items choose spans. Dashboards such as analytics tools and admin panels use named areas so that rearranging widgets for mobile is a CSS-only change. Firefox's DevTools, whose team helped specify Grid, added a grid inspector that draws lines, numbers and area names over the page; Chrome has the same under the "grid" badges in the Elements panel.

## Common mistakes

- **Using Flexbox for two-dimensional layouts** and fighting misaligned rows.
- **Using percentages with `gap`,** causing overflow; use `fr`.
- **`1fr` columns growing because of long content;** use `minmax(0, 1fr)`.
- **Confusing `auto-fill` and `auto-fit`.**
- **Off-by-one line numbers:** 3 columns have 4 lines; use `1 / -1` for full width.
- **Placing grid properties on the wrong element:** `grid-template-*` on the container, `grid-column`/`grid-area` on items. Only direct children are grid items.
- **Area names that don't form rectangles,** which make the whole `grid-template-areas` invalid.
- **Reordering visually with areas or `dense`** so the screen-reader and Tab order no longer match what users see.
- **Fixed row heights for text,** causing overflow; use `auto` or `minmax(100px, auto)`.

## Security lens

<Callout type="security">
Grid makes it easy to separate visual position from document order, which is good for design but needs care when information matters.
</Callout>

- **Reading order:** the DOM order is what screen readers, keyboard users, search engines, copy-paste and many automated checks see. Keep critical information (prices, fees, legal terms, warnings) in a logical DOM order, even if the visual layout differs.
- **Overlapping layers:** placing items in the same cell is a legitimate design technique but also a way to cover content. If users can supply HTML or CSS (profiles, CMS content), sanitise it so they can't overlay fake buttons or hide warnings.
- **Content in invisible cells:** collapsing tracks (`auto-fit`, zero-sized rows) can hide elements visually while they remain in the page. Don't rely on layout to hide anything sensitive.

## Interview questions

<QA q="When would you choose CSS Grid over Flexbox?">
Grid is for two-dimensional layouts where items must align in rows and columns at the same time, or where you define the structure before the content, such as page layouts, galleries, dashboards and form grids. Flexbox is for one-dimensional rows or columns where item sizes come from content, such as navbars and toolbars. They are often combined.
</QA>

<QA q="What is the fr unit?">
It represents a fraction of the free space in the grid container after fixed and content-sized tracks and gaps are subtracted. For example, one fr and two fr gives one third and two thirds of the remaining space. A one fr track has an automatic minimum of its content size, so minmax zero one fr is used for strictly equal columns.
</QA>

<QA q="What is the difference between auto-fill and auto-fit?">
Both create as many tracks as fit in the container when used with repeat and minmax. Auto-fill keeps the empty tracks, so a few items keep the column size and leave empty columns. Auto-fit collapses empty tracks to zero, so the existing items stretch to fill the row.
</QA>

<QA q="How do you make a responsive grid without media queries?">
Use grid-template-columns with repeat auto-fit or auto-fill and minmax, for example a minimum of 200 pixels and a maximum of one fr. The browser creates as many columns as fit at the minimum size and stretches them to fill the row, so the column count changes with the container width. Wrapping the minimum in min with 100 percent avoids overflow on very narrow screens.
</QA>

<QA q="What are grid-template-areas and implicit tracks?">
Grid-template-areas defines named rectangular areas with strings that visually describe the layout, and items are placed with grid-area set to a name. Implicit tracks are rows or columns the browser creates automatically when items are placed outside the explicitly defined grid or there are more items than cells; their size is controlled with grid-auto-rows and grid-auto-columns.
</QA>

## Key terms

<Terms>
  <Term name="CSS Grid">Two-dimensional layout system of rows and columns.</Term>
  <Term name="Grid container">Element with display grid.</Term>
  <Term name="Track">A single row or column of the grid.</Term>
  <Term name="Grid line">Numbered boundary between tracks.</Term>
  <Term name="Grid area">Rectangle of one or more cells, optionally named.</Term>
  <Term name="fr unit">Fraction of the free space in the grid.</Term>
  <Term name="minmax()">Track size with a minimum and a maximum.</Term>
  <Term name="auto-fit">Creates fitting tracks and collapses empty ones.</Term>
  <Term name="auto-fill">Creates fitting tracks and keeps empty ones.</Term>
  <Term name="Implicit grid">Tracks created automatically beyond the template.</Term>
  <Term name="Dense packing">Auto-placement that backfills holes.</Term>
  <Term name="Subgrid">Nested grid that reuses its parent's tracks.</Term>
</Terms>
