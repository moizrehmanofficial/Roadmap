<Callout type="tip" title="In one minute">
**Flexbox** is a CSS layout mode for arranging items **in one direction**: a row or a column. Put `display: flex` on a **container** and its direct children become **flex items** laid out along the **main axis** (horizontal for `flex-direction: row`, the default). **`justify-content`** distributes items along the main axis (start, center, space-between…), **`align-items`** aligns them on the **cross axis** (stretch, center…), and **`gap`** adds space between them. Items can **grow** to fill free space (`flex-grow`), **shrink** when there isn't enough (`flex-shrink`), and start from a base size (`flex-basis`); the shorthand **`flex: 1`** means "share the free space equally". **`flex-wrap: wrap`** lets items move onto new lines. Flexbox is perfect for navbars, toolbars, centring, card internals and lists of tags; for two-dimensional page layouts (rows **and** columns), use **Grid**.
</Callout>

## Start from zero

<Callout type="analogy">
Imagine **books on a shelf**. The shelf is the **container**; the books are the **items**. You can push all the books to the left, centre them, or spread them out with equal gaps (`justify-content`). Books of different heights can stand on the bottom of the shelf, be centred vertically, or (if they were stretchy) all grow to the shelf's height (`align-items`). If the shelf is too short for all the books, you can squeeze them (`flex-shrink`) or start a second shelf below (`flex-wrap`). If there's extra space, some books can be told to "fatten up" and take it (`flex-grow`). Turn the shelf on its side and it becomes a vertical stack (`flex-direction: column`).
</Callout>

### Words you need first

| Word | Simple meaning | Example |
| --- | --- | --- |
| **Flex container** | Element with `display: flex` | `<nav class="menu">` |
| **Flex item** | Direct child of a flex container | each `<a>` in the nav |
| **Main axis** | Direction items are placed in | horizontal in a row |
| **Cross axis** | Perpendicular direction | vertical in a row |
| **justify-content** | Alignment along the main axis | `space-between` |
| **align-items** | Alignment along the cross axis | `center` |
| **gap** | Space between items | `gap: 16px` |
| **flex-grow** | Share of free space an item takes | `flex-grow: 1` |
| **flex-shrink** | How much an item gives up when space is short | `flex-shrink: 0` |
| **flex-basis** | Starting size before growing/shrinking | `flex-basis: 200px` |
| **Free space** | Container size minus items' base sizes and gaps | |

## What is it?

The smallest useful flex layout:

```css
.toolbar {
  display: flex;            /* children become flex items in a row */
  justify-content: space-between; /* main axis: push to the ends */
  align-items: center;      /* cross axis: vertically centred */
  gap: 12px;                /* space between items */
}
```

```html
<div class="toolbar">
  <strong>Mango Shop</strong>
  <input type="search" aria-label="Search">
  <button type="button">Cart (2)</button>
</div>
```

The axes depend on `flex-direction`:

```text
flex-direction: row (default)           flex-direction: column
main axis  ─────────────────▶           main axis ▼   cross axis ─▶
┌──────────────────────────────┐        ┌─────────────┐
│ [item1] [item2] [item3]      │ cross  │ [item1]     │
│                              │ axis ▼ │ [item2]     │
└──────────────────────────────┘        │ [item3]     │
justify-content = horizontal            └─────────────┘
align-items     = vertical              justify-content = vertical
                                        align-items     = horizontal
```

## Why does it matter?

- Before Flexbox (widely supported from about 2015), developers used **floats**, `inline-block`, tables and negative-margin hacks for layout. Vertical centring was famously hard. Flexbox made these tasks one or two lines.
- It's used in nearly every modern interface: navigation bars, buttons with icons, form rows, card layouts, media objects, footers, chat bubbles.
- Tailwind's `flex`, `justify-between`, `items-center`, `gap-4` and `flex-1` classes are Flexbox; React Native uses Flexbox for all layout.
- Interviews regularly ask how to centre an element and how `flex: 1` works.

## When and where do you use it?

Use Flexbox for **one-dimensional** arrangements: a row of things or a column of things, especially when sizes depend on content. Use **Grid** when you need rows and columns aligned at the same time (page layouts, image galleries with strict columns). They're often combined: a Grid page layout whose cells contain flex components.

## Concepts one by one

### 1. Flex container and items

<Explain>
<What>
`display: flex` makes an element a **block-level** flex container; `display: inline-flex` makes it an inline-level one (it flows in text like an inline-block). Only **direct children** become flex items; grandchildren are laid out normally unless their parent is also a flex container.
</What>
<Why>
Inside a flex container, items: are placed in a row by default, stretch to the same height, keep their content width (instead of each taking the full width like blocks), don't collapse margins, and ignore `float`.
</Why>
<When>
Whenever you want children side by side or stacked with controlled alignment.
</When>
<Where>
Text directly inside a flex container becomes an anonymous flex item.
</Where>
<How>
Before and after `display: flex`:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>
body { margin: 0; width: 600px; font: 16px/1.5 sans-serif; }
.box > div { padding: 8px; border: 1px solid; }
.tall { height: 80px; }
#flex { display: flex; }
</style>
<div class="box" id="block"><div>One</div><div class="tall">Two (tall)</div><div>Three</div></div>
<div class="box" id="flex"><div>One</div><div class="tall">Two (tall)</div><div>Three</div></div>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    for box in ["#block", "#flex"]:
        rows = page.eval_on_selector_all(box + " > div", "els => els.map(e => { const r = e.getBoundingClientRect(); return [e.textContent, Math.round(r.x), Math.round(r.y - e.parentElement.getBoundingClientRect().y), Math.round(r.width), Math.round(r.height)] })")
        print(box)
        for text, x, y, w, h in rows:
            print(f"  {text:11} x={x:<4} y={y:<4} {w}x{h}")
    browser.close()
PY
```

```text output
#block
  One         x=0    y=0    600x42
  Two (tall)  x=0    y=42   600x98
  Three       x=0    y=140  600x42
#flex
  One         x=0    y=0    48x98
  Two (tall)  x=48   y=0    83x98
  Three       x=131  y=0    60x98
```

Line by line:

- Without flex, the three divs are blocks: each is 600px wide and they stack vertically.
- With `display: flex`, they sit in one **row** (x increases, y stays 0).
- Each item is only as wide as its content plus padding and border.
- All items are **98px tall**: the default `align-items: stretch` makes them as tall as the tallest one (80px + 2 × 8px padding + 2 × 1px border).

### 2. flex-direction and flex-wrap

<Explain>
<What>
- `flex-direction`: `row` (default), `row-reverse`, `column`, `column-reverse`. It sets the main axis.
- `flex-wrap`: `nowrap` (default: all items on one line, shrinking if necessary), `wrap` (items move to new lines when they don't fit), `wrap-reverse`.
- `flex-flow: row wrap` is the shorthand for both.
</What>
<Why>
`column` makes vertical stacks (sidebars, forms, card contents); `wrap` makes responsive lists of tags or cards that reflow on small screens.
</Why>
<When>
Use `wrap` whenever items have a minimum readable size and the container might be narrow.
</When>
<Where>
`row-reverse` and `column-reverse` only change the **visual** order. Screen readers and Tab still follow the HTML order, so reversed layouts can confuse keyboard users.
</Where>
<How>
Five 120px tags in a 400px container, with and without wrapping:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>
.tags { display: flex; width: 400px; gap: 10px; }
.tags span { width: 120px; flex-shrink: 1; box-sizing: border-box; border: 1px solid; }
#wrap { flex-wrap: wrap; }
</style>
<div class="tags" id="nowrap"><span>a</span><span>b</span><span>c</span><span>d</span><span>e</span></div>
<div class="tags" id="wrap"><span>a</span><span>b</span><span>c</span><span>d</span><span>e</span></div>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    for box in ["#nowrap", "#wrap"]:
        items = page.eval_on_selector_all(box + " span", "els => els.map(e => { const r = e.getBoundingClientRect(); return `${e.textContent}:${Math.round(r.width)}px@line${Math.round((r.y - e.parentElement.getBoundingClientRect().y) / 10)}` })")
        print(f"{box:8}", " ".join(items))
    browser.close()
PY
```

```text output
#nowrap  a:72px@line0 b:72px@line0 c:72px@line0 d:72px@line0 e:72px@line0
#wrap    a:120px@line0 b:120px@line0 c:120px@line0 d:120px@line3 e:120px@line3
```

Line by line:

- **nowrap:** five 120px items plus four 10px gaps need 640px, but there are only 400px. All items stay on one line and **shrink** to 72px each ((400 − 40) / 5).
- **wrap:** items keep their 120px; three fit on the first line (3 × 120 + 2 × 10 = 380px), and d and e move to the second line (the script prints the vertical position divided by 10, so `line3` means about 28px down: one line of text plus the 10px row gap).

### 3. justify-content: the main axis

<Explain>
<What>
Distributes free space along the main axis:
| Value | Effect |
| --- | --- |
| `flex-start` / `start` (default) | Items packed at the start |
| `flex-end` / `end` | Packed at the end |
| `center` | Packed in the middle |
| `space-between` | First and last at the edges, equal gaps between |
| `space-around` | Equal space around each item (half-size at the edges) |
| `space-evenly` | Exactly equal gaps everywhere, including edges |
</What>
<Why>
Navbars (logo left, menu right), centred button groups, evenly spaced icons.
</Why>
<When>
Only matters when there's **free space**. If items grow (`flex: 1`) to fill the container, there's nothing to distribute.
</When>
<Where>
`justify-content` has no effect in a row if any item has `flex-grow` that uses up all the space.
</Where>
<How>
Three 60px items in a 400px row, positions measured:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
values = ["flex-start", "center", "flex-end", "space-between", "space-around", "space-evenly"]
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content("""<!DOCTYPE html><title>t</title><style>body{margin:0}
      #row { display: flex; width: 400px; } #row div { width: 60px; height: 20px; }</style>
      <div id="row"><div></div><div></div><div></div></div>""")
    for v in values:
        xs = page.eval_on_selector("#row", """(e, v) => { e.style.justifyContent = v;
            return [...e.children].map(c => Math.round(c.getBoundingClientRect().x)) }""", v)
        print(f"{v:14} item x positions {xs}")
    browser.close()
PY
```

```text output
flex-start     item x positions [0, 60, 120]
center         item x positions [110, 170, 230]
flex-end       item x positions [220, 280, 340]
space-between  item x positions [0, 170, 340]
space-around   item x positions [37, 170, 303]
space-evenly   item x positions [55, 170, 285]
```

Line by line:

- Free space is 400 − 3 × 60 = **220px**.
- `center` puts 110px (half of 220) before the first item.
- `flex-end` puts all 220px before the first item.
- `space-between` puts 110px between each pair and nothing at the edges.
- `space-around` gives each item 220 / 3 ≈ 73px, split ≈ 37px per side, so edges get 37px and the gaps between items about 73px.
- `space-evenly` makes four equal gaps of 55px.

### 4. align-items, align-self and align-content: the cross axis

<Explain>
<What>
- **`align-items`** (on the container) aligns every item within its line on the cross axis: `stretch` (default: fill the line's height, if the item has no fixed height), `flex-start`, `flex-end`, `center`, `baseline` (align text baselines).
- **`align-self`** (on one item) overrides `align-items` for that item.
- **`align-content`** (on the container) distributes **lines** when wrapping creates several lines and there's extra cross-axis space. It accepts the same values as `justify-content`, plus `stretch`.
</What>
<Why>
Vertical centring of icons and text, buttons of equal height, aligning prices on a common text baseline.
</Why>
<When>
`align-items: center` on almost every horizontal toolbar; `baseline` when items have different font sizes.
</When>
<Where>
`align-content` does nothing on a single-line (`nowrap`) container.
</Where>
<How>
Items of different heights in a 100px tall row:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content("""<!DOCTYPE html><title>t</title><style>body{margin:0}
      #row { display: flex; height: 100px; width: 300px; }
      #a { min-height: 20px; } #b { min-height: 40px; } #c { min-height: 60px; }</style>
      <div id="row"><div id="a">a</div><div id="b">b</div><div id="c">c</div></div>""")
    for v in ["stretch", "flex-start", "center", "flex-end"]:
        r = page.eval_on_selector("#row", """(e, v) => { e.style.alignItems = v;
            return [...e.children].map(c => { const b = c.getBoundingClientRect(); return `${c.id}: y=${b.y} h=${b.height}` }) }""", v)
        print(f"{v:11}", " | ".join(r))
    r = page.eval_on_selector("#row", """e => { e.style.alignItems = 'flex-start'; document.querySelector('#c').style.alignSelf = 'flex-end';
        return [...e.children].map(c => `${c.id}: y=${c.getBoundingClientRect().y}`) }""")
    print("align-self:", " | ".join(r))
    browser.close()
PY
```

```text output
stretch     a: y=0 h=100 | b: y=0 h=100 | c: y=0 h=100
flex-start  a: y=0 h=20 | b: y=0 h=40 | c: y=0 h=60
center      a: y=40 h=20 | b: y=30 h=40 | c: y=20 h=60
flex-end    a: y=80 h=20 | b: y=60 h=40 | c: y=40 h=60
align-self: a: y=0 | b: y=0 | c: y=40
```

Line by line:

- `stretch`: all items are as tall as the 100px container (they have only `min-height`, no fixed `height`).
- `flex-start`: each keeps its own height at the top.
- `center`: each is centred: a 20px item starts at (100 − 20) / 2 = 40px.
- `flex-end`: each sits at the bottom.
- With `align-items: flex-start` on the container and `align-self: flex-end` on `#c`, only c moves to the bottom.

### 5. gap

<Explain>
<What>
`gap: 16px` (or `row-gap` and `column-gap` separately, or `gap: 8px 16px` for row then column) puts space **between** items, never at the outer edges.
</What>
<Why>
Before `gap` worked in Flexbox (2021), developers used margins on items and had to remove the margin from the last item, or use negative margins on the container to cancel edge margins with wrapping.
</Why>
<When>
Always prefer `gap` over margins for spacing between flex or grid items.
</When>
<Where>
Supported in all modern browsers.
</Where>
<How>
`gap` counts as used space when calculating free space, as the wrapping example above shows.
</How>
</Explain>

### 6. How items share space: flex-grow, flex-shrink, flex-basis

<Explain>
<What>
For each item, the browser:
1. Takes its **flex-basis** (its starting main size). `auto` (default) means "use `width` (in a row) if set, otherwise the content size".
2. Adds up all bases and gaps and compares with the container size.
3. If there's **positive free space**, it gives each item `free space × (its flex-grow ÷ sum of flex-grow)`. The default `flex-grow` is **0**: items don't grow.
4. If there's **negative free space** (overflow), it shrinks items in proportion to `flex-shrink × flex-basis`. The default `flex-shrink` is **1**: items can shrink, but never below their **minimum content size** (see concept 8).
</What>
<Why>
This is how "the search box takes all remaining space" or "the sidebar stays 250px while the main column flexes" work.
</Why>
<When>
- `flex-grow: 1` on the item that should absorb extra space.
- `flex-shrink: 0` on items that must not shrink (icons, avatars, fixed sidebars).
- `flex-basis` for the ideal size before growing/shrinking.
</When>
<Where>
`flex-basis` takes priority over `width` in the main axis (but is still limited by `min-width`/`max-width`).
</Where>
<How>
Real numbers from the browser:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
cases = {
    "grow 0/0/0 (default)":      ["0 1 100px", "0 1 100px", "0 1 100px"],
    "grow 1/1/1":                ["1 1 100px", "1 1 100px", "1 1 100px"],
    "grow 1/2/1":                ["1 1 100px", "2 1 100px", "1 1 100px"],
    "grow 0/1/0 (search box)":   ["0 1 100px", "1 1 100px", "0 1 100px"],
    "too wide, shrink 1/1/1":    ["0 1 300px", "0 1 300px", "0 1 300px"],
    "too wide, shrink 0/1/1":    ["0 0 300px", "0 1 300px", "0 1 300px"],
}
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content("""<!DOCTYPE html><title>t</title><style>body{margin:0}
      #row { display: flex; width: 600px; } #row div { min-width: 0; }</style>
      <div id="row"><div></div><div></div><div></div></div>""")
    for name, flexes in cases.items():
        widths = page.eval_on_selector("#row", """(e, f) => { [...e.children].forEach((c, i) => c.style.flex = f[i]);
            return [...e.children].map(c => Math.round(c.getBoundingClientRect().width)) }""", flexes)
        print(f"{name:26} {widths}  total {sum(widths)}")
    browser.close()
PY
```

```text output
grow 0/0/0 (default)       [100, 100, 100]  total 300
grow 1/1/1                 [200, 200, 200]  total 600
grow 1/2/1                 [175, 250, 175]  total 600
grow 0/1/0 (search box)    [100, 400, 100]  total 600
too wide, shrink 1/1/1     [200, 200, 200]  total 600
too wide, shrink 0/1/1     [300, 150, 150]  total 600
```

Line by line (container 600px; each case sets `flex: grow shrink basis`):

- **0/0/0:** bases are 100px each, free space is 300px, but nobody grows, so 300px stays empty.
- **1/1/1:** 300px free ÷ 3 = 100px extra each → 200px each.
- **1/2/1:** total grow 4; the middle gets 2/4 of 300 = 150 extra (250px), the others 75 extra (175px).
- **0/1/0:** only the middle grows, taking all 300px extra (a typical search box between a logo and buttons).
- **Shrink 1/1/1:** bases 3 × 300 = 900px, 300px too much; each shrinks by 100px → 200px.
- **Shrink 0/1/1:** the first refuses to shrink (`flex-shrink: 0`), so the other two absorb the 300px deficit, 150px each.

### 7. The flex shorthand

<Explain>
<What>
`flex` sets grow, shrink and basis together. The common values:
| Shorthand | Means | Use for |
| --- | --- | --- |
| `flex: initial` (default) | `0 1 auto` | content-sized, can shrink, won't grow |
| `flex: auto` | `1 1 auto` | grow and shrink, starting from content size |
| `flex: 1` | `1 1 0%` | **equal** shares regardless of content |
| `flex: none` | `0 0 auto` | fixed at content size: never grow or shrink |
| `flex: 2` | `2 1 0%` | twice the share of `flex: 1` items |
| `flex: 0 0 250px` | fixed 250px | sidebars, avatars |
</What>
<Why>
`flex: 1` and `flex: auto` look similar but differ: with `flex: 1`, the basis is **0**, so **all** space is shared equally and items end up the same width. With `flex: auto`, each item starts from its content width and only the **leftover** space is shared, so items with more content stay wider.
</Why>
<When>
Equal columns → `flex: 1`. Items that should keep proportion to their content → `flex: auto`. Fixed elements → `flex: none` or `flex: 0 0 <size>`.
</When>
<Where>
Prefer the shorthand over `flex-grow: 1` alone: `flex: 1` also resets the basis, which is usually what you want.
</Where>
<How>
Two items with very different text lengths:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content("""<!DOCTYPE html><title>t</title><style>body{margin:0; font: 16px monospace}
      .row { display: flex; width: 600px; }</style>
      <div class="row" id="r"><div>Short</div><div>A much longer piece of text</div></div>""")
    for value in ["initial", "auto", "1", "none"]:
        print(f"flex: {value:8}", page.eval_on_selector("#r", """(e, v) => { [...e.children].forEach(c => c.style.flex = v);
            return [...e.children].map(c => Math.round(c.getBoundingClientRect().width)) }""", value))
    browser.close()
PY
```

```text output
flex: initial  [48, 260]
flex: auto     [194, 406]
flex: 1        [300, 300]
flex: none     [48, 260]
```

Line by line:

- **initial / none:** each item is its content width (48px for "Short", 260px for the long text); 292px stays empty. With `none`, they also wouldn't shrink if the container were narrow.
- **auto:** each starts from its content width, and the 292px of free space is split equally (146px each): 48 + 146 = 194, 260 + 146 = 406. The longer item stays longer.
- **1:** bases are 0, so all 600px is split equally: 300px each, whatever the content.

### 8. The min-width: auto trap

<Explain>
<What>
Flex items have a default **`min-width: auto`** (in a row), which means they **won't shrink below their minimum content width**: the longest word, a long URL, a wide image, or a `<pre>` code block. So a flex item containing a long unbreakable string overflows its container instead of shrinking.
</What>
<Why>
This is the most common Flexbox bug: "my flex child is wider than the screen" or "`text-overflow: ellipsis` doesn't work in my flex item".
</Why>
<When>
Any flex item containing long text, URLs, tables, code or images that should shrink.
</When>
<Where>
Fix it with **`min-width: 0`** (or `overflow: hidden`) on the item. In columns, the same applies to `min-height`.
</Where>
<How>
A 300px row where the main item contains a long URL:
</How>
</Explain>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>body{margin:0; font: 16px sans-serif}
.row { display: flex; width: 300px; gap: 8px; }
.icon { flex: none; width: 40px; }
.text { flex: 1; white-space: nowrap; overflow: hidden; text-overflow: ellipsis; }
#a .text { overflow: visible; }
#b .text { min-width: auto; }
</style>
<div class="row" id="a"><span class="icon">📦</span><span class="text">https://mangoshop.example/orders/2026/11/track?id=88412</span></div>
<div class="row" id="b"><span class="icon">📦</span><span class="text">https://mangoshop.example/orders/2026/11/track?id=88412</span></div>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    for row, label in [("#a", "overflow visible (min-width auto)"), ("#b", "overflow hidden + ellipsis")]:
        w, scroll = page.eval_on_selector(row, "e => [e.querySelector('.text').getBoundingClientRect().width, e.scrollWidth]")
        print(f"{label:34} text item {round(w)}px, row content {scroll}px of 300px")
    browser.close()
PY
```

```text output
overflow visible (min-width auto)  text item 422px, row content 470px of 300px
overflow hidden + ellipsis         text item 252px, row content 300px of 300px
```

Line by line:

- In row `#a`, the text item keeps `min-width: auto` (because `overflow` is `visible`), so it refuses to shrink below the URL's length: 422px wide, and the row's content is 470px, overflowing the 300px container.
- In row `#b`, `overflow: hidden` makes the automatic minimum size 0 (any `overflow` other than `visible` does that), so the item shrinks to the remaining 252px (300 − 40 − 8) and the ellipsis appears. Writing `min-width: 0` explicitly has the same effect and is the usual fix.

### 9. order and auto margins

<Explain>
<What>
- **`order`** (default 0) changes the visual order of items: lower numbers come first.
- **Auto margins** in a flex container absorb all free space in that direction. `margin-left: auto` on the last item of a navbar pushes it to the far right; `margin-top: auto` on a card's button pushes it to the bottom; `margin: auto` on a single item centres it in both directions.
</What>
<Why>
Auto margins solve "everything left, except one thing right" without extra wrappers.
</Why>
<When>
Navbars, card footers, toolbars.
</When>
<Where>
Like the reverse directions, `order` changes only what you see, not the reading or Tab order. Only use it when the visual order still makes sense in the HTML order.
</Where>
<How>
Logo and links on the left, account button pushed right:
</How>
</Explain>

```bash
python3 - <<'PY'

html = """<!DOCTYPE html><title>t</title><style>body{margin:0}
nav { display: flex; width: 600px; gap: 10px; }

.account { margin-left: auto; }
</style>
<nav><span id="logo">Logo</span><a id="shop" href="#">Shop</a><a id="offers" href="#">Offers</a><a class="account" id="account" href="#">Account</a></nav>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    print(page.eval_on_selector_all("nav > *", "els => els.map(e => `${e.id}@${e.getBoundingClientRect().x}`)"))

```


Line by line:

- Logo, Shop and Offers are packed at the start with 10px gaps.
- The auto left margin on Account takes all the free space, placing it at 540 (600 − 60): the right edge.

## Real-world example

Before Flexbox, the "holy grail" layout (header, footer, three columns of equal height with the footer at the bottom of the screen even with little content) was a famous CSS puzzle requiring floats, negative margins and faux-column background images. Bootstrap's grid used floats until version 4 (2018), which switched it to Flexbox, and Bootstrap 5 adds CSS Grid utilities too. Today, component libraries (Material UI's `Stack`, Chakra's `Flex`, Tailwind's `flex` utilities) are thin wrappers over the properties in this lesson, and React Native implements Flexbox (via the Yoga layout engine) as the only layout system for iOS and Android apps, with `flexDirection: 'column'` as its default.

## Common mistakes

- **Applying flex properties to the wrong element:** `justify-content` and `align-items` go on the **container**; `flex`, `align-self` and `order` go on **items**.
- **Forgetting which axis is which** after switching to `flex-direction: column` (now `justify-content` is vertical).
- **Long content overflowing flex items:** add `min-width: 0` to the item.
- **Using `flex: 1` when you meant `flex: auto`** (or the reverse), and getting equal widths you didn't expect.
- **Expecting `justify-content` to work when items fill the space** via `flex-grow`.
- **Using margins instead of `gap`,** then fighting edge spacing.
- **Trying to build two-dimensional grids with Flexbox,** leaving a last row with stretched or misaligned items. Use Grid.
- **Changing visual order** with `order` or `row-reverse` so it no longer matches the HTML and Tab order.
- **No `flex-wrap`,** so items squash or overflow on mobile.

## Security lens

<Callout type="security">
Layout itself isn't a security feature, but it affects what users see first and what they can trust.
</Callout>

- **Visual vs DOM order:** `order` and `*-reverse` can show content in a different order than screen readers and copy-paste see. Don't use them to reorder important information such as prices, terms or warnings, and never rely on visual order for anything a user must read before confirming.
- **Overflow hides content:** `min-width: 0` plus `overflow: hidden` and ellipsis is great for layout, but in security-sensitive UI (sender addresses, domains, account numbers, payment recipients) make sure the full value is available (tooltip, wrap, or a details view), so phishing look-alikes aren't hidden by truncation.
- **Spoofed UI:** injected CSS can use flex `order` and auto margins to move a fake "Confirm" button where the real one was. Keep user-supplied styles out of your pages.

## Interview questions

<QA q="What is the difference between the main axis and the cross axis in Flexbox?">
The main axis is the direction items are laid out, set by flex-direction: horizontal for row and vertical for column. The cross axis is perpendicular to it. Justify-content aligns items along the main axis, while align-items, align-self and align-content work on the cross axis.
</QA>

<QA q="What does flex: 1 mean, and how is it different from flex: auto?">
Flex 1 is shorthand for flex-grow 1, flex-shrink 1 and flex-basis 0 percent, so items start from zero and share all the space in proportion to their grow factors, giving equal widths regardless of content. Flex auto is grow 1, shrink 1 and basis auto, so items start from their content size and only the remaining free space is shared, leaving larger content larger.
</QA>

<QA q="How are flex-grow and flex-shrink calculated?">
The browser computes free space as the container's main size minus the items' flex-basis sizes and gaps. Positive free space is distributed in proportion to each item's flex-grow value. Negative free space is removed in proportion to flex-shrink multiplied by the flex-basis, without shrinking items below their minimum size.
</QA>

<QA q="Why does a flex item with long text overflow its container, and how do you fix it?">
Flex items default to min-width auto, which prevents them from shrinking below their minimum content size, such as a long word or URL. Setting min-width 0 on the item, or an overflow value other than visible, allows it to shrink so the text can wrap or be truncated.
</QA>

<QA q="When would you use Flexbox instead of CSS Grid?">
Flexbox suits one-dimensional layouts where items flow in a single row or column and their sizes depend on content, such as navigation bars, toolbars, button groups and card internals. Grid suits two-dimensional layouts where rows and columns must align together, such as page layouts and galleries. They are often combined.
</QA>

## Key terms

<Terms>
  <Term name="Flexbox">One-dimensional CSS layout for rows or columns.</Term>
  <Term name="Flex container">Element with display flex or inline-flex.</Term>
  <Term name="Flex item">Direct child of a flex container.</Term>
  <Term name="Main axis">Direction items are placed, set by flex-direction.</Term>
  <Term name="Cross axis">Axis perpendicular to the main axis.</Term>
  <Term name="justify-content">Distributes items along the main axis.</Term>
  <Term name="align-items">Aligns items on the cross axis.</Term>
  <Term name="gap">Space between flex or grid items.</Term>
  <Term name="flex-grow">Share of positive free space an item takes.</Term>
  <Term name="flex-shrink">How much an item shrinks when space is short.</Term>
  <Term name="flex-basis">Item's starting size before growing or shrinking.</Term>
  <Term name="Free space">Container size minus item bases and gaps.</Term>
</Terms>
