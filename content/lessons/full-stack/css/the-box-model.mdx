<BigIdea>
<Tr>
<En>
In CSS **every element is a rectangle** with four layers from the inside out: **content**, **padding** (space inside the border), **border**, and **margin** (space outside, pushing other boxes away). By default (`content-box`), `width` sets only the **content**, so padding and border are **added**: `width: 200px; padding: 20px; border: 5px` gives a **250px** box. With **`box-sizing: border-box`** the width includes them, so the box is exactly 200px; almost every project sets it globally. **Block** boxes (div, p, h1) fill the width and stack; **inline** boxes (span, a) flow in a line and ignore `width`/`height`. Vertical margins between blocks can **collapse** into one. DevTools' box diagram shows every layer.
</En>
<Ur>
CSS me **har element ek mustateel (dabba)** hai jis ki andar se bahar chaar parten hain: **content**, **padding** (border ke andar ki jagah), **border**, aur **margin** (bahar ki jagah jo doosre dabbon ko door dhakelti hai). Default (`content-box`) me `width` sirf **content** set karta hai, isliye padding aur border **jur jate hain**: `width: 200px; padding: 20px; border: 5px` **250px** ka dabba deta hai. **`box-sizing: border-box`** ke saath width me ye shamil hain, isliye dabba bilkul 200px; taqreeban har project ise sab par lagata hai. **Block** dabbe (div, p, h1) poori chaurai lete aur upar neeche lagte hain; **inline** dabbe (span, a) line me behte aur `width`/`height` nazar andaz karte hain. Blocks ke beech upar neeche ke margins **simat** kar ek ho sakte hain. DevTools ka box diagram har parat dikhata hai.
</Ur>
</Tr>

## Learn it step by step

<Walkthrough>

<Step title="The four layers, measured">

<Tr>
<En>**Content** is sized by `width`/`height` (or its content when `auto`). **Padding** takes the element's **background** and can't be negative. **Border** needs a `border-style`, or nothing is drawn. **Margin** is always **transparent**, can be negative or `auto`. Padding is clickable and coloured, margin isn't; margins collapse, padding doesn't. JavaScript exposes the layers: `offsetWidth` (border box), `clientWidth` (padding box). Below, a real browser measures the same element with both `box-sizing` values.</En>
<Ur>**Content** ka size `width`/`height` se (ya `auto` ho to mawad se). **Padding** element ka **background** leti hai aur manfi nahi ho sakti. **Border** ko `border-style` chahiye, warna kuch nahi banta. **Margin** hamesha **shaffaf** hai, manfi ya `auto` ho sakta hai. Padding clickable aur rangeen hai, margin nahi; margins simat te hain, padding nahi. JavaScript parten dikhati hai: `offsetWidth` (border box), `clientWidth` (padding box). Neeche asli browser ek hi element ko dono `box-sizing` values se naapta hai.</Ur>
</Tr>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>
.box { width: 200px; height: 100px; padding: 20px; border: 5px solid black; margin: 30px; }
#b { box-sizing: border-box; }
</style>
<div class="box" id="a">content-box</div>
<div class="box" id="b">border-box</div>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    for el in ["#a", "#b"]:
        m = page.eval_on_selector(el, """e => {
            const s = getComputedStyle(e);
            return { sizing: s.boxSizing, contentW: e.clientWidth - 2 * parseFloat(s.paddingLeft),
                     paddingBoxW: e.clientWidth, borderBoxW: e.offsetWidth, borderBoxH: e.offsetHeight,
                     marginBoxW: e.offsetWidth + 2 * parseFloat(s.marginLeft) } }""")
        print(m)
    browser.close()
PY
```

```text output
{'sizing': 'content-box', 'contentW': 200, 'paddingBoxW': 240, 'borderBoxW': 250, 'borderBoxH': 150, 'marginBoxW': 310}
{'sizing': 'border-box', 'contentW': 150, 'paddingBoxW': 190, 'borderBoxW': 200, 'borderBoxH': 100, 'marginBoxW': 260}
```

<Happened>
<Tr>
<En>**content-box:** the content is exactly 200px; padding makes 240, the border 250, and with margins it occupies 310. Height grows the same way: 100 + 40 + 10 = **150**. **border-box:** the **visible box** is exactly 200 × 100; the browser shrank the content to 150px (200 − 40 − 10). Margins are outside both models: 30px each side either way.</En>
<Ur>**content-box:** content bilkul 200px hai; padding se 240, border se 250, aur margins samet 310 leta hai. Height bhi waise hi barhti hai: 100 + 40 + 10 = **150**. **border-box:** **nazar aane wala dabba** bilkul 200 × 100 hai; browser ne content 150px tak sukera (200 − 40 − 10). Margins dono models se bahar hain: har taraf 30px dono soorat me.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Why everyone uses border-box">

<Tr>
<En>A short global rule switches every element: `*, *::before, *::after { box-sizing: border-box; }`. With `content-box`, `width: 100%` plus padding or border **overflows** its parent; with `border-box` it always fits, and the size you write is the size you see (designers think this way: a "320px card" includes its padding). Put it at the top of every stylesheet; Tailwind's Preflight, Bootstrap's Reboot and modern-normalize include it. Old widgets expecting `content-box` can be reset locally. Below, the classic 100%-width input bug, measured.</En>
<Ur>Ek chhota sa aam rule har element badal deta hai: `*, *::before, *::after { box-sizing: border-box; }`. `content-box` me `width: 100%` aur padding ya border parent se **bahar** nikal jata hai; `border-box` me hamesha fit, aur jo size likho wahi dikhta hai (designers isi tarah sochte hain: "320px card" me us ki padding shamil). Har stylesheet ke shuru me lagayen; Tailwind ka Preflight, Bootstrap ka Reboot aur modern-normalize me ye shamil hai. `content-box` maangne wale purane widgets ke liye mahdood reset ho sakta hai. Neeche 100% chaurai wale input ka purana bug naapa gaya.</Ur>
</Tr>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>
.form { width: 300px; border: 1px dashed gray; }
input { width: 100%; padding: 10px; border: 2px solid black; display: block; }
.fixed input { box-sizing: border-box; }
</style>
<div class="form" id="broken"><input aria-label="a"></div>
<div class="form fixed" id="ok"><input aria-label="b"></div>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    for el in ["#broken", "#ok"]:
        parent, child = page.eval_on_selector(el, "e => [e.clientWidth, e.querySelector('input').offsetWidth]")
        print(f"{el:8} container {parent}px, input {child}px, overflow {child - parent}px")
    browser.close()
PY
```

```text output
#broken  container 300px, input 324px, overflow 24px
#ok      container 300px, input 300px, overflow 0px
```

<Happened>
<Tr>
<En>The container is 300px inside. With `content-box` the input's content is 100% = 300px, plus 2 × 10px padding and 2 × 2px border = **324px**, sticking out by 24. With `border-box` it's exactly 300px and fits.</En>
<Ur>Container andar se 300px hai. `content-box` me input ka content 100% = 300px, aur 2 × 10px padding aur 2 × 2px border = **324px**, 24 bahar. `border-box` me bilkul 300px aur fit.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Shorthand: one to four values">

<Tr>
<En>

`margin`, `padding`, `border-width`, `border-color`, `border-style` and `inset` take 1–4 values, **clockwise from the top** (remember **TRouBLe**: Top, Right, Bottom, Left). `border` sets width, style and colour of all sides (`border: 1px solid #e5e7eb`), and sides can be set alone (`border-bottom: 2px dashed red`). A shorthand resets every sub-property it covers: `border: 1px solid` after `border-color: red` puts the colour back to `currentColor`.

| Written | Top | Right | Bottom | Left |
| --- | --- | --- | --- | --- |
| `padding: 10px` | 10 | 10 | 10 | 10 |
| `padding: 10px 20px` | 10 | 20 | 10 | 20 |
| `padding: 10px 20px 30px` | 10 | 20 | 30 | 20 |
| `padding: 10px 20px 30px 40px` | 10 | 20 | 30 | 40 |

</En>
<Ur>

`margin`, `padding`, `border-width`, `border-color`, `border-style` aur `inset` 1–4 values lete hain, **upar se ghari ki suiyon ki simt** (yaad rakhein **TRouBLe**: Top, Right, Bottom, Left). `border` saare kinaron ki chaurai, andaz aur rang set karta hai (`border: 1px solid #e5e7eb`), aur kinare alag bhi set ho sakte hain (`border-bottom: 2px dashed red`). Shorthand apni har sub-property reset karta hai: `border-color: red` ke baad `border: 1px solid` rang wapas `currentColor` kar deta hai.

| Likha | Top | Right | Bottom | Left |
| --- | --- | --- | --- | --- |
| `padding: 10px` | 10 | 10 | 10 | 10 |
| `padding: 10px 20px` | 10 | 20 | 10 | 20 |
| `padding: 10px 20px 30px` | 10 | 20 | 30 | 20 |
| `padding: 10px 20px 30px 40px` | 10 | 20 | 30 | 40 |

</Ur>
</Tr>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content("<!DOCTYPE html><title>t</title><div id='d'>x</div>")
    for value in ["10px", "10px 20px", "10px 20px 30px", "10px 20px 30px 40px"]:
        sides = page.eval_on_selector("#d", """(e, v) => { e.style.padding = v; const s = getComputedStyle(e);
            return [s.paddingTop, s.paddingRight, s.paddingBottom, s.paddingLeft].join(' ') }""", value)
        print(f"padding: {value:20} -> top right bottom left = {sides}")
    browser.close()
PY
```

```text output
padding: 10px 20px            -> top right bottom left = 10px 20px 10px 20px
padding: 10px 20px 30px       -> top right bottom left = 10px 20px 30px 20px
padding: 10px 20px 30px 40px  -> top right bottom left = 10px 20px 30px 40px
```

<Happened>
<Tr>
<En>The browser expanded each shorthand: one value for all sides; two for vertical then horizontal; three for top, horizontal, bottom; four clockwise from the top.</En>
<Ur>Browser ne har shorthand phailaya: ek value sab kinaron ke liye; do me pehle upar neeche phir daayen baayen; teen me upar, daayen baayen, neeche; chaar upar se ghari ki simt.</Ur>
</Tr>

<Step title="Block, inline and inline-block boxes">

<Tr>
<En>`display` sets the box's outer behaviour. **block** (`div`, `p`, `h1`, `ul`, `section`) starts a new line, fills the width and respects all sizes and spacing. **inline** (`span`, `a`, `strong`, `code`) flows in the text, **ignores `width`/`height`**, and its vertical margins don't affect layout (vertical padding is painted but doesn't push lines apart). **inline-block** sits in the line but respects sizes like a block. **none** removes the box entirely. Make links block or inline-block for big click areas. `<img>`, `<input>` and `<button>` are inline-level but do respect width and height.</En>
<Ur>`display` dabbe ka bahar ka rawaiya set karta hai. **block** (`div`, `p`, `h1`, `ul`, `section`) nayi line se shuru, poori chaurai leta aur saare sizes aur faasle maanta hai. **inline** (`span`, `a`, `strong`, `code`) text me behta hai, **`width`/`height` nazar andaz** karta hai, aur us ke upar neeche ke margins layout par asar nahi karte (upar neeche ki padding rangi jati hai magar lines door nahi karti). **inline-block** line me rehta hai magar block ki tarah sizes maanta hai. **none** dabba bilkul hata deta hai. Bare click area ke liye links ko block ya inline-block banayen. `<img>`, `<input>` aur `<button>` inline-level hain magar width aur height maante hain.</Ur>
</Tr>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>
body { margin: 0; width: 600px; font: 16px/20px sans-serif; }
.x { width: 150px; height: 50px; padding: 10px; margin: 10px; border: 0; box-sizing: border-box; }
#blk { display: block; } #inl { display: inline; } #ib { display: inline-block; }
</style>
<p>Text <span class="x" id="inl">inline</span> text.</p>
<p>Text <span class="x" id="ib">inline-block</span> text.</p>
<span class="x" id="blk">block</span>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    for el in ["#inl", "#ib", "#blk"]:
        w, h = page.eval_on_selector(el, "e => { const r = e.getBoundingClientRect(); return [Math.round(r.width), Math.round(r.height)] }")
        print(f"{el:5} {w}x{h}")
    browser.close()
PY
```

```text output
#inl  57x37
#ib   150x50
#blk  150x50
```

<Happened>
<Tr>
<En>All three asked for 150 × 50. **inline** ignored it: its width is text plus padding (57px) and its height the font's glyph area (~17px for 16px text) plus 2 × 10px padding = 37px, and that padding overlaps neighbouring lines instead of pushing them. **inline-block** and **block** both respected the size; inline-block stays in the text line while block starts its own line.</En>
<Ur>Teeno ne 150 × 50 maanga. **inline** ne nazar andaz kiya: us ki chaurai text aur padding (57px) aur oonchai font ka glyph hissa (16px text ke liye ~17px) aur 2 × 10px padding = 37px, aur wo padding pados ki lines ko dhakelne ke bajaye un par chadh jati hai. **inline-block** aur **block** dono ne size maana; inline-block text ki line me rehta hai jabke block apni line se shuru hota hai.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Margins: auto, negative and collapsing">

<Tr>
<En>**`margin: 0 auto`** on a block with a `width` or `max-width` centres it by splitting the leftover space. **Negative margins** pull elements closer, even overlapping. **Margin collapsing:** when two **vertical** block margins touch, they merge into the **larger** one, not the sum: between siblings, between a parent and its first/last child (if no padding or border separates them), and in empty blocks. It's why headings and paragraphs don't double-space, and why a child's margin can push its parent down. It does **not** happen horizontally, inside **flex**/**grid**, with padding or borders between, or for floats and absolutely positioned elements. Many layouts sidestep it with `gap` or one-direction margins.</En>
<Ur>`width` ya `max-width` wale block par **`margin: 0 auto`** bachi jagah baraabar baant kar use beech me karta hai. **Manfi margins** elements ko qareeb kheenchte hain, upar chadhne tak. **Margin collapsing:** jab do **upar neeche** ke block margins milte hain to **bara** wala bachta hai, jama nahi: siblings ke beech, parent aur us ke pehle/aakhri bachche ke beech (agar padding ya border beech me na ho), aur khaali blocks me. Isi wajah se headings aur paragraphs dugna faasla nahi lete, aur isi wajah se bachche ka margin parent ko neeche dhakel sakta hai. Ye daayen baayen, **flex**/**grid** ke andar, beech me padding ya border ke saath, ya floats aur absolute elements me **nahi** hota. Kai layouts `gap` ya ek simt ke margins se is se bachte hain.</Ur>
</Tr>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>
body { margin: 0; }
.a { margin-bottom: 30px; height: 20px; }
.b { margin-top: 20px; height: 20px; }
.parent { background: #eee; }
.parent .child { margin-top: 40px; height: 20px; }
.flex { display: flex; flex-direction: column; }
.wrap { width: 400px; } .center { width: 200px; margin: 0 auto; height: 10px; }
</style>
<div id="s1"><div class="a" id="a1"></div><div class="b" id="b1"></div></div>
<div class="flex" id="s2"><div class="a" id="a2"></div><div class="b" id="b2"></div></div>
<div style="height:50px"></div>
<div class="parent" id="p"><div class="child" id="c"></div></div>
<div class="wrap"><div class="center" id="ctr"></div></div>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    gap = lambda x, y: page.evaluate(f"document.querySelector('{y}').getBoundingClientRect().top - document.querySelector('{x}').getBoundingClientRect().bottom")
    print("block siblings (30px + 20px margins), gap:", gap("#a1", "#b1"))
    print("flex column siblings, gap:", gap("#a2", "#b2"))
    print("parent top vs child top:", page.evaluate("document.querySelector('#c').getBoundingClientRect().top - document.querySelector('#p').getBoundingClientRect().top"))
    print("centred box left/right margins:", page.eval_on_selector("#ctr", "e => [getComputedStyle(e).marginLeft, getComputedStyle(e).marginRight]"))
    browser.close()
PY
```

```text output
block siblings (30px + 20px margins), gap: 30
flex column siblings, gap: 50
parent top vs child top: 0
centred box left/right margins: ['100px', '100px']
```

<Happened>
<Tr>
<En>Block siblings with 30px and 20px margins are **30px** apart: collapsed to the larger. In a flex column the same boxes are **50px** apart: flex margins never collapse. The child's 40px top margin collapsed **through** the parent: the child sits at the parent's very top (0px) and the gap appears **above the parent**, grey background and all; `padding-top: 1px`, a border or `display: flow-root` on the parent stops it. `margin: 0 auto` gave the 200px box 100px each side in its 400px parent.</En>
<Ur>30px aur 20px margins wale block siblings **30px** door hain: bare wale tak simat gaye. Flex column me wahi dabbe **50px** door hain: flex margins kabhi nahi simat te. Bachche ka 40px upar ka margin parent ke **aar paar** simat gaya: bachcha parent ke bilkul upar (0px) baitha aur khala **parent ke upar** aa gaya, saleti background samet; parent par `padding-top: 1px`, border ya `display: flow-root` ise rokta hai. `margin: 0 auto` ne 400px parent me 200px dabbe ko har taraf 100px diye.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Logical properties">

<Tr>
<En>

**Logical properties** follow the text direction instead of physical sides. In right-to-left languages (Arabic, Hebrew, Persian) "start" is the right side, so one stylesheet works both ways. Use them in new code, especially for sites that may be translated; `margin-inline: auto` and `padding-block: 1rem` are also shorter. Supported everywhere modern.

| Physical | Logical (in English) |
| --- | --- |
| `margin-top` / `margin-bottom` | `margin-block-start` / `margin-block-end` |
| `margin-left` / `margin-right` | `margin-inline-start` / `margin-inline-end` |
| `padding-left` + `padding-right` | `padding-inline` |
| `width` / `height` | `inline-size` / `block-size` |
| `border-left` | `border-inline-start` |
| `text-align: left` | `text-align: start` |

</En>
<Ur>

**Logical properties** physical kinaron ke bajaye text ki simt par chalti hain. Daayen se baayen zabanon (Arabic, Hebrew, Persian) me "start" daayan kinara hai, isliye ek stylesheet dono taraf chalti hai. Naye code me istemal karein, khaas kar tarjuma hone wali sites me; `margin-inline: auto` aur `padding-block: 1rem` chhote bhi hain. Har jadeed browser me.

| Physical | Logical (English me) |
| --- | --- |

<Step title="Sizing: auto, percentages, min and max">

<Tr>
<En>`width: auto` fills the available width; `height: auto` fits content. Percentage widths are relative to the **parent's content width**; percentage heights need a parent with a definite height; percentage **padding and margin** (even vertical) use the parent's **width**. `min-`/`max-width` and `-height` override `width`/`height`; `fit-content`, `min-content`, `max-content` size to content. Responsive layouts use flexible widths with limits: `max-width: 65ch; margin-inline: auto;` for readable text (`ch` = width of "0"), `max-width: 100%; height: auto;` for images, and `min-height` instead of fixed `height` on text boxes.</En>
<Ur>`width: auto` dastyab chaurai bharta hai; `height: auto` mawad jitna. Percentage widths **parent ki content chaurai** ke hisaab se; percentage heights ko tay shuda height wala parent chahiye; percentage **padding aur margin** (upar neeche bhi) parent ki **chaurai** istemal karte hain. `min-`/`max-width` aur `-height` `width`/`height` par ghalib hain; `fit-content`, `min-content`, `max-content` mawad ke hisaab se. Responsive layouts hadon wali lachakdar chauraiyan lete hain: parhne ke qabil text ke liye `max-width: 65ch; margin-inline: auto;` (`ch` = "0" ki chaurai), tasveeron ke liye `max-width: 100%; height: auto;`, aur text dabbon par fixed `height` ke bajaye `min-height`.</Ur>
</Tr>

<Step title="Overflow">

<Tr>
<En>When content is bigger than its box, `overflow` decides: `visible` (default, spills and overlaps), `hidden` (clipped), `clip` (also no programmatic scroll), `scroll` (always scrollbars), `auto` (scrollbars when needed, usually best); `overflow-x`/`-y` per direction. Long words or URLs: `overflow-wrap: anywhere`. One-line truncation: `white-space: nowrap; overflow: hidden; text-overflow: ellipsis;`. Horizontal scrolling on phones is a top responsive bug; wrap wide tables and code in `overflow-x: auto`. Don't put `overflow: hidden` on `body` to hide it; find the wide element (DevTools, or a temporary `* { outline: 1px solid red }`).</En>
<Ur>Jab mawad dabbe se bara ho to `overflow` tay karta hai: `visible` (default, bahar behta aur chadhta), `hidden` (kata hua), `clip` (program se scroll bhi nahi), `scroll` (hamesha scrollbars), `auto` (zaroorat par scrollbars, aksar behtar); har simt ke liye `overflow-x`/`-y`. Lambe alfaaz ya URLs: `overflow-wrap: anywhere`. Ek line kaatna: `white-space: nowrap; overflow: hidden; text-overflow: ellipsis;`. Phones par side scroll responsive ka bara bug hai; chauri tables aur code ko `overflow-x: auto` me lapeten. Use chhupane ke liye `body` par `overflow: hidden` na lagayen; chaura element dhoondhein (DevTools, ya waqti `* { outline: 1px solid red }`).</Ur>
</Tr>

<Step title="Outline, box-shadow and border-radius">

<Tr>
<En>**`outline`** is drawn outside the border and takes **no space**, which is why focus rings use it (`outline-offset` moves it out). **`box-shadow`** (`x y blur spread color`, or `inset`) also takes no space. **`border-radius`** rounds corners; `50%` on a square makes a circle. Changing `border-width` on hover or focus makes content **jump**, because the border is part of the box; outline and shadows don't. Tailwind's `ring-*` utilities are box-shadows.</En>
<Ur>**`outline`** border ke bahar banti hai aur **koi jagah nahi** leti, isi liye focus rings ise istemal karti hain (`outline-offset` use bahar khiskata hai). **`box-shadow`** (`x y blur spread color`, ya `inset`) bhi jagah nahi leta. **`border-radius`** kone gol karta hai; murabba par `50%` daira banata hai. Hover ya focus par `border-width` badalna mawad ko **uchhalta** hai, kyun ke border dabbe ka hissa hai; outline aur shadows nahi. Tailwind ki `ring-*` utilities box-shadows hain.</Ur>
</Tr>

## Common mistakes

<Compare>
<Bad title="Fighting the box">

```text
input { width: 100%; padding: 10px; }          /* overflows: content-box */
.tag { display: inline; width: 80px; }        /* ignored on inline */
.card { height: 200px; }                       /* text overflows when it wraps */
.btn:hover { border-width: 3px; }              /* layout jumps */
```

</Bad>
<Good title="Working with it">

```text
*, *::before, *::after { box-sizing: border-box; }
.tag { display: inline-block; width: 80px; }
.card { min-height: 200px; }
.btn:hover { box-shadow: 0 0 0 3px #2563eb; }  /* no layout change */
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Confusing padding and margin**: backgrounds and click areas cover padding, not margin.
- **Surprise margin collapsing**, especially parent and first child.
- **Hiding overflow** instead of fixing the too-wide element.
- **Forgetting browser default margins** on `body`, headings, paragraphs and lists.
- **Physical properties everywhere** on a site that will support RTL.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Padding aur margin me ulajhna**: background aur click area padding par hote hain, margin par nahi.
- **Hairan karne wala margin collapsing**, khaas kar parent aur pehla bachcha.
- Bohot chaure element ko theek karne ke bajaye **overflow chhupana**.
- `body`, headings, paragraphs aur lists ke **browser default margins bhoolna**.
- RTL wali site par **har jagah physical properties**.

</Ur>
</Tr>

<DeepDive title="Real world: the IE box model comes back">

Before `box-sizing` existed, Internet Explorer 5 rendered boxes with what we now call border-box (the "IE box model"), while standards browsers used content-box, and developers spent years writing hacks to get equal widths in both. When `box-sizing` arrived, developers realised the old IE model was more intuitive; in 2012 Paul Irish popularised `* { box-sizing: border-box; }`, and today it's in virtually every reset, framework and design system. Another everyday case: many "why is there a white gap at the top of my page?" questions turn out to be the `<h1>`'s default top margin collapsing through its parent `<header>`, fixed by setting the heading's margin, adding padding, or using `display: flow-root` on the header.

</DeepDive>

<DeepDive title="Security lens">

Box properties shape what users see and click, which matters for trust.

- **Overlapping elements:** negative margins, overflow and stacking can cover one element with another. Attackers who can inject CSS or styled HTML can place a fake button over a real one or hide warnings; sanitise user HTML and strip `style` attributes and `<style>` tags.
- **Click targets:** give destructive actions (Delete account) enough spacing from common ones to prevent accidental clicks.
- **Truncation hides information:** `text-overflow: ellipsis` on URLs or account names can hide the part revealing a phishing domain (`paypal.com.security-check.example`); show full values in security-sensitive places.
- **`overflow: hidden` isn't secret:** clipped content is still in the page.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="Explain the CSS box model.">
Every element generates a rectangular box with four areas: the content, padding around the content, a border around the padding, and a margin outside the border. Padding and border are part of the element's visible box and take its background; margin is transparent space that separates it from other boxes. The total space an element occupies is the sum of all four.
</QA>

<QA q="What is the difference between content-box and border-box?">
With content-box, the default, width and height set only the content area, and padding and border are added on top, so the rendered box is larger than the declared width. With border-box, width and height include padding and border, and the content shrinks to fit, so the declared size is the visible size. Most projects set border-box globally.
</QA>

<QA q="What is margin collapsing and when does it not happen?">
When vertical margins of block boxes in normal flow touch, between siblings, between a parent and its first or last child with nothing separating them, or within an empty block, they combine into a single margin equal to the largest, not their sum. It does not happen for horizontal margins, inside flex or grid containers, for floated or absolutely positioned elements, or when padding, a border or a new block formatting context such as display flow-root separates them.
</QA>

<QA q="What is the difference between display inline, block and inline-block?">
Block boxes start on a new line, fill the available width and respect width, height, margin and padding. Inline boxes flow within a line of text, ignore width and height, and their vertical margins and padding do not affect line layout. Inline-block boxes flow in the line like inline ones but respect width, height, margin and padding like blocks.
</QA>

<QA q="How do you centre a block element horizontally?">
Give it a width or max-width smaller than its container and set its left and right margins to auto, for example margin-inline auto. The browser divides the remaining space equally between both margins. In flex or grid containers you can also centre items with alignment properties.
</QA>

</DeepDive>

<Terms>
  <Term name="Box model">Content, padding, border and margin around every element.</Term>
  <Term name="Content box">The area holding the element's content.</Term>
  <Term name="Padding">Space inside the border, painted with the background.</Term>
  <Term name="Border">Line drawn between padding and margin.</Term>
  <Term name="Margin">Transparent space outside the border.</Term>
  <Term name="box-sizing">Whether width and height include padding and border.</Term>
  <Term name="Block box">Box that starts a new line and fills the width.</Term>
  <Term name="Inline box">Box that flows inside a line of text.</Term>
  <Term name="Margin collapsing">Adjacent vertical margins merging into the larger one.</Term>
  <Term name="Logical properties">Direction-aware properties such as margin-inline.</Term>
  <Term name="Overflow">Content larger than its box and how it is handled.</Term>
  <Term name="Outline">Line drawn outside the border without taking space.</Term>
