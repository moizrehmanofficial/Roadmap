<BigIdea>
<Tr>
<En>
**CSS variables** (officially **custom properties**) store values you reuse: declare one with a double-dash name, `--brand: #f59e0b;`, and use it with **`var(--brand)`**. Unlike Sass variables, they are **live in the browser**: they follow the **cascade** and **inheritance**, so you can declare them on `:root` for the whole page and **override** them on any element, class or media query, and everything using them updates instantly. That makes **theming** (dark mode = swap a few variables), **design tokens** (spacing and colour scales) and **component customisation** (`.btn { --btn-bg: …; }`) simple. `var(--x, fallback)` gives a fallback; JavaScript reads and changes them with `getPropertyValue` and `setProperty`; **`@property`** registers a typed variable that can be animated.
</En>
<Ur>
**CSS variables** (asal naam **custom properties**) dobara istemal hone wali values rakhte hain: double-dash naam se banayen, `--brand: #f59e0b;`, aur **`var(--brand)`** se istemal karein. Sass variables ke baraks ye **browser me zinda** hain: **cascade** aur **inheritance** maante hain, isliye poore page ke liye `:root` par rakhein aur kisi bhi element, class ya media query me **badal** dein, aur inhe istemal karne wali har cheez foran update hoti hai. Is se **theming** (dark mode = chand variables badlo), **design tokens** (faasle aur rangon ke paimane) aur **component ki customisation** (`.btn { --btn-bg: …; }`) aasan ho jate hain. `var(--x, fallback)` fallback deta hai; JavaScript `getPropertyValue` aur `setProperty` se parhti aur badalti hai; **`@property`** type wala variable register karta hai jo animate ho sakta hai.
</Ur>
</Tr>

## At a glance

<Glance>
<What>
<Tr>
<En>

A property whose name starts with `--`, read with `var()`:

```text
:root  { --brand: #f59e0b; --space: 1rem; }        /* declare (global) */
.button { background: var(--brand);                 /* use */
          padding: calc(var(--space) / 2) var(--space); }
.sale  { --brand: #dc2626; }                         /* override inside .sale */
```

Any button inside `.sale` turns red; all others stay orange, with no new button rules.

</En>
<Ur>

Aisi property jis ka naam `--` se shuru ho, `var()` se parhi jaye:

```text
:root  { --brand: #f59e0b; --space: 1rem; }        /* banana (global) */
.button { background: var(--brand);                 /* istemal */
          padding: calc(var(--space) / 2) var(--space); }
.sale  { --brand: #dc2626; }                         /* .sale ke andar badalna */
```

`.sale` ke andar har button laal ho jata hai; baqi naranji rehte hain, button ke naye rules ke baghair.

</Ur>
</Tr>
</What>
<Why>
<Tr>
<En>

- **One source of truth:** brand colours, spacing and fonts are defined once; changing the brand colour is a one-line change.
- **Theming:** dark mode, high contrast, per-customer themes in white-label products, all by swapping variables.
- **Runtime changes:** unlike Sass/Less variables (replaced at build time), they change in the browser: per element, per media query, on hover, from JavaScript.
- **Design systems:** Tailwind v4, shadcn/ui, Material Design 3, Bootstrap 5 and Radix all expose tokens as CSS variables.

</En>
<Ur>

- **Sach ka ek zariya:** brand rang, faasle aur fonts ek dafa tay; brand rang badalna ek line ka kaam.
- **Theming:** dark mode, high contrast, white-label products me har customer ki theme, sab variables badal kar.
- **Chalte waqt tabdeeli:** Sass/Less variables (build par badal jate hain) ke baraks ye browser me badalte hain: har element, har media query, hover par, JavaScript se.
- **Design systems:** Tailwind v4, shadcn/ui, Material Design 3, Bootstrap 5 aur Radix sab tokens CSS variables ki shakal me dete hain.

</Ur>
</Tr>
</Why>

- **Components:** local variables as a "styling API" (`--card-padding`).
- **Values from JavaScript or inline styles:** progress percentages, positions, user-chosen colours.

## Learn it step by step

<Walkthrough>

<Step title="Declaring and using variables">

<Tr>
<En>Declare a property whose name starts with **two dashes** inside any rule: `--main-color: #1f2937;`. Names are **case-sensitive** (`--Brand` ≠ `--brand`). Use `var(--main-color)` anywhere a value or part of one is allowed (`border: 1px solid var(--main-color)`). Values can be anything: colours, lengths, numbers, strings, whole lists such as a multi-layer shadow. `var()` can't be used in property **names**, selectors or media query conditions (`@media (min-width: var(--bp))` doesn't work).</En>
<Ur>Kisi bhi rule ke andar aisi property banayen jis ka naam **do dash** se shuru ho: `--main-color: #1f2937;`. Naam **case-sensitive** hain (`--Brand` ≠ `--brand`). Jahan value ya us ka hissa chal sake wahan `var(--main-color)` lagayen (`border: 1px solid var(--main-color)`). Values kuch bhi: rang, lambaiyan, numbers, strings, poori lists jaise kai tah wala shadow. `var()` property ke **naam**, selectors ya media query ki shart me nahi chalta (`@media (min-width: var(--bp))` kaam nahi karta).</Ur>
</Tr>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>
:root { --brand: #f59e0b; --space: 1rem; --radius: 8px; --shadow: 0 1px 2px rgb(0 0 0 / 0.2); }
.btn { background: var(--brand); padding: calc(var(--space) / 2) var(--space);
       border-radius: var(--radius); box-shadow: var(--shadow); }
</style><button class="btn" type="button">Buy</button>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    print("raw --brand on :root:", repr(page.evaluate("getComputedStyle(document.documentElement).getPropertyValue('--brand')")))
    s = page.eval_on_selector(".btn", "e => { const c = getComputedStyle(e); return [c.backgroundColor, c.padding, c.borderRadius, c.boxShadow] }")
    for name, value in zip(["background", "padding", "border-radius", "box-shadow"], s):
        print(f"{name:14} {value}")
    browser.close()
PY
```

```text output

background     rgb(245, 158, 11)
padding        8px 16px
border-radius  8px
box-shadow     rgba(0, 0, 0, 0.2) 0px 1px 2px 0px
```

<Tr>
<En>Reading `--brand` itself returned the **text** you wrote (`#f59e0b`): the browser doesn't interpret an ordinary custom property until it's used. Inside `background` it became a real colour, `rgb(245, 158, 11)`. `calc(var(--space) / 2) var(--space)` became `8px 16px`, and a whole multi-part shadow lived in one variable.</En>
<Ur>Khud `--brand` parhne par wahi **text** mila jo likha tha (`#f59e0b`): browser aam custom property ko istemal hone tak samajhta nahi. `background` ke andar ye asli rang `rgb(245, 158, 11)` ban gaya. `calc(var(--space) / 2) var(--space)` `8px 16px` bana, aur poora kai hisson wala shadow ek variable me raha.</Ur>
</Tr>

<Step title="Scope, inheritance and the cascade">

<Tr>
<En>To the cascade, custom properties are ordinary properties: a declaration applies to the elements its selector matches, they are **inherited** by descendants unless overridden, and specificity, source order and media queries decide which wins. So override a variable on a container and every descendant using it changes: globals on `:root`, overrides on sections (`.sidebar`), states (`.btn:hover { --btn-bg: … }`) or media queries. Changing a `:root` variable recomputes styles for the whole page; fine for themes, but for values that change many times per second (mouse position), set them on the smallest element that needs them.</En>
<Ur>Cascade ke liye custom properties aam properties hain: declaration un elements par lagti hai jin se selector milta hai, aulad inhe **wirse** me leti hai jab tak badla na jaye, aur specificity, tarteeb aur media queries jeetne wala tay karti hain. Isliye container par variable badlein to use istemal karne wali har aulad badal jati hai: globals `:root` par, sections (`.sidebar`), halaat (`.btn:hover { --btn-bg: … }`) ya media queries me tabdeeli. `:root` variable badalne se poore page ke styles dobara bante hain; themes ke liye theek, magar second me kai dafa badalne wali values (mouse position) sab se chhote zaroori element par rakhein.</Ur>
</Tr>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>
:root { --brand: rgb(245, 158, 11); --space: 8px; }
@media (min-width: 1000px) { :root { --space: 16px; } }
.sale { --brand: rgb(220, 38, 38); }
.btn { background: var(--brand); padding: var(--space); }
.btn:hover { --brand: rgb(30, 64, 175); }
</style>
<button class="btn" id="normal" type="button">Normal</button>
<section class="sale"><button class="btn" id="sale" type="button">Sale</button></section>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    for width in [600, 1200]:
        page = browser.new_page(viewport={"width": width, "height": 400})
        page.set_content(html)
        info = [page.eval_on_selector(el, "e => getComputedStyle(e).backgroundColor + ' pad ' + getComputedStyle(e).paddingTop") for el in ["#normal", "#sale"]]
        print(f"screen {width}px: normal = {info[0]} | sale = {info[1]}")
        if width == 600:
            page.hover("#normal")
            print("             hovered normal =", page.eval_on_selector("#normal", "e => getComputedStyle(e).backgroundColor"))
        page.close()
    browser.close()
PY
```

```text output
screen 600px: normal = rgb(245, 158, 11) pad 8px | sale = rgb(220, 38, 38) pad 8px
             hovered normal = rgb(30, 64, 175)
screen 1200px: normal = rgb(245, 158, 11) pad 16px | sale = rgb(220, 38, 38) pad 16px
```

<Happened>
<Tr>
<En>Both buttons use the same `.btn` rule. The one inside `.sale` inherited the overridden `--brand` and turned red. Hovering set the variable **on the button itself**, so it turned blue: a state change written as "change a variable". On the 1200px screen the media query changed `--space` on `:root`, so every button's padding grew to 16px.</En>
<Ur>Dono buttons ek hi `.btn` rule istemal karte hain. `.sale` ke andar wale ne badla hua `--brand` wirse me liya aur laal ho gaya. Hover ne variable **khud button par** badla, isliye neela hua: halat ki tabdeeli "variable badlo" ki shakal me. 1200px screen par media query ne `:root` par `--space` badla, isliye har button ki padding 16px ho gayi.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Fallbacks and invalid values">

<Tr>
<En>`var(--name, fallback)` uses the fallback when `--name` is **not defined**; the fallback can contain commas and even another `var()`. If a variable **is** defined but invalid for the property using it (`--size: red; width: var(--size)`), the declaration is **"invalid at computed-value time"**: the property falls back to its **inherited** value (inherited properties) or its **initial** value, **not** to an earlier declaration in your CSS. The browser can't check a variable when parsing, so the usual "invalid declaration, previous one applies" rule doesn't help. `@property` can give a safe typed initial value.</En>
<Ur>`var(--name, fallback)` fallback tab istemal karta hai jab `--name` **bana hi na ho**; fallback me commas aur doosra `var()` bhi ho sakta hai. Agar variable **bana hai** magar istemal karne wali property ke liye ghalat hai (`--size: red; width: var(--size)`), to declaration **"computed-value time par invalid"** hai: property apni **wirse** wali value (wirse wali properties) ya **shuruati** value par jati hai, aap ki CSS ki pichhli declaration par **nahi**. Browser parse karte waqt variable jaanch nahi sakta, isliye aam "ghalat declaration, pichhli lagegi" qaida kaam nahi aata. `@property` mehfooz type wali shuruati value de sakta hai.</Ur>
</Tr>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>
:root { --brand: rgb(245, 158, 11); --bad: 20px; }
body { color: rgb(17, 24, 39); }
#a { color: var(--missing, rgb(22, 163, 74)); }
#b { color: var(--missing, var(--brand)); }
#c { color: var(--missing); }
#d { color: blue; color: var(--bad); }
#e { background-color: red; background-color: var(--bad); }
</style>
<p id="a">a</p><p id="b">b</p><p id="c">c</p><p id="d">d</p><p id="e">e</p>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    for el, desc in [("#a", "missing + fallback"), ("#b", "missing + var fallback"), ("#c", "missing, no fallback"),
                     ("#d", "invalid value (color)"), ("#e", "invalid value (background)")]:
        prop = "backgroundColor" if el == "#e" else "color"
        print(f"{desc:28} -> {page.eval_on_selector(el, f'e => getComputedStyle(e).{prop}')}")
    browser.close()
PY
```

```text output
missing + fallback           -> rgb(22, 163, 74)
missing + var fallback       -> rgb(245, 158, 11)
missing, no fallback         -> rgb(17, 24, 39)
invalid value (color)        -> rgb(17, 24, 39)
invalid value (background)   -> rgba(0, 0, 0, 0)
```

<Happened>
<Tr>
<En>`#a`: `--missing` isn't defined, so the green fallback was used. `#b`: the fallback was itself a variable, resolving to brand orange. `#c`: no fallback, so `color` (inherited) took the body's dark colour. `#d`: `--bad` is `20px`, not a colour; the earlier `color: blue` did **not** come back, it took the inherited body colour. `#e`: `background-color` isn't inherited, so it fell to its initial `transparent`, not the earlier red.</En>
<Ur>`#a`: `--missing` bana nahi, isliye hara fallback laga. `#b`: fallback khud variable tha, jo brand naranji bana. `#c`: fallback nahi, isliye `color` (wirse wali) ne body ka gehra rang liya. `#d`: `--bad` `20px` hai, rang nahi; pichhla `color: blue` wapas **nahi** aaya, body ka wirse wala rang laga. `#e`: `background-color` wirse me nahi aata, isliye shuruati `transparent` par gaya, pichhle laal par nahi.</Ur>
</Tr>
</Happened>

<Step title="Design tokens">

<Tr>
<En>**Design tokens** are named design decisions: colours, spacing, font sizes, radii, shadows, durations. Good systems have two layers. **Primitive tokens** are the raw palette and scales (`--orange-500`, `--space-4`). **Semantic tokens** say what a value is **for** (`--color-primary: var(--orange-500)`, `--color-text-muted`). Components use only semantic tokens, so a theme re-points them without touching components, and nobody has to remember hex codes. Keep scales small (spacing 4, 8, 12, 16, 24, 32, 48, 64px) and avoid one-off values. Figma variables can export tokens straight to CSS.</En>
<Ur>**Design tokens** naam wale design faisle hain: rang, faasle, font sizes, radii, shadows, durations. Achhe systems me do tahen hoti hain. **Primitive tokens** kachcha palette aur paimane hain (`--orange-500`, `--space-4`). **Semantic tokens** batate hain value **kis liye** hai (`--color-primary: var(--orange-500)`, `--color-text-muted`). Components sirf semantic tokens istemal karte hain, isliye theme components chhue baghair inhe naye primitives par mor deti hai, aur kisi ko hex codes yaad nahi rakhne parte. Paimane chhote rakhein (faasle 4, 8, 12, 16, 24, 32, 48, 64px) aur ek dafa wali values se bachen. Figma variables tokens seedhe CSS me nikal sakte hain.</Ur>
</Tr>

```text
:root {
  /* Primitive tokens */
  --gray-50: #f9fafb;  --gray-200: #e5e7eb;  --gray-600: #4b5563;  --gray-900: #111827;
  --orange-500: #f59e0b;  --orange-700: #b45309;  --red-600: #dc2626;
  --space-1: 0.25rem;  --space-2: 0.5rem;  --space-3: 0.75rem;  --space-4: 1rem;  --space-6: 1.5rem;  --space-8: 2rem;
  --text-sm: 0.875rem;  --text-base: 1rem;  --text-lg: 1.125rem;  --text-2xl: 1.5rem;
  --radius-sm: 0.25rem;  --radius-md: 0.5rem;  --radius-full: 9999px;
  --duration-fast: 150ms;  --duration-normal: 250ms;

  /* Semantic tokens: what components use */
  --color-bg: #ffffff;
  --color-surface: var(--gray-50);
  --color-border: var(--gray-200);
  --color-text: var(--gray-900);
  --color-text-muted: var(--gray-600);
  --color-primary: var(--orange-500);
  --color-primary-text: var(--gray-900);
  --color-danger: var(--red-600);
}
```

<Happened>
<Tr>
<En>Primitives hold raw values; semantic tokens point to them by purpose. A dark theme or a new brand only changes the semantic lines; every component keeps working.</En>
<Ur>Primitives kachchi values rakhte hain; semantic tokens maqsad ke naam se un ki taraf ishara karte hain. Dark theme ya naya brand sirf semantic lines badalta hai; har component chalta rehta hai.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Theming and dark mode">

<Tr>
<En>A theme is a different set of semantic token values. Switch **automatically** with `@media (prefers-color-scheme: dark) { :root { … } }`, or by **user choice** with a `data-theme` attribute on `<html>`, set by a toggle and saved in `localStorage`. Often both: follow the system by default, let users override. Also set `color-scheme: light` / `dark` so browser-drawn controls (inputs, scrollbars) match, and set `data-theme` in a tiny inline script in `<head>` to avoid a flash of the wrong theme. Toggle the theme below.</En>
<Ur>Theme semantic token values ka doosra set hai. **Khud ba khud** `@media (prefers-color-scheme: dark) { :root { … } }` se badlein, ya **user ki marzi** se `<html>` par `data-theme` attribute ke zariye, jo toggle se lage aur `localStorage` me mehfooz ho. Aksar dono: default me system ke saath, users badal saken. `color-scheme: light` / `dark` bhi lagayen taa ke browser ke banaye controls (inputs, scrollbars) mil jayen, aur ghalat theme ki jhalak se bachne ke liye `<head>` me chhote inline script se `data-theme` lagayen. Neeche theme toggle karein.</Ur>
</Tr>

```html preview-js h=260 noqa
<style>
  :root { --bg: #ffffff; --surface: #f9fafb; --text: #111827; --muted: #4b5563; --border: #e5e7eb; --primary: #f59e0b; color-scheme: light; }
  [data-theme="dark"] { --bg: #0f172a; --surface: #1e293b; --text: #f1f5f9; --muted: #cbd5e1; --border: #334155; --primary: #fbbf24; color-scheme: dark; }
  body { margin: 0; padding: 16px; background: var(--bg); color: var(--text); font-family: system-ui, sans-serif; transition: background-color 0.2s, color 0.2s; }
  .card { padding: 16px; border: 1px solid var(--border); border-radius: 12px; background: var(--surface); max-width: 320px; }
  .card p { color: var(--muted); }
  .btn { padding: 8px 14px; border: 0; border-radius: 8px; background: var(--primary); color: #111827; font: inherit; }
</style>
<button type="button" id="toggle">Toggle theme</button>
<div class="card" style="margin-top: 12px">
  <h2>Kent mangoes</h2>
  <p>Every colour on this card comes from a variable.</p>
  <button class="btn" type="button">Add to cart</button>
  <p><label>Note <input placeholder="form controls follow color-scheme"></label></p>
</div>
<script>
  document.getElementById("toggle").addEventListener("click", () => {
    const root = document.documentElement;
    root.dataset.theme = root.dataset.theme === "dark" ? "light" : "dark";
  });
</script>
```

<Happened>
<Tr>
<En>Light values live on `:root`; dark values override the same names under `[data-theme="dark"]`. <Step title="Component APIs with variables">

<Tr>
<En>A component can declare **local** variables with defaults and use only them inside; users customise it by setting those variables, without knowing its selectors: `.btn { --btn-bg: var(--color-primary); --btn-pad-x: 1em; background: var(--btn-bg); … }`, then `.btn.danger { --btn-bg: var(--color-danger); }`. <Step title="Variables and JavaScript">

<Tr>
<En>Read with `getComputedStyle(el).getPropertyValue("--brand")` (it returns text, possibly with spaces, so `.trim()` it). JavaScript changes a variable once and CSS updates every place it's used: user-chosen colours, cursor-following effects, sliders, scroll progress. Prefer classes or data attributes for discrete states (themes) and variables for continuous values (positions, percentages).</En>
<Ur>`getComputedStyle(el).getPropertyValue("--brand")` se parhein (text deta hai, shayad spaces ke saath, isliye `.trim()`). `el.style.setProperty("--brand", "#16a34a")` se likhein, inline tabdeeli `removeProperty` se hatayen. `el.style.--brand = …` kaam **nahi** karta. JavaScript variable ek dafa badalti hai aur CSS har istemal ki jagah update karti hai: user ke chune rang, cursor ke peechhe chalne wale effects, sliders, scroll progress. <Step title="@property: typed and animatable variables">

<Tr>
<En>`@property --angle { syntax: "<angle>"; inherits: false; initial-value: 0deg; }` registers a variable with a **type** (`<length>`, `<percentage>`, `<color>`, `<number>`, `<integer>`, `<angle>`, `<time>`…), inheritance and an **initial value**. Ordinary custom properties are just text, so the browser can only flip them; a typed one can be **transitioned and animated** (gradient angles, progress rings, counters). Invalid values fall back to the initial value, and `inherits: false` stops leaking into descendants (also faster). Supported in all modern browsers since 2024; also `CSS.registerProperty()` from JavaScript. Sampling an animation halfway:</En>
<Ur>`@property --angle { syntax: "<angle>"; inherits: false; initial-value: 0deg; }` variable ko **type** (`<length>`, `<percentage>`, `<color>`, `<number>`, `<integer>`, `<angle>`, `<time>`…), wirasat aur **shuruati value** ke saath register karta hai. Aam custom properties sirf text hain, isliye browser unhe bas palat sakta hai; type wala **transition aur animate** ho sakta hai (gradient ke zawiye, progress rings, counters). Ghalat values shuruati value par jati hain, aur `inherits: false` aulad me phailne se rokta hai (tez bhi). 2024 se tamam jadeed browsers me; JavaScript se `CSS.registerProperty()` bhi. Animation ke beech me jaanch:</Ur>
</Tr>

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
html = """<!DOCTYPE html><title>t</title><style>
@property --typed { syntax: "<number>"; inherits: false; initial-value: 0; }
.box { --plain: 0; --typed: 0; animation: grow 10s linear paused; animation-delay: -5s; }
@keyframes grow { to { --plain: 100; --typed: 100; } }
</style><div class="box" id="b"></div>"""
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html)
    plain, typed = page.eval_on_selector("#b", "e => { const s = getComputedStyle(e); return [s.getPropertyValue('--plain').trim(), s.getPropertyValue('--typed').trim()] }")
    print(f"halfway through the animation: --plain = {plain}, --typed = {typed}")
    browser.close()
PY
```

```text output
halfway through the animation: --plain = 100, --typed = 50
```

<Happened>
<Tr>
<En>The 10s animation is paused and starts 5s in (negative delay), so we read values exactly halfway. The unregistered `--plain` is text and can't be interpolated: it had already flipped to 100. The registered `--typed` is a number, so the browser interpolated it to exactly 50. That's what makes smooth variable animations possible.</En>
<Ur>10s ki animation ruki hui hai aur 5s aage se shuru hoti hai (manfi delay), isliye values bilkul beech me parhi gayin. Ghair registered `--plain` text hai aur beech ki value nahi ban sakti: ye pehle hi 100 par palat chuka tha. Registered `--typed` number hai, isliye browser ne bilkul 50 nikala. Isi se variables ki hamwar animation mumkin hoti hai.</Ur>
</Tr>
</Happened>

<Tr>
<En>

| | Sass/Less `$var` | CSS `--var` |
| --- | --- | --- |

## Common mistakes

<Compare>
<Bad title="Hard-coded and leaky">

```text
.btn  { background: #f59e0b; }            /* hex repeated everywhere */
.card { --bg: white; }                    /* generic name leaks into children */
.btn  { background: var(--orange-500); }  /* primitive used in a component */
@media (min-width: var(--bp)) { }         /* not supported */
el.style.--brand = "red";                 /* syntax error */
```

</Bad>
<Good title="Tokens, prefixes, setProperty">

```text
.btn  { background: var(--color-primary); }
.card { --card-bg: var(--color-surface); background: var(--card-bg); }
.btn  { --btn-bg: var(--color-primary); background: var(--btn-bg); }
@media (min-width: 48rem) { }
el.style.setProperty("--brand", "red");
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Forgetting the double dash** (`-brand`) or `var()` (`color: --brand`).
- **Typos and case differences** in names, silently producing invalid values.
- **Expecting the previous declaration to apply** when a variable's value is invalid.
- **Expecting unregistered variables to animate smoothly;** use `@property`.
- **Changing `:root` variables on every mouse move,** causing whole-page style recalculation.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Double dash bhoolna** (`-brand`) ya `var()` (`color: --brand`).
- **Naamon me typos aur case ka farq**, jo chupke se ghalat values banate hain.
- **Variable ki value ghalat ho to pichhli declaration lagne ki umeed.**
- **Ghair registered variables ki hamwar animation ki umeed;** `@property` lein.
- **Har mouse harkat par `:root` variables badalna,** jis se poore page ka style dobara banta hai.

</Ur>
</Tr>

<DeepDive title="Real world: theming GitHub and shadcn/ui">

Before custom properties shipped in browsers (2016–2017), teams theming large products had to compile a separate stylesheet per theme with Sass, or swap whole CSS files with JavaScript. GitHub offers many colour themes (light, dark, dimmed, high-contrast and colour-blind variants); its Primer design system defines them as CSS variables like `--fgColor-default` and `--bgColor-muted`, so switching theme just changes which set of values is active, with no page reload. Similarly, shadcn/ui components only reference variables such as `--primary` and `--radius`, which is why teams can restyle the whole library by editing a dozen token values.

</DeepDive>

<DeepDive title="Security lens">

CSS variables are often fed from user settings or URLs. Treat their values as untrusted input.

- **User-chosen values:** if users can pick a theme colour or upload "custom CSS" that sets variables, validate the values server-side (a strict hex colour pattern). A value like `url(https://attacker.example/track)` placed into a variable used by `background` makes visitors' browsers send requests to the attacker.
- **Inline style injection:** building `style="--name: <user input>"` without escaping can break out of the attribute and inject HTML. Use framework bindings (`style={{ "--x": value }}` in React) or proper escaping, and a Content Security Policy that restricts `style-src` and image/font sources.
- **Contrast and readability:** themes built from user-chosen colours can produce unreadable text; compute contrast and reject or adjust colours below 4.5:1, especially for security warnings.
- **Don't store secrets in CSS:** values in variables are visible to anyone through DevTools.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What are CSS custom properties and how do they differ from Sass variables?">
Custom properties are properties whose names begin with two dashes and whose values are read with the var function. They live in the browser at runtime, follow the cascade and inheritance, can differ per element or media query, and can be read and changed from JavaScript. Sass variables are replaced at build time, so they cannot change at runtime, but they can be used in places custom properties cannot, such as media query conditions and selectors.
</QA>

<QA q="How do you implement dark mode with CSS variables?">
Define semantic colour tokens on the root, such as background, surface, text and border, and use only those in components. Override the same token names under a prefers-color-scheme dark media query, a data-theme attribute set by a user toggle, or both, and set the color-scheme property so browser controls match. Components then change theme without any changes to their rules.
</QA>

<QA q="What happens if a CSS variable holds a value that is invalid for the property using it?">
The declaration becomes invalid at computed-value time. Instead of falling back to an earlier declaration in the cascade, the property behaves as if it were set to unset: inherited properties take the parent's value and others take their initial value. Registering the property with the property at-rule gives it a type and initial value to fall back to.
</QA>

<QA q="How do you read and change a CSS variable from JavaScript?">
Read it with getComputedStyle on the element followed by getPropertyValue with the variable name, trimming whitespace, and change it with the element's style setProperty method, or remove an inline value with removeProperty. Everything using the variable updates automatically.
</QA>

<QA q="Why would you use the @property rule?">
It registers a custom property with a syntax type, inheritance behaviour and an initial value. This lets the browser interpolate the variable in transitions and animations, such as animating a gradient angle or number, provides a safe fallback for invalid values, and can prevent inheritance when it's not needed.
</QA>

</DeepDive>

<DeepDive title="All key terms">

<Terms>
  <Term name="Custom property">CSS property named with a double-dash prefix.</Term>
  <Term name="var()">Function reading a custom property, with optional fallback.</Term>
  <Term name=":root">Selector for the html element, used for global variables.</Term>
  <Term name="Fallback value">Value used when a variable is undefined.</Term>
  <Term name="Invalid at computed-value time">Variable value invalid where it is used.</Term>
  <Term name="Design token">Named design decision such as a colour or spacing value.</Term>
  <Term name="Primitive token">Raw palette or scale value.</Term>
  <Term name="Semantic token">Token named by purpose, pointing to a primitive.</Term>
  <Term name="Theme">A set of token values such as light or dark.</Term>
  <Term name="color-scheme">Tells the browser which colour schemes the page supports.</Term>
  <Term name="@property">Registers a typed, animatable custom property.</Term>
  <Term name="setProperty">JavaScript method to change a CSS variable.</Term>
</Terms>

</DeepDive>

<DeepDive title="More practice">

1. Move every colour, spacing and radius in one of your stylesheets into variables on `:root`.
2. Split them into primitive and semantic tokens.
3. Add dark mode that follows the system, plus a toggle that overrides it.
4. Build a button with `--btn-*` variables and three variants that only change variables.
5. Make a progress bar whose width comes from an inline `--value`, and update it from JavaScript.
6. Animate a conic gradient's angle with `@property`.
