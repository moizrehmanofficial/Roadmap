<BigIdea>
<Tr>
<En>
Images, fonts and the `<head>` are where many sites quietly lose speed and search traffic: a 3000-pixel photo sent to a phone, a font that makes the text jump when it loads, a page that shares on social media as a bare link. Next.js gives you three tools that fix this by default. **`next/image`** (`<Image>`) generates a **`srcset`** of sizes, converts to **WebP** (or AVIF), lazy-loads below-the-fold images, reserves space with **width and height** so nothing jumps, and can show a **blur placeholder**. **`next/font`** downloads fonts **at build time** and serves them from your own domain, adds `font-display: swap`, and creates a **size-adjusted fallback** font so the layout doesn't shift when the real font arrives. The **Metadata API** (`export const metadata` or `generateMetadata`) produces `<title>`, description, canonical and **Open Graph / Twitter** tags; special files like **`opengraph-image.tsx`**, **`robots.ts`** and **`sitemap.ts`** generate social images, `robots.txt` and `sitemap.xml` from code.
</En>
<Ur>
Images, fonts aur `<head>` wo jagahein hain jahan bohot si sites chupke se raftaar aur search traffic kho deti hain: phone ko bheji gayi 3000 pixel ki tasveer, aisa font jo load hote waqt text ko uchhal deta hai, aisa page jo social media par sirf khaali link ban kar share hota hai. Next.js teen auzaar deta hai jo default me ye theek karte hain. **`next/image`** (`<Image>`) sizes ka **`srcset`** banata hai, **WebP** (ya AVIF) me badalta hai, neeche wali images lazy-load karta hai, **width aur height** se jagah mehfooz karta hai taa ke kuch na uchhle, aur **blur placeholder** dikha sakta hai. **`next/font`** fonts **build ke waqt** download kar ke aap ke apne domain se deta hai, `font-display: swap` lagata hai, aur **size-adjusted fallback** font banata hai taa ke asli font aane par layout na khiske. **Metadata API** (`export const metadata` ya `generateMetadata`) `<title>`, description, canonical aur **Open Graph / Twitter** tags banati hai; **`opengraph-image.tsx`**, **`robots.ts`** aur **`sitemap.ts`** jaisi khaas files code se social images, `robots.txt` aur `sitemap.xml` banati hain.
</Ur>
</Tr>

<Why>
<Tr>
<En>

- **LCP** (Largest Contentful Paint) is usually an image: smaller, correctly sized, preloaded images make pages feel fast.
- **CLS** (layout shift): images without dimensions and late-loading fonts make text jump; both tools prevent it.
- **SEO and sharing**: titles, descriptions and canonical URLs help search engines; Open Graph images decide how links look on WhatsApp, LinkedIn, Slack and X.
- **Privacy**: self-hosted fonts mean visitors' browsers don't contact Google on every page view.

</En>
<Ur>

- **LCP** (Largest Contentful Paint) aam taur par image hoti hai: chhoti, sahi size ki, pehle se load images pages ko tez mehsoos karati hain.

## Picture it

<Tr>
<En>

Think of a **photo printing shop**.

- You hand over one huge original photo. When customers ask for a **wallet size**, a **postcard** or a **poster**, the shop prints the right size from it instead of handing everyone the giant original (`srcset` and the image optimiser).
- Before the print is ready, the customer gets a **blurry preview** in the right frame size, so the album page doesn't need rearranging later (blur placeholder + width/height).
- The shop keeps **its own stock of paper** instead of sending a runner to another store for every order (self-hosted fonts).
- Each photo envelope has a **label**: title, short description and a thumbnail on the front (metadata and Open Graph image), so people know what's inside without opening it.
- At the door there's a **directory** of the shop's sections and a sign saying which rooms are staff-only (`sitemap.xml` and `robots.txt`).

</En>
<Ur>

**Photo print karne wali dukan** ka sochein.

- Aap ek bohot bari asli tasveer dete hain. Jab customers **batwe ka size**, **postcard** ya **poster** maangte hain, dukan har ek ko bari asli dene ke bajaye usi se sahi size chhapti hai (`srcset` aur image optimiser).
- Print tayyar hone se pehle customer ko sahi frame size me **dhundla preview** milta hai, taa ke baad me album ka safha dobara na tarteeb dena pare (blur placeholder + width/height).
- Dukan har order ke liye doosri dukan ko aadmi bhejne ke bajaye **apna kaghaz** rakhti hai (khud host kiye fonts).
- Har photo lifafe par **label** hai: title, chhoti tafseel aur saamne thumbnail (metadata aur Open Graph image), taa ke log khole baghair jaan lein andar kya hai.
- Darwaze par dukan ke hisson ki **fehrist** aur ek board hai ke kaun se kamre sirf staff ke liye hain (`sitemap.xml` aur `robots.txt`).

</Ur>
</Tr>

## Words you'll see

<Tr>
<En>

| Word | What it means | Example |
| --- | --- | --- |
| **`srcset`** | List of image versions at different widths | `…&w=640 640w, …&w=1080 1080w` |
| **`sizes`** | How wide the image will display, so the browser picks from `srcset` | `"(max-width: 600px) 100vw, 33vw"` |
| **Image optimiser** | Next.js endpoint that resizes and converts images | `/_next/image?url=…&w=640&q=75` |
| **Placeholder** | What shows while the image loads | `placeholder="blur"` |

| **CLS** | How much the layout jumps while loading | text pushed down |

| **Fallback font metrics** | Adjusting a system font to match the real font's size | `size-adjust: 107.89%` |
| **`metadataBase`** | Base URL for relative metadata URLs | `https://shop.example.com` |
| **Canonical URL** | The preferred URL of a page for search engines | `<link rel="canonical">` |
| **Open Graph** | Meta tags used for link previews | `og:title`, `og:image` |

## Learn it step by step

<Walkthrough>

<Step title="A hero image with next/image">

<Tr>
<En>
Our test photo is 3000 × 2000 pixels and **822 KB**, a typical camera export. Importing it statically lets Next.js read its size and make a tiny blurred version at build time.
</En>
<Ur>
Hamari test tasveer 3000 × 2000 pixels aur **822 KB** ki hai, camera se nikli aam file. Ise static import karna Next.js ko build ke waqt is ka size parhne aur chhota dhundla version banane deta hai.
</Ur>
</Tr>

```tsx
// app/page.tsx
import Image from "next/image";
import hero from "./hero.jpg";

export default function Home() {
  return (
    <main>
      <h1>Summer collection</h1>
      <Image
        src={hero}
        alt="Sunny beach with a calm blue sky"
        placeholder="blur"
        preload
        sizes="100vw"
        style={{ width: "100%", height: "auto" }}
      />
      <p>Free shipping on orders over $50.</p>
    </main>
  );
}
```

```text
The generated HTML (shortened):

<img alt="Sunny beach with a calm blue sky" width="3000" height="2000" decoding="async"
     style="color:transparent;width:100%;height:auto;background-image:url(&quot;data:image/svg+xml;…blurred jpeg…&quot;)"
     sizes="100vw"
     srcSet="/_next/image?url=%2F_next%2Fstatic%2Fmedia%2Fhero.11qy5tg2zib_6.jpg&amp;w=640&amp;q=75 640w,
             …&amp;w=750&amp;q=75 750w, …&amp;w=828 828w, …&amp;w=1080 1080w, …&amp;w=1200 1200w,
             …&amp;w=1920 1920w, …&amp;w=2048 2048w, …&amp;w=3840 3840w"
     src="/_next/image?url=…&amp;w=3840&amp;q=75"/>

and in <head>, because of `preload`:
<link rel="preload" as="image" imageSrcSet="…same srcset…" imageSizes="100vw"/>
```

<Happened>
<Tr>
<En>

- `width="3000" height="2000"` came from the import, so the browser reserves the right space before the image loads (no layout shift), even though CSS scales it to 100% width.
- The **blur placeholder** is a tiny inline JPEG inside an SVG filter, shown as a background until the real image arrives.
- **`srcset`** lists eight widths; with `sizes="100vw"`, a 390-pixel-wide phone at 2× density picks the 828 version, a laptop picks 1920 or 2048.
- **`preload`** adds a `<link rel="preload">` so the browser fetches the hero early. Use it only for the main above-the-fold image. (`priority` from older versions is deprecated in Next.js 16.) Other images are **lazy-loaded** by default.

</En>
<Ur>

- `width="3000" height="2000"` import se aaye, isliye browser image load hone se pehle sahi jagah mehfooz karta hai (layout shift nahi), halanke CSS ise 100% chaurai par chhota karta hai.
- **Blur placeholder** SVG filter ke andar chhoti inline JPEG hai, jo asli image aane tak background ki tarah dikhti hai.
- **`srcset`** aath chauraiyan batata hai; `sizes="100vw"` ke saath 2× density wala 390 pixel chaura phone 828 version chunta hai, laptop 1920 ya 2048.
- **`preload`** `<link rel="preload">` jorta hai taa ke browser hero jaldi laye. Ise sirf upar ki asal image ke liye lein. (Purane versions ka `priority` Next.js 16 me deprecated hai.) Doosri images default me **lazy-load** hoti hain.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="What the optimiser actually sends">

<Tr>
<En>
Each `srcset` entry points to `/_next/image`, which resizes the original on first request, converts the format based on the browser's `Accept` header, and caches the result. We requested three widths with three different `Accept` headers.
</En>
<Ur>
Har `srcset` entry `/_next/image` ki taraf ishara karti hai, jo pehli request par asli ko chhota karta hai, browser ke `Accept` header ke hisaab se format badalta hai, aur nateeja cache karta hai. Humne teen chauraiyan teen mukhtalif `Accept` headers ke saath maangin.
</Ur>
</Tr>

```text
original /photos/beach.jpg                                   822,324 bytes

w=640   Accept: image/avif,image/webp,*/*   image/webp    10,080 bytes
w=640   Accept: */*                         image/jpeg    16,033 bytes
w=1080  Accept: image/avif,image/webp,*/*   image/webp    17,338 bytes
w=1080  Accept: */*                         image/jpeg    28,969 bytes
w=1920  Accept: image/avif,image/webp,*/*   image/webp    30,792 bytes
w=1920  Accept: */*                         image/jpeg    54,053 bytes

w=640 q=50      → 400  "q" parameter (quality) of 50 is not allowed
w=500 q=75      → 400  "w" parameter (width) of 500 is not allowed

Second request for the same image:
Cache-Control: public, max-age=315360000, immutable
X-Nextjs-Cache: HIT
```

<Happened>
<Tr>
<En>

- A phone gets a **10 KB** WebP instead of the **822 KB** original: about 80 times smaller. Browsers that don't accept WebP get a resized JPEG.
- Even though the browser offered AVIF, WebP came back: AVIF is opt-in with `images: { formats: ["image/avif", "image/webp"] }` (smaller files, slower to encode).
- Only configured widths and qualities are allowed (`qualities` defaults to `[75]` in Next.js 16), so nobody can make your server generate thousands of variants.
- Optimised images are cached on disk (`X-Nextjs-Cache: HIT`) and sent with long cache headers. On Vercel and similar platforms, image optimisation may be billed per source image; check your plan.

</En>
<Ur>

- Phone ko asli **822 KB** ke bajaye **10 KB** ki WebP milti hai: taqreeban 80 guna chhoti. Jo browsers WebP qubool nahi karte unhen chhoti ki gayi JPEG milti hai.
- Browser ne AVIF ki peshkash ki phir bhi WebP aaya: AVIF `images: { formats: ["image/avif", "image/webp"] }` se on hota hai (chhoti files, encode karne me sust).
- Sirf set ki gayi chauraiyan aur qualities ki ijazat hai (Next.js 16 me `qualities` default `[75]`), isliye koi aap ke server se hazaron variants nahi banwa sakta.
- Optimise ki gayi images disk par cache hoti hain (`X-Nextjs-Cache: HIT`) aur lambe cache headers ke saath bheji jati hain. Vercel jaise platforms par image optimisation har source image par bill ho sakti hai; apna plan check karein.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Remote images and fill">

<Tr>
<En>
Images from another domain (a CMS, an S3 bucket, a CDN) must be **allowed explicitly**, otherwise anyone could use your server to optimise images from anywhere. And for images inside boxes of unknown size, use **`fill`** with a `sizes` hint.
</En>
<Ur>
Doosre domain (CMS, S3 bucket, CDN) ki images ko **wazeh ijazat** deni hoti hai, warna koi bhi aap ke server se kahin ki bhi images optimise karwa sakta. Aur na maloom size ke dabbon ke andar ki images ke liye `sizes` ishare ke saath **`fill`** lein.
</Ur>
</Tr>

```tsx
// next.config.ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  images: {
    remotePatterns: [new URL("https://images.example-cdn.com/products/**")],
  },
};

export default nextConfig;

// app/gallery/page.tsx
import Image from "next/image";

export const metadata = { title: "Gallery" };

const photos = Array.from({ length: 6 }, (_, i) => ({ id: i + 1, src: "/photos/beach.jpg" }));

export default function Gallery() {
  return (
    <main>
      <h1>Gallery</h1>
      <div style={{ display: "grid", gridTemplateColumns: "repeat(auto-fill, minmax(240px, 1fr))", gap: 8 }}>
        {photos.map((p) => (
          <div key={p.id} style={{ position: "relative", aspectRatio: "3 / 2" }}>
            <Image src={p.src} alt={`Beach photo ${p.id}`} fill sizes="(max-width: 600px) 100vw, 33vw" style={{ objectFit: "cover" }} />
          </div>
        ))}
      </div>
    </main>
  );
}
```

```text
An <Image> from a host that ISN'T in remotePatterns (cdn.other-site.com):
GET /_next/image?url=https%3A%2F%2Fcdn.other-site.com%2Fcat.jpg&w=828&q=75
→ 400  "url" parameter is not allowed
(in development, Next.js shows: Invalid src prop (…) on `next/image`, hostname "cdn.other-site.com"
 is not configured under images in your `next.config.js`)
```

<Happened>
<Tr>
<En>

- Unlisted hosts are refused with **400**, so the broken image shows up as an empty box in production and a clear error in development.
- Remote images need `width` and `height` props (or `fill`), because Next.js can't read their size at build time.
- With `fill`, the image is absolutely positioned inside its parent, which needs `position: relative` and a size (here `aspectRatio: 3 / 2`). `objectFit: "cover"` crops instead of stretching.
- `sizes` matters most here: without it the browser assumes 100vw and downloads images three times too big for a three-column grid.

</En>
<Ur>

- Fehrist se bahar ke hosts **400** se radd hote hain, isliye production me tooti image khaali dabba dikhti hai aur development me wazeh error.
- Remote images ko `width` aur `height` props (ya `fill`) chahiyen, kyun ke Next.js build ke waqt un ka size nahi parh sakta.
- `fill` ke saath image apne parent ke andar absolute position hoti hai, jise `position: relative` aur size chahiye (yahan `aspectRatio: 3 / 2`). `objectFit: "cover"` khinchne ke bajaye kaat'ta hai.
- Yahan `sizes` sab se ahem hai: is ke baghair browser 100vw samajhta hai aur teen column grid ke liye teen guna bari images download karta hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Fonts with next/font: self-hosted, no layout shift">

<Tr>
<En>
`next/font` loads fonts **at build time** and serves them from your domain. With Google fonts it's one import; for your own files, `next/font/local`. We used the Inter font files locally (our build machine had no access to Google Fonts; with internet access, `next/font/google` produces the same result).
</En>
<Ur>
`next/font` fonts **build ke waqt** load kar ke aap ke domain se deta hai. Google fonts ke liye ek import kaafi hai; apni files ke liye `next/font/local`. Humne Inter font files maqami tor par istemal kin (hamari build machine ko Google Fonts tak rasai nahi thi; internet ke saath `next/font/google` yahi nateeja deta hai).
</Ur>
</Tr>

```tsx
// With Google Fonts (downloads at build time, so the build needs internet):
// import { Inter } from "next/font/google";
// export const inter = Inter({ subsets: ["latin"], display: "swap", variable: "--font-inter" });

// app/fonts.ts (local files)
import localFont from "next/font/local";

export const inter = localFont({
  src: [
    { path: "./fonts/Inter-Regular.woff2", weight: "400", style: "normal" },
    { path: "./fonts/Inter-Bold.woff2", weight: "700", style: "normal" },
  ],
  display: "swap",
  variable: "--font-inter",
});

// app/layout.tsx (part)
<html lang="en" className={inter.variable}>
  <body className={inter.className}>{children}</body>
</html>
```

In <head>:
<link rel="preload" href="/_next/static/media/Inter_Bold-s.p.4421omqeymgmp.woff2" as="font" crossorigin="" type="font/woff2"/>
<link rel="preload" href="/_next/static/media/Inter_Regular-s.p.2qdljeg3s-lsl.woff2" as="font" crossorigin="" type="font/woff2"/>

<html lang="en" class="sF36MG_variable">
<body class="sF36MG_className">

Generated CSS:
@font-face{font-family:inter;src:url(../media/Inter_Regular-s.p.2qdljeg3s-lsl.woff2)format("woff2");font-display:swap;font-weight:400;font-style:normal}
@font-face{font-family:inter;src:url(../media/Inter_Bold-s.p.4421omqeymgmp.woff2)format("woff2");font-display:swap;font-weight:700;font-style:normal}

<Tr>
<En>

- The font files got **hashed names** under `/_next/static/media/`, so they're cached forever and served from your own domain: no extra DNS lookup or connection to another server, and no third-party tracking.
- The fonts are **preloaded**, so the browser starts downloading them immediately.
- The clever part is **`inter Fallback`**: Arial adjusted with `size-adjust: 107.89%` and ascent/descent overrides so it takes up almost exactly the same space as Inter. Text shows instantly in the fallback and barely moves when Inter arrives.
- `className` applies the font directly; `variable` exposes `--font-inter` for CSS or Tailwind (`font-family: var(--font-inter)`). Load each font **once** (in the root layout or a shared module); every call creates another copy.

</En>
<Ur>

<Step title="Metadata: titles, descriptions, canonical and Open Graph">

<Tr>
<En>
The root layout sets site-wide defaults; pages override what's specific to them. For pages built from data, `generateMetadata` receives the same `params` as the page.
</En>
<Ur>
Root layout poori site ke defaults set karta hai; pages apni mukhsoos cheezein badalte hain. Data se bane pages ke liye `generateMetadata` ko page jaise hi `params` milte hain.

```tsx
// app/layout.tsx
import type { Metadata } from "next";
import { inter } from "./fonts";

export const metadata: Metadata = {
  metadataBase: new URL("https://shop.example.com"),
  title: { default: "Acme Store", template: "%s | Acme Store" },
  description: "Everyday things, made to last.",
  openGraph: { siteName: "Acme Store", type: "website" },
};

// app/products/[slug]/page.tsx
import type { Metadata } from "next";
import { notFound } from "next/navigation";
import { getProduct, products } from "@/lib/products";

type Props = { params: Promise<{ slug: string }> };

export function generateStaticParams() {
  return products.map((p) => ({ slug: p.slug }));
}

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { slug } = await params;
  const product = getProduct(slug);
  if (!product) return { title: "Product not found" };
  return {
    title: product.name,
    description: product.description,
    alternates: { canonical: `/products/${product.slug}` },
    openGraph: { title: `${product.name}: $${product.price}`, description: product.description },
  };
}

export default async function ProductPage({ params }: Props) {
  const { slug } = await params;
  const product = getProduct(slug);
  if (!product) notFound();
  return (
    <main>
      <h1>{product.name}</h1>
      <p>${product.price} · {product.description}</p>
    </main>
  );
}
```

</En>
<Ur>

}

## Common mistakes

<Compare>
<Bad title="A full-width image without sizes">

```text
<Image src={photo} alt="" fill />           // no sizes, no alt text
// the browser assumes 100vw: a 33%-wide card downloads a 3× too large image,
// and screen readers get nothing
```

</Bad>
<Good title="Describe it and tell the browser how big it will be">

```text
<Image src={photo} alt="Blue ceramic travel mug on a desk" fill
       sizes="(max-width: 600px) 100vw, 33vw" style={{ objectFit: "cover" }} />
```

</Good>
</Compare>

<Compare>
<Bad title="Loading a font in every component">

```text
// components/Card.tsx
const inter = Inter({ subsets: ["latin"] });   // a new font instance per file
// components/Header.tsx
const inter = Inter({ subsets: ["latin"] });
```

</Bad>
<Good title="One font module, imported where needed">

```text
// app/fonts.ts
export const inter = Inter({ subsets: ["latin"], variable: "--font-inter" });
// app/layout.tsx: <html className={inter.variable}>; CSS uses var(--font-inter)
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **`preload` on many images**: it competes with what matters; use it only for the LCP image.
- **Remote images without `remotePatterns`**, or overly broad patterns (`hostname: "**"`) that let anyone use your optimiser.
- **`unoptimized` everywhere** to "fix" errors: you lose resizing and modern formats.
- **Same title and description on every page**: search results look identical and click-through drops.
- **Relative Open Graph URLs without `metadataBase`**: previews show no image.
- **Huge OG images or text that doesn't fit**: keep 1200×630 and test with a link preview tool.
- **Using `robots.txt` to hide private pages**: it publishes their paths.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Bohot si images par `preload`**: ye ahem cheez se muqabla karta hai; ise sirf LCP image ke liye lein.
- **`remotePatterns` ke baghair remote images**, ya bohot khule patterns (`hostname: "**"`) jo kisi ko bhi aap ka optimiser istemal karne dein.
- Errors "theek" karne ke liye **har jagah `unoptimized`**: resizing aur jadeed formats kho jate hain.
- **Har page par ek jaisa title aur description**: search nataij ek jaise dikhte hain aur clicks kam hote hain.
- **`metadataBase` ke baghair relative Open Graph URLs**: previews me image nahi aati.
- **Bari OG images ya na samane wala text**: 1200×630 rakhein aur link preview tool se test karein.
- **Private pages chhupane ke liye `robots.txt`**: ye un ke paths shaya kar deta hai.

</Ur>
</Tr>

<Takeaways>
<Tr>
<En>

- `<Image>` resizes, converts (WebP by default, AVIF if enabled), lazy-loads, and reserves space; always give `alt` and a realistic `sizes`.

<DeepDive title="More about images, fonts and metadata">

**Custom loaders.** If images live on Cloudinary, Imgix or a CDN with its own resizing, set `images.loader: "custom"` and a `loaderFile` that builds that service's URLs; Next.js then only generates the `srcset`.

**`getImageProps`.** Returns the props `<Image>` would use, for art direction with `<picture>` (different crops for mobile and desktop) or CSS backgrounds.

**`deviceSizes` and `imageSizes`.** Control which widths appear in `srcset`; smaller `imageSizes` are used when `sizes` says the image is narrow.

**SVG.** `<Image>` serves SVGs without optimisation unless `dangerouslyAllowSVG` is set (SVGs can contain scripts), so inline small icons or use plain `<img>` for trusted SVGs.

**Variable fonts.** One file covers all weights (`Inter({ subsets: ["latin"] })` loads the variable version), usually smaller than several static weights.

**Viewport and theme colour.** Use `export const viewport = { themeColor: "#0f766e" }` (separate from `metadata`).

**Streaming metadata.** For bots, Next.js waits for `generateMetadata` before sending HTML; for browsers it can stream metadata later so slow metadata doesn't block the page.

**JSON-LD.** Add structured data (Product, Article, FAQ) with a `<script type="application/ld+json">` in the page for rich search results; escape `<` in the JSON.

</DeepDive>

<DeepDive title="Real world: the blog that shared as a blank box">

A company blog built on Next.js had great articles but almost no traffic from LinkedIn and Slack. Every shared link appeared as a plain grey box with the site name and no image.

Investigation took ten minutes with a link preview debugger:

1. Every page had the same `<title>` ("Company Blog") because metadata was only set in the root layout.
2. The `og:image` tag pointed to `/images/share.png`, a **relative** URL. Without `metadataBase`, social crawlers couldn't resolve it.
3. The hero images were 4 MB PNGs exported from a design tool, sent at full size to every phone, giving an LCP of over 6 seconds on mobile.
4. The custom font was loaded with a `<link>` to an external font service in the layout, causing a visible text jump on every page load.

The fix, in one afternoon: `metadataBase` and a title template in the root layout, `generateMetadata` and an `opengraph-image.tsx` per article (title, author and reading time on a branded card), hero images converted to `<Image preload sizes="100vw">`, and the font moved to `next/font/local`. Mobile LCP dropped to 1.8 seconds, layout shift disappeared, and the click-through rate from social posts roughly doubled in the following month.

</DeepDive>

<DeepDive title="Security lens">

- **Image optimiser abuse**: keep `remotePatterns` narrow (exact hostnames and path prefixes); a wide pattern turns your server into a free image proxy and can be used for SSRF-style probing of internal hosts.
- **SVG risk**: SVGs can contain scripts; don't enable `dangerouslyAllowSVG` for user uploads, or serve them with `contentDispositionType: "attachment"` and a strict CSP.
- **User-uploaded images**: validate type and size, strip EXIF metadata (it may include GPS location), and store them on a separate domain or bucket.
- **Metadata from user content**: Next.js escapes values, but don't put private data (emails, internal IDs) in titles or OG images; they're public and cached by third parties.
- **`robots.txt` and sitemaps are public**: don't list hidden or admin URLs in them.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What does next/image do compared with a plain img tag?">
It generates responsive srcset and sizes, serves images through an optimiser that resizes and converts to modern formats like WebP or AVIF with caching, lazy-loads by default, requires dimensions to prevent layout shift, supports blur placeholders and preloading for the LCP image, and restricts remote sources to configured patterns.
</QA>

<QA q="How does next/font prevent layout shift?">
It self-hosts the font files with preload links and font-display swap, and generates a fallback font face based on a system font with size-adjust and ascent and descent overrides that match the real font's metrics, so text occupies the same space before and after the font loads.
</QA>

<QA q="How do you set dynamic metadata for a page in the App Router?">
Export an async generateMetadata function from the page or layout. It receives params and searchParams, can fetch data, and returns a Metadata object with title, description, alternates, openGraph and more. Child metadata merges with parent metadata, and title templates in layouts format child titles.
</QA>

<QA q="How do you create Open Graph images in Next.js?">
Either place a static opengraph-image file in a route segment or add opengraph-image.tsx that returns an ImageResponse rendered from JSX with a subset of CSS. Next.js generates the image route and adds og:image tags with size and type automatically.
</QA>

<QA q="What is the sizes attribute and why does it matter?">
It tells the browser how wide the image will be displayed at different viewport sizes, so it can choose the right file from srcset before layout. Without it, the browser assumes full viewport width and may download much larger images than needed.
</QA>
