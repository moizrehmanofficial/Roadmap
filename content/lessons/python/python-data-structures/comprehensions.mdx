<BigIdea>
<Tr>
<En>
So much code follows the same shape: make an empty list, loop over something, maybe skip some items, transform the rest, append. A **comprehension** says all of that in one expression: `[s // 1024 for s in sizes if s >= 1024]` reads "the size in KB, for each size, if it's at least 1024". It's a **list comprehension** with square brackets; the same syntax with braces and a `key: value` builds a **dict comprehension**, and braces with a single expression build a **set comprehension**. The optional `if` at the end **filters**; an `a if cond else b` at the front **chooses a value** for every item. Several `for` clauses work like nested loops, read from left to right. Swap the brackets for parentheses and you get a **generator expression**: instead of building the whole list in memory, it produces items **one at a time, on demand**, which is ideal for feeding functions like `sum()`, `max()`, `any()` and `"".join()`, for huge or endless inputs, and for stopping early. Comprehensions are about **clarity**: when the logic needs several conditions, side effects or more than two loops, a normal `for` loop is better.
</En>
<Ur>
Bohot sa code ek hi shakal ka hota hai: khaali list banao, kisi cheez par loop chalao, shayad kuch items chhoro, baqi ko badlo, append karo. **Comprehension** ye sab ek expression me kehta hai: `[s // 1024 for s in sizes if s >= 1024]` parhta hai "KB me size, har size ke liye, agar kam az kam 1024 ho". Square brackets ke saath ye **list comprehension** hai; braces aur `key: value` ke saath wahi syntax **dict comprehension**, aur ek expression wale braces **set comprehension** banate hain. Aakhir ka ikhtiyari `if` **filter** karta; aage `a if cond else b` har item ke liye **value chunta** hai. Kayi `for` clauses nested loops ki tarah baayen se daayen parhe jate hain. Brackets ki jagah qausen lagayen to **generator expression** milta hai: poori list memory me banane ke bajaye ye items **ek ek kar ke, maang par** deta hai, jo `sum()`, `max()`, `any()` aur `"".join()` jaise functions ko khilane, bohot bare ya na khatam hone wale inputs, aur jaldi rukne ke liye behtareen hai. Comprehensions **wazahat** ke liye hain: jab mantiq ko kayi shartein, side effects ya do se zyada loops chahiyen to aam `for` loop behtar hai.
</Ur>

## Picture it

<Tr>
<En>

Think of **sorting fruit on a conveyor belt**.

- The belt carries every fruit past you (`for fruit in crates`).
- You only pick ripe ones (`if ripe`), and you slice each one you pick (`slice(fruit)`); the sliced pieces land in a bowl (the new list).
- A generator expression is slicing a fruit only when the customer asks for the next piece: no bowl full of slices waiting around, and if the customer leaves after two pieces, you never slice the rest.

</En>
<Ur>

**Conveyor belt par phal chhantna** socheyn.

- Belt har phal aap ke saamne se guzarti hai (`for fruit in crates`).
- Aap sirf pake hue uthate (`if ripe`), aur har uthaye ko kaat te hain (`slice(fruit)`); kate tukre pyale me girte hain (nayi list).
- Generator expression phal tabhi kaatna hai jab customer agla tukra maange: kate tukron se bhara pyala intezar nahi karta, aur agar customer do tukron ke baad chala jaye to baqi kabhi nahi kaate jate.

</Ur>

## Words you'll see

<Tr>
<En>

| Word | What it means | Example |
| --- | --- | --- |
| **Comprehension** | Expression that builds a collection from an iterable | `[x * 2 for x in xs]` |
| **Filter clause** | `if` at the end that drops items | `if s >= 1024` |
| **Conditional expression** | `a if c else b` choosing a value | `"big" if s > 1 else "small"` |

| **Exhausted** | A generator with no items left | second `list(gen)` is empty |
| **Walrus operator** | `:=` assigns inside an expression | `(n := len(x)) > 3` |
| **Side effect** | Doing something besides producing a value | printing, writing files |

## Learn it step by step

<Walkthrough>

<Step title="List, dict and set comprehensions">

<Tr>
<En>
`comps.py` writes the same "large sizes in KB" logic as a loop and as a comprehension and checks they're equal. It then transforms, filters, labels every item with if/else, cleans a messy email list, builds host:port combinations and flattens a nested list with two `for` clauses, builds dicts and a set, and checks that the comprehension's variable `x` didn't overwrite the outer `x`.
</En>
<Ur>
`comps.py` wahi "KB me bare sizes" ki mantiq loop aur comprehension dono tarah likhti aur check karti hai ke barabar hain. Phir badalti, filter karti, if/else se har item ko label deti, gandi email list saaf karti, do `for` clauses se host:port jore banati aur nested list flatten karti, dicts aur ek set banati, aur check karti hai ke comprehension ke variable `x` ne bahar wale `x` ko nahi mitaya.
</Ur>
</Tr>

```bash
cat > comps.py <<'EOF'
sizes = [1024, 512, 2048, 256, 4096]

# A loop that builds a list...
large = []
for s in sizes:
    if s >= 1024:
        large.append(s // 1024)
# ...is the same as one list comprehension: [expression for item in iterable if condition]
large2 = [s // 1024 for s in sizes if s >= 1024]
print(large, large2, large == large2)

# Transform only, filter only
print([s * 2 for s in sizes], [s for s in sizes if s < 1000])

# if/else in the EXPRESSION (choose a value) vs if at the END (filter)
print(["big" if s >= 1024 else "small" for s in sizes])

# Strings: clean a messy list in one pass
raw = ["  Jane@Example.com", "", "john@example.com ", "   ", "ANA@corp.example"]
print([e.strip().lower() for e in raw if e.strip()])

# Two for clauses: read left to right like nested loops
hosts, ports = ["web1", "db1"], [22, 443]
print([f"{h}:{p}" for h in hosts for p in ports])
matrix = [[1, 2], [3], [4, 5, 6]]
print([n for row in matrix for n in row])            # flatten

# Dict and set comprehensions
users = [("jane", "admin"), ("john", "viewer"), ("ana", "admin")]
print({name: role for name, role in users})
print({name: role for name, role in users if role == "admin"})
print(sorted({role for _, role in users}))
print({ip: ip.split(".")[0] for ip in ["10.0.0.5", "192.0.2.1"]})

# The loop variable doesn't leak out of a comprehension
x = "outer"
squares = [x * x for x in range(4)]
print(squares, x)
EOF
python3 comps.py
```

```text output
[1, 2, 4] [1, 2, 4] True
[2048, 1024, 4096, 512, 8192] [512, 256]
['big', 'small', 'big', 'small', 'big']
['jane@example.com', 'john@example.com', 'ana@corp.example']
['web1:22', 'web1:443', 'db1:22', 'db1:443']
[1, 2, 3, 4, 5, 6]
{'jane': 'admin', 'john': 'viewer', 'ana': 'admin'}
{'jane': 'admin', 'ana': 'admin'}
['admin', 'viewer']
{'10.0.0.5': '10', '192.0.2.1': '192'}
```

<Happened>
<Tr>
<En>

- The loop and the comprehension produced the same **[1, 2, 4]**. Reading the comprehension aloud follows the loop: what to keep (`s // 1024`), for each item, if a condition holds.
- `[s * 2 for s in sizes]` only transformed; `[s for s in sizes if s < 1000]` only filtered.
- `["big" if s >= 1024 else "small" for s in sizes]` kept **all five** items and chose a label for each. An `if` at the end removes items; an `if/else` before `for` picks values. You can't put `else` on the filter.
- The cleaning comprehension stripped, lower-cased and dropped blank entries in one pass: **three clean emails**.
- Two `for` clauses behave like nested loops in the same order: every host with every port, and `for row in matrix for n in row` **flattened** the rows.
- Dict comprehensions built a name-to-role map (and a filtered one), and the set comprehension collected unique roles.
- After the comprehension, `x` was still **"outer"**: comprehensions have their own scope, unlike a `for` loop, whose variable survives.

</En>
<Ur>

- Loop aur comprehension ne wahi **[1, 2, 4]** banaya. Comprehension ko bulund aawaz me parhna loop ke peeche chalta hai: kya rakhna (`s // 1024`), har item ke liye, agar shart poori ho.
- `[s * 2 for s in sizes]` ne sirf badla; `[s for s in sizes if s < 1000]` ne sirf filter kiya.
- `["big" if s >= 1024 else "small" for s in sizes]` ne **paanchon** items rakhe aur har ek ka label chuna. Aakhir ka `if` items hatata hai; `for` se pehle ka `if/else` values chunta hai. Filter par `else` nahi laga sakte.
- Safai wale comprehension ne ek chakkar me strip, lower-case aur khaali entries gira di: **teen saaf emails**.
- Do `for` clauses usi tarteeb me nested loops jaise chalte hain: har host har port ke saath, aur `for row in matrix for n in row` ne rows **flatten** kin.
- Dict comprehensions ne naam se role ka naqsha (aur filter wala) banaya, aur set comprehension ne munfarid roles jama kiye.
- Comprehension ke baad `x` ab bhi **"outer"** tha: comprehensions ka apna scope hota hai, `for` loop ke baraks, jis ka variable bach jata hai.

</Ur>
</Tr>
</Happened>

<Step title="Generator expressions: lazy, light and single-use">

<Tr>
<En>
`gens.py` builds a million squares as a list and as a generator and compares their memory, feeds generator expressions into `sum`, `max`, `any`, `all` and `join`, uses `next()` with a checking function that prints every time it runs (to show how much work is skipped), tries to use one generator twice, and filters log lines with the walrus operator so the status code is parsed only once.
</En>
<Ur>
`gens.py` ek million squares list aur generator dono tarah bana kar un ki memory milati, generator expressions ko `sum`, `max`, `any`, `all` aur `join` me khilati, aisi checking function ke saath `next()` istemal karti jo har chalne par print kare (dikhane ke liye ke kitna kaam bach jata hai), ek generator do dafa istemal karne ki koshish karti, aur walrus operator se log lines filter karti taa ke status code ek hi dafa parse ho.
</Ur>
</Tr>

```bash
cat > gens.py <<'EOF'
import sys

# A generator expression uses ( ) and produces items ONE AT A TIME, on demand
squares_list = [n * n for n in range(1_000_000)]
squares_gen = (n * n for n in range(1_000_000))
print(type(squares_gen).__name__, sys.getsizeof(squares_list) > 1_000_000, sys.getsizeof(squares_gen) < 1_000)

# Feed it straight into sum(), max(), any(), all(), "".join() ... (no extra brackets needed)
sizes = [1024, 512, 2048, 256]
print(sum(s for s in sizes if s >= 1024), max(len(w) for w in ["ssh", "https", "ftp"]))
ports = [22, 80, 3306]
print(any(p in {3306, 6379} for p in ports), all(p < 1024 for p in ports))
print(", ".join(str(p) for p in ports))

# Lazy: nothing runs until you ask, and stops early when you stop asking
def check(ip):
    print("  checking", ip)
    return ip.startswith("10.")
ips = ["192.0.2.1", "10.0.0.5", "10.0.0.9", "203.0.113.7"]
print("first internal:", next(ip for ip in ips if check(ip)))

# A generator can be used up only once
gen = (n for n in range(3))
print(list(gen), list(gen))

# Walrus inside a comprehension: compute once, filter and keep
lines = ["GET / 200", "GET /admin 403", "POST /login 401", "GET /api 200"]
print([code for line in lines if (code := int(line.split()[-1])) >= 400])
EOF
python3 gens.py
```

```text output
generator True True
3072 5
True False
22, 80, 3306
  checking 192.0.2.1
  checking 10.0.0.5
first internal: 10.0.0.5
[0, 1, 2] []
[403, 401]
```

<Happened>
<Tr>
<En>

- The list of a million squares took **more than a megabyte**; the generator object took **under a kilobyte** whatever the range, because it only remembers where it is.
- `sum(s for s in sizes if s >= 1024)` needed no extra brackets: a generator expression as the only argument can drop its own parentheses. `any()` and `all()` also **stop early** as soon as the answer is known.
- `next(ip for ip in ips if check(ip))` checked **only two IPs**: the generator stopped as soon as it found the first internal one. With a list comprehension all four would have been checked first. Pass a default, `next(gen, None)`, when nothing may match.
- A generator is **used up** after one pass: the second `list(gen)` was empty. Build a list if you need the data more than once.
- `(code := int(...)) >= 400` parsed each status once, used it in the filter and kept it: **[403, 401]**. Handy, but if a comprehension needs a walrus and more, consider a loop.

</En>
<Ur>

- Ek million squares ki list ne **ek megabyte se zyada** liya; generator object ne range jo bhi ho **ek kilobyte se kam** liya, kyunke ye sirf yaad rakhta hai ke kahan hai.
- `sum(s for s in sizes if s >= 1024)` ko izafi brackets nahi chahiye the: akela argument hone par generator expression apni qausen chhor sakta hai. `any()` aur `all()` bhi jawab maloom hote hi **jaldi ruk** jate hain.
- `next(ip for ip in ips if check(ip))` ne **sirf do IPs** check kiye: generator pehla internal milte hi ruk gaya. List comprehension ke saath pehle chaaron check hote. Jab kuch na mile to default dein, `next(gen, None)`.
- Generator ek chakkar ke baad **khatam** ho jata hai: doosra `list(gen)` khaali tha. Data ek se zyada dafa chahiye to list banayen.
- `(code := int(...)) >= 400` ne har status ek dafa parse kiya, filter me istemal kiya aur rakha: **[403, 401]**. Kaam ka, magar agar comprehension ko walrus aur mazeed chahiye to loop par ghaur karein.

</Ur>
</Tr>
</Happened>

## Common mistakes

<Compare>
<Bad title="A comprehension that's too clever">

```text
report = [f"{u['name']}: {'LOCKED' if u['fails'] > 5 else 'ok'}" for team in data["teams"]
          if team["active"] for u in team["users"] if u.get("email") and not u["name"].startswith("svc-")]
```

</Bad>
<Good title="A loop when it reads better">

```text
report = []
for team in data["teams"]:
    if not team["active"]:
        continue
    for u in team["users"]:
        if not u.get("email") or u["name"].startswith("svc-"):
            continue
        status = "LOCKED" if u["fails"] > 5 else "ok"
        report.append(f"{u['name']}: {status}")
```

</Good>
</Compare>

<Compare>
<Bad title="Comprehensions for side effects">

```text
[print(host) for host in hosts]                  # builds a useless list of None
[requests.post(url, json=e) for e in events]     # hides important work in an expression
```

</Bad>
<Good title="Loops for doing, comprehensions for building">

```text
for host in hosts:
    print(host)
for e in events:
    requests.post(url, json=e, timeout=5)
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Putting `else` on the filter**: `[x for x in xs if c else y]` is a SyntaxError; move the condition to the front.
- **Reusing an exhausted generator**: convert to a list if you need two passes.
- **Building a big list just to sum or check it**: `sum([x for x in ...])` should be `sum(x for x in ...)`.
- **Wrong order of nested `for` clauses**: they read left to right, outer loop first.
- **Dict comprehensions that silently drop duplicates**: later items overwrite earlier keys.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Filter par `else` lagana**: `[x for x in xs if c else y]` SyntaxError hai; shart aage le jayen.
- **Khatam hua generator dobara istemal karna**: do chakkar chahiyen to list me badlein.
- **Sirf jor ya check ke liye bari list banana**: `sum([x for x in ...])` ko `sum(x for x in ...)` hona chahiye.
- **Nested `for` clauses ki ghalat tarteeb**: baayen se daayen parhe jate, bahar ka loop pehle.
- **Dict comprehensions jo khamoshi se duplicates gira dein**: baad ke items pehli keys mita dete hain.

</Ur>
</Tr>

<Challenge title="Parse a header block">

<Tr>
<En>
Turn this HTTP header text into a dict with lower-case names and stripped values, skipping blank lines, with a single dict comprehension: `"Host: example.test\nContent-Type: application/json\n\nX-Request-ID:  req-9f2 "`. Use `line.partition(":")`.
</En>
<Ur>
Is HTTP header text ko ek dict comprehension se aisi dict me badlein jis ke naam chhote haroof me aur values strip shuda hon, khaali lines chhor kar: `"Host: example.test\nContent-Type: application/json\n\nX-Request-ID:  req-9f2 "`. `line.partition(":")` istemal karein.

<Solution>

<Tr>
<En>

```text
raw = "Host: example.test\nContent-Type: application/json\n\nX-Request-ID:  req-9f2 "
headers = {name.strip().lower(): value.strip()
           for line in raw.splitlines() if line.strip()
           for name, _, value in [line.partition(":")]}
print(headers)

# {'host': 'example.test', 'content-type': 'application/json', 'x-request-id': 'req-9f2'}
```

The inner `for name, _, value in [line.partition(":")]` is a trick to name the parts of each line inside a comprehension; a two-line loop is equally fine.

<DeepDive title="More about comprehensions and generators">

**Generator functions.** A function with `yield` returns a generator too, for logic that doesn't fit in one expression; you'll meet them with functions and iterators.

**Pipelines.** Chain generator expressions to process files line by line: `lines = (l for l in f)`, `errors = (l for l in lines if " 500 " in l)`, `ips = (l.split()[0] for l in errors)`; nothing is read until something consumes `ips`.

**Performance.** Comprehensions avoid repeated `append` lookups and run a bit faster than loops; `map` and `filter` exist too but comprehensions are usually clearer in Python.

**Scope details.** The first iterable is evaluated in the enclosing scope, the rest inside the comprehension; since Python 3.12, comprehensions are inlined for speed but still don't leak their variables.

**Async comprehensions.** `[x async for x in aiter()]` and `await` inside comprehensions work in async code.

</DeepDive>

<DeepDive title="Real world: the report that ran out of memory">

A nightly job computed the total bytes served from 40 GB of access logs with `total = sum([int(l.split()[-1]) for l in open("access.log")])`. The square brackets built a list of hundreds of millions of integers before summing them, and the job was killed by the server's out-of-memory killer.

The fixes:

1. Remove the brackets: `sum(int(l.split()[-1]) for l in f)` streams one line at a time with flat memory use.
2. Open the file with `with open(...) as f` so it's closed reliably.
3. Skip malformed lines inside a small generator function with error handling instead of one long expression.

</DeepDive>

<DeepDive title="Security lens">

- **Filter early with allow-lists**: `{k: v for k, v in body.items() if k in ALLOWED_FIELDS}` copies only safe fields from untrusted input.
- **Generators bound memory** when processing attacker-controlled sizes of input, such as large uploads or logs.
- **Don't hide network or file writes in comprehensions**; reviewers expect them to be pure.
- **Normalise inside the comprehension** (`.strip().lower()`) so later security checks compare like with like.
- **Watch nested comprehensions over user-controlled lists**: combinations multiply, which can be abused for denial of service.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What is a list comprehension?">
An expression that builds a new list from an iterable, optionally filtering items, in the form of an expression for each item in an iterable with an optional if condition; it replaces the empty-list, loop and append pattern.
</QA>

<QA q="What is the difference between a list comprehension and a generator expression?">
A list comprehension builds the entire list in memory immediately; a generator expression yields items lazily one at a time, uses constant memory and can be iterated only once.
</QA>

<QA q="How do you write an if/else in a comprehension?">
Put a conditional expression before the for, such as a if cond else b for x in xs; a trailing if can only filter and can't have an else.
</QA>

<QA q="In what order do nested for clauses run?">
Left to right, exactly like nested for loops written top to bottom: the first for is the outer loop.
</QA>

<QA q="When should you not use a comprehension?">
When the main purpose is side effects, when the logic needs several statements or error handling, or when nesting makes it hard to read.
</QA>

</DeepDive>
