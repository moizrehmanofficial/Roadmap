<BigIdea>
<Tr>
<En>
A **list** holds items **in order** inside square brackets: `["web1", "web2", "db1"]`. Items can be of any type (even other lists), duplicates are allowed, and you reach them by **index** from 0, or from the end with negative numbers, exactly like characters in a string. The big difference from strings is that lists are **mutable**: you can **add** (`append`, `extend`, `insert`), **remove** (`remove` by value, `pop` and `del` by position) and **replace** items in place. That makes lists the natural place to collect results in a loop: start with `[]` and `append`. Two kinds of operations need care. Methods that **change** the list, such as `.sort()`, `.append()` and `.reverse()`, return **`None`**, so never write `x = x.sort()`; functions like **`sorted()`** return a **new** list and leave the original alone. And because a list holds **references**, putting the same inner list in several places (as `[[0] * 3] * 2` does) means changing one changes them all. Sorting is powerful thanks to **`key=`**: give a function that turns each item into the value to sort by, such as `str.lower`, `len`, or a tuple of several fields.
</En>
<Ur>
**List** square brackets ke andar items **tarteeb se** rakhti hai: `["web1", "web2", "db1"]`. Items kisi bhi type ke ho sakte (doosri lists bhi), duplicates ki ijazat hai, aur aap unhe 0 se **index** ke zariye, ya aakhir se negative numbers se pohanchte hain, bilkul string ke characters ki tarah. Strings se bara farq ye hai ke lists **mutable** hain: aap items apni jagah **jor** (`append`, `extend`, `insert`), **hata** (`remove` value se, `pop` aur `del` jagah se) aur **badal** sakte hain. Is liye loop me natije jama karne ki qudrati jagah list hai: `[]` se shuru karein aur `append` karein. Do qism ke kaam dhyan maangte hain. Jo methods list **badalte** hain, jaise `.sort()`, `.append()` aur `.reverse()`, **`None`** lautate hain, isliye kabhi `x = x.sort()` na likhein; **`sorted()`** jaise functions **nayi** list lautate aur asal ko chhorte hain. Aur kyunke list **references** rakhti hai, ek hi andar wali list kayi jagah rakhna (jaise `[[0] * 3] * 2` karta hai) ka matlab ek badlein to sab badalti hain. Sorting **`key=`** ki wajah se taqatwar hai: aisa function dein jo har item ko sort karne wali value me badle, jaise `str.lower`, `len`, ya kayi fields ka tuple.
</Ur>

## Picture it

<Tr>
<En>

Think of a **numbered queue of people holding cards**.

- Each position has a number starting at 0; you can ask "who's at position 2?" or "who's last?".
- People can join at the end (`append`), push in at a position (`insert`), leave by name (`remove`) or by position (`pop`), and everyone behind them shuffles forward.
- Sorting rearranges the people. `sorted()` takes a photo and rearranges the photo; `.sort()` makes the real people move.
- `[[0] * 3] * 2` is two mirrors pointing at the same person: wave at one, and both reflections wave.

</En>
<Ur>

**Cards pakre logon ki numbered qataar** socheyn.

- Har jagah ka number 0 se shuru hota; aap pooch sakte "jagah 2 par kaun hai?" ya "aakhri kaun?".
- Log aakhir me shamil ho sakte (`append`), kisi jagah ghus sakte (`insert`), naam se (`remove`) ya jagah se (`pop`) ja sakte, aur un ke peeche sab aage khiskte hain.
- Sorting logon ki tarteeb badalti hai. `sorted()` tasveer le kar tasveer ki tarteeb badalta; `.sort()` asal logon ko hilata hai.
- `[[0] * 3] * 2` ek hi shakhs ki taraf do aaine hain: ek ki taraf haath hilayen to dono aks hilate hain.

</Ur>
</Tr>

<Step title="Create, read, change and search lists">

<Tr>
<En>

It builds a list of odd ports in a loop, shows other ways to make lists, counts status codes, treats a nested list as a table, and triggers the two errors you'll meet most often.
</En>
<Ur>
`lists.py` hosts ki list aur mili jhuli types ki list banati, index aur slice se parhti, phir har jorne aur hatane wale method se host list badalti aur raste me print karti hai. Loop me odd ports ki list banati, lists banane ke doosre tareeqe dikhati, status codes ginti, nested list ko table ki tarah istemal karti, aur sab se aam do errors chhedti hai.
</Ur>

```bash
cat > lists.py <<'EOF'
hosts = ["web1", "web2", "db1"]              # ordered, can hold anything, can change
mixed = [42, "text", 3.5, True, None, [1, 2]]
print(len(hosts), hosts[0], hosts[-1], hosts[1:], "db1" in hosts, len(mixed))

# Changing a list in place
hosts.append("cache1")                       # add one item at the end
hosts.extend(["web3", "web4"])               # add several
hosts.insert(0, "lb1")                       # add at a position
print(hosts)
hosts.remove("web2")                         # remove the first matching VALUE
last = hosts.pop()                           # remove and return the last item
first = hosts.pop(0)                         # ... or the item at an index
print(hosts, "| popped:", last, first)
hosts[1] = "db-primary"                      # replace by index
del hosts[-1]                                # delete by index
print(hosts, "| index of db-primary:", hosts.index("db-primary"))

# Building lists
ports = []
for p in range(20, 26):
    if p % 2 == 1:
        ports.append(p)
print(ports, [0] * 4, [1, 2] + [3], list("abc"), "a b c".split())

# Counting and finding
statuses = [200, 404, 200, 500, 200, 404]
print(statuses.count(200), max(statuses), min(statuses), sum(statuses) / len(statuses))

# Lists inside lists: a table of rows
rows = [["jane", 2], ["john", 7], ["ana", 0]]
print(rows[1], rows[1][0], [r[0] for r in rows if r[1] > 0])
try:
    hosts[99]
except IndexError as e:
    print("IndexError:", e)
try:
    hosts.remove("nope")
except ValueError as e:
    print("ValueError:", e)
EOF
```

- `count`, `max`, `min` and `sum / len` summarised status codes (an average of **318.0**, which shows averages of codes are meaningless; count them instead).
- `rows[1][0]` reached into the nested list: row 1, column 0, **john**.
- Out-of-range indexes raise **IndexError**, and `remove` of a missing value raises **ValueError**; check with `in` first or catch the error.

</En>
<Ur>

<Step title="Sorting, keys, stacks and the shared-list trap">

<Tr>
<En>
`sorting.py` compares `sorted()` with `.sort()`, sorts names in three different ways, ranks users by failures with ties broken by name, finds the max and min by key, fixes version-number sorting, uses a list as an undo stack, and shows why `[[0] * 3] * 2` behaves strangely.
</En>
<Ur>
`sorting.py` `sorted()` ko `.sort()` se milati, naamon ko teen mukhtalif tareeqon se sort karti, users ko nakamiyon se darja deti aur barabari ko naam se torti, key se max aur min dhoondti, version numbers ki sorting theek karti, list ko undo stack ki tarah istemal karti, aur dikhati hai ke `[[0] * 3] * 2` ajeeb kyun chalta hai.
</Ur>
</Tr>

```bash
cat > sorting.py <<'EOF'
nums = [42, 7, 19, 3]
print(sorted(nums), nums)                 # sorted() returns a NEW list
result = nums.sort()                      # .sort() changes the list and returns None
print(nums, result)
print(sorted(nums, reverse=True))

# Sort by a key: a function applied to each item
names = ["ana", "Zed", "john", "Bob"]
print(sorted(names), sorted(names, key=str.lower), sorted(names, key=len))

users = [("jane", 2, "admin"), ("john", 7, "viewer"), ("ana", 7, "admin"), ("bob", 0, "viewer")]
print([u[0] for u in sorted(users, key=lambda u: u[1], reverse=True)])         # most failures first
print([u[0] for u in sorted(users, key=lambda u: (-u[1], u[0]))])               # then by name
print(max(users, key=lambda u: u[1])[0], min(users, key=lambda u: u[1])[0])

# Versions sort wrong as strings
versions = ["1.10.0", "1.2.0", "1.9.3"]
print(sorted(versions), sorted(versions, key=lambda v: [int(x) for x in v.split(".")]))

# A list as a stack (last in, first out)
undo = []
undo.append("typed a"); undo.append("typed b"); undo.append("deleted b")
print("undo:", undo.pop(), "| left:", undo)

# The shared-inner-list trap
grid = [[0] * 3] * 2                       # two references to ONE inner list
grid[0][0] = 9
print(grid)
grid = [[0] * 3 for _ in range(2)]         # two separate lists
grid[0][0] = 9
print(grid)
EOF
python3 sorting.py
```

<Happened>
<Tr>
<En>

- `sorted(nums)` returned a **new sorted list** and `nums` was untouched; `nums.sort()` sorted in place and returned **None**. Writing `nums = nums.sort()` would lose your list.
- Plain sorting puts **uppercase first** (`'Bob'`, `'Zed'` before `'ana'`) because it compares character codes. `key=str.lower` gave the human order, and `key=len` sorted by length (equal lengths keep their original order: Python's sort is **stable**).
- `key=lambda u: u[1], reverse=True` ranked by failures, but john and ana tie on 7. `key=lambda u: (-u[1], u[0])` sorts by a **tuple**: failures descending (the minus sign), then name ascending, giving **ana, john, jane, bob**.
- `max(..., key=...)` and `min(..., key=...)` returned the whole record with the highest and lowest failures.
- As strings, **"1.10.0" sorted before "1.2.0"** (character "1" < "2"). Turning each version into a list of ints fixed it. Real projects use `packaging.version.Version`.
- `append` and `pop` made a **stack**: the last action was undone first.
- `[[0] * 3] * 2` created **two references to one inner list**, so setting one cell changed both rows. A comprehension creates separate rows.

</En>
<Ur>

- `sorted(nums)` ne **nayi sorted list** lautayi aur `nums` ko haath nahi laga; `nums.sort()` ne apni jagah sort kiya aur **None** lautaya. `nums = nums.sort()` likhna aap ki list kho deta.
- Saadi sorting **bare haroof pehle** rakhti hai (`'Bob'`, `'Zed'` `'ana'` se pehle) kyunke character codes milati hai. `key=str.lower` ne insaani tarteeb di, aur `key=len` ne lambai se sort kiya (barabar lambai apni asal tarteeb rakhti hai: Python ka sort **stable** hai).
- `key=lambda u: u[1], reverse=True` ne nakamiyon se darja diya, magar john aur ana 7 par barabar hain. `key=lambda u: (-u[1], u[0])` **tuple** se sort karta hai: nakamiyan ulti tarteeb (minus ka nishan), phir naam seedhi tarteeb, jis se **ana, john, jane, bob** bana.
- `max(..., key=...)` aur `min(..., key=...)` ne sab se zyada aur kam nakamiyon wala poora record lautaya.
- Strings ki tarah **"1.10.0" "1.2.0" se pehle** sort hua (character "1" < "2"). Har version ko ints ki list banane se theek hua. Asal projects `packaging.version.Version` istemal karte hain.
- `append` aur `pop` ne **stack** banaya: aakhri kaam pehle undo hua.
- `[[0] * 3] * 2` ne **ek andar wali list ke do references** banaye, isliye ek cell set karne se dono rows badlin. Comprehension alag rows banata hai.

</Ur>
</Tr>

## Common mistakes

<Compare>
<Bad title="Assigning the result of an in-place method">

```text
hosts = ["web2", "web1"]
hosts = hosts.sort()          # hosts is now None
hosts.append("db1")           # AttributeError: 'NoneType' object has no attribute 'append'
```

</Bad>
<Good title="Either sort in place or keep the new list">

```text
hosts.sort()                  # in place, no assignment
ordered = sorted(hosts)       # or: a new list, original unchanged
```

</Good>
</Compare>

<Compare>
<Bad title="append when you meant extend">

```text
ports = [22, 80]
ports.append([443, 8443])
print(ports)                  # [22, 80, [443, 8443]]  <- a list inside the list
print(len(ports))             # 3
```

</Bad>
<Good title="extend adds each item">

```text
ports = [22, 80]
ports.extend([443, 8443])     # or: ports += [443, 8443]
print(ports)                  # [22, 80, 443, 8443]
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Checking `x in big_list` thousands of times**: a list search looks at every item; convert to a set first.
- **`list.pop(0)` in a loop on a big list**: every item shifts; use `collections.deque.popleft()`.
- **Sorting mixed types**: `sorted([3, "a"])` raises TypeError in Python 3.
- **Sorting version numbers or numeric text as strings**: use a key that converts them.
- **Using a list as a default argument** (`def f(items=[])`): it's shared between calls; use `None` and create the list inside.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Hazaron dafa `x in big_list` check karna**: list ki talash har item dekhti hai; pehle set me badlein.
- **Bari list par loop me `list.pop(0)`**: har item khiskta hai; `collections.deque.popleft()` lein.
- **Mili jhuli types sort karna**: Python 3 me `sorted([3, "a"])` TypeError deta hai.
- **Version numbers ya numeric text ko strings ki tarah sort karna**: badalne wali key lein.
- **Default argument me list** (`def f(items=[])`): calls ke beech mushtarak hoti hai; `None` lein aur andar list banayen.

</Ur>
</Tr>

</En>
<Ur>
Failed logins ke IPs ki list di ho, `["203.0.113.7", "198.51.100.4", "203.0.113.7", "192.0.2.10", "203.0.113.7", "198.51.100.4"]`, `(ip, count)` joron ki list banayen (har IP ek dafa, loop aur `count` se), ise ginti ulti tarteeb aur phir IP se sort karein, aur top 2 print karein.
</Ur>

<Solution>

<Tr>
<En>

```text
ips = ["203.0.113.7", "198.51.100.4", "203.0.113.7", "192.0.2.10", "203.0.113.7", "198.51.100.4"]
pairs = []
for ip in ips:
    if ip not in [p[0] for p in pairs]:
```

<DeepDive title="More about lists">

**Performance.** Lists are dynamic arrays: indexing and `append` are fast (constant time), while `insert(0, x)`, `pop(0)`, `remove` and `in` have to touch many items (linear time).

**Sorting internals.** Python uses Timsort, which is stable and very fast on partly sorted data. `operator.itemgetter(1)` and `attrgetter("name")` are faster, clearer alternatives to simple lambdas.

**bisect.** For a list kept sorted, `bisect.insort` inserts in order and `bisect.bisect_left` finds positions quickly.

**collections.deque.** A double-ended queue with fast appends and pops on both ends, and an optional `maxlen` for "keep the last N items" buffers.

**List unpacking.** `first, *rest = items` and `*init, last = items` split a list into parts; more in Slicing and Unpacking.

</DeepDive>

<DeepDive title="Real world: the sort that returned nothing">

A script that generated a weekly report of the largest S3 buckets had a line `buckets = buckets.sort(key=size, reverse=True)`. It worked in a quick test where the next line only printed `buckets` (it printed None, and nobody looked closely). In production, the next line `for b in buckets[:10]:` raised `TypeError: 'NoneType' object is not subscriptable`, and the report silently stopped arriving because the cron job's errors went to a mailbox nobody read.

The fixes:

1. `top = sorted(buckets, key=size, reverse=True)[:10]`.
2. A linter rule and code review habit: never assign the result of `.sort()`, `.append()` or `.reverse()`.
3. Exit codes and alerting on cron failures, as covered earlier.

</DeepDive>

<DeepDive title="Security lens">

- **Allow-lists as lists**: for anything checked often, use a set for speed, and normalise entries (case, whitespace) before comparing.
- **Bound list growth from untrusted input**: appending every line of a huge upload can exhaust memory; stream or cap it.
- **Mutable defaults leak data**: a `def handle(req, seen=[])` shares `seen` across every request and user.
- **Sorting user-controlled data with expensive keys** can be slow; keep keys simple.
- **Slices are copies of the references, not deep copies**: nested data is still shared.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What is the difference between sort() and sorted()?">
list.sort() sorts the list in place and returns None; sorted() accepts any iterable and returns a new sorted list, leaving the original unchanged.
</QA>

<QA q="What is the time complexity of common list operations?">
Indexing, assignment by index, append and pop from the end are O(1) on average; insert or pop at the front, remove, index, count and the in operator are O(n).
</QA>

<QA q="How would you sort records by two fields, one descending?">
Use a key returning a tuple, negating numeric fields that should be descending, for example key=lambda u: (-u.failures, u.name); or sort twice using stability, first by the secondary key, then by the primary.
</QA>

<QA q="Why is [[0] * 3] * 3 a problem?">
The outer multiplication repeats references to the same inner list, so all rows are one object and changing one cell changes every row. Build rows with a comprehension instead.
</QA>

<QA q="When would you use a deque instead of a list?">
When you need fast appends and pops at both ends, such as a queue or a sliding window, because list operations at the front are O(n).
</QA>

</DeepDive>
