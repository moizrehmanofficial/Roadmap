<BigIdea>
<Tr>
<En>
Every app needs a place where staff can look at data and fix it: find an order, correct a typo, publish a book. The **Django admin** builds that for you from your models. You **register** a model with a **`ModelAdmin`** class and describe the screens with options instead of templates: **`list_display`** for the columns, **`list_filter`** for the sidebar filters, **`search_fields`** for the search box (`author__name` follows a foreign key), **`readonly_fields`** for values staff may see but not change, **inlines** to edit related rows on the parent's page, and **actions** for bulk operations such as "mark selected as published". Because the admin is so powerful, it's also a favourite target, so you lock it down: only users with **`is_staff`** can enter, each model screen checks Django's **permissions** (view, add, change, delete) so a clerk can be view-only, you can override methods like **`has_delete_permission`** and **`get_queryset`** to remove actions or limit rows, a less obvious URL cuts bot noise, and every change is written to a **history log**. The admin is a tool for trusted staff, not a page for customers.
</En>
<Ur>
Har app ko aisi jagah chahiye jahan staff data dekh aur theek kar sake: order dhoondhna, typo durust karna, kitab publish karna. **Django admin** ye aap ke models se bana deta hai. Aap model ko **`ModelAdmin`** class ke saath **register** karte aur templates ke bajaye options se screens batate hain: columns ke liye **`list_display`**, sidebar filters ke liye **`list_filter`**, search box ke liye **`search_fields`** (`author__name` foreign key ke paar jata), un values ke liye **`readonly_fields`** jo staff dekh sake magar badal na sake, parent ke page par mutalliqa rows badalne ke liye **inlines**, aur "chuni hui ko published karo" jaise bulk kaamon ke liye **actions**. Kyunke admin itna taqatwar hai, ye pasandeeda nishana bhi hai, isliye aap use band karte hain: sirf **`is_staff`** wale users andar aa sakte, har model screen Django ki **permissions** (view, add, change, delete) check karti taa ke clerk sirf dekh sake, aap **`has_delete_permission`** aur **`get_queryset`** jaise methods override kar ke kaam hata ya rows mehdood kar sakte, kam wazeh URL bots ka shor ghatata, aur har tabdeeli **history log** me likhi jati hai. Admin bharosemand staff ka tool hai, customers ka page nahi.
</Ur>

## Picture it

<Tr>
<En>

Think of the **back room of a library**.

- Shelves are your tables, and the catalogue drawers are the admin lists: sorted by title, with tabs for "published" and "year" (filters) and an index you can search by author (search across a relation).
- The ISBN sticker can be read but not peeled off (read-only field), and a stamp can mark a whole cart of books as published at once (an action).
- The door says "Staff only" (`is_staff`). Inside, a new assistant has a key to look at the catalogue but not to change or throw out books (view permission only, delete removed).
- A logbook records who changed which card and when (admin history).

</En>
<Ur>

**Library ka pichhla kamra** socheyn.

- Shelves aap ki tables hain, aur catalogue ke daraz admin lists: title se tarteeb, "published" aur "year" ke tabs (filters) aur author se search hone wala index (rishte ke paar search).
- ISBN sticker parha ja sakta magar utara nahi (read-only field), aur ek muhr kitabon ki poori trolley ek saath published kar sakti (action).
- Darwaze par likha "Staff only" (`is_staff`). Andar naye assistant ke paas catalogue dekhne ki chabi hai magar kitaben badalne ya phenkne ki nahi (sirf view permission, delete hata hua).
- Ek logbook likhti ke kis ne kaun sa card kab badla (admin history).

</Ur>
</Tr>

## Learn it step by step

<Walkthrough>

<Step title="Register models and build the screens">

<Tr>
<En>
We create a `catalog` app with `Author` and `Book` models and register both. `BookAdmin` sets columns, filters, search (including the author's name), ordering, a read-only ISBN and a custom action; `AuthorAdmin` shows the author's books inline. A script logs in as a superuser with Django's test client and uses the real admin pages: the list, a search, two filters, the action, the edit page and the author page.
</En>
<Ur>
Hum `Author` aur `Book` models wali `catalog` app banate aur dono register karte hain. `BookAdmin` columns, filters, search (author ke naam samet), tarteeb, read-only ISBN aur custom action set karta; `AuthorAdmin` author ki books inline dikhata. Script Django ke test client se superuser ban kar login karti aur asal admin pages istemal karti hai: list, search, do filters, action, edit page aur author page.
</Ur>
</Tr>

```bash
export UV_EXCLUDE_NEWER=2025-06-01T00:00:00Z
uv venv -q --python 3.13 .venv && uv pip install -q --python .venv "django==5.2.1"
. .venv/bin/activate
mkdir library && django-admin startproject config library && cd library && python manage.py startapp catalog
sed -i 's/    "django.contrib.staticfiles",/    "django.contrib.staticfiles",\n    "catalog",/' config/settings.py
cat > catalog/models.py <<'EOF'
from django.db import models

class Author(models.Model):
    name = models.CharField(max_length=100)

    def __str__(self):
        return self.name

class Book(models.Model):
    title = models.CharField(max_length=200)
    author = models.ForeignKey(Author, on_delete=models.PROTECT, related_name="books")
    year = models.PositiveSmallIntegerField()
    published = models.BooleanField(default=False)
    isbn = models.CharField(max_length=13, unique=True)

    def __str__(self):
        return self.title
EOF
cat > catalog/admin.py <<'EOF'
from django.contrib import admin, messages
from .models import Author, Book

class BookInline(admin.TabularInline):              # edit an author's books on the author page
    model = Book
    extra = 0

@admin.register(Author)
class AuthorAdmin(admin.ModelAdmin):
    search_fields = ["name"]
    inlines = [BookInline]

@admin.register(Book)
class BookAdmin(admin.ModelAdmin):
    list_display = ["title", "author", "year", "published"]   # columns
    list_filter = ["published", "year"]                        # sidebar filters
    search_fields = ["title", "author__name"]                  # search box, follows the foreign key
    ordering = ["title"]
    readonly_fields = ["isbn"]                                 # visible, not editable
    list_select_related = ["author"]                           # one query for the list
    actions = ["mark_published"]

    @admin.action(description="Mark selected books as published")
    def mark_published(self, request, queryset):
        updated = queryset.update(published=True)
        self.message_user(request, f"{updated} book(s) marked as published.", messages.SUCCESS)
EOF
python manage.py makemigrations catalog -v 0 && python manage.py migrate -v 0
python manage.py check
cat > try_admin.py <<'EOF'

os.environ.setdefault("DJANGO_SETTINGS_MODULE", "config.settings"); django.setup()
logging.disable(logging.WARNING)
from django.contrib.auth.models import User
from django.test import Client
from catalog.models import Author, Book

User.objects.create_superuser("admin", "admin@example.com", "correct-horse-battery-staple")
ada = Author.objects.create(name="Ada Lane")
sam = Author.objects.create(name="Sam Fisher")
Book.objects.create(title="Clean Pipelines", author=ada, year=2023, isbn="9780000000001")
Book.objects.create(title="Secure APIs", author=ada, year=2024, isbn="9780000000002", published=True)
Book.objects.create(title="Django Basics", author=sam, year=2024, isbn="9780000000003")

c = Client(HTTP_HOST="localhost")
c.login(username="admin", password="correct-horse-battery-staple")

def titles(url):
    html = c.get(url).content.decode()
    return re.findall(r'<th class="field-title"><a [^>]*>(.*?)</a>', html)

print("all books:     ", titles("/admin/catalog/book/"))
print("search 'ada':  ", titles("/admin/catalog/book/?q=ada"))
print("unpublished:   ", titles("/admin/catalog/book/?published__exact=0"))
print("year 2024:     ", titles("/admin/catalog/book/?year=2024"))

ids = [str(b.pk) for b in Book.objects.filter(published=False)]
r = c.post("/admin/catalog/book/", {"action": "mark_published", "_selected_action": ids}, follow=True)
print("action message:", re.findall(r'<li class="success">(.*?)</li>', r.content.decode()))
print("published now: ", Book.objects.filter(published=True).count(), "of", Book.objects.count())

edit = c.get(f"/admin/catalog/book/{Book.objects.get(title='Secure APIs').pk}/change/").content.decode()
print("isbn editable: ", 'name="isbn"' in edit, "| isbn shown:", "9780000000002" in edit)
author_page = c.get(f"/admin/catalog/author/{ada.pk}/change/").content.decode()
print("inline books on author page:", author_page.count('name="books-') > 0)
EOF
```

- `manage.py check` found **no issues**, so the admin options are valid (Django checks names in `list_display` and similar options at startup).

<Step title="Lock the admin down">

<Tr>
<En>
Now we harden it: move the admin to a non-default URL, set a header, and re-register `Book` with a subclass that blocks deleting. A script then tries the admin as different people: an anonymous visitor, a logged-in user who isn't staff, a staff user with no permissions, the same user with only `view_book`, and a superuser. Finally the superuser edits a book and we read the admin's history log.
</En>
<Ur>
Ab hum ise mazboot karte hain: admin ko ghair-default URL par le jana, header set karna, aur `Book` ko aisi subclass ke saath dobara register karna jo delete rokti hai. Phir script mukhtalif logon ki tarah admin aazmati hai: anjaan visitor, login user jo staff nahi, bina permissions wala staff user, sirf `view_book` wala wahi user, aur superuser. Aakhir me superuser ek book badalta aur hum admin ka history log parhte hain.
</Ur>
</Tr>

```bash
. .venv/bin/activate && cd library
sed -i 's|    path("admin/", admin.site.urls),|    path("staff-portal-7f3a/", admin.site.urls),|' config/urls.py
cat >> config/urls.py <<'EOF'

admin.site.site_header = "Library back office"
EOF
cat >> catalog/admin.py <<'EOF'

admin.site.unregister(Book)

@admin.register(Book)
class LockedBookAdmin(BookAdmin):
    def has_delete_permission(self, request, obj=None):   # nobody deletes books here, not even superusers
        return False
EOF
cat > try_lockdown.py <<'EOF'
import os, re, django, logging
os.environ.setdefault("DJANGO_SETTINGS_MODULE", "config.settings"); django.setup()
logging.disable(logging.WARNING)
from django.contrib.admin.models import LogEntry
from django.contrib.auth.models import Permission, User
from django.test import Client
from catalog.models import Book

A = "/staff-portal-7f3a"
anon = Client(HTTP_HOST="localhost")
print("old /admin/ URL:", anon.get("/admin/").status_code)
r = anon.get(f"{A}/catalog/book/")
print("anonymous:", r.status_code, "->", r.url)

User.objects.create_user("reader", password="a-long-reader-pass")            # not staff
c = Client(HTTP_HOST="localhost"); c.login(username="reader", password="a-long-reader-pass")
print("non-staff user:", c.get(f"{A}/").status_code)

clerk = User.objects.create_user("clerk", password="a-long-clerk-pass", is_staff=True)
c = Client(HTTP_HOST="localhost"); c.login(username="clerk", password="a-long-clerk-pass")
print("staff, no permissions: index", c.get(f"{A}/").status_code, "| book list", c.get(f"{A}/catalog/book/").status_code)

clerk.user_permissions.add(Permission.objects.get(codename="view_book"))
book = Book.objects.get(title="Secure APIs")
page = c.get(f"{A}/catalog/book/{book.pk}/change/")
print("with view_book: list", c.get(f"{A}/catalog/book/").status_code,
      "| add", c.get(f"{A}/catalog/book/add/").status_code,
      "| change page", page.status_code, "| save button:", 'name="_save"' in page.content.decode())

admin = Client(HTTP_HOST="localhost"); admin.login(username="admin", password="correct-horse-battery-staple")
listing = admin.get(f"{A}/catalog/book/").content.decode()
print("superuser: delete page", admin.get(f"{A}/catalog/book/{book.pk}/delete/").status_code,
      "| delete action offered:", "delete_selected" in listing, "| header:", "Library back office" in listing)

admin.post(f"{A}/catalog/book/{book.pk}/change/",
           {"title": "Secure APIs, 2nd ed.", "author": book.author_id, "year": 2024, "published": "on"})
for e in LogEntry.objects.all():
    print("history:", e.user.username, e.get_action_flag_display(), repr(e.object_repr), e.get_change_message())
EOF
python try_lockdown.py
```

```text output
old /admin/ URL: 404
anonymous: 302 -> /staff-portal-7f3a/login/?next=/staff-portal-7f3a/catalog/book/
non-staff user: 302
staff, no permissions: index 200 | book list 403
with view_book: list 200 | add 403 | change page 200 | save button: False
superuser: delete page 403 | delete action offered: False | header: True
history: admin Change 'Secure APIs, 2nd ed.' Changed Title.
```

<Happened>
<Tr>
<En>

- The old `/admin/` path now returns **404**. This doesn't make the admin secure on its own, but it removes it from automated scans that hammer `/admin/login/`.
- An anonymous visitor was **redirected to the login page** with `next=` set, and a logged-in user without `is_staff` was redirected too: being a user isn't enough.
- A staff user with no permissions could open the index (which would say there's nothing to manage) but got **403** on the book list. Permissions are checked per model.
- With only `view_book`, the list and the change page opened, but **add** returned 403 and the change page had **no Save button**: a true read-only account.
- Even the superuser got **403** on the delete page, and the "delete selected" action disappeared, because `has_delete_permission` returns False. Overriding these methods is how you enforce rules beyond the standard permissions.
- The superuser's edit created a **LogEntry**: who, what kind of change, which object and which field. Note that bulk actions using `update()` don't write history unless you log them yourself.

</En>
<Ur>

- Purana `/admin/` path ab **404** deta hai. Ye akela admin ko mehfooz nahi banata, magar use un automated scans se hata deta jo `/admin/login/` par baar baar hamla karte hain.
- Anjaan visitor ko `next=` ke saath **login page par bheja** gaya, aur `is_staff` ke baghair login user ko bhi: sirf user hona kaafi nahi.
- Bina permissions wala staff user index khol saka (jo kehta ke sambhalne ko kuch nahi) magar book list par **403** mila. Permissions har model par check hoti hain.
- Sirf `view_book` ke saath list aur change page khule, magar **add** ne 403 diya aur change page par **Save button nahi** tha: sahi read-only account.
- Superuser ko bhi delete page par **403** mila, aur "delete selected" action ghayab ho gaya, kyunke `has_delete_permission` False lautata hai. In methods ko override karna aam permissions se aage qawaid lagu karne ka tareeqa hai.
- Superuser ki tabdeeli ne **LogEntry** banayi: kaun, kis qism ki tabdeeli, kaun sa object aur kaun sa field. Yaad rahe ke `update()` wale bulk actions history nahi likhte jab tak aap khud log na karein.

</Ur>

## Common mistakes

<Compare>
<Bad title="Everyone is a superuser">

```text
# "just make them superuser so they can work"
for u in User.objects.filter(team="support"):
    u.is_superuser = True
    u.is_staff = True
    u.save()
# one phished support account = full control of every table
```

</Bad>
<Good title="Groups with the smallest permissions needed">

```text
support = Group.objects.create(name="Support")
support.permissions.add(*Permission.objects.filter(codename__in=["view_order", "change_order"]))
user.is_staff = True
user.groups.add(support)
```

</Good>
</Compare>

<Compare>
<Bad title="A slow, unguarded list page">

```text
class OrderAdmin(admin.ModelAdmin):
    list_display = ["id", "customer", "product"]   # 2 extra queries per row
    # no search, no filters, deletes allowed for every staff user
```

</Bad>
<Good title="Fast and restricted">

```text
import django
from django.conf import settings
settings.configure(
    INSTALLED_APPS=["django.contrib.contenttypes", "django.contrib.auth", "django.contrib.admin"],
    DATABASES={"default": {"ENGINE": "django.db.backends.sqlite3", "NAME": ":memory:"}},

django.setup()

from django.contrib import admin
from django.db import connection, models
from django.test import RequestFactory

class Product(models.Model):
    name = models.CharField(max_length=100)
    stock = models.PositiveIntegerField()
    class Meta:
        app_label = "shop"

class StockFilter(admin.SimpleListFilter):
    title = "stock level"
    parameter_name = "stock"

    def lookups(self, request, model_admin):
        return [("out", "Out of stock"), ("low", "Low (1-5)"), ("ok", "In stock")]

    def queryset(self, request, queryset):
        if self.value() == "out":
            return queryset.filter(stock=0)
        if self.value() == "low":
            return queryset.filter(stock__range=(1, 5))
        if self.value() == "ok":
            return queryset.filter(stock__gt=5)
        return queryset

class ProductAdmin(admin.ModelAdmin):
    list_display = ["name", "stock", "stock_status"]
    list_filter = [StockFilter]

    @admin.display(description="Status", ordering="stock")
    def stock_status(self, obj):
        if obj.stock == 0:
            return "OUT"
        return "low" if obj.stock <= 5 else "ok"

with connection.schema_editor() as editor:
    editor.create_model(Product)
for name, stock in [("Desk lamp", 0), ("Notebook", 3), ("Pen pack", 40), ("Mug", 5)]:
    Product.objects.create(name=name, stock=stock)

ma = ProductAdmin(Product, admin.site)
for p in Product.objects.order_by("name"):
    print(f"{p.name:10} {p.stock:>3}  {ma.stock_status(p)}")

rf = RequestFactory()
for choice in ["out", "low", "ok"]:
    request = rf.get("/", {"stock": choice})
    f = StockFilter(request, request.GET.copy(), Product, ma)
    print(choice, "->", sorted(f.queryset(request, Product.objects.all()).values_list("name", flat=True)))
print("column header:", ProductAdmin.stock_status.short_description, "| sortable by:", ProductAdmin.stock_status.admin_order_field)
```

```text
import django
from django.conf import settings
settings.configure(
    INSTALLED_APPS=["django.contrib.contenttypes", "django.contrib.auth", "django.contrib.admin"],
    DATABASES={"default": {"ENGINE": "django.db.backends.sqlite3", "NAME": ":memory:"}},
    USE_I18N=False,
)
django.setup()

from django.contrib import admin
```
```text
from django.contrib.auth.models import User
from django.core.management import call_command
from django.db import connection, models
from django.test import RequestFactory

class Ticket(models.Model):
    subject = models.CharField(max_length=100)
    owner = models.ForeignKey(User, on_delete=models.CASCADE)
    class Meta:
        app_label = "support"

class TicketAdmin(admin.ModelAdmin):
    exclude = ["owner"]                                  # never chosen in the form

    def get_queryset(self, request):                     # list and lookups: own rows only
        qs = super().get_queryset(request)
        return qs if request.user.is_superuser else qs.filter(owner=request.user)

    def has_change_permission(self, request, obj=None):  # object-level check as a second guard
        if obj is not None and not request.user.is_superuser:
            return obj.owner_id == request.user.id
        return True

    def save_model(self, request, obj, form, change):    # owner comes from the session, not the form
        if not change:
            obj.owner = request.user
        super().save_model(request, obj, form, change)

call_command("migrate", verbosity=0)
with connection.schema_editor() as editor:
    editor.create_model(Ticket)

jane = User.objects.create_user("jane")
omar = User.objects.create_user("omar")
boss = User.objects.create_superuser("boss")
Ticket.objects.create(subject="VPN down", owner=jane)
Ticket.objects.create(subject="Printer jam", owner=omar)

ma = TicketAdmin(Ticket, admin.site)
rf = RequestFactory()
def req(user):
    r = rf.get("/"); r.user = user; return r

for u in (jane, omar, boss):
    print(f"{u.username:5} sees", sorted(ma.get_queryset(req(u)).values_list("subject", flat=True)))

printer = Ticket.objects.get(subject="Printer jam")
print("jane may change omar's ticket:", ma.has_change_permission(req(jane), printer))
print("omar may change his ticket:   ", ma.has_change_permission(req(omar), printer))

t = Ticket(subject="Laptop slow", owner=boss)            # pretend the form tried to set another owner
ma.save_model(req(jane), t, form=None, change=False)
print("new ticket owner:", Ticket.objects.get(subject="Laptop slow").owner.username)
print("owner field in the form:", "owner" in ma.get_form(req(jane))().fields)

# jane  sees ['VPN down']
# omar  sees ['Printer jam']
# boss  sees ['Printer jam', 'VPN down']
# jane may change omar's ticket: False
# omar may change his ticket:    True
# new ticket owner: jane
# owner field in the form: False
```

<DeepDive title="More about the admin">

**fieldsets.** Group fields on the edit page into sections, with collapsible advanced options.

**autocomplete_fields.** Replace huge dropdowns of foreign keys with a searchable widget.

**date_hierarchy.** Drill down a list by year, month and day.

**Custom admin views.** `get_urls` adds pages such as reports to a ModelAdmin.

**Multiple AdminSites.** A separate site for a team, with its own URL and registered models.

</DeepDive>

<DeepDive title="Real world: the forgotten demo account">

A startup created an `admin` superuser with a simple password for a demo and never removed it. The admin lived at the default `/admin/` path and was open to the internet. A credential-stuffing bot found it within weeks and downloaded the customer table through the admin's export plugin.

The fixes:

1. Removed shared and demo accounts, moved every staff member to a personal account in a Group with limited permissions.
2. Added two-factor login and rate limiting on the admin login.
3. Restricted the admin to the company VPN at the reverse proxy, and alerted on admin logins from new locations.

</DeepDive>

<DeepDive title="Security lens">

- **Least privilege**: few superusers; staff get Groups with only the permissions their job needs.
- **Strong authentication**: unique accounts, long passwords, 2FA, login rate limits.
- **Network limits**: VPN or IP allow-lists for the admin where possible, always HTTPS.
- **Row-level rules**: `get_queryset` and object-level checks for multi-tenant or per-owner data.
- **Audit**: review LogEntry, and log bulk actions and exports yourself.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What is a ModelAdmin?">
A class that configures how a model appears in the Django admin, including list columns, filters, search, forms, inlines, actions and permission hooks.
</QA>

<QA q="Who can log in to the Django admin?">
Active users with is_staff set to True; what they can see and do is then controlled by per-model permissions, while superusers have every permission.
</QA>

<QA q="How would you make one model read-only for a group of staff?">
Give the group only the view permission for that model, or override has_add_permission, has_change_permission and has_delete_permission to return False for them.
</QA>

<QA q="How do you restrict which rows a staff user sees?">
Override get_queryset to filter by the user, and add object-level checks in has_change_permission, since the admin looks up objects through get_queryset.
</QA>

<QA q="How do you avoid N+1 queries in an admin list?">
Use list_select_related or override get_queryset with select_related or prefetch_related for the columns that follow relations.
</QA>

</DeepDive>
