<BigIdea>
<Tr>
<En>
A **variable** in Python is a **name that points to a value**. `failed_attempts = 3` creates the integer object `3` and attaches the label `failed_attempts` to it. You don't declare variables or write their types: the **value** carries the type, and the same name can later point at a different value (**rebinding**). Because names are labels, two names can point to the **same object**: change a list through one name and the other "sees" the change. Every value has a **type** that decides what operations make sense: **int** and **float** for numbers, **str** for text, **bool** for True/False, **None** for "no value", and containers like **list**, **tuple**, **dict** and **set**. Data from files, the network or the keyboard arrives as **text**, so you **convert** it on purpose with `int()`, `float()` or `str()`, and handle the `ValueError` when the text isn't a valid number. Finally, every value is either **truthy** or **falsy**: zero, empty and `None` count as false in an `if`.
</En>
<Ur>
Python me **variable** ek **naam hai jo kisi value ki taraf ishara karta hai**. `failed_attempts = 3` integer object `3` banata aur us par `failed_attempts` ka label lagata hai. Aap variables declare nahi karte na un ki types likhte hain: **value** type rakhti hai, aur wahi naam baad me kisi aur value ki taraf ishara kar sakta hai (**rebinding**). Kyunke naam labels hain, do naam **ek hi object** ki taraf ishara kar sakte hain: ek naam se list badlein to doosra bhi tabdeeli "dekhta" hai. Har value ki ek **type** hoti hai jo tay karti hai kaunse kaam bante hain: numbers ke liye **int** aur **float**, text ke liye **str**, True/False ke liye **bool**, "koi value nahi" ke liye **None**, aur **list**, **tuple**, **dict** aur **set** jaise containers. Files, network ya keyboard se data **text** ban kar aata hai, isliye aap use `int()`, `float()` ya `str()` se jaan boojh kar **convert** karte hain, aur jab text durust number na ho to `ValueError` sambhalte hain. Aakhir me har value ya to **truthy** hoti hai ya **falsy**: `if` me zero, khaali aur `None` false gine jate hain.
</Ur>

## Picture it

<Tr>
<En>

Think of **luggage tags at an airport**.

- A suitcase is a value; a tag with a name on it is a variable. Writing `user = "jane"` ties a tag to a suitcase.
- Moving a tag to another suitcase is rebinding; the first suitcase doesn't change.
- Two tags can hang on the same suitcase. Open the suitcase using either tag, add a shirt, and whoever uses the other tag finds the shirt too (two names, one list).
- The kind of luggage is the type: a backpack, a box, a guitar case. What you can do depends on the luggage, not the tag.

</En>
<Ur>

**Airport par saamaan ke tags** socheyn.

- Suitcase value hai; naam wala tag variable. `user = "jane"` likhna suitcase se tag baandhna hai.
- Tag ko doosre suitcase par le jana rebinding hai; pehla suitcase nahi badalta.
- Ek suitcase par do tags lag sakte hain. Kisi bhi tag se suitcase kholein, qameez daalein, aur doosra tag istemal karne wala bhi qameez paata hai (do naam, ek list).
- Saamaan ki qism type hai: backpack, dabba, guitar case. Kya kar sakte hain ye saamaan par mabni hai, tag par nahi.

</Ur>

## Learn it step by step

<Walkthrough>

<Step title="Names, assignment and shared objects">

<Tr>
<En>
`variables.py` creates a few variables, checks a type, rebinds a name (even to a different type), assigns several names at once, swaps two values, points two names at one list, and uses an UPPER_CASE constant. Then four one-liners test the naming rules: a name starting with a digit, a keyword as a name, case sensitivity, and using a name that was never assigned.
</En>
<Ur>
`variables.py` kuch variables banati, ek type check karti, ek naam dobara jorti (doosri type se bhi), kayi naam ek saath assign karti, do values adal badal karti, do naam ek list ki taraf karti, aur UPPER_CASE constant istemal karti hai. Phir chaar one-liners naam ke qaide test karte hain: digit se shuru hone wala naam, keyword naam ki tarah, chhote bare haroof ka farq, aur kabhi assign na hua naam istemal karna.
</Ur>
</Tr>

```bash
cat > variables.py <<'EOF'
# A variable is a NAME that points to a value (an object). No declarations, no types written.
user = "jane"
failed_attempts = 3
is_locked = False
print(user, failed_attempts, is_locked)

# The value has a type; the name doesn't. A name can be pointed at something else.
print(type(failed_attempts))
failed_attempts = failed_attempts + 1      # rebinding: now points to 4
print("after one more failure:", failed_attempts)
failed_attempts = "four"                   # allowed, but confusing: avoid changing a name's type
print(type(failed_attempts))

# Several names at once, and the classic swap without a temporary variable
host, port = "example.test", 443
a, b = 1, 2
a, b = b, a
print(host, port, "| swapped:", a, b)

# Two names can point to the SAME object
servers = ["web1", "web2"]
backup = servers                           # not a copy!
backup.append("web3")
print("servers:", servers, "| same object?", servers is backup)

# Constants are a naming convention (UPPER_CASE); Python doesn't enforce them
MAX_ATTEMPTS = 5
print("locked?", 4 >= MAX_ATTEMPTS)
EOF
python3 variables.py
# Names: letters, digits, underscores; can't start with a digit; case matters; no keywords
python3 -c '2fa_enabled = True' 2>&1 | tail -1
python3 -c 'class = "admin"' 2>&1 | tail -1
python3 -c 'User = 1; user = 2; print(User, user)'
python3 -c 'print(retry_count)' 2>&1 | tail -1
```

```text output
jane 3 False
<class 'int'>
after one more failure: 4
<class 'str'>
example.test 443 | swapped: 2 1
servers: ['web1', 'web2', 'web3'] | same object? True
locked? False
SyntaxError: invalid decimal literal
SyntaxError: invalid syntax
1 2
NameError: name 'retry_count' is not defined
```

<Happened>
<Tr>
<En>

- No variable was declared: `user`, `failed_attempts` and `is_locked` came into existence when first assigned, and `type()` reported **`<class 'int'>`** from the value.
- `failed_attempts = failed_attempts + 1` **read** the old value (3), computed 4, then pointed the name at 4. Python happily let us rebind it to the string `"four"` too, which is legal but makes code hard to follow; keep one type per name.
- `host, port = "example.test", 443` assigned both at once, and `a, b = b, a` **swapped** without a temporary variable: the right side is built first, then unpacked.
- `backup = servers` did **not** copy the list: both names point at the same object (`is` said **True**), so appending through `backup` changed `servers`. Use `servers.copy()` or `list(servers)` for a real copy; you'll see more in Mutability and Copying.
- Naming rules: `2fa_enabled` is a **SyntaxError** (can't start with a digit), `class` is a reserved **keyword**, `User` and `user` are **different** names, and reading a name that was never assigned raises **NameError**, usually a typo.

</En>
<Ur>

- Koi variable declare nahi hua: `user`, `failed_attempts` aur `is_locked` pehli assignment par wujood me aaye, aur `type()` ne value se **`<class 'int'>`** bataya.
- `failed_attempts = failed_attempts + 1` ne purani value (3) **parhi**, 4 banaya, phir naam ko 4 ki taraf kiya. Python ne use string `"four"` se dobara jorne bhi diya, jo jaaiz hai magar code samajhna mushkil banata; har naam ki ek type rakhein.
- `host, port = "example.test", 443` ne dono ek saath assign kiye, aur `a, b = b, a` ne aarzi variable ke baghair **adla badli** ki: daayan hissa pehle banta, phir khulta hai.
- `backup = servers` ne list **copy nahi** ki: dono naam ek hi object ki taraf hain (`is` ne **True** kaha), isliye `backup` ke zariye append ne `servers` badal diya. Asal copy ke liye `servers.copy()` ya `list(servers)` lein; Mutability and Copying me mazeed dekhenge.
- Naam ke qaide: `2fa_enabled` **SyntaxError** hai (digit se shuru nahi ho sakta), `class` mehfooz **keyword** hai, `User` aur `user` **alag** naam hain, aur kabhi assign na hua naam parhna **NameError** deta hai, aam taur par typo.

</Ur>
</Tr>
</Happened>

<Step title="Built-in types, conversions and truthiness">

<Tr>
<En>
`types.py` prints the type name and representation (`!r`) of one value of each built-in type. `convert.py` then shows the difference between text and numbers, the conversion functions, number bases, what happens when conversion fails, which values are truthy or falsy, the fact that `bool` is a kind of `int`, and a famous float surprise.
</En>
<Ur>
`types.py` har built-in type ki ek value ka type naam aur representation (`!r`) print karti hai. Phir `convert.py` text aur numbers ka farq, conversion functions, number bases, conversion nakam hone par kya hota hai, kaunsi values truthy ya falsy hain, ye baat ke `bool` ek qism ka `int` hai, aur float ka mash-hoor tajjub dikhati hai.
</Ur>
</Tr>

```bash
cat > types.py <<'EOF'
values = [42, 3.14, "admin", True, None, [22, 80], (10, 20), {"user": "jane"}, {443, 22, 80}]
for v in values:
    print(f"{type(v).__name__:<9} {v!r}")
EOF
python3 types.py
cat > convert.py <<'EOF'
# Input from files, the network and input() is TEXT. Convert it on purpose.
port_text = "8080"
print(port_text + "1", "vs", int(port_text) + 1)        # text joins, numbers add
print(float("2.5"), str(404) + " Not Found", int(3.99), round(3.99))
print(int("0x1F", 16), int("101", 2), hex(255), bin(5))

for bad in ["4.5", "abc", ""]:
    try:
        int(bad)
    except ValueError as e:
        print("ValueError:", e)

# Truthiness: empty and zero values count as False in an if
for v in [0, 0.0, "", [], {}, None, "0", "False", [0], -1]:
    print(f"{v!r:>7} -> {bool(v)}")

print(isinstance(True, int), True + True)                # bool is a kind of int
print(0.1 + 0.2 == 0.3, 0.1 + 0.2)                       # floats are approximate
EOF
python3 convert.py
```

<Happened>
<Tr>
<En>

- Nine values, nine types. `!r` shows the **representation**: strings get quotes (`'admin'`), so you can tell `'42'` from `42` when debugging.
- The set printed as **`{80, 443, 22}`**, not in the order written: sets have **no order**, only membership. Never rely on a set's printed order.
- `"8080" + "1"` gave **`80801`** (joining text) while `int("8080") + 1` gave **8081**. Input from `input()`, files, URLs and environment variables is always text: convert it first.
- `int(3.99)` **cut off** the decimals (3) while `round(3.99)` gave 4. `int()` with a base parsed hex and binary text; `hex()` and `bin()` go the other way.
- `int("4.5")`, `int("abc")` and `int("")` all raised **ValueError**. Catching it with `try`/`except` lets a program reject bad input politely instead of crashing.
- Falsy values: **0, 0.0, empty string, empty list, empty dict, None**. Everything else is truthy, including the strings `"0"` and `"False"` and the list `[0]`. So `bool("False")` is True; compare text explicitly (`answer == "yes"`).
- `True + True` is **2** because bool is a subclass of int. And `0.1 + 0.2` is **0.30000000000000004**: floats are binary approximations, so compare with tolerance (`math.isclose`) and use `decimal.Decimal` for money.

</En>
<Ur>

- Nau values, nau types. `!r` **representation** dikhata hai: strings ko quotes milte (`'admin'`), isliye debugging me `'42'` aur `42` me farq pata chalta hai.
- Set **`{80, 443, 22}`** print hua, likhi tarteeb me nahi: sets ki **koi tarteeb nahi**, sirf mojoodgi. Set ki print tarteeb par kabhi bharosa na karein.
- `"8080" + "1"` ne **`80801`** diya (text jorna) jabke `int("8080") + 1` ne **8081**. `input()`, files, URLs aur environment variables se input hamesha text hota hai: pehle convert karein.
- `int(3.99)` ne aashariya **kaat** diya (3) jabke `round(3.99)` ne 4 diya. Base ke saath `int()` ne hex aur binary text parha; `hex()` aur `bin()` ulti taraf jate hain.
- `int("4.5")`, `int("abc")` aur `int("")` sab ne **ValueError** diya. `try`/`except` se pakarna program ko crash ke bajaye tameez se kharab input radd karne deta hai.
- Falsy values: **0, 0.0, khaali string, khaali list, khaali dict, None**. Baqi sab truthy, strings `"0"` aur `"False"` aur list `[0]` samait. Isliye `bool("False")` True hai; text ko saaf saaf milayen (`answer == "yes"`).
- `True + True` **2** hai kyunke bool int ka subclass hai. Aur `0.1 + 0.2` **0.30000000000000004** hai: floats binary andaze hain, isliye gunjaish ke saath milayen (`math.isclose`) aur paise ke liye `decimal.Decimal` lein.

</Ur>

## Common mistakes

<Compare>
<Bad title="Treating input text as a number">

```text
age = input("Age: ")          # "17"
if age >= 18:                 # TypeError: '>=' not supported between instances of 'str' and 'int'
    ...
total = "10" + 5              # TypeError: can only concatenate str (not "int") to str
```

</Bad>
<Good title="Convert, and handle bad input">

```text
text = input("Age: ")
try:
    age = int(text)
except ValueError:
    print("Please enter a whole number")
else:
    print("adult" if age >= 18 else "minor")
```

</Good>
</Compare>

<Compare>
<Bad title="Assuming = copies a list">

```text
defaults = ["read"]
admin_perms = defaults
admin_perms.append("delete")
print(defaults)               # ['read', 'delete']  <- every user just got delete
```

</Bad>
<Good title="Make a copy when you mean a copy">

```text
defaults = ["read"]
admin_perms = defaults.copy()      # or list(defaults), or defaults[:]
admin_perms.append("delete")
print(defaults)               # ['read']
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Shadowing built-ins**: naming a variable `list`, `str`, `type`, `id` or `input` hides the built-in function for the rest of the file.
- **Using `is` to compare values**: `x is 1000` may be False even when `x == 1000`; use `is` only for `None` (`x is None`).
- **`bool("False")` expecting False**: any non-empty string is truthy.
- **Comparing floats with `==`**: use `math.isclose()` or round first.
- **Vague names** like `x`, `data2`, `tmp`: name variables by what they hold (`failed_logins`, `server_ip`).

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Built-ins ko chhupana**: variable ka naam `list`, `str`, `type`, `id` ya `input` rakhna baqi file ke liye built-in function chhupa deta hai.
- **Values milane ke liye `is`**: `x == 1000` hone par bhi `x is 1000` False ho sakta; `is` sirf `None` ke liye (`x is None`).
- **`bool("False")` se False ki tawaqqo**: har na-khaali string truthy hai.
- **Floats ko `==` se milana**: `math.isclose()` lein ya pehle round karein.
- **Mubham naam** jaise `x`, `data2`, `tmp`: variables ka naam us cheez par rakhein jo un me hai (`failed_logins`, `server_ip`).

</Ur>
</Tr>

A config file line reads `max_retries=5`. Split it into a name and a value (`line.split("=")`), convert the value to an int, add 1, and print `max_retries is now 6`. Then try the line `max_retries=five` and print a friendly error instead of crashing.

<Solution>

<Tr>

```text
for line in ["max_retries=5", "max_retries=five"]:
    name, value = line.split("=")
    try:
        number = int(value)
    except ValueError:
        print(f"{name}: expected a whole number, got {value!r}")
        continue
    print(f"{name} is now {number + 1}")

# max_retries is now 6
# max_retries: expected a whole number, got 'five'
```

<DeepDive title="More about Python's object model">

**Everything is an object.** Numbers, strings, functions, classes and modules all have a type, an identity (`id()`) and a value. Variables store references to them.

**Small integer caching.** CPython reuses objects for small integers (-5 to 256) and some strings, which is why `is` sometimes appears to work for values. It's an implementation detail; never rely on it.

**Strong and dynamic typing.** Python is dynamic (types checked at run time) but strong (it won't silently turn `"10" + 5` into 15 like some languages). Type hints add optional static checking, covered later.

**Garbage collection.** When no names refer to an object any more, CPython frees it (reference counting plus a cycle collector), so you rarely manage memory yourself.

**Other useful types.** `bytes` for raw data (network, files, crypto), `complex`, `Decimal` and `Fraction` for exact arithmetic, `datetime` for dates.

</DeepDive>

<DeepDive title="Real world: the string that wasn't a number">

A billing script read usage limits from environment variables: `LIMIT = os.environ.get("API_LIMIT", 1000)`. Locally, with the variable unset, `LIMIT` was the int 1000 and comparisons worked. In production the variable was set, so `LIMIT` was the string `"5000"`, and `if requests_made > LIMIT:` raised a TypeError on the first comparison, stopping the nightly job.

The fixes:

1. Convert explicitly: `LIMIT = int(os.environ.get("API_LIMIT", "1000"))`, so both paths give an int.
2. Validate config at startup and exit with a clear message if conversion fails.
3. A test that sets the variable as a string, like production does.

</DeepDive>

<DeepDive title="Security lens">

- **All external input is text and untrusted**: convert, check ranges (a port is 1 to 65535) and reject the rest.
- **Don't use `eval()` to convert input**: `eval("__import__('os').system('...')")` runs code; use `int()`, `float()`, `json.loads()` or `ast.literal_eval()`.
- **Truthiness bugs can be security bugs**: `if user.is_admin:` where `is_admin` came from a form as the string `"false"` is truthy.
- **Shared mutable defaults** (one list for every user) can leak data between users or requests; copy when needed.
- **Floats for money** cause rounding errors attackers can sometimes exploit; use integer cents or `Decimal`.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What is a variable in Python?">
A name bound to an object. Assignment binds the name to the object on the right; the object has the type, and the name can later be rebound to another object.
</QA>

<QA q="What is the difference between == and is?">
`==` compares values, calling the type's equality method. `is` checks whether two names refer to the same object. Use `is` for singletons like None.
</QA>

<QA q="Which built-in types are mutable?">
list, dict, set, bytearray and most user-defined objects are mutable. int, float, bool, str, tuple, frozenset and bytes are immutable.
</QA>

<QA q="What values are falsy in Python?">
False, None, numeric zeros, and empty containers or strings such as empty str, list, tuple, dict and set, plus objects whose `__bool__` or `__len__` says so.
</QA>

<QA q="Why is 0.1 + 0.2 not equal to 0.3?">
Floats are stored in binary, which can't represent 0.1 or 0.2 exactly, so the sum is a tiny bit off. Compare with math.isclose or use Decimal for exact decimal arithmetic.
</QA>

</DeepDive>
