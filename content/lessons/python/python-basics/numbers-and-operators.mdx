<BigIdea>
<Tr>
<En>
Python has two everyday number types: **int** (whole numbers of unlimited size) and **float** (decimals, stored as binary approximations). The **arithmetic operators** are `+ - * /` plus three you'll use constantly: `//` **floor division** (divide and round down), `%` **modulo** (the remainder) and `**` **power**. `/` always returns a float, even for `6 / 3`. Operators follow **precedence** rules (powers first, then `* / // %`, then `+ -`), and parentheses make your intent clear. **Comparison operators** (`== != < <= > >=`) return booleans and can be **chained** (`1 <= port <= 65535`). The **logical operators** `and`, `or` and `not` combine conditions and **short-circuit**: Python stops as soon as the answer is known, and `and`/`or` return one of their operands, which gives the handy `value or default` idiom. The **math** module adds square roots, rounding up and down, logarithms and constants. For money, use **`Decimal`** (or whole cents) because floats drift. **Bitwise operators** (`& | ^ ~ << >>`) work on the individual bits of integers, which is how flags and Unix permissions are stored.
</En>
<Ur>
Python me do roz-marra ki number types hain: **int** (be-had size ke poore numbers) aur **float** (aashariya, binary andazon me mehfooz). **Arithmetic operators** `+ - * /` hain, aur teen aur jo aap barabar istemal karenge: `//` **floor division** (taqseem kar ke neeche round), `%` **modulo** (baqi) aur `**` **power**. `/` hamesha float lautata hai, `6 / 3` par bhi. Operators **precedence** ke qaidon par chalte hain (pehle powers, phir `* / // %`, phir `+ -`), aur qausen aap ka iraada wazeh karti hain. **Comparison operators** (`== != < <= > >=`) booleans lautate aur **zanjeer** ban sakte hain (`1 <= port <= 65535`). **Logical operators** `and`, `or` aur `not` shartein jorte aur **short-circuit** karte hain: jawab maloom hote hi Python ruk jata hai, aur `and`/`or` apne operands me se ek lautate hain, jis se kaam ka `value or default` tareeqa milta hai. **math** module square roots, upar neeche rounding, logarithms aur constants deta hai. </Ur>

## Picture it

<Tr>
<En>

Think of **packing eggs into boxes of 12**.

- 50 eggs `// 12` = **4** full boxes; `50 % 12` = **2** eggs left over; `divmod(50, 12)` gives both.
- How many boxes do you need for all of them? Round **up**: 5. That's `math.ceil(50 / 12)` or `(50 + 11) // 12`.
- `50 / 12` = 4.1666...: a fractional box, the exact ratio, but not a number of boxes.
- A clock is modulo too: 10 o'clock plus 5 hours is `(10 + 5) % 12` = 3.

</En>
<Ur>

**12 wale dabbon me ande bharna** socheyn.

- 50 ande `// 12` = **4** bhare dabbe; `50 % 12` = **2** ande bache; `divmod(50, 12)` dono deta hai.
- Sab ke liye kitne dabbe chahiyen? **Upar** round: 5. Yani `math.ceil(50 / 12)` ya `(50 + 11) // 12`.
- `50 / 12` = 4.1666...: adhoora dabba, durust tanasub, magar dabbon ki ginti nahi.
- Ghari bhi modulo hai: 10 baje plus 5 ghante `(10 + 5) % 12` = 3.

</Ur>

## Learn it step by step

<Walkthrough>

<Step title="Arithmetic, precedence and modulo in real tasks">

<Tr>
<En>
`arithmetic.py` runs every arithmetic operator, shows floor division and modulo with negative numbers, `divmod`, precedence, then uses them for real jobs: how many pages 47 items need at 10 per page, turning 3725 seconds into hours, minutes and seconds, picking every 5th request. It finishes with augmented assignment, big integers and dividing by zero.
</En>
<Ur>
`arithmetic.py` har arithmetic operator chalati, negative numbers ke saath floor division aur modulo, `divmod`, precedence dikhati, phir unhe asal kaamon me lagati hai: 10 fi page ke hisaab se 47 items ko kitne pages chahiyen, 3725 second ko ghante, minute aur second me badalna, har 5th request chunna. Aakhir me augmented assignment, bare integers aur zero se taqseem.
</Ur>
</Tr>

```bash
cat > arithmetic.py <<'EOF'
print(7 + 2, 7 - 2, 7 * 2, 7 / 2)        # / always gives a float
print(7 // 2, 7 % 2, 2 ** 10)            # floor division, remainder, power
print(-7 // 2, -7 % 2)                   # // rounds DOWN (toward minus infinity)
print(divmod(125, 60))                   # (quotient, remainder) in one go
print(6 / 3, type(6 / 3).__name__)       # still a float
print(2 + 3 * 4, (2 + 3) * 4, 2 ** 3 ** 2, -2 ** 2)   # precedence

# Real uses
total_items, per_page = 47, 10
pages = (total_items + per_page - 1) // per_page   # round up without floats
print("pages needed:", pages)
seconds = 3725
h, rest = divmod(seconds, 3600)
m, s = divmod(rest, 60)
print(f"uptime {h}h {m}m {s}s")
print("even?", 42 % 2 == 0, "| every 5th request:", [r for r in range(1, 21) if r % 5 == 0])

# Augmented assignment
score = 10
score += 5; score *= 2; score -= 1
print("score:", score)

# Readable big numbers, and ints that never overflow
budget = 1_500_000
print(budget * 12, 2 ** 64, len(str(2 ** 1000)), "digits")
try:
    print(10 / 0)
except ZeroDivisionError as e:
    print("ZeroDivisionError:", e)
EOF
python3 arithmetic.py
```

<Happened>
<Tr>
<En>

- `7 / 2` gave **3.5** and `6 / 3` gave **2.0**, a float: true division always returns a float. Use `//` when you need a whole number.
- `-7 // 2` is **-4**, not -3: floor division rounds toward minus infinity, and `%` matches it so `(-7 // 2) * 2 + (-7 % 2) == -7`. Watch out when negatives are possible; `int(-7 / 2)` truncates to -3 instead.
- Precedence: `2 + 3 * 4` is **14**, `2 ** 3 ** 2` is **512** (powers group right to left: 2 to the 9th) and `-2 ** 2` is **-4** (the power happens before the minus). Parentheses remove doubt.
- `(47 + 10 - 1) // 10` gave **5 pages**, rounding up with integers only. `divmod` turned 3725 seconds into **1h 2m 5s**, and `% 5 == 0` picked every 5th request.
- `score += 5; score *= 2; score -= 1` took 10 to **29**. There's no `++` in Python; use `+= 1`.
- Python ints **never overflow**: `2 ** 64` printed exactly and `2 ** 1000` has 302 digits. Dividing by zero raised **ZeroDivisionError**, which you can catch.

</En>
<Ur>

- `7 / 2` ne **3.5** aur `6 / 3` ne float **2.0** diya: asal taqseem hamesha float lautati hai. Poora number chahiye to `//` lein.
- `-7 // 2` **-4** hai, -3 nahi: floor division minus infinity ki taraf round karti, aur `%` us se milta hai taa ke `(-7 // 2) * 2 + (-7 % 2) == -7`. Jab negatives mumkin hon to dhyan rakhein; `int(-7 / 2)` is ke bajaye -3 tak kaat deta hai.
- Precedence: `2 + 3 * 4` **14**, `2 ** 3 ** 2` **512** (powers daayen se baayen judti hain: 2 ki power 9) aur `-2 ** 2` **-4** hai (power minus se pehle). Qausen shak khatam karti hain.
- `(47 + 10 - 1) // 10` ne sirf integers se upar round karte hue **5 pages** diye. `divmod` ne 3725 second ko **1h 2m 5s** banaya, aur `% 5 == 0` ne har 5th request chuni.
- `score += 5; score *= 2; score -= 1` ne 10 ko **29** banaya. Python me `++` nahi; `+= 1` lein.
- Python ints **kabhi overflow nahi** hote: `2 ** 64` bilkul durust print hua aur `2 ** 1000` me 302 digits hain. Zero se taqseem ne **ZeroDivisionError** diya, jo pakra ja sakta hai.

</Ur>

<Step title="Comparisons, logic, math, rounding, Decimal and bits">

<Tr>
<En>
`compare.py` checks a port with normal and chained comparisons, compares mixed types and strings, uses `and`/`or`/`not` including short-circuiting and a default value, calls built-in and `math` functions, shows how `round()` treats halves, does money with floats versus `Decimal`, and finally reads and changes Unix file permissions with bitwise operators.
</En>
<Ur>
`compare.py` aam aur zanjeer wale comparisons se port check karti, mili jhuli types aur strings milati, short-circuit aur default value samait `and`/`or`/`not` istemal karti, built-in aur `math` functions bulati, dikhati hai ke `round()` aadhon ko kaise sambhalta hai, floats aur `Decimal` se paise ka hisaab karti, aur aakhir me bitwise operators se Unix file permissions parhti aur badalti hai.
</Ur>
</Tr>

```bash
cat > compare.py <<'EOF'
import math
from decimal import Decimal

port = 8080
print(port == 8080, port != 80, port > 1024, 1 <= port <= 65535)   # chained comparison
print("10" == 10, 10 == 10.0, "apple" < "banana", "Zebra" < "apple")

# and / or / not: short-circuit, and they return one of the operands
print(True and False, True or False, not True)
name = "" or "anonymous"                 # first truthy value: a default
print(name, 0 and 1 / 0)                 # 1/0 never runs: and stopped at 0

# Built-ins and the math module
print(abs(-5), min(3, 9, 1), max([20, 80, 443]), sum([1.5, 2.5]), pow(2, 8))
print(math.sqrt(144), math.ceil(4.1), math.floor(4.9), math.log2(1024), math.pi)

# round() uses "banker's rounding": halves go to the nearest EVEN number
print(round(2.5), round(3.5), round(2.675, 2), round(1234.5678, -2))

# Money: floats drift, Decimal doesn't
print(0.1 * 3, Decimal("0.1") * 3)
price = Decimal("19.99")
print("3 items:", price * 3, "| with 8% tax:", (price * 3 * Decimal("1.08")).quantize(Decimal("0.01")))
print(math.isclose(0.1 * 3, 0.3))

# Bitwise operators: Unix permissions are bits
perms = 0o640                             # rw- r-- ---
print(oct(perms), "owner can write?", bool(perms & 0o200), "others can read?", bool(perms & 0o004))
print(oct(perms | 0o004), "<- add 'others read'", oct(perms & ~0o040), "<- remove 'group read'")
EOF
python3 compare.py
```

<Happened>
<Tr>
<En>

- `1 <= port <= 65535` reads like maths and means `1 <= port and port <= 65535`: the idiomatic range check.
- `"10" == 10` is **False** (text never equals a number) but `10 == 10.0` is **True**. Strings compare letter by letter by character code, so `"Zebra" < "apple"` is **True**: capitals come before lowercase. Use `.lower()` for human ordering.
- `"" or "anonymous"` returned **anonymous**: `or` gives the first truthy operand, a quick default. `0 and 1 / 0` returned **0** without ever dividing: `and` stopped at the first falsy value. Short-circuiting lets you write `user and user.is_admin` safely.
- `math.ceil(4.1)` is **5**, `math.floor(4.9)` is **4**; `math.sqrt` returns a float.
- `round(2.5)` is **2** and `round(3.5)` is **4**: halves go to the even neighbour, which avoids bias in large sums. `round(2.675, 2)` gave **2.67** because 2.675 is really stored as 2.67499999...
- `0.1 * 3` drifted to 0.30000000000000004 while **`Decimal("0.1") * 3` is exactly 0.3**. With `Decimal` and `quantize`, 3 items at 19.99 plus 8% tax came to exactly **64.77**. Create Decimals from strings, not floats.
- Permissions `0o640` are bits: `& 0o200` tested **owner write (True)**, `& 0o004` tested **others read (False)**, `| 0o004` **added** a bit (0o644) and `& ~0o040` **removed** one (0o600). The same pattern works for any set of flags.

</En>
<Ur>

- `1 <= port <= 65535` riyazi jaisa parhta aur `1 <= port and port <= 65535` ka matlab rakhta hai: range check ka asal Python tareeqa.
- `"10" == 10` **False** hai (text kabhi number ke barabar nahi) magar `10 == 10.0` **True**. Strings character code ke hisaab se harf ba harf milti hain, isliye `"Zebra" < "apple"` **True** hai: bare haroof chhoton se pehle aate hain. Insaani tarteeb ke liye `.lower()` lein.
- `"" or "anonymous"` ne **anonymous** lautaya: `or` pehla truthy operand deta hai, jaldi ka default. `0 and 1 / 0` ne taqseem kiye baghair **0** lautaya: `and` pehli falsy value par ruk gaya. Short-circuit aap ko mehfooz taur par `user and user.is_admin` likhne deta hai.
- `math.ceil(4.1)` **5**, `math.floor(4.9)` **4** hai; `math.sqrt` float lautata hai.
- `round(2.5)` **2** aur `round(3.5)` **4** hai: aadhe juft padosi ki taraf jate hain, jo bare joron me jhukao se bachata hai. `round(2.675, 2)` ne **2.67** diya kyunke 2.675 asal me 2.67499999... ki tarah mehfooz hai.
- `0.1 * 3` 0.30000000000000004 tak khiska jabke **`Decimal("0.1") * 3` bilkul 0.3** hai. `Decimal` aur `quantize` se 19.99 ke 3 items aur 8% tax bilkul **64.77** bane. Decimals strings se banayen, floats se nahi.
- Permissions `0o640` bits hain: `& 0o200` ne **owner write (True)** test kiya, `& 0o004` ne **others read (False)**, `| 0o004` ne bit **joraa** (0o644) aur `& ~0o040` ne ek **hataya** (0o600). Yahi tareeqa flags ke kisi bhi set par chalta hai.

</Ur>

## Common mistakes

<Compare>
<Bad title="Floats for money">

```text
total = 0.0
for price in [10.1, 0.2]:
    total += price
print(total)                 # 10.299999999999999
if total == 10.3: ...        # False
```

</Bad>
<Good title="Decimal from strings, or integer cents">

```text
from decimal import Decimal
total = sum(Decimal(p) for p in ["10.1", "0.2"])
print(total)                 # 10.3
cents = 1010 + 20            # 1030 -> format as $10.30 when showing it
```

</Good>
</Compare>

<Compare>
<Bad title="Misreading precedence">

```text
average = a + b / 2          # only b is halved
is_valid = not x == 5        # works, but reads like (not x) == 5
discount = price * 1 - 0.1   # not 10% off
```

</Bad>
<Good title="Parentheses say what you mean">

```text
average = (a + b) / 2
is_valid = x != 5
discount = price * (1 - 0.1)
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Expecting `/` to give an int**: `len(items) / 2` is a float and can't be used as a list index; use `//`.
- **`x++`**: not Python; use `x += 1`.
- **`^` for powers**: it's bitwise XOR (`2 ^ 3 == 1`); use `**`.
- **`Decimal(0.1)`**: copies the float's error; use `Decimal("0.1")`.
- **Mixing `and`/`or` without parentheses**: `a or b and c` means `a or (b and c)`.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **`/` se int ki tawaqqo**: `len(items) / 2` float hai aur list index nahi ban sakta; `//` lein.
- **`x++`**: Python nahi; `x += 1` lein.
- **Powers ke liye `^`**: ye bitwise XOR hai (`2 ^ 3 == 1`); `**` lein.
- **`Decimal(0.1)`**: float ki ghalti copy karta; `Decimal("0.1")` lein.
- **Qauson ke baghair `and`/`or` milana**: `a or b and c` ka matlab `a or (b and c)` hai.

</Ur>
</Tr>

<Challenge title="Bandwidth calculator">

<Tr>
<En>

</En>
<Ur>

<Solution>

<Tr>
<En>

```text
import math
size_bytes = 7_340_032_000

seconds = math.ceil(size_bytes * 8 / speed_bps)
h, rest = divmod(seconds, 3600)
m, s = divmod(rest, 60)
print(f"{h}h {m}m {s}s")              # 0h 9m 48s   (587.2 s rounded up to 588)
```

</En>
<Ur>

<DeepDive title="More about numbers">

**IEEE 754 floats.** A float has 53 bits of precision, about 15 to 17 significant decimal digits; `sys.float_info` shows the limits, and special values `inf` and `nan` exist (`float("inf")`, `math.isnan`).

**Decimal contexts.** `decimal.getcontext()` controls precision and rounding mode (ROUND_HALF_UP for traditional rounding); `quantize` fixes the number of decimal places.

**Fractions.** `fractions.Fraction(1, 3) * 3 == 1` exactly; useful for ratios.

**Integer tricks.** `int.bit_length()`, `int.to_bytes()` and `int.from_bytes()` convert between numbers and raw bytes, which you'll use in networking and crypto. `pow(a, b, m)` computes modular powers fast, the heart of RSA.

**Operator functions.** Every operator maps to a special method (`__add__`, `__lt__`), which is how `Decimal`, `datetime` and your own classes support `+` and `<`.

</DeepDive>

<DeepDive title="Real world: the rounding that cost cents">

An invoicing service calculated line totals with floats and `round(x, 2)`. Customers occasionally received invoices one cent off from their own spreadsheet, and the accounting system rejected batches whose totals didn't match the payment provider's. The causes: values like 2.675 stored as 2.67499..., banker's rounding where accountants expected half-up, and rounding each line versus the total.

The fixes:

1. All money became `Decimal` created from strings (or integer cents in the database).
2. A single rounding policy: `quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`, applied per line as the tax rules required.
3. Tests with known tricky values (2.675, 0.005, large totals) against the expected results.

</DeepDive>

<DeepDive title="Security lens">

- **Validate numeric ranges**: a negative quantity or a port of 70000 should be rejected, not computed with.
- **Beware huge numbers from input**: converting a 1-million-digit string to int is slow; Python 3.11+ limits int-string conversion to 4300 digits by default for this reason.
- **Money with floats** can create rounding gaps that are abused at scale; use exact types.
- **Short-circuit for safety**: `if token and compare_digest(token, expected)` avoids errors on missing values.
- **Permission bits**: checking for world-writable files (`mode & 0o002`) is a classic hardening check you'll automate.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What is the difference between / and // in Python 3?">
/ is true division and always returns a float. // is floor division and returns the quotient rounded toward minus infinity, as an int for int operands.
</QA>

<QA q="How does Python's round() handle .5?">
It uses round-half-to-even (banker's rounding), so 2.5 rounds to 2 and 3.5 to 4; additionally, many decimal values aren't exactly representable as floats, which affects results like round(2.675, 2).
</QA>

<QA q="What do and and or return?">
They return one of their operands, not necessarily a bool: and returns the first falsy operand or the last one; or returns the first truthy operand or the last one. Both short-circuit.
</QA>

<QA q="How should you represent money in Python?">
With decimal.Decimal created from strings, or as integers in the smallest currency unit, with an explicit rounding policy, never with binary floats.
</QA>

<QA q="Can Python integers overflow?">
No. Python ints have arbitrary precision and grow as needed, limited only by memory, although converting extremely long digit strings is limited by default for safety.
</QA>

</DeepDive>
