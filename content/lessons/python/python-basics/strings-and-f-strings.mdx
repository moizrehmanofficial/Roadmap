<BigIdea>
<Tr>
<En>
A **string** (`str`) is a sequence of characters: text. You write it in single or double quotes (they're identical), use triple quotes for several lines, **escape sequences** like `\n` (new line) and `\t` (tab) for special characters, and **raw strings** `r"..."` when backslashes should stay as they are (Windows paths, regular expressions). Each character has a position starting at **0**, so `s[0]` is the first, `s[-1]` the last, and **slicing** `s[start:stop]` takes a piece (stop not included). Strings are **immutable**: methods like `.upper()`, `.strip()` and `.replace()` never change the original, they **return a new string**, so you assign the result. A handful of methods do most real work: `strip` to clean, `lower` to normalise, `split` to break into parts, `join` to glue parts, `startswith`/`endswith`/`in` to test. For output, **f-strings** (`f"..."`) put any expression inside `{}` and a **format spec** after a colon controls width, alignment, decimals, thousands separators, percentages and number bases, which makes reports and tables readable.
</En>
<Ur>
**String** (`str`) characters ki sequence hai: text. Ise single ya double quotes me likhte hain (dono ek jaise), kayi lines ke liye triple quotes, khaas characters ke liye `\n` (nayi line) aur `\t` (tab) jaise **escape sequences**, aur jab backslashes waise hi rehne chahiyen (Windows paths, regular expressions) to **raw strings** `r"..."`. Har character ki jagah **0** se shuru hoti hai, isliye `s[0]` pehla, `s[-1]` aakhri, aur **slicing** `s[start:stop]` ek tukra leti hai (stop shamil nahi). Strings **immutable** hain: `.upper()`, `.strip()` aur `.replace()` jaise methods asal ko kabhi nahi badalte, **nayi string lautate** hain, isliye natija assign karte hain. Kuch methods zyadatar asal kaam karte hain: saaf karne ke liye `strip`, ek jaisa banane ke liye `lower`, hisson me torne ke liye `split`, hisse jorne ke liye `join`, test ke liye `startswith`/`endswith`/`in`. Output ke liye **f-strings** (`f"..."`) `{}` ke andar koi bhi expression rakhti hain aur colon ke baad **format spec** width, alignment, aashariya, hazaron ke separators, feesad aur number bases tay karta hai, jis se reports aur tables parhne layak banti hain.
</Ur>

## Picture it

<Tr>
<En>

Think of a **row of numbered mailboxes**, one letter per box.

- The boxes are numbered from 0 on the left; you can also count from the right with -1, -2...
- A slice `[4:11]` says "boxes 4 up to, but not including, 11".
- The row is welded shut (immutable): to "change" it you build a new row, perhaps copying most boxes and swapping a few letters.
- An f-string is a printed form with blanks: you write the values into the blanks, and the format spec says how wide each blank is and how to write the number in it.

</En>
<Ur>

**Numbered mailboxes ki qataar** socheyn, har dabbe me ek harf.

- Dabbe baayen se 0 se ginay jate hain; daayen se -1, -2... se bhi gin sakte hain.
- Slice `[4:11]` kehta hai "dabba 4 se 11 tak, magar 11 shamil nahi".
- Qataar weld shuda hai (immutable): use "badalne" ke liye nayi qataar banate hain, shayad zyadatar dabbe copy kar ke aur kuch harf badal kar.
- f-string khaali jagahon wala chhapa form hai: aap values khaali jagahon me likhte, aur format spec batata hai har jagah kitni chauri ho aur number kaise likha jaye.

</Ur>
</Tr>

## Learn it step by step

<Walkthrough>

<Step title="Writing, slicing, cleaning and parsing strings">

<Tr>
<En>
`strings.py` shows quotes and escapes, a raw string next to the escaped equivalent, a multi-line string, indexing and slicing a hostname, what happens when you try to change a character, the everyday methods applied to a messy email address, and finally pulls the IP, method, path and status out of a real-looking web server log line.
</En>
<Ur>
`strings.py` quotes aur escapes, escaped barabar ke saath raw string, kayi line ki string, hostname ki indexing aur slicing, character badalne ki koshish par kya hota hai, gande email address par roz ke methods, aur aakhir me asal jaisi web server log line se IP, method, path aur status nikalti hai.
</Ur>
</Tr>

```bash
cat > strings.py <<'EOF'
# Quotes, escapes, raw strings and multi-line strings
print('single', "double", "it's", 'say "hi"')
print("tab:\tend | newline ->\n<- here | backslash: \\")
print(r"C:\new\temp", "vs", "C:\\new\\temp")              # raw: backslashes stay
banner = """Line one
Line two"""
print(banner)

# Indexing and slicing: positions start at 0; negative counts from the end
host = "api.example.test"
print(len(host), host[0], host[-1], host[:3], host[4:11], host[-4:], host[::-1])

# Strings are immutable: methods return NEW strings
try:
    host[0] = "A"
except TypeError as e:
    print("TypeError:", e)
print(host.upper(), host, host.replace("api", "www"))

# Everyday methods
raw = "   Jane.Doe@Example.TEST \n"
email = raw.strip().lower()
print(repr(raw), "->", repr(email))
user, domain = email.split("@")
print(user, domain, email.startswith("jane"), email.endswith(".test"), "@" in email)
print("a,b,,c".split(","), " lots   of   space ".split(), "-".join(["2026", "11", "23"]))
print(host.find("example"), host.find("nope"), host.count("e"), "ab" * 3 + "!")
print("42".isdigit(), "abc".isalpha(), "Admin".istitle(), "  ".isspace())

# Parse a web server log line
line = '203.0.113.7 - - [23/Nov/2026:10:15:32 +0000] "GET /login HTTP/1.1" 401 512'
ip = line.split()[0]
request = line.split('"')[1]
method, path, _ = request.split()
status = int(line.split()[-2])
print(ip, method, path, status, "FAILED" if status >= 400 else "ok")
EOF
python3 strings.py
```

<Happened>
<Tr>
<En>

- `\t` became a real tab and `\n` a line break; `\\` printed one backslash. The raw string `r"C:\new\temp"` and the escaped `"C:\\new\\temp"` printed the **same** text. Without either, `"C:\new"` would contain a newline because `\n` is an escape.
- `host[:3]` gave **api**, `host[4:11]` **example** (index 11 not included), `host[-4:]` **test**, and `host[::-1]` the reversed string. Slices never raise errors when out of range; indexes do (`host[99]` is an IndexError).
- `host[0] = "A"` raised **TypeError**: strings can't be changed. `host.upper()` returned a new string and `host` stayed lowercase. That's why you write `email = raw.strip().lower()`: methods **chain**, each returning a new string.
- `repr()` revealed the hidden spaces and `\n` around the raw email, which would make `==` comparisons fail. Always `strip()` input.
- `split("@")` gave user and domain; `split(",")` kept the **empty field** between two commas, while `split()` with no argument splits on any run of whitespace. `"-".join([...])` glued parts into **2026-11-23**.
- `find` returned the position **4**, or **-1** when not found (use `in` for a yes/no). The `is...` methods test the whole string.
- The log line was taken apart with `split()` and `split('"')` into **203.0.113.7, GET, /login, 401** and flagged as FAILED. For anything more complex, the `re` module (regular expressions) is the right tool, coming later in the track.

</En>
<Ur>

- `\t` asal tab aur `\n` line break bana; `\\` ne ek backslash print kiya. Raw string `r"C:\new\temp"` aur escaped `"C:\\new\\temp"` ne **ek hi** text print kiya. Dono ke baghair `"C:\new"` me newline hoti kyunke `\n` escape hai.
- `host[:3]` ne **api**, `host[4:11]` ne **example** (index 11 shamil nahi), `host[-4:]` ne **test**, aur `host[::-1]` ne ulti string di. Slices range se bahar errors nahi dete; indexes dete hain (`host[99]` IndexError hai).
- `host[0] = "A"` ne **TypeError** diya: strings badli nahi ja saktin. `host.upper()` ne nayi string lautayi aur `host` chhote haroof me raha. Isi liye `email = raw.strip().lower()` likhte hain: methods **zanjeer** bante, har ek nayi string lautata hai.
- `repr()` ne gande email ke ird gird chhupe spaces aur `\n` dikhaye, jo `==` muqable nakam karte. Input hamesha `strip()` karein.
- `split("@")` ne user aur domain diye; `split(",")` ne do commas ke beech **khaali field** rakha, jabke bina argument `split()` whitespace ke kisi bhi silsile par torta hai. `"-".join([...])` ne hisse jor kar **2026-11-23** banaya.
- `find` ne jagah **4** lautayi, ya na milne par **-1** (haan/nahi ke liye `in` lein). `is...` methods poori string test karte hain.
- Log line `split()` aur `split('"')` se **203.0.113.7, GET, /login, 401** me khuli aur FAILED mark hui. Is se pecheeda ke liye `re` module (regular expressions) sahi auzaar hai, jo track me aage aayega.

</Ur>

<Step title="Formatting output with f-strings">

<Tr>
<En>
`fstrings.py` puts variables and expressions in f-strings, then uses format specs for alignment and fill, decimals, thousands separators, zero padding, signs, hex, binary and octal. It prints an aligned table with percentages, uses the `=` debugging shortcut and `!r`, formats a date, shows the two older formatting styles you'll meet in existing code, and prints literal braces.
</En>
<Ur>
`fstrings.py` variables aur expressions f-strings me rakhti, phir alignment aur fill, aashariya, hazaron ke separators, zero padding, signs, hex, binary aur octal ke liye format specs istemal karti hai. Feesad ke saath seedhi table print karti, `=` debugging shortcut aur `!r` istemal karti, date format karti, mojooda code me milne wale do purane formatting styles dikhati, aur asal braces print karti hai.
</Ur>
</Tr>

```bash
cat > fstrings.py <<'EOF'
from datetime import datetime
user, attempts, ratio = "jane", 7, 0.0583
print(f"{user} failed {attempts} times ({ratio:.1%})")       # expressions + format spec
print(f"{user.upper()} has {attempts * 2} points, next is {attempts + 1}")

# Format specs: width, alignment, fill, decimals, thousands, bases
price, total = 19.5, 1234567.891
print(f"[{user:<10}] [{user:>10}] [{user:^10}] [{user:*^10}]")
print(f"{price:.2f} {total:,.2f} {total:_.0f} {attempts:03d} {-5:+d}")
print(f"{255:x} {255:#x} {255:08b} {0o755:o} {1e6:.1e}")

# A neat table
rows = [("ssh", 22, 0.9512), ("http", 80, 0.0421), ("https", 443, 0.71)]
print(f"{'service':<8}{'port':>6}{'share':>9}")
for name, port, share in rows:
    print(f"{name:<8}{port:>6}{share:>9.1%}")

# Debugging with = and the repr with !r
port = "8080"
print(f"{port=}", f"{attempts=}", f"{port!r}")

# Dates have their own format codes
when = datetime(2026, 11, 23, 14, 5)
print(f"{when:%Y-%m-%d %H:%M}", f"{when:%d %b %Y}", f"{when:%A}")

# Older styles you'll still meet in existing code
print("{} has {} attempts".format(user, attempts), "%s has %d attempts" % (user, attempts))

# Literal braces are doubled
print(f"JSON-like: {{\"user\": \"{user}\"}}")
EOF
python3 fstrings.py
```


<Happened>
<Tr>
<En>

- `{ratio:.1%}` turned 0.0583 into **5.8%** (multiplied by 100, one decimal). Any expression works inside the braces: method calls and arithmetic.
- `<10`, `>10` and `^10` padded "jane" to 10 characters on the left, right or centre, and `*^10` used `*` as the fill.
- `.2f` gave **19.50**, `,.2f` gave **1,234,567.89**, `_` used underscores, `03d` zero-padded to **007**, and `+d` always shows the sign.
- `x`, `#x`, `08b` and `o` printed **ff, 0xff, 11111111, 755**: handy for permissions, bit flags and hashes.
- Fixed widths (`<8`, `>6`, `>9.1%`) lined the table up in columns. Build headers with the same widths.
- `{port=}` printed **`port='8080'`**: name and repr in one go, perfect for quick debugging. The quotes show it's a string, not a number.
- Dates take `strftime` codes: `%Y-%m-%d %H:%M` gave **2026-11-23 14:05** and `%A` the weekday.
- `"{}".format(...)` and `"%s" % (...)` produce the same output; prefer f-strings in new code. To print a literal brace, double it: `{{` and `}}`.

</En>
<Ur>

- `{ratio:.1%}` ne 0.0583 ko **5.8%** banaya (100 se zarb, ek aashariya). Braces ke andar koi bhi expression chalta hai: method calls aur hisaab.
- `<10`, `>10` aur `^10` ne "jane" ko baayen, daayen ya beech me 10 characters tak bhara, aur `*^10` ne `*` se bhara.
- `.2f` ne **19.50**, `,.2f` ne **1,234,567.89**, `_` ne underscores, `03d` ne zero bhar kar **007** diya, aur `+d` hamesha sign dikhata hai.
- `x`, `#x`, `08b` aur `o` ne **ff, 0xff, 11111111, 755** print kiye: permissions, bit flags aur hashes ke liye kaam ke.
- Tay shuda chaurai (`<8`, `>6`, `>9.1%`) ne table ko columns me seedha kiya. Headers bhi unhi chauraiyon se banayen.
- `{port=}` ne **`port='8080'`** print kiya: naam aur repr ek saath, jaldi debugging ke liye behtareen. Quotes dikhate hain ke ye string hai, number nahi.
- Dates `strftime` codes leti hain: `%Y-%m-%d %H:%M` ne **2026-11-23 14:05** aur `%A` ne hafte ka din diya.
- `"{}".format(...)` aur `"%s" % (...)` wahi output dete hain; naye code me f-strings ko tarjeeh dein. Asal brace print karne ke liye dohra karein: `{{` aur `}}`.

</Ur>

## Common mistakes

<Compare>
<Bad title="Calling a method and ignoring the result">

```text
username = "  Admin "
username.strip()
username.lower()
print(username == "admin")       # False: strings never change in place
```

</Bad>
<Good title="Assign the new string">

```text
username = "  Admin "
username = username.strip().lower()
print(username == "admin")       # True
```

</Good>
</Compare>

<Compare>
<Bad title="Building strings with + in a loop and str() everywhere">

```text
report = ""
for name, n in counts.items():
    report = report + name + ": " + str(n) + " failures" + "\n"
```

</Bad>
<Good title="f-strings and join">

```text
lines = [f"{name}: {n} failures" for name, n in counts.items()]
report = "\n".join(lines)
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Forgetting the `f`**: `"Hello {name}"` prints the braces literally.
- **Backslashes in Windows paths**: `"C:\new"` contains a newline; use `r"C:\new"`, forward slashes or `pathlib`.
- **Splitting real CSV with `split(",")`**: quoted fields with commas break it; use the `csv` module.
- **Case-sensitive comparisons on user input**: compare `.lower()` (or `.casefold()`) versions.
- **Building SQL, shell commands or HTML with f-strings from user input**: that's injection; use parameters and escaping.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **`f` bhoolna**: `"Hello {name}"` braces jyon ke tyon print karta hai.
- **Windows paths me backslashes**: `"C:\new"` me newline hai; `r"C:\new"`, forward slashes ya `pathlib` lein.
- **Asal CSV ko `split(",")` se torna**: commas wale quoted fields isse torte hain; `csv` module lein.
- **User input par chhote bare haroof wale muqable**: `.lower()` (ya `.casefold()`) versions milayen.
- **User input se f-strings ke zariye SQL, shell commands ya HTML banana**: ye injection hai; parameters aur escaping lein.

</Ur>
</Tr>

<DeepDive title="More about strings">

**Unicode.** Python strings are Unicode: `len("café")` is 4 characters, but `"café".encode("utf-8")` is 5 bytes. Text is decoded from bytes when reading files and network data, and encoded when writing; always say `encoding="utf-8"`.

**Case-insensitive matching.** `casefold()` is a stronger `lower()` for comparisons across languages (German ß becomes ss).

**Useful extras.** `removeprefix()`/`removesuffix()`, `partition()` (split once into three parts), `splitlines()`, `zfill()`, `center()`, `str.translate` for character mapping, and `textwrap` for wrapping paragraphs.

**Template strings.** Python 3.14 added t-strings (`t"..."`), which look like f-strings but produce a template object that a library can safely process, for example escaping values for HTML or SQL instead of pasting them in.

**Performance.** Joining a list with `"".join(parts)` is much faster than repeated `+=` in large loops, because each `+` builds a new string.

</DeepDive>

<DeepDive title="Real world: the admin who wasn't">

A small internal tool checked `if role == "admin":` against a role read from a CSV export. A new export added a trailing space after every field, so `"admin "` no longer matched and every admin lost access during a deploy. Worse, another check used `if "admin" in role:` and treated `"not-admin"` as an admin.

The fixes:

1. Normalise once on input: `role = row["role"].strip().lower()`.
2. Compare exactly against an allowed set: `if role in {"admin", "editor", "viewer"}`, rejecting anything else.
3. Use the `csv` module instead of `split(",")`.
4. Tests with whitespace, capitals and look-alike values.

</DeepDive>

<DeepDive title="Security lens">

- **Injection starts with string building**: SQL, shell commands, HTML and LDAP queries built with f-strings from user input are classic vulnerabilities. Use query parameters, `subprocess` argument lists and template escaping.
- **Substring checks are not authorization**: `"admin" in role` or `url.startswith("https://example.test")` (which `https://example.test.evil.example` also passes) need exact or parsed comparisons.
- **Normalise before comparing**: case, whitespace and Unicode look-alikes can bypass naive checks.
- **Mask secrets in output and logs**: show only the last 4 characters of keys and cards.
- **Don't log raw input with newlines**: attackers can forge log lines; replace `\n` or use structured logging.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="Are Python strings mutable?">
No. Strings are immutable; every method that seems to modify a string returns a new string, so you assign the result. This makes strings safe to use as dict keys and share between parts of a program.
</QA>

<QA q="How does slicing work?">
s[start:stop:step] returns a new string from start up to but not including stop, moving by step. Missing values default to the beginning, end and 1; negative values count from the end; out-of-range slices don't raise errors.
</QA>

<QA q="What are f-strings and why prefer them?">
String literals prefixed with f that evaluate expressions inside braces at run time, with optional format specs. They're more readable and faster than format() or % formatting.
</QA>

<QA q="What is the difference between split() with and without a separator?">
Without an argument, split() splits on any run of whitespace and ignores leading and trailing whitespace. With a separator, it splits on exactly that string and keeps empty fields between consecutive separators.
</QA>

<QA q="Why use join instead of + in a loop?">
Each + creates a new string and copies the old content, which becomes slow for many pieces; join computes the total size once and builds the result in one pass.
</QA>

</DeepDive>
