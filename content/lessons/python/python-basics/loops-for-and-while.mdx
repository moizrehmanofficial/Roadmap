<BigIdea>
<Tr>
<En>
A **loop** repeats a block of code. Python has two. The **`for` loop** walks through the items of anything **iterable** (a list, a string, a range of numbers, a dictionary, the lines of a file or of stdin), giving you one item per round: `for port in ports:`. It stops by itself when the items run out, so it's the right choice almost every time. Helpers make it expressive: **`range()`** for counting, **`enumerate()`** when you also need the position, **`zip()`** to walk several sequences together, **`.items()`** for dictionary keys and values, and `sorted()`/`reversed()` to change the order. The **`while` loop** repeats **as long as a condition is true**: retrying a connection, waiting for a job, reading until the user types "quit". You must make sure something changes so the condition eventually becomes false, or the loop runs forever. Inside either loop, **`break`** leaves immediately, **`continue`** skips to the next round, and an optional **`else`** runs only if the loop finished without `break`, which is perfect for "search, and report if not found".
</En>
<Ur>
**Loop** code ka block dohrata hai. Python me do hain. **`for` loop** kisi bhi **iterable** (list, string, numbers ki range, dictionary, file ya stdin ki lines) ke items se guzarta, har chakkar me ek item deta hai: `for port in ports:`. Items khatam hone par khud ruk jata hai, isliye takreeban har dafa yahi sahi intekhab hai. Madadgar isse wazeh banate hain: ginti ke liye **`range()`**, jab jagah bhi chahiye to **`enumerate()`**, kayi sequences saath chalane ke liye **`zip()`**, dictionary ki keys aur values ke liye **`.items()`**, aur tarteeb badalne ke liye `sorted()`/`reversed()`. **`while` loop** **jab tak shart sach rahe** dohrata hai: connection dobara aazmana, job ka intezar, user ke "quit" likhne tak parhna. Aap ko yaqeeni banana hai ke kuch badle taa ke shart aakhir jhooti ho, warna loop hamesha chalta rahega. Dono loops ke andar **`break`** foran nikalta, **`continue`** agle chakkar par jata, aur ikhtiyari **`else`** tabhi chalta hai jab loop `break` ke baghair khatam ho, jo "dhoondo, aur na mile to batao" ke liye behtareen hai.
</Ur>

## Picture it

<Tr>
<En>

Think of **checking tickets at a gate**.

- A `for` loop is a guard with a printed guest list: they go down the list name by name and stop when the list ends.
- A `while` loop is a guard told "keep the gate open while there are people in the queue": they keep going until the queue is empty, and if people never stop arriving, they never go home.
- `continue` is waving through someone who doesn't need checking; `break` is closing the gate the moment the VIP arrives.
- The `else` on a loop is the guard's note at the end of a shift: "checked everyone, no VIP showed up", written only if they didn't close the gate early.

</En>
<Ur>

**Gate par tickets check karna** socheyn.

- `for` loop chhapi hui mehmanon ki list wala guard hai: list me naam ba naam neeche jata aur list khatam hone par rukta hai.
- `while` loop woh guard hai jise kaha gaya "jab tak line me log hon gate khula rakho": line khaali hone tak chalta rehta, aur agar log aana band na karein to kabhi ghar nahi jata.
- `continue` us shakhs ko guzar jane dena hai jise jaanch ki zaroorat nahi; `break` VIP ke aate hi gate band karna hai.
- Loop ka `else` shift ke aakhir me guard ka note hai: "sab check kiye, koi VIP nahi aaya", jo tabhi likha jata hai jab gate jaldi band na kiya ho.

## Learn it step by step

<Walkthrough>

<Step title="for loops: lists, ranges, enumerate, zip, dicts and accumulators">

<Tr>
<En>
`forloops.py` loops over a list of ports and the characters of a string, prints three kinds of `range`, counts attempts, numbers hosts with `enumerate`, pairs users with their failure counts using `zip`, walks a dictionary with `.items()`, accumulates a total, a maximum and a filtered list (and checks against the built-ins), and combines every host with every port in a nested loop.
</En>
<Ur>
`forloops.py` ports ki list aur string ke characters par loop chalati, `range` ki teen qismen print karti, koshishen ginti, `enumerate` se hosts ko number deti, `zip` se users ko un ki nakamiyon ki ginti se jorti, `.items()` se dictionary par chalti, total, maximum aur chhani hui list jama karti (aur built-ins se milati), aur nested loop me har host ko har port se jorti hai.
</Ur>
</Tr>

```bash
cat > forloops.py <<'EOF'
ports = [22, 80, 443]
for port in ports:                        # each item in turn
    print("checking port", port)

for ch in "abc":                          # strings are sequences too
    print(ch, end=" ")
print()

print(list(range(5)), list(range(2, 10, 3)), list(range(5, 0, -1)))
for attempt in range(1, 4):               # counting: 1, 2, 3
    print(f"attempt {attempt} of 3")

# enumerate: position + item (instead of range(len(...)))
for i, host in enumerate(["web1", "web2", "db1"], start=1):
    print(i, host)

# zip: walk several lists side by side
for user, n in zip(["jane", "john", "ana"], [0, 7, 2]):
    print(f"{user}: {n} failed")

# dictionaries: keys, values, or both
limits = {"free": 100, "pro": 10_000, "team": 50_000}
for plan, limit in limits.items():
    print(f"{plan:<5} {limit:>6,}")

# accumulate a total, a maximum and a filtered list
sizes = [1024, 512, 2048, 256]
total, biggest, large = 0, sizes[0], []
for s in sizes:
    total += s
    if s > biggest:
        biggest = s
    if s >= 1024:
        large.append(s)
print("total", total, "| biggest", biggest, "| large", large, "| built-ins agree:", sum(sizes), max(sizes))

# nested loops: every host x every port
for host in ["web1", "db1"]:
    for port in [22, 5432]:
        print(f"{host}:{port}", end="  ")
print()
print(sorted(["web2", "db1", "web1"]), list(reversed([1, 2, 3])))
EOF
python3 forloops.py
```

<Happened>
<Tr>
<En>

- `for port in ports:` handed each item to the loop body in order; the same works for a string, one **character** at a time.
- `range(5)` is **0 to 4** (stop excluded), `range(2, 10, 3)` is 2, 5, 8, and a negative step counts down. `range(1, 4)` gave the human-friendly **1, 2, 3** for attempts.
- `enumerate(..., start=1)` gave the number and the item together, so you never write `for i in range(len(hosts))` and `hosts[i]`.
- `zip` walked two lists in step, pairing **john with 7**. It stops at the shorter list, so check lengths when that matters.
- `.items()` gave each plan and its limit, formatted with thousands separators.
- The accumulator pattern built **total 3840**, **biggest 2048** and the list of large files in one pass, and the built-ins `sum()` and `max()` agreed. Prefer the built-ins when they exist; write the loop when you need several results or custom logic.
- The nested loop produced every **host:port** combination: 2 hosts x 2 ports = 4 rounds. Nested loops multiply, so 1,000 hosts x 1,000 ports is a million rounds.

</En>
<Ur>

- `for port in ports:` ne har item tarteeb se loop ke jism ko diya; string par bhi yahi chalta hai, ek waqt me ek **character**.
- `range(5)` **0 se 4** (stop shamil nahi), `range(2, 10, 3)` yani 2, 5, 8, aur negative step ulta ginta hai. `range(1, 4)` ne koshishon ke liye insaan dost **1, 2, 3** diya.
- `enumerate(..., start=1)` ne number aur item saath diye, isliye aap kabhi `for i in range(len(hosts))` aur `hosts[i]` nahi likhte.
- `zip` ne do lists qadam se qadam mila kar chalayin, **john ko 7** se jora. Ye chhoti list par rukta hai, isliye jab zaroori ho lambai check karein.
- `.items()` ne har plan aur us ki had di, hazaron ke separators ke saath format.
- Accumulator pattern ne ek chakkar me **total 3840**, **biggest 2048** aur bari files ki list banayi, aur built-ins `sum()` aur `max()` ne ittefaq kiya. Jahan built-ins hon unhe tarjeeh dein; jab kayi natije ya khaas mantiq chahiye to loop likhein.
- Nested loop ne har **host:port** jor banaya: 2 hosts x 2 ports = 4 chakkar. Nested loops zarb hote hain, isliye 1,000 hosts x 1,000 ports ek million chakkar hain.

</Ur>
</Tr>

<Step title="while loops, break, continue, else and loop pitfalls">

<Tr>
<En>
`whileloops.py` retries a flaky call (made repeatable with a fixed random seed) up to six times, doubling the wait each time and breaking on success. It parses config lines with `continue` to skip comments and blanks, searches a batch of IPs with `for ... else`, demonstrates the bug of removing items from a list while looping over it, and runs a calculation with a safety limit on the number of steps.
</En>
<Ur>
`whileloops.py` ek ghair yaqeeni call (fixed random seed se dohrane layak) chhe dafa tak dobara aazmati, har dafa intezar dugna karti aur kamyabi par break karti hai. `continue` se comments aur khaali lines chhor kar config lines parse karti, `for ... else` se IPs ka batch dhoondti, loop chalate hue list se items hatane ka bug dikhati, aur qadmon ki tadad par hifazati had ke saath hisaab chalati hai.
</Ur>
</Tr>

```bash
cat > whileloops.py <<'EOF'
import random
random.seed(11)                           # fixed seed: same "random" results every run

# while: repeat until a condition changes. Retry a flaky call with exponential backoff.
def flaky_call():
    return random.random() > 0.7          # succeeds about 30% of the time

attempt, delay, max_attempts = 1, 0.5, 6
while attempt <= max_attempts:
    if flaky_call():
        print(f"attempt {attempt}: success")
        break                             # leave the loop now
    print(f"attempt {attempt}: failed, waiting {delay}s")
    delay *= 2                            # (a real script would time.sleep(delay))
    attempt += 1
else:
    print("gave up")                      # while-else: runs only if the loop did NOT break

# continue: skip the rest of this round
for line in ["# comment", "", "PORT=8080", "  ", "HOST=example.test"]:
    if not line.strip() or line.startswith("#"):
        continue
    key, value = line.split("=")
    print("setting", key, "to", value)

# for-else: "search, and react if nothing was found"
banned = {"203.0.113.7", "198.51.100.4"}
for ip in ["192.0.2.1", "192.0.2.2"]:
    if ip in banned:
        print("found banned ip", ip)
        break
else:
    print("no banned ips in this batch")

# Don't remove items from a list while looping over it
nums = [1, 2, 2, 3, 2]
for n in nums:
    if n == 2:
        nums.remove(n)
print("removed while looping:", nums, "<- a 2 survived")
nums = [1, 2, 2, 3, 2]
print("build a new list instead:", [n for n in nums if n != 2])

# A countdown with a safety limit
n, steps = 27, 0
while n != 1 and steps < 1000:            # Collatz: always guard loops with an upper bound
    n = n // 2 if n % 2 == 0 else 3 * n + 1
    steps += 1
print("27 reached 1 after", steps, "steps")
EOF
python3 whileloops.py
```

```text output
attempt 1: failed, waiting 0.5s
attempt 2: failed, waiting 1.0s
attempt 3: success
setting PORT to 8080
setting HOST to example.test
no banned ips in this batch
removed while looping: [1, 3, 2] <- a 2 survived
build a new list instead: [1, 3]
27 reached 1 after 111 steps
```

<Happened>
<Tr>
<En>

- The retry loop failed twice, waiting **0.5 s then 1.0 s**, and succeeded on **attempt 3**, where `break` left the loop. Because it broke, the `else` ("gave up") did **not** run; it would only run after six failures. The counter `attempt += 1` is what eventually ends the loop.
- `continue` skipped the comment and the blank lines (`not line.strip()` is true for whitespace-only lines), so only **PORT** and **HOST** were set.
- The `for ... else` found no banned IP and printed **"no banned ips in this batch"**; had it found one, `break` would have skipped that message.
- Removing items from `nums` while looping left **[1, 3, 2]**: deleting shifts the remaining items left, so the loop skips the one right after each removal. Build a new list (or loop over a copy, `for n in nums[:]`) instead.
- The Collatz loop had two exit conditions: reaching 1 **or** hitting 1000 steps. It needed **111** steps for 27. When you can't be certain a `while` loop ends, add an upper bound.

</En>
<Ur>

- Retry loop do dafa nakam hua, **0.5 s phir 1.0 s** intezar kar ke, aur **attempt 3** par kamyab hua, jahan `break` ne loop chhora. Kyunke break hua, `else` ("gave up") **nahi** chala; ye sirf chhe nakamiyon ke baad chalta. Counter `attempt += 1` hi aakhir kaar loop khatam karta hai.
- `continue` ne comment aur khaali lines chhoren (`not line.strip()` sirf whitespace wali lines ke liye sach hai), isliye sirf **PORT** aur **HOST** set hue.
- `for ... else` ko koi banned IP nahi mila aur us ne **"no banned ips in this batch"** print kiya; agar milta to `break` woh paigham chhor deta.
- Loop chalate hue `nums` se items hatane ne **[1, 3, 2]** chhora: hatane se baqi items baayen khiskte hain, isliye loop har hataye gaye ke foran baad wala chhor deta hai. Is ke bajaye nayi list banayen (ya copy par loop chalayen, `for n in nums[:]`).
- Collatz loop ke nikalne ki do shartein thin: 1 tak pohanchna **ya** 1000 qadam. 27 ke liye **111** qadam lage. Jab yaqeen na ho ke `while` loop khatam hoga, upar ki had lagayen.

</Ur>
</Tr>
</Happened>

## Common mistakes

<Compare>
<Bad title="Index juggling">

```text
for i in range(len(users)):
    print(i + 1, users[i], counts[i])
```

</Bad>
<Good title="enumerate and zip">

```text
for i, (user, count) in enumerate(zip(users, counts), start=1):
    print(i, user, count)
```

</Good>
</Compare>

<Compare>
<Bad title="A while loop that never ends">

```text
attempt = 1
while attempt <= 3:
    if connect():
        break
    print("retrying...")
    # forgot attempt += 1 -> retries forever when the server is down
```

</Bad>
<Good title="Bounded retries">

```text
for attempt in range(1, 4):
    if connect():
        break
    time.sleep(2 ** attempt)
else:
    raise SystemExit("could not connect after 3 attempts")
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Off-by-one with `range`**: `range(1, 10)` stops at 9; `range(10)` starts at 0.
- **Changing a list or dict while looping over it**: loop over a copy, or build a new one. Changing a dict's size during iteration raises RuntimeError.
- **Retrying instantly in a tight loop**: hammering a failing service; add a delay with backoff and a maximum.
- **Doing slow work (a network call, a database query) inside a nested loop**: it multiplies; batch it or cache results.
- **Forgetting that the loop variable keeps its last value** after the loop: don't rely on it by accident.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **`range` ke saath ek ka farq**: `range(1, 10)` 9 par rukta; `range(10)` 0 se shuru hota hai.
- **Loop chalate hue list ya dict badalna**: copy par loop chalayen, ya nayi banayen. Iteration ke dauran dict ka size badalna RuntimeError deta hai.
- **Tang loop me foran retry**: nakam service par barabar hamla; backoff aur had ke saath intezar jorein.
- **Nested loop ke andar sust kaam (network call, database query)**: zarb hota hai; batch karein ya natije cache karein.
- **Bhoolna ke loop variable loop ke baad apni aakhri value rakhta hai**: ittefaqan us par bharosa na karein.

</Ur>
</Tr>

Given a list of login results in order, like `["fail", "fail", "ok", "fail", "fail", "fail", "fail", "fail", "ok"]`, find the position (1-based) of the attempt where an account would be locked after 5 failures **in a row**, or print "never locked". A success resets the streak.
</En>
<Ur>
Tarteeb se login natijon ki list di ho, jaise `["fail", "fail", "ok", "fail", "fail", "fail", "fail", "fail", "ok"]`, us koshish ki jagah (1 se shuru) dhoondein jahan **lagatar** 5 nakamiyon ke baad account lock hoga, ya "never locked" print karein. Kamyabi silsila reset karti hai.
</Ur>
</Tr>

<Solution>

<Tr>
<En>

```text
results = ["fail", "fail", "ok", "fail", "fail", "fail", "fail", "fail", "ok"]
streak = 0
for i, r in enumerate(results, start=1):
    streak = streak + 1 if r == "fail" else 0
    if streak == 5:
        print("locked at attempt", i)
        break
else:
    print("never locked")

# locked at attempt 8
```

## Remember

<Takeaways>
<Tr>
<En>

- Prefer `for` over anything iterable; it stops by itself.
- Use `range`, `enumerate`, `zip` and `.items()` instead of manual indexes.
- `while` needs a condition that eventually changes, plus an upper bound when in doubt.
- `break` leaves, `continue` skips, `else` runs only when no `break` happened.
- Don't modify a collection while looping over it; build a new one.

</En>

<DeepDive title="More about iteration">

**The iterator protocol.** `for` calls `iter()` on the object and then `next()` until StopIteration. Files, `range`, `zip` and generators produce items lazily, one at a time, so they use little memory.

**itertools.** `itertools.product(hosts, ports)` replaces nested loops, `islice` takes the first N items, `chain` joins iterables, `groupby` groups consecutive items, and `count()` counts forever (with a `break`).

**Comprehensions.** `[x * 2 for x in items if x > 0]` builds a list in one expression; you'll meet them in the data structures module.

**Retry libraries.** For real retries, libraries like `tenacity` add jitter (random extra delay), maximum delays and retry conditions; add jitter so many clients don't retry at the same moment.

**Performance.** Loops in Python are slower than in compiled languages; built-ins (`sum`, `max`, `sorted`, `any`) and libraries like NumPy do the looping in C.

</DeepDive>

<DeepDive title="Real world: the retry storm">

A mobile app's backend called a payment provider and, on any error, retried immediately in a `while True` loop until it succeeded. During a 10-minute provider outage, every request thread spun in that loop, sending thousands of calls per second, exhausting connections and CPU and making the outage worse for everyone. When the provider recovered, the retry flood tripped its rate limits.

The fixes:

1. A bounded loop: at most 5 attempts per request.
2. Exponential backoff with jitter between attempts, capped at 30 seconds.
3. Retrying only errors that are worth retrying (timeouts, 503) and never ones that aren't (400, 401).
4. A circuit breaker that stops calling the provider for a while after many failures and returns a clear error instead.

</DeepDive>

<DeepDive title="Security lens">

- **Bound every loop that handles untrusted input**: a crafted file or request can make an unbounded loop run forever (denial of service).
- **Rate-limit and back off** in scanners and clients so you don't accidentally attack a service or get your IP banned.
- **Lockout logic is a loop over events**: count consecutive failures carefully and reset on success, as in the challenge.
- **Avoid nested loops over attacker-controlled sizes**: quadratic work can be triggered on purpose.
- **Stop scans cleanly**: handle Ctrl+C (KeyboardInterrupt) and leave things in a consistent state.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="When would you use while instead of for?">
When the number of rounds isn't known in advance and depends on a condition, such as retrying until success, polling until a job finishes, or reading until a sentinel. For walking through a collection or a known count, for is clearer and can't run forever.
</QA>

<QA q="What does the else clause on a loop do?">
It runs after the loop completes normally, that is, without hitting break. It's useful for search loops to handle the not-found case without a flag variable.
</QA>

<QA q="Why use enumerate instead of range(len(x))?">
It's clearer, avoids index errors, works with any iterable (not just sequences), and gives the item directly along with its position.
</QA>

<QA q="What happens if you modify a list while iterating over it?">
Items shift and the loop can skip or repeat elements; for dicts and sets, changing the size raises a RuntimeError. Iterate over a copy or build a new collection.
</QA>

<QA q="How do you implement a retry with backoff?">
Loop a bounded number of times, try the operation, break on success, otherwise sleep for an increasing delay such as base times 2 to the attempt number plus random jitter, and raise or report an error after the last attempt.
</QA>

</DeepDive>
