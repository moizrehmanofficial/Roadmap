<BigIdea>
<Tr>
<En>
When you call a function, Python matches **arguments** to **parameters** in two ways: **positional** arguments by order (`connect("db1", 5432)`) and **keyword** arguments by name (`connect(port=5432, host="db1")`). You can mix them, but positional ones come first. A function's definition can shape how it's called. Parameters after a bare **`*`** are **keyword-only**, so callers must write `delete_user("john", force=True)`, never a mysterious `delete_user("john", True)`. Parameters before a **`/`** are **positional-only**, so their names can change without breaking callers. **`*args`** collects any extra positional arguments into a **tuple**, and **`**kwargs`** collects any extra keyword arguments into a **dict**, which lets one function accept "anything" and pass it along. At the call site the same symbols work in reverse: `f(*items)` spreads a sequence into positional arguments and `f(**options)` spreads a dict into keyword arguments. Together they're how wrappers, decorators, retry helpers and flexible APIs such as `requests.get(url, **options)` are built.
</En>
<Ur>
Function call karte waqt Python **arguments** ko **parameters** se do tareeqon se milata hai: **positional** arguments tarteeb se (`connect("db1", 5432)`) aur **keyword** arguments naam se (`connect(port=5432, host="db1")`). Aap unhe mila sakte hain, magar positional pehle aate hain. Function ki definition tay kar sakti hai ke use kaise bulaya jaye. Khaali **`*`** ke baad wale parameters **keyword-only** hain, isliye bulane walon ko `delete_user("john", force=True)` likhna parta hai, kabhi pur-asrar `delete_user("john", True)` nahi. **`/`** se pehle wale parameters **positional-only** hain, isliye un ke naam bulane walon ko tore baghair badal sakte hain. **`*args`** izafi positional arguments ko **tuple** me jama karta, aur **`**kwargs`** izafi keyword arguments ko **dict** me, jis se ek function "kuch bhi" qabool kar ke aage de sakta hai. Call ki jagah wahi nishan ulta kaam karte hain: `f(*items)` sequence ko positional arguments me phailata aur `f(**options)` dict ko keyword arguments me. Mil kar inhi se wrappers, decorators, retry helpers aur `requests.get(url, **options)` jaisi lachakdar APIs banti hain.
</Ur>
</Tr>

## Learn it step by step

<Walkthrough>

<Step title="Positional, keyword, keyword-only, positional-only, *args and **kwargs">

<Tr>
<En>
`args.py` calls `connect` with positional, keyword and mixed arguments, then makes three bad calls and prints each TypeError. It defines `delete_user` with keyword-only flags and `clamp` with positional-only parameters and tries to break both, collects any number of sizes with `*args` and any labels with `**kwargs`, and shows a function using every kind of parameter. A last one-liner tries a positional argument after a keyword one.
</En>
<Ur>
`args.py` `connect` ko positional, keyword aur mile jule arguments se bulati, phir teen ghalat calls kar ke har TypeError print karti hai. Keyword-only flags ke saath `delete_user` aur positional-only parameters ke saath `clamp` define kar ke dono todne ki koshish karti, `*args` se kisi bhi tadad ke sizes aur `**kwargs` se koi bhi labels jama karti, aur har qism ke parameter wala function dikhati hai. Aakhri one-liner keyword ke baad positional argument aazmata hai.
</Ur>
</Tr>

```bash
cat > args.py <<'EOF'
def connect(host, port, timeout=5, tls=True):
    return f"{host}:{port} timeout={timeout} tls={tls}"

print(connect("db1", 5432))                              # positional: matched by order
print(connect(port=5432, host="db1"))                    # keyword: matched by name, any order
print(connect("db1", 5432, tls=False))                   # mix: positional first, then keyword

bad_calls = [lambda: connect("db1"),                      # missing port
             lambda: connect("db1", 5432, host="x"),       # host given twice
             lambda: connect("db1", 5432, retries=3)]      # no such parameter
for call in bad_calls:
    try:
        call()
    except TypeError as e:
        print("TypeError:", e)

# Keyword-only parameters: everything after * must be named
def delete_user(user, *, force=False, dry_run=True):
    return f"delete {user} force={force} dry_run={dry_run}"
print(delete_user("john", dry_run=False))
try:
    delete_user("john", True)                             # what would True mean here? Not allowed.
except TypeError as e:
    print("TypeError:", e)

# Positional-only parameters: everything before / can't be passed by name
def clamp(value, low, high, /):
    return max(low, min(value, high))
print(clamp(150, 0, 100))
try:
    clamp(value=150, low=0, high=100)
except TypeError as e:
    print("TypeError:", str(e)[:60])

# *args collects extra positional arguments into a tuple
def total(*sizes):
    return sum(sizes), sizes
print(total(), total(1024, 2048, 512))

# **kwargs collects extra keyword arguments into a dict
def tag(resource, **labels):
    return resource + " " + " ".join(f"{k}={v}" for k, v in labels.items())
print(tag("web1", env="prod", team="payments", tier=1))

# The full order: positional-only, normal, *args, keyword-only, **kwargs
def everything(a, /, b, *args, c, d=4, **kwargs):
    return a, b, args, c, d, kwargs
print(everything(1, 2, 3, 4, c=5, e=6))
EOF
python3 args.py
python3 -c 'print(dict(a=1, 2))' 2>&1 | tail -1
```

<Happened>
<Tr>
<En>

- All three working calls produced the same connection string: by position, by name in any order, and mixed. Use keywords for anything that isn't obvious from position.
- The three bad calls show the messages you'll meet: a **missing** required argument, a parameter given **twice** (by position and by name), and an **unexpected** keyword (a typo or an option the function doesn't support). Read the parameter name in the message.
- `delete_user("john", True)` was **rejected**: after `*`, `force` and `dry_run` can only be passed by name, so the call site always says what `True` means.
- `clamp(value=150, ...)` was rejected because parameters before `/` are positional-only. Library authors use this so they can rename parameters later.
- `*sizes` became a **tuple**: empty `()` with no arguments, `(1024, 2048, 512)` with three. `**labels` became a **dict** of whatever names the caller invented.
- `everything(1, 2, 3, 4, c=5, e=6)` put 1 in `a`, 2 in `b`, the extra 3 and 4 in `args`, required keyword-only `c`, default `d=4`, and the unknown `e` in `kwargs`.
- A positional argument after a keyword is a **SyntaxError**: Python can't tell where it should go.

</En>
<Ur>

- Teeno chalti calls ne wahi connection string banayi: jagah se, kisi bhi tarteeb me naam se, aur mila kar. Jo cheez jagah se wazeh na ho us ke liye keywords lein.
- Teen ghalat calls woh paighamat dikhati hain jo aap ko milenge: lazmi argument **ghayab**, parameter **do dafa** diya gaya (jagah aur naam dono se), aur **ghair mutawaqqo** keyword (typo ya aisa option jo function support nahi karta). Paigham me parameter ka naam parhein.
- `delete_user("john", True)` **radd** hua: `*` ke baad `force` aur `dry_run` sirf naam se diye ja sakte hain, isliye call ki jagah hamesha batati hai ke `True` ka matlab kya hai.
- `clamp(value=150, ...)` radd hua kyunke `/` se pehle wale parameters positional-only hain. Library likhne wale ise is liye istemal karte hain taa ke baad me parameters ke naam badal sakein.
- `*sizes` **tuple** bana: bina arguments khaali `()`, teen ke saath `(1024, 2048, 512)`. `**labels` bulane wale ke ijaad kiye kisi bhi naam ki **dict** bana.
- `everything(1, 2, 3, 4, c=5, e=6)` ne 1 `a` me, 2 `b` me, izafi 3 aur 4 `args` me, lazmi keyword-only `c`, default `d=4`, aur na-maloom `e` `kwargs` me rakha.
- Keyword ke baad positional argument **SyntaxError** hai: Python nahi bata sakta ke use kahan jana chahiye.

</Ur>

<Step title="Forwarding arguments: wrappers, defaults and retries">

<Tr>
<En>
`wrappers.py` builds a `timed` helper that runs any function with any arguments and reports how long it took, and a `build_request` function with a keyword-only section and `**params` for query parameters. It calls `build_request` with a prepared tuple and dict, merges default options with overrides in `get`, retries a function that fails twice through a generic `retry` helper, and prints a signature with `inspect`.
</En>
<Ur>
`wrappers.py` `timed` helper banati jo kisi bhi function ko kisi bhi arguments ke saath chala kar batata hai kitna waqt laga, aur `build_request` function jis me keyword-only hissa aur query parameters ke liye `**params` hai. Tayyar tuple aur dict se `build_request` bulati, `get` me default options ko overrides se milati, do dafa nakam hone wale function ko aam `retry` helper se dobara aazmati, aur `inspect` se signature print karti hai.
</Ur>
</Tr>

```bash
cat > wrappers.py <<'EOF'
import inspect
import time

# A wrapper that accepts ANY arguments and forwards them unchanged
def timed(func, *args, **kwargs):
    start = time.perf_counter()
    result = func(*args, **kwargs)          # unpack them back into the real call
    took = time.perf_counter() - start
    print(f"{func.__name__} took {'<1' if took < 0.001 else round(took * 1000)} ms")
    return result

def build_request(method, url, *, headers=None, timeout=10, **params):
    query = "&".join(f"{k}={v}" for k, v in params.items())
    return f"{method} {url}{'?' + query if query else ''} timeout={timeout} headers={headers or {}}"

print(timed(build_request, "GET", "/api/orders", page=2, status="open", timeout=5))

# Prepared arguments: a tuple for positional, a dict for keyword
target = ("POST", "/api/login")
options = {"headers": {"Content-Type": "application/json"}, "timeout": 3}
print(build_request(*target, **options))

# Merging defaults with caller options
DEFAULTS = {"timeout": 10, "headers": {"User-Agent": "devguide/1.0"}}
def get(url, **overrides):
    opts = {**DEFAULTS, **overrides}
    return build_request("GET", url, **opts)
print(get("/health"))
print(get("/health", timeout=2))

# Retry helper: forwards arguments to a flaky function
def retry(func, *args, attempts=3, **kwargs):
    for n in range(1, attempts + 1):
        try:
            return func(*args, **kwargs)
        except ConnectionError as e:
            print(f"  attempt {n} failed: {e}")
    raise RuntimeError(f"gave up after {attempts} attempts")

calls = {"n": 0}
def flaky_fetch(path, *, fail_times):
    calls["n"] += 1
    if calls["n"] <= fail_times:
        raise ConnectionError("connection reset")
    return f"200 OK {path}"
print(retry(flaky_fetch, "/api/orders", fail_times=2))

# Inspect a function's parameters
print(inspect.signature(build_request))
EOF
python3 wrappers.py
```

```text output

GET /health timeout=10 headers={'User-Agent': 'devguide/1.0'}
GET /health timeout=2 headers={'User-Agent': 'devguide/1.0'}
  attempt 1 failed: connection reset
  attempt 2 failed: connection reset
200 OK /api/orders
(method, url, *, headers=None, timeout=10, **params)
```

<Happened>
<Tr>
<En>

- `timed(build_request, "GET", "/api/orders", page=2, status="open", timeout=5)` collected everything after the function into `*args` and `**kwargs` and passed it on **unchanged** with `func(*args, **kwargs)`. That pattern is the heart of every decorator you'll write.
- Inside `build_request`, `timeout` matched its keyword-only parameter and the unknown names `page` and `status` landed in `**params`, becoming the **query string**.
- `build_request(*target, **options)` spread a tuple into the method and URL and a dict into headers and timeout: useful when arguments come from config or another function.
- `get` merged `DEFAULTS` with the caller's overrides (`{**DEFAULTS, **overrides}`), so `timeout=2` won but the default **User-Agent** header stayed.
- `retry` forwarded `fail_times=2` to `flaky_fetch` while keeping its own `attempts` option for itself; after **two failures** the third attempt returned **200 OK**. Give helper options keyword-only names that won't clash with the wrapped function's.
- `inspect.signature` printed the parameter list, the same information your editor uses for autocomplete.

</En>
<Ur>

- `timed(build_request, "GET", "/api/orders", page=2, status="open", timeout=5)` ne function ke baad sab kuch `*args` aur `**kwargs` me jama kar ke `func(*args, **kwargs)` se **baghair badle** aage diya. Yahi pattern har decorator ka dil hai jo aap likhenge.
- `build_request` ke andar `timeout` apne keyword-only parameter se mila aur na-maloom naam `page` aur `status` `**params` me pohanche, **query string** ban kar.
- `build_request(*target, **options)` ne tuple ko method aur URL me aur dict ko headers aur timeout me phailaya: kaam ka jab arguments config ya doosre function se aayen.
- `get` ne `DEFAULTS` ko bulane wale ke overrides se milaya (`{**DEFAULTS, **overrides}`), isliye `timeout=2` jeeta magar default **User-Agent** header raha.
- `retry` ne apna `attempts` option apne paas rakhte hue `fail_times=2` `flaky_fetch` ko diya; **do nakamiyon** ke baad teesri koshish ne **200 OK** lautaya. Helper options ko aise keyword-only naam dein jo lapete gaye function ke naamon se na takrayen.
- `inspect.signature` ne parameter list print ki, wahi maloomat jo aap ka editor autocomplete ke liye istemal karta hai.

</Ur>
</Tr>
</Happened>

## Common mistakes

<Compare>
<Bad title="Mystery booleans">

```text
def sync(path, recursive, delete):
    ...
sync("/srv/www", True, True)      # which True deletes files?
```

</Bad>
<Good title="Keyword-only flags">

```text
def sync(path, *, recursive=False, delete=False):
    ...
sync("/srv/www", recursive=True, delete=True)
```

</Good>
</Compare>

<Compare>
<Bad title="Swallowing typos with **kwargs">

```text
def connect(host, **kwargs):
    timeout = kwargs.get("timeout", 5)
    ...
connect("db1", timout=30)          # typo silently ignored, timeout stays 5
```

</Bad>
<Good title="Name the options you support">

```text
def connect(host, *, timeout=5, tls=True):
    ...
connect("db1", timout=30)          # TypeError: unexpected keyword argument 'timout'
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Forgetting to unpack when forwarding**: `func(args, kwargs)` passes a tuple and a dict as two arguments; write `func(*args, **kwargs)`.
- **Mutable defaults** like `headers={}`: use `None` and create the dict inside.
- **Too many positional parameters**: more than three or four is hard to call correctly; make the rest keyword-only or group them.
- **Modifying `kwargs` that the caller passed as `**opts`**: `kwargs` is a new dict, but values inside (lists, dicts) are shared.
- **Naming them anything but `args`/`kwargs` without reason**: the names are convention; only the stars matter, but readers expect these names.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Aage dete waqt unpack bhoolna**: `func(args, kwargs)` tuple aur dict do arguments ki tarah deta; `func(*args, **kwargs)` likhein.
- **`headers={}` jaise mutable defaults**: `None` lein aur andar dict banayen.
- **Bohot se positional parameters**: teen chaar se zyada sahi bulana mushkil; baqi keyword-only karein ya group karein.
- **`**opts` ki tarah diye `kwargs` badalna**: `kwargs` nayi dict hai, magar andar ki values (lists, dicts) mushtarak hain.
- **Baghair wajah `args`/`kwargs` ke ilawa naam rakhna**: naam riwaj hain; sirf stars maayne rakhte, magar parhne wale yahi naam chahte hain.

</Ur>
</Tr>

<DeepDive title="More about arguments">

**Decorators.** `@functools.wraps(func)` plus `def wrapper(*args, **kwargs)` is how decorators preserve the wrapped function's name and docstring; you'll see this pattern often.

**functools.partial.** `partial(connect, port=5432)` pre-fills some arguments and returns a new callable.

**Typing *args and **kwargs.** `def f(*args: int, **kwargs: str)` types each item; `typing.ParamSpec` lets type checkers follow arguments through wrappers.

**Evaluation order.** Arguments are evaluated left to right before the call; default values were evaluated once at definition time.

**Built-ins with positional-only parameters.** Many C functions (like `len(obj, /)`) are positional-only, which is why `len(obj=x)` fails.

</DeepDive>

<DeepDive title="Real world: the True that deleted production">

A cleanup tool had `def purge(bucket, older_than_days, dry_run=True, include_locked=False)`. A teammate wrote `purge("prod-logs", 30, False)` meaning "don't include locked files", but the third positional argument was `dry_run`, so the tool deleted 30 days of production logs for real.

The fixes:

1. `def purge(bucket, older_than_days, *, dry_run=True, include_locked=False)`: flags must be named.
2. Print a summary and ask for confirmation unless `--yes` is passed explicitly.
3. Object versioning on the bucket so deletions could be undone.
4. Code review guidance: no bare booleans at call sites.

</DeepDive>

<DeepDive title="Security lens">

- **Keyword-only safety flags** (`dry_run`, `force`, `verify_tls`) make dangerous choices explicit and reviewable.
- **Never forward untrusted `**data` into internal functions** (`create_user(**request.json)`): attackers can set parameters like `is_admin=True`. Pick allowed fields.
- **Watch `verify=False`-style options** being passed through generic `**kwargs` wrappers; log or forbid them.
- **Validate `*args` counts and types** when they come from user input such as command-line arguments.
- **Don't log full `kwargs`** if they may contain passwords or tokens.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What are *args and **kwargs?">
In a definition, *args collects extra positional arguments into a tuple and **kwargs collects extra keyword arguments into a dict. In a call, * and ** unpack a sequence or mapping into arguments.
</QA>

<QA q="What are keyword-only arguments and why use them?">
Parameters after * (or after *args) that must be passed by name. They make calls readable and prevent mistakes with booleans and optional settings.
</QA>

<QA q="What does / mean in a function signature?">
Parameters before it are positional-only and can't be passed by keyword, letting authors rename them without breaking callers.
</QA>

<QA q="What is the order of parameter kinds?">
Positional-only, then normal, then *args, then keyword-only, then **kwargs.
</QA>

<QA q="How do you write a function that wraps any other function?">
Accept *args and **kwargs and call the wrapped function with func(*args, **kwargs), returning its result, usually with functools.wraps when building a decorator.
</QA>

</DeepDive>
