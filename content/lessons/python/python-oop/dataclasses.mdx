title: "Dataclasses"
summary: "Most classes that mainly hold data need the same boilerplate: an __init__ that stores each field, a readable __repr__, and __eq__ that compares fields. The @dataclass decorator writes all of that from simple type-annotated fields. Learn from zero fields and defaults, default_factory for lists and dicts (and the error for mutable defaults), asdict, astuple and replace, hiding secrets with field(repr=False), validation in __post_init__, order=True for sorting, frozen=True for immutable hashable records, kw_only and slots, compare=False, building from JSON-like dicts safely, serialising to JSON, and inheritance. All verified with Python 3.13."

<BigIdea>
<Tr>
<En>
A **dataclass** is a normal class with the boring parts generated for you. You list the **fields** as class-level type annotations, `name: str`, `ports: list[int] = field(default_factory=list)`, and **`@dataclass`** writes `__init__`, `__repr__` and `__eq__` (comparing all fields in order). Options turn on more: **`order=True`** adds `<`, `>` and friends so records sort by their fields; **`frozen=True`** makes instances **immutable** (assigning raises an error) and **hashable**, so they can be set members and dict keys; **`kw_only=True`** forces callers to name every field; **`slots=True`** saves memory and blocks accidental new attributes. **`field()`** tunes individual fields: `default_factory` creates a fresh list or dict per instance (a plain `[]` default is rejected, avoiding the shared-mutable-default bug), `repr=False` hides secrets, `compare=False` leaves a field out of equality. **`__post_init__`** runs after the generated `__init__`, the place to **validate** and normalise. Helpers `asdict()`, `astuple()` and `replace()` convert and copy. Dataclasses are still regular classes: you can add methods, properties and class methods. They're ideal for records like hosts, findings, configs and API payloads; note that type hints aren't enforced, so validate untrusted input yourself (or use Pydantic).
</En>
<Ur>
**Dataclass** aam class hai jis ke bore hisse aap ke liye ban jate hain. Aap **fields** ko class level ke type annotations ki tarah likhte hain, `name: str`, `ports: list[int] = field(default_factory=list)`, aur **`@dataclass`** `__init__`, `__repr__` aur `__eq__` (tamam fields tarteeb se milata) likh deta hai. Options mazeed kholte hain: **`order=True`** `<`, `>` waghaira jorta taa ke records apne fields se sort hon; **`frozen=True`** instances ko **immutable** (assign karna error deta) aur **hashable** banata, taa ke set members aur dict keys ban sakein; **`kw_only=True`** bulane walon ko har field ka naam lene par majboor karta; **`slots=True`** memory bachata aur ittefaqi naye attributes rokta hai. **`field()`** alag fields ko set karta hai: `default_factory` har instance ke liye taza list ya dict banata (saada `[]` default radd hota hai, mushtarak mutable default ke bug se bachate hue), `repr=False` secrets chhupata, `compare=False` field ko barabari se bahar rakhta hai. **`__post_init__`** bane hue `__init__` ke baad chalta, **validate** aur normalise karne ki jagah. Helpers `asdict()`, `astuple()` aur `replace()` badalte aur copy karte hain. Dataclasses phir bhi aam classes hain: aap methods, properties aur class methods jor sakte hain. Ye hosts, findings, configs aur API payloads jaise records ke liye behtareen hain; dhyan rahe type hints lagu nahi hote, isliye ghair bharosemand input khud validate karein (ya Pydantic lein).
</Ur>

## Picture it

<Tr>
<En>

Think of a **form generator**.

- You write the list of fields once ("name: text; ip: text; ports: list; env: text, default prod").
- The generator produces the paper form (`__init__`), the way it's displayed (`__repr__`) and the rule for whether two forms say the same thing (`__eq__`).
- `frozen=True` prints the form in ink: once filled in, it can't be changed, only copied with changes (`replace`).
- `__post_init__` is the clerk who checks the form right after it's filled in and rejects a port of 70000.

</En>
<Ur>

**Form banane wali machine** socheyn.

- Aap fields ki list ek dafa likhte hain ("name: text; ip: text; ports: list; env: text, default prod").
- Machine kaghazi form (`__init__`), us ke dikhne ka tareeqa (`__repr__`) aur do forms ke ek hi baat kehne ka qaida (`__eq__`) bana deti hai.
- `frozen=True` form ko siyahi se chhapta hai: bharne ke baad badla nahi ja sakta, sirf tabdeeliyon ke saath copy (`replace`).
- `__post_init__` woh clerk hai jo form bharte hi check karta aur 70000 wala port radd karta hai.

</Ur>
</Tr>

## Learn it step by step

<Walkthrough>

<Step title="Fields, defaults, validation, ordering and freezing">

<Tr>
<En>
`dc.py` defines a `Host` dataclass with a `default_factory` list and a plain default, shows the generated repr and equality and converts to a dict and a tuple. It tries a mutable `[]` default, then builds a `Credential` with a hidden token and a `__post_init__` that validates the port and normalises the user. Finally a frozen, ordered `Version` sorts, compares, deduplicates in a set, refuses assignment, and is "changed" with `replace`.
</En>
<Ur>
`dc.py` `default_factory` list aur saade default ke saath `Host` dataclass define karti, bana hua repr aur barabari dikhati aur dict aur tuple me badalti hai. Mutable `[]` default aazmati, phir chhupe token aur port validate karne aur user normalise karne wale `__post_init__` ke saath `Credential` banati hai. Aakhir me frozen, ordered `Version` sort, muqabla, set me duplicate hatana, assign se inkar, aur `replace` se "badalna" karta hai.
</Ur>
</Tr>

```bash
cat > dc.py <<'EOF'
from dataclasses import dataclass, field, asdict, astuple, replace

@dataclass
class Host:
    name: str
    ip: str
    ports: list[int] = field(default_factory=list)    # a NEW list for each host
    env: str = "prod"

web = Host("web1", "10.0.0.10", [80, 443])
db = Host("db1", "10.0.0.20")
db.ports.append(5432)
print(web)                                            # generated __repr__
print(db, web == Host("web1", "10.0.0.10", [80, 443])) # generated __eq__ compares fields
print(asdict(web), astuple(db))

# Mutable defaults are rejected outright
try:
    @dataclass
    class Bad:
        ports: list[int] = []
except ValueError as e:
    print("ValueError:", e)

# Validation and derived fields in __post_init__, secrets hidden from repr
@dataclass
class Credential:
    user: str
    token: str = field(repr=False)                    # not shown in repr
    port: int = 443
    def __post_init__(self):
        if not 1 <= self.port <= 65535:
            raise ValueError(f"bad port {self.port}")
        self.user = self.user.strip().lower()

print(Credential("  Jane ", "acme_live_9f8e7d6c5b4a"))
try:
    Credential("john", "t", port=70000)
except ValueError as e:
    print("ValueError:", e)

# order=True: compare and sort by the fields in order; frozen=True: immutable and hashable
@dataclass(order=True, frozen=True)
class Version:
    major: int
    minor: int
    patch: int = 0

vs = [Version(1, 10), Version(1, 2), Version(1, 9, 3)]
print(sorted(vs)[-1], Version(2, 0) > Version(1, 99), len({Version(1, 2), Version(1, 2, 0)}))
v = Version(1, 2)
try:
    v.minor = 3
except Exception as e:
    print(type(e).__name__ + ":", e)
print(replace(v, minor=3), v)                         # a modified COPY
EOF
python3 dc.py
```

```text output
Host(name='web1', ip='10.0.0.10', ports=[80, 443], env='prod')
Host(name='db1', ip='10.0.0.20', ports=[5432], env='prod') True
{'name': 'web1', 'ip': '10.0.0.10', 'ports': [80, 443], 'env': 'prod'} ('db1', '10.0.0.20', [5432], 'prod')
ValueError: mutable default <class 'list'> for field ports is not allowed: use default_factory
Credential(user='jane', port=443)
ValueError: bad port 70000
Version(major=1, minor=10, patch=0) True 1
FrozenInstanceError: cannot assign to field 'minor'
Version(major=1, minor=3, patch=0) Version(major=1, minor=2, patch=0)
```

<Happened>
<Tr>
<En>

- Five lines of field declarations gave `Host` a working `__init__`, a **readable repr** and **field-by-field equality** (`True` for an identical host). No hand-written methods.
- `default_factory=list` gave `db` its own list, so appending 5432 didn't touch `web`. A plain `ports: list[int] = []` is **rejected** with a ValueError that tells you to use `default_factory`: dataclasses prevent the shared-mutable-default bug.
- `asdict` and `astuple` converted the records, ready for JSON or CSV.
- `Credential`'s repr **omitted the token** thanks to `field(repr=False)`, and `__post_init__` normalised "  Jane " to **jane** and rejected port **70000** with a clear error. Validation in `__post_init__` means no invalid object can exist.
- `order=True` made `Version` compare field by field like a tuple (major, minor, patch), so sorting put **1.10.0** last. `frozen=True` made it **hashable** (two equal versions collapsed to one in a set) and **immutable**: assigning raised **FrozenInstanceError**, and `replace()` returned a modified copy.

</En>
<Ur>

- Fields ki paanch lines ne `Host` ko chalta `__init__`, **parhne layak repr** aur **field ba field barabari** (`True` ek jaise host ke liye) di. Haath se likha koi method nahi.
- `default_factory=list` ne `db` ko apni list di, isliye 5432 append karne se `web` ko kuch nahi hua. Saada `ports: list[int] = []` aise ValueError ke saath **radd** hota hai jo `default_factory` istemal karne ko kehta hai: dataclasses mushtarak mutable default ka bug rokti hain.
- `asdict` aur `astuple` ne records badle, JSON ya CSV ke liye tayyar.
- `field(repr=False)` ki badaulat `Credential` ke repr ne **token chhora**, aur `__post_init__` ne "  Jane " ko **jane** banaya aur port **70000** ko wazeh error ke saath radd kiya. `__post_init__` me validation ka matlab koi ghalat object wujood me nahi aa sakta.
- `order=True` ne `Version` ko tuple (major, minor, patch) ki tarah field ba field milaya, isliye sorting ne **1.10.0** aakhir me rakha. `frozen=True` ne ise **hashable** (do barabar versions set me ek ban gaye) aur **immutable** banaya: assign karna **FrozenInstanceError** deta, aur `replace()` ne badli hui copy lautayi.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="kw_only, slots, JSON in and out, inheritance">

<Tr>
<En>
`dc2.py` defines a `Finding` with `kw_only` and `slots`, a datetime default, and a `notes` field excluded from comparisons. It serialises a finding to JSON, builds one from a dict that contains an unexpected extra key, tries positional arguments and a new attribute, and finally shows dataclass inheritance with `fields()`.
</En>
<Ur>
`dc2.py` `kw_only` aur `slots`, datetime default, aur comparisons se bahar `notes` field wali `Finding` define karti hai. Finding ko JSON me badalti, ghair mutawaqqo izafi key wali dict se banati, positional arguments aur naya attribute aazmati, aur aakhir me `fields()` ke saath dataclass inheritance dikhati hai.
</Ur>
</Tr>

```bash
cat > dc2.py <<'EOF'
import json
from dataclasses import dataclass, field, asdict, fields
from datetime import datetime, timezone

@dataclass(kw_only=True, slots=True)
class Finding:
    host: str
    port: int
    severity: str = "medium"
    found_at: datetime = field(default_factory=lambda: datetime(2026, 11, 23, 14, 5, tzinfo=timezone.utc))
    notes: list[str] = field(default_factory=list, compare=False)   # ignored by ==

    @classmethod
    def from_dict(cls, data):                       # build from JSON-like data, ignoring unknown keys
        known = {f.name for f in fields(cls)}
        return cls(**{k: v for k, v in data.items() if k in known})

    def to_json(self):
        d = asdict(self)
        d["found_at"] = self.found_at.isoformat()   # datetimes aren't JSON-serialisable as-is
        return json.dumps(d)

f1 = Finding(host="db1", port=6379, severity="high")
f2 = Finding(host="db1", port=6379, severity="high", notes=["seen twice"])
print(f1 == f2, "(notes ignored in comparisons)")
print(f1.to_json())

incoming = {"host": "win1", "port": 3389, "severity": "high", "is_admin": True}   # extra key from outside
print(Finding.from_dict(incoming))

try:
    Finding("db1", 6379)                            # kw_only: positional arguments not allowed
except TypeError as e:
    print("TypeError:", e)
try:
    f1.extra = 1                                    # slots: no new attributes by accident
except AttributeError as e:
    print("AttributeError:", e)

# Inheritance works field by field
@dataclass
class Base:
    id: int
@dataclass
class User(Base):
    email: str
    roles: list[str] = field(default_factory=lambda: ["viewer"])
print(User(7, "jane@example.com"), [f.name for f in fields(User)])
EOF
python3 dc2.py
```

```text output
True (notes ignored in comparisons)
{"host": "db1", "port": 6379, "severity": "high", "found_at": "2026-11-23T14:05:00+00:00", "notes": []}
Finding(host='win1', port=3389, severity='high', found_at=datetime.datetime(2026, 11, 23, 14, 5, tzinfo=datetime.timezone.utc), notes=[])
TypeError: Finding.__init__() takes 1 positional argument but 3 were given
AttributeError: 'Finding' object has no attribute 'extra' and no __dict__ for setting new attributes
User(id=7, email='jane@example.com', roles=['viewer']) ['id', 'email', 'roles']
```

<Happened>
<Tr>
<En>

- `f1 == f2` was **True** even though only one had notes: `compare=False` left `notes` out of equality, useful for metadata that shouldn't affect identity.
- `to_json()` used `asdict`, then converted the datetime to ISO text because `json.dumps` can't serialise datetimes directly.
- `from_dict` built a `Finding` from incoming data but **dropped the unknown `is_admin` key** by filtering against `fields(cls)`. Never pass untrusted dicts straight into `cls(**data)`; choose the fields you accept.
- `kw_only=True` made `Finding("db1", 6379)` a **TypeError**: callers must write `host=` and `port=`, which keeps long records readable.
- `slots=True` blocked `f1.extra = 1`: typos like `f1.serverity = "low"` fail loudly instead of silently creating a new attribute.
- `User(Base)` inherited the `id` field and added its own, in order: **id, email, roles**.

</En>
<Ur>

- `f1 == f2` **True** tha halanke sirf ek ke notes the: `compare=False` ne `notes` ko barabari se bahar rakha, aise metadata ke liye kaam ka jo pehchaan par asar na kare.
- `to_json()` ne `asdict` istemal kiya, phir datetime ko ISO text me badla kyunke `json.dumps` datetimes seedhe serialise nahi kar sakta.
- `from_dict` ne aane wale data se `Finding` banayi magar `fields(cls)` se chhaan kar **na-maloom `is_admin` key gira di**. Ghair bharosemand dicts kabhi seedhe `cls(**data)` me na dein; jo fields qabool karte hain unhe chunein.
- `kw_only=True` ne `Finding("db1", 6379)` ko **TypeError** banaya: bulane walon ko `host=` aur `port=` likhna parta hai, jo lambe records parhne layak rakhta hai.
- `slots=True` ne `f1.extra = 1` roka: `f1.serverity = "low"` jaise typos khamoshi se naya attribute banane ke bajaye zor se nakam hote hain.
- `User(Base)` ne `id` field inherit kiya aur apne tarteeb se jore: **id, email, roles**.

</Ur>
</Tr>
</Happened>

## Common mistakes

<Compare>
<Bad title="Trusting type hints to validate">

```text
@dataclass
class Host:
    name: str
    port: int

Host(name=None, port="eighty")      # accepted: hints aren't checked at runtime
```

</Bad>
<Good title="Validate in __post_init__ (or use Pydantic for external data)">

```text
@dataclass
class Host:
    name: str
    port: int
    def __post_init__(self):
        if not isinstance(self.name, str) or not self.name:
            raise ValueError("name required")
        if not isinstance(self.port, int) or not 1 <= self.port <= 65535:
            raise ValueError(f"bad port {self.port!r}")
```

</Good>
</Compare>

<Compare>
<Bad title="Secrets in the generated repr">

```text
@dataclass
class ApiClient:
    base_url: str
    token: str
print(client)    # ApiClient(base_url='...', token='acme_live_...')
```

</Bad>
<Good title="Exclude them">

```text
@dataclass
class ApiClient:
    base_url: str
    token: str = field(repr=False)
print(client)    # ApiClient(base_url='...')
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Non-default field after a default field**: `a: int = 0` then `b: int` is a TypeError; reorder, or use `kw_only=True`.
- **Frozen dataclasses holding lists**: the list itself can still be changed; use tuples for truly immutable data.
- **`order=True` comparing fields in the wrong order**: field order defines sort priority; declare the most important first or write a `sort_index` field.
- **`cls(**request_json)`**: mass assignment; filter allowed fields.
- **Expecting `asdict` to handle datetimes, Decimals or sets for JSON**: convert them yourself.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Default field ke baad baghair default field**: `a: int = 0` phir `b: int` TypeError hai; tarteeb badlein, ya `kw_only=True` lein.
- **Lists rakhne wali frozen dataclasses**: list khud phir bhi badal sakti hai; sach me immutable data ke liye tuples lein.
- **`order=True` ka fields ko ghalat tarteeb me milana**: fields ki tarteeb sort ki tarjeeh tay karti hai; sab se ahem pehle likhein ya `sort_index` field banayen.
- **`cls(**request_json)`**: mass assignment; ijazat yafta fields chhaanein.
- **`asdict` se JSON ke liye datetimes, Decimals ya sets sambhalne ki tawaqqo**: khud badlein.

</Ur>
</Tr>

```text
from dataclasses import dataclass, replace

@dataclass(frozen=True)
class Rule:
    action: str
    port: int
    source: str = "any"
    def __post_init__(self):
        if self.action not in ("allow", "deny"):
            raise ValueError(f"bad action {self.action!r}")
        if not 1 <= self.port <= 65535:
            raise ValueError(f"bad port {self.port}")

rules = {Rule("allow", 443), Rule("allow", 443), Rule("allow", 22, "10.0.0.0/8")}
print(len(rules))
print(replace(Rule("allow", 443), action="deny"))
try:
    Rule("permit", 80)
except ValueError as e:
    print("ValueError:", e)

# 2
# Rule(action='deny', port=443, source='any')
# ValueError: bad action 'permit'
```

<DeepDive title="More about dataclasses">

**How it works.** The decorator reads `__annotations__`, generates source for the methods and attaches them to the class at definition time; there's no runtime overhead afterwards compared with hand-written methods.

**InitVar and ClassVar.** `InitVar[str]` fields are passed to `__init__` and `__post_init__` but not stored; `ClassVar[int]` marks a real class attribute that isn't a field.

**Frozen plus post_init.** In a frozen dataclass, `__post_init__` must use `object.__setattr__(self, "name", value)` to normalise fields.

**Alternatives.** `attrs` (the library dataclasses were inspired by) adds validators and converters; Pydantic adds runtime validation and JSON parsing; `msgspec` is very fast for serialisation.

**Pattern matching.** Dataclasses define `__match_args__`, so `match finding: case Finding(host=h, port=3389):` works.

</DeepDive>

<DeepDive title="Real world: the config that accepted anything">

A deployment tool loaded YAML into `@dataclass class DeployConfig` with `replicas: int` and `env: str`, trusting the hints. A typo in a YAML file set `replicas: "3 "` (a string with a space), and `env: prdo`. The dataclass happily accepted both; a later `range(config.replicas)` crashed mid-deploy, and the misspelled environment silently used defaults meant for development.

The fixes:

1. `__post_init__` validation: `replicas` must be an int from 1 to 50, `env` must be in `{"dev", "staging", "prod"}` (or a `Literal` plus a checker).
2. Parsing with Pydantic for files coming from humans, giving clear error messages with line context.
3. Failing the deploy at config load time, before any change is made.

</DeepDive>

<DeepDive title="Security lens">

- **`field(repr=False)`** for passwords, tokens and keys, because dataclass reprs appear in logs and tracebacks.
- **Validate in `__post_init__`** so invalid security settings (an empty allow-list, a port of 0, an unknown role) can't be constructed.
- **Avoid mass assignment**: build from external dicts by explicit allowed fields, never `cls(**untrusted)`.
- **Frozen records for decisions** (an evaluated permission, an audit entry) prevent tampering after creation.
- **`asdict` exposes everything**: when serialising to API responses, choose fields explicitly to avoid leaking internal or sensitive data.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What does @dataclass do?">
It inspects the class's annotated fields and generates methods such as `__init__`, `__repr__` and `__eq__`, and optionally ordering, hashing, slots and keyword-only parameters, reducing boilerplate for data-holding classes.
</QA>

<QA q="Why can't you use [] as a default in a dataclass?">
Defaults are evaluated once and would be shared by every instance; dataclasses detect mutable defaults like lists and raise ValueError, requiring field(default_factory=list) instead.
</QA>

<QA q="What is __post_init__ for?">
It runs after the generated `__init__`, allowing validation, normalisation and computing derived fields.
</QA>

<QA q="Dataclass vs NamedTuple?">
NamedTuples are immutable tuples with named fields that support unpacking and indexing; dataclasses are regular classes, mutable by default, more flexible with defaults, methods, validation and options like frozen and slots.
</QA>

<QA q="Are dataclass type hints enforced?">
No. They define fields and help type checkers, but values aren't validated at runtime unless you add checks in `__post_init__` or use a library like Pydantic.
</QA>

</DeepDive>
