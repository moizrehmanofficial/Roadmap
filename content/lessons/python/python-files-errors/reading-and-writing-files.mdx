<BigIdea>
<Tr>
<En>
`open(path, mode, encoding=...)` gives you a **file object**. The **mode** says what you'll do: `"r"` read (the default), `"w"` write (creates the file or **erases** it first), `"a"` append to the end, `"x"` create a **new** file and fail if it exists; add `"b"` for **binary** (`"rb"`, `"wb"`) to work with raw bytes instead of text. Always open files with **`with open(...) as f:`**, which closes the file even if an error happens. Text files are bytes on disk that Python **decodes** into strings; always pass **`encoding="utf-8"`**, because the default depends on the operating system and is a common source of `UnicodeDecodeError` and mangled characters. To read, use `f.read()` for small files, or loop **`for line in f:`** to stream big files one line at a time. To write, use `f.write(text)` (you add the `"\n"` yourself) or `print(..., file=f)`. Robust scripts also handle the usual errors (`FileNotFoundError`, `PermissionError`, `FileExistsError`), read binary data in **chunks**, write important files **atomically** so readers never see a half-written file, and create secret files with **restrictive permissions**.
</En>
<Ur>
`open(path, mode, encoding=...)` aap ko **file object** deta hai. **Mode** batata hai aap kya karenge: `"r"` parhna (default), `"w"` likhna (file banata ya pehle **mita** deta), `"a"` aakhir me jorna, `"x"` **nayi** file banana aur mojood ho to nakam hona; text ke bajaye khaam bytes ke saath kaam ke liye `"b"` jorein (`"rb"`, `"wb"`) jo **binary** hai. Files hamesha **`with open(...) as f:`** se kholein, jo error hone par bhi file band karta hai. Text files disk par bytes hain jinhe Python strings me **decode** karta hai; hamesha **`encoding="utf-8"`** dein, kyunke default operating system par mabni hai aur `UnicodeDecodeError` aur bigre characters ka aam sarchashma hai. Parhne ke liye chhoti files ke liye `f.read()`, ya bari files line ba line chalane ke liye **`for line in f:`** loop. Likhne ke liye `f.write(text)` (`"\n"` khud jorte hain) ya `print(..., file=f)`. Mazboot scripts aam errors (`FileNotFoundError`, `PermissionError`, `FileExistsError`) bhi sambhalti, binary data **tukron** me parhti, ahem files **atomic** tareeqe se likhti taa ke parhne wale kabhi adhi likhi file na dekhein, aur secret files **sakht permissions** ke saath banati hain.
</Ur>

## Picture it

<Tr>
<En>

Think of a **notebook**.

- `"r"` is reading it; `"a"` is writing on the next empty page; `"w"` is tearing out every page and starting again; `"x"` is "give me a brand-new notebook, and refuse if this one already exists".
- `with` is putting the notebook back on the shelf automatically when you're done, even if you're interrupted.
- The encoding is the alphabet the notebook is written in. Reading a French notebook as if it only contained English letters makes the accented words come out as nonsense.
- An atomic write is writing the new version in a fresh notebook and swapping it onto the shelf in one movement, so nobody ever picks up a half-written one.

</En>
<Ur>

**Copy (notebook)** socheyn.

- `"r"` use parhna hai; `"a"` agle khaali safhe par likhna; `"w"` saare safhe phaar kar dobara shuru karna; `"x"` "mujhe bilkul nayi copy do, aur agar ye pehle se ho to inkar karo".
- `with` kaam khatam hone par copy khud shelf par wapas rakhna hai, chahe beech me rokna pare.
- Encoding woh haroof tahji hai jis me copy likhi gayi. French copy ko sirf English haroof wali samajh kar parhna aaraab wale alfaaz ko be-maani bana deta hai.
- Atomic write naya version taza copy me likh kar ek harkat me shelf par badalna hai, taa ke koi kabhi adhi likhi copy na uthaye.

## Learn it step by step

<Walkthrough>

<Step title="Text files: write, read, append, create and encodings">

<Tr>
<En>
`files.py` writes a hosts file with `write` and `writelines` (one name has an accented character), reads it three ways, appends a line with `print(file=f)`, tries `"x"` mode on an existing file, opens a missing file, then looks at the raw bytes and decodes the file with the wrong encoding to see what happens.
</En>
<Ur>
`files.py` `write` aur `writelines` se hosts file likhti (ek naam me aaraab wala character hai), use teen tareeqon se parhti, `print(file=f)` se line jorti, mojood file par `"x"` mode aazmati, ghayab file kholti, phir khaam bytes dekhti aur ghalat encoding se file decode kar ke dekhti hai kya hota hai.
</Ur>
</Tr>

```bash
cat > files.py <<'EOF'
# Write a text file: "w" creates or OVERWRITES. Always say the encoding.
with open("hosts.txt", "w", encoding="utf-8") as f:     # with: the file is closed automatically
    f.write("web1 10.0.0.10\n")
    f.write("db1 10.0.0.20\n")
    f.writelines(["cache1 10.0.0.30\n", "café-proxy 10.0.0.40\n"])

# Read it all at once, as lines, or (best for big files) one line at a time
with open("hosts.txt", encoding="utf-8") as f:
    text = f.read()
print(repr(text[:30]), "...", len(text), "characters")
with open("hosts.txt", encoding="utf-8") as f:
    print(f.readlines()[:2])
with open("hosts.txt", encoding="utf-8") as f:
    for n, line in enumerate(f, start=1):              # streams: one line in memory at a time
        name, ip = line.split()                         # split() also drops the "\n"
        print(n, name, ip)

# "a" appends to the end instead of overwriting
with open("hosts.txt", "a", encoding="utf-8") as f:
    print("lb1 10.0.0.5", file=f)                       # print can write to files too
with open("hosts.txt", encoding="utf-8") as f:
    print("now", sum(1 for _ in f), "lines")

# "x" creates a NEW file and refuses to overwrite an existing one
try:
    with open("hosts.txt", "x", encoding="utf-8") as f:
        f.write("oops")
except FileExistsError as e:
    print("FileExistsError:", e)

# Common errors
try:
    with open("missing.txt", encoding="utf-8") as f:
        f.read()
except FileNotFoundError as e:
    print(type(e).__name__, "-", e.strerror, "-", e.filename)

# Encoding matters: bytes on disk vs text in Python
with open("hosts.txt", "rb") as f:                     # "b": raw bytes, no decoding
    raw = f.read()
print(raw[-30:-14], "| é is", len("é".encode("utf-8")), "bytes in UTF-8")
try:
    with open("hosts.txt", encoding="ascii") as f:
        f.read()
except UnicodeDecodeError as e:
    print("UnicodeDecodeError:", e.reason, "at byte", e.start)
EOF
python3 files.py
```

<Tr>
<En>

- `"w"` created **hosts.txt**; each `write` needed its own `"\n"`. When the `with` block ended, the file was **closed** and flushed to disk automatically.
- `f.read()` returned one string with **67 characters**, `readlines()` a list of lines (each still ending in `"\n"`), and `for line in f` streamed line by line; `split()` handily dropped the newline.
- `"a"` added **lb1** at the end, so the file now had **5 lines**. Opening a log with `"w"` by mistake would have erased it.
- `"x"` refused to touch the existing file with **FileExistsError**: a safe way to avoid overwriting reports or keys.
- `FileNotFoundError` carries `strerror` and `filename`, useful for clear messages.
- In the raw bytes, **é is 2 bytes** in UTF-8. Reading the same file as ASCII raised **UnicodeDecodeError** at byte 49, where the é starts. Always pass `encoding="utf-8"` (and `errors="replace"` for messy logs) instead of relying on the platform default.

</En>
<Ur>

- `"w"` ne **hosts.txt** banayi; har `write` ko apna `"\n"` chahiye tha. `with` block khatam hone par file khud **band** ho kar disk par likh di gayi.
- `f.read()` ne **67 characters** ki ek string lautayi, `readlines()` ne lines ki list (har ek ab bhi `"\n"` par khatam), aur `for line in f` ne line ba line chalaya; `split()` ne aasani se newline gira di.
- `"a"` ne aakhir me **lb1** jora, isliye file me ab **5 lines** thin. Ghalti se log ko `"w"` se kholna use mita deta.
- `"x"` ne **FileExistsError** ke saath mojood file chhoone se inkar kiya: reports ya keys overwrite hone se bachne ka mehfooz tareeqa.
- `FileNotFoundError` `strerror` aur `filename` rakhta hai, wazeh paighamat ke liye kaam ka.
- Khaam bytes me UTF-8 ka **é 2 bytes** hai. Wahi file ASCII ki tarah parhne par byte 49 par, jahan é shuru hota hai, **UnicodeDecodeError** aaya. Platform default par bharosa karne ke bajaye hamesha `encoding="utf-8"` (aur gande logs ke liye `errors="replace"`) dein.

</Ur>

<Step title="Binary files, chunks, big logs, atomic writes and secret files">

<Tr>
<En>
`binary.py` writes a 1 MiB binary file and hashes it 64 KiB at a time, creates a 10,000-line log and gets its last three lines with a `deque` and the line numbers of errors by streaming. It then writes a config file atomically through a temporary file and `os.replace`, and creates an API key file that only its owner can read. Finally we check that no temporary files were left behind.
</En>
<Ur>
`binary.py` 1 MiB ki binary file likh kar use 64 KiB ek waqt me hash karti, 10,000 line ka log bana kar `deque` se us ki aakhri teen lines aur streaming se errors ke line numbers nikalti hai. Phir temporary file aur `os.replace` ke zariye config file atomic tareeqe se likhti, aur aisi API key file banati jo sirf us ka maalik parh sake. Aakhir me hum check karte hain ke koi temporary file peeche nahi bachi.
</Ur>
</Tr>

```bash
cat > binary.py <<'EOF'
import hashlib, os, tempfile
from collections import deque

# 1. Binary files and hashing in chunks (works for files bigger than memory)
with open("backup.bin", "wb") as f:
    f.write(bytes(range(256)) * 4096)                        # 1 MiB of predictable bytes

def sha256_of(path, chunk_size=64 * 1024):
    h = hashlib.sha256()
    with open(path, "rb") as f:
        while chunk := f.read(chunk_size):                     # read 64 KiB at a time
            h.update(chunk)
    return h.hexdigest()
print("size:", os.path.getsize("backup.bin"), "| sha256:", sha256_of("backup.bin")[:16] + "...")

# 2. Last N lines of a log without loading it all
with open("app.log", "w", encoding="utf-8") as f:
    for i in range(1, 10_001):
        f.write(f"line {i} status={'ERROR' if i % 2500 == 0 else 'ok'}\n")
with open("app.log", encoding="utf-8") as f:
    last = deque(f, maxlen=3)                                   # keeps only the last 3 lines
print([l.strip() for l in last])
with open("app.log", encoding="utf-8") as f:
    errors = [n for n, l in enumerate(f, 1) if "ERROR" in l]
print("errors on lines:", errors)

# 3. Atomic write: write a temp file, then replace in one step (readers never see half a file)
def atomic_write(path, text):
    folder = os.path.dirname(os.path.abspath(path))
    fd, tmp = tempfile.mkstemp(dir=folder, prefix=".tmp-")
    try:
        with os.fdopen(fd, "w", encoding="utf-8") as f:
            f.write(text)
            f.flush()
            os.fsync(f.fileno())                               # make sure it's on disk
        os.replace(tmp, path)                                  # atomic on the same filesystem
    except BaseException:
        os.remove(tmp)
        raise
atomic_write("config.json", '{"retries": 5}\n')
with open("config.json", encoding="utf-8") as f:
    print("config:", f.read().strip())

# 4. Secret files: create them readable by the owner only (Unix permissions 600)
fd = os.open("api.key", os.O_WRONLY | os.O_CREAT | os.O_TRUNC, 0o600)
with os.fdopen(fd, "w") as f:
    f.write("acme_live_9f8e7d6c5b4a\n")
print("api.key mode:", oct(os.stat("api.key").st_mode & 0o777))
EOF
python3 binary.py
echo "leftover temp files: $(ls -a | grep -c '^\.tmp-')"
```

```text output
size: 1048576 | sha256: fbbab289f7f94b25...
['line 9998 status=ok', 'line 9999 status=ok', 'line 10000 status=ERROR']
errors on lines: [2500, 5000, 7500, 10000]
config: {"retries": 5}
api.key mode: 0o600
leftover temp files: 0
```

<Happened>
<Tr>
<En>

- `"wb"` wrote **bytes**, not text. `sha256_of` read **64 KiB chunks** in a loop (`while chunk := f.read(...)` stops at the empty chunk at the end), so the same function can hash a 50 GB disk image with constant memory. Use this to verify downloads and backups.
- `deque(f, maxlen=3)` walked through 10,000 lines but kept only the **last three**: a memory-safe `tail`. Streaming with `enumerate` found the **four ERROR lines** without loading the file.
- `atomic_write` wrote to a hidden temp file in the **same folder**, forced it to disk with `fsync`, then `os.replace` swapped it into place in one step. A reader (or a crash) sees either the old config or the new one, never a half-written file. **0 temp files** were left over.
- `os.open(..., 0o600)` created **api.key** with permissions **0o600**: only the owner can read or write it. Creating with `open()` and fixing permissions afterwards leaves a short window where others could read it.

</En>
<Ur>

- `"wb"` ne text nahi, **bytes** likhe. `sha256_of` ne loop me **64 KiB ke tukre** parhe (`while chunk := f.read(...)` aakhir ke khaali tukre par rukta hai), isliye wahi function 50 GB ki disk image ko tay memory me hash kar sakta hai. Downloads aur backups ki tasdeeq ke liye ise lein.
- `deque(f, maxlen=3)` 10,000 lines se guzra magar sirf **aakhri teen** rakhin: memory ke liye mehfooz `tail`. `enumerate` ke saath streaming ne file load kiye baghair **chaar ERROR lines** dhoondin.
- `atomic_write` ne **usi folder** me chhupi temp file me likha, `fsync` se disk par lazmi likhwaya, phir `os.replace` ne use ek qadam me jagah par badla. Parhne wala (ya crash) ya to purana config dekhta hai ya naya, kabhi adhi likhi file nahi. **0 temp files** bachin.
- `os.open(..., 0o600)` ne **api.key** permissions **0o600** ke saath banayi: sirf maalik parh ya likh sakta hai. `open()` se bana kar baad me permissions theek karna ek chhoti khirki chhorta hai jis me doosre parh sakte hain.

</Ur>
</Tr>

## Common mistakes

<Compare>
<Bad title="Opening without with, and without an encoding">

```text
f = open("report.csv", "w")         # platform-dependent encoding
f.write(data)
process(f)                          # raises -> file never closed, data maybe not written
f.close()
```

</Bad>
<Good title="with and an explicit encoding">

```text
with open("report.csv", "w", encoding="utf-8", newline="") as f:
    f.write(data)
    process(f)                      # even if this raises, the file is closed
```

</Good>
</Compare>

<Compare>
<Bad title="Reading a huge file into memory">

```text
lines = open("access.log").read().splitlines()      # 20 GB -> out of memory
errors = [l for l in lines if " 500 " in l]
```

</Bad>
<Good title="Stream it">

```text
with open("access.log", encoding="utf-8", errors="replace") as f:
    errors = [l.rstrip("\n") for l in f if " 500 " in l]
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **`"w"` when you meant `"a"`**: the old content is gone instantly.
- **Forgetting `"\n"` with `write()`**: everything ends up on one line.
- **Opening a user-supplied path directly**: `../../etc/passwd` style paths can escape your folder; resolve and check paths (next lesson).
- **Writing secrets with default permissions** (often world-readable 644).
- **Binary data in text mode** (images, zips): you'll get decode errors or corrupted files; use `"rb"`/`"wb"`.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **`"a"` ki jagah `"w"`**: purana mawad foran khatam.
- **`write()` ke saath `"\n"` bhoolna**: sab kuch ek line par aa jata hai.
- **User ka diya path seedha kholna**: `../../etc/passwd` jaise paths aap ke folder se bahar ja sakte hain; paths resolve aur check karein (agla lesson).
- **Secrets default permissions ke saath likhna** (aksar sab ke parhne layak 644).
- **Text mode me binary data** (images, zips): decode errors ya kharab files milengi; `"rb"`/`"wb"` lein.

</Ur>
</Tr>

<Challenge title="Verify a download">

<Tr>
<En>
Write `verify(path, expected_sha256)` that hashes the file in 1 MiB chunks and returns True only if it matches (compare case-insensitively). Test it on a file you create with `"wb"` containing `b"hello\n"`, whose SHA-256 begins with `5891b5b5`, and on a missing file (return False and print a message instead of crashing).
</En>
<Ur>
`verify(path, expected_sha256)` likhein jo file ko 1 MiB ke tukron me hash kare aur sirf mel hone par True lautaye (chhote bare haroof ka farq nazar andaz). Ise `"wb"` se bani `b"hello\n"` wali file par test karein, jis ka SHA-256 `5891b5b5` se shuru hota hai, aur ghayab file par (crash ke bajaye False lautayen aur paigham print karein).
</Ur>
</Tr>

<Solution>

<Tr>
<En>

```text
import hashlib

def verify(path, expected_sha256):
    h = hashlib.sha256()
    try:
        with open(path, "rb") as f:
            while chunk := f.read(1024 * 1024):
                h.update(chunk)
    except FileNotFoundError:
        print(f"{path}: not found")
        return False
    return h.hexdigest() == expected_sha256.lower()

with open("hello.bin", "wb") as f:
    f.write(b"hello\n")
digest = hashlib.sha256(b"hello\n").hexdigest()
print(digest[:8], verify("hello.bin", digest.upper()), verify("hello.bin", "0" * 64), verify("nope.bin", digest))

# nope.bin: not found
# 5891b5b5 True False False
```

For comparing secrets such as tokens, use `hmac.compare_digest` instead of `==`; for public checksums like this, `==` is fine.

<DeepDive title="More about files">

**Buffering.** Writes go to a buffer first; `f.flush()` pushes them to the OS and `os.fsync()` asks the OS to write to disk. Closing the file flushes automatically.

**Newlines.** In text mode Python translates line endings; pass `newline=""` when writing CSV with the csv module so it controls `\r\n` itself.

**Seeking.** `f.seek(offset)` and `f.tell()` move and report the position; binary formats and "resume from where we stopped" readers use them.

**Temporary files.** `tempfile.TemporaryDirectory()` and `NamedTemporaryFile()` create secure, automatically cleaned temp locations with unpredictable names.

**Memory-mapped files.** `mmap` lets you treat a large file like a bytes object for fast random access.

</DeepDive>

<DeepDive title="Real world: the half-written config">

A service reloaded `config.json` every minute. A deploy script rewrote the file with `open("config.json", "w")` and `json.dump`. Occasionally the service reloaded in the middle of that write, read truncated JSON, crashed, and restarted in a loop until someone noticed.

The fixes:

1. Write to a temp file in the same directory, `fsync`, then `os.replace`, so readers only ever see a complete file.
2. The service validates a new config before swapping it in and keeps the old one on errors.
3. Both sides log the config version they wrote and loaded.

</DeepDive>

<DeepDive title="Security lens">

- **Path traversal**: never join user input to a base directory without resolving and checking the result stays inside (`pathlib` lesson).
- **Restrictive permissions for secrets**: create keys and tokens with `0o600` from the start; check umask in services.
- **Unpredictable temp names**: use `tempfile`, never fixed names like `/tmp/report.tmp` that attackers can pre-create or symlink.
- **Hash and verify downloads** before using them; compare secrets with `hmac.compare_digest`.
- **Don't trust file contents**: limit sizes, handle decode errors, and never `eval` or `pickle.load` data from untrusted files.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What is the difference between modes w, a and x?">
w opens for writing and truncates an existing file; a opens for writing at the end without truncating; x creates a new file and raises FileExistsError if it already exists.
</QA>

<QA q="Why use a with statement for files?">
It guarantees the file is closed, and buffered data flushed, when the block ends, even if an exception occurs, avoiding leaked file handles and lost data.
</QA>

<QA q="How do you process a file too large for memory?">
Iterate over the file object line by line for text, or read fixed-size chunks in binary mode, keeping only what you need, such as counts or a deque of recent lines.
</QA>

<QA q="What is the difference between text and binary mode?">
Text mode decodes bytes to str using an encoding and translates newlines; binary mode returns raw bytes unchanged, needed for images, archives, hashes and network data.
</QA>

<QA q="How do you write a file safely so readers never see partial content?">
Write to a temporary file in the same directory, flush and fsync it, then atomically rename it over the target with os.replace.
</QA>

</DeepDive>
