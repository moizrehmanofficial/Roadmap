<BigIdea>
<Tr>
<En>
Programs exchange data as **text formats**. **JSON** is the language of web APIs: objects, arrays, strings, numbers, `true`/`false` and `null`. Python's `json` module converts both ways: **`json.dumps(obj)`** turns Python into a JSON string and **`json.loads(text)`** turns it back (`dump` and `load`, without the s, work directly with files). The mapping isn't perfect: tuples come back as lists, dict keys always become strings, and types like `datetime` and `Decimal` can't be serialized until you give a **`default=`** function. **CSV** is rows of comma-separated values, the format every spreadsheet exports. Use the `csv` module (**`DictWriter`**, **`DictReader`**) instead of splitting on commas yourself, because real fields contain commas, quotes and newlines; every value you read back is a **string**, so convert types yourself. **YAML** is the indentation-based format of configuration files; read it with **`yaml.safe_load`** (from the PyYAML package). Each format has traps: invalid JSON raises `JSONDecodeError`, CSV cells starting with `=` can run as formulas in Excel, YAML silently turns unquoted `NO` into `False` and `1.10` into `1.1`, and loading untrusted YAML with an unsafe loader can run code.
</En>
<Ur>
Programs data **text formats** me badalte hain. **JSON** web APIs ki zaban hai: objects, arrays, strings, numbers, `true`/`false` aur `null`. Python ka `json` module dono taraf badalta hai: **`json.dumps(obj)`** Python ko JSON string banata aur **`json.loads(text)`** wapas laata hai (s ke baghair `dump` aur `load` seedha files ke saath kaam karte hain). Khud commas par todne ke bajaye `csv` module (**`DictWriter`**, **`DictReader`**) lein, kyunke asal fields me commas, quotes aur newlines hote hain; wapas parhi har value **string** hoti hai, isliye types khud badlein. **YAML** configuration files ka indentation par mabni format hai; ise **`yaml.safe_load`** (PyYAML package se) se parhein. Har format ke jaal hain: ghalat JSON `JSONDecodeError` deta, `=` se shuru hone wale CSV cells Excel me formulas ban kar chal sakte, YAML khamoshi se be-quote `NO` ko `False` aur `1.10` ko `1.1` bana deta, aur na-qabil-e-bharosa YAML unsafe loader se load karna code chala sakta hai.
</Ur>

## Picture it

<Tr>
<En>

Think of **three ways to write down an order**.

- **JSON** is a labelled form in a strict official format: every label in double quotes, no notes in the margin, and the clerk rejects it for a single extra comma.
- **CSV** is a ledger page: one row per order, columns separated by commas. It's simple, but if a customer's address contains a comma, you must put it in quotes or the columns shift.
- **YAML** is a neatly indented handwritten note with comments. It's pleasant to read, but the reader guesses types from how things look, so "NO" (Norway) might be read as "no".

</En>
<Ur>

**Order likhne ke teen tareeqe** socheyn.

- **JSON** sakht sarkari format wala label laga form hai: har label double quotes me, haashiye me koi note nahi, aur clerk ek zayed comma par bhi radd kar deta hai.
- **CSV** khata ka safha hai: har order ki ek row, columns commas se alag. Saada hai, magar agar customer ke pate me comma ho to use quotes me rakhna parta hai warna columns khisak jate hain.
- **YAML** saaf indentation wala haath se likha note hai jis me comments hain. Parhne me khushgawar, magar parhne wala cheezon ki shakal se types ka andaza lagata hai, isliye "NO" (Norway) "no" parha ja sakta hai.

</Ur>
</Tr>

## Learn it step by step

<Walkthrough>

<Step title="JSON: dumps, loads, files, special types and invalid input">

<Tr>
<En>
`data_json.py` converts an order dict to JSON and back, writes it to a file with `indent` and `sort_keys`, tries to serialize a `datetime`, fixes that with a `default=` function that also keeps `Decimal` money exact, shows that keys become strings, and parses four inputs, three of them invalid.
</En>
<Ur>
`data_json.py` order dict ko JSON me aur wapas badalti, use `indent` aur `sort_keys` ke saath file me likhti, `datetime` serialize karne ki koshish karti, ise aise `default=` function se theek karti jo `Decimal` paisa bhi bilkul durust rakhta hai, dikhati hai ke keys strings ban jati hain, aur chaar inputs parse karti hai, jin me se teen ghalat hain.
</Ur>
</Tr>

```bash
cat > data_json.py <<'EOF'
import json
from datetime import datetime, timezone
from decimal import Decimal

order = {"id": 1042, "customer": "Jane Cooper", "paid": True, "coupon": None,
         "items": [{"sku": "KB-01", "qty": 2, "price": 49.5}], "tags": ("new", "web")}

text = json.dumps(order)                       # Python -> JSON string
print(text)
back = json.loads(text)                        # JSON string -> Python
print(type(back["items"]), back["tags"], back["paid"], back["coupon"])   # tuple came back as a list

with open("order.json", "w", encoding="utf-8") as f:
    json.dump(order, f, indent=2, sort_keys=True, ensure_ascii=False)
with open("order.json", encoding="utf-8") as f:
    print(json.load(f)["items"][0]["sku"], "| lines in file:", sum(1 for _ in open("order.json", encoding="utf-8")))

# Types JSON doesn't know
try:
    json.dumps({"at": datetime(2026, 11, 23, 9, 30, tzinfo=timezone.utc)})
except TypeError as e:
    print("TypeError:", e)

def to_json(obj):
    if isinstance(obj, datetime):
        return obj.isoformat()
    if isinstance(obj, Decimal):
        return str(obj)                         # keep money exact
    raise TypeError(f"cannot serialize {type(obj).__name__}")

print(json.dumps({"at": datetime(2026, 11, 23, 9, 30, tzinfo=timezone.utc), "total": Decimal("99.10")}, default=to_json))
print(json.dumps({1: "a"}), json.loads('{"1": "a"}'))           # keys always become strings

# Bad input
for raw in ['{"ok": true}', "{'ok': True}", '{"ok": true,}', ""]:
    try:
        print("parsed:", json.loads(raw))
    except json.JSONDecodeError as e:
        print(f"invalid JSON {raw!r}: {e.msg} (line {e.lineno}, col {e.colno})")
EOF
python3 data_json.py
```

<Happened>
<Tr>
<En>

- `dumps` produced a JSON string: `True` became `true`, `None` became `null`, and the tuple became an array. `loads` brought it back with the **tuple turned into a list**: JSON has no tuples.
- `dump` with `indent=2` and `sort_keys=True` wrote a readable, stable file (**17 lines**); stable ordering makes diffs and caching easier. `ensure_ascii=False` keeps characters like é readable instead of `é`.
- `datetime` raised **TypeError**. Our `default=` function converted it to an ISO 8601 string and the `Decimal` to the string **"99.10"**; a float would risk rounding errors for money.
- The integer key `1` came back as the string **"1"**: JSON object keys are always strings.
- Python-style dicts with single quotes, **trailing commas** and empty input are all invalid JSON. `JSONDecodeError` reports the message, line and column; catch it and return a clear 400-style error instead of crashing.

</En>
<Ur>

- `dumps` ne JSON string banayi: `True` `true`, `None` `null`, aur tuple array ban gaya. `loads` ne wapas laya magar **tuple list ban gaya**: JSON me tuples nahi hote.
- `indent=2` aur `sort_keys=True` ke saath `dump` ne parhne layak, mustaqil file (**17 lines**) likhi; mustaqil tarteeb diffs aur caching aasan banati hai. `ensure_ascii=False` é jaise characters ko `é` ke bajaye parhne layak rakhta hai.
- `datetime` ne **TypeError** diya. Hamare `default=` function ne ise ISO 8601 string aur `Decimal` ko string **"99.10"** me badla; paise ke liye float rounding ki ghaltiyon ka khatra hai.
- Integer key `1` string **"1"** ban kar wapas aayi: JSON object keys hamesha strings hoti hain.
- Single quotes wali Python jaisi dicts, **aakhri zayed commas** aur khaali input sab ghalat JSON hain. `JSONDecodeError` paigham, line aur column batata hai; crash ke bajaye ise pakar kar 400 jaisa wazeh error lautayen.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="CSV with the csv module, formula injection, and YAML safely">

<Tr>
<En>
`data_csv_yaml.py` writes customers to CSV with `DictWriter` (one city contains a comma, one name contains quotes), reads them back with `DictReader`, compares a naive comma split with the csv module, escapes cells that a spreadsheet would treat as formulas, then loads a YAML config with `safe_load`, writes YAML with `safe_dump`, and feeds `safe_load` a malicious document.
</En>
<Ur>
`data_csv_yaml.py` `DictWriter` se customers CSV me likhti (ek shehar me comma, ek naam me quotes hain), `DictReader` se wapas parhti, comma par seedhe todne ka csv module se muqabla karti, woh cells escape karti jinhe spreadsheet formulas samjhe, phir `safe_load` se YAML config load karti, `safe_dump` se YAML likhti, aur `safe_load` ko nuqsan deh document deti hai.
</Ur>
</Tr>

```bash
cat > data_csv_yaml.py <<'EOF'
import csv, io
import yaml          # pip install pyyaml

rows = [
    {"name": "Jane Cooper", "email": "jane@example.com", "city": "Austin, TX", "spent": 120.5},
    {"name": 'Robert "Bob" Fox', "email": "bob@example.com", "city": "Denver", "spent": 80},
]
with open("customers.csv", "w", encoding="utf-8", newline="") as f:     # newline="" for csv
    w = csv.DictWriter(f, fieldnames=["name", "email", "city", "spent"])
    w.writeheader()
    w.writerows(rows)
print(open("customers.csv", encoding="utf-8").read(), end="")

with open("customers.csv", encoding="utf-8", newline="") as f:
    for r in csv.DictReader(f):
        print(r["name"], "|", r["city"], "|", repr(r["spent"]), "->", float(r["spent"]) * 2)

# Splitting on commas yourself breaks on quoted fields
line = open("customers.csv", encoding="utf-8").readlines()[1]
print("naive split:", len(line.strip().split(",")), "fields; csv module:", len(next(csv.reader([line]))))

# Spreadsheet formula injection: cells starting with = + - @ run as formulas in Excel
def safe_cell(v):
    s = str(v)
    return "'" + s if s[:1] in ("=", "+", "-", "@") else s
buf = io.StringIO()
csv.writer(buf).writerow([safe_cell(v) for v in ["=HYPERLINK(\"http://evil.example\")", "-5", "ok"]])
print("escaped:", buf.getvalue().strip())

# YAML: human-friendly config
config_text = """
app: billing
debug: false
port: 8080
workers: 4
db:
  host: db.internal
  pool: 10
allowed_hosts:
  - example.com
  - api.example.com
country: NO          # careful: YAML 1.1 reads unquoted NO as false!
version: 1.10        # and this becomes a float
"""
cfg = yaml.safe_load(config_text)
print(cfg["db"]["host"], cfg["port"] + 1, cfg["allowed_hosts"], "| country:", cfg["country"], "| version:", cfg["version"])
print(yaml.safe_dump({"app": "billing", "ports": [80, 443], "country": "NO"}, sort_keys=False), end="")

# Never yaml.load untrusted input with an unsafe loader
evil = "!!python/object/apply:os.system ['echo HACKED']"
try:
    yaml.safe_load(evil)
except yaml.YAMLError as e:
    print("safe_load refused:", type(e).__name__)
EOF
python3 data_csv_yaml.py
```

```text output
name,email,city,spent
Jane Cooper,jane@example.com,"Austin, TX",120.5
"Robert ""Bob"" Fox",bob@example.com,Denver,80
Jane Cooper | Austin, TX | '120.5' -> 241.0
Robert "Bob" Fox | Denver | '80' -> 160.0
naive split: 5 fields; csv module: 4
escaped: "'=HYPERLINK(""http://evil.example"")",'-5,ok
db.internal 8081 ['example.com', 'api.example.com'] | country: False | version: 1.1
app: billing
ports:
- 80
- 443
country: 'NO'
safe_load refused: ConstructorError
```

<Happened>
<Tr>
<En>

- `DictWriter` **quoted** `"Austin, TX"` and doubled the inner quotes in `"Robert ""Bob"" Fox"`, exactly what Excel expects. Opening the file with `newline=""` lets the csv module control line endings (otherwise you get blank lines on Windows).
- `DictReader` returned each row as a dict, and every value as a **string**: `'120.5'`, `'80'`. Convert with `float`, `int` or `Decimal` before doing maths.
- Splitting the quoted line on commas gave **5 fields instead of 4**: never parse CSV by hand.
- A cell like `=HYPERLINK(...)` would run as a formula when an admin opens the export in a spreadsheet (CSV or formula injection). Prefixing `= + - @` with `'` makes it plain text. Here `-5` was escaped too, a trade-off: you may skip numbers you produced yourself, but escape user-supplied text.
- `safe_load` turned the YAML into dicts, lists, ints and bools. But **`country: NO` became `False`** and **`version: 1.10` became `1.1`**: quote strings in YAML ("NO", "1.10"). `safe_dump` quoted `'NO'` for us when writing.
- The `!!python/object/apply` tag asks YAML to call `os.system`. `safe_load` **refused** with a `ConstructorError`. `yaml.load` with an unsafe loader would have run the command.

</En>
<Ur>

- `DictWriter` ne `"Austin, TX"` ko **quote** kiya aur `"Robert ""Bob"" Fox"` me andar ke quotes dohre kiye, bilkul jo Excel chahta hai. File `newline=""` ke saath kholna csv module ko line endings sambhalne deta hai (warna Windows par khaali lines aati hain).
- `DictReader` ne har row dict ki shakal me lautayi, aur har value **string**: `'120.5'`, `'80'`. Hisaab se pehle `float`, `int` ya `Decimal` se badlein.
- Quote wali line ko commas par todne se **4 ke bajaye 5 fields** mile: CSV kabhi haath se parse na karein.
- `=HYPERLINK(...)` jaisa cell tab formula ban kar chalega jab admin export spreadsheet me kholega (CSV ya formula injection). `= + - @` se pehle `'` lagana ise saada text banata hai. Yahan `-5` bhi escape hua, ek samjhauta: apne banaye numbers chhor sakte hain, magar user ka diya text escape karein.
- `safe_load` ne YAML ko dicts, lists, ints aur bools me badla. Magar **`country: NO` `False` ban gaya** aur **`version: 1.10` `1.1` ban gaya**: YAML me strings quote karein ("NO", "1.10"). Likhte waqt `safe_dump` ne hamare liye `'NO'` quote kiya.
- `!!python/object/apply` tag YAML se `os.system` bulwane ko kehta hai. `safe_load` ne `ConstructorError` ke saath **inkar** kiya. Unsafe loader ke saath `yaml.load` command chala deta.

</Ur>
</Tr>
</Happened>

## Common mistakes

<Compare>
<Bad title="Parsing CSV by hand and keeping strings">

```text
for line in open("orders.csv"):
    name, city, total = line.strip().split(",")     # breaks on "Austin, TX"
    grand += total                                  # TypeError: str
```

</Bad>
<Good title="csv module and explicit conversion">

```text
with open("orders.csv", encoding="utf-8", newline="") as f:
    for row in csv.DictReader(f):
        grand += Decimal(row["total"])
```

</Good>
</Compare>

<Compare>
<Bad title="Unsafe YAML and unquoted values">

```text
cfg = yaml.load(request_body, Loader=yaml.UnsafeLoader)   # remote code execution
# country: NO       -> False
# version: 1.10     -> 1.1
```

</Bad>
<Good title="safe_load and quoted strings">

```text
cfg = yaml.safe_load(request_body)
# country: "NO"
# version: "1.10"
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Floats for money in JSON**: `0.1 + 0.2` problems; send strings or integer cents.
- **`str(dict)` instead of `json.dumps`**: produces single quotes, which isn't JSON.
- **Assuming a JSON key exists**: use `.get()` and validate the shape (pydantic or JSON Schema for bigger apps).
- **`json.load` on huge files**: it loads everything into memory; use JSON Lines and stream line by line.
- **Exporting user data to CSV without escaping formulas.**

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **JSON me paise ke liye floats**: `0.1 + 0.2` ke masail; strings ya integer cents bhejein.
- **`json.dumps` ke bajaye `str(dict)`**: single quotes banata hai, jo JSON nahi.
- **JSON key ka mojood hona farz karna**: `.get()` lein aur shakal validate karein (bari apps ke liye pydantic ya JSON Schema).
- **Bohat bari files par `json.load`**: sab memory me load karta hai; JSON Lines lein aur line ba line stream karein.
- **Formulas escape kiye baghair user data CSV me export karna.**

</Ur>

Create `sales.csv` with columns `region,amount` and rows `West,120.50`, `East,80.25`, `West,40.00`, `North,15.75`. Read it with `DictReader`, total the amounts per region using `Decimal`, and write `report.json` with regions sorted by name and totals as strings, pretty-printed with `indent=2`. Print the JSON.

<Tr>
<En>

```text
import csv, json
from collections import defaultdict
from decimal import Decimal

with open("sales.csv", "w", encoding="utf-8", newline="") as f:
    f.write("region,amount\nWest,120.50\nEast,80.25\nWest,40.00\nNorth,15.75\n")

totals = defaultdict(Decimal)
with open("sales.csv", encoding="utf-8", newline="") as f:
    for row in csv.DictReader(f):
        totals[row["region"]] += Decimal(row["amount"])

report = {region: str(totals[region]) for region in sorted(totals)}
with open("report.json", "w", encoding="utf-8") as f:
    json.dump(report, f, indent=2)
print(open("report.json", encoding="utf-8").read())

#   "East": "80.25",
#   "North": "15.75",
#   "West": "160.50"
# }
```

<Challenge title="Config with defaults and validation">

<Tr>
<En>
Write `load_config(text)` that parses YAML with `safe_load`, merges it over the defaults `port: 8000`, `debug: false`, `workers: 2`, and raises `ValueError` if `port` isn't an integer between 1 and 65535 or if the YAML isn't a mapping. Test it with `"port: 9000\ndebug: true"`, `"port: 70000"`, and `"- just\n- a list"`.
</En>
<Ur>
`load_config(text)` likhein jo `safe_load` se YAML parse kare, use defaults `port: 8000`, `debug: false`, `workers: 2` par milaye, aur `ValueError` uthaye agar `port` 1 se 65535 ke beech integer na ho ya YAML mapping na ho. Ise `"port: 9000\ndebug: true"`, `"port: 70000"` aur `"- just\n- a list"` se test karein.
</Ur>
</Tr>

<Solution>

<Tr>
<En>

```text
import yaml

DEFAULTS = {"port": 8000, "debug": False, "workers": 2}

def load_config(text):
    data = yaml.safe_load(text) or {}
    if not isinstance(data, dict):
        raise ValueError("config must be a mapping")
    cfg = {**DEFAULTS, **data}
    port = cfg["port"]
    if not isinstance(port, int) or isinstance(port, bool) or not 1 <= port <= 65535:
        raise ValueError(f"invalid port: {port!r}")
    return cfg

for text in ["port: 9000\ndebug: true", "port: 70000", "- just\n- a list"]:
    try:
        print(load_config(text))
    except ValueError as e:
        print("error:", e)

# {'port': 9000, 'debug': True, 'workers': 2}
# error: invalid port: 70000
# error: config must be a mapping
```

The `isinstance(port, bool)` check matters because `True` is also an `int` in Python.

<DeepDive title="More about data formats">

**JSON Lines.** One JSON object per line (`.jsonl`); append-friendly and streamable, common for logs and ML datasets.

**TOML.** `tomllib` (built in since 3.11) reads TOML, the format of `pyproject.toml`; it has explicit types and avoids YAML's guessing.

**Validation.** `pydantic` models or JSON Schema check that parsed data has the right shape and types before you use it.

**Faster JSON.** `orjson` is much faster and natively serializes datetimes and dataclasses.

**CSV dialects.** `csv.Sniffer` can guess delimiters; Excel in some regions uses semicolons. Pass `delimiter=";"` when needed.

</DeepDive>

<DeepDive title="Real world: the CSV export that phished an admin">

A support portal let users set a display name. An attacker set it to a formula that built a link to their own site. When an admin exported users to CSV and opened it in a spreadsheet, the cell rendered as a clickable link labelled "Click to verify", and an older spreadsheet setup even prompted to run external content.

The fixes:

1. Escape cells starting with `=`, `+`, `-`, `@`, tab or carriage return in every export.
2. Validate display names on input.
3. Train staff not to enable external content in exported files.

</DeepDive>

<DeepDive title="Security lens">

- **Unsafe deserialization**: `yaml.load` with unsafe loaders and `pickle.load` can execute code; only use `safe_load` and plain JSON for untrusted data.
- **CSV injection**: escape formula characters in exports.
- **Resource limits**: cap request body sizes before parsing JSON; deeply nested input can exhaust memory or recursion.
- **Validate shape and types** after parsing; parsed JSON is still untrusted input.
- **Secrets in config files**: keep them out of YAML committed to Git; use environment variables or a secret manager.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="How do you serialize a datetime to JSON?">
Pass a default function to json.dumps that converts datetime objects to ISO 8601 strings with isoformat, or convert them before serializing; parse them back explicitly when loading.
</QA>

<QA q="Why not split CSV lines on commas?">
Fields can contain commas, quotes and newlines inside quoted values; the csv module implements the quoting rules correctly.
</QA>

<QA q="What is the difference between yaml.load and yaml.safe_load?">
safe_load only constructs basic types such as dicts, lists, strings and numbers, while loading with an unsafe loader can construct arbitrary Python objects and execute code from tags in the document.
</QA>

<QA q="What is CSV injection and how do you prevent it?">
Cells beginning with characters like =, +, - or @ are interpreted as formulas by spreadsheet software; prefix such values with a single quote or otherwise escape them when exporting.
</QA>

<QA q="What is lost when converting Python data to JSON?">
Tuples become lists, non-string keys become strings, sets and datetimes are unsupported without conversion, and Decimal precision is lost if converted to float.
</QA>

</DeepDive>
