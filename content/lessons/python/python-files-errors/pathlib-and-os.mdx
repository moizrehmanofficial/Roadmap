<BigIdea>
<Tr>
<En>
A **path** is the address of a file or folder. Treating paths as plain strings causes bugs: missing or doubled slashes, Windows versus Linux separators, splitting on dots that appear in folder names. **`pathlib.Path`** gives you a path **object** instead. You join parts with the **`/` operator** (`Path("logs") / "2026" / "app.log"`), read pieces with attributes (`.name`, `.stem`, `.suffix`, `.parent`), and ask the filesystem questions with methods (`.exists()`, `.is_file()`, `.stat()`). Paths also do the common work: `.mkdir(parents=True, exist_ok=True)` creates folders, `.read_text()` and `.write_text()` read and write small files, `.iterdir()` lists a folder, `.glob("*.log")` and `.rglob("*.py")` search, `.rename()` and `.unlink()` move and delete, and `.resolve()` turns a path into a clean absolute one with `..` collapsed. The **`os`** module covers the operating system around it (environment variables, current directory, `os.walk`, permissions), and **`shutil`** handles higher-level operations: copying files and whole folders, moving, making archives and deleting trees. Because paths often come from users, a key safety habit is to **resolve** any user-supplied path and check it stays **inside** the folder you allow, which blocks path traversal attacks like `../../etc/passwd`.
</En>
<Ur>
**Path** file ya folder ka pata hai. Paths ko saadi strings samajhna bugs banata hai: ghayab ya dohre slashes, Windows aur Linux ke separators, folder naamon me aane wale dots par todna. **`pathlib.Path`** is ke bajaye path **object** deta hai. Aap hisse **`/` operator** se jorte (`Path("logs") / "2026" / "app.log"`), tukre attributes se parhte (`.name`, `.stem`, `.suffix`, `.parent`), aur methods se filesystem se sawal karte hain (`.exists()`, `.is_file()`, `.stat()`). Kyunke paths aksar users se aate hain, ek ahem hifazati aadat hai ke user ka diya path **resolve** kar ke check karein ke woh ijazat wale folder ke **andar** rahe, jo `../../etc/passwd` jaise path traversal hamle rokta hai.
</Ur>

## Picture it

<Tr>
<En>

Think of **postal addresses**.

- A path is an address: country, city, street, house. `/` adds the next line of the address.
- `.parent` is "the street this house is on", `.name` is the house name, `.suffix` is the kind of building (".log" or ".py").
- `glob` is asking the post office "every house on this street whose name ends in .log", and `rglob` asks the same for the whole city.
- `resolve()` turns "go to the house, then back up two streets, then..." into the one real final address, which is how you notice that a delivery request for `../../etc/passwd` actually points outside the neighbourhood you agreed to deliver to.

</En>
<Ur>

**Daak ke pate** socheyn.

- Path pata hai: mulk, shehar, gali, ghar. `/` pate ki agli line jorta hai.
- `.parent` "ye ghar kis gali me hai", `.name` ghar ka naam, `.suffix` imarat ki qism (".log" ya ".py") hai.
- `glob` daak khane se poochna hai "is gali ke har ghar jis ka naam .log par khatam ho", aur `rglob` poore shehar ke liye wahi poochta hai.
- `resolve()` "ghar jao, phir do galiyan peeche, phir..." ko ek asal aakhri pate me badalta hai, isi tarah aap dekhte hain ke `../../etc/passwd` ki delivery darkhwast asal me us mohalle se bahar ishara karti hai jahan delivery ka wada kiya tha.

</Ur>
</Tr>

## Learn it step by step

<Walkthrough>

<Step title="Path objects: parts, folders, reading, searching and metadata">

<Tr>
<En>
`paths.py` takes a path apart, changes its suffix and name, builds a small project tree with `mkdir` and `write_text`, reads a file back, lists a folder, searches with `glob` and `rglob`, prints each log's size from `stat()`, renames and deletes a file, and resolves a path containing `.` and `..`.
</En>
<Ur>
`paths.py` path ko hisson me kholti, us ka suffix aur naam badalti, `mkdir` aur `write_text` se chhota project darakht banati, file wapas parhti, folder ki list banati, `glob` aur `rglob` se dhoondti, `stat()` se har log ka size print karti, file ka naam badal kar delete karti, aur `.` aur `..` wala path resolve karti hai.
</Ur>
</Tr>

```bash
cat > paths.py <<'EOF'
from pathlib import Path

p = Path("logs") / "2026" / "app.log.gz"          # "/" joins path parts, on any OS
print(p, "|", p.name, p.stem, p.suffix, p.suffixes, "|", p.parent, p.parts)
print(p.with_suffix(".txt"), p.with_name("db.log"), Path("~/backups").expanduser().name)

# Build a small project tree
root = Path("project")
(root / "logs").mkdir(parents=True, exist_ok=True)   # like mkdir -p; no error if it exists
(root / "src").mkdir(exist_ok=True)
(root / "src" / "app.py").write_text("print('hi')\n", encoding="utf-8")
(root / "src" / "util.py").write_text("X = 1\n", encoding="utf-8")
for name, size in [("app.log", 1200), ("auth.log", 50_000), ("old.log.1", 300)]:
    (root / "logs" / name).write_text("x" * size, encoding="utf-8")
(root / "README.md").write_text("# demo\n", encoding="utf-8")

print((root / "README.md").read_text(encoding="utf-8").strip(), (root / "src").is_dir(), (root / "nope").exists())
print(sorted(c.name for c in root.iterdir()))                       # direct children
print(sorted(str(f) for f in root.glob("logs/*.log")))              # pattern in one folder
print(sorted(str(f.relative_to(root)) for f in root.rglob("*.py")))  # recursive search

# Metadata
for f in sorted((root / "logs").iterdir()):
    st = f.stat()
    print(f"{f.name:<10} {st.st_size:>6} bytes  file={f.is_file()}")

# Rename, delete
old = root / "logs" / "old.log.1"
moved = old.rename(root / "logs" / "archived.log.1")
moved.unlink()                                                      # delete a file
print(sorted(c.name for c in (root / "logs").iterdir()))
print("resolved:", Path("project/./src/../logs").resolve().name, Path("project").resolve().is_absolute())
EOF
python3 paths.py
```

# demo True False
['README.md', 'logs', 'src']
['project/logs/app.log', 'project/logs/auth.log']
['src/app.py', 'src/util.py']

auth.log    50000 bytes  file=True
old.log.1     300 bytes  file=True

<Happened>
<Tr>
<En>

- `Path("logs") / "2026" / "app.log.gz"` built a path without worrying about separators. `.name` is **app.log.gz**, `.stem` **app.log**, `.suffix` only the last **.gz** (`.suffixes` lists both), `.parent` **logs/2026**. `with_suffix` and `with_name` return new paths; they don't touch the disk.
- `mkdir(parents=True, exist_ok=True)` created `project/logs` in one go and won't fail if run again, which makes scripts safe to re-run.
- `write_text` and `read_text` are one-liners for small files (still pass `encoding`).
- `iterdir()` listed direct children; `glob("logs/*.log")` matched only `.log` files in that folder (**not** `old.log.1`); `rglob("*.py")` searched every subfolder. We wrapped results in `sorted()` because the filesystem doesn't guarantee an order.
- `stat()` gave sizes in bytes; `rename()` returned the new path and `unlink()` deleted it, leaving **app.log** and **auth.log**.
- `resolve()` collapsed `project/./src/../logs` to the real **logs** folder and made it absolute.

</En>
<Ur>

- `Path("logs") / "2026" / "app.log.gz"` ne separators ki fikr ke baghair path banaya. `.name` **app.log.gz**, `.stem` **app.log**, `.suffix` sirf aakhri **.gz** (`.suffixes` dono ki list), `.parent` **logs/2026** hai. `with_suffix` aur `with_name` naye paths lautate hain; disk ko nahi chhoote.
- `mkdir(parents=True, exist_ok=True)` ne ek hi dafa me `project/logs` banaya aur dobara chalane par nakam nahi hota, jo scripts ko dobara chalane layak mehfooz banata hai.
- `write_text` aur `read_text` chhoti files ke liye ek line ke kaam hain (phir bhi `encoding` dein).
- `iterdir()` ne seedhe bachche bataye; `glob("logs/*.log")` ne us folder me sirf `.log` files milayin (`old.log.1` **nahi**); `rglob("*.py")` ne har subfolder dhoonda. Humne natije `sorted()` me lapete kyunke filesystem tarteeb ki zamanat nahi deta.
- `stat()` ne bytes me sizes diye; `rename()` ne naya path lautaya aur `unlink()` ne use delete kiya, **app.log** aur **auth.log** chhor kar.
- `resolve()` ne `project/./src/../logs` ko asal **logs** folder me samet kar absolute banaya.

<Step title="Safe paths, os, finding old and big files, and shutil">

<Tr>
<En>
`safe.py` defines `safe_path(base, user_name)` that resolves a user-supplied name and refuses anything outside the uploads folder, then tests five names, including traversal attempts and an absolute path. It reads the environment and current directory, walks the project with `os.walk`, finds logs bigger than 10 KB and older than 30 days (we backdate one file with `os.utime`), and uses `shutil` to copy a file, copy a folder, make a zip archive and delete a whole tree.
</En>
<Ur>
`safe.py` `safe_path(base, user_name)` define karti jo user ka diya naam resolve kar ke uploads folder ke bahar kuch bhi radd karta hai, phir traversal koshishon aur absolute path samait paanch naam test karti hai. Environment aur mojooda folder parhti, `os.walk` se project chalti, 10 KB se bare aur 30 din se purane logs dhoondti (hum `os.utime` se ek file ki taareekh peeche karte hain), aur `shutil` se file copy, folder copy, zip archive aur poora darakht delete karti hai.
</Ur>
</Tr>

```bash
cat > safe.py <<'EOF'
import os, shutil, time
from pathlib import Path

UPLOADS = Path("uploads").resolve()
UPLOADS.mkdir(exist_ok=True)
(UPLOADS / "report.pdf").write_bytes(b"%PDF-1.7 demo")

# 1. Path traversal: never trust a file name from a user
def safe_path(base, user_name):
    target = (base / user_name).resolve()                # collapse .. and follow symlinks
    if not target.is_relative_to(base):
        raise PermissionError(f"blocked: {user_name!r} escapes {base.name}/")
    return target

for name in ["report.pdf", "../paths.py", "../../etc/passwd", "/etc/shadow", "sub/../report.pdf"]:
    try:
        print("ok:", safe_path(UPLOADS, name).relative_to(UPLOADS))
    except PermissionError as e:
        print(e)

# 2. os: environment, current directory, walking a tree
print("HOME set:", "HOME" in os.environ, "| cwd is absolute:", os.path.isabs(os.getcwd()))
for folder, subdirs, files in sorted(os.walk("project")):
    print(folder, sorted(subdirs), sorted(files))

# 3. Find files by size and age (e.g. clean-up candidates)
old_time = time.time() - 40 * 86400
os.utime("project/logs/app.log", (old_time, old_time))     # pretend app.log is 40 days old
cutoff = time.time() - 30 * 86400
big = [f.name for f in Path("project").rglob("*.log") if f.stat().st_size > 10_000]
old = [f.name for f in Path("project").rglob("*.log") if f.stat().st_mtime < cutoff]
print("over 10 KB:", big, "| older than 30 days:", old)

# 4. shutil: copy, move, archive, remove whole trees
shutil.copy2("project/README.md", "README.copy.md")           # copy2 keeps timestamps
shutil.copytree("project/src", "backup/src", dirs_exist_ok=True)
archive = shutil.make_archive("project-backup", "zip", "project")
print(Path(archive).name, sorted(p.name for p in Path("backup/src").iterdir()))
shutil.rmtree("backup")                                       # careful: deletes everything inside
print("backup exists:", Path("backup").exists())
EOF
python3 safe.py
```

```text output
ok: report.pdf
blocked: '../paths.py' escapes uploads/
blocked: '../../etc/passwd' escapes uploads/
blocked: '/etc/shadow' escapes uploads/
ok: report.pdf
HOME set: True | cwd is absolute: True
project ['logs', 'src'] ['README.md']
project/logs [] ['app.log', 'auth.log']
project/src [] ['app.py', 'util.py']
over 10 KB: ['auth.log'] | older than 30 days: ['app.log']
project-backup.zip ['app.py', 'util.py']
backup exists: False
```

<Happened>
<Tr>
<En>

- `safe_path` allowed **report.pdf** and even **sub/../report.pdf** (it resolves back inside), but **blocked** `../paths.py`, `../../etc/passwd` and the absolute `/etc/shadow`. Note that `base / "/etc/shadow"` becomes `/etc/shadow`: joining with an absolute path discards the base, another reason to check after resolving. `resolve()` also follows symlinks, so a link pointing outside is caught too.
- `os.environ` behaves like a dict of environment variables (use `.get()` with a default), and `os.getcwd()` is where relative paths start: run a script from another folder and relative paths change. Use `Path(__file__).resolve().parent` to find files next to your script.
- `os.walk` yielded every folder with its subfolders and files, useful when you want per-folder decisions (for example skipping `.git`).
- Size and age checks with `stat()` found **auth.log** over 10 KB and **app.log** older than 30 days: the basis of clean-up and retention scripts.
- `shutil.copy2` copied a file with its timestamps, `copytree` copied a folder, `make_archive` created **project-backup.zip**, and `rmtree` deleted the copy entirely. `rmtree` doesn't use a recycle bin: double-check paths (and consider a dry-run flag) before calling it.

</En>
<Ur>

- `safe_path` ne **report.pdf** aur **sub/../report.pdf** tak ki ijazat di (ye resolve ho kar andar hi aata hai), magar `../paths.py`, `../../etc/passwd` aur absolute `/etc/shadow` ko **roka**. Dhyan dein `base / "/etc/shadow"` `/etc/shadow` ban jata hai: absolute path ke saath jorna base phenk deta hai, resolve ke baad check ki ek aur wajah. `resolve()` symlinks bhi follow karta hai, isliye bahar ishara karne wala link bhi pakra jata hai.
- `os.environ` environment variables ki dict jaisa chalta hai (default ke saath `.get()` lein), aur `os.getcwd()` woh jagah hai jahan se relative paths shuru hote: script doosre folder se chalayen to relative paths badal jate hain. Script ke saath ki files dhoondne ke liye `Path(__file__).resolve().parent` lein.
- `os.walk` ne har folder us ke subfolders aur files ke saath diya, kaam ka jab har folder par faisla chahiye (maslan `.git` chhorna).
- `stat()` se size aur umar ke checks ne 10 KB se bari **auth.log** aur 30 din se purani **app.log** dhoondi: safai aur retention scripts ki bunyad.
- `shutil.copy2` ne timestamps ke saath file copy ki, `copytree` ne folder copy kiya, `make_archive` ne **project-backup.zip** banayi, aur `rmtree` ne copy poori delete kar di. `rmtree` recycle bin istemal nahi karta: bulane se pehle paths dobara check karein (aur dry-run flag par ghaur karein).

</Ur>
</Tr>

## Common mistakes

<Compare>
<Bad title="Paths as strings">

```text

if not os.path.exists(out_dir): os.mkdir(out_dir)   # fails if the parent is missing

path = Path(base) / folder / name

```

<Bad title="Trusting a file name from a request">

```text
@app.get("/download")
def download(name):
    return open(f"/srv/files/{name}", "rb").read()   # name="../../etc/passwd"
```

</Bad>
<Good title="Resolve and confirm it stays inside">

```text
BASE = Path("/srv/files").resolve()
def download(name):
    target = (BASE / name).resolve()
    if not target.is_relative_to(BASE) or not target.is_file():
        raise PermissionError("not allowed")
    return target.read_bytes()
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Relying on the current directory**: a script that works from its own folder fails from cron; build paths from `Path(__file__).resolve().parent`.
- **Checking `exists()` then acting**: another process can change things in between; prefer `exist_ok=True`, `"x"` mode or catching errors.
- **`shutil.rmtree` on a computed path without checks**: an empty variable can turn `rmtree(base / sub)` into deleting `base`.
- **Assuming `iterdir()`/`glob()` order**: sort when order matters.
- **`str.startswith` to check "inside a folder"**: `/srv/files-old` starts with `/srv/files`; use `is_relative_to` on resolved paths.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **Mojooda folder par bharosa**: apne folder se chalne wali script cron se nakam hoti hai; paths `Path(__file__).resolve().parent` se banayen.
- **`exists()` check kar ke phir kaam**: beech me doosra process cheezen badal sakta hai; `exist_ok=True`, `"x"` mode ya errors pakarne ko tarjeeh dein.
- **Checks ke baghair hisaab kiye path par `shutil.rmtree`**: khaali variable `rmtree(base / sub)` ko `base` delete karne me badal sakta hai.
- **`iterdir()`/`glob()` ki tarteeb farz karna**: jab tarteeb maayne rakhe to sort karein.
- **"Folder ke andar" check ke liye `str.startswith`**: `/srv/files-old` `/srv/files` se shuru hota hai; resolved paths par `is_relative_to` lein.

Write `find_suspicious(root)` that walks a folder with `rglob` and returns sorted relative paths of files named `.env`, ending in `.pem` or `.key`, or containing `id_rsa` in the name, while skipping anything inside a `.git` folder. Test it on a small tree you create.

<Tr>

from pathlib import Path

def find_suspicious(root):
    root = Path(root)
    hits = []
    for p in root.rglob("*"):
        rel = p.relative_to(root)
        if ".git" in rel.parts or not p.is_file():
            continue
        if p.name == ".env" or p.suffix in (".pem", ".key") or "id_rsa" in p.name:
            hits.append(str(rel))
    return sorted(hits)

for f in ["repo/.env", "repo/app.py", "repo/certs/server.pem", "repo/.git/config",
          "repo/.git/hooks/x.key", "repo/home/id_rsa.pub", "repo/notes.txt"]:
    Path(f).parent.mkdir(parents=True, exist_ok=True)
    Path(f).write_text("demo", encoding="utf-8")
print(find_suspicious("repo"))

# ['.env', 'certs/server.pem', 'home/id_rsa.pub']

<DeepDive title="More about paths">

**Pure paths.** `PurePosixPath` and `PureWindowsPath` manipulate paths for another OS without touching the filesystem, handy for building remote paths.

**Path.walk.** Python 3.12 added `Path.walk()`, a pathlib version of `os.walk`; modify the `dirs` list in place to skip folders.

**Permissions and ownership.** `Path.chmod(0o600)`, `os.chown`, and `stat.filemode(st.st_mode)` (gives `-rw-------`) help with audits.

**Temporary and user folders.** `tempfile.gettempdir()`, `Path.home()`, and `platformdirs` for proper per-OS config and cache locations.

**Watching for changes.** Libraries like `watchdog` react to new or modified files instead of polling with `stat`.

</DeepDive>

<DeepDive title="Real world: the clean-up script that deleted home">

A clean-up script ran `shutil.rmtree(Path(os.environ.get("BUILD_DIR", "")) / "tmp")` on build servers. On one machine the variable wasn't set, so the path became `tmp` relative to the current directory, which for that cron job was the user's home, and a different `tmp` folder with important data was deleted.

The fixes:

1. Fail fast if required environment variables are missing.
2. Resolve the target and assert it's inside an expected root (`/srv/builds`) before any `rmtree`.
3. A `--dry-run` default that prints what would be deleted.
4. Cron jobs set an explicit working directory.

</DeepDive>

<DeepDive title="Security lens">

- **Path traversal** (CWE-22) is common in upload, download and archive-extraction code: resolve and verify every user-influenced path.
- **Archive extraction**: zip and tar entries can contain `../` or absolute paths; validate each member's target (or use `tarfile`'s `filter="data"`).
- **Symlink attacks**: an attacker-controlled symlink can redirect writes; resolving before checking (and not following links where possible) helps.
- **Secret files in the wrong place**: scan for `.env`, keys and dumps before publishing folders or images.
- **Deletion safety**: never run `rmtree` on paths built from unchecked input or empty variables.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="Why use pathlib instead of string paths?">
Path objects handle separators across operating systems, offer clear attributes for name, suffix and parent, and include methods for common filesystem operations, avoiding bugs from manual string concatenation and splitting.
</QA>

<QA q="What is the difference between glob and rglob?">
glob matches a pattern in the given folder (or as specified by the pattern), while rglob searches recursively through all subfolders, equivalent to prefixing the pattern with **/.
</QA>

<QA q="How do you prevent path traversal?">
Join the user input to a trusted base, resolve the result to an absolute canonical path, and verify it is still inside the base with is_relative_to before using it; reject otherwise.
</QA>

<QA q="What's the difference between os.remove, Path.rmdir and shutil.rmtree?">
os.remove or Path.unlink deletes a file; Path.rmdir deletes an empty directory; shutil.rmtree deletes a directory and everything inside it.
</QA>

<QA q="Why might a script work in one folder and fail from cron?">
Relative paths are resolved against the current working directory, which differs under cron; build paths from the script's own location or use absolute paths.
</QA>

</DeepDive>
