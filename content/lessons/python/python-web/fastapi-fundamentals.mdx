<BigIdea>
<Tr>
<En>
**FastAPI** turns typed Python functions into an HTTP API. You decorate a function with a route such as `@app.get("/items/{item_id}")`, and its **parameters** describe the request: a parameter named in the path becomes a **path parameter**, other simple parameters become **query parameters** (`?in_stock=true&limit=10`), and a parameter typed as a **Pydantic model** becomes the **JSON body**. FastAPI uses the type hints to **convert and validate** every value: `/items/abc` for an `int` path parameter is rejected with **422 Unprocessable Entity** and a precise error before your code runs. A **`response_model`** filters and documents what you send back, `status_code=201` sets the success code, and **`HTTPException`** returns errors like 404. Because the types are known, FastAPI generates an **OpenAPI** schema and interactive docs at `/docs` for free. Reusable logic such as pagination, database sessions or authentication goes into **dependencies** (`Depends`), which FastAPI runs before your endpoint and which can reject requests. FastAPI is built on ASGI and runs under **Uvicorn**; endpoints can be `async def` (use `await` for I/O, never blocking calls like `time.sleep` or `requests.get`) or plain `def`, which FastAPI runs in a thread pool so blocking code doesn't freeze the server. Tests use **`TestClient`** without starting a server.
</En>
<Ur>
**FastAPI** typed Python functions ko HTTP API me badalta hai. Aap function par `@app.get("/items/{item_id}")` jaisa route lagate hain, aur us ke **parameters** request bayan karte hain: path me naam wala parameter **path parameter** banta, baqi saade parameters **query parameters** (`?in_stock=true&limit=10`) bante, aur **Pydantic model** type wala parameter **JSON body** banta hai. FastAPI type hints se har value **badalta aur validate** karta: `int` path parameter ke liye `/items/abc` aap ka code chalne se pehle bilkul durust error ke saath **422 Unprocessable Entity** se radd hota hai. **`response_model`** jo wapas bhejte us ko chhaanta aur document karta, `status_code=201` kamyabi ka code set karta, aur **`HTTPException`** 404 jaise errors lautata hai. Kyunke types maloom hain, FastAPI muft me **OpenAPI** schema aur `/docs` par interactive docs banata hai. Pagination, database sessions ya authentication jaisi dobara istemal hone wali logic **dependencies** (`Depends`) me jati hai, jinhe FastAPI endpoint se pehle chalata aur jo requests radd kar sakti hain. FastAPI ASGI par bana aur **Uvicorn** ke neeche chalta hai; endpoints `async def` (I/O ke liye `await`, `time.sleep` ya `requests.get` jaisi blocking calls kabhi nahi) ya saade `def` ho sakte hain, jinhe FastAPI thread pool me chalata hai taa ke blocking code server ko jama na kare. Tests server shuru kiye baghair **`TestClient`** istemal karte hain.
</Ur>

## Picture it

<Tr>
<En>

Think of a **post office counter with printed forms**.

- Each endpoint is a counter, and its function signature is the **printed form**: "item ID (a number)", "in stock (yes/no, optional)". The clerk (FastAPI) checks the form before passing it to the back office (your code), and hands back obviously wrong forms with notes (422).
- The response model is the **standard receipt**: it only lists the fields that belong on it.
- Dependencies are the **security guard and ticket machine** at the entrance: they check your ID or assign a queue number before you reach any counter.
- `async def` clerks can serve someone else while waiting for the back office to call back; a clerk who stands frozen by the phone (`time.sleep` in `async def`) holds up the whole line.

</En>
<Ur>

**Chhape forms wala post office counter** socheyn.

- Har endpoint ek counter hai, aur us ka function signature **chhapa form** hai: "item ID (number)", "stock me (haan/nahi, ikhtiyari)". Clerk (FastAPI) form back office (aap ka code) ko dene se pehle check karta, aur saaf ghalat forms notes ke saath wapas karta (422).
- Response model **mayari raseed** hai: is par sirf woh fields hote jo hone chahiye.
- Dependencies darwaze par **security guard aur ticket machine** hain: kisi counter tak pohanchne se pehle aap ki ID check karte ya line ka number dete.
- `async def` clerks back office ke wapas call karne ka intezar karte hue kisi aur ko serve kar sakte; phone ke paas jama khara clerk (`async def` me `time.sleep`) poori line rok deta hai.

</Ur>
</Tr>

<Step title="Routes, parameters, bodies, response models, errors and OpenAPI">

<Tr>
<En>
We install pinned FastAPI, Uvicorn and httpx. `main.py` defines an `Item` model for input and an `ItemOut` model with an `id` for output, and four endpoints: a health check, a list with optional query filters, a single item by ID with a 404, and a create endpoint returning 201. `try_api.py` calls them with `TestClient`, including a missing item, a non-numeric ID, a valid body and an invalid body, and reads the generated OpenAPI schema.
</En>
<Ur>
Hum pinned FastAPI, Uvicorn aur httpx install karte hain. `main.py` input ke liye `Item` model aur output ke liye `id` wala `ItemOut` model, aur chaar endpoints define karti: health check, ikhtiyari query filters wali list, 404 ke saath ID se ek item, aur 201 lautane wala create endpoint. `try_api.py` unhe `TestClient` se bulati, ghayab item, ghair numeric ID, durust body aur ghalat body samait, aur bana OpenAPI schema parhti hai.
</Ur>

```bash
export UV_EXCLUDE_NEWER=2025-06-01T00:00:00Z
uv venv -q --python 3.13 .venv && uv pip install -q --python .venv "fastapi==0.115.12" "uvicorn==0.34.2" "httpx==0.28.1"
. .venv/bin/activate
cat > main.py <<'EOF'
from fastapi import FastAPI, HTTPException, status
from pydantic import BaseModel

app = FastAPI(title="Inventory API", version="1.0.0")

class Item(BaseModel):
    name: str
    price: float
    in_stock: bool = True

class ItemOut(Item):
    id: int

ITEMS: dict[int, ItemOut] = {1: ItemOut(id=1, name="Keyboard", price=49.5),
                             2: ItemOut(id=2, name="Monitor", price=189.0, in_stock=False)}

@app.get("/health")
def health():
    return {"status": "ok"}

@app.get("/items", response_model=list[ItemOut])
def list_items(in_stock: bool | None = None, limit: int = 10):           # query parameters
    items = [i for i in ITEMS.values() if in_stock is None or i.in_stock == in_stock]
    return items[:limit]

@app.get("/items/{item_id}", response_model=ItemOut)
def get_item(item_id: int):                                              # path parameter, converted to int
    if item_id not in ITEMS:
        raise HTTPException(status_code=404, detail="Item not found")
    return ITEMS[item_id]

@app.post("/items", response_model=ItemOut, status_code=status.HTTP_201_CREATED)
def create_item(item: Item):                                             # JSON body, validated
    new = ItemOut(id=max(ITEMS) + 1, **item.model_dump())
    ITEMS[new.id] = new
    return new
EOF
cat > try_api.py <<'EOF'
from fastapi.testclient import TestClient
from main import app

c = TestClient(app)
print(c.get("/health").json())
print("all:", [i["name"] for i in c.get("/items").json()])
print("in stock only:", c.get("/items", params={"in_stock": "true"}).json())
print("item 2:", c.get("/items/2").json())

print("bad body:", r.status_code, [(e["loc"], e["type"]) for e in r.json()["detail"]])
schema = c.get("/openapi.json").json()
print("OpenAPI:", schema["info"]["title"], "| paths:", sorted(schema["paths"]))
EOF
```

<Step title="Dependencies, middleware, and async versus blocking under Uvicorn">

<Tr>
<En>
`app2.py` adds a middleware that times every request, a `pagination` dependency that rejects page sizes over 100, a `require_api_key` dependency that reads the `X-API-Key` header and compares it with an environment variable, and three endpoints that each wait 0.5 seconds in a different way: `await asyncio.sleep` in `async def`, `time.sleep` in plain `def`, and `time.sleep` in `async def`. We run it with Uvicorn (one process), and `load.py` calls `/orders` with and without a key, then sends ten concurrent requests to each waiting endpoint.
</En>
<Ur>
`app2.py` har request ka waqt naapne wala middleware, 100 se bare page size radd karne wali `pagination` dependency, `X-API-Key` header parh kar environment variable se milane wali `require_api_key` dependency, aur teen endpoints jorti jo har ek 0.5 second mukhtalif tareeqe se intezar karta: `async def` me `await asyncio.sleep`, saade `def` me `time.sleep`, aur `async def` me `time.sleep`. Hum ise Uvicorn (ek process) se chalate, aur `load.py` key ke saath aur baghair `/orders` bulati, phir har intezar wale endpoint par das concurrent requests bhejti hai.
</Ur>
</Tr>

```bash
export NO_PROXY=127.0.0.1,localhost
. .venv/bin/activate
cat > app2.py <<'EOF'
import asyncio, os, time
from typing import Annotated
from fastapi import Depends, FastAPI, Header, HTTPException, Request

app = FastAPI()

@app.middleware("http")
async def timing(request: Request, call_next):              # runs around every request
    start = time.perf_counter()
    response = await call_next(request)
    response.headers["X-Process-Time-ms"] = f"{(time.perf_counter() - start) * 1000:.0f}"
    return response

def pagination(page: int = 1, size: int = 20):              # a reusable dependency
    if size > 100:
        raise HTTPException(400, "size must be at most 100")
    return {"offset": (page - 1) * size, "limit": size}

def require_api_key(x_api_key: Annotated[str | None, Header()] = None):
    if x_api_key != os.environ.get("INVENTORY_API_KEY"):
        raise HTTPException(401, "invalid or missing API key")
    return "partner-1"

Page = Annotated[dict, Depends(pagination)]
Client = Annotated[str, Depends(require_api_key)]

@app.get("/orders")
def orders(page: Page, client: Client):
    return {"client": client, **page}

@app.get("/async-wait")
async def async_wait():
    await asyncio.sleep(0.5)                 # non-blocking: other requests run meanwhile
    return {"ok": True}

@app.get("/blocking-wait")
async def blocking_wait():
    time.sleep(0.5)                          # WRONG inside async def: blocks the event loop
    return {"ok": True}

@app.get("/sync-wait")
def sync_wait():
    time.sleep(0.5)                          # plain def runs in a thread pool, so this is fine
    return {"ok": True}
EOF
export INVENTORY_API_KEY=acme_test_key_123
uvicorn app2:app --port 8020 --log-level warning & SERVER=$!
sleep 2
cat > load.py <<'EOF'
import asyncio, time, httpx

async def main():
    async with httpx.AsyncClient(base_url="http://127.0.0.1:8020", trust_env=False, timeout=20) as c:
        r = await c.get("/orders", params={"page": 3, "size": 10}, headers={"X-API-Key": "acme_test_key_123"})
        print("orders:", r.status_code, r.json(), "| timing header present:", "x-process-time-ms" in r.headers)
        print("no key:", (await c.get("/orders")).status_code, "| size=500:",
              (await c.get("/orders", params={"size": 500}, headers={"X-API-Key": "acme_test_key_123"})).json())
        for path in ["/async-wait", "/sync-wait", "/blocking-wait"]:
            start = time.perf_counter()
            await asyncio.gather(*(c.get(path) for _ in range(10)))
            took = time.perf_counter() - start
            print(f"10 concurrent {path:<15} {'about 0.5s (concurrent)' if took < 2 else 'about 5s (one at a time)'}")
asyncio.run(main())
EOF
python load.py
kill $SERVER
```

<Happened>
<Tr>
<En>

- `/orders` received the results of two dependencies: pagination turned `page=3, size=10` into **offset 20, limit 10**, and the API-key dependency returned the client name. Without a key the dependency raised **401** before the endpoint ran; `size=500` was rejected with our message. Dependencies keep endpoints short and make security checks impossible to forget once attached.
- The middleware added an `X-Process-Time-ms` header to every response, a typical place for request IDs, timing and logging.
- Ten concurrent requests to **`async def` + `await asyncio.sleep`** finished in about 0.5 s: while one waited, the event loop served the others.
- **Plain `def` with `time.sleep`** also took about 0.5 s, because FastAPI runs sync endpoints in a **thread pool**. That's the safe choice when you use blocking libraries.
- **`async def` with `time.sleep`** took about **5 s**: the blocking call froze the single event loop, so requests ran one at a time. The same happens with `requests.get`, a sync database driver or heavy CPU work inside `async def`. Either use async libraries, switch to plain `def`, or offload with `run_in_threadpool`/`asyncio.to_thread`.

</En>
<Ur>

- `/orders` ko do dependencies ke nataij mile: pagination ne `page=3, size=10` ko **offset 20, limit 10** banaya, aur API-key dependency ne client ka naam lautaya. Key ke baghair dependency ne endpoint chalne se pehle **401** uthaya; `size=500` hamare paigham ke saath radd hua. Dependencies endpoints chhote rakhti aur ek dafa lagne par security checks bhoolna na-mumkin banati hain.
- Middleware ne har response me `X-Process-Time-ms` header jora, request IDs, timing aur logging ki aam jagah.
- **`async def` + `await asyncio.sleep`** par das concurrent requests taqreeban 0.5 s me khatam huin: jab ek intezar karti, event loop doosron ko serve karta.
- **`time.sleep` wale saade `def`** ne bhi taqreeban 0.5 s liye, kyunke FastAPI sync endpoints **thread pool** me chalata hai. Blocking libraries istemal karte waqt yahi mehfooz intikhab hai.
- **`time.sleep` wale `async def`** ne taqreeban **5 s** liye: blocking call ne akela event loop jama kar diya, isliye requests ek ek kar ke chalin. `async def` ke andar `requests.get`, sync database driver ya bhaari CPU kaam ke saath bhi yahi hota hai. Ya async libraries lein, saade `def` par jayen, ya `run_in_threadpool`/`asyncio.to_thread` se alag karein.

</Ur>

## Common mistakes

<Compare>
<Bad title="Blocking calls in async endpoints">

```text
@app.get("/weather")
async def weather(city: str):
    r = requests.get(f"https://api.example.com/w?city={city}")   # blocks every other request
    return r.json()
```

</Bad>
<Good title="Async client in async def, or plain def">

```text
@app.get("/weather")
async def weather(city: str):
    async with httpx.AsyncClient(timeout=5) as client:
        r = await client.get("https://api.example.com/w", params={"city": city})
    return r.json()
# or: def weather(city: str): ... requests.get(..., timeout=5)
```

</Good>
</Compare>

<Compare>

Create a `current_client` dependency that looks up the `X-API-Key` header in a dict of keys (each with a name and scopes) and raises 401 for unknown keys, and a dependency factory `require_scope(scope)` that raises 403 when the client lacks the scope. <Solution>

<Tr>
<En>

```text
from typing import Annotated
from fastapi import Depends, FastAPI, Header, HTTPException
from fastapi.testclient import TestClient

KEYS = {"acme_test_partner_a": {"name": "partner-a", "scopes": {"orders:read"}},
        "acme_test_admin_1": {"name": "ops", "scopes": {"orders:read", "orders:write"}}}

def current_client(x_api_key: Annotated[str | None, Header()] = None):
    client = KEYS.get(x_api_key or "")
    if client is None:
        raise HTTPException(401, "invalid API key", headers={"WWW-Authenticate": "ApiKey"})
    return client

def require_scope(scope: str):
    def checker(client: Annotated[dict, Depends(current_client)]):
        if scope not in client["scopes"]:
            raise HTTPException(403, f"missing scope {scope}")
        return client
    return checker

app = FastAPI()

@app.get("/orders")
def read_orders(client: Annotated[dict, Depends(require_scope("orders:read"))]):
    return {"client": client["name"], "orders": [1042, 1043]}

@app.post("/orders/{order_id}/refund")
def refund(order_id: int, client: Annotated[dict, Depends(require_scope("orders:write"))]):
    return {"refunded": order_id, "by": client["name"]}

c = TestClient(app)
for key in [None, "wrong", "acme_test_partner_a", "acme_test_admin_1"]:
    headers = {"X-API-Key": key} if key else {}
    r1 = c.get("/orders", headers=headers).status_code
    r2 = c.post("/orders/1042/refund", headers=headers).status_code
    print(f"{key or 'no key':<20} GET /orders {r1}  POST refund {r2}")

# no key               GET /orders 401  POST refund 401
# wrong                GET /orders 401  POST refund 401
# acme_test_partner_a  GET /orders 200  POST refund 403
# acme_test_admin_1    GET /orders 200  POST refund 200
```

<DeepDive title="More about FastAPI">

**Routers.** `APIRouter(prefix="/orders", tags=["orders"], dependencies=[Depends(auth)])` splits a large app into modules and applies dependencies to every route in it.

**Lifespan.** `@asynccontextmanager` lifespan functions open and close shared resources (DB pools, HTTP clients) at startup and shutdown.

**Dependencies with yield.** A dependency can `yield` a database session and close it afterwards, like a context manager per request.

**Background tasks.** `BackgroundTasks` runs small jobs after the response; real queues (Celery, RQ, arq) handle heavier work.

**Error handlers.** `@app.exception_handler(MyError)` maps your exceptions to consistent JSON errors.

</DeepDive>

<DeepDive title="Real world: the API that slowed to a crawl">

A team moved an endpoint to `async def` to "make it faster". Inside, it still called a payment provider with `requests` and queried the database with a sync driver. Under normal traffic latency doubled, and during a provider slowdown the whole service stopped responding, including health checks, so the orchestrator restarted it in a loop.

The fixes:

1. The endpoint went back to plain `def` immediately, restoring the thread pool behaviour.
2. Later it moved to `httpx.AsyncClient` and an async database driver, with timeouts on every call.
3. A load test in CI sends concurrent requests to catch event-loop blocking.

</DeepDive>

<DeepDive title="Security lens">

- **Validate at the edge**: types, lengths, enums and ranges in models and `Query`/`Path` constraints.
- **Authenticate with dependencies** applied at router level so new endpoints are protected by default.
- **Control output** with response models to avoid leaking internal fields.
- **Limit resources**: pagination caps, request size limits at the proxy, rate limiting (slowapi or the gateway).
- **Configure CORS deliberately** with `CORSMiddleware` and explicit origins, never `*` with credentials.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="How does FastAPI use type hints?">
It reads parameter and model types to decide where values come from (path, query, header, body), converts and validates them with Pydantic, returns 422 on failure, and generates the OpenAPI schema and documentation.
</QA>

<QA q="When should an endpoint be async def versus def?">
Use async def when the code awaits async libraries for I/O; use plain def when it calls blocking libraries, because FastAPI runs those in a thread pool instead of blocking the event loop.
</QA>

<QA q="What are dependencies in FastAPI?">
Functions declared with Depends that FastAPI resolves before calling the endpoint, used for reusable logic like authentication, pagination or database sessions; they can raise HTTP errors and be nested or applied to whole routers.
</QA>

<QA q="What does a 422 response mean in FastAPI?">
The request failed validation: a parameter or body field had the wrong type, was missing, or violated a constraint; the body lists each error's location, message and type.
</QA>

<QA q="How do you test a FastAPI app?">
Use TestClient (or httpx.AsyncClient with the ASGI transport) to call endpoints in-process, override dependencies with app.dependency_overrides for fakes, and assert on status codes and JSON.
</QA>

</DeepDive>
