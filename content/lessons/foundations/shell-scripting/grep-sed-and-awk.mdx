<Callout type="tip" title="In one minute">
**grep** searches text and prints the lines that match: `grep ERROR app.log`. **sed** edits text as it flows past — mostly find-and-replace: `sed 's/old/new/g'`. **awk** splits each line into columns (`$1`, `$2`, …) and can filter and calculate: `awk '{print $1}'`. All three understand **regular expressions** — patterns like `^ERROR` (line starts with ERROR) or `[0-9]+` (one or more digits).
</Callout>

## Start from zero

### Why text tools?

Almost everything on a Linux server is text: log files, configuration files, command output, CSV exports. Questions you will ask every day are text questions:

- "Which lines of this log contain errors?"
- "Change `port=8080` to `port=9090` in this config."
- "Which IP made the most requests?"

<Callout type="analogy">
Imagine a huge register book.

- **grep** is a highlighter: it marks only the lines containing the word you want.
- **sed** is correction fluid and a pen: it replaces words as it reads.
- **awk** is a calculator with a ruler: it reads the book as columns — name, amount, date — and can add up the amounts.
</Callout>

### Words you need first

| Word | Simple meaning | Example |
| --- | --- | --- |
| **Line** | One row of text, ending with a newline | `ERROR db timeout` |
| **Match** | A line (or part) that fits what you searched for | `ERROR` matches `ERROR db timeout` |
| **Pattern** | What you search for — plain text or a regular expression | `ERROR`, `^[0-9]+` |
| **Regular expression (regex)** | A mini-language for describing text patterns | `^ERROR` = "starts with ERROR" |
| **Field / column** | One part of a line, separated by spaces or another character | in `10.0.0.5 GET /home`, field 1 is `10.0.0.5` |
| **Delimiter** | The character that separates fields | space, `,`, `:` |
| **Stream** | Text flowing through a pipe | `cat log \| grep ERROR` |

### The sample file used in this lesson

Every example below uses this small web-server log. Create it first:

```bash
cat > app.log <<'EOF'
2026-11-10 08:01:12 INFO  web-1 GET /home 200 120ms
2026-11-10 08:01:15 ERROR web-2 GET /api/users 500 2300ms
2026-11-10 08:02:01 WARN  web-1 GET /login 401 80ms
2026-11-10 08:02:44 ERROR web-1 POST /api/orders 500 1900ms
2026-11-10 08:03:10 INFO  web-2 GET /about 200 95ms
2026-11-10 08:03:59 info  web-2 GET /health 200 5ms
EOF
wc -l app.log
```

```text output
6 app.log
```

Columns (fields), separated by spaces: 1 date, 2 time, 3 level, 4 server, 5 method, 6 path, 7 status code, 8 duration.

## What is it?

Three standard command-line programs, installed on every Linux and macOS system:

| Tool | Job | Think of it as |
| --- | --- | --- |
| `grep` | **Find** lines that match a pattern | Search / filter |
| `sed` | **Change** text (replace, delete, insert) as it passes through | Find-and-replace |
| `awk` | **Split lines into columns**, filter by column, calculate, format | A tiny spreadsheet language |

## Why does it matter?

- **Log analysis** — the first thing you do in any incident: find errors, count them, find who caused them.
- **Config changes in scripts** — change a setting on 50 servers without opening an editor.
- **Data extraction** — pull usernames, IPs, versions or totals out of command output.
- **Security** — find failed logins in `auth.log`, suspicious IPs in web logs, secrets accidentally committed to code.
- **Interviews** — "count the top 10 IPs in an access log" is a classic DevOps and security interview task.

## When and where do you use it?

| You want to… | Use |
| --- | --- |
| Find lines containing something | `grep` |
| Check whether something exists (yes/no) | `grep -q` |
| Replace text in output or in a file | `sed` |
| Delete or print specific lines | `sed` |
| Get a column, sum numbers, filter by a column's value | `awk` |

## Concepts one by one

### 1. Regular expressions — the shared pattern language

<Explain>
<What>
A way of writing **patterns** instead of exact text. For example, "any line that starts with a date" or "any number".
</What>
<Why>
Real searches are rarely exact: you want "any IP address", "lines starting with ERROR", "a version like v1.2.3".
</Why>
<When>
With grep, sed, awk, and in almost every programming language (JavaScript, Python, Go…).
</When>
<Where>
Log searches, input validation, find-and-replace in editors like VS Code.
</Where>
<How>
Combine normal characters with special symbols from the table below. Use `grep -E` (extended regex) so `+`, `?`, `|` and `()` work without backslashes.
</How>
</Explain>

| Symbol | Means | Example | Matches |
| --- | --- | --- | --- |
| `.` | Any single character | `h.t` | hat, hot, h9t |
| `^` | Start of the line | `^ERROR` | lines starting with ERROR |
| `$` | End of the line | `ms$` | lines ending with ms |
| `*` | The previous thing 0 or more times | `ab*c` | ac, abc, abbbc |
| `+` | The previous thing 1 or more times (`-E`) | `[0-9]+` | 5, 42, 2026 |
| `?` | The previous thing 0 or 1 time (`-E`) | `colou?r` | color, colour |
| `[abc]` | One of these characters | `[aeiou]` | any vowel |
| `[0-9]` | One character in this range | `[A-Z]` | any capital letter |
| `[^0-9]` | One character **not** in this set | `[^ ]` | anything except a space |
| `a\|b` | a or b (`-E`) | `ERROR\|WARN` | either word |
| `( )` | Group (`-E`) | `(ab)+` | ab, abab |
| `\.` | A real dot (escaped) | `1\.2` | only "1.2" |

```bash
grep -E '^2026-11-10 08:02' app.log
echo "---"
grep -E ' (401|500) ' app.log
echo "---"
grep -E '[0-9]{4}ms$' app.log
```

```text output
2026-11-10 08:02:01 WARN  web-1 GET /login 401 80ms
2026-11-10 08:02:44 ERROR web-1 POST /api/orders 500 1900ms
---
2026-11-10 08:01:15 ERROR web-2 GET /api/users 500 2300ms
2026-11-10 08:02:01 WARN  web-1 GET /login 401 80ms
2026-11-10 08:02:44 ERROR web-1 POST /api/orders 500 1900ms
---
2026-11-10 08:01:15 ERROR web-2 GET /api/users 500 2300ms
2026-11-10 08:02:44 ERROR web-1 POST /api/orders 500 1900ms
```

- `^2026-11-10 08:02` — lines that **start** with that minute.
- ` (401|500) ` — a space, then 401 **or** 500, then a space (the spaces stop it matching inside other numbers).
- `[0-9]{4}ms$` — exactly four digits followed by `ms` at the **end** of the line: requests that took 1000 ms or more.

### 2. grep — find matching lines

<Explain>
<What>
A command that reads text line by line and prints only the lines that contain the pattern.
</What>
<Why>
To cut thousands of lines down to the few you care about.
</Why>
<When>
The first step of almost every log investigation, and to check whether text exists.
</When>
<Where>
Logs, config files, source code, command output (`ps aux | grep nginx`).
</Where>
<How>
`grep PATTERN FILE` or `command | grep PATTERN`. Quote the pattern (`'…'`) so the shell does not change it.
</How>
</Explain>

```bash
grep ERROR app.log
```

```text output
2026-11-10 08:01:15 ERROR web-2 GET /api/users 500 2300ms
2026-11-10 08:02:44 ERROR web-1 POST /api/orders 500 1900ms
```

### 3. The most useful grep options

<Explain>
<What>
Letters after a dash that change how grep searches or what it prints.
</What>
<Why>
Plain grep is case-sensitive and prints whole lines; options let you ignore case, count, invert, show line numbers, or just answer yes/no.
</Why>
<When>
Almost every time you use grep.
</When>
<Where>
Combine them: `grep -in error app.log`.
</Where>
<How>
See the table, then the examples.
</How>
</Explain>

| Option | Meaning |
| --- | --- |
| `-i` | **I**gnore upper/lower case |
| `-v` | In**v**ert: print lines that do **not** match |
| `-c` | **C**ount matching lines instead of printing them |
| `-n` | Show line **n**umbers |
| `-o` | Print **o**nly the matching part, not the whole line |
| `-w` | Match whole **w**ords only |
| `-q` | **Q**uiet: print nothing, just exit 0 (found) or 1 (not found) |
| `-E` | **E**xtended regex (`+`, `?`, `\|`, `()`) |
| `-r` | Search **r**ecursively through a folder |
| `-l` | Print only the names of files that match |
| `-A 2` / `-B 2` / `-C 2` | Also show 2 lines **A**fter / **B**efore / around each match |

```bash
echo "1) count of ERROR lines: $(grep -c ERROR app.log)"
echo "2) case-insensitive 'info' lines: $(grep -ci info app.log)"
echo "3) lines that are NOT INFO (any case):"
grep -vi info app.log
echo "4) with line numbers:"
grep -n WARN app.log
echo "5) only the matching part (status codes):"
grep -oE ' [0-9]{3} ' app.log | sort | uniq -c
grep -q "POST" app.log && echo "6) there is at least one POST request"
```

```text output
1) count of ERROR lines: 2
2) case-insensitive 'info' lines: 3
3) lines that are NOT INFO (any case):
2026-11-10 08:01:15 ERROR web-2 GET /api/users 500 2300ms
2026-11-10 08:02:01 WARN  web-1 GET /login 401 80ms
2026-11-10 08:02:44 ERROR web-1 POST /api/orders 500 1900ms
4) with line numbers:
3:2026-11-10 08:02:01 WARN  web-1 GET /login 401 80ms
5) only the matching part (status codes):
      3  200 
      1  401 
      2  500 
6) there is at least one POST request
```

- `-c` counts instead of printing.
- `-ci info` finds `INFO` **and** `info` (3 lines); plain `grep info` would find only 1.
- `-v` keeps everything that does **not** match.
- `-o` prints only the part that matched — here just the status codes, which we then count.
- `-q` prints nothing; perfect inside `if` or with `&&`.

**Searching a whole folder:**

```bash
mkdir -p project/src
echo 'const apiKey = "sk-test-123";' > project/src/config.js
echo 'console.log("hello");' > project/src/app.js
grep -rn "apiKey" project/
grep -rl "console.log" project/
```

```text output
project/src/config.js:1:const apiKey = "sk-test-123";
project/src/app.js
```

`-r` searches every file under `project/`; `-n` shows the line number; `-l` lists just the file names.

### 4. sed — find and replace

<Explain>
<What>
A **s**tream **ed**itor. It reads text line by line, applies your editing commands, and prints the result. Its most-used command is `s/old/new/` (substitute).
</What>
<Why>
To change text without opening an editor — inside scripts, on many files, on many servers.
</Why>
<When>
Changing a setting in a config file, cleaning up command output, renaming text in bulk.
</When>
<Where>
Deploy scripts (`sed -i "s/VERSION/$ver/" config`), Dockerfiles, CI pipelines.
</Where>
<How>
`sed 's/old/new/'` replaces the **first** match on each line; add `g` (`s/old/new/g`) to replace **all** matches on each line. Add `I` to ignore case (GNU sed).
</How>
</Explain>

```bash
echo "cat cat cat" | sed 's/cat/dog/'
echo "cat cat cat" | sed 's/cat/dog/g'
echo "Error error ERROR" | sed 's/error/issue/gI'
```

```text output
dog cat cat
dog dog dog
issue issue issue
```

- `s` = substitute, `cat` = what to find, `dog` = the replacement.
- Without `g` only the first `cat` on the line changes.
- `gI` = all matches, ignoring case.

**Replacing in our log** (the file itself is not changed — sed prints the result):

```bash
sed 's/web-/server-/g' app.log | head -2
```

```text output
2026-11-10 08:01:12 INFO  server-1 GET /home 200 120ms
2026-11-10 08:01:15 ERROR server-2 GET /api/users 500 2300ms
```

### 5. sed — editing files in place with `-i`

<Explain>
<What>
The `-i` option makes sed write the changes back into the file instead of printing them.
</What>
<Why>
To update config files automatically.
</Why>
<When>
In scripts that set ports, versions, hostnames or feature flags.
</When>
<Where>
Server setup scripts, Docker builds, CI.
</Where>
<How>
`sed -i 's/old/new/' file`. Safer: `sed -i.bak 's/old/new/' file` keeps a backup copy named `file.bak`. On macOS, write `sed -i '' 's/…/…/' file`.
</How>
</Explain>

```bash
printf 'port=8080\nhost=localhost\ndebug=true\n' > app.conf
sed -i.bak 's/^port=.*/port=9090/; s/^debug=true/debug=false/' app.conf
echo "--- app.conf now:"; cat app.conf
echo "--- backup app.conf.bak:"; cat app.conf.bak
```

```text output
--- app.conf now:
port=9090
host=localhost
debug=false
--- backup app.conf.bak:
port=8080
host=localhost
debug=true
```

- `^port=.*` — a line that starts with `port=` followed by anything (`.*` = any characters).
- `;` separates two sed commands in one call.
- `-i.bak` changed the file **and** kept the original as `app.conf.bak`.

**When the text contains `/`**, use another separator so you do not need to escape every slash:

```bash
echo "path=/var/www/old" | sed 's|/var/www/old|/srv/app|'
```

```text output
path=/srv/app
```

### 6. sed — printing and deleting lines

<Explain>
<What>
Besides replacing, sed can delete lines (`d`) and print chosen lines (`p` together with `-n`).
</What>
<Why>
To remove comments or blank lines, or show a specific range of lines from a large file.
</Why>
<When>
Cleaning config files, extracting a section of a log.
</When>
<Where>
`sed '/^#/d' config` to strip comments; `sed -n '100,120p' big.log` to look at lines 100–120.
</Where>
<How>
`sed '/pattern/d'` deletes matching lines; `sed -n '2,4p'` prints only lines 2 to 4 (`-n` stops sed printing everything else).
</How>
</Explain>

```bash
printf '# database settings\nhost=db\n\n# port\nport=5432\n' > db.conf
echo "--- without comments and blank lines:"
sed '/^#/d; /^$/d' db.conf
echo "--- only lines 2 to 3 of app.log:"
sed -n '2,3p' app.log
```

```text output
--- without comments and blank lines:
host=db
port=5432
--- only lines 2 to 3 of app.log:
2026-11-10 08:01:15 ERROR web-2 GET /api/users 500 2300ms
2026-11-10 08:02:01 WARN  web-1 GET /login 401 80ms
```

- `/^#/d` — delete lines that start with `#`.
- `/^$/d` — delete empty lines (start immediately followed by end).

### 7. awk — working with columns

<Explain>
<What>
A small programming language built for text organised in columns. It splits every line into **fields**: `$1` is the first column, `$2` the second, … `$0` is the whole line, and `NF` is the number of fields.
</What>
<Why>
grep works with whole lines; awk understands the **structure** of a line, so you can pick and compare individual columns.
</Why>
<When>
When you need one column from output, or want to filter by the value of a column.
</When>
<Where>
Logs, `ps` and `df` output, CSV files, `/etc/passwd`.
</Where>
<How>
`awk '{ print $1, $3 }' file` prints columns 1 and 3 of every line. Always use **single quotes** around the awk program so the shell does not touch the `$`.
</How>
</Explain>

```bash
awk '{ print $3, $6 }' app.log
```

```text output
INFO /home
ERROR /api/users
WARN /login
ERROR /api/orders
INFO /about
info /health
```

Columns are split on spaces (any number of spaces). That is why the double space after `INFO` and `WARN` causes no problem.

### 8. awk — filtering by a column

<Explain>
<What>
A condition placed before the `{ … }` block. The block runs only for lines where the condition is true.
</What>
<Why>
To ask questions like "requests with status 500" or "lines where the 4th column is web-1" — something grep cannot do reliably.
</Why>
<When>
Whenever the decision depends on a specific column's value.
</When>
<Where>
Finding slow requests, large files, users with a certain shell.
</Where>
<How>
`awk 'CONDITION { ACTION }'`. Conditions can compare numbers (`$7 >= 500`), text (`$4 == "web-1"`) or match regex (`$3 ~ /ERR/`).
</How>
</Explain>

```bash
echo "Status 500 on which server and path:"
awk '$7 == 500 { print $4, $6 }' app.log
echo "Requests on web-1:"
awk '$4 == "web-1" { print $2, $6 }' app.log
```

```text output
Status 500 on which server and path:
web-2 /api/users
web-1 /api/orders
Requests on web-1:
08:01:12 /home
08:02:01 /login
08:02:44 /api/orders
```

### 9. awk — calculations, counting and `BEGIN` / `END`

<Explain>
<What>
awk can keep variables, add numbers, and run code before the first line (`BEGIN`) and after the last line (`END`).
</What>
<Why>
To produce totals, averages and per-group counts straight from a log, without a spreadsheet.
</Why>
<When>
Summaries: total bytes, average response time, requests per server.
</When>
<Where>
Reports in cron jobs, quick checks during incidents.
</Where>
<How>
`awk '{ sum += $8 } END { print sum }'`. For counting per group, use an array: `count[$4]++` then loop over it in `END`.
</How>
</Explain>

```bash
awk '{ total += $8; n++ } END { print "requests:", n, "| average time:", total / n, "ms" }' app.log

awk '{ hits[$4]++ } END { for (s in hits) print s, hits[s] }' app.log | sort
```

```text output
requests: 6 | average time: 750 ms
web-1 3
web-2 3
```

- `total += $8` — add column 8 to `total`. `"120ms"` becomes the number 120 because awk reads the leading digits.
- `n++` — count the lines.
- `END { … }` — after the last line, print the result.
- `hits[$4]++` — an **array** keyed by server name; each line adds 1 to its server's counter.

### 10. awk — other separators with `-F`

<Explain>
<What>
The `-F` option tells awk which character separates the columns.
</What>
<Why>
Many files are not space-separated: CSV uses `,`, `/etc/passwd` uses `:`.
</Why>
<When>
Any file with a fixed separator.
</When>
<Where>
CSV exports, `/etc/passwd`, `/etc/group`, colon-separated config.
</Where>
<How>
`awk -F, '…'` for commas, `awk -F: '…'` for colons.
</How>
</Explain>

```bash
printf 'name,role,salary\nAli,dev,250000\nSara,ops,300000\nUsman,dev,200000\n' > staff.csv
awk -F, 'NR > 1 && $2 == "dev" { print $1 }' staff.csv
awk -F, 'NR > 1 { sum += $3 } END { print "total payroll:", sum }' staff.csv
```

```text output
Ali
Usman
total payroll: 750000
```

`NR` is the current line number; `NR > 1` skips the header line.

### 11. Choosing the right tool

| Question | Best tool | Example |
| --- | --- | --- |
| Which lines contain X? | grep | `grep -i timeout app.log` |
| Does X exist at all? | grep -q | `grep -q '^port=' app.conf` |
| Change X to Y | sed | `sed -i 's/8080/9090/' app.conf` |
| Remove comments / blank lines | sed | `sed '/^#/d; /^$/d'` |
| Show column N | awk | `awk '{print $1}'` |
| Filter by a column's value | awk | `awk '$7 >= 500'` |
| Sum / average / count per group | awk | `awk '{s+=$8} END {print s}'` |

They combine with pipes: `grep ERROR app.log | awk '{print $4}' | sort | uniq -c`.

## Hands-on

```bash
mkdir -p ~/text-lab && cd ~/text-lab
cat > access.log <<'EOF'
10.0.0.5 - - [10/Nov/2026:08:01:12] "GET /home HTTP/1.1" 200 512
10.0.0.7 - - [10/Nov/2026:08:01:15] "POST /login HTTP/1.1" 401 64
10.0.0.5 - - [10/Nov/2026:08:01:20] "GET /about HTTP/1.1" 200 1024
10.0.0.9 - - [10/Nov/2026:08:02:01] "POST /login HTTP/1.1" 401 64
10.0.0.7 - - [10/Nov/2026:08:02:05] "POST /login HTTP/1.1" 401 64
10.0.0.7 - - [10/Nov/2026:08:02:09] "POST /login HTTP/1.1" 200 128
EOF

echo "1) failed logins: $(grep -c '" 401 ' access.log)"
echo "2) IPs with failed logins:"
grep '" 401 ' access.log | awk '{print $1}' | sort | uniq -c | sort -rn
echo "3) total bytes sent: $(awk '{s += $NF} END {print s}' access.log)"
echo "4) paths only:"
awk '{print $6}' access.log | sort -u
echo "5) anonymised IPs:"
sed -E 's/^([0-9]+\.[0-9]+)\.[0-9]+\.[0-9]+/\1.x.x/' access.log | head -2

cd ~ && rm -rf ~/text-lab
```

```text output
1) failed logins: 3
2) IPs with failed logins:
      2 10.0.0.7
      1 10.0.0.9
3) total bytes sent: 1856
4) paths only:
/about
/home
/login
5) anonymised IPs:
10.0.x.x - - [10/Nov/2026:08:01:12] "GET /home HTTP/1.1" 200 512
10.0.x.x - - [10/Nov/2026:08:01:15] "POST /login HTTP/1.1" 401 64
```

- `$NF` — the **last** field (NF = number of fields), here the response size.
- `sed -E 's/^([0-9]+\.[0-9]+)\.…/\1.x.x/'` — the brackets **capture** the first two parts of the IP and `\1` puts them back, hiding the rest. Useful before sharing logs.

## Real-world example

A DevSecOps engineer adds a quick **"no secrets, no debug in production config"** gate to a CI pipeline, plus a nightly report — using only these tools:

```bash
#!/usr/bin/env bash
set -euo pipefail

# 1. Fail the build if a production env file enables debug or uses http://
if grep -nE '^(DEBUG=true|NODE_ENV=development)|http://' deploy/production.env; then
  echo "✖ Production config contains debug settings or plain HTTP URLs" >&2
  exit 1
fi

# 2. Fail if anything looks like a private key or AWS key was committed
if grep -rnE 'BEGIN (RSA |EC |OPENSSH )?PRIVATE KEY|AKIA[0-9A-Z]{16}' --exclude-dir=node_modules .; then
  echo "✖ Possible secret committed" >&2
  exit 1
fi

# 3. Stamp the build version into the config
sed -i "s/^APP_VERSION=.*/APP_VERSION=${GITHUB_SHA:0:7}/" deploy/production.env

# 4. Nightly: top scanners and error rate from yesterday's logs
zcat -f /var/log/nginx/access.log.1* \
  | awk '$9 ~ /^5/ {e++} {t++} $7 ~ /\.(env|git|php)/ {probe[$1]++}
         END {printf "error rate: %.2f%%\n", 100*e/t;
              for (ip in probe) print probe[ip], ip}' \
  | sort -rn | head
```

(Dedicated tools like gitleaks do secret scanning far better — covered in DevSecOps — but this shows how far three classic tools go.)

## Common mistakes

- **Unquoted patterns:** `grep *.log` — the shell expands `*` first. Always quote: `grep 'pattern' file`.
- **Forgetting `-E`** and wondering why `+`, `|` or `{3}` do not work.
- **Dots in IPs and domains:** `grep 1.2.3.4` also matches `1x2y3z4`. Use `grep -F` or escape: `1\.2\.3\.4`.
- **`sed -i` without testing first** — run without `-i` (prints the result), check it, then add `-i` (or `-i.bak`).
- **Greedy matches:** `s/".*"/X/` replaces from the first quote to the **last** one on the line. Use `"[^"]*"`.
- **Parsing CSV/JSON with awk** — quoted commas and nested data break simple splitting. Use proper tools.
- **Single vs double quotes:** `awk '{print $1}'` must use single quotes, or the shell will expand `$1` first.

## Security lens

<Callout type="security">
These three tools are the fastest way to answer "what happened?" on any Linux system — and the fastest way to find secrets before attackers do.
</Callout>

- **Threat hunting basics:** probes for `/.env`, `/.git/config`, `/wp-login.php`, `/phpmyadmin`; spikes of 401/403; long or encoded URLs (`%2e%2e%2f`); unusual user agents (`sqlmap`, `nikto`, `curl`, `python-requests`) — all findable with grep and awk.
- **IOC sweeps:** given indicators (IPs, domains, file hashes) from a threat report, `grep -rFf iocs.txt /var/log` checks a server in seconds.
- **Secret discovery:** `grep -rnE "(api[_-]?key|secret|passw(or)?d|token)\s*[:=]"` across repos and servers finds hard-coded credentials — run it on your own code before an attacker or a public GitHub scan does.
- **Regex denial of service (ReDoS):** badly written regexes with nested quantifiers (`(a+)+$`) can take exponential time on crafted input. In applications that apply regex to user input, prefer simple patterns, length limits and safe regex engines.
- **Command injection via sed/awk:** building a `sed` expression from user input (`sed "s/$input/x/"`) lets an attacker inject sed commands — GNU sed's `e` flag can even run shell commands. Never interpolate untrusted input into sed or awk programs; pass data with `awk -v var="$input"` instead.

## Interview questions

<QA q="How would you find the 10 IP addresses with the most requests in an Nginx access log?">
`awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -n 10`. awk prints the first field (client IP), sort groups identical IPs, uniq -c counts each group, sort -rn orders by count descending, and head keeps the top ten. An awk-only version is `awk '{c[$1]++} END {for (i in c) print c[i], i}' access.log | sort -rn | head`.
</QA>

<QA q="How do you replace a value in a config file from a script, safely?">
Use sed with in-place editing and a backup, anchoring the pattern to the start of the line: `sed -i.bak 's/^PasswordAuthentication .*/PasswordAuthentication no/' /etc/ssh/sshd_config`. Test the expression without -i first, validate the resulting file (for example sshd -t), and use a different delimiter like | when the values contain slashes.
</QA>

<QA q="What is the difference between grep, grep -E and grep -F?">
grep uses basic regular expressions, where characters such as +, ?, |, () and {} need backslashes to have special meaning. grep -E uses extended regular expressions, where they work directly. grep -F treats the pattern as a fixed string with no regex meaning at all, which is fastest and correct for literal text containing dots or brackets, like IP addresses.
</QA>

<QA q="When would you use awk instead of grep or sed?">
When the data has columns or you need logic or arithmetic: selecting specific fields, filtering on a field's value (status code over 499), summing or averaging a column, counting by group with associative arrays, or reformatting output. grep is for finding matching lines and sed for line-oriented edits such as substitutions.
</QA>

<QA q="Why is it dangerous to build a sed command from user input?">
The input becomes part of the sed program, so special characters can change its meaning: an attacker could add commands, break out of the substitution or, with GNU sed's e flag, execute shell commands. Validate input against an allow-list, escape it properly, or use tools that take data as data, such as awk -v or a real programming language.
</QA>

## Key terms

<Terms>
  <Term name="grep">Prints lines matching a pattern.</Term>
  <Term name="sed">Stream editor for transforming text line by line.</Term>
  <Term name="awk">A pattern-action language for processing columns of text.</Term>
  <Term name="Regular expression">A pattern describing text, used for matching and replacing.</Term>
  <Term name="Extended regex (-E)">Regex syntax where + ? | ( ) { } work without backslashes.</Term>
  <Term name="Field">A column of a line, split by whitespace or a chosen separator; $1, $2 in awk.</Term>
  <Term name="Capture group">Part of a regex in parentheses, reused as \1 in sed replacements.</Term>
  <Term name="In-place edit">sed -i: writing changes back to the file instead of stdout.</Term>
  <Term name="Associative array">A key-value map, such as count[$1]++ in awk.</Term>
</Terms>
