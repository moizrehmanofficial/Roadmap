<Callout type="tip" title="In one minute">
**grep** prints lines that match a pattern (`grep -rin "error" /var/log/app/`). **sed** transforms text line by line — most often find-and-replace: `sed 's/old/new/g' file`, or in place with `sed -i`. **awk** splits each line into fields (`$1`, `$2`…) and can filter, sum and format: `awk '$9 == 500 {print $1}' access.log`. All three use **regular expressions**. Rule of thumb: *find* → grep, *replace* → sed, *columns and numbers* → awk.
</Callout>

## What is it?

| Tool | Name comes from | One-line job | Typical use |
| --- | --- | --- | --- |
| **grep** | **g**lobal **r**egular **e**xpression **p**rint | Show lines matching a pattern | Search logs and code, filter output |
| **sed** | **s**tream **ed**itor | Change text as it flows past | Replace values in configs, delete lines, extract ranges |
| **awk** | **A**ho, **W**einberger, **K**ernighan (its authors) | Process text as rows and columns | Pick fields, sum numbers, group and report |

All three read **line by line**, which means they work on files far larger than your RAM and fit naturally into pipelines.

### Regular expressions — the shared language

A **regular expression** (regex) describes a text pattern. The parts you will use 95% of the time:

| Pattern | Matches | Example |
| --- | --- | --- |
| `abc` | The literal text | `error` |
| `.` | Any one character | `h.t` → hat, hot, h1t |
| `^` / `$` | Start / end of line | `^root`, `\.log$` |
| `*` | Previous item 0+ times | `ab*c` → ac, abc, abbc |
| `+` | 1+ times (extended) | `[0-9]+` |
| `?` | 0 or 1 time (extended) | `colou?r` |
| `[abc]` | One of these characters | `[aeiou]` |
| `[^abc]` | Any character except these | `[^ ]+` = a "word" |
| `[0-9]`, `[a-z]` | Ranges | `[0-9]{3}` = three digits |
| `{n,m}` | Between n and m times (extended) | `[0-9]{1,3}` |
| `a\|b` / `(a\|b)` | Alternatives (extended) | `(GET\|POST)` |
| `\` | Escape a special character | `\.` = a real dot |
| `\b` | Word boundary (GNU) | `\bcat\b` not "category" |

**Basic vs extended regex:** in basic mode (default for grep and sed) `+ ? { } | ( )` need a backslash. Use **`grep -E`** and **`sed -E`** to get the extended syntax above without backslashes. Use **`grep -F`** for a fixed string with no regex at all (fastest, and safe for text containing dots or brackets).

## Why does it matter?

- **Full-stack:** finding where an env variable or function is used, pulling errors out of logs, quick edits on servers without an editor.
- **DevOps:** CI scripts edit config files (`sed -i "s/VERSION/$TAG/"`), extract values from command output, and gate builds on log contents.
- **Cloud:** parsing CLI output (when `--query`/`jq` is not available), templating user-data.
- **Security:** log analysis and threat hunting ("which IPs hit `/wp-login.php`?"), finding secrets in code, IOC searches across servers, quick triage during incidents. These tools are on every Linux box, including minimal and compromised ones where you cannot install anything.

## When and where do you use it?

- `grep -rn "DATABASE_URL" .` — where is it used?
- `journalctl -u app | grep -i "timeout"` — filter service logs.
- `sed -i 's/^#\?PasswordAuthentication .*/PasswordAuthentication no/' /etc/ssh/sshd_config` — enforce a setting.
- `awk '{sum += $10} END {print sum/1024/1024 " MB"}' access.log` — total traffic.
- `ps aux | awk '$3 > 50'` — processes over 50% CPU.

## How does it work?

### grep

```bash
grep "error" app.log                 # lines containing "error" (case-sensitive)
grep -i "error" app.log              # ignore case
grep -n "error" app.log              # show line numbers
grep -c "error" app.log              # count matching lines
grep -v "healthcheck" access.log     # lines NOT matching
grep -w "id" file                    # whole word only (not "idle")
grep -x "done" file                  # whole line must match
grep -o "[0-9]\{3\}" file            # print only the matching part
grep -E "ERROR|FATAL" app.log        # extended regex: either word
grep -F "1.2.3.4" access.log         # fixed string (dots are literal)
grep -r "TODO" src/                  # recursive
grep -rn --include="*.ts" "useEffect" src/   # only .ts files
grep -rl "password" config/          # only file names
grep -A 3 -B 2 "Exception" app.log   # 3 lines After, 2 Before each match (context)
grep -f bad-ips.txt access.log       # patterns from a file
```

Exit status: **0** if something matched, **1** if nothing matched, **2** on error — perfect for `if grep -q …; then`.

Modern alternative: **ripgrep** (`rg`) — much faster, respects `.gitignore` automatically. Same ideas.

### sed

The most used command is **substitute**:

```text
sed 's/PATTERN/REPLACEMENT/FLAGS'
         │       │            └ g = all matches on the line (default: first only), i = ignore case
         │       └ new text; & = the whole match, \1 = first captured group
         └ regex to find
```

```bash
sed 's/http:/https:/' urls.txt            # first match per line, printed to stdout
sed 's/http:/https:/g' urls.txt           # all matches
sed -i 's/localhost/db.internal/g' app.env              # edit the file IN PLACE
sed -i.bak 's/DEBUG=true/DEBUG=false/' app.env          # in place, keep app.env.bak
sed 's|/var/www|/srv/www|g' nginx.conf    # any delimiter — handy for paths
sed -E 's/([0-9]+)\.([0-9]+)/\2.\1/' f    # capture groups with -E
```

Other everyday commands:

```bash
sed -n '10,20p' big.log                   # print only lines 10–20
sed -n '/BEGIN CERT/,/END CERT/p' file.pem   # print a range between two patterns
sed '/^#/d' config                        # delete comment lines
sed '/^$/d' file                          # delete empty lines
sed '1i # Generated file — do not edit' f # insert a line before line 1
sed '$a last line' file                   # append after the last line
sed -n '$=' file                          # count lines (like wc -l)
```

macOS note: BSD `sed -i` needs an argument: `sed -i '' 's/a/b/' file`. GNU (Linux) does not. Scripts meant for both often use `sed -i.bak` and delete the backup.

### awk

awk reads each line, splits it into **fields** by whitespace (or `-F` delimiter), and runs `pattern { action }` rules:

```text
awk -F',' 'PATTERN { ACTION }' file
   │        │         └ what to do: print, compute, store
   │        └ when to do it: a condition or /regex/ (omit = every line)
   └ field separator (default: spaces/tabs)
```

| Variable | Meaning |
| --- | --- |
| `$0` | The whole line |
| `$1`, `$2` … | Field 1, 2 … |
| `$NF` | The last field (`NF` = number of fields) |
| `NR` | Current line number (record number) |
| `FS` / `OFS` | Input / output field separator |
| `BEGIN { }` / `END { }` | Run before the first line / after the last line |

```bash
awk '{print $1}' access.log                       # first column
awk '{print $1, $9}' access.log                   # IP and status code
awk -F: '{print $1, $7}' /etc/passwd              # user and shell (colon-separated)
awk '$9 == 404' access.log                        # rows where status is 404 (print is default)
awk '$9 >= 500 {print $1, $7}' access.log         # server errors: IP and path
awk '/POST/ && $9 == 401' access.log              # regex AND condition
awk 'NR > 1' data.csv                             # skip a header line
awk '{print NR": "$0}' file                       # number the lines
awk '{print $NF}' file                            # last field
awk -F, '{sum += $3} END {print "Total:", sum}' sales.csv            # sum a column
awk '{bytes += $10} END {printf "%.1f MB\n", bytes/1048576}' access.log
awk '{count[$1]++} END {for (ip in count) print count[ip], ip}' access.log | sort -rn | head   # group by
awk 'length($0) > 200' file                       # long lines
```

`count[$1]++` uses an **associative array** (a dictionary): this one line replaces `sort | uniq -c`.

### Choosing the right tool

| Task | Best tool |
| --- | --- |
| "Does this file contain X?", "which files mention X?" | grep |
| Replace text, delete or insert lines | sed |
| Pick columns, filter by a column's value | awk |
| Sum, average, count by group | awk |
| Structured data (JSON) | **jq** (lesson later in this module) |
| CSV with quoted commas | A real CSV tool (Python, `mlr`, `csvkit`) — awk splits naively |
| Anything beyond a few lines of logic | Python |

## Hands-on

Create sample data, then work through each tool:

```bash
mkdir -p ~/text-lab && cd ~/text-lab

cat > access.log <<'EOF'
203.0.113.5 - - [10/Nov/2026:10:00:01 +0500] "GET /products HTTP/1.1" 200 5120 "-" "Mozilla/5.0"
198.51.100.7 - - [10/Nov/2026:10:00:02 +0500] "POST /api/login HTTP/1.1" 401 54 "-" "python-requests/2.32"
198.51.100.7 - - [10/Nov/2026:10:00:03 +0500] "POST /api/login HTTP/1.1" 401 54 "-" "python-requests/2.32"
203.0.113.9 - - [10/Nov/2026:10:00:04 +0500] "GET /wp-login.php HTTP/1.1" 404 162 "-" "curl/8.5"
198.51.100.7 - - [10/Nov/2026:10:00:05 +0500] "POST /api/login HTTP/1.1" 200 210 "-" "python-requests/2.32"
203.0.113.5 - - [10/Nov/2026:10:00:06 +0500] "GET /api/orders HTTP/1.1" 500 98 "-" "Mozilla/5.0"
192.0.2.44 - - [10/Nov/2026:10:00:07 +0500] "GET /.env HTTP/1.1" 404 162 "-" "Go-http-client/1.1"
EOF

cat > app.env <<'EOF'
# App configuration
NODE_ENV=development
DATABASE_URL=postgres://localhost:5432/app
DEBUG=true

API_URL=http://api.example.com
EOF

# grep
grep -c "POST /api/login" access.log
grep -E '" (4|5)[0-9]{2} ' access.log                  # all 4xx and 5xx
grep -oE '^[0-9.]+' access.log | sort -u               # unique IPs
grep -E '/(\.env|wp-login\.php|\.git)' access.log      # classic scanner probes
grep -v '^#' app.env | grep -v '^$'                    # config without comments/blank lines

# sed
sed 's/development/production/' app.env
sed -E 's#http://#https://#g; s/DEBUG=true/DEBUG=false/' app.env
sed -i.bak '/^#/d; /^$/d' app.env && cat app.env && ls app.env*
sed -n '2,4p' access.log

# awk
awk '{print $1, $9}' access.log
awk '$9 == 401 {print $1}' access.log | sort | uniq -c
awk '{n[$9]++} END {for (s in n) print s, n[s]}' access.log | sort
awk '{bytes += $10} END {print "total bytes:", bytes}' access.log
awk -F= '/^DATABASE_URL/ {print $2}' app.env

cd ~ && rm -rf ~/text-lab
```

Regex works the same way in JavaScript — try patterns here before using them in grep:

```javascript
const lines = [
  '198.51.100.7 "POST /api/login HTTP/1.1" 401',
  '203.0.113.9 "GET /wp-login.php HTTP/1.1" 404',
  '192.0.2.44 "GET /.env HTTP/1.1" 404',
  '203.0.113.5 "GET /products HTTP/1.1" 200',
];

const probe = /\/(\.env|wp-login\.php|\.git)/;          // same as grep -E
console.log("probes:", lines.filter((l) => probe.test(l)));

const ipAndStatus = /^([0-9.]+) .* (\d{3})$/;            // capture groups, like sed -E \1 \2
for (const l of lines) {
  const [, ip, status] = l.match(ipAndStatus);
  console.log(ip.padEnd(15), status);
}

// sed 's/http:/https:/g'
console.log("http://a.com and http://b.com".replace(/http:/g, "https:"));
```

## Real-world example

A DevSecOps engineer adds a quick **"no secrets, no debug in production config"** gate to a CI pipeline, plus a nightly report — using only these tools:

```bash
#!/usr/bin/env bash
set -euo pipefail

# 1. Fail the build if a production env file enables debug or uses http://
if grep -nE '^(DEBUG=true|NODE_ENV=development)|http://' deploy/production.env; then
  echo "✖ Production config contains debug settings or plain HTTP URLs" >&2
  exit 1
fi

# 2. Fail if anything looks like a private key or AWS key was committed
if grep -rnE 'BEGIN (RSA |EC |OPENSSH )?PRIVATE KEY|AKIA[0-9A-Z]{16}' --exclude-dir=node_modules .; then
  echo "✖ Possible secret committed" >&2
  exit 1
fi

# 3. Stamp the build version into the config
sed -i "s/^APP_VERSION=.*/APP_VERSION=${GITHUB_SHA:0:7}/" deploy/production.env

# 4. Nightly: top scanners and error rate from yesterday's logs
zcat -f /var/log/nginx/access.log.1* \
  | awk '$9 ~ /^5/ {e++} {t++} $7 ~ /\.(env|git|php)/ {probe[$1]++}
         END {printf "error rate: %.2f%%\n", 100*e/t;
              for (ip in probe) print probe[ip], ip}' \
  | sort -rn | head
```

(Dedicated tools like gitleaks do secret scanning far better — covered in DevSecOps — but this shows how far three classic tools go.)

## Common mistakes

- **Unquoted patterns:** `grep *.log` — the shell expands `*` first. Always quote: `grep 'pattern' file`.
- **Forgetting `-E`** and wondering why `+`, `|` or `{3}` do not work.
- **Dots in IPs and domains:** `grep 1.2.3.4` also matches `1x2y3z4`. Use `grep -F` or escape: `1\.2\.3\.4`.
- **`sed -i` without testing first** — run without `-i` (prints the result), check it, then add `-i` (or `-i.bak`).
- **Greedy matches:** `s/".*"/X/` replaces from the first quote to the **last** one on the line. Use `"[^"]*"`.
- **Parsing CSV/JSON with awk** — quoted commas and nested data break simple splitting. Use proper tools.
- **Single vs double quotes:** `awk '{print $1}'` must use single quotes, or the shell will expand `$1` first.

## Security lens

<Callout type="security">
These three tools are the fastest way to answer "what happened?" on any Linux system — and the fastest way to find secrets before attackers do.
</Callout>

- **Threat hunting basics:** probes for `/.env`, `/.git/config`, `/wp-login.php`, `/phpmyadmin`; spikes of 401/403; long or encoded URLs (`%2e%2e%2f`); unusual user agents (`sqlmap`, `nikto`, `curl`, `python-requests`) — all findable with grep and awk.
- **IOC sweeps:** given indicators (IPs, domains, file hashes) from a threat report, `grep -rFf iocs.txt /var/log` checks a server in seconds.
- **Secret discovery:** `grep -rnE "(api[_-]?key|secret|passw(or)?d|token)\s*[:=]"` across repos and servers finds hard-coded credentials — run it on your own code before an attacker or a public GitHub scan does.
- **Regex denial of service (ReDoS):** badly written regexes with nested quantifiers (`(a+)+$`) can take exponential time on crafted input. In applications that apply regex to user input, prefer simple patterns, length limits and safe regex engines.
- **Command injection via sed/awk:** building a `sed` expression from user input (`sed "s/$input/x/"`) lets an attacker inject sed commands — GNU sed's `e` flag can even run shell commands. Never interpolate untrusted input into sed or awk programs; pass data with `awk -v var="$input"` instead.

## Interview questions

<QA q="How would you find the 10 IP addresses with the most requests in an Nginx access log?">
`awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -n 10`. awk prints the first field (client IP), sort groups identical IPs, uniq -c counts each group, sort -rn orders by count descending, and head keeps the top ten. An awk-only version is `awk '{c[$1]++} END {for (i in c) print c[i], i}' access.log | sort -rn | head`.
</QA>

<QA q="How do you replace a value in a config file from a script, safely?">
Use sed with in-place editing and a backup, anchoring the pattern to the start of the line: `sed -i.bak 's/^PasswordAuthentication .*/PasswordAuthentication no/' /etc/ssh/sshd_config`. Test the expression without -i first, validate the resulting file (for example sshd -t), and use a different delimiter like | when the values contain slashes.
</QA>

<QA q="What is the difference between grep, grep -E and grep -F?">
grep uses basic regular expressions, where characters such as +, ?, |, () and {} need backslashes to have special meaning. grep -E uses extended regular expressions, where they work directly. grep -F treats the pattern as a fixed string with no regex meaning at all, which is fastest and correct for literal text containing dots or brackets, like IP addresses.
</QA>

<QA q="When would you use awk instead of grep or sed?">
When the data has columns or you need logic or arithmetic: selecting specific fields, filtering on a field's value (status code over 499), summing or averaging a column, counting by group with associative arrays, or reformatting output. grep is for finding matching lines and sed for line-oriented edits such as substitutions.
</QA>

<QA q="Why is it dangerous to build a sed command from user input?">
The input becomes part of the sed program, so special characters can change its meaning: an attacker could add commands, break out of the substitution or, with GNU sed's e flag, execute shell commands. Validate input against an allow-list, escape it properly, or use tools that take data as data, such as awk -v or a real programming language.
</QA>

## Key terms

<Terms>
  <Term name="grep">Prints lines matching a pattern.</Term>
  <Term name="sed">Stream editor for transforming text line by line.</Term>
  <Term name="awk">A pattern-action language for processing columns of text.</Term>
  <Term name="Regular expression">A pattern describing text, used for matching and replacing.</Term>
  <Term name="Extended regex (-E)">Regex syntax where + ? | ( ) { } work without backslashes.</Term>
  <Term name="Field">A column of a line, split by whitespace or a chosen separator; $1, $2 in awk.</Term>
  <Term name="Capture group">Part of a regex in parentheses, reused as \1 in sed replacements.</Term>
  <Term name="In-place edit">sed -i: writing changes back to the file instead of stdout.</Term>
  <Term name="Associative array">A key-value map, such as count[$1]++ in awk.</Term>
</Terms>
