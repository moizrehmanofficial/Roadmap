<Callout type="tip" title="In one minute">
`for x in a b c; do …; done` repeats once per item. Loop over files with a glob (`for f in *.log`), over numbers with `for i in {1..5}` or `for ((i=0; i<n; i++))`, over arrays with `for x in "${arr[@]}"`. Read a file line by line with `while IFS= read -r line; do …; done < file`. `until cond; do …; done` repeats until something becomes true — perfect for waiting on a service. `break` leaves the loop, `continue` skips to the next item. Never loop over `$(ls)` or `$(cat file)`.
</Callout>

## What is it?

A loop runs the same block of commands many times. Bash has three kinds:

| Loop | Repeats | Typical use |
| --- | --- | --- |
| `for` | Once per item in a list | Files, servers, numbers, array items |
| `while` | As long as a command succeeds | Reading lines, polling, counters |
| `until` | As long as a command **fails** | Waiting until something is ready |

All three share the same body syntax: `do … done`.

```bash
for name in alice bob carol; do
  echo "hello $name"
done
```

`name` is an ordinary variable. On each pass Bash puts the next word in it and runs the body.

## Why does it matter?

Automation is mostly "do this to every X": every server, every log file, every user, every container, every line of a CSV, every region. Without loops you would copy-paste commands — and forget one.

- **DevOps:** restart a service on 20 hosts, build images for every folder in `services/`, retry a flaky command.
- **Cloud:** run the same AWS CLI query in every region, tag every untagged instance.
- **Security:** check every user's shell, hash every file, scan a list of IPs, parse every line of `auth.log`.

## When and where do you use it?

- `for` — when you already have the list (files, names, numbers, array).
- `while read` — when data arrives line by line (a file, a command's output).
- `while true` / `until` — polling and waiting (health checks, deployments).
- C-style `for ((…))` — when you need an index or a counter.

## How does it work?

### for over a literal list, a range, and a glob

```bash
for env in dev staging prod; do echo "deploy to $env"; done

for i in {1..5}; do echo "attempt $i"; done            # 1 2 3 4 5
for i in {0..20..5}; do echo "$i"; done                 # 0 5 10 15 20
for i in $(seq 1 "$n"); do …; done                      # when the end is a variable

for f in /var/log/*.log; do
  [[ -e $f ]] || continue          # glob matched nothing → skip the literal pattern
  echo "$f: $(wc -l < "$f") lines"
done
```

Brace ranges like `{1..5}` are expanded **before** variables, so `{1..$n}` does not work — use `seq` or a C-style loop.

A glob like `*.log` returns real filenames, even ones with spaces, as separate items. That is why globs are safe and `$(ls)` is not.

### for over an array

```bash
servers=(web-1 web-2 "db primary")
for s in "${servers[@]}"; do      # quotes keep "db primary" as one item
  echo "checking $s"
done

for i in "${!servers[@]}"; do     # loop over indexes
  echo "$i → ${servers[$i]}"
done
```

### C-style for

```bash
for ((i = 1; i <= 3; i++)); do
  echo "retry $i of 3"
done
```

Inside `(( ))` you do not need `$` in front of variable names.

### while — repeat while a command succeeds

```bash
count=0
while (( count < 3 )); do
  echo "count is $count"
  ((count++))
done
```

### while read — the right way to process lines

```bash
while IFS= read -r line; do
  echo "got: $line"
done < servers.txt
```

Every part matters:

- `read` reads **one line** into `line` and fails at end of file, which ends the loop.
- `-r` keeps backslashes literally (without it `C:\temp` becomes `C:temp`).
- `IFS=` keeps leading and trailing spaces.
- `< servers.txt` feeds the file to the **whole loop**, not to each `read` separately.

Split lines into fields by setting `IFS` for the `read`:

```bash
# users.csv:  alice,admin,/bin/bash
while IFS=, read -r user role shell; do
  echo "$user is $role (uses $shell)"
done < users.csv

while IFS=: read -r user _ uid _ _ home shell; do     # /etc/passwd
  (( uid >= 1000 )) && echo "$user → $home"
done < /etc/passwd
```

`_` is a conventional "I do not care about this field" variable.

### Feeding command output into while — and the subshell trap

```bash
# Looks fine, but has a hidden problem:
total=0
cat sizes.txt | while read -r n; do ((total += n)); done
echo "$total"     # prints 0!
```

Each side of a pipe runs in a **subshell** — a copy of the shell. The loop changed `total` in the copy, which disappears when the pipe finishes. Fix with process substitution, which keeps the loop in the current shell:

```bash
total=0
while read -r n; do ((total += n)); done < <(cat sizes.txt)
echo "$total"     # correct
```

`< <(command)` means "read the loop's input from this command's output".

### until — repeat until success

```bash
until curl -fsS http://localhost:8080/health > /dev/null; do
  echo "waiting for app…"
  sleep 2
done
echo "app is up"
```

`until X` is exactly `while ! X`. Always add a limit so it cannot hang forever (see the real-world example).

### break and continue

```bash
for f in *.csv; do
  [[ -s $f ]] || continue            # skip empty files, go to the next one
  if grep -q "FATAL" "$f"; then
    echo "fatal entry in $f — stopping"
    break                            # leave the loop completely
  fi
  echo "processing $f"
done
```

`break 2` / `continue 2` act on the outer loop when loops are nested.

### Infinite loops on purpose

```bash
while true; do
  date; uptime
  sleep 60
done
```

Stop it with Ctrl+C. In real scripts, prefer systemd timers or cron over a script that never exits.

### One-liners

```bash
for h in web-1 web-2 web-3; do ssh "$h" uptime; done
for f in *.jpg; do mv -- "$f" "${f%.jpg}.jpeg"; done      # bulk rename
```

## Hands-on

```bash
mkdir -p ~/loop-lab && cd ~/loop-lab

# for over a list, a range and a stepped range
for env in dev staging prod; do echo "deploy → $env"; done
for i in {1..3}; do echo "attempt $i"; done
echo {0..20..5}
n=4; for i in $(seq 1 "$n"); do printf '%s ' "$i"; done; echo

# globs are safe with spaces, $(ls) is not
touch "my report.txt" notes.txt
echo "--- glob:";   for f in *.txt; do echo "[$f]"; done
echo "--- \$(ls):"; for f in $(ls *.txt); do echo "[$f]"; done

# empty glob guard
for f in *.nothing; do [[ -e $f ]] || { echo "no .nothing files"; continue; }; echo "$f"; done

# arrays and indexes
servers=(web-1 web-2 "db primary")
for s in "${servers[@]}"; do echo "check: $s"; done
for i in "${!servers[@]}"; do echo "$i = ${servers[$i]}"; done

# C-style
for ((i = 10; i > 0; i -= 3)); do printf '%s ' "$i"; done; echo

# while read with fields
printf 'alice,admin,/bin/bash\nbob,dev,/bin/zsh\n  carol  ,guest,/usr/sbin/nologin\n' > users.csv
while IFS=, read -r user role shell; do
  echo "user=[$user] role=$role shell=$shell"
done < users.csv

# the pipe/subshell trap and the fix
printf '10\n20\n30\n' > sizes.txt
total=0; cat sizes.txt | while read -r x; do ((total += x)); done; echo "pipe total: $total"
total=0; while read -r x; do ((total += x)); done < <(cat sizes.txt); echo "fixed total: $total"

# until with a limit
tries=0
until [[ -f ready.flag ]] || (( tries >= 3 )); do
  ((++tries)); echo "waiting… ($tries)"
  (( tries == 2 )) && touch ready.flag
done
[[ -f ready.flag ]] && echo "ready after $tries tries"

# break and continue
for i in {1..10}; do
  (( i % 2 == 0 )) && continue
  (( i > 7 )) && break
  printf 'odd:%s ' "$i"
done; echo

# bulk rename
touch a.jpg b.jpg
for f in *.jpg; do mv -- "$f" "${f%.jpg}.jpeg"; done
ls *.jpeg

cd ~ && rm -rf ~/loop-lab
```

## Real-world example

A deployment step that waits for the new version to become healthy — with a timeout, so a broken release fails the pipeline instead of hanging it:

```bash
#!/usr/bin/env bash
# wait-healthy.sh <url> [timeout-seconds]
set -euo pipefail

url="${1:?usage: wait-healthy.sh <url> [timeout]}"
timeout="${2:-60}"
deadline=$(( SECONDS + timeout ))     # SECONDS = seconds since the script started

until curl -fsS --max-time 3 "$url" > /dev/null 2>&1; do
  if (( SECONDS >= deadline )); then
    echo "✖ $url not healthy after ${timeout}s" >&2
    exit 1
  fi
  echo "… not ready yet, retrying in 3s"
  sleep 3
done
echo "✓ $url is healthy after ${SECONDS}s"
```

And a security sweep over every user account:

```bash
# Find accounts other than root with UID 0 and login-capable system accounts
while IFS=: read -r user _ uid _ _ _ shell; do
  if (( uid == 0 )) && [[ $user != root ]]; then
    echo "ALERT: $user has UID 0"
  fi
  if (( uid < 1000 && uid != 0 )) && [[ $shell != */nologin && $shell != /bin/false ]]; then
    echo "review: system user $user has shell $shell"
  fi
done < /etc/passwd
```

## Common mistakes

- **`for line in $(cat file)`** — splits on every space, not on lines, and expands `*`. Use `while IFS= read -r line`.
- **`for f in $(ls)`** — breaks on spaces in names. Use `for f in *`.
- **Unquoted `$f` in the body** — `rm $f` on `my report.txt` tries to delete two files. Always `"$f"`.
- **Expecting variables set inside `cmd | while …` to survive** — use `< <(cmd)`.
- **`{1..$n}`** — braces expand before variables. Use `seq` or `for ((…))`.
- **Polling loops without a timeout** — a pipeline can hang for hours.
- **A command inside a `while read` loop that reads stdin** (`ssh`, `ffmpeg`) eats the rest of the file. Give it `< /dev/null` or use `ssh -n`.
- **Missing the last line** of a file without a final newline: use `while IFS= read -r line || [[ -n $line ]]`.

## Security lens

<Callout type="security">
Loops multiply whatever a script does — including mistakes and attacks. One bad `rm` in a loop runs a thousand times.
</Callout>

- **Filenames are untrusted input:** a file can be named `-rf` or contain newlines. Use `--` before filenames (`rm -- "$f"`) and quote every variable.
- **Prefer `find … -print0 | while IFS= read -r -d '' f`** when walking directories others can write to — newline-safe.
- **Dry-run first:** write loops that `echo` the dangerous command, check the output, then remove the `echo`.
- **Rate-limit loops against remote systems:** a loop of API calls or SSH logins without `sleep` can trigger lockouts, rate limits or look like an attack.
- **Log-parsing loops** (`auth.log`, `access.log`) are a core blue-team skill: counting failed logins per IP is a `while read` loop away.

## Interview questions

<QA q="How do you read a file line by line in Bash, and why not use for line in $(cat file)?">
Use `while IFS= read -r line; do …; done < file`. read takes one line at a time, -r keeps backslashes, and IFS= keeps leading and trailing whitespace. A for loop over `$(cat file)` splits on all whitespace instead of newlines and also performs glob expansion, so lines with spaces or wildcards break.
</QA>

<QA q="Why is a variable modified inside cmd | while read … empty after the loop?">
Each part of a pipeline runs in a subshell, so the while loop works on a copy of the variables that disappears when the pipeline ends. Use process substitution, `while read …; done < <(cmd)`, to keep the loop in the current shell (or enable `shopt -s lastpipe` in non-interactive scripts).
</QA>

<QA q="What is the difference between while and until?">
while repeats as long as its condition command succeeds (exit status 0); until repeats as long as its condition fails and stops when it succeeds. until X is equivalent to while ! X. until is natural for waiting until something is ready.
</QA>

<QA q="How would you wait for a service to become healthy in a deployment script?">
Use an until loop that runs a health check such as curl -fsS on the health endpoint, sleeps a few seconds between attempts, and checks a deadline (for example using the SECONDS variable) so it exits with a non-zero status if the service is not healthy within the timeout.
</QA>

<QA q="What do break and continue do?">
continue skips the rest of the current iteration and moves to the next item; break leaves the loop entirely. Both accept a number to act on an outer loop when loops are nested, for example break 2.
</QA>

## Key terms

<Terms>
  <Term name="for loop">Runs the body once for each item in a list.</Term>
  <Term name="while loop">Repeats while a command succeeds.</Term>
  <Term name="until loop">Repeats while a command fails; stops on success.</Term>
  <Term name="while read">The standard pattern for processing input line by line.</Term>
  <Term name="IFS">Internal Field Separator; the characters used to split words and fields.</Term>
  <Term name="Subshell">A child copy of the shell; variable changes in it are lost.</Term>
  <Term name="Process substitution">`<(cmd)` — lets a command's output be read like a file.</Term>
  <Term name="break / continue">Leave the loop / skip to the next iteration.</Term>
</Terms>
