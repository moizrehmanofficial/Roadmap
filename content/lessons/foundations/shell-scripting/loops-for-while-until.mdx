<Callout type="tip" title="In one minute">
A **loop** repeats the same commands many times, so you write them once instead of copy-pasting. `for` repeats once **for each item** in a list (`for f in *.log`). `while` repeats **as long as** something is true. `until` repeats **until** something becomes true — great for waiting. `while IFS= read -r line` reads a file one line at a time. `break` stops a loop early; `continue` skips to the next round.
</Callout>

## Start from zero

### Doing the same thing again and again

<Callout type="analogy">
A teacher taking attendance does the same thing for every student: read the name, wait for "present", tick the register. She does not write separate instructions for each of 40 students — she follows **one** instruction: "**for each** student on the list, call the name and tick".

A tea maker waits by the stove: "**while** the water is not boiling, keep waiting". The moment it boils, he stops waiting.
</Callout>

Computers are perfect at this kind of repetitive work. A loop lets you say "do this for every file", "for every server", "for every line", "keep trying until it works" — in two or three lines.

Without a loop, restarting a service on 20 servers means writing 20 nearly identical lines — and forgetting one. With a loop, it is three lines, no matter whether there are 2 servers or 2,000.

### Words you need first

| Word | Simple meaning | Example |
| --- | --- | --- |
| **Loop** | Code that runs again and again | `for`, `while`, `until` |
| **Iteration** | One round of the loop | the 3rd time the body runs |
| **Body** | The commands that are repeated, between `do` and `done` | `echo "$name"` |
| **Loop variable** | A variable that holds the current item in each round | `name` in `for name in …` |
| **List** | The items a `for` loop goes through | `alice bob carol` |
| **Condition** | The yes/no check that decides whether `while`/`until` continues | `(( count < 3 ))` |
| **Infinite loop** | A loop that never stops on its own | `while true` |

## What is it?

A **loop** is a block of commands that Bash runs **repeatedly**. Bash has three loops:

| Loop | Repeats… | Real-life version |
| --- | --- | --- |
| `for` | once for **each item** in a list | "For each student, call the name" |
| `while` | **as long as** a condition is true | "While the shop is open, serve customers" |
| `until` | **until** a condition becomes true | "Until the water boils, keep waiting" |

All three use the same shape: the repeated commands go between `do` and `done`.

## Why does it matter?

Most automation is "do this to every X":

- **DevOps:** restart a service on every server, build every app in a folder, retry a command that sometimes fails.
- **Cloud:** run the same check in every region, tag every server that is missing a tag.
- **Security:** check every user account, scan every IP in a list, count failed logins in every line of a log.

Loops turn hours of manual work into one command — and they never forget an item.

## When and where do you use it?

| You have… | Use |
| --- | --- |
| A list of things already (files, names, numbers, an array) | `for` |
| A file or command output to process line by line | `while read` |
| Something to repeat while a condition stays true | `while` |
| Something to wait for (a server to start, a file to appear) | `until` |
| A need for a counter like 1, 2, 3… | `for` with a range, or C-style `for ((…))` |

You will see loops in backup scripts, deploy scripts, log analysis, server setup scripts, CI pipelines and security audits.

## Concepts one by one

### 1. `for` over a simple list

<Explain>
<What>
A loop that takes a list of words and runs its body once for each word. In each round, the current word is stored in a variable.
</What>
<Why>
To do the same job for several items without repeating the code.
</Why>
<When>
When you can write the list of items yourself, or it comes from a variable or array.
</When>
<Where>
Lists of environments (`dev staging prod`), servers, usernames, package names.
</Where>
<How>
`for VARIABLE in ITEM1 ITEM2 ITEM3; do COMMANDS; done`. Inside the body, use `"$VARIABLE"` to get the current item.
</How>
</Explain>

```bash
for name in Sam Emma Daniel; do
  echo "Hello, $name"
done
echo "Done greeting everyone"
```

```text output
Hello, Sam
Hello, Emma
Hello, Daniel
Done greeting everyone
```

Line by line:

- `for name in Sam Emma Daniel; do` — the list has three words, so the body will run three times. Each time, `name` holds the next word.
- `echo "Hello, $name"` — the body. Round 1: `name` is `Sam`; round 2: `Emma`; round 3: `Daniel`.
- `done` — end of the loop body.
- `echo "Done greeting everyone"` — after `done`, so it runs **once**, after the loop finishes.

### 2. `for` over numbers (ranges)

<Explain>
<What>
A `for` loop whose list is a sequence of numbers, written as a **range** like `{1..5}`.
</What>
<Why>
To repeat something a fixed number of times or to number things: attempts, days, file names like `backup-1`, `backup-2`.
</Why>
<When>
When you need "do this 5 times" or "for numbers from 1 to 10".
</When>
<Where>
Retry counters, creating numbered test files, checking ports in a range.
</Where>
<How>
`{START..END}` counts by 1, `{START..END..STEP}` counts by STEP. If the end is in a variable, use `$(seq 1 "$n")` instead, because `{1..$n}` does not work.
</How>
</Explain>

```bash
for i in {1..3}; do
  echo "Attempt number $i"
done

echo "Counting by 5:" {0..20..5}

n=4
for i in $(seq 1 "$n"); do
  echo "Creating file report-$i.txt"
done
```

```text output
Attempt number 1
Attempt number 2
Attempt number 3
Counting by 5: 0 5 10 15 20
Creating file report-1.txt
Creating file report-2.txt
Creating file report-3.txt
Creating file report-4.txt
```

- `{1..3}` — Bash expands it to `1 2 3` before the loop starts.
- `{0..20..5}` — from 0 to 20, jumping by 5.
- `seq 1 "$n"` — a command that prints the numbers 1 to n; `$(…)` puts that output into the list.

### 3. `for` over files (globs)

<Explain>
<What>
A `for` loop whose list is file names matched by a **glob** pattern such as `*.log` ("every name ending in .log").
</What>
<Why>
Processing every file of a kind is one of the most common jobs: compress logs, rename photos, check configs.
</Why>
<When>
Whenever you need to do something to many files in a folder.
</When>
<Where>
Log rotation, bulk renaming, backups, converting files.
</Where>
<How>
`for f in *.txt; do …; done`. The `*` is replaced by real file names — even names with spaces stay as one item. Always quote the variable: `"$f"`.
</How>
</Explain>

```bash
touch "my report.txt" notes.txt todo.txt

for f in *.txt; do
  echo "Found file: [$f]"
done
```

```text output
Found file: [my report.txt]
Found file: [notes.txt]
Found file: [todo.txt]
```

- `touch` creates three empty files, one with a space in its name.
- `*.txt` matches all three. `my report.txt` stays **one** item — that is why globs are the safe way to loop over files.
- The square brackets in the `echo` only make it easy to see where each name starts and ends.

<Callout type="warning" title="Never loop over $(ls)">
`for f in $(ls)` splits names at spaces, so `my report.txt` becomes two items: `my` and `report.txt`. Use `for f in *` instead.
</Callout>

If a pattern matches **no** files, Bash leaves the pattern itself as the item (`*.nothing`). Guard against it:

```bash
for f in *.nothing; do
  [[ -e $f ]] || { echo "No .nothing files here"; continue; }
  echo "Processing $f"
done
```

```text output
No .nothing files here
```

### 4. `for` over an array

<Explain>
<What>
Looping over the items stored in an **array** (a variable that holds a list).
</What>
<Why>
Arrays keep each item separate even if it contains spaces, so they are the safest way to store and loop over lists.
</Why>
<When>
When your list is built up in the script or comes from configuration.
</When>
<Where>
Lists of servers, regions, packages to install, files to back up.
</Where>
<How>
`for item in "${array[@]}"` — the quotes and `[@]` are both needed to keep every item intact. Use `"${!array[@]}"` to loop over the positions (0, 1, 2…).
</How>
</Explain>

```bash
servers=(web-1 web-2 "db primary")

for s in "${servers[@]}"; do
  echo "Checking server: $s"
done

for i in "${!servers[@]}"; do
  echo "Position $i holds ${servers[$i]}"
done
```

```text output
Checking server: web-1
Checking server: web-2
Checking server: db primary
Position 0 holds web-1
Position 1 holds web-2
Position 2 holds db primary
```

### 5. C-style `for` — counting with a start, a check and a step

<Explain>
<What>
A `for` loop written like in C, Java or JavaScript: a starting value, a condition to keep going, and a step.
</What>
<Why>
Gives full control over counting: count down, jump by 3, stop at a number held in a variable.
</Why>
<When>
When you need an index or unusual counting.
</When>
<Where>
Countdowns, retry loops, loops over positions in an array.
</Where>
<How>
`for (( START; CONDITION; STEP )); do …; done`. Inside `(( ))`, variable names do not need `$`.
</How>
</Explain>

```bash
for ((i = 3; i >= 1; i--)); do
  echo "Launching in $i…"
done
echo "Go!"
```

```text output
Launching in 3…
Launching in 2…
Launching in 1…
Go!
```

- `i = 3` — start at 3.
- `i >= 1` — keep going while `i` is at least 1.
- `i--` — after each round, subtract 1.

### 6. `while` — repeat as long as something is true

<Explain>
<What>
A loop that checks a condition **before every round**. If it is true, the body runs; if false, the loop ends.
</What>
<Why>
For repetition where you do not know the number of rounds in advance — you only know when to stop.
</Why>
<When>
Counting up to a limit, polling, keep processing while there is data.
</When>
<Where>
Monitoring scripts, retry logic, reading input.
</Where>
<How>
`while CONDITION; do COMMANDS; done`. Make sure something in the body eventually makes the condition false, or the loop never ends.
</How>
</Explain>

```bash
count=1
while (( count <= 3 )); do
  echo "Round $count"
  ((count++))
done
echo "Finished with count = $count"
```

```text output
Round 1
Round 2
Round 3
Finished with count = 4
```

- `(( count <= 3 ))` — checked before each round.
- `((count++))` — add 1 to `count`. Without this line the loop would run forever.
- After round 3, `count` becomes 4, the check fails, and the loop ends.

### 7. Reading a file line by line: `while read`

<Explain>
<What>
The standard way to process text one line at a time: `while IFS= read -r line; do …; done < file`.
</What>
<Why>
Log files, CSV exports, lists of hosts and config files are all line-based. You need each line as a separate piece.
</Why>
<When>
Whenever data comes as lines — from a file or from a command's output.
</When>
<Where>
Log analysis, importing users from a CSV, running a command for every host in a list.
</Where>
<How>
`read` reads **one** line into a variable and fails at the end of the file, which ends the loop. `< file` at the end feeds the file into the loop. `-r` and `IFS=` keep the line exactly as it is.
</How>
</Explain>

```bash
printf 'web-1\nweb-2\ndb-1\n' > hosts.txt

while IFS= read -r host; do
  echo "Connecting to $host"
done < hosts.txt
```

```text output
Connecting to web-1
Connecting to web-2
Connecting to db-1
```

Every part explained:

- `printf … > hosts.txt` — create a file with three lines (`\n` means "new line").
- `while … read -r host` — read the next line into `host`. When there are no more lines, `read` fails and the loop stops.
- `IFS=` — keep spaces at the start and end of the line.
- `-r` — keep backslashes as they are (otherwise `C:\temp` becomes `C:temp`).
- `done < hosts.txt` — the whole loop reads from `hosts.txt`.

**Splitting each line into fields** — set `IFS` to the separator:

```bash
printf 'alice,admin,Chicago\nbob,developer,Houston\n' > users.csv

while IFS=, read -r user role city; do
  echo "$user works as $role in $city"
done < users.csv
```

```text output
alice works as admin in Chicago
bob works as developer in Houston
```

`IFS=,` tells `read` to split at commas: the first part goes into `user`, the second into `role`, the rest into `city`.

<Callout type="warning" title="Do not use for line in $(cat file)">
`for` splits on **every space**, not on lines — a line "John Smith" becomes two items. Always use `while IFS= read -r line`.
</Callout>

### 8. The pipe trap: variables lost after `| while`

<Explain>
<What>
When you send output into a loop with a pipe (`command | while read …`), the loop runs in a **copy** of the shell (a subshell). Changes to variables inside it are thrown away when it ends.
</What>
<Why>
This is one of the most confusing Bash bugs: the total you calculated inside the loop is 0 afterwards.
</Why>
<When>
Whenever you count or collect something inside a piped loop and need it after the loop.
</When>
<Where>
Summing sizes, counting matches, building lists from command output.
</Where>
<How>
Instead of `cmd | while …; done`, write `while …; done < <(cmd)`. The `< <(…)` form keeps the loop in the main shell.
</How>
</Explain>

```bash
printf '10\n20\n30\n' > numbers.txt

total=0
cat numbers.txt | while read -r n; do ((total += n)); done
echo "With a pipe, total = $total"

total=0
while read -r n; do ((total += n)); done < <(cat numbers.txt)
echo "With < <(…), total = $total"
```

```text output
With a pipe, total = 0
With < <(…), total = 60
```

<Callout type="analogy">
The pipe gives the loop a **photocopy** of your notebook. It writes the total on the photocopy, which is thrown away at the end. `< <(…)` lets the loop write in your **real** notebook.
</Callout>

### 9. `until` — repeat until something becomes true

<Explain>
<What>
The opposite of `while`: it keeps looping **as long as the condition is false**, and stops as soon as it becomes true.
</What>
<Why>
Perfect for waiting: "until the server answers", "until the file exists", "until the database is ready".
</Why>
<When>
In deployments and startup scripts, where one step must wait for another.
</When>
<Where>
Docker entrypoints waiting for a database, CI pipelines waiting for a deployment, scripts waiting for a lock file to disappear.
</Where>
<How>
`until CONDITION; do COMMANDS; done`. Always add a limit (a maximum number of tries or a time limit) so it cannot wait forever.
</How>
</Explain>

```bash
tries=0
until [[ -f ready.flag ]] || (( tries >= 5 )); do
  ((++tries))
  echo "Waiting for ready.flag… (try $tries)"
  (( tries == 3 )) && touch ready.flag     # simulate: the file appears on try 3
done

if [[ -f ready.flag ]]; then
  echo "Ready after $tries tries"
else
  echo "Gave up after $tries tries"
fi
```

```text output
Waiting for ready.flag… (try 1)
Waiting for ready.flag… (try 2)
Waiting for ready.flag… (try 3)
Ready after 3 tries
```

- The loop continues while **neither** "the file exists" **nor** "we tried 5 times" is true.
- On try 3 we create the file (in real life, another program would create it), so the next check is true and the loop stops.
- The `|| (( tries >= 5 ))` part is the safety limit.

### 10. `break` and `continue`

<Explain>
<What>
Two commands that change the normal flow inside a loop. `continue` skips the rest of the current round and jumps to the next one. `break` leaves the loop completely.
</What>
<Why>
To skip items you do not care about (empty files, comments) or to stop early once you found what you need or hit a serious problem.
</Why>
<When>
Inside any `for`, `while` or `until` loop, usually inside an `if`.
</When>
<Where>
Skipping blank lines in a file, stopping a search at the first match, stopping a batch on a fatal error.
</Where>
<How>
Write `continue` or `break` on its own. In nested loops, `break 2` leaves two loops at once.
</How>
</Explain>

<Callout type="analogy">
Checking exam papers: if a paper is blank, you **skip** it and pick up the next one (`continue`). If you find someone cheating, you **stop** checking and report it (`break`).
</Callout>

```bash
for i in {1..10}; do
  if (( i % 2 == 0 )); then
    continue                 # even number: skip to the next round
  fi
  if (( i > 7 )); then
    break                    # bigger than 7: stop the loop
  fi
  echo "Odd number: $i"
done
echo "Loop finished"
```

```text output
Odd number: 1
Odd number: 3
Odd number: 5
Odd number: 7
Loop finished
```

- `i % 2 == 0` — `%` gives the remainder of dividing by 2; remainder 0 means even.
- For 2, 4, 6, 8 → `continue` jumps straight to the next number.
- For 9 → `break` ends the loop; 10 is never checked.

### 11. Loops that run forever (on purpose)

<Explain>
<What>
`while true; do …; done` — a loop whose condition is always true.
</What>
<Why>
For simple watchers that repeat a check every few seconds until you stop them.
</Why>
<When>
Quick monitoring in a terminal. For permanent jobs, use cron or a systemd timer instead.
</When>
<Where>
Watching a log, printing server load every minute while debugging.
</Where>
<How>
Always put a `sleep` inside so it does not use 100% CPU. Stop it with Ctrl+C.
</How>
</Explain>

```bash
while true; do
  date +%T
  uptime
  sleep 60
done
```

(This runs until you press Ctrl+C, so it has no fixed output.)

## Real-world example

A deployment step that waits for the new version to become healthy — with a timeout, so a broken release fails the pipeline instead of hanging it:

```bash
#!/usr/bin/env bash
# wait-healthy.sh <url> [timeout-seconds]
set -euo pipefail

url="${1:?usage: wait-healthy.sh <url> [timeout]}"
timeout="${2:-60}"
deadline=$(( SECONDS + timeout ))     # SECONDS = seconds since the script started

until curl -fsS --max-time 3 "$url" > /dev/null 2>&1; do
  if (( SECONDS >= deadline )); then
    echo "✖ $url not healthy after ${timeout}s" >&2
    exit 1
  fi
  echo "… not ready yet, retrying in 3s"
  sleep 3
done
echo "✓ $url is healthy after ${SECONDS}s"
```

And a security sweep over every user account:

```bash
# Find accounts other than root with UID 0 and login-capable system accounts
while IFS=: read -r user _ uid _ _ _ shell; do
  if (( uid == 0 )) && [[ $user != root ]]; then
    echo "ALERT: $user has UID 0"
  fi
  if (( uid < 1000 && uid != 0 )) && [[ $shell != */nologin && $shell != /bin/false ]]; then
    echo "review: system user $user has shell $shell"
  fi
done < /etc/passwd
```

## Common mistakes

- **`for line in $(cat file)`** — splits on every space, not on lines, and expands `*`. Use `while IFS= read -r line`.
- **`for f in $(ls)`** — breaks on spaces in names. Use `for f in *`.
- **Unquoted `$f` in the body** — `rm $f` on `my report.txt` tries to delete two files. Always `"$f"`.
- **Expecting variables set inside `cmd | while …` to survive** — use `< <(cmd)`.
- **`{1..$n}`** — braces expand before variables. Use `seq` or `for ((…))`.
- **Polling loops without a timeout** — a pipeline can hang for hours.
- **A command inside a `while read` loop that reads stdin** (`ssh`, `ffmpeg`) eats the rest of the file. Give it `< /dev/null` or use `ssh -n`.
- **Missing the last line** of a file without a final newline: use `while IFS= read -r line || [[ -n $line ]]`.

## Security lens

<Callout type="security">
Loops multiply whatever a script does — including mistakes and attacks. One bad `rm` in a loop runs a thousand times.
</Callout>

- **Filenames are untrusted input:** a file can be named `-rf` or contain newlines. Use `--` before filenames (`rm -- "$f"`) and quote every variable.
- **Prefer `find … -print0 | while IFS= read -r -d '' f`** when walking directories others can write to — newline-safe.
- **Dry-run first:** write loops that `echo` the dangerous command, check the output, then remove the `echo`.
- **Rate-limit loops against remote systems:** a loop of API calls or SSH logins without `sleep` can trigger lockouts, rate limits or look like an attack.
- **Log-parsing loops** (`auth.log`, `access.log`) are a core blue-team skill: counting failed logins per IP is a `while read` loop away.

## Interview questions

<QA q="How do you read a file line by line in Bash, and why not use for line in $(cat file)?">
Use `while IFS= read -r line; do …; done < file`. read takes one line at a time, -r keeps backslashes, and IFS= keeps leading and trailing whitespace. A for loop over `$(cat file)` splits on all whitespace instead of newlines and also performs glob expansion, so lines with spaces or wildcards break.
</QA>

<QA q="Why is a variable modified inside cmd | while read … empty after the loop?">
Each part of a pipeline runs in a subshell, so the while loop works on a copy of the variables that disappears when the pipeline ends. Use process substitution, `while read …; done < <(cmd)`, to keep the loop in the current shell (or enable `shopt -s lastpipe` in non-interactive scripts).
</QA>

<QA q="What is the difference between while and until?">
while repeats as long as its condition command succeeds (exit status 0); until repeats as long as its condition fails and stops when it succeeds. until X is equivalent to while ! X. until is natural for waiting until something is ready.
</QA>

<QA q="How would you wait for a service to become healthy in a deployment script?">
Use an until loop that runs a health check such as curl -fsS on the health endpoint, sleeps a few seconds between attempts, and checks a deadline (for example using the SECONDS variable) so it exits with a non-zero status if the service is not healthy within the timeout.
</QA>

<QA q="What do break and continue do?">
continue skips the rest of the current iteration and moves to the next item; break leaves the loop entirely. Both accept a number to act on an outer loop when loops are nested, for example break 2.
</QA>

## Key terms

<Terms>
  <Term name="for loop">Runs the body once for each item in a list.</Term>
  <Term name="while loop">Repeats while a command succeeds.</Term>
  <Term name="until loop">Repeats while a command fails; stops on success.</Term>
  <Term name="while read">The standard pattern for processing input line by line.</Term>
  <Term name="IFS">Internal Field Separator; the characters used to split words and fields.</Term>
  <Term name="Subshell">A child copy of the shell; variable changes in it are lost.</Term>
  <Term name="Process substitution">`<(cmd)` — lets a command's output be read like a file.</Term>
  <Term name="break / continue">Leave the loop / skip to the next iteration.</Term>
</Terms>
