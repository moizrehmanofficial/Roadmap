<BigIdea>
<Tr>
<En>
A **loop** repeats the same commands many times, so you write them **once**. `for` does it **for each item** in a list, `while` does it **as long as** something is true, and `until` does it **until** something becomes true. Restarting a service on 2 servers or 2,000 takes the same three lines.
</En>
<Ur>
**Loop** wahi commands baar baar chalata hai, taa ke aap unhe **ek dafa** likhein. `for` list ki **har cheez ke liye** chalata hai, `while` **jab tak** kuch sach ho, aur `until` **jab tak** kuch sach na ho jaye. 2 servers par service restart karni ho ya 2,000 par, wahi teen lines lagti hain.
</Ur>
</Tr>
</BigIdea>

## At a glance

<Glance>
<What>
<Tr>
<En>

| Loop | Repeats… | Real-life version |
| --- | --- | --- |
| `for` | once for **each item** in a list | "For each student, call the name" |
| `while` | **as long as** a condition is true | "While the shop is open, serve customers" |
| `until` | **until** a condition becomes true | "Until the water boils, keep waiting" |

All three put the repeated commands between `do` and `done`.

</En>
<Ur>

| Loop | Kab tak dohrata hai | Asal zindagi me |
| --- | --- | --- |
| `for` | list ki **har cheez** ke liye ek dafa | "Har student ka naam pukaro" |
| `while` | **jab tak** shart sach ho | "Jab tak dukaan khuli hai, gahakon ko do" |
| `until` | **jab tak** shart sach na ho jaye | "Jab tak paani na uble, intezar karo" |

Teeno dohrayi jane wali commands `do` aur `done` ke darmiyan rakhte hain.

</Ur>
</Tr>
</What>
<Why>
<Tr>
<En>

Most automation is "do this to **every** X":

- **DevOps:** restart a service on every server, retry a command that sometimes fails.
- **Cloud:** run the same check in every region.
- **Security:** check every user account, count failed logins in every log line.

Loops turn hours of manual work into one command, and they **never forget** an item.

</En>
<Ur>

Zyada tar automation "**har** X ke saath ye karo" hai:

- **DevOps:** har server par service restart, kabhi kabhi fail hone wali command dobara chalana.
- **Cloud:** har region me wahi check.
- **Security:** har user account check karna, har log line me fail logins ginna.

Loops ghanton ka haath ka kaam ek command bana dete hain, aur koi cheez **kabhi nahi bhoolte**.

</Ur>
</Tr>
</Why>
<When>
<Tr>
<En>

| You have… | Use |
| --- | --- |
| A list already (files, names, an array) | `for` |
| A file or command output, line by line | `while read` |
| Something to repeat while a condition stays true | `while` |
| Something to **wait** for (server starting, file appearing) | `until` |
| A counter 1, 2, 3… | `for` with a range, or `for ((…))` |

</En>
<Ur>

| Aap ke paas… | Istemal |
| --- | --- |
| Pehle se list (files, naam, array) | `for` |
| File ya command ka output, line ba line | `while read` |
| Kuch dohrana jab tak shart sach rahe | `while` |
| Kisi cheez ka **intezar** (server shuru hona, file aana) | `until` |
| Counter 1, 2, 3… | range wala `for`, ya `for ((…))` |

</Ur>
</Tr>
</When>
<How>
<Tr>
<En>

Two control words work inside any loop:

- `continue` = skip to the **next** round
- `break` = **leave** the loop

</En>
<Ur>

Do control alfaz har loop ke andar kaam karte hain:

- `continue` = **agle** round par jao
- `break` = loop se **bahar** niklo

</Ur>
</Tr>
</How>
</Glance>

## Picture it

<Tr>
<En>

A **teacher taking attendance** does the same thing for every student: read the name, wait for "present", tick the register. She doesn't write 40 separate instructions; she follows **one**: "**for each** student on the list, call the name and tick". That's `for`.

Someone waiting by a kettle: "**while** the water isn't boiling, keep waiting". The moment it boils, they stop. That's `while` (or `until`).

</En>
<Ur>

**Haazri lene wali teacher** har student ke saath ek hi kaam karti hai: naam parhna, "haazir" ka intezar, register me nishan. Wo 40 alag hidayat nahi likhti; **ek** par chalti hai: "list ke **har** student ka naam pukaro aur nishan lagao". Yahi `for` hai.

Ketli ke paas intezar karta koi shakhs: "**jab tak** paani na uble, intezar karo". Ubalte hi ruk jata hai. Yahi `while` (ya `until`) hai.

</Ur>
</Tr>

## Words you'll see

<Tr>
<En>

| Word | What it means | Example |
| --- | --- | --- |
| **Iteration** | One round of the loop | the 3rd time the body runs |
| **Body** | The repeated commands, between `do` and `done` | `echo "$name"` |
| **Loop variable** | Holds the current item in each round | `name` in `for name in …` |
| **Condition** | The yes/no check for `while`/`until` | `(( count < 3 ))` |
| **Infinite loop** | A loop that never stops by itself | `while true` |

</En>
<Ur>

| Lafz | Matlab | Misaal |
| --- | --- | --- |
| **Iteration** | Loop ka ek round | body ka teesri dafa chalna |
| **Body** | Dohrayi jane wali commands, `do` aur `done` ke darmiyan | `echo "$name"` |
| **Loop variable** | Har round me mojooda cheez rakhta hai | `for name in …` me `name` |
| **Condition** | `while`/`until` ke liye haan/nahi check | `(( count < 3 ))` |
| **Infinite loop** | Loop jo khud kabhi nahi rukta | `while true` |

</Ur>
</Tr>

## Learn it step by step

<Walkthrough>

<Step title="for over a simple list">

<Tr>
<En>

`for VARIABLE in ITEM1 ITEM2 ITEM3; do COMMANDS; done`. In each round, the variable holds the next item. Use `"$VARIABLE"` inside the body.

</En>
<Ur>

`for VARIABLE in ITEM1 ITEM2 ITEM3; do COMMANDS; done`. Har round me variable agli cheez rakhta hai. Body ke andar `"$VARIABLE"` istemal karein.

</Ur>
</Tr>

```bash
for name in Sam Emma Daniel; do
  echo "Hello, $name"
done
echo "Done greeting everyone"
```

```text output
Hello, Sam
Hello, Emma
Hello, Daniel
Done greeting everyone
```

<Happened>
<Tr>
<En>Three words, so the body ran three times: `name` was Sam, then Emma, then Daniel. The last `echo` is after `done`, so it ran **once**, at the end.</En>
<Ur>Teen alfaz, isliye body teen dafa chali: `name` pehle Sam, phir Emma, phir Daniel. Aakhri `echo` `done` ke baad hai, isliye aakhir me **ek dafa** chala.</Ur>
</Tr>
</Happened>

</Step>

<Step title="for over numbers">

<Tr>
<En>

- `{1..5}` counts 1 to 5
- `{0..20..5}` counts by 5
- If the end number is in a variable, use `$(seq 1 "$n")`, because `{1..$n}` **doesn't work** (braces are expanded before variables).

</En>
<Ur>

- `{1..5}` 1 se 5 tak ginta hai
- `{0..20..5}` 5 ke faasle se ginta hai
- Agar aakhri number variable me ho to `$(seq 1 "$n")` istemal karein, kyun ke `{1..$n}` **kaam nahi karta** (braces variables se pehle phailte hain).

</Ur>
</Tr>

```bash
for i in {1..3}; do
  echo "Attempt number $i"
done

echo "Counting by 5:" {0..20..5}

n=4
for i in $(seq 1 "$n"); do
  echo "Creating file report-$i.txt"
done
```

```text output
Attempt number 1
Attempt number 2
Attempt number 3
Counting by 5: 0 5 10 15 20
Creating file report-1.txt
Creating file report-2.txt
Creating file report-3.txt
Creating file report-4.txt
```

</Step>

<Step title="for over files">

<Tr>
<En>

`for f in *.txt` loops over every matching file. Names **with spaces stay as one item**, so this is the safe way to loop over files. Always quote: `"$f"`.

</En>
<Ur>

`for f in *.txt` har milti file par loop chalata hai. **Spaces wale naam ek hi cheez rehte hain**, isliye files par loop ka yahi mehfooz tareeqa hai. Hamesha quotes: `"$f"`.

</Ur>
</Tr>

```bash
touch "my report.txt" notes.txt todo.txt

for f in *.txt; do
  echo "Found file: [$f]"
done
```

```text output
Found file: [my report.txt]
Found file: [notes.txt]
Found file: [todo.txt]
```

<Callout type="warning" title="Never loop over $(ls)">
<Tr>
<En>`for f in $(ls)` splits names at spaces, so `my report.txt` becomes two items: `my` and `report.txt`. Use `for f in *` instead.</En>
<Ur>`for f in $(ls)` naamon ko spaces par tor deta hai, isliye `my report.txt` do cheezen ban jati hai: `my` aur `report.txt`. Is ki jagah `for f in *` istemal karein.</Ur>
</Tr>
</Callout>

<Tr>
<En>If the pattern matches **no** files, Bash gives you the pattern itself (`*.nothing`) as the item. Guard against it:</En>
<Ur>Agar pattern **kisi** file se na mile, to Bash khud pattern (`*.nothing`) ko cheez bana deta hai. Is se bachein:</Ur>
</Tr>

```bash
for f in *.nothing; do
  [[ -e $f ]] || { echo "No .nothing files here"; continue; }
  echo "Processing $f"
done
```

```text output
No .nothing files here
```

</Step>

<Step title="for over an array">

<Tr>
<En>`for item in "${array[@]}"` (both the quotes and `[@]` are needed). For positions, loop over `"${!array[@]}"`.</En>
<Ur>`for item in "${array[@]}"` (quotes aur `[@]` dono zaroori). Jagahon ke liye `"${!array[@]}"` par loop chalayen.</Ur>
</Tr>

```bash
servers=(web-1 web-2 "db primary")

for s in "${servers[@]}"; do
  echo "Checking server: $s"
done

for i in "${!servers[@]}"; do
  echo "Position $i holds ${servers[$i]}"
done
```

```text output
Checking server: web-1
Checking server: web-2
Checking server: db primary
Position 0 holds web-1
Position 1 holds web-2
Position 2 holds db primary
```

</Step>

<Step title="C-style for: start, check, step">

<Tr>
<En>

`for (( START; CONDITION; STEP ))`, like in JavaScript or Java. Full control: count down, jump by 3, stop at a number in a variable.

</En>
<Ur>

`for (( START; CONDITION; STEP ))`, JavaScript ya Java ki tarah. Poora ikhtiyar: ulta gino, 3 ke faasle se, variable me rakhe number par ruko.

</Ur>
</Tr>

```bash
for ((i = 3; i >= 1; i--)); do
  echo "Launching in $i…"
done
echo "Go!"
```

```text output
Launching in 3…
Launching in 2…
Launching in 1…
Go!
```

<Happened>
<Tr>
<En>Start at 3; keep going while `i >= 1`; after each round, `i--` subtracts 1.</En>
<Ur>3 se shuru; jab tak `i >= 1` chalte raho; har round ke baad `i--` 1 ghatata hai.</Ur>
</Tr>
</Happened>

</Step>

<Step title="while: repeat as long as something is true">

<Tr>
<En>

`while` checks the condition **before every round**. Use it when you don't know how many rounds there will be, only when to stop. Make sure something in the body eventually makes the condition **false**, or it never ends.

</En>
<Ur>

`while` **har round se pehle** shart check karta hai. Ise tab istemal karein jab pata na ho kitne round honge, sirf ye ke kab rukna hai. Yaqeeni banayen ke body me kuch aakhir kaar shart ko **jhoot** kar de, warna ye kabhi khatam nahi hoga.

</Ur>
</Tr>

```bash
count=1
while (( count <= 3 )); do
  echo "Round $count"
  ((count++))
done
echo "Finished with count = $count"
```

```text output
Round 1
Round 2
Round 3
Finished with count = 4
```

<Happened>
<Tr>
<En>`((count++))` adds 1 each round. After round 3, `count` is 4, the check `4 <= 3` fails, and the loop ends. Without that line, it would run **forever**.</En>
<Ur>`((count++))` har round 1 jorta hai. Round 3 ke baad `count` 4 hai, check `4 <= 3` fail hota hai, aur loop khatam. Us line ke baghair ye **hamesha** chalta rehta.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Read a file line by line: while read">

<Tr>
<En>

The standard pattern: `while IFS= read -r line; do …; done < file`

- `read` reads **one** line; at the end of the file it fails, which ends the loop.
- `IFS=` keeps spaces at the start and end of the line.
- `-r` keeps backslashes (otherwise `C:\temp` becomes `C:temp`).
- `< file` after `done` feeds the file into the loop.

</En>
<Ur>

Mayari tareeqa: `while IFS= read -r line; do …; done < file`

- `read` **ek** line parhta hai; file ke aakhir par fail hota hai, jis se loop khatam hota hai.
- `IFS=` line ke shuru aur aakhir ki spaces rakhta hai.
- `-r` backslashes rakhta hai (warna `C:\temp` `C:temp` ban jata hai).
- `done` ke baad `< file` file ko loop me daalta hai.

</Ur>
</Tr>

```bash
printf 'web-1\nweb-2\ndb-1\n' > hosts.txt

while IFS= read -r host; do
  echo "Connecting to $host"
done < hosts.txt
```

```text output
Connecting to web-1
Connecting to web-2
Connecting to db-1
```

<Tr>
<En>**Split each line into fields** by setting `IFS` to the separator: `IFS=,` splits at commas, filling `user`, `role` and `city`.</En>
<Ur>`IFS` ko separator bana kar **har line ko hisson me todein**: `IFS=,` commas par torta hai, aur `user`, `role` aur `city` bharta hai.</Ur>
</Tr>

```bash
printf 'alice,admin,Chicago\nbob,developer,Houston\n' > users.csv

while IFS=, read -r user role city; do
  echo "$user works as $role in $city"
done < users.csv
```

```text output
alice works as admin in Chicago
bob works as developer in Houston
```

<Callout type="warning" title="Don't use for line in $(cat file)">
<Tr>
<En>`for` splits on **every space**, not on lines, so a line "John Smith" becomes two items. Always use `while IFS= read -r line`.</En>
<Ur>`for` **har space** par torta hai, lines par nahi, isliye "John Smith" wali line do cheezen ban jati hai. Hamesha `while IFS= read -r line` istemal karein.</Ur>
</Tr>
</Callout>

</Step>

<Step title="The pipe trap: variables lost after | while">

<Tr>
<En>

When you send output into a loop with a pipe (`command | while read …`), the loop runs in a **copy** of the shell. Changes to variables inside it are **thrown away** when it ends, so your total is 0 afterwards.

It's like the pipe gives the loop a **photocopy** of your notebook: it writes the total on the photocopy, which is thrown away. The fix, `while …; done < <(cmd)`, lets it write in your **real** notebook.

</En>
<Ur>

Jab aap pipe se output loop me bhejte hain (`command | while read …`), to loop shell ki ek **copy** me chalta hai. Andar variables ki tabdeeliyan khatam hone par **phaink** di jati hain, isliye baad me aap ka total 0 hota hai.

Jaise pipe loop ko aap ki notebook ki **photocopy** deta hai: wo total photocopy par likhta hai, jo phaink di jati hai. Hal, `while …; done < <(cmd)`, use aap ki **asli** notebook me likhne deta hai.

</Ur>
</Tr>

```bash
printf '10\n20\n30\n' > numbers.txt

total=0
cat numbers.txt | while read -r n; do ((total += n)); done
echo "With a pipe, total = $total"

total=0
while read -r n; do ((total += n)); done < <(cat numbers.txt)
echo "With < <(…), total = $total"
```

```text output
With a pipe, total = 0
With < <(…), total = 60
```

</Step>

<Step title="until: wait until something is true">

<Tr>
<En>

`until` keeps looping **while the condition is false** and stops as soon as it's true. Perfect for **waiting**: "until the server answers", "until the database is ready". **Always add a limit** (max tries or a deadline) so it can't wait forever.

</En>
<Ur>

`until` **jab tak shart jhoot ho** chalta rehta hai aur sach hote hi ruk jata hai. **Intezar** ke liye behtareen: "jab tak server jawab na de", "jab tak database tayyar na ho". **Hamesha had lagayen** (zyada se zyada koshishen ya deadline) taa ke ye hamesha intezar na kare.

</Ur>
</Tr>

```bash
tries=0
until [[ -f ready.flag ]] || (( tries >= 5 )); do
  ((++tries))
  echo "Waiting for ready.flag… (try $tries)"
  (( tries == 3 )) && touch ready.flag     # simulate: the file appears on try 3
done

if [[ -f ready.flag ]]; then
  echo "Ready after $tries tries"
else
  echo "Gave up after $tries tries"
fi
```

```text output
Waiting for ready.flag… (try 1)
Waiting for ready.flag… (try 2)
Waiting for ready.flag… (try 3)
Ready after 3 tries
```

<Happened>
<Tr>
<En>The loop continued while **neither** "the file exists" **nor** "we tried 5 times" was true. On try 3 we created the file (in real life another program would), so the next check was true and the loop stopped. `|| (( tries >= 5 ))` is the safety limit.</En>
<Ur>Loop tab tak chala jab tak "file mojood hai" **aur** "5 dafa koshish ho chuki" me se **koi** sach nahi tha. Koshish 3 par hum ne file banayi (asal me koi aur program banata), isliye agla check sach hua aur loop ruk gaya. `|| (( tries >= 5 ))` hifazati had hai.</Ur>
</Tr>
</Happened>

</Step>

<Step title="break and continue">

<Tr>
<En>

Checking exam papers: if a paper is blank, you **skip** it and pick up the next one (`continue`). If you find someone cheating, you **stop** checking and report it (`break`). In nested loops, `break 2` leaves two loops at once.

</En>
<Ur>

Imtihaan ke parche check karna: parcha khaali ho to use **chhor** kar agla uthao (`continue`). Kisi ko nakal karte pakro to check karna **band** karo aur report karo (`break`). Loops ke andar loops me `break 2` ek saath do loops se bahar nikalta hai.

</Ur>
</Tr>

```bash
for i in {1..10}; do
  if (( i % 2 == 0 )); then
    continue                 # even number: skip to the next round
  fi
  if (( i > 7 )); then
    break                    # bigger than 7: stop the loop
  fi
  echo "Odd number: $i"
done
echo "Loop finished"
```

```text output
Odd number: 1
Odd number: 3
Odd number: 5
Odd number: 7
Loop finished
```

<Happened>
<Tr>
<En>`i % 2 == 0` means "even". For 2, 4, 6, 8, `continue` jumped to the next number. At 9, `break` ended the loop; 10 was never checked.</En>
<Ur>`i % 2 == 0` ka matlab "jufta". 2, 4, 6, 8 par `continue` agle number par le gaya. 9 par `break` ne loop khatam kiya; 10 kabhi check nahi hua.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Loops that run forever, on purpose">

<Tr>
<En>

`while true; do …; done` repeats until you press **Ctrl+C**. Good for a quick watcher in a terminal. **Always add `sleep`** so it doesn't use 100% CPU. For permanent jobs, use cron or a systemd timer instead.

</En>
<Ur>

`while true; do …; done` tab tak dohrata hai jab tak aap **Ctrl+C** na dabayen. Terminal me jaldi ki nigrani ke liye achha. **Hamesha `sleep` lagayen** taa ke ye 100% CPU na le. Mustaqil kaamon ke liye cron ya systemd timer istemal karein.

</Ur>
</Tr>

```text
while true; do
  date +%T
  uptime
  sleep 60
done
```

</Step>

</Walkthrough>

## Common mistakes

<Compare>
<Bad title="{1..$n}">

```text
n=5; for i in {1..$n}; do …   # prints {1..5} once
```

</Bad>
<Good title="seq or C-style">

```text
for i in $(seq 1 "$n"); do …
for ((i = 1; i <= n; i++)); do …
```

</Good>
</Compare>

<Compare>
<Bad title="Polling without a timeout">

```text
until curl -fs "$url"; do sleep 3; done    # can hang for hours
```

</Bad>
<Good title="With a deadline">

```text
deadline=$((SECONDS + 60))
until curl -fs "$url"; do (( SECONDS >= deadline )) && exit 1; sleep 3; done
```

</Good>
</Compare>

<Compare>
<Bad title="ssh inside while read">

```text
while read -r h; do ssh "$h" uptime; done < hosts.txt   # ssh eats the rest of the file
```

</Bad>
<Good title="Give ssh nothing to read">

```text
while read -r h; do ssh -n "$h" uptime; done < hosts.txt
```

</Good>
</Compare>

## Try it yourself

<Challenge title="Loop lab">

<Tr>
<En>
This lab tries every loop: lists, ranges, safe vs unsafe file loops, the empty-glob guard, arrays, C-style, `while read` with fields, the pipe trap and fix, `until` with a limit, `break`/`continue`, and a bulk rename.
</En>
<Ur>
Ye lab har loop aazmata hai: lists, ranges, mehfooz bamuqabla ghair mehfooz file loops, khaali-glob ki hifazat, arrays, C-style, hisson ke saath `while read`, pipe ka jaal aur hal, had ke saath `until`, `break`/`continue`, aur ek saath naam badalna.
</Ur>
</Tr>

```bash
mkdir -p ~/loop-lab && cd ~/loop-lab

# for over a list, a range and a stepped range
for env in dev staging prod; do echo "deploy → $env"; done
for i in {1..3}; do echo "attempt $i"; done
echo {0..20..5}
n=4; for i in $(seq 1 "$n"); do printf '%s ' "$i"; done; echo

# globs are safe with spaces, $(ls) is not
touch "my report.txt" notes.txt
echo "--- glob:";   for f in *.txt; do echo "[$f]"; done
echo "--- \$(ls):"; for f in $(ls *.txt); do echo "[$f]"; done

# empty glob guard
for f in *.nothing; do [[ -e $f ]] || { echo "no .nothing files"; continue; }; echo "$f"; done

# arrays and indexes
servers=(web-1 web-2 "db primary")
for s in "${servers[@]}"; do echo "check: $s"; done
for i in "${!servers[@]}"; do echo "$i = ${servers[$i]}"; done

# C-style
for ((i = 10; i > 0; i -= 3)); do printf '%s ' "$i"; done; echo

# while read with fields
printf 'alice,admin,/bin/bash\nbob,dev,/bin/zsh\n  carol  ,guest,/usr/sbin/nologin\n' > users.csv
while IFS=, read -r user role shell; do
  echo "user=[$user] role=$role shell=$shell"
done < users.csv

# the pipe/subshell trap and the fix
printf '10\n20\n30\n' > sizes.txt
total=0; cat sizes.txt | while read -r x; do ((total += x)); done; echo "pipe total: $total"
total=0; while read -r x; do ((total += x)); done < <(cat sizes.txt); echo "fixed total: $total"

# until with a limit
tries=0
until [[ -f ready.flag ]] || (( tries >= 3 )); do
  ((++tries)); echo "waiting… ($tries)"
  (( tries == 2 )) && touch ready.flag
done
[[ -f ready.flag ]] && echo "ready after $tries tries"

# break and continue
for i in {1..10}; do
  (( i % 2 == 0 )) && continue
  (( i > 7 )) && break
  printf 'odd:%s ' "$i"
done; echo

# bulk rename
touch a.jpg b.jpg
for f in *.jpg; do mv -- "$f" "${f%.jpg}.jpeg"; done
ls *.jpeg

cd ~ && rm -rf ~/loop-lab
```

```text output
deploy → dev
deploy → staging
deploy → prod
attempt 1
attempt 2
attempt 3
0 5 10 15 20
1 2 3 4 
--- glob:
[my report.txt]
[notes.txt]
--- $(ls):
[my]
[report.txt]
[notes.txt]
no .nothing files
check: web-1
check: web-2
check: db primary
```

<Tr>
<En>

- `for x in list; do …; done`: once per item. Ranges `{1..5}`, `$(seq 1 "$n")`, `for ((i=0; i<n; i++))`.
- `for f in *.txt` for files (never `$(ls)`); guard empty globs with `[[ -e $f ]]`.
- `for s in "${arr[@]}"` for arrays.
- `while cond; do …; done`: make sure the condition eventually turns false.
- `while IFS= read -r line; do …; done < file` for lines; `IFS=,` to split fields.
- `| while` loses variables: use `done < <(cmd)`.
- `until` for waiting, **always** with a limit.

<DeepDive title="Real world: wait for health, and sweep user accounts">

A deployment step that waits for the new version to become healthy, with a timeout, so a broken release fails the pipeline instead of hanging it:

```bash
#!/usr/bin/env bash
# wait-healthy.sh <url> [timeout-seconds]
set -euo pipefail

url="${1:?usage: wait-healthy.sh <url> [timeout]}"
timeout="${2:-60}"
deadline=$(( SECONDS + timeout ))     # SECONDS = seconds since the script started

until curl -fsS --max-time 3 "$url" > /dev/null 2>&1; do
  if (( SECONDS >= deadline )); then
    echo "✖ $url not healthy after ${timeout}s" >&2
    exit 1
  fi
  echo "… not ready yet, retrying in 3s"
  sleep 3
done
echo "✓ $url is healthy after ${SECONDS}s"
```

And a security sweep over every user account:

```bash
# Find accounts other than root with UID 0 and login-capable system accounts
while IFS=: read -r user _ uid _ _ _ shell; do
  if (( uid == 0 )) && [[ $user != root ]]; then
    echo "ALERT: $user has UID 0"
  fi
  if (( uid < 1000 && uid != 0 )) && [[ $shell != */nologin && $shell != /bin/false ]]; then
    echo "review: system user $user has shell $shell"
  fi
done < /etc/passwd
```

One more gotcha: a file without a final newline loses its last line in `while read`. Use `while IFS= read -r line || [[ -n $line ]]`.

</DeepDive>

<DeepDive title="Security lens">

Loops multiply whatever a script does, including mistakes and attacks. One bad `rm` in a loop runs a thousand times.

- **Filenames are untrusted input:** a file can be named `-rf` or contain newlines. Use `--` before filenames (`rm -- "$f"`) and quote every variable.
- **Prefer `find … -print0 | while IFS= read -r -d '' f`** when walking folders others can write to: it's newline-safe.
- **Dry-run first:** write loops that `echo` the dangerous command, check the output, then remove the `echo`.
- **Rate-limit loops against remote systems:** a loop of API calls or SSH logins without `sleep` can trigger lockouts and rate limits, or look like an attack.
- **Log-parsing loops** (`auth.log`, `access.log`) are a core blue-team skill: counting failed logins per IP is a `while read` loop away.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="How do you read a file line by line in Bash, and why not use for line in $(cat file)?">
Use `while IFS= read -r line; do …; done < file`. read takes one line at a time, -r keeps backslashes, and IFS= keeps leading and trailing whitespace. A for loop over `$(cat file)` splits on all whitespace instead of newlines and also performs glob expansion, so lines with spaces or wildcards break.
</QA>

<QA q="Why is a variable modified inside cmd | while read … empty after the loop?">
Each part of a pipeline runs in a subshell, so the while loop works on a copy of the variables that disappears when the pipeline ends. Use process substitution, `while read …; done < <(cmd)`, to keep the loop in the current shell (or enable `shopt -s lastpipe` in non-interactive scripts).
</QA>

<QA q="What is the difference between while and until?">
while repeats as long as its condition command succeeds (exit status 0); until repeats as long as its condition fails and stops when it succeeds. until X is equivalent to while ! X. until is natural for waiting until something is ready.
</QA>

<QA q="How would you wait for a service to become healthy in a deployment script?">
Use an until loop that runs a health check such as curl -fsS on the health endpoint, sleeps a few seconds between attempts, and checks a deadline (for example using the SECONDS variable) so it exits with a non-zero status if the service is not healthy within the timeout.
</QA>

<QA q="What do break and continue do?">
continue skips the rest of the current iteration and moves to the next item; break leaves the loop entirely. Both accept a number to act on an outer loop when loops are nested, for example break 2.
</QA>

</DeepDive>
