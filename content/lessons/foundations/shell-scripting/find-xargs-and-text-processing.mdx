<BigIdea>
<Tr>
<En>
`ls` looks inside **one** folder. **find** walks through a **whole tree** of folders and brings back exactly the files you described (by name, size, age or permissions), and can **do something** with each one. Then a few small text tools (`sort`, `uniq`, `cut`, `wc`…) turn the results into answers.
</En>
<Ur>
`ls` **ek** folder ke andar dekhta hai. **find** folders ke **poore darakht** me ghoom kar bilkul wahi files le aata hai jo aap ne batayin (naam, size, umar ya permissions se), aur har ek ke saath **kuch kar** bhi sakta hai. Phir chand chhote text tools (`sort`, `uniq`, `cut`, `wc`…) nateejon ko jawab me badal dete hain.
</Ur>
</Tr>
</BigIdea>

## At a glance

<Glance>
<What>
<Tr>
<En>

- **find**: `find WHERE CONDITIONS ACTION`. Example: `find /var/log -name "*.log" -mtime +7` = "log files older than 7 days".
- **Actions**: `-delete`, or `-exec command {} +` to run a command on each result.
- **xargs**: turns a list of lines into arguments for another command.
- **Text tools**: `sort` (order), `uniq -c` (count duplicates), `cut` (columns), `tr` (change characters), `wc -l` (count lines), `head`/`tail` (start/end).

</En>
<Ur>

- **find**: `find KAHAN SHARTEN KAAM`. Misaal: `find /var/log -name "*.log" -mtime +7` = "7 din se purani log files".
- **Kaam (actions)**: `-delete`, ya har nateeje par command chalane ke liye `-exec command {} +`.
- **xargs**: lines ki list ko doosri command ke arguments me badalta hai.
- **Text tools**: `sort` (tarteeb), `uniq -c` (dohri lines gino), `cut` (columns), `tr` (characters badlo), `wc -l` (lines gino), `head`/`tail` (shuru/aakhir).

</Ur>
</Tr>
</What>
<Why>
<Tr>
<En>

- **Cleanup**: delete old logs and backups before the disk fills up (a classic cause of outages).
- **Bulk changes**: fix permissions, compress or search thousands of files at once.
- **Security audits**: find files anyone can write to, dangerous programs, files changed after an attack.
- **Reports**: turn raw output into counts and top-10 lists.

</En>
<Ur>

- **Safai**: disk bharne se pehle purane logs aur backups delete karo (outages ki mashhoor wajah).
- **Ek saath tabdeeliyan**: hazaron files ki permissions theek, compress ya talash ek saath.
- **Security audits**: har kisi ke likhne layak files, khatarnak programs, hamle ke baad badli files dhoondo.
- **Reports**: kachcha output ginti aur top-10 lists me badlo.

</Ur>
</Tr>
</Why>
<When>
<Tr>
<En>

| Task | Command |
| --- | --- |
| Locate a file by name | `find / -name nginx.conf 2>/dev/null` |
| Clean up old files | `find /backups -mtime +30 -delete` |
| Find large files | `find / -size +500M` |
| Run a command on every match | `find … -exec cmd {} +` |
| Count, sort, de-duplicate | `sort \| uniq -c \| sort -rn` |

</En>
<Ur>

| Kaam | Command |
| --- | --- |
| Naam se file dhoondo | `find / -name nginx.conf 2>/dev/null` |
| Purani files saaf karo | `find /backups -mtime +30 -delete` |
| Bari files dhoondo | `find / -size +500M` |
| Har match par command | `find … -exec cmd {} +` |
| Gino, tarteeb do, dohri hatao | `sort \| uniq -c \| sort -rn` |

</Ur>
</Tr>
</When>
<How>
<Tr>
<En>

The safety rule for anything that deletes:

1. Run the `find` **without** an action first and **read the list**.
2. Only then add `-delete` (always **at the end**) or `-exec`.

</En>
<Ur>

Delete karne wali har cheez ka hifazati qaida:

1. Pehle `find` **baghair** kaam ke chalayen aur **list parhein**.
2. Sirf phir `-delete` (hamesha **aakhir me**) ya `-exec` lagayen.

</Ur>
</Tr>
</How>
</Glance>

## Words you'll see

<Tr>
<En>

| Word | What it means | Example |
| --- | --- | --- |
| **Directory tree** | A folder plus every folder inside it, at every level | `/var/log` and everything below |
| **Starting point** | Where find begins searching | `.` (here), `/etc` |
| **Test / condition** | A rule a file must match | `-name "*.log"`, `-size +10M` |
| **Action** | What find does with each match | `-print`, `-delete`, `-exec` |
| **Null character** | An invisible character (`\0`) that safely separates file names | `-print0` |
| **Modification time** | When a file's content last changed | used by `-mtime` |

</En>
<Ur>

| Lafz | Matlab | Misaal |
| --- | --- | --- |
| **Directory tree** | Folder aur us ke andar ka har folder, har darje tak | `/var/log` aur neeche sab |
| **Starting point** | Jahan se find talash shuru karta hai | `.` (yahan), `/etc` |
| **Test / condition** | Qaida jis se file ka milna zaroori hai | `-name "*.log"`, `-size +10M` |
| **Action** | Har match ke saath find kya kare | `-print`, `-delete`, `-exec` |
| **Null character** | Nazar na aane wala character (`\0`) jo file naamon ko mehfooz tareeqe se alag karta hai | `-print0` |
| **Modification time** | File ka mawad aakhri dafa kab badla | `-mtime` istemal karta hai |

</Ur>
</Tr>

## The sample folder

<Tr>
<En>We create: web files, two logs, a 3 MB image, a backup with a **space** in its name, two files that look **40 days old** (`touch -d`), and one file **anyone can write to** (`chmod 777`).</En>
<Ur>Hum banate hain: web files, do logs, 3 MB ki image, ek backup jis ke naam me **space** hai, do files jo **40 din purani** lagti hain (`touch -d`), aur ek file jis me **har koi likh** sakta hai (`chmod 777`).</Ur>
</Tr>

```bash
mkdir -p site/logs site/img site/backup
echo "<h1>home</h1>" > site/index.html
echo "body{}" > site/style.css
printf 'line\n%.0s' {1..50} > site/logs/app.log
echo "old" > site/logs/old.log
head -c 3000000 /dev/zero > site/img/banner.png
echo "dump" > "site/backup/db 2026-01.sql"
touch -d "40 days ago" site/logs/old.log "site/backup/db 2026-01.sql"
chmod 777 site/style.css
find site | sort
```

```text output
site
site/backup
site/backup/db 2026-01.sql
site/img
site/img/banner.png
site/index.html
site/logs
site/logs/app.log
site/logs/old.log
site/style.css
```

## Learn it step by step

<Walkthrough>

<Step title="The shape of a find command">

<Tr>
<En>

`find WHERE CONDITIONS ACTION` reads like a sentence: `find site -name "*.log"` = "start in `site`, keep names ending in `.log`, (print them)". Printing is the default action.

Always **quote** the pattern (`"*.log"`). Without quotes, the shell may expand `*.log` itself before find even runs.

</En>
<Ur>

`find KAHAN SHARTEN KAAM` ek jumle ki tarah parha jata hai: `find site -name "*.log"` = "`site` se shuru karo, `.log` par khatam hone wale naam rakho, (print karo)". Print karna default kaam hai.

Pattern hamesha **quotes** me rakhein (`"*.log"`). Quotes ke baghair shell find chalne se pehle hi `*.log` khud phaila sakta hai.

</Ur>
</Tr>

```bash
find site -name "*.log" | sort
```

```text output
site/logs/app.log
site/logs/old.log
```

<Happened>
<Tr>
<En>Both log files were found, even though they're inside `site/logs/`: find searches **every level**. (`| sort` only puts results in a fixed order.)</En>
<Ur>Dono log files mil gayin, halanke wo `site/logs/` ke andar hain: find **har darje** me dhoondta hai. (`| sort` sirf nateejon ko tay tarteeb deta hai.)</Ur>
</Tr>
</Happened>

</Step>

<Step title="By name and type">

<Tr>
<En>

- `-name "*.html"`: name pattern (`-iname` ignores case)
- `-type f` files, `-type d` folders, `-type l` links
- Several conditions next to each other must **all** be true.
- For "**or**", use `-o` inside escaped brackets: `\( -name "*.html" -o -name "*.css" \)`.

</En>
<Ur>

- `-name "*.html"`: naam ka pattern (`-iname` case nazar andaz karta hai)
- `-type f` files, `-type d` folders, `-type l` links
- Saath saath likhi kai sharten **sab** sach honi chahiyen.
- "**Ya**" ke liye escaped brackets ke andar `-o`: `\( -name "*.html" -o -name "*.css" \)`.

</Ur>
</Tr>

```bash
echo "--- folders:"
find site -type d | sort
echo "--- html or css files:"
find site -type f \( -name "*.html" -o -name "*.css" \) | sort
```

```text output
--- folders:
site
site/backup
site/img
site/logs
--- html or css files:
site/index.html
site/style.css
```

</Step>

<Step title="By size">

<Tr>
<En>

When the disk is full, you need to know what's using the space. `-size +1M` = **bigger** than 1 MB, `-size -10k` = **smaller** than 10 KB. Units: `k`, `M`, `G`. `-empty` = size zero.

</En>
<Ur>

Disk bhar jaye to pata hona chahiye jagah kaun le raha hai. `-size +1M` = 1 MB se **bari**, `-size -10k` = 10 KB se **chhoti**. Units: `k`, `M`, `G`. `-empty` = size zero.

</Ur>
</Tr>

```bash
find site -type f -size +1M
find site -type f -size +1M -exec ls -lh {} \; | awk '{print $5, $9}'
```

```text output
site/img/banner.png
2.9M site/img/banner.png
```

<Happened>
<Tr>
<En>Only the 3 MB image is bigger than 1 MB. The second line runs `ls -lh` on it to show the size in human units (2.9M).</En>
<Ur>Sirf 3 MB wali image 1 MB se bari hai. Doosri line us par `ls -lh` chala kar size insani units me (2.9M) dikhati hai.</Ur>
</Tr>
</Happened>

</Step>

<Step title="By age">

<Tr>
<En>

- `-mtime +30`: changed **more than** 30 days ago (old)
- `-mtime -1`: changed **within** the last day
- `-mmin -60`: changed within the last **60 minutes**

Used for cleanup ("keep 30 days") and for security ("what changed in the last hour?").

</En>
<Ur>

- `-mtime +30`: 30 din se **zyada** pehle badli (purani)
- `-mtime -1`: pichle ek din ke **andar** badli
- `-mmin -60`: pichle **60 minute** me badli

Safai ("30 din rakho") aur security ("pichle ghante me kya badla?") ke liye istemal hota hai.

</Ur>
</Tr>

```bash
echo "--- older than 30 days:"
find site -type f -mtime +30 | sort
echo "--- changed in the last 60 minutes:"
find site -type f -mmin -60 | sort
```

```text output
--- older than 30 days:
site/backup/db 2026-01.sql
site/logs/old.log
--- changed in the last 60 minutes:
site/img/banner.png
site/index.html
site/logs/app.log
site/style.css
```

</Step>

<Step title="By permissions and owner">

<Tr>
<En>

A file **anyone can write to** can be changed by any user, or by an attacker who got in. Find them:

- `-perm -o+w`: others can write (world-writable)
- `-perm -4000`: SUID programs (run with the owner's rights)
- `-user www-data`: owned by that user

</En>
<Ur>

Jis file me **har koi likh** sakta hai use koi bhi user, ya andar ghusa hua hacker, badal sakta hai. Inhe dhoondein:

- `-perm -o+w`: others likh sakte hain (world-writable)
- `-perm -4000`: SUID programs (maalik ki taqat se chalte hain)
- `-user www-data`: us user ki milkiyat

</Ur>
</Tr>

```bash
find site -type f -perm -o+w
```

```text output
site/style.css
```

<Happened>
<Tr>
<En>That's the file we set to `777` on purpose. A real audit runs this across `/var/www` or `/etc`.</En>
<Ur>Ye wahi file hai jise hum ne jaan boojh kar `777` kiya tha. Asli audit ise `/var/www` ya `/etc` par chalata hai.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Act on results: -delete and -exec">

<Tr>
<En>

- `-delete`: remove each match. Must come **last**.
- `-exec COMMAND {} \;`: run the command **once per file** (`{}` = the file name)
- `-exec COMMAND {} +`: run it **once with many files**: much faster

**Always do a dry run first**: the same `find` without the action.

</En>
<Ur>

- `-delete`: har match hata do. **Aakhir me** hona chahiye.
- `-exec COMMAND {} \;`: command **har file ke liye ek dafa** (`{}` = file ka naam)
- `-exec COMMAND {} +`: **kai files ke saath ek dafa**: kahin tez

**Hamesha pehle dry run karein**: wahi `find` baghair kaam ke.

</Ur>
</Tr>

```bash
echo "--- dry run (just list):"
find site -type f -mtime +30 | sort
find site -type f -mtime +30 -delete
echo "--- after -delete:"
find site -type f -mtime +30 | wc -l

find site -type f -perm -o+w -exec chmod 644 {} +
echo "--- world-writable files left: $(find site -type f -perm -o+w | wc -l)"
```

```text output
--- dry run (just list):
site/backup/db 2026-01.sql
site/logs/old.log
--- after -delete:
0
--- world-writable files left: 0
```

<Happened>
<Tr>
<En>

- The dry run showed exactly which 2 old files would go. Then `-delete` removed them: 0 left.
- `-exec chmod 644 {} +` fixed the dangerous permissions: 0 world-writable files left.

</En>
<Ur>

- Dry run ne bilkul dikhaya ke kaun si 2 purani files jayengi. Phir `-delete` ne unhe hata diya: 0 baaqi.
- `-exec chmod 644 {} +` ne khatarnak permissions theek kar din: 0 world-writable files baaqi.

</Ur>
</Tr>
</Happened>

<Callout type="danger" title="The order of -delete matters">
<Tr>
<En>`find . -delete -name "*.log"` deletes **everything**, because find works left to right and `-delete` comes first. The action always goes **at the end**.</En>
<Ur>`find . -delete -name "*.log"` **sab kuch** mita deta hai, kyun ke find baayen se dayen kaam karta hai aur `-delete` pehle aa gaya. Kaam hamesha **aakhir me** likhein.</Ur>
</Tr>
</Callout>

</Step>

<Step title="xargs: turn a list into arguments">

<Tr>
<En>

Many commands (`rm`, `tar`, `wc`) take file names as **arguments**, not from a pipe. **xargs** connects the two: it reads items and runs a command with them.

- `xargs cmd`: all items at once
- `xargs -n 1 cmd`: one item per run
- `xargs -I {} cmd {} …`: put the item anywhere in the command

</En>
<Ur>

Kai commands (`rm`, `tar`, `wc`) file naam **arguments** ki shakal me leti hain, pipe se nahi. **xargs** dono ko jorta hai: items parh kar un ke saath command chalata hai.

- `xargs cmd`: saare items ek saath
- `xargs -n 1 cmd`: har run me ek item
- `xargs -I {} cmd {} …`: item ko command me kahin bhi rakho

</Ur>
</Tr>

```bash
printf 'alpha\nbeta\ngamma\n' | xargs echo "Got:"
printf 'alpha\nbeta\ngamma\n' | xargs -n 1 echo "One at a time:"
printf 'web-1\nweb-2\n' | xargs -I {} echo "Restarting {} now"
```

```text output
Got: alpha beta gamma
One at a time: alpha
One at a time: beta
One at a time: gamma
Restarting web-1 now
Restarting web-2 now
```

</Step>

<Step title="Spaces in file names: -print0 | xargs -0">

<Tr>
<En>

By default xargs splits at **spaces**, so a file called `my file.txt` becomes two wrong arguments: `my` and `file.txt`. A delete command could then hit the **wrong** files.

The fix: `find -print0` separates names with an invisible null character, and `xargs -0` splits only there. Use it **every time** you pipe find into xargs.

</En>
<Ur>

Default me xargs **spaces** par torta hai, isliye `my file.txt` naam ki file do ghalat arguments ban jati hai: `my` aur `file.txt`. Phir delete command **ghalat** files par chal sakti hai.

Hal: `find -print0` naamon ko nazar na aane wale null character se alag karta hai, aur `xargs -0` sirf wahin torta hai. Jab bhi find ko xargs me pipe karein, **har dafa** yahi istemal karein.

</Ur>
</Tr>

```bash
mkdir -p demo && touch "demo/my file.txt" demo/other.txt
echo "--- unsafe:"
find demo -name "*.txt" | xargs ls 2>&1 | sed 's/^ls: //' | sort
echo "--- safe:"
find demo -name "*.txt" -print0 | xargs -0 ls | sort
```

```text output
--- unsafe:
cannot access 'demo/my': No such file or directory
cannot access 'file.txt': No such file or directory
demo/other.txt
--- safe:
demo/my file.txt
demo/other.txt
```

</Step>

<Step title="sort and uniq: how many of each?">

<Tr>
<En>

- `sort`: put lines in order (`-n` numbers, `-r` reverse, `-k2` by column 2, `-u` unique)
- `uniq -c`: squash **neighbouring** duplicates and count them

`uniq` only compares **neighbours**, so **always sort first**. `sort | uniq -c | sort -rn` = "how many of each, biggest first": the most common question in log analysis.

</En>
<Ur>

- `sort`: lines ko tarteeb do (`-n` numbers, `-r` ulta, `-k2` column 2 se, `-u` ek jaisi ek dafa)
- `uniq -c`: **saath wali** dohri lines ko ek kar ke gino

`uniq` sirf **saath walon** ko milata hai, isliye **hamesha pehle sort**. `sort | uniq -c | sort -rn` = "har ek kitne, bara pehle": log analysis ka sab se aam sawal.

</Ur>
</Tr>

```bash
printf 'ERROR\nINFO\nERROR\nWARN\nERROR\nINFO\n' > levels.txt
echo "--- uniq WITHOUT sort (wrong):"
uniq -c levels.txt
echo "--- sort | uniq -c | sort -rn (right):"
sort levels.txt | uniq -c | sort -rn
```

```text output
--- uniq WITHOUT sort (wrong):
      1 ERROR
      1 INFO
      1 ERROR
      1 WARN
      1 ERROR
      1 INFO
--- sort | uniq -c | sort -rn (right):
      3 ERROR
      2 INFO
      1 WARN
```

</Step>

<Step title="cut and tr">

<Tr>
<En>

- `cut -d: -f1,7`: split each line at `:` and keep fields 1 and 7
- `tr 'a-z' 'A-Z'`: make upper case
- `tr ',' '\n'`: put each comma-separated item on its own line
- `tr -d ' %'`: delete spaces and `%`

</En>
<Ur>

- `cut -d: -f1,7`: har line ko `:` par tor kar fields 1 aur 7 rakho
- `tr 'a-z' 'A-Z'`: bare huroof me badlo
- `tr ',' '\n'`: comma se alag har cheez alag line par
- `tr -d ' %'`: spaces aur `%` mitao

</Ur>
</Tr>

```bash
printf 'root:x:0:0:root:/root:/bin/bash\nalex:x:1000:1000:Alex:/home/alex:/bin/zsh\n' > passwd.txt
cut -d: -f1,7 passwd.txt
echo "devops engineer" | tr 'a-z' 'A-Z'
echo "web-1,web-2,db-1" | tr ',' '\n'
echo " 4 2 % " | tr -d ' %'
```

```text output
root:/bin/bash
alex:/bin/zsh
DEVOPS ENGINEER
web-1
web-2
db-1
42
```

</Step>

<Step title="wc, head and tail">

<Tr>
<En>

- `wc -l`: count lines (`-w` words, `-c` characters)
- `head -n 5`: first 5 lines
- `tail -n 5`: last 5 lines
- `tail -f file`: keep showing new lines live (Ctrl+C to stop)

</En>
<Ur>

- `wc -l`: lines gino (`-w` alfaz, `-c` characters)
- `head -n 5`: pehli 5 lines
- `tail -n 5`: aakhri 5 lines
- `tail -f file`: nayi lines live dikhate raho (rokne ke liye Ctrl+C)

</Ur>
</Tr>

```bash
seq 1 100 > numbers.txt
echo "lines: $(wc -l < numbers.txt)"
echo "first 3: $(head -n 3 numbers.txt | tr '\n' ' ')"
echo "last 3:  $(tail -n 3 numbers.txt | tr '\n' ' ')"
echo "lines 50-52: $(sed -n '50,52p' numbers.txt | tr '\n' ' ')"
```

```text output
lines: 100
first 3: 1 2 3 
last 3:  98 99 100 
lines 50-52: 50 51 52 
```

</Step>

</Walkthrough>

## Common mistakes

<Compare>
<Bad title="Unquoted pattern">

```text
find . -name *.log
```

<Tr>
<En>The shell expands `*.log` in the current folder first, so find gets the wrong pattern (or an error).</En>
<Ur>Shell pehle mojooda folder me `*.log` phaila deta hai, isliye find ko ghalat pattern milta hai (ya error).</Ur>
</Tr>

</Bad>
<Good title="Quote it">

```text
find . -name "*.log"
```

</Good>
</Compare>

<Compare>
<Bad title="-exec \; on thousands of files">

```text
find . -name "*.log" -exec gzip {} \;      # starts gzip once per file
```

</Bad>
<Good title="Batch with +">

```text
find . -name "*.log" -exec gzip {} +       # many files per gzip
```

</Good>
</Compare>

<Compare>
<Bad title="sort on numbers without -n">

```text
printf '9\n10\n' | sort       # 10 comes before 9
```

</Bad>
<Good title="Numeric sort">

```text
printf '9\n10\n' | sort -n    # 9, then 10
```

</Good>
</Compare>

## Try it yourself

<Challenge title="A cleanup and report job">

<Tr>
<En>
This lab creates logs of different ages, deletes the ones older than 30 days safely, and builds a small report from an access file.
</En>
<Ur>
Ye lab mukhtalif umar ke logs banata hai, 30 din se purane mehfooz tareeqe se delete karta hai, aur ek access file se chhoti report banata hai.
</Ur>
</Tr>

```bash
mkdir -p ~/find-lab/logs && cd ~/find-lab
for d in 1 5 10 20 40 60; do
  echo "log from $d days ago" > "logs/app-$d.log"
  touch -d "$d days ago" "logs/app-$d.log"
done
printf 'GET /a 200\nGET /b 404\nGET /a 200\nPOST /c 500\nGET /a 200\n' > logs/access.txt

echo "1) all logs: $(find logs -name '*.log' | wc -l)"
echo "2) older than 30 days:"
find logs -name '*.log' -mtime +30 | sort
find logs -name '*.log' -mtime +30 -print0 | xargs -0 rm -f
echo "3) after cleanup: $(find logs -name '*.log' | wc -l) logs left"
echo "4) top paths:"
```

<DeepDive title="Real world: a nightly cleanup script">

A server's disk alert fires every few weeks because a Next.js app keeps old release folders and logs. The fix is one script on a nightly timer:

```bash
#!/usr/bin/env bash
# cleanup.sh — keep the server lean. Runs nightly from a systemd timer.
set -euo pipefail

RELEASES=/srv/app/releases
LOGS=/var/log/app

# Keep the 5 newest release folders, delete the rest
find "$RELEASES" -mindepth 1 -maxdepth 1 -type d -printf '%T@ %p\0' \
  | sort -z -rn \
  | tail -z -n +6 \
  | cut -z -d' ' -f2- \
  | xargs -0 -r rm -rf --

# Compress logs older than 1 day, delete compressed logs older than 30 days
find "$LOGS" -name "*.log" -mtime +1 -print0 | xargs -0 -r gzip
find "$LOGS" -name "*.log.gz" -mtime +30 -delete

# Report
echo "Disk after cleanup:"; df -h /srv /var/log | tail -n +2
```

Every step is NUL-safe, does nothing when there's nothing to do (`-r`), and never touches the current release.

Another gotcha: forgetting `-xdev` when searching from `/`, so find wanders into `/proc`, network mounts and huge Docker overlay folders.

</DeepDive>

<DeepDive title="Security lens">

find is the auditor's microscope; unsafe find/xargs pipelines are a classic way to turn a crafted file name into code execution.

- **Audit commands worth memorising:**
  - `find / -xdev -perm -4000 -type f 2>/dev/null`: setuid programs
  - `find / -xdev -perm -0002 -type f 2>/dev/null`: world-writable files
  - `find / -xdev \( -nouser -o -nogroup \) 2>/dev/null`: orphaned files
  - `find /var/www -type f -mtime -2`: recently changed web files (web shells)
  - `find /tmp /dev/shm -type f -executable`: executables in temp locations
- **File-name injection:** a file named `-rf`, `--checkpoint-action=exec=sh evil.sh` (for `tar`) or containing a newline can change what a command does when names are passed unsafely. Use `-print0 | xargs -0`, `-exec … {} +`, and `--` before file arguments, especially in scripts that run as root over user-writable folders.
- **Race conditions (TOCTOU):** between `find` listing a file and a command acting on it, a local attacker can swap the file for a symlink to `/etc/shadow`. For root cleanup jobs in shared folders, prefer `-delete`/`-execdir`, and avoid following symlinks.
- **Evidence:** `find -newer` and `-mmin` reconstruct what changed during an incident window. Timestamps can be forged (`touch -d`), so treat them as clues, not proof.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="How do you delete all .log files older than 14 days under /var/log/app?">
First check with `find /var/log/app -type f -name "*.log" -mtime +14 -print`, then run the same command with `-delete` instead of -print. Quote the pattern so the shell does not expand it, and make sure the action comes after the tests.
</QA>

<QA q="What is the difference between find -exec cmd {} \; and -exec cmd {} +?">
With `\;` find runs the command once per matching file. With `+` it passes as many file names as fit into one command line, running the command far fewer times, which is much faster for large numbers of files. Use + unless the command only accepts one file.
</QA>

<QA q="Why use find -print0 with xargs -0?">
xargs normally splits input on whitespace and treats quotes specially, so file names containing spaces, quotes or newlines break into wrong arguments, and names starting with a dash may be read as options. -print0 and -0 use the NUL byte, which cannot appear in file names, as the separator, so every name is passed exactly. Adding -- before the file list protects against option-like names.
</QA>

<QA q="Why does uniq need sort first?">
uniq only compares each line with the one directly before it, so it collapses consecutive duplicates only. Sorting first groups identical lines together, so sort | uniq -c counts every distinct line correctly. sort -u is a shortcut when no counts are needed.
</QA>

<QA q="Which find commands would you run when auditing a Linux server?">
Search for setuid and setgid binaries (-perm -4000 / -2000), world-writable files and directories (-perm -0002), files with no valid owner (-nouser, -nogroup), recently modified files in web roots and system directories (-mtime, -mmin), and executables or scripts in /tmp, /dev/shm and upload directories. Compare results against a known baseline.
</QA>
