<BigIdea>
<Tr>
<En>
An **array** is one variable that holds a **list**: `servers=(web-1 web-2 db-1)`. An **associative array** holds **name → value** pairs: `port[db]=5432`. Loop over them with `for s in "${servers[@]}"`, **with the quotes**, and every item stays safe, even if it contains spaces.
</En>
<Ur>
**Array** ek aisa variable hai jo **list** rakhta hai: `servers=(web-1 web-2 db-1)`. **Associative array** **naam → value** ke jore rakhta hai: `port[db]=5432`. In par `for s in "${servers[@]}"` se loop chalayen, **quotes ke saath**, aur har cheez mehfooz rehti hai, chahe us me spaces hon.
</Ur>
</Tr>
</BigIdea>

<Why>
<Tr>
<En>

- **Lists are everywhere**: hosts, regions, files, packages, users, ports.
- **Spaces stay safe**: an array item `"db primary"` stays **one** item. A space-separated string would break it in two.
- **Safe commands**: collecting options in an array avoids quoting bugs.
- **Lookups**: "what's the port of service X?" in one step.

</En>
<Ur>

- **Lists har jagah hain**: hosts, regions, files, packages, users, ports.
- **Spaces mehfooz**: array ki cheez `"db primary"` **ek** hi rehti hai. Spaces se alag string ise do me tor deti.
- **Mehfooz commands**: options array me jama karne se quotes ke bugs nahi hote.
- **Talash**: "service X ka port kya hai?" ek qadam me.

</Ur>

## Picture it

<Tr>
<En>

An **array** is a **train**: one train (the variable) with numbered carriages (0, 1, 2…), each carrying one passenger (a value). You can ask for "carriage 2", "how many carriages?", "everyone step out", or "attach one more carriage".

An **associative array** is a row of **labelled gym lockers**: instead of numbers, each locker has a **name** on it ("Sam", "Emma"), and you open it by name.

</En>
<Ur>

**Array** ek **train** hai: ek train (variable) jis ke numbered dabbe (0, 1, 2…) hain, har dabbe me ek musafir (value). Aap keh sakte hain "dabba 2", "kitne dabbe?", "sab utar jao", ya "ek aur dabba joro".

**Associative array** **gym ke label wale lockers** ki qataar hai: numbers ki jagah har locker par **naam** likha hai ("Sam", "Emma"), aur aap naam se kholte hain.

</Ur>
</Tr>

## Learn it step by step

<Walkthrough>

<Step title="Create an array and read items">

<Tr>
<En>

Put the values in round brackets: `name=(a b "c d")`. **Quote** items that contain spaces. Read one with braces: `${name[1]}`; the last with `${name[-1]}`. Counting starts at **0**: an array of 3 items has indexes 0, 1, 2.

</En>
<Ur>

Values gol brackets me rakhein: `name=(a b "c d")`. Spaces wali cheezon ko **quotes** me rakhein. Ek cheez braces se parhein: `${name[1]}`; aakhri `${name[-1]}` se. Ginti **0** se shuru hoti hai: 3 cheezon wale array ke indexes 0, 1, 2 hain.

</Ur>
</Tr>

```bash
servers=(web-1 web-2 "db primary")
echo "First:  ${servers[0]}"
echo "Second: ${servers[1]}"
echo "Third:  ${servers[2]}"
echo "Last:   ${servers[-1]}"
```

```text output
First:  web-1
Second: web-2
Third:  db primary
Last:   db primary
```

```text
index:   [0]      [1]      [2]
value:   web-1    web-2    db primary
```

</Step>

<Step title="All items, the count, the indexes">

<Tr>
<En>

- `"${arr[@]}"`: every item, each kept separate
- `${#arr[@]}`: how many items
- `${!arr[@]}`: all the indexes

</En>
<Ur>

- `"${arr[@]}"`: har cheez, har ek alag
- `${#arr[@]}`: kitni cheezen
- `${!arr[@]}`: saare indexes

</Ur>
</Tr>

```bash
packages=(git curl "build-essential" jq)
echo "Number of packages: ${#packages[@]}"
echo "All: ${packages[*]}"
echo "Indexes: ${!packages[*]}"
```

```text output
Number of packages: 4
All: git curl build-essential jq
Indexes: 0 1 2 3
```

</Step>

<Step title="Loop over an array">

<Tr>
<En>

`for item in "${arr[@]}"; do …; done` visits each item. To know the **position** too, loop over the indexes: `for i in "${!arr[@]}"`.

</En>
<Ur>

`for item in "${arr[@]}"; do …; done` har cheez par jata hai. **Jagah** bhi jaanni ho to indexes par loop chalayen: `for i in "${!arr[@]}"`.

</Ur>
</Tr>

```bash
servers=(web-1 web-2 "db primary")
for s in "${servers[@]}"; do
  echo "Checking: $s"
done
for i in "${!servers[@]}"; do
  echo "#$((i + 1)) is ${servers[$i]}"
done
```

```text output
Checking: web-1
Checking: web-2
Checking: db primary
#1 is web-1
#2 is web-2
#3 is db primary
```

</Step>

<Step title="Quoted or not: [@] vs [*]">

<Tr>
<En>

Three ways to get all items, which treat spaces differently:

- `"${arr[@]}"`: each item stays separate. **Use this.**
- `${arr[@]}` (no quotes): items split again at spaces.
- `"${arr[*]}"`: everything joined into **one** string (good for printing).

</En>
<Ur>

Saari cheezen lene ke teen tareeqe, jo spaces ko alag tarah sambhalte hain:

- `"${arr[@]}"`: har cheez alag rehti hai. **Yahi istemal karein.**
- `${arr[@]}` (baghair quotes): cheezen spaces par dobara toot jati hain.
- `"${arr[*]}"`: sab kuch **ek** string me jur jata hai (print ke liye achha).

</Ur>
</Tr>

```bash
arr=(one "two words" three)
echo "Quoted [@]:";   printf '  <%s>\n' "${arr[@]}"
echo "Unquoted [@]:"; printf '  <%s>\n' ${arr[@]}
echo "Quoted [*]:";   printf '  <%s>\n' "${arr[*]}"
```

```text output
Quoted [@]:
  <one>
  <two words>
  <three>
Unquoted [@]:
  <one>
  <two>
  <words>
  <three>
Quoted [*]:
  <one two words three>
```

<Happened>
<Tr>
<En>Quoted `[@]` gave **3** correct items. Unquoted split "two words" into **4**. Quoted `[*]` gave **1** joined string.</En>
<Ur>Quotes wale `[@]` ne **3** sahi cheezen din. Baghair quotes ne "two words" tor kar **4** bana din. Quotes wale `[*]` ne **1** juri string di.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Add, change and remove">

<Tr>
<En>

- Append: `arr+=(new)`
- Replace: `arr[1]=other`
- Delete: `unset 'arr[1]'` (leaves a **gap** in the indexes)
- Empty it: `arr=()`

A common pattern: start with `failed=()` and add every server that fails.

</En>
<Ur>

- Jorna: `arr+=(new)`
- Badalna: `arr[1]=other`
- Mitana: `unset 'arr[1]'` (indexes me **khala** chhorta hai)
- Khaali karna: `arr=()`

Aam tareeqa: `failed=()` se shuru karein aur fail hone wala har server jorte jayen.

</Ur>
</Tr>

```bash
failed=()
for s in web-1 web-2 web-3 db-1; do
  if [[ $s == web-2 || $s == db-1 ]]; then
    failed+=("$s")
  fi
done
echo "Failed: ${failed[*]} (${#failed[@]} servers)"

failed[0]="WEB-2"
echo "After change: ${failed[*]}"
unset 'failed[0]'
echo "After unset: ${failed[*]}  indexes left: ${!failed[*]}"
```

```text output
Failed: web-2 db-1 (2 servers)
After change: WEB-2 db-1
After unset: db-1  indexes left: 1
```

<Happened>
<Tr>
<En>After removing index 0, the remaining item is **still at index 1**: there's a gap. That's why loops should use `"${arr[@]}"` instead of counting from 0.</En>
<Ur>Index 0 hatane ke baad baaqi cheez **ab bhi index 1 par** hai: khala hai. Isi liye loops ko 0 se ginne ke bajaye `"${arr[@]}"` istemal karna chahiye.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Slicing: part of an array">

<Tr>
<En>

`"${arr[@]:start:count}"` gives `count` items starting at `start`. `"${arr[@]:1}"` = everything except the first. Useful for "deploy to the first 2 servers (canary), then the rest".

</En>
<Ur>

`"${arr[@]:start:count}"` `start` se shuru kar ke `count` cheezen deta hai. `"${arr[@]:1}"` = pehli ke siwa sab. "Pehle 2 servers par deploy (canary), phir baaqi" ke liye kaam ka.

</Ur>
</Tr>

```bash
hosts=(h1 h2 h3 h4 h5)
echo "Canary (first 2): ${hosts[*]:0:2}"
echo "Rest:             ${hosts[*]:2}"
```

```text output
Canary (first 2): h1 h2
Rest:             h3 h4 h5
```

</Step>

<Step title="Read a file's lines into an array">

<Tr>
<En>

`mapfile -t name < file` stores **one line per item**; `-t` removes the line ending. From a command: `mapfile -t files < <(find . -name "*.log")`.

</En>
<Ur>

`mapfile -t name < file` **har line ko ek cheez** ki shakal me rakhta hai; `-t` line ka aakhir hata deta hai. Command se: `mapfile -t files < <(find . -name "*.log")`.

</Ur>
</Tr>

```bash
printf 'web-1\nweb-2\ndb primary\n' > hosts.txt
mapfile -t hosts < hosts.txt
echo "Loaded ${#hosts[@]} hosts"
echo "Third host: ${hosts[2]}"
```

```text output
Loaded 3 hosts
Third host: db primary
```

</Step>

<Step title="Split one string into an array">

<Tr>
<En>

Lists often arrive as **one string**, like `SERVERS="a,b,c"` in CI settings. `IFS=, read -r -a arr <<< "$string"` splits it: `IFS=,` = split at commas, `-a arr` = store in an array, `<<<` = feed the string in.

</En>
<Ur>

Lists aksar **ek string** ki shakal me aati hain, jaise CI settings me `SERVERS="a,b,c"`. `IFS=, read -r -a arr <<< "$string"` ise torta hai: `IFS=,` = commas par toro, `-a arr` = array me rakho, `<<<` = string andar bhejo.

</Ur>
</Tr>

```bash
SERVERS="web-1,web-2,db-1"
IFS=, read -r -a list <<< "$SERVERS"
echo "Count: ${#list[@]}"
printf ' - %s\n' "${list[@]}"

IFS=: read -r -a dirs <<< "/usr/local/bin:/usr/bin:/bin"
echo "First PATH folder: ${dirs[0]}"
```

```text output
Count: 3
 - web-1
 - web-2
 - db-1
First PATH folder: /usr/local/bin
```

</Step>

<Step title="Build commands safely with arrays">

<Tr>
<En>

Building a command as one **string** breaks as soon as a value has a space. Collect options in an **array** instead, and run `command "${opts[@]}"`. Each argument stays exactly as you wrote it. `show_args` below prints each argument it receives in `< >`.

</En>
<Ur>

Command ko ek **string** ki shakal me banana tab toot jata hai jab value me space ho. Is ke bajaye options ek **array** me jama karein, aur `command "${opts[@]}"` chalayen. Har argument bilkul waisa rehta hai jaisa likha. Neeche `show_args` har milne wala argument `< >` me print karta hai.

</Ur>
</Tr>

```bash
show_args() { printf '  arg: <%s>\n' "$@"; }

dry_run=true
opts=(-a --delete)
$dry_run && opts+=(--dry-run)
opts+=(--exclude "my uploads")

echo "With an array:"
show_args "${opts[@]}"

echo "With a string (broken):"
opts_string="-a --exclude my uploads"
show_args $opts_string
```

```text output
With an array:
  arg: <-a>
  arg: <--delete>
  arg: <--dry-run>
  arg: <--exclude>
  arg: <my uploads>
With a string (broken):
  arg: <-a>
  arg: <--exclude>
  arg: <my>
  arg: <uploads>
```

<Happened>
<Tr>
<En>The array kept `my uploads` as **one** argument and added `--dry-run` only because `dry_run` was true. The string broke it into `my` and `uploads`, so rsync would exclude the wrong thing.</En>
<Ur>Array ne `my uploads` ko **ek** argument rakha aur `--dry-run` sirf is liye jora ke `dry_run` true tha. String ne use `my` aur `uploads` me tor diya, yani rsync ghalat cheez chhorta.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Associative arrays: name → value">

<Tr>
<En>

Declare first with `declare -A`, then look things up by name:

- `declare -A port=([web]=80 [db]=5432)`
- read: `${port[db]}`, add: `port[cache]=6379`
- all keys: `"${!port[@]}"`
- does a key exist? `[[ -v port[web] ]]`

They have **no fixed order**, so sort the keys when printing.

</En>
<Ur>

Pehle `declare -A` se elaan karein, phir naam se dhoondein:

- `declare -A port=([web]=80 [db]=5432)`
- parhna: `${port[db]}`, jorna: `port[cache]=6379`
- saari keys: `"${!port[@]}"`
- kya key mojood hai? `[[ -v port[web] ]]`

In ki **koi tay tarteeb nahi**, isliye print karte waqt keys ko sort karein.

</Ur>
</Tr>

```bash
declare -A port=([web]=80 [db]=5432 [cache]=6379)
echo "Database port: ${port[db]}"
port[api]=3000
echo "Services: ${#port[@]}"
for name in $(printf '%s\n' "${!port[@]}" | sort); do
  echo "  $name → ${port[$name]}"
done
[[ -v port[web] ]] && echo "web is defined"
[[ -v port[mail] ]] || echo "mail is not defined"
```

```text output
Database port: 5432
Services: 4
  api → 3000
  cache → 6379
  db → 5432
  web → 80
web is defined
mail is not defined
```

</Step>

<Step title="Counting with an associative array">

<Tr>
<En>

Use keys as **categories** and values as **counters**: `((count[$key]++))`. Perfect for "how many errors per server?".

</En>
<Ur>

Keys ko **qismen** aur values ko **counters** banayen: `((count[$key]++))`. "Har server par kitne errors?" ke liye behtareen.

</Ur>
</Tr>

```bash
declare -A errors=()
while read -r server level; do
  [[ $level == ERROR ]] && ((errors[$server]++))
done <<'EOF'
web-1 ERROR
web-2 INFO
web-1 ERROR
db-1 ERROR
web-1 WARN
EOF
for s in $(printf '%s\n' "${!errors[@]}" | sort); do
  echo "$s: ${errors[$s]} error(s)"
done
```

```text output
db-1: 1 error(s)
web-1: 2 error(s)
```

</Step>

<Step title="Limits to know">

<Tr>
<En>

- **No nested arrays** (no array inside an array).
- Arrays **can't be exported** to child programs.
- `declare -A` needs **Bash 4+** (not macOS's old Bash 3.2).
- For complex data like JSON, use `jq` (later lesson) or switch to Python.

</En>
<Ur>

- **Array ke andar array nahi** (nested nahi).
- Arrays child programs ko **export nahi** ho sakte.
- `declare -A` ko **Bash 4+** chahiye (macOS ka purana Bash 3.2 nahi).
- JSON jaise pecheeda data ke liye `jq` (agla lesson) ya Python istemal karein.

</Ur>
</Tr>

</Step>

</Walkthrough>

## Common mistakes

<Compare>
<Bad title="$arr instead of all items">

```text
echo $servers       # only the FIRST item
```

</Bad>
<Good title="All items, quoted">

```text
printf '%s\n' "${servers[@]}"
```

</Good>
</Compare>

<Compare>
<Bad title="Forgetting declare -A">

```text
port[db]=5432       # Bash makes a normal array; every text key becomes index 0
```

</Bad>
<Good title="Declare first">

```text
declare -A port
port[db]=5432
```

</Good>
</Compare>

<Compare>
<Bad title="A command in a string">

```text
cmd="rsync -a --exclude 'my uploads' src/ dst/"
$cmd                # the quotes don't work inside the string
```

</Bad>
<Good title="A command in an array">

```text
cmd=(rsync -a --exclude "my uploads" src/ dst/)
"${cmd[@]}"
```

</Good>
</Compare>

<Challenge title="Array lab">

<Tr>
<En>
This lab covers the basics, a loop with positions, loading a file, an associative lookup, and collecting failures.
</En>
<Ur>
Ye lab bunyadi baaten, jagah ke saath loop, file load karna, associative talash, aur failures jama karna aazmata hai.

```bash
mkdir -p ~/array-lab && cd ~/array-lab

# indexed array basics
envs=(dev staging prod)
echo "count=${#envs[@]} first=${envs[0]} last=${envs[-1]}"
envs+=(dr)
echo "all: ${envs[*]}"

# loop with positions
for i in "${!envs[@]}"; do printf '%d:%s ' "$i" "${envs[$i]}"; done; echo

# file into array
printf 'nginx\npostgresql\nredis\n' > pkgs.txt
mapfile -t pkgs < pkgs.txt
echo "would run: apt-get install -y ${pkgs[*]}"

# associative lookup
declare -A url=([dev]=http://localhost:3000 [prod]=https://shop.example.com)
target=prod
echo "deploying to ${url[$target]}"

# collect failures
failed=()
for s in web-1 web-2 web-3; do [[ $s == web-3 ]] && failed+=("$s"); done
(( ${#failed[@]} == 0 )) && echo "all ok" || echo "failed: ${failed[*]}"

cd ~ && rm -rf ~/array-lab
```


## Remember

<Takeaways>
<Tr>
<En>

- `arr=(a b "c d")`; counting starts at **0**; `${arr[0]}`, `${arr[-1]}`.
- `"${arr[@]}"` all items (quoted!), `${#arr[@]}` count, `${!arr[@]}` indexes.
- `arr+=(x)` add, `arr[1]=y` change, `unset 'arr[1]'` remove (leaves a gap).
- `"${arr[@]:0:2}"` slice.

- Build commands in arrays: `cmd "${opts[@]}"`.
- `declare -A map`; `${map[key]}`; `[[ -v map[key] ]]`; no fixed order.
- No nested arrays; for JSON use `jq`.

<DeepDive title="Real world: deploying to three servers">

A small company runs a Node.js app on three servers. The deploy script loops over an array of hosts, builds the `rsync` options as an array, and tracks results in an associative array:

```bash
#!/usr/bin/env bash
set -euo pipefail

hosts=(web-01.internal web-02.internal web-03.internal)
rsync_opts=(-az --delete --exclude ".env" --exclude "node_modules")
[[ ${DRY_RUN:-0} == 1 ]] && rsync_opts+=(--dry-run --itemize-changes)

declare -A result=()

for host in "${hosts[@]}"; do
  echo "▶ $host"
  if rsync "${rsync_opts[@]}" dist/ "deploy@${host}:/srv/app/" \
     && ssh "deploy@${host}" 'sudo systemctl restart app' \
     && curl -fsS --max-time 5 "http://${host}:3000/api/health" > /dev/null; then
    result[$host]="ok"
  else
    result[$host]="FAILED"
  fi
done

echo; echo "Summary:"
failed=0
for host in "${hosts[@]}"; do                       # iterate the indexed array to keep order
  printf '  %-20s %s\n' "$host" "${result[$host]}"
  [[ ${result[$host]} == ok ]] || failed=1
done
exit "$failed"
```

The script exits non-zero if any host failed, so CI marks the deploy red, and prints a clear per-host summary.

Other mistakes: relying on associative array order; using `for i in $(cat file)` instead of `mapfile -t` or `while read -r`; and assuming macOS's Bash 3.2 supports `declare -A`.

</DeepDive>

<DeepDive title="Security lens">

Arrays are the safe way to pass untrusted values to commands: every element stays one argument, with no re-parsing by the shell.

- **Prefer arrays over `eval` and string-built commands**: they remove the main reason people reach for `eval`, which is a code-injection risk.
- **Still validate elements** that come from input or files before using them as hosts, paths or options; an element starting with `-` is still an option to the target command, so add `--` where supported.
- **Associative array keys from untrusted input** used inside `(( ))` are evaluated as arithmetic: the same injection risk as the previous lesson (`hits[$ip]` is fine for real IPs; validate first if attackers control the data).
- **Host lists are sensitive:** whoever can edit the array (or the file it's loaded from) of a root deploy script decides where your code and secrets go. Keep such lists in version control with review.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="How do you loop over all elements of a Bash array, safely?">
Use `for item in "${arr[@]}"; do …; done`. The quoted [@] expansion produces each element as a separate word exactly as stored, including spaces. Unquoted `${arr[@]}` or `${arr[*]}` would re-split elements on whitespace and expand wildcards.
</QA>

<QA q="What is an associative array in Bash, and how do you declare one?">
An associative array maps string keys to values, like a dictionary. It must be declared with `declare -A name` (Bash 4+), then used as name[key]=value and "`${name[key]}`". "`${!name[@]}`" lists the keys and "`${name[@]}`" the values; key order is unspecified.
</QA>

<QA q="Why build command arguments in an array instead of a string?">
A string is re-split on whitespace when expanded, and quotes inside it are just characters, so arguments containing spaces or special characters break. An array stores each argument separately, and "`${arr[@]}`" passes them to the command exactly, so you can add options conditionally without quoting bugs or resorting to eval.
</QA>

<QA q="How do you read a file's lines into an array?">
Use `mapfile -t lines < file` (or readarray), which stores one line per element and strips the trailing newlines with -t. For command output use process substitution: `mapfile -t lines < <(command)`. For NUL-separated data such as find -print0, use `mapfile -d '' -t`.
</QA>

</DeepDive>
