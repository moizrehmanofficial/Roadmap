<Callout type="tip" title="In one minute">
An **array** is one variable that holds a **list**: `servers=(web-1 web-2 db-1)`. Read one item by its position (starting at 0): `${servers[0]}`; all items: `"${servers[@]}"`; the count: `${#servers[@]}`; add one: `servers+=(cache-1)`. An **associative array** holds **key → value** pairs: `declare -A port=([web]=80 [db]=5432)`, read with `${port[db]}`. Always loop with `for s in "${servers[@]}"` — with the quotes.
</Callout>

## Start from zero

### One variable, many values

So far, one variable held one value: `server="web-1"`. But scripts usually deal with **lists**: 10 servers, 50 files, 5 packages to install. Creating `server1`, `server2`, `server3`… is clumsy and you cannot loop over them easily.

<Callout type="analogy">
An **array** is a train: one train (the variable) with numbered carriages (positions 0, 1, 2…), and each carriage carries one passenger (a value). You can say "carriage 2", "how many carriages?", "every passenger, please step out", or "attach one more carriage".

An **associative array** is a row of labelled lockers at a gym: instead of numbers, each locker has a **name** on it — "Sam", "Emma" — and you open a locker by its name.
</Callout>

### Words you need first

| Word | Simple meaning | Example |
| --- | --- | --- |
| **Array** | A variable holding a numbered list of values | `servers=(web-1 web-2)` |
| **Element / item** | One value in the array | `web-2` |
| **Index** | The position number of an item, **starting at 0** | `0` is the first item |
| **Associative array** | A variable holding named keys, each with a value | `port[db]=5432` |
| **Key** | The name used to look up a value | `db` |
| **Append** | Add to the end | `servers+=(db-1)` |
| **Slice** | A part of the array | items 1 to 2 |

## What is it?

- An **indexed array** stores values at numbered positions 0, 1, 2… Created with `name=(value1 value2 …)`.
- An **associative array** stores values under **text keys**. Created with `declare -A name`.

Both keep each value **separate**, even if it contains spaces — which plain text variables cannot do.

## Why does it matter?

- **Lists are everywhere** in automation: hosts, regions, files, packages, users, ports.
- **Spaces-safe:** an array item `"db primary"` stays one item. A space-separated string would break it in two.
- **Building commands safely:** collecting options in an array avoids the quoting bugs of building command strings.
- **Lookups:** associative arrays answer "what's the port of service X?" or "what's the URL of environment Y?" in one step.

## When and where do you use it?

| Need | Use |
| --- | --- |
| A list of servers, files, packages | Indexed array |
| Options/arguments built up step by step | Indexed array |
| Lines of a file kept in memory | `mapfile -t lines < file` |
| Name → value lookup (service → port, env → URL) | Associative array |
| Counting things per category | Associative array |

## Concepts one by one

### 1. Creating an array and reading items

<Explain>
<What>
A list of values inside round brackets, stored in one variable. Each item has an index starting from 0.
</What>
<Why>
To keep related values together and process them as a group.
</Why>
<When>
Whenever you have more than one value of the same kind.
</When>
<Where>
Server lists, file lists, package lists at the top of scripts.
</Where>
<How>
Create: `name=(a b "c d")` — quote items that contain spaces. Read one: `${name[1]}` (braces are required). Read the last: `${name[-1]}`.
</How>
</Explain>

```bash
servers=(web-1 web-2 "db primary")
echo "First:  ${servers[0]}"
echo "Second: ${servers[1]}"
echo "Third:  ${servers[2]}"
echo "Last:   ${servers[-1]}"
```

```text output
First:  web-1
Second: web-2
Third:  db primary
Last:   db primary
```

```text
index:   [0]      [1]      [2]
value:   web-1    web-2    db primary
```

<Callout type="warning" title="Counting starts at 0">
The first item is `[0]`, not `[1]`. An array with 3 items has indexes 0, 1, 2.
</Callout>

### 2. All items and the count

<Explain>
<What>
`"${array[@]}"` gives every item, each kept separate. `${#array[@]}` gives how many items there are. `${!array[@]}` gives all the indexes.
</What>
<Why>
Most of the time you want to do something with **every** item, or check how many there are.
</Why>
<When>
Loops, passing the list to a command, checking for an empty list.
</When>
<Where>
Everywhere arrays are used.
</Where>
<How>
Always use the quoted form `"${array[@]}"`.
</How>
</Explain>

```bash
packages=(git curl "build-essential" jq)
echo "Number of packages: ${#packages[@]}"
echo "All: ${packages[*]}"
echo "Indexes: ${!packages[*]}"
```

```text output
Number of packages: 4
All: git curl build-essential jq
Indexes: 0 1 2 3
```

### 3. Looping over an array

<Explain>
<What>
Using `for` to visit each item in turn.
</What>
<Why>
To perform the same action for every item: ping every server, install every package.
</Why>
<When>
Almost every time you have an array.
</When>
<Where>
Health checks, deploys, setup scripts.
</Where>
<How>
`for item in "${array[@]}"; do …; done`. To know the position as well, loop over the indexes: `for i in "${!array[@]}"`.
</How>
</Explain>

```bash
servers=(web-1 web-2 "db primary")
for s in "${servers[@]}"; do
  echo "Checking: $s"
done
for i in "${!servers[@]}"; do
  echo "#$((i + 1)) is ${servers[$i]}"
done
```

```text output
Checking: web-1
Checking: web-2
Checking: db primary
#1 is web-1
#2 is web-2
#3 is db primary
```

### 4. `"${arr[@]}"` vs `${arr[@]}` vs `"${arr[*]}"`

<Explain>
<What>
Three ways of expanding all items, which differ in how they treat spaces.
</What>
<Why>
Using the wrong one splits items like `"db primary"` into two, or merges everything into one string.
</Why>
<When>
Every time you use all items.
</When>
<Where>
Loops and command arguments.
</Where>
<How>
`"${arr[@]}"` — each item stays separate (**use this**). `${arr[@]}` unquoted — items split again at spaces. `"${arr[*]}"` — all items joined into **one** string (good for printing).
</How>
</Explain>

```bash
arr=(one "two words" three)
echo "Quoted [@]:";   printf '  <%s>\n' "${arr[@]}"
echo "Unquoted [@]:"; printf '  <%s>\n' ${arr[@]}
echo "Quoted [*]:";   printf '  <%s>\n' "${arr[*]}"
```

```text output
Quoted [@]:
  <one>
  <two words>
  <three>
Unquoted [@]:
  <one>
  <two>
  <words>
  <three>
Quoted [*]:
  <one two words three>
```

### 5. Adding, changing and removing items

<Explain>
<What>
Arrays can grow, have items replaced, or have items deleted.
</What>
<Why>
Lists are often built up as the script runs — for example, collecting failed servers.
</Why>
<When>
Collecting results, building lists conditionally.
</When>
<Where>
Health checks ("failed=()"), file collection, option building.
</Where>
<How>
Append: `arr+=(new)`. Replace: `arr[1]=other`. Delete: `unset 'arr[1]'` (this leaves a gap in the indexes). Empty the array: `arr=()`.
</How>
</Explain>

```bash
failed=()
for s in web-1 web-2 web-3 db-1; do
  if [[ $s == web-2 || $s == db-1 ]]; then
    failed+=("$s")
  fi
done
echo "Failed: ${failed[*]} (${#failed[@]} servers)"

failed[0]="WEB-2"
echo "After change: ${failed[*]}"
unset 'failed[0]'
echo "After unset: ${failed[*]}  indexes left: ${!failed[*]}"
```

```text output
Failed: web-2 db-1 (2 servers)
After change: WEB-2 db-1
After unset: db-1  indexes left: 1
```

Notice the gap: after removing index 0, the remaining item is still at index 1. That is why loops should use `"${arr[@]}"`, not counting from 0.

### 6. Slicing: taking part of an array

<Explain>
<What>
`"${arr[@]:start:count}"` returns `count` items starting from position `start`.
</What>
<Why>
To skip the first item, take the first N, or process in batches.
</Why>
<When>
Processing a list in groups, ignoring a header.
</When>
<Where>
Batch deploys ("first 2 servers, then the rest"), argument handling.
</Where>
<How>
`"${arr[@]:1}"` = everything except the first. `"${arr[@]:0:2}"` = the first two.
</How>
</Explain>

```bash
hosts=(h1 h2 h3 h4 h5)
echo "Canary (first 2): ${hosts[*]:0:2}"
echo "Rest:             ${hosts[*]:2}"
```

```text output
Canary (first 2): h1 h2
Rest:             h3 h4 h5
```

### 7. Reading lines of a file into an array

<Explain>
<What>
`mapfile -t name < file` (also called `readarray`) reads every line of a file into an array, one line per item.
</What>
<Why>
Lists of hosts, users or packages are often kept in a text file, one per line.
</Why>
<When>
Loading a list from a file or from a command's output.
</When>
<Where>
Inventory files, allow-lists, results of `find` or `grep`.
</Where>
<How>
`mapfile -t hosts < hosts.txt`. `-t` removes the newline at the end of each line. From a command: `mapfile -t files < <(find . -name "*.log")`.
</How>
</Explain>

```bash
printf 'web-1\nweb-2\ndb primary\n' > hosts.txt
mapfile -t hosts < hosts.txt
echo "Loaded ${#hosts[@]} hosts"
echo "Third host: ${hosts[2]}"
```

```text output
Loaded 3 hosts
Third host: db primary
```

### 8. Splitting one string into an array

<Explain>
<What>
Turning a string like `"web-1,web-2,db-1"` into an array of separate items.
</What>
<Why>
Lists often arrive as one string: an environment variable, a CSV field, a command-line option.
</Why>
<When>
Reading comma- or colon-separated values.
</When>
<Where>
`SERVERS="a,b,c"` in CI settings, `PATH` (colon-separated).
</Where>
<How>
`IFS=, read -r -a arr <<< "$string"` — `IFS=,` splits at commas, `-a arr` stores the parts in an array, `<<<` feeds the string in.
</How>
</Explain>

```bash
SERVERS="web-1,web-2,db-1"
IFS=, read -r -a list <<< "$SERVERS"
echo "Count: ${#list[@]}"
printf ' - %s\n' "${list[@]}"

IFS=: read -r -a dirs <<< "/usr/local/bin:/usr/bin:/bin"
echo "First PATH folder: ${dirs[0]}"
```

```text output
Count: 3
 - web-1
 - web-2
 - db-1
First PATH folder: /usr/local/bin
```

### 9. Building commands safely with arrays

<Explain>
<What>
Collecting a command's options in an array and then running `command "${opts[@]}"`.
</What>
<Why>
Building a command as one **string** breaks as soon as a value contains a space or a quote. An array keeps each argument exact.
</Why>
<When>
When options depend on conditions (verbose, dry-run, extra excludes).
</When>
<Where>
Wrappers around `rsync`, `tar`, `curl`, `docker`, `kubectl`.
</Where>
<How>
`opts=(-a)`, then `opts+=(--exclude "my folder")` when needed, then `rsync "${opts[@]}" src/ dest/`.
</How>
</Explain>

```bash
show_args() { printf '  arg: <%s>\n' "$@"; }

dry_run=true
opts=(-a --delete)
$dry_run && opts+=(--dry-run)
opts+=(--exclude "my uploads")

echo "With an array:"
show_args "${opts[@]}"

echo "With a string (broken):"
opts_string="-a --exclude my uploads"
show_args $opts_string
```

```text output
With an array:
  arg: <-a>
  arg: <--delete>
  arg: <--dry-run>
  arg: <--exclude>
  arg: <my uploads>
With a string (broken):
  arg: <-a>
  arg: <--exclude>
  arg: <my>
  arg: <uploads>
```

### 10. Associative arrays: key → value

<Explain>
<What>
An array whose items are found by a **name** (key) instead of a number. It must be declared first with `declare -A`.
</What>
<Why>
For lookups: "what is the port of `db`?", "what is the URL for `staging`?" — no searching needed.
</Why>
<When>
Mapping names to settings, counting per category.
</When>
<Where>
Service → port tables, environment → URL tables, counting errors per server.
</Where>
<How>
`declare -A port=([web]=80 [db]=5432)`. Read `${port[db]}`. Add `port[cache]=6379`. All keys: `"${!port[@]}"`. Check a key exists: `[[ -v port[web] ]]`.
</How>
</Explain>

```bash
declare -A port=([web]=80 [db]=5432 [cache]=6379)
echo "Database port: ${port[db]}"
port[api]=3000
echo "Services: ${#port[@]}"
for name in $(printf '%s\n' "${!port[@]}" | sort); do
  echo "  $name → ${port[$name]}"
done
[[ -v port[web] ]] && echo "web is defined"
[[ -v port[mail] ]] || echo "mail is not defined"
```

```text output
Database port: 5432
Services: 4
  api → 3000
  cache → 6379
  db → 5432
  web → 80
web is defined
mail is not defined
```

Associative arrays have **no fixed order**, so the keys were sorted before printing.

### 11. Counting with an associative array

<Explain>
<What>
Using keys as categories and values as counters.
</What>
<Why>
"How many errors per server?" is a constant question in log analysis.
</Why>
<When>
Grouping and counting lines by some field.
</When>
<Where>
Log summaries, inventory reports.
</Where>
<How>
`((count[$key]++))` inside a loop over the lines.
</How>
</Explain>

```bash
declare -A errors=()
while read -r server level; do
  [[ $level == ERROR ]] && ((errors[$server]++))
done <<'EOF'
web-1 ERROR
web-2 INFO
web-1 ERROR
db-1 ERROR
web-1 WARN
EOF
for s in $(printf '%s\n' "${!errors[@]}" | sort); do
  echo "$s: ${errors[$s]} error(s)"
done
```

```text output
db-1: 1 error(s)
web-1: 2 error(s)
```

### 12. Limits to know

<Explain>
<What>
Things Bash arrays cannot do.
</What>
<Why>
So you know when to switch to a better tool.
</Why>
<When>
When your data gets complex.
</When>
<Where>
Large or nested data.
</Where>
<How>
No nested arrays (an array inside an array). Cannot be exported to child programs. `declare -A` needs Bash 4+ (not the old Bash 3.2 on macOS). For complex data like JSON, use `jq` (later lesson) or switch to Python.
</How>
</Explain>

## Hands-on

```bash
mkdir -p ~/array-lab && cd ~/array-lab

# indexed array basics
envs=(dev staging prod)
echo "count=${#envs[@]} first=${envs[0]} last=${envs[-1]}"
envs+=(dr)
echo "all: ${envs[*]}"

# loop with positions
for i in "${!envs[@]}"; do printf '%d:%s ' "$i" "${envs[$i]}"; done; echo

# file into array
printf 'nginx\npostgresql\nredis\n' > pkgs.txt
mapfile -t pkgs < pkgs.txt
echo "would run: apt-get install -y ${pkgs[*]}"

# associative lookup
declare -A url=([dev]=http://localhost:3000 [prod]=https://shop.example.com)
target=prod
echo "deploying to ${url[$target]}"

# collect failures
failed=()
for s in web-1 web-2 web-3; do [[ $s == web-3 ]] && failed+=("$s"); done
(( ${#failed[@]} == 0 )) && echo "all ok" || echo "failed: ${failed[*]}"

cd ~ && rm -rf ~/array-lab
```

```text output
count=3 first=dev last=prod
all: dev staging prod dr
0:dev 1:staging 2:prod 3:dr 
would run: apt-get install -y nginx postgresql redis
deploying to https://shop.example.com
failed: web-3
```

## Real-world example

A small company runs a Node.js app on three servers. The deploy script loops over an array of hosts, builds the `rsync` options as an array, and tracks results in an associative array:

```bash
#!/usr/bin/env bash
set -euo pipefail

hosts=(web-01.internal web-02.internal web-03.internal)
rsync_opts=(-az --delete --exclude ".env" --exclude "node_modules")
[[ ${DRY_RUN:-0} == 1 ]] && rsync_opts+=(--dry-run --itemize-changes)

declare -A result=()

for host in "${hosts[@]}"; do
  echo "▶ $host"
  if rsync "${rsync_opts[@]}" dist/ "deploy@${host}:/srv/app/" \
     && ssh "deploy@${host}" 'sudo systemctl restart app' \
     && curl -fsS --max-time 5 "http://${host}:3000/api/health" > /dev/null; then
    result[$host]="ok"
  else
    result[$host]="FAILED"
  fi
done

echo; echo "Summary:"
failed=0
for host in "${hosts[@]}"; do                       # iterate the indexed array to keep order
  printf '  %-20s %s\n' "$host" "${result[$host]}"
  [[ ${result[$host]} == ok ]] || failed=1
done
exit "$failed"
```

The script exits non-zero if any host failed — so CI marks the deploy red — and prints a clear per-host summary.

## Common mistakes

- **Unquoted `${arr[@]}`** — splits elements with spaces.
- **`$arr`** instead of `"${arr[@]}"` — gives only the first element.
- **Forgetting `declare -A`** — Bash silently creates an indexed array and every string key becomes index 0.
- **Storing a command in a string** instead of an array, then fighting with quotes.
- **Relying on associative array order** — it is unspecified.
- **`for i in $(cat file)`** instead of `mapfile -t` or `while read -r`.
- **Assuming macOS's Bash 3.2** supports `declare -A`.

## Security lens

<Callout type="security">
Arrays are the safe way to pass untrusted values to commands: every element stays one argument, with no re-parsing by the shell.
</Callout>

- **Prefer arrays over `eval` and string-built commands** — they remove the main reason people reach for `eval`, which is a code-injection risk.
- **Still validate elements** that come from input or files before using them as hosts, paths or options; an element starting with `-` is still an option to the target command, so add `--` where supported.
- **Associative array keys from untrusted input** used inside `(( ))` are evaluated as arithmetic — the same injection risk as the previous lesson (`hits[$ip]` is fine for real IPs; validate first if the data is attacker-controlled).
- **Host lists are sensitive:** an attacker who can edit the array (or the file it is loaded from) of a root deploy script decides where your code and secrets go. Keep such lists in version control with review.

## Interview questions

<QA q="How do you loop over all elements of a Bash array, safely?">
Use `for item in "${arr[@]}"; do …; done`. The quoted [@] expansion produces each element as a separate word exactly as stored, including spaces. Unquoted `${arr[@]}` or `${arr[*]}` would re-split elements on whitespace and expand wildcards.
</QA>

<QA q="What is an associative array in Bash, and how do you declare one?">
An associative array maps string keys to values, like a dictionary. It must be declared with `declare -A name` (Bash 4+), then used as name[key]=value and "`${name[key]}`". "`${!name[@]}`" lists the keys and "`${name[@]}`" the values; key order is unspecified.
</QA>

<QA q="Why build command arguments in an array instead of a string?">
A string is re-split on whitespace when expanded, and quotes inside it are just characters, so arguments containing spaces or special characters break. An array stores each argument separately, and "`${arr[@]}`" passes them to the command exactly, so you can add options conditionally without quoting bugs or resorting to eval.
</QA>

<QA q="How do you read a file's lines into an array?">
Use `mapfile -t lines < file` (or readarray), which stores one line per element and strips the trailing newlines with -t. For command output use process substitution: `mapfile -t lines < <(command)`. For NUL-separated data such as find -print0, use `mapfile -d '' -t`.
</QA>
