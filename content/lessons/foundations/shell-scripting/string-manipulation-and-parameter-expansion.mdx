<Callout type="tip" title="In one minute">
**Parameter expansion** works on a variable's value inside `${…}`. The ones you will use every week: `${var:-default}` (fallback), `${var:?message}` (required), `${#var}` (length), `${var#prefix}` / `${var%suffix}` (strip), `${var//old/new}` (replace all), `${var:0:7}` (substring), `${var^^}` / `${var,,}` (upper/lower case). Remember: `#` removes from the **front**, `%` from the **end** (on a keyboard, # is left of $, % is right of it).
</Callout>

## What is it?

Normally `$var` just inserts the value. Inside `${…}` you can transform it on the way:

```bash
file="/var/log/nginx/access.log.2.gz"

echo "${file##*/}"      # access.log.2.gz      — file name (like basename)
echo "${file%/*}"       # /var/log/nginx       — directory (like dirname)
echo "${file%.gz}"      # /var/log/nginx/access.log.2
echo "${file%%.*}"      # /var/log/nginx/access — everything before the FIRST dot
echo "${#file}"         # 31                   — length
```

### The full cheat sheet

**Defaults and checks**

| Form | If `var` is unset or empty | Otherwise |
| --- | --- | --- |
| `${var:-default}` | Use `default` (var unchanged) | Value of var |
| `${var:=default}` | Assign `default` to var and use it | Value of var |
| `${var:?message}` | Print `message` and **exit** | Value of var |
| `${var:+alt}` | Empty | Use `alt` |

(Without the colon — `${var-default}` — only **unset** triggers it; an empty value is kept. You almost always want the colon.)

**Length and substrings**

| Form | Result for `s="DevSecOps"` |
| --- | --- |
| `${#s}` | `9` |
| `${s:3}` | `SecOps` (from index 3) |
| `${s:3:3}` | `Sec` (3 characters from index 3) |
| `${s: -3}` | `Ops` (last 3 — note the space before `-`) |
| `${s:0:-3}` | `DevSec` (drop last 3) |

**Removing prefixes and suffixes** (patterns use glob syntax: `*`, `?`, `[…]`)

| Form | Removes | `p="backup.2026.tar.gz"` |
| --- | --- | --- |
| `${p#*.}` | Shortest match from the **front** | `2026.tar.gz` |
| `${p##*.}` | Longest match from the front | `gz` (the extension) |
| `${p%.*}` | Shortest match from the **end** | `backup.2026.tar` |
| `${p%%.*}` | Longest match from the end | `backup` |

**Replacing**

| Form | Replaces | `t="a-b-c"` |
| --- | --- | --- |
| `${t/-/_}` | First match | `a_b-c` |
| `${t//-/_}` | All matches | `a_b_c` |
| `${t/#a/X}` | Match at the start | `X-b-c` |
| `${t/%c/X}` | Match at the end | `a-b-X` |
| `${t//-/}` | Delete all matches | `abc` |

**Case** (Bash 4+)

| Form | `n="moiz Rehman"` |
| --- | --- |
| `${n^}` | `Moiz Rehman` (first character upper) |
| `${n^^}` | `MOIZ REHMAN` |
| `${n,,}` | `moiz rehman` |

**Indirection**

| Form | Meaning |
| --- | --- |
| `${!name}` | Value of the variable whose **name** is stored in `name` |
| `${!prefix*}` | Names of all variables starting with `prefix` |

## Why does it matter?

- **Speed:** each `$(basename …)`, `$(echo … | sed …)` or `$(echo … | tr …)` starts a new process. In a loop over 10,000 files that is 10,000 processes; `${file##*/}` costs nothing.
- **Safety:** `${VAR:?}` stops scripts before an empty variable deletes the wrong directory; `${PORT:-3000}` gives sane defaults.
- **Everyday tasks:** changing file extensions, extracting versions from tags (`v1.4.2` → `1.4.2`), building names, normalising input case, trimming paths — all one expansion.

## When and where do you use it?

- Config with defaults: `env="${DEPLOY_ENV:-staging}"`.
- Required settings: `: "${AWS_REGION:?set AWS_REGION}"`.
- Renaming in bulk: `mv "$f" "${f%.jpeg}.jpg"`.
- Tags and versions: `version="${GITHUB_REF_NAME#v}"`.
- Short commit IDs: `"${GITHUB_SHA:0:7}"`.
- Case-insensitive input: `case "${answer,,}" in y|yes) …`.
- Safe Docker tags: `"${branch//\//-}"` (replace `/` with `-`).

## How does it work?

### Patterns, not regex

`#`, `%` and `/` use **glob patterns** — the same as file names: `*` (anything), `?` (one character), `[0-9]` (one of). For real regular expressions, use `[[ $var =~ regex ]]` and `BASH_REMATCH`:

```bash
tag="release-v2.14.3"
if [[ $tag =~ v([0-9]+)\.([0-9]+)\.([0-9]+)$ ]]; then
  major="${BASH_REMATCH[1]}"; minor="${BASH_REMATCH[2]}"; patch="${BASH_REMATCH[3]}"
  echo "next patch: v$major.$minor.$(( patch + 1 ))"
fi
```

### Shortest vs longest

One character = **shortest** match, doubled = **longest**:

```text
p = backup.2026.tar.gz
${p%.*}   → remove shortest ".*" from end   → backup.2026.tar
${p%%.*}  → remove longest  ".*" from end   → backup
${p#*.}   → remove shortest "*." from front → 2026.tar.gz
${p##*.}  → remove longest  "*." from front → gz
```

### Trimming whitespace without external tools

```bash
s="   hello world   "
s="${s#"${s%%[![:space:]]*}"}"   # trim leading
s="${s%"${s##*[![:space:]]}"}"   # trim trailing
echo "[$s]"                      # [hello world]
```

(It looks cryptic — copy it as a function `trim()` once and reuse. For readability, `xargs` or `sed` are fine outside hot loops.)

### Defaults vs required — decide deliberately

```bash
log_level="${LOG_LEVEL:-info}"                  # optional: sensible default
: "${DATABASE_URL:?DATABASE_URL is required}"   # mandatory: fail fast
backup_dir="${BACKUP_DIR:-/var/backups/app}"
```

The `:` command does nothing; it is used here only so the expansion (and its check) runs.

### printf for formatting

`echo` is fine for simple text; `printf` gives control and is portable:

```bash
printf '%-12s %6s %s\n' "SERVICE" "PORT" "STATUS"
printf '%-12s %6d %s\n' "nginx" 443 "running" "postgres" 5432 "running"
printf '%05d\n' 42                 # 00042
printf '%.2f\n' 3.14159            # 3.14
printf -v padded '%03d' 7          # store into a variable: padded=007
printf '%q\n' "it's a \"test\""    # shell-escaped — safe to paste into a command
```

## Hands-on

```bash
# Paths
f="/srv/app/releases/2026-11-10/app.tar.gz"
echo "name:  ${f##*/}"
echo "dir:   ${f%/*}"
echo "ext:   ${f##*.}"
echo "stem:  ${f%%.*}"
echo "len:   ${#f}"

# Defaults and required
unset PORT; echo "port: ${PORT:-3000}"
PORT=8080;  echo "port: ${PORT:-3000}"
bash -c ': "${API_KEY:?API_KEY must be set}"; echo "never printed"' 2>&1

# Substrings and versions
sha="ce072a5f1b9d4e8a"; echo "short sha: ${sha:0:7}"
ref="v2.14.3";          echo "version: ${ref#v}"
branch="feature/login-page"; echo "docker-safe: ${branch//\//-}"

# Case
answer="YeS"
case "${answer,,}" in y|yes) echo "confirmed";; *) echo "cancelled";; esac
name="moiz"; echo "Hello, ${name^}"

# Bulk rename .jpeg → .jpg, without any external command
mkdir -p ~/pe-lab && cd ~/pe-lab && touch a.jpeg b.jpeg "c d.jpeg"
for img in *.jpeg; do mv -- "$img" "${img%.jpeg}.jpg"; done; ls

# Speed: parameter expansion vs basename in a loop
time (for i in $(seq 2000); do x="${f##*/}"; done)
time (for i in $(seq 2000); do x="$(basename "$f")"; done)

# Regex with BASH_REMATCH
line='2026-11-10T04:15:33Z ERROR payment failed order=A1029 user=u_42'
if [[ $line =~ order=([A-Z0-9]+)\ user=([a-z0-9_]+) ]]; then
  echo "order ${BASH_REMATCH[1]} for ${BASH_REMATCH[2]}"
fi

# printf table
printf '%-10s %6s\n' SERVICE PORT nginx 443 postgres 5432 redis 6379

cd ~ && rm -rf ~/pe-lab
```

The same transformations in JavaScript, for comparison:

```javascript
const f = "/srv/app/releases/2026-11-10/app.tar.gz";
console.log("name:", f.split("/").pop());                       // ${f##*/}
console.log("dir:", f.slice(0, f.lastIndexOf("/")));            // ${f%/*}
console.log("ext:", f.slice(f.lastIndexOf(".") + 1));           // ${f##*.}
console.log("stem:", f.slice(0, f.indexOf(".")));               // ${f%%.*}
console.log("port:", globalThis.process?.env?.PORT ?? "3000");             // ${PORT:-3000}
console.log("docker-safe:", "feature/login-page".replaceAll("/", "-")); // ${b//\//-}
console.log("upper:", "moiz rehman".toUpperCase());             // ${n^^}
```

## Real-world example

A GitHub Actions deploy script derives everything from the environment the runner provides — no hard-coded values, no external tools:

```bash
#!/usr/bin/env bash
set -euo pipefail

: "${GITHUB_SHA:?}" "${GITHUB_REF_NAME:?}" "${REGISTRY:?REGISTRY must be set}"

env="${DEPLOY_ENV:-staging}"                     # default environment
env="${env,,}"                                    # normalise case: "Prod" → "prod"
case "$env" in staging|prod) ;; *) echo "unknown env: $env" >&2; exit 1 ;; esac

short_sha="${GITHUB_SHA:0:7}"
safe_ref="${GITHUB_REF_NAME//\//-}"              # feature/x → feature-x
version="${GITHUB_REF_NAME#v}"                    # v1.4.2 → 1.4.2 (for tag builds)
image="${REGISTRY%/}/api:${safe_ref}-${short_sha}"   # strip a trailing slash from REGISTRY

printf 'Deploying %s to %s (version %s)\n' "$image" "$env" "$version"
```

## Common mistakes

- **Mixing up `#` and `%`** — # trims the front, % trims the end.
- **Forgetting the colon**: `${var-default}` keeps an **empty** value; `${var:-default}` replaces it.
- **`${s:-3}`** (default value "3") instead of **`${s: -3}`** (last 3 characters) — the space matters.
- **Expecting regex** in `${var//pattern/}` — it is a glob. Use `[[ =~ ]]` for regex.
- **Not quoting the pattern part** when it comes from a variable: `${f#"$prefix"}` treats `$prefix` literally; without quotes, `*` in it acts as a wildcard.
- **Case conversion on Bash 3** (macOS default `/bin/bash`) — `${var^^}` needs Bash 4+. Install a newer bash or use `tr`.
- **Calling `basename`/`dirname`/`sed` in tight loops** where an expansion would do.

## Security lens

<Callout type="security">
Parameter expansion is also input handling. The same rules apply: validate, normalise, then use — and fail closed when values are missing.
</Callout>

- **Fail closed:** `${VAR:?}` on every variable used in destructive commands (`rm`, `rsync --delete`, `aws s3 rm`, `kubectl delete`).
- **Normalise before comparing:** lower-case and strip input before allow-list checks (`case "${env,,}" in prod|staging)`), so `PROD` or `Prod ` cannot slip past or be misrouted.
- **Path handling:** `${path##*/}` keeps only the last component — a cheap guard against `../` in user-supplied file names, but still validate the result against an allow-list pattern (`[[ $name =~ ^[A-Za-z0-9._-]+$ ]]`) and reject `.` and `..`.
- **`printf '%q'`** escapes values safely when you must build a command string (for example for `ssh host "…"`).
- **Indirection `${!var}`** with a user-supplied variable name can read any variable in the script — including secrets. Do not use it with untrusted input.

## Interview questions

<QA q="How do you give a Bash variable a default value?">
Use `${VAR:-default}`, which expands to default when VAR is unset or empty without changing VAR, or `${VAR:=default}`, which also assigns it. For mandatory values use `${VAR:?error message}`, which prints the message and exits the script if the variable is unset or empty.
</QA>

<QA q="How do you get a file's name and extension in Bash without calling basename?">
Use parameter expansion: `${path##*/}` removes everything up to the last slash to give the file name, `${path%/*}` gives the directory, `${name##*.}` gives the extension after the last dot, and `${name%.*}` gives the name without its last extension. These run inside the shell with no extra processes.
</QA>

<QA q="What is the difference between `${var#pattern}` and `${var##pattern}`?">
Both remove a matching prefix from the value. A single # removes the shortest match; ## removes the longest match. For example with p=backup.2026.tar.gz, `${p#*.}` gives 2026.tar.gz while `${p##*.}` gives gz. % and %% do the same from the end of the string.
</QA>

<QA q="How do you use a regular expression in Bash and get the captured groups?">
Use the [[ string =~ regex ]] test, with the regex unquoted (or stored in a variable). If it matches, the whole match is in `${BASH_REMATCH[0]}` and each capture group in `${BASH_REMATCH[1]}`, `${BASH_REMATCH[2]}` and so on.
</QA>
