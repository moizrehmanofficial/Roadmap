<Callout type="tip" title="In one minute">
**Command substitution** `$(command)` runs a command and puts its output where you wrote it: `today="$(date +%F)"`. **Arithmetic expansion** `$((…))` does whole-number maths: `$((5 * 3))` → `15`. `(( … ))` on its own line changes variables or compares numbers: `((count++))`, `if (( disk > 80 ))`. Bash only does **whole numbers**; for decimals use `awk` or `bc`.
</Callout>

## Start from zero

### Two everyday needs

1. **Use the result of a command.** You want a backup file named with today's date, like `backup-2026-11-10.tgz`. The date comes from the `date` command — so you need a way to put a command's **output** inside another command.
2. **Do maths.** "Disk is 85% full — is that over 80?", "how many seconds did the backup take?", "add 1 to the retry counter".

<Callout type="analogy">
**Command substitution** is like asking a colleague a question in the middle of writing a letter: "What's today's date?" — they answer "10 November", and you write their answer straight into the letter.

**Arithmetic** is the calculator on your desk. Bash's calculator is simple: it only works with **whole numbers** (no decimals).
</Callout>

### Words you need first

| Word | Simple meaning | Example |
| --- | --- | --- |
| **Output** | The text a command prints | `date +%F` prints `2026-11-10` |
| **Command substitution** | Replacing `$(command)` with that command's output | `"$(whoami)"` → `alex` |
| **Arithmetic** | Maths: adding, subtracting, multiplying, dividing | `$((2 + 3))` |
| **Integer** | A whole number, no decimal point | `5`, `-12`, `2026` |
| **Operator** | A maths or comparison symbol | `+`, `*`, `>`, `==` |
| **Increment** | Add 1 to a variable | `((count++))` |
| **Modulo `%`** | The remainder after division | `10 % 3` → `1` |

## What is it?

- **`$(command)`** — Bash runs the command first, then replaces the whole `$(…)` with what the command printed (trailing newlines are removed).
- **`$((expression))`** — Bash calculates the expression and replaces it with the result.
- **`(( expression ))`** — the same calculator used as a **command**: it can change variables and returns success (true) or failure (false), so it works with `if` and `while`.

## Why does it matter?

- **Dynamic names and values:** dated backups, hostnames in messages, the current Git commit in a build tag.
- **Thresholds and limits:** disk, memory and CPU checks; retry counts; timeouts.
- **Timing:** how long a backup or deploy took.
- **Everywhere in DevOps scripts:** `$(git rev-parse --short HEAD)`, `$(nproc)`, `$(aws sts get-caller-identity …)`.

## When and where do you use it?

| Need | Use | Example |
| --- | --- | --- |
| Store a command's output | `$(…)` | `ip="$(hostname -I)"` |
| Calculate a value | `$((…))` | `total=$((a + b))` |
| Change a counter | `((…))` | `((retries++))` |
| Compare numbers | `((…))` | `if (( usage > 90 ))` |
| Decimals | `awk` or `bc` | `awk 'BEGIN{print 7/2}'` |

## Concepts one by one

### 1. Command substitution `$(…)`

<Explain>
<What>
A way to run a command and use its output as text inside another command or a variable.
</What>
<Why>
Many values you need are produced by commands: the date, the user, the number of CPUs, a file count, a Git commit.
</Why>
<When>
Whenever a value comes from a command.
</When>
<Where>
Variable assignments, file names, messages, conditions.
</Where>
<How>
Write the command inside `$( )`. Put double quotes around it when storing or using it: `"$(command)"`. The old form with backticks `` `command` `` does the same but is harder to read and to nest — prefer `$( )`.
</How>
</Explain>

```bash
user="$(whoami)"
files_here="$(ls /etc | wc -l)"
echo "Logged in as: $user" | sed "s/: .*/: <your user>/"
echo "/etc contains more than 10 files: $(( files_here > 10 ))"
echo "Backup name: backup-$(date +%Y)-XX-XX.tgz"
```

```text output
Logged in as: <your user>
/etc contains more than 10 files: 1
Backup name: backup-2026-XX-XX.tgz
```

- `$(whoami)` — runs `whoami` and stores your user name (hidden here with `sed` because it is different on every computer).
- `$(ls /etc | wc -l)` — a whole pipeline can go inside `$( )`.
- `$(( files_here > 10 ))` — a comparison inside maths gives `1` for true and `0` for false.
- `$(date +%Y)` — the current year inside a file name.

### 2. Command substitution keeps spaces only when quoted

<Explain>
<What>
Like variables, an unquoted `$(…)` is split into words at spaces and newlines.
</What>
<Why>
Multi-line output (like a list of files) gets squashed into one line, and names with spaces break.
</Why>
<When>
Whenever the output can contain spaces or several lines.
</When>
<Where>
Saving lists, file names, messages.
</Where>
<How>
Always quote: `"$(command)"`.
</How>
</Explain>

```bash
lines="$(printf 'first line\nsecond line')"
echo "Quoted keeps lines:"
echo "$lines"
echo "Unquoted squashes them:"
echo $lines
```

```text output
Quoted keeps lines:
first line
second line
Unquoted squashes them:
first line second line
```

### 3. Arithmetic expansion `$((…))`

<Explain>
<What>
Bash's built-in calculator for whole numbers. The result replaces the `$((…))`.
</What>
<Why>
Bash variables are text, so `$a+$b` just joins them. `$((a + b))` really adds.
</Why>
<When>
Totals, sizes, percentages, timestamps, counters.
</When>
<Where>
Monitoring scripts, loops, reports.
</Where>
<How>
`$((expression))`. Inside, you can use variable names **without** `$`. Spaces are allowed and make it readable.
</How>
</Explain>

| Operator | Meaning | Example | Result |
| --- | --- | --- | --- |
| `+` `-` | Add, subtract | `$((10 - 3))` | `7` |
| `*` | Multiply | `$((4 * 5))` | `20` |
| `/` | Divide (whole number, rounds **down**) | `$((7 / 2))` | `3` |
| `%` | Remainder | `$((7 % 2))` | `1` |
| `**` | Power | `$((2 ** 10))` | `1024` |
| `( )` | Group | `$(((2 + 3) * 4))` | `20` |

```bash
price=1500
qty=3
total=$((price * qty))
echo "Total: $total"
echo "Split between 4 people: $((total / 4)) each, remainder $((total % 4))"
echo "With 17% tax: $((total * 117 / 100))"
echo "2 to the power 10: $((2 ** 10))"
```

```text output
Total: 4500
Split between 4 people: 1125 each, remainder 0
With 17% tax: 5265
2 to the power 10: 1024
```

- `price * qty` — no `$` needed inside `$(( ))`.
- `total * 117 / 100` — a trick for percentages with whole numbers: multiply first, then divide, so you do not lose precision.

### 4. `(( … ))` as a command: counters and comparisons

<Explain>
<What>
Double brackets **without** a leading `$`. They run the maths as a command: they can change variables, and they end with success if the result is non-zero (true) or failure if it is zero (false).
</What>
<Why>
Cleaner counters (`((count++))`) and natural-looking number comparisons in `if` and `while`.
</Why>
<When>
Changing a numeric variable, or checking a numeric condition.
</When>
<Where>
Loops, retries, thresholds.
</Where>
<How>
`((count++))` add 1, `((count--))` subtract 1, `((total += 5))` add 5, `if (( a > b ))` compare. Comparison operators: `==`, `!=`, `<`, `<=`, `>`, `>=`, and `&&`, `||` to combine.
</How>
</Explain>

```bash
count=0
((count++))
((count++))
((count += 10))
echo "count = $count"

disk=85
if (( disk > 80 )); then
  echo "Disk warning: ${disk}%"
fi
(( disk > 95 )) || echo "Not critical yet"
```

```text output
count = 12
Disk warning: 85%
Not critical yet
```

### 5. Whole numbers only — decimals need help

<Explain>
<What>
Bash maths cannot handle decimal points. `$((7 / 2))` gives `3`, and `$((1.5 + 1))` is an error.
</What>
<Why>
You will meet decimals in load averages (`0.75`), prices, percentages and durations.
</Why>
<When>
Whenever a value or result can have a decimal part.
</When>
<Where>
CPU load checks, averages, money.
</Where>
<How>
Use `awk` (installed everywhere) or `bc` (may need installing): `awk "BEGIN { print 7 / 2 }"`, `echo "scale=2; 7/2" | bc`.
</How>
</Explain>

```bash
echo "Bash: 7 / 2 = $((7 / 2))"
echo "awk:  7 / 2 = $(awk 'BEGIN { print 7 / 2 }')"
echo "awk with 2 decimals: $(awk 'BEGIN { printf "%.2f", 10 / 3 }')"

load="1.75"
cores=2
if awk -v l="$load" -v c="$cores" 'BEGIN { exit !(l > c * 0.8) }'; then
  echo "Load $load is high for $cores cores"
fi
```

```text output
Bash: 7 / 2 = 3
awk:  7 / 2 = 3.5
awk with 2 decimals: 3.33
Load 1.75 is high for 2 cores
```

- `-v l="$load"` passes a Bash variable into awk safely.
- `exit !(condition)` makes awk exit with 0 when the condition is true, so it works with `if`.

### 6. Dates and time maths

<Explain>
<What>
The `date` command prints dates in any format, and `date +%s` prints the current time as a number of seconds (since 1 January 1970, called a **Unix timestamp**).
</What>
<Why>
Seconds are just numbers, so you can subtract them to measure durations, or compare them to check how old something is.
</Why>
<When>
Dated file names, measuring how long something took, checking expiry.
</When>
<Where>
Backups, logs, deploy timers, certificate checks.
</Where>
<How>
Formats: `%F` = 2026-11-10, `%T` = 14:30:05, `%Y%m%d-%H%M%S` = 20261110-143005. `date -d "7 days ago" +%F` gives an earlier date (GNU/Linux).
</How>
</Explain>

```bash
start=$(date +%s)
sleep 2
end=$(date +%s)
echo "That took $((end - start)) seconds"

echo "Fixed date in different formats:"
date -d "2026-11-10 14:30:05" +"%F | %T | %d/%m/%Y | %A"
date -d "2026-11-10 - 7 days" +"One week earlier: %F"
```

```text output
That took 2 seconds
Fixed date in different formats:
2026-11-10 | 14:30:05 | 10/11/2026 | Tuesday
One week earlier: 2026-11-03
```

Bash also has a built-in timer: `$SECONDS` counts seconds since the script started.

### 7. Human-readable sizes

<Explain>
<What>
Turning a number of bytes into KB, MB or GB.
</What>
<Why>
`3145728` means nothing to a human; `3.0M` does.
</Why>
<When>
Reports about files, backups and disk usage.
</When>
<Where>
Backup scripts, disk reports, upload limits.
</Where>
<How>
`numfmt --to=iec 3145728` → `3.0M`. Or `du -h`, `ls -lh`, `df -h`, which print human sizes directly. For maths, keep the raw bytes and convert only for display.
</How>
</Explain>

```bash
head -c 3145728 /dev/zero > big.bin
bytes=$(stat -c %s big.bin)
echo "Bytes: $bytes"
echo "Human: $(numfmt --to=iec "$bytes")"
echo "MB (whole): $((bytes / 1024 / 1024))"
```

```text output
Bytes: 3145728
Human: 3.0M
MB (whole): 3
```

### 8. Numbers with leading zeros

<Explain>
<What>
Inside `$(( ))`, a number starting with `0` is read as **octal** (base 8). `08` and `09` are invalid in octal and cause an error.
</What>
<Why>
`date +%H` returns hours like `08` and `09` — a classic surprise bug that only appears in the morning.
</Why>
<When>
Using parts of dates and times, or numbers read from files with leading zeros.
</When>
<Where>
Deploy windows, scheduled checks.
</Where>
<How>
Force base 10 with `10#`: `$((10#$hour))`.
</How>
</Explain>

```bash
hour="09"
( echo $((hour + 1)) ) 2>&1 | sed 's/.*: //'
echo "Fixed: $((10#$hour + 1))"
```

```text output
value too great for base (error token is "09")
Fixed: 10
```

## Hands-on

```bash
mkdir -p ~/math-lab && cd ~/math-lab

# command substitution
cores=$(nproc)
echo "CPU cores (at least 1): $(( cores >= 1 ))"
for i in 1 2 3; do echo "file $i" > "f$i.txt"; done
count=$(ls *.txt | wc -l)
echo "Text files: $count"

# arithmetic
used=42; total=50
echo "Used: $(( used * 100 / total ))%"
(( used * 100 / total >= 80 )) && echo "Over 80% — warning"

# counters
retries=0
while (( retries < 3 )); do ((retries++)); done
echo "Retries done: $retries"

# decimals
echo "Average: $(awk 'BEGIN { printf "%.1f", (120 + 95 + 2300) / 3 }') ms"

# leading zeros
for h in 08 09 10; do echo "hour $h → $((10#$h))"; done

cd ~ && rm -rf ~/math-lab
```

```text output
CPU cores (at least 1): 1
Text files: 3
Used: 84%
Over 80% — warning
Retries done: 3
Average: 838.3 ms
hour 08 → 8
hour 09 → 9
hour 10 → 10
```

## Real-world example

A CI job builds and pushes a Docker image, tagging it from Git, timing each step, and failing if the image is too large:

```bash
#!/usr/bin/env bash
set -euo pipefail

sha="$(git rev-parse --short HEAD)"
branch="$(git rev-parse --abbrev-ref HEAD | tr '/' '-')"
stamp="$(date -u +%Y%m%d%H%M)"
tag="${branch}-${stamp}-${sha}"            # main-202611100415-ce072a5

t0=$SECONDS
docker build -t "registry.example.com/api:${tag}" .
echo "build took $(( SECONDS - t0 ))s"

size_bytes="$(docker image inspect "registry.example.com/api:${tag}" --format '{{.Size}}')"
size_mb=$(( size_bytes / 1024 / 1024 ))
echo "image size: ${size_mb} MB"
if (( size_mb > 400 )); then
  echo "✖ Image is larger than 400 MB — check the Dockerfile (multi-stage build? dev dependencies?)" >&2
  exit 1
fi

docker push "registry.example.com/api:${tag}"
echo "pushed ${tag} in $(( SECONDS / 60 ))m $(( SECONDS % 60 ))s total"
```

## Common mistakes

- **Unquoted `$(cmd)`** — output with spaces or `*` breaks the command.
- **Expecting decimals**: `$(( 7 / 2 ))` is 3. Use awk or bc.
- **`(( count++ ))` under `set -e`** when count is 0 — exits the script.
- **Leading zeros**: `$(( 08 + 1 ))` fails — `08` is read as (invalid) octal. Strip zeros or force base 10: `$(( 10#08 + 1 ))`. Common with `date +%m`.
- **Comparing numbers as strings**: `[ "$a" > "$b" ]` is a redirection, and `[[ "$a" > "$b" ]]` compares text ("10" < "9"). Use `(( a > b ))` or `[ "$a" -gt "$b" ]`.
- **Backticks** in new code — hard to read and nest.
- **Ignoring command failures** inside substitutions in older scripts without `set -e`.

## Security lens

<Callout type="security">
Command substitution runs code; arithmetic evaluates expressions. Both can execute more than you intended if untrusted data gets inside.
</Callout>

- **Never substitute untrusted text as code:** `$(echo "$input")` is fine, but `eval "$input"` or `bash -c "… $input …"` executes it.
- **Arithmetic injection:** Bash evaluates array subscripts inside arithmetic, so a value like `a[$(id)]` used in `(( ))` or `$(( ))` **executes `id`**. Never do arithmetic on unvalidated input — check it is a number first: `[[ $n =~ ^[0-9]+$ ]] || exit 1`.
- **Integer overflow:** Bash integers are 64-bit signed; huge values wrap silently. Validate ranges for user-controlled numbers (sizes, counts, ports).
- **Timestamps:** log and name evidence files in **UTC** (`date -u`) so they line up with other systems during an investigation.

## Interview questions

<QA q="What is the difference between $(command) and backticks?">
Both perform command substitution, inserting the command's output with trailing newlines removed. $(command) is the modern POSIX form: it nests without escaping, is easier to read and handles quotes and backslashes more predictably. Backticks are legacy and should be avoided in new scripts.
</QA>

<QA q="How do you do arithmetic in Bash, and what are its limits?">
Use arithmetic expansion $((expression)) to compute a value, or the (( expression )) command for conditions and updates such as (( count++ )). Bash arithmetic is integer-only with 64-bit signed integers, so division truncates; for decimals use awk or bc. Comparisons inside (( )) use normal operators like > and ==.
</QA>

<QA q="Why can (( count++ )) make a script with set -e exit unexpectedly?">
(( )) returns exit status 1 when the expression evaluates to zero. count++ returns the old value, so when count is 0 the expression is 0, the command 'fails', and set -e terminates the script. Use (( ++count )), count=$((count + 1)) or append || true.
</QA>

<QA q="How do you capture a command's output into a variable safely?">
Use var="$(command)" with double quotes, so whitespace is preserved and no globbing happens. Check the command's success (set -e, or if ! var="$(command)"; then …), and for multi-line output that you want to process line by line, use a while read loop or mapfile rather than splitting the variable.
</QA>
