<BigIdea>
<Tr>
<En>
Two everyday needs: **use a command's answer** inside another command (`$(date +%F)` puts today's date into a file name), and **do maths** (`$((used * 100 / total))`). Bash's calculator only knows **whole numbers**; for decimals, ask `awk`.
</En>
<Ur>
Roz ki do zaroortein: kisi command ka **jawab doosri command me istemal karna** (`$(date +%F)` aaj ki tareekh file ke naam me daal deta hai), aur **hisaab karna** (`$((used * 100 / total))`). Bash ka calculator sirf **poore numbers** jaanta hai; decimals ke liye `awk` se poochein.
</Ur>
</Tr>
</BigIdea>

## At a glance

<Glance>
<What>
<Tr>
<En>

- **`$(command)`**: runs the command and puts its output right there. `today="$(date +%F)"`
- **`$((…))`**: whole-number maths. `$((5 * 3))` → `15`
- **`(( … ))`** on its own: changes counters or compares numbers. `((count++))`, `if (( disk > 80 ))`
- **Decimals**: `awk 'BEGIN { print 7 / 2 }'` → `3.5`

</En>
<Ur>

- **`$(command)`**: command chala kar us ka output wahin rakh deta hai. `today="$(date +%F)"`
- **`$((…))`**: poore numbers ka hisaab. `$((5 * 3))` → `15`
- **`(( … ))`** akela: counters badalta ya numbers milata hai. `((count++))`, `if (( disk > 80 ))`
- **Decimals**: `awk 'BEGIN { print 7 / 2 }'` → `3.5`

</Ur>
</Tr>
</What>
<Why>
<Tr>
<En>

- **Dynamic names**: dated backups, the Git commit in a build tag, the server name in a message.
- **Limits and alerts**: "disk 85%, is that over 80?", retry counters, timeouts.
- **Timing**: how long did the backup or deploy take?

</En>
<Ur>

- **Badalte naam**: tareekh wale backups, build tag me Git commit, paigham me server ka naam.
- **Hadden aur alerts**: "disk 85%, kya 80 se zyada hai?", retry counters, timeouts.
- **Waqt**: backup ya deploy me kitna waqt laga?

</Ur>
</Tr>
</Why>
<When>
<Tr>
<En>

| Need | Use | Example |
| --- | --- | --- |
| Store a command's output | `$(…)` | `ip="$(hostname -I)"` |
| Calculate a value | `$((…))` | `total=$((a + b))` |
| Change a counter | `((…))` | `((retries++))` |
| Compare numbers | `((…))` | `if (( usage > 90 ))` |
| Decimals | `awk` or `bc` | `awk 'BEGIN{print 7/2}'` |

</En>
<Ur>

| Zaroorat | Istemal | Misaal |
| --- | --- | --- |
| Command ka output rakhna | `$(…)` | `ip="$(hostname -I)"` |
| Value ka hisaab | `$((…))` | `total=$((a + b))` |
| Counter badalna | `((…))` | `((retries++))` |
| Numbers milana | `((…))` | `if (( usage > 90 ))` |
| Decimals | `awk` ya `bc` | `awk 'BEGIN{print 7/2}'` |

</Ur>
</Tr>
</When>
<How>
<Tr>
<En>

Bash first runs whatever is inside `$( )` or calculates whatever is inside `$(( ))`, then puts the **result** in its place, and only then runs the line.

</En>
<Ur>

Bash pehle `$( )` ke andar wali cheez chalata hai ya `$(( ))` ke andar ka hisaab karta hai, phir us ki jagah **nateeja** rakhta hai, aur sirf phir line chalata hai.

</Ur>
</Tr>
</How>
</Glance>

## Learn it step by step

<Walkthrough>

<Step title="$( ): use a command's output">

<Tr>
<En>

Write the command inside `$( )`, and put **double quotes** around it when you store or use it: `"$(command)"`. A whole pipeline can go inside. (The old form with backticks `` `command` `` does the same, but is harder to read; prefer `$( )`.)

</En>
<Ur>

Command ko `$( )` ke andar likhein, aur rakhte ya istemal karte waqt us ke gird **double quotes** lagayen: `"$(command)"`. Poori pipeline bhi andar ja sakti hai. (Purani shakal backticks `` `command` `` wahi kaam karti hai, lekin parhna mushkil; `$( )` ko tarjeeh dein.)

</Ur>
</Tr>

```bash
user="$(whoami)"
files_here="$(ls /etc | wc -l)"
echo "Logged in as: $user" | sed "s/: .*/: <your user>/"
echo "/etc contains more than 10 files: $(( files_here > 10 ))"
echo "Backup name: backup-$(date +%Y)-XX-XX.tgz"
```

```text output
Logged in as: <your user>
/etc contains more than 10 files: 1
Backup name: backup-2026-XX-XX.tgz
```

<Happened>
<Tr>
<En>

- `$(whoami)` stored your user name (hidden with `sed`, because it's different on every computer).
- `$(ls /etc | wc -l)`: a whole pipeline inside `$( )`.
- `$(( files_here > 10 ))`: a comparison inside maths gives **1 for true**, **0 for false**.
- `$(date +%Y)` put the current year into a file name.

</En>
<Ur>

- `$(whoami)` ne aap ka user naam rakha (`sed` se chhupaya, kyun ke har computer par alag hai).
- `$(ls /etc | wc -l)`: `$( )` ke andar poori pipeline.
- `$(( files_here > 10 ))`: hisaab ke andar muqabla **sach ke liye 1**, **jhoot ke liye 0** deta hai.
- `$(date +%Y)` ne mojooda saal file ke naam me daala.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Quote it, or lines get squashed">

<Tr>
<En>

Like variables, an **unquoted** `$(…)` is split into words at spaces and new lines. Multi-line output gets squashed into one line, and names with spaces break. So always quote: `"$(command)"`.

</En>
<Ur>

Variables ki tarah **baghair quotes** wala `$(…)` spaces aur nayi lines par alfaz me toot jata hai. Kai lines wala output ek line me dab jata hai, aur spaces wale naam toot jate hain. Isliye hamesha quotes: `"$(command)"`.

</Ur>
</Tr>

```bash
lines="$(printf 'first line\nsecond line')"
echo "Quoted keeps lines:"
echo "$lines"
echo "Unquoted squashes them:"
echo $lines
```

```text output
Quoted keeps lines:
first line
second line
Unquoted squashes them:
first line second line
```

</Step>

<Step title="$(( )): the calculator">

<Tr>
<En>

Bash variables are text, so `$a+$b` just joins them. `$((a + b))` really **adds**. Inside `$(( ))` you can write variable names **without** `$`, and spaces are fine.

</En>
<Ur>

Bash variables text hain, isliye `$a+$b` sirf jorta hai. `$((a + b))` waqai **jama** karta hai. `$(( ))` ke andar variables ke naam `$` ke **baghair** likh sakte hain, aur spaces theek hain.

</Ur>
</Tr>

| Operator | Meaning | Example | Result |
| --- | --- | --- | --- |
| `+` `-` | Add, subtract | `$((10 - 3))` | `7` |
| `*` | Multiply | `$((4 * 5))` | `20` |
| `/` | Divide (whole number, rounds **down**) | `$((7 / 2))` | `3` |
| `%` | Remainder | `$((7 % 2))` | `1` |
| `**` | Power | `$((2 ** 10))` | `1024` |
| `( )` | Group | `$(((2 + 3) * 4))` | `20` |

```bash
price=1500
qty=3
total=$((price * qty))
echo "Total: $total"
echo "Split between 4 people: $((total / 4)) each, remainder $((total % 4))"
echo "With 17% tax: $((total * 117 / 100))"
echo "2 to the power 10: $((2 ** 10))"
```

```text output
Total: 4500
Split between 4 people: 1125 each, remainder 0
With 17% tax: 5265
2 to the power 10: 1024
```

<Happened>
<Tr>
<En>

- `price * qty`: no `$` needed inside `$(( ))`.
- `total * 117 / 100`: a trick for percentages with whole numbers. **Multiply first, then divide**, so you don't lose precision.

</En>
<Ur>

- `price * qty`: `$(( ))` ke andar `$` ki zaroorat nahi.
- `total * 117 / 100`: poore numbers ke saath percentage ki tarkeeb. **Pehle zarb, phir taqseem**, taa ke durusti zaya na ho.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="(( )) for counters and comparisons">

<Tr>
<En>

Double brackets **without** a `$` in front run the maths as a **command**. They can change variables, and they count as "true" when the result isn't zero, so they work with `if` and `while`.

- `((count++))` add 1, `((count--))` subtract 1, `((total += 5))` add 5
- Compare: `==`, `!=`, `<`, `<=`, `>`, `>=`, and combine with `&&`, `||`

</En>
<Ur>

Aage `$` ke **baghair** double brackets hisaab ko **command** ki tarah chalate hain. Ye variables badal sakte hain, aur nateeja zero na ho to "sach" gine jate hain, isliye `if` aur `while` ke saath chalte hain.

- `((count++))` 1 joro, `((count--))` 1 ghatao, `((total += 5))` 5 joro
- Milao: `==`, `!=`, `<`, `<=`, `>`, `>=`, aur `&&`, `||` se joro

</Ur>
</Tr>

```bash
count=0
((count++))
((count++))
((count += 10))
echo "count = $count"

disk=85
if (( disk > 80 )); then
  echo "Disk warning: ${disk}%"
fi
(( disk > 95 )) || echo "Not critical yet"
```

```text output
count = 12
Disk warning: 85%
Not critical yet
```

<Happened>
<Tr>
<En>Two `++` and one `+= 10` made `count` 12. `85 > 80` was true, so the warning printed; `85 > 95` was false, so the part after `||` ran.</En>
<Ur>Do `++` aur ek `+= 10` ne `count` ko 12 kiya. `85 > 80` sach tha, isliye warning print hui; `85 > 95` jhoot tha, isliye `||` ke baad wala hissa chala.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Decimals need awk">

<Tr>
<En>

Bash can't handle a decimal point: `$((7 / 2))` gives `3`, and `$((1.5 + 1))` is an error. Load averages (`0.75`), prices and averages need decimals, so use **awk** (installed everywhere) or `bc`.

</En>
<Ur>

Bash decimal point nahi sambhal sakta: `$((7 / 2))` `3` deta hai, aur `$((1.5 + 1))` error hai. Load averages (`0.75`), qeematon aur averages ko decimals chahiyen, isliye **awk** (har jagah mojood) ya `bc` istemal karein.

</Ur>
</Tr>

```bash
echo "Bash: 7 / 2 = $((7 / 2))"
echo "awk:  7 / 2 = $(awk 'BEGIN { print 7 / 2 }')"
echo "awk with 2 decimals: $(awk 'BEGIN { printf "%.2f", 10 / 3 }')"

load="1.75"
cores=2
if awk -v l="$load" -v c="$cores" 'BEGIN { exit !(l > c * 0.8) }'; then
  echo "Load $load is high for $cores cores"
fi
```

```text output
Bash: 7 / 2 = 3
awk:  7 / 2 = 3.5
awk with 2 decimals: 3.33
Load 1.75 is high for 2 cores
```

<Happened>
<Tr>
<En>

- Bash said 3; awk said 3.5. `printf "%.2f"` rounds to 2 decimals.
- `-v l="$load"` passes a Bash variable **safely** into awk.
- `exit !(condition)` makes awk say "success" when the condition is true, so it works with `if`.

</En>
<Ur>

- Bash ne 3 kaha; awk ne 3.5. `printf "%.2f"` 2 decimals tak gol karta hai.
- `-v l="$load"` Bash variable ko **mehfooz tareeqe se** awk me bhejta hai.
- `exit !(condition)` shart sach hone par awk se "kamyabi" kehlwata hai, isliye `if` ke saath chalta hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Dates and time maths">

<Tr>
<En>

`date +%s` prints the time as **seconds since 1970** (a Unix timestamp). Seconds are just numbers, so you can **subtract** them to measure how long something took.

Formats: `%F` = 2026-11-10, `%T` = 14:30:05, `%Y%m%d-%H%M%S` = 20261110-143005. `date -d "7 days ago"` gives an earlier date. Bash also has `$SECONDS`: seconds since the script started.

</En>
<Ur>

`date +%s` waqt ko **1970 se ab tak ke seconds** (Unix timestamp) ki shakal me print karta hai. Seconds sirf numbers hain, isliye unhe **ghata** kar naap sakte hain ke kitna waqt laga.

Formats: `%F` = 2026-11-10, `%T` = 14:30:05, `%Y%m%d-%H%M%S` = 20261110-143005. `date -d "7 days ago"` pichli tareekh deta hai. Bash me `$SECONDS` bhi hai: script shuru hone se ab tak ke seconds.

</Ur>
</Tr>

```bash
start=$(date +%s)
sleep 2
end=$(date +%s)
echo "That took $((end - start)) seconds"

echo "Fixed date in different formats:"
date -d "2026-11-10 14:30:05" +"%F | %T | %d/%m/%Y | %A"
date -d "2026-11-10 - 7 days" +"One week earlier: %F"
```

```text output
That took 2 seconds
Fixed date in different formats:
2026-11-10 | 14:30:05 | 10/11/2026 | Tuesday
One week earlier: 2026-11-03
```

</Step>

<Step title="Human-readable sizes">

<Tr>
<En>

`3145728` means nothing to a person; `3.0M` does. `numfmt --to=iec` converts bytes. Keep the **raw bytes** for maths and convert only for display.

</En>
<Ur>

`3145728` insaan ke liye bekaar hai; `3.0M` samajh aata hai. `numfmt --to=iec` bytes badalta hai. Hisaab ke liye **asal bytes** rakhein aur sirf dikhane ke liye badlein.

</Ur>
</Tr>

```bash
head -c 3145728 /dev/zero > big.bin
bytes=$(stat -c %s big.bin)
echo "Bytes: $bytes"
echo "Human: $(numfmt --to=iec "$bytes")"
echo "MB (whole): $((bytes / 1024 / 1024))"
```

```text output
Bytes: 3145728
Human: 3.0M
MB (whole): 3
```

</Step>

<Step title="The leading-zero trap">

<Tr>
<En>

Inside `$(( ))`, a number starting with `0` is read as **octal** (base 8), where `08` and `09` don't exist. `date +%H` returns hours like `08` and `09`, so this bug **only appears in the morning**. Fix: force base 10 with `10#`.

</En>
<Ur>

`$(( ))` ke andar `0` se shuru hone wala number **octal** (base 8) samjha jata hai, jahan `08` aur `09` hote hi nahi. `date +%H` `08` aur `09` jaise ghante deta hai, isliye ye bug **sirf subah** nazar aata hai. Hal: `10#` se base 10 lagu karein.

</Ur>
</Tr>

```bash
hour="09"
( echo $((hour + 1)) ) 2>&1 | sed 's/.*: //'
echo "Fixed: $((10#$hour + 1))"
```

```text output
value too great for base (error token is "09")
Fixed: 10
```

</Step>

</Walkthrough>

## Common mistakes

<Compare>
<Bad title="(( count++ )) under set -e">

```text
set -e
count=0
(( count++ ))     # result is 0 → "false" → the script exits!
```

</Bad>
<Good title="Safe ways to add 1">

```text
(( ++count ))
count=$((count + 1))
```

</Good>
</Compare>

<Compare>
<Bad title="Comparing numbers as text">

```text
[[ "10" > "9" ]]     # false: compares text, and "1" comes before "9"
```

</Bad>
<Good title="Compare as numbers">

```text
(( 10 > 9 ))
[ "10" -gt "9" ]
```

</Good>
</Compare>

<Compare>
<Bad title="Backticks in new code">

```text
n=`ls | wc -l`
```

</Bad>
<Good title="$( ), quoted">

```text
n="$(ls | wc -l)"
```

</Good>
</Compare>

<Challenge title="Maths lab">

<Tr>
<En>
This lab mixes everything: command substitution, a percentage with a warning, a counter loop, an average with decimals, and the leading-zero fix.
</En>
<Ur>

```bash
mkdir -p ~/math-lab && cd ~/math-lab

# command substitution
cores=$(nproc)
echo "CPU cores (at least 1): $(( cores >= 1 ))"
for i in 1 2 3; do echo "file $i" > "f$i.txt"; done
count=$(ls *.txt | wc -l)
echo "Text files: $count"

# arithmetic
used=42; total=50
echo "Used: $(( used * 100 / total ))%"
(( used * 100 / total >= 80 )) && echo "Over 80% — warning"

# counters
retries=0
while (( retries < 3 )); do ((retries++)); done
echo "Retries done: $retries"

# decimals
echo "Average: $(awk 'BEGIN { printf "%.1f", (120 + 95 + 2300) / 3 }') ms"

# leading zeros
for h in 08 09 10; do echo "hour $h → $((10#$h))"; done

cd ~ && rm -rf ~/math-lab
```

```text output
Text files: 3
Used: 84%
Over 80% — warning
Retries done: 3
Average: 838.3 ms
hour 08 → 8
hour 09 → 9
hour 10 → 10
```

## Remember

<Takeaways>
<Tr>
<En>

- `"$(command)"` puts a command's output in place. Always quote it.
- `$((…))` = whole-number maths; no `$` needed inside.
- `/` rounds down, `%` is the remainder, `**` is power.
- `((count++))`, `if (( a > b ))` for counters and comparisons.

- Under `set -e`, use `((++count))`, not `((count++))` from 0.

</En>

- Leading zeros: `$((10#$h))`.

</Ur>

<DeepDive title="Real world: tagging and checking a Docker build in CI">

A CI job builds and pushes a Docker image, tagging it from Git, timing each step, and failing if the image is too large:

```bash
#!/usr/bin/env bash
set -euo pipefail

sha="$(git rev-parse --short HEAD)"
branch="$(git rev-parse --abbrev-ref HEAD | tr '/' '-')"
stamp="$(date -u +%Y%m%d%H%M)"
tag="${branch}-${stamp}-${sha}"            # main-202611100415-ce072a5

t0=$SECONDS
docker build -t "registry.example.com/api:${tag}" .
echo "build took $(( SECONDS - t0 ))s"

size_bytes="$(docker image inspect "registry.example.com/api:${tag}" --format '{{.Size}}')"
size_mb=$(( size_bytes / 1024 / 1024 ))
echo "image size: ${size_mb} MB"
if (( size_mb > 400 )); then
  echo "✖ Image is larger than 400 MB — check the Dockerfile (multi-stage build? dev dependencies?)" >&2
  exit 1
fi

docker push "registry.example.com/api:${tag}"
echo "pushed ${tag} in $(( SECONDS / 60 ))m $(( SECONDS % 60 ))s total"
```

One more pitfall: in older scripts without `set -e`, a command that fails inside `$( )` is silently ignored and the variable is just empty.

</DeepDive>

<DeepDive title="Security lens">

Command substitution runs code; arithmetic evaluates expressions. Both can execute more than you intended if untrusted data gets inside.

- **Never substitute untrusted text as code:** `$(echo "$input")` is fine, but `eval "$input"` or `bash -c "… $input …"` executes it.
- **Arithmetic injection:** Bash evaluates array subscripts inside arithmetic, so a value like `a[$(id)]` used in `(( ))` or `$(( ))` **executes `id`**. Never do arithmetic on unvalidated input; check it's a number first: `[[ $n =~ ^[0-9]+$ ]] || exit 1`.
- **Integer overflow:** Bash integers are 64-bit signed; huge values wrap silently. Validate ranges for user-controlled numbers (sizes, counts, ports).
- **Timestamps:** log and name evidence files in **UTC** (`date -u`) so they line up with other systems during an investigation.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What is the difference between $(command) and backticks?">
Both perform command substitution, inserting the command's output with trailing newlines removed. $(command) is the modern POSIX form: it nests without escaping, is easier to read and handles quotes and backslashes more predictably. Backticks are legacy and should be avoided in new scripts.
</QA>

<QA q="How do you do arithmetic in Bash, and what are its limits?">
Use arithmetic expansion $((expression)) to compute a value, or the (( expression )) command for conditions and updates such as (( count++ )). Bash arithmetic is integer-only with 64-bit signed integers, so division truncates; for decimals use awk or bc. Comparisons inside (( )) use normal operators like > and ==.
</QA>

<QA q="Why can (( count++ )) make a script with set -e exit unexpectedly?">
(( )) returns exit status 1 when the expression evaluates to zero. count++ returns the old value, so when count is 0 the expression is 0, the command 'fails', and set -e terminates the script. Use (( ++count )), count=$((count + 1)) or append || true.
</QA>

<QA q="How do you capture a command's output into a variable safely?">
Use var="$(command)" with double quotes, so whitespace is preserved and no globbing happens. Check the command's success (set -e, or if ! var="$(command)"; then …), and for multi-line output that you want to process line by line, use a while read loop or mapfile rather than splitting the variable.
</QA>

</DeepDive>
