<Callout type="tip" title="In one minute">
**Command substitution** `$(command)` runs a command and inserts its output: `today="$(date +%F)"`. Quote it, because the output is word-split like any expansion. **Arithmetic expansion** `$((expr))` does **integer** maths: `$((size / 1024))`. The `(( ))` command evaluates a condition or updates a counter: `(( count++ ))`, `if (( errors > 0 )); then`. Bash has **no decimals** — use `awk` or `bc` for those. Avoid the old backtick form `` `cmd` ``.
</Callout>

## What is it?

| Form | Purpose | Example | Result |
| --- | --- | --- | --- |
| `$(cmd)` | Insert a command's output | `"$(hostname)"` | `web-01` |
| `` `cmd` `` | Old form of the same — avoid | `` `hostname` `` | `web-01` |
| `$((expr))` | Integer arithmetic, gives a value | `$((7 / 2))` | `3` |
| `(( expr ))` | Arithmetic as a command (true/false, or update a variable) | `(( n > 5 ))` | exit status 0 or 1 |
| `let` | Older arithmetic command | `let n=n+1` | — |
| `$[expr]` | Obsolete arithmetic — never use | | |

## Why does it matter?

Real scripts constantly need values that only a command knows — today's date for a backup name, the current Git commit for a Docker tag, the number of failed logins, free disk space — and need to compare or calculate with them: "if more than 80% full", "retry up to 5 times", "duration in seconds".

- **DevOps:** `TAG="$(git rev-parse --short HEAD)"`, `docker build -t app:"$TAG"`; timing deploys with `$SECONDS`; retry loops with counters.
- **Cloud:** capturing IDs from CLI output: `instance_id="$(aws ec2 run-instances … --query 'Instances[0].InstanceId' --output text)"`.
- **Security:** thresholds in monitoring scripts ("alert if more than 20 failed logins"); timestamps for evidence files.

## When and where do you use it?

- Naming files with dates: `backup-$(date +%F_%H%M).tar.gz`.
- Tagging builds with Git info.
- Counting things: `lines=$(wc -l < access.log)`.
- Percentages and thresholds for alerts.
- Loops with counters and retries.
- Measuring how long something took.

## How does it work?

### Command substitution

```bash
today="$(date +%F)"                       # 2026-11-10
kernel="$(uname -r)"
commit="$(git rev-parse --short HEAD)"
users="$(wc -l < /etc/passwd)"            # "< file" gives just the number, no file name
echo "Backup for $today on kernel $kernel ($users accounts)"
```

Rules:

- The command runs in a **subshell** — variables it sets do not survive.
- **Trailing newlines are removed**; other whitespace is kept (if you quote).
- **Quote it** (`"$(cmd)"`), or the output is split on spaces and globbed.
- The exit status of `var="$(cmd)"` is the exit status of `cmd` — so `set -e` stops the script if it fails.
- `$(…)` nests cleanly: `"$(basename "$(pwd)")"`. Backticks need escaping to nest — another reason to avoid them.

### Arithmetic expansion `$(( ))`

```bash
a=17; b=5
echo $(( a + b ))     # 22
echo $(( a - b ))     # 12
echo $(( a * b ))     # 85
echo $(( a / b ))     # 3   ← integer division, rounds toward zero
echo $(( a % b ))     # 2   ← remainder (modulo)
echo $(( a ** 2 ))    # 289 ← power
echo $(( (a + b) * 2 ))
```

Inside `$(( ))` you do not need `$` before variable names, spaces are allowed, and the usual operators work: `+ - * / % **`, comparisons `< <= > >= == !=`, logic `&& || !`, bitwise `& | ^ << >>`, and `?:`.

Number bases: `$(( 16#ff ))` = 255, `$(( 2#1010 ))` = 10, `$(( 8#755 ))` = 493.

### `(( ))` as a command

```bash
count=0
(( count++ ))                 # increment
(( count += 5 ))
if (( count > 3 )); then echo "more than 3"; fi
(( disk_pct >= 80 )) && echo "disk almost full"
```

`(( ))` returns exit status 0 when the result is **non-zero** (true) and 1 when it is zero (false).

Watch out with `set -e`: `(( count++ ))` when `count` is 0 evaluates to 0 → status 1 → the script **exits**. Use `(( ++count ))` (pre-increment, value is 1) or `count=$((count + 1))` in `set -e` scripts.

### Integer only — decimals need help

```bash
echo $(( 10 / 3 ))                          # 3
awk 'BEGIN { printf "%.2f\n", 10 / 3 }'     # 3.33
echo "scale=2; 10 / 3" | bc                 # 3.33 (install bc if missing)
awk -v used=7.5 -v total=20 'BEGIN { printf "%.1f%%\n", used / total * 100 }'
```

Percentages with integers only: multiply first, then divide — `$(( used * 100 / total ))`.

### Dates and time maths

```bash
date +%F                  # 2026-11-10
date +%F_%H%M%S           # 2026-11-10_041533
date -u +%Y-%m-%dT%H:%M:%SZ  # ISO 8601 in UTC (for logs)
date +%s                  # seconds since 1970 (epoch) — easy to subtract
date -d "7 days ago" +%F  # GNU date
date -d @1762731333       # epoch → readable

start=$(date +%s)
sleep 2
echo "took $(( $(date +%s) - start ))s"
echo "script running for ${SECONDS}s"      # built-in timer
```

### Human-readable sizes

```bash
bytes=$(stat -c %s /var/log/syslog 2>/dev/null || echo 0)
echo "$(( bytes / 1024 / 1024 )) MiB"
numfmt --to=iec "$bytes"                   # 12M — coreutils does the formatting
```

## Hands-on

```bash
# Capture and use output
host="$(hostname)"; today="$(date +%F)"; kernel="$(uname -r)"
echo "Report for $host on $today (kernel $kernel)"

# Subshell: variables set inside $( ) do not survive
x=1; y="$(x=2; echo "$x")"; echo "x=$x y=$y"

# Arithmetic
a=17; b=5
echo "sum=$((a+b)) div=$((a/b)) mod=$((a%b)) pow=$((a**2)) hex ff=$((16#ff))"
echo "decimal: $(awk -v a="$a" -v b="$b" 'BEGIN{printf "%.2f", a/b}')"

# Disk usage of / as a number, then a threshold check
pct="$(df --output=pcent / | tail -n 1 | tr -dc '0-9')"
echo "root disk: ${pct}%"
if (( pct >= 80 )); then echo "WARNING: disk almost full"; else echo "disk OK"; fi

# Counter and the set -e gotcha
bash -c 'set -e; n=0; (( n++ )); echo "never printed"'; echo "exit status: $?"
bash -c 'set -e; n=0; (( ++n )); echo "n=$n — fine"'

# Timing
start=$(date +%s); sleep 1; echo "elapsed: $(( $(date +%s) - start ))s"

# A retry loop with a counter (next lessons cover loops properly)
attempt=0
until curl -fsS -o /dev/null https://example.com || (( ++attempt >= 3 )); do
  echo "attempt $attempt failed, retrying in 2s"; sleep 2
done
echo "done after $attempt retries"
```

## Real-world example

A CI job builds and pushes a Docker image, tagging it from Git, timing each step, and failing if the image is too large:

```bash
#!/usr/bin/env bash
set -euo pipefail

sha="$(git rev-parse --short HEAD)"
branch="$(git rev-parse --abbrev-ref HEAD | tr '/' '-')"
stamp="$(date -u +%Y%m%d%H%M)"
tag="${branch}-${stamp}-${sha}"            # main-202611100415-ce072a5

t0=$SECONDS
docker build -t "registry.example.com/api:${tag}" .
echo "build took $(( SECONDS - t0 ))s"

size_bytes="$(docker image inspect "registry.example.com/api:${tag}" --format '{{.Size}}')"
size_mb=$(( size_bytes / 1024 / 1024 ))
echo "image size: ${size_mb} MB"
if (( size_mb > 400 )); then
  echo "✖ Image is larger than 400 MB — check the Dockerfile (multi-stage build? dev dependencies?)" >&2
  exit 1
fi

docker push "registry.example.com/api:${tag}"
echo "pushed ${tag} in $(( SECONDS / 60 ))m $(( SECONDS % 60 ))s total"
```

## Common mistakes

- **Unquoted `$(cmd)`** — output with spaces or `*` breaks the command.
- **Expecting decimals**: `$(( 7 / 2 ))` is 3. Use awk or bc.
- **`(( count++ ))` under `set -e`** when count is 0 — exits the script.
- **Leading zeros**: `$(( 08 + 1 ))` fails — `08` is read as (invalid) octal. Strip zeros or force base 10: `$(( 10#08 + 1 ))`. Common with `date +%m`.
- **Comparing numbers as strings**: `[ "$a" > "$b" ]` is a redirection, and `[[ "$a" > "$b" ]]` compares text ("10" < "9"). Use `(( a > b ))` or `[ "$a" -gt "$b" ]`.
- **Backticks** in new code — hard to read and nest.
- **Ignoring command failures** inside substitutions in older scripts without `set -e`.

## Security lens

<Callout type="security">
Command substitution runs code; arithmetic evaluates expressions. Both can execute more than you intended if untrusted data gets inside.
</Callout>

- **Never substitute untrusted text as code:** `$(echo "$input")` is fine, but `eval "$input"` or `bash -c "… $input …"` executes it.
- **Arithmetic injection:** Bash evaluates array subscripts inside arithmetic, so a value like `a[$(id)]` used in `(( ))` or `$(( ))` **executes `id`**. Never do arithmetic on unvalidated input — check it is a number first: `[[ $n =~ ^[0-9]+$ ]] || exit 1`.
- **Integer overflow:** Bash integers are 64-bit signed; huge values wrap silently. Validate ranges for user-controlled numbers (sizes, counts, ports).
- **Timestamps:** log and name evidence files in **UTC** (`date -u`) so they line up with other systems during an investigation.

## Interview questions

<QA q="What is the difference between $(command) and backticks?">
Both perform command substitution, inserting the command's output with trailing newlines removed. $(command) is the modern POSIX form: it nests without escaping, is easier to read and handles quotes and backslashes more predictably. Backticks are legacy and should be avoided in new scripts.
</QA>

<QA q="How do you do arithmetic in Bash, and what are its limits?">
Use arithmetic expansion $((expression)) to compute a value, or the (( expression )) command for conditions and updates such as (( count++ )). Bash arithmetic is integer-only with 64-bit signed integers, so division truncates; for decimals use awk or bc. Comparisons inside (( )) use normal operators like > and ==.
</QA>

<QA q="Why can (( count++ )) make a script with set -e exit unexpectedly?">
(( )) returns exit status 1 when the expression evaluates to zero. count++ returns the old value, so when count is 0 the expression is 0, the command 'fails', and set -e terminates the script. Use (( ++count )), count=$((count + 1)) or append || true.
</QA>

<QA q="How do you capture a command's output into a variable safely?">
Use var="$(command)" with double quotes, so whitespace is preserved and no globbing happens. Check the command's success (set -e, or if ! var="$(command)"; then …), and for multi-line output that you want to process line by line, use a while read loop or mapfile rather than splitting the variable.
</QA>

## Key terms

<Terms>
