<BigIdea>
<Tr>
<En>
**JSON** is the text format that APIs, cloud tools, Docker and Kubernetes use for data: `{"name": "web-1", "cpu": 42}`. **jq** is a command-line tool that reads JSON and lets you pick, filter and reshape it. `.name` reads a field, `.[]` goes through every item of a list, `select(.cpu > 80)` keeps the matching ones, and `-r` prints plain text for Bash.
</En>
<Ur>
**JSON** wo text format hai jo APIs, cloud tools, Docker aur Kubernetes data ke liye istemal karte hain: `{"name": "web-1", "cpu": 42}`. **jq** command-line tool hai jo JSON parhta hai aur use chunne, filter karne aur nayi shakal dene deta hai. `.name` field parhta hai, `.[]` list ki har cheez se guzarta hai, `select(.cpu > 80)` milti hui cheezen rakhta hai, aur `-r` Bash ke liye saada text chhaapta hai.
</Ur>

## At a glance

<Glance>
<What>
<Tr>
<En>

**JSON** (JavaScript Object Notation) writes structured data as text:

```json
{
  "name": "web-1",
  "region": "eu-west-1",
  "running": true,
  "cpu": 42,
  "tags": ["web", "prod"],
  "owner": { "team": "platform", "email": "ops@example.com" }
}
```

| JSON piece | Looks like | Means |
| --- | --- | --- |
| **Object** | `{ "key": value, … }` | A record with named fields (like a form) |
| **Array** | `[ value, value, … ]` | An ordered list |
| **String** | `"web-1"` | Text, always in double quotes |
| **Number** | `42`, `3.5` | A number, no quotes |
| **Boolean** | `true` / `false` | Yes / no |
| **null** | `null` | "No value" |

Objects and arrays can be **nested**: `owner` is an object inside an object. **jq** (install with `sudo apt install jq` or `brew install jq`) works like `sed` and `awk`, but for JSON.

</En>
<Ur>

**JSON** (JavaScript Object Notation) tarteeb wala data text ki shakal me likhta hai:

```json
{
  "name": "web-1",
  "region": "eu-west-1",
  "running": true,
  "cpu": 42,
  "tags": ["web", "prod"],
  "owner": { "team": "platform", "email": "ops@example.com" }
}
```

| JSON hissa | Shakal | Matlab |
| --- | --- | --- |
| **Object** | `{ "key": value, … }` | Naam wale fields ka record (form jaisa) |
| **Array** | `[ value, value, … ]` | Tarteeb wali list |
| **String** | `"web-1"` | Text, hamesha double quotes me |
| **Number** | `42`, `3.5` | Number, quotes nahi |
| **Boolean** | `true` / `false` | Haan / nahi |
| **null** | `null` | "Koi value nahi" |

Objects aur arrays ek doosre ke **andar** ho sakte hain: `owner` object ke andar object hai. **jq** (`sudo apt install jq` ya `brew install jq` se install) `sed` aur `awk` jaisa kaam karta hai, lekin JSON ke liye.

</Ur>
</Tr>
</What>
<Why>
<Tr>
<En>

- **Cloud CLIs output JSON:** `aws`, `az`, `gcloud`, `kubectl -o json`, `docker inspect`, `terraform output -json`.
- **APIs return JSON:** GitHub, Slack, payment gateways, your own backends.
- **Config is JSON:** `package.json`, `tsconfig.json`, IAM policies.
- **Why not grep?** JSON can be all on one line, keys come in any order, and the same key appears at many levels. `grep` sees only text lines; jq understands the **structure**.

</En>
<Ur>

- **Cloud CLIs JSON dete hain:** `aws`, `az`, `gcloud`, `kubectl -o json`, `docker inspect`, `terraform output -json`.
- **APIs JSON lautati hain:** GitHub, Slack, payment gateways, aap ke apne backends.
- **Config JSON hai:** `package.json`, `tsconfig.json`, IAM policies.
- **grep kyun nahi?** JSON poora ek line me ho sakta hai, keys kisi bhi tarteeb me aati hain, aur ek hi key kai satahon par hoti hai. `grep` sirf text lines dekhta hai; jq **dhaancha** samajhta hai.

</Ur>
</Tr>
</Why>

## Picture it

<Tr>
<En>

JSON is like a **set of folders and lists**: a folder (`{ }`) has labelled pages inside it, and some pages are lists (`[ ]`) or more folders. **jq** is the assistant who walks into the folder and fetches exactly what you ask for: "the owner's email", "the names of all servers whose CPU is above 80".

</En>
<Ur>

JSON **folders aur lists ka majmua** hai: folder (`{ }`) me label wale safhe hote hain, aur kuch safhe lists (`[ ]`) ya mazeed folders hote hain. **jq** wo madadgar hai jo folder me ja kar bilkul wahi laata hai jo aap maangte hain: "owner ki email", "un saare servers ke naam jin ka CPU 80 se ooper hai".

</Ur>
</Tr>

## Words you'll see

<Tr>
<En>

| Word | What it means | Example |
| --- | --- | --- |
| **Key / field** | The name of a value inside an object | `"name"` |
| **Value** | What's stored under a key | `"web-1"` |
| **Nested** | Something inside something else | `.owner.email` |
| **Filter** | A jq expression: JSON in, JSON out | `.name` |
| **Pipe (in jq)** | `\|` inside jq passes results to the next filter | `.[] \| .name` |
| **Raw output** | Text without JSON quotes | `-r` |
| **API** | A web service that returns data, usually JSON | `https://api.github.com/…` |

</En>
<Ur>

| Lafz | Matlab | Misaal |
| --- | --- | --- |
| **Key / field** | Object ke andar value ka naam | `"name"` |
| **Value** | Key ke neeche rakhi cheez | `"web-1"` |
| **Nested** | Kisi cheez ke andar koi cheez | `.owner.email` |
| **Filter** | jq expression: JSON andar, JSON bahar | `.name` |
| **Pipe (jq me)** | jq ke andar `\|` nateeje agle filter ko deta hai | `.[] \| .name` |
| **Raw output** | JSON quotes ke baghair text | `-r` |
| **API** | Web service jo data deti hai, aam tor par JSON | `https://api.github.com/…` |

## Learn it step by step

<Walkthrough>

<Step title="The sample file for this lesson">

<Tr>
<En>An array of 4 server objects. Every example below reads this file.</En>
<Ur>4 server objects ka array. Neeche ki har misaal yahi file parhti hai.</Ur>
</Tr>

```bash
cat > servers.json <<'EOF'
[
  {"name": "web-1", "region": "eu-west-1", "cpu": 42, "running": true,  "tags": ["web","prod"]},
  {"name": "web-2", "region": "eu-west-1", "cpu": 91, "running": true,  "tags": ["web","prod"]},
  {"name": "db-1",  "region": "us-east-1", "cpu": 67, "running": true,  "tags": ["db","prod"]},
  {"name": "test-1","region": "us-east-1", "cpu": 3,  "running": false, "tags": ["test"]}
]
EOF
jq length servers.json
```

```text output
4
```

</Step>

<Step title=". : pretty-print the input">

<Tr>
<En>

`.` means "the whole input, unchanged", and jq prints it nicely indented. API responses usually arrive as one long unreadable line, so `curl … | jq .` is the first thing you do. `-c` does the opposite: compact, one line.

</En>
<Ur>

`.` ka matlab "poora input, bina tabdeeli", aur jq use achhe indent ke saath chhaapta hai. API jawab aam tor par ek lambi na-parhne layaq line me aate hain, isliye `curl … | jq .` pehla kaam hai. `-c` ulta karta hai: chhota, ek line.

</Ur>
</Tr>

```bash
echo '{"name":"web-1","tags":["web","prod"],"owner":{"team":"platform"}}' | jq .
```

```text output
{
  "name": "web-1",
  "tags": [
    "web",
    "prod"
  ],
  "owner": {
    "team": "platform"
  }
}
```

</Step>

<Step title="Read fields: .key and .a.b">

<Tr>
<En>

`.name` reads the `name` field. Chain dots to go deeper: `.owner.email`. A missing key gives `null` (not an error). Keys with dashes or spaces need quotes: `.["user-id"]`.

</En>
<Ur>

`.name` `name` field parhta hai. Gehrai me jane ke liye dots jorein: `.owner.email`. Ghayab key `null` deti hai (error nahi). Dash ya space wali keys ko quotes chahiye: `.["user-id"]`.

</Ur>
</Tr>

```bash
json='{"name":"web-1","owner":{"team":"platform","email":"ops@example.com"},"user-id":7}'
echo "$json" | jq '.name'
echo "$json" | jq '.owner.email'
echo "$json" | jq '.["user-id"]'
echo "$json" | jq '.missing'
```

```text output
"web-1"
"ops@example.com"
7
null
```

</Step>

<Step title="Raw output with -r: values for Bash">

<Tr>
<En>

In Bash you want `web-1`, not `"web-1"`; otherwise the quotes end up inside file names and comparisons. `-r` prints strings **without** JSON quotes. Use it every time a jq result goes into a Bash variable.

</En>
<Ur>

Bash me aap ko `web-1` chahiye, `"web-1"` nahi; warna quotes file naamon aur muqablon me chale jate hain. `-r` strings ko JSON quotes ke **baghair** chhaapta hai. Jab bhi jq ka nateeja Bash variable me jaye, ise lagayen.

</Ur>
</Tr>

```bash
echo '{"version":"2.14.3"}' | jq '.version'
echo '{"version":"2.14.3"}' | jq -r '.version'
version=$(echo '{"version":"2.14.3"}' | jq -r '.version')
echo "Deploying v$version"
```

```text output
"2.14.3"
2.14.3
Deploying v2.14.3
```

</Step>

<Step title="Arrays: .[0], .[] and length">

<Tr>
<En>

Most API results are lists: servers, users, pods.

- `.[0]` = first item, `.[-1]` = last, `.[1:3]` = a slice.
- `.[]` goes through **every** item, outputting each one separately.
- `length` counts items.

</En>
<Ur>

Zyada tar API nateeje lists hain: servers, users, pods.

- `.[0]` = pehli cheez, `.[-1]` = aakhri, `.[1:3]` = tukra.
- `.[]` **har** cheez se guzarta hai, har ek alag nikalta hai.
- `length` cheezen ginta hai.

</Ur>
</Tr>

```bash
echo "first: $(jq -r '.[0].name' servers.json)"
echo "last:  $(jq -r '.[-1].name' servers.json)"
echo "count: $(jq 'length' servers.json)"
echo "all names:"
jq -r '.[].name' servers.json
```

```text output
first: web-1
last:  test-1
count: 4
all names:
web-1
web-2
db-1
test-1
```

</Step>

<Step title="The jq pipe |">

<Tr>
<En>

Inside a jq filter, `|` sends results to the next filter, like the shell pipe but **inside** jq: "for each item, then take its tags, then count them". `+` joins strings, and `tostring` turns a number into text so it can be joined.

</En>
<Ur>

jq filter ke andar `|` nateeje agle filter ko bhejta hai, shell pipe ki tarah lekin jq ke **andar**: "har cheez ke liye, phir us ke tags lo, phir gino". `+` strings jorta hai, aur `tostring` number ko text banata hai taa ke jora ja sake.

</Ur>
</Tr>

```bash
jq -r '.[] | .name + " has " + (.tags | length | tostring) + " tag(s)"' servers.json
```

```text output
web-1 has 2 tag(s)
web-2 has 2 tag(s)
db-1 has 2 tag(s)
test-1 has 1 tag(s)
```

</Step>

<Step title="Filter with select">

<Tr>
<En>

`select(condition)` keeps an item only if the condition is true. Combine with `and`, `or`, `not`. For text: `==`, `startswith("web")`, `test("regex")`. For arrays: `index("prod")`.

</En>
<Ur>

`select(condition)` cheez tab rakhta hai jab shart sach ho. `and`, `or`, `not` se jorein. Text ke liye: `==`, `startswith("web")`, `test("regex")`. Arrays ke liye: `index("prod")`.

</Ur>
</Tr>

```bash
echo "High CPU:"
jq -r '.[] | select(.cpu > 80) | .name' servers.json
echo "Running in us-east-1:"
jq -r '.[] | select(.region == "us-east-1" and .running) | .name' servers.json
echo "Names starting with web:"
jq -r '.[] | select(.name | startswith("web")) | .name' servers.json
echo "Not tagged prod:"
jq -r '.[] | select(.tags | index("prod") | not) | .name' servers.json
```

```text output
High CPU:
web-2
Running in us-east-1:
db-1
Names starting with web:
web-1
web-2
Not tagged prod:
test-1
```

</Step>

<Step title="Build new JSON: objects and arrays">

<Tr>
<En>

Make your own output shape, keeping only the fields you need:

- `{name, cpu}` is shorthand for `{"name": .name, "cpu": .cpu}`; rename with `{server: .name}`.
- Wrap in `[ … ]` to collect results into **one** array.
- `map(f)` is the same as `[.[] | f]`.

</En>
<Ur>

Apni output shakal banayen, sirf zaroori fields rakh kar:

- `{name, cpu}` `{"name": .name, "cpu": .cpu}` ka chhota roop hai; `{server: .name}` se naam badlein.
- Nateeje **ek** array me jama karne ke liye `[ … ]` me lapetein.
- `map(f)` `[.[] | f]` jaisa hai.

</Ur>
</Tr>

```bash
jq -c '.[] | {server: .name, cpu}' servers.json
jq -c '[.[] | select(.running) | .name]' servers.json
jq -c 'map(.cpu)' servers.json
```

```text output
{"server":"web-1","cpu":42}
{"server":"web-2","cpu":91}
{"server":"db-1","cpu":67}
{"server":"test-1","cpu":3}
["web-1","web-2","db-1"]
[42,91,67,3]
```

</Step>

<Step title="Count, sum, sort and group">

<Tr>
<En>

Turn raw data into answers: "how many?", "average?", "busiest?", "per region?". `"\(.cpu)%"` is **string interpolation**: `\( … )` inside a jq string inserts a value.

</En>
<Ur>

Kachche data ko jawabon me badlein: "kitne?", "ausat?", "sab se masroof?", "har region me?". `"\(.cpu)%"` **string interpolation** hai: jq string ke andar `\( … )` value daal deta hai.

</Ur>
</Tr>

```bash
echo "average CPU: $(jq 'map(.cpu) | add / length' servers.json)"
echo "busiest:     $(jq -r 'max_by(.cpu) | .name' servers.json)"
echo "by CPU, high to low:"
jq -r 'sort_by(.cpu) | reverse | .[] | "\(.cpu)%\t\(.name)"' servers.json
echo "servers per region:"
jq -r 'group_by(.region) | .[] | "\(.[0].region): \(length)"' servers.json
echo "all tags: $(jq -c '[.[].tags[]] | unique' servers.json)"
```

```text output
average CPU: 50.75
busiest:     web-2
by CPU, high to low:
91%	web-2
67%	db-1
42%	web-1
3%	test-1
servers per region:
eu-west-1: 2
us-east-1: 2
all tags: ["db","prod","test","web"]
```

</Step>

<Step title="Columns for Bash: @tsv and @csv">

<Tr>
<En>

Bash `while read` loops and spreadsheets like simple columns. `@tsv` makes tab-separated lines and `@csv` comma-separated ones. Then read them with `while IFS=$'\t' read -r name cpu`.

</En>
<Ur>

Bash ke `while read` loops aur spreadsheets saada columns pasand karte hain. `@tsv` tab se alag lines banata hai aur `@csv` comma se alag. Phir unhe `while IFS=$'\t' read -r name cpu` se parhein.

</Ur>
</Tr>

```bash
jq -r '.[] | [.name, .region, .cpu] | @csv' servers.json | head -2

while IFS=$'\t' read -r name cpu; do
  (( cpu > 60 )) && echo "ALERT: $name is at ${cpu}% CPU"
done < <(jq -r '.[] | [.name, .cpu] | @tsv' servers.json)
```

```text output
"web-1","eu-west-1",42
"web-2","eu-west-1",91
ALERT: web-2 is at 91% CPU
ALERT: db-1 is at 67% CPU
```

</Step>

<Step title="Pass Bash variables in safely: --arg">

<Tr>
<En>

Pasting Bash variables into the jq text breaks on quotes and is an **injection risk**. Instead:

- `--arg name value` makes a jq string variable `$name`.
- `--argjson name value` does the same for numbers, booleans and JSON.

Inside single quotes, `$r` is **jq's** variable, not Bash's.

</En>
<Ur>

Bash variables jq text me chipkana quotes par toot jata hai aur **injection ka khatra** hai. Is ke bajaye:

- `--arg name value` jq ka string variable `$name` banata hai.
- `--argjson name value` numbers, booleans aur JSON ke liye yahi karta hai.

Single quotes ke andar `$r` **jq ka** variable hai, Bash ka nahi.

</Ur>
</Tr>

```bash
region="us-east-1"
limit=50
jq -r --arg r "$region" --argjson max "$limit" \
  '.[] | select(.region == $r and .cpu > $max) | .name' servers.json
```

```text output
db-1
```

</Step>

<Step title="Create JSON from Bash: jq -n">

<Tr>
<En>

Writing JSON by hand with `echo "{\"text\": \"$msg\"}"` breaks as soon as the message has a quote or newline. `jq -n` (no input) with `--arg` builds it and escapes everything correctly. Perfect for request bodies to Slack, GitHub or your backend.

</En>
<Ur>

`echo "{\"text\": \"$msg\"}"` se haath se JSON likhna message me quote ya nayi line aate hi toot jata hai. `jq -n` (bina input) `--arg` ke saath ise banata hai aur sab kuch sahi escape karta hai. Slack, GitHub ya aap ke backend ko request body ke liye behtareen.

</Ur>
</Tr>

```bash
msg='Deploy of "shop" finished — 2 warnings'
payload=$(jq -nc --arg text "$msg" --arg env prod '{text: $text, env: $env, ok: true}')
echo "$payload"
```

```text output
{"text":"Deploy of \"shop\" finished — 2 warnings","env":"prod","ok":true}
```

<Happened>
<Tr>
<En>The quotes inside the message were escaped (`\"`) automatically. A real script would then send it: `curl -X POST -H 'Content-Type: application/json' -d "$payload" "$WEBHOOK_URL"`.</En>
<Ur>Message ke andar ke quotes khud escape (`\"`) ho gaye. Asli script phir ise bhejta: `curl -X POST -H 'Content-Type: application/json' -d "$payload" "$WEBHOOK_URL"`.</Ur>
</Tr>
</Happened>

</Step>

<Step title="Edit a JSON file">

<Tr>
<En>

- `=` sets a value, `|=` updates based on the old value, `del()` removes a key.
- jq **never edits in place**: write to a temporary file, then move it over the original.

</En>
<Ur>

- `=` value set karta hai, `|=` purani value ki bunyad par badalta hai, `del()` key hatata hai.
- jq file **kabhi khud nahi badalta**: temporary file me likho, phir asal par move karo.

</Ur>
</Tr>

```bash
echo '{"name":"shop","version":"1.4.2","private":true,"apiKey":"secret"}' > package.json
tmp=$(mktemp)
jq '.version = "1.5.0" | .name |= ascii_upcase | del(.apiKey)' package.json > "$tmp" && mv "$tmp" package.json
jq -c . package.json
```

```text output
{"name":"SHOP","version":"1.5.0","private":true}
```

</Step>

<Step title="Missing values and defaults: // and -e">

<Tr>
<En>

Real API data is messy: fields are sometimes missing.

- `.a // "x"` gives `"x"` if `.a` is missing, `null` or `false`.
- `-e` makes jq exit non-zero when the result is `null` or `false`, which is handy in `if`.

</En>
<Ur>

Asli API data be-tarteeb hota hai: fields kabhi kabhi ghayab hote hain.

- `.a // "x"` `"x"` deta hai agar `.a` ghayab, `null` ya `false` ho.
- `-e` jq ko non-zero par nikalta hai jab nateeja `null` ya `false` ho, jo `if` me kaam aata hai.

</Ur>
</Tr>

```bash
echo '{"name":"web-1"}' | jq -r '.owner // "unknown"'
if echo '{"status":"success"}' | jq -e '.status == "success"' > /dev/null; then
  echo "deploy succeeded"
fi
echo '{"status":null}' | jq -e '.status' > /dev/null || echo "status missing (exit $?)"
```

```text output
unknown
deploy succeeded
status missing (exit 1)
```

</Step>

## Common mistakes

<Compare>
<Bad title="Bash variable pasted into the filter">

```text
jq ".[] | select(.name == \"$name\")" servers.json    # breaks on quotes, injection risk
```

</Bad>
<Good title="Single quotes and --arg">

```text
jq --arg n "$name" '.[] | select(.name == $n)' servers.json
```

</Good>
</Compare>

<Compare>
<Bad title="Writing back to the same file">

```text
jq '.version = "2.0.0"' package.json > package.json    # file is emptied first
```

</Bad>
<Good title="Through a temporary file">

```text
tmp=$(mktemp)
jq '.version = "2.0.0"' package.json > "$tmp" && mv "$tmp" package.json
```

</Good>
</Compare>

<Tr>
<En>

More mistakes to avoid:

- **Forgetting `-r`**: `"web-1"` with its quotes ends up in file names and comparisons.
- **Parsing JSON with grep/sed/cut**: works until the format changes slightly.
- **Confusing `.[]` with `.`**: `.` is the whole array; `.[]` is each item separately.
- **Building JSON with `echo`**: breaks on quotes and newlines. Use `jq -n --arg`.
- **Not handling `null`**: missing fields silently become the text `null`. Use `//` defaults or `-e`.

</En>
<Ur>

Bachne wali mazeed ghaltiyan:

- **`-r` bhoolna**: quotes samet `"web-1"` file naamon aur muqablon me chala jata hai.
- **grep/sed/cut se JSON parhna**: tab tak chalta hai jab tak format zara na badle.
- **`.[]` aur `.` me ulajhna**: `.` poora array hai; `.[]` har cheez alag.
- **`echo` se JSON banana**: quotes aur nayi lines par toot jata hai. `jq -n --arg` istemal karein.
- **`null` na sambhalna**: ghayab fields khamoshi se text `null` ban jate hain. `//` defaults ya `-e` istemal karein.

</Ur>
</Tr>

<Challenge title="jq lab: Kubernetes-style pods">

```bash

cat > pods.json <<'EOF'

  {"metadata": {"name": "api-7d9f", "namespace": "shop"}, "status": {"phase": "Running", "restarts": 0}},
  {"metadata": {"name": "api-2k1x", "namespace": "shop"}, "status": {"phase": "CrashLoopBackOff", "restarts": 14}},
  {"metadata": {"name": "worker-9q", "namespace": "jobs"}, "status": {"phase": "Running", "restarts": 2}}
]}
EOF

echo "1) pods: $(jq '.items | length' pods.json)"
echo "2) not running:"
jq -r '.items[] | select(.status.phase != "Running") | "\(.metadata.name) (\(.status.phase), \(.status.restarts) restarts)"' pods.json

echo "5) names in $ns: $(jq -r --arg ns "$ns" '[.items[] | select(.metadata.namespace == $ns) | .metadata.name] | join(", ")' pods.json)"
```

<DeepDive title="Real world: check for a new release and notify Slack">

A script that checks the latest GitHub release of a tool, compares it with the installed version, and posts a Slack message only if it changed:

```bash
#!/usr/bin/env bash
set -euo pipefail

repo="hashicorp/terraform"
current="$(terraform version -json | jq -r '.terraform_version')"

latest="$(curl -fsS "https://api.github.com/repos/$repo/releases/latest" \
  | jq -r '.tag_name // empty' | sed 's/^v//')"
[[ -n $latest ]] || { echo "could not read latest version" >&2; exit 1; }

if [[ $latest == "$current" ]]; then
  echo "terraform $current is up to date"
  exit 0
fi

echo "update available: $current → $latest"
payload=$(jq -nc --arg t "Terraform $latest is available (we run $current)" '{text: $t}')
curl -fsS -X POST -H 'Content-Type: application/json' -d "$payload" "$SLACK_WEBHOOK_URL"
```

- `terraform version -json` and the GitHub API both return JSON; jq extracts the one value needed from each.
- `// empty` produces **no output** if the field is missing, so the `-n` check catches API errors.
- The Slack payload is built with `--arg`, so any characters in the text are escaped safely.

</DeepDive>

<DeepDive title="Security lens">

JSON from APIs is untrusted input, and JSON you build often carries secrets. jq helps with both, if you use it correctly.

- **Never paste untrusted values into a jq program:** `--arg` treats them as data, not code, preventing jq injection.
- **Never `eval` jq output.** Read values into variables and validate them (allow-list patterns) before using them in commands.
- **Strip secrets before sharing:** `jq 'del(.. | .password?, .token?, .apiKey?)'` removes those keys at every level of a config dump.
- **Audit IAM policies:** `jq '.Statement[] | select(.Effect=="Allow" and .Action=="*")'` finds dangerously broad permissions.
- **Security tools speak JSON:** Trivy, Semgrep, Gitleaks, AWS Security Hub and CloudTrail logs can all be filtered with jq to count and triage findings.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="How would you get a single value from a JSON API response in a Bash script?">
Pipe the response into jq with the raw flag and a path filter, for example value=$(curl -fsS URL | jq -r '.data.id'). The -r flag removes JSON quotes so the value can be used directly in Bash, and a default such as '.data.id // empty' combined with a check for an empty result handles missing fields.
</QA>

<QA q="What is the difference between . and .[] in jq?">
. is the entire input value. .[] iterates over an array (or the values of an object) and outputs each element as a separate result, so further filters are applied to each element.
</QA>

<QA q="How do you filter items in a list with jq?">
Iterate the list and use select with a condition, for example .[] | select(.cpu > 80) | .name. Wrap the expression in square brackets to keep the results as one array, or use map(select(...)).
</QA>

<QA q="Why use --arg instead of putting a shell variable inside the jq filter?">
--arg passes the value as a jq string variable, so it is treated purely as data regardless of quotes or special characters. Interpolating shell variables into the filter text can break the filter or allow the input to change the jq program itself.
</QA>

</DeepDive>
