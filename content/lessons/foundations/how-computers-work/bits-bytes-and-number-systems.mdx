<BigIdea>
<Tr>
<En>
Everything a computer stores (text, photos, music, passwords) is turned into long rows of **0s and 1s**. One 0-or-1 is a **bit**. Eight bits together are a **byte**.
</En>
<Ur>
Computer jo kuch bhi rakhta hai (text, photos, music, passwords) sab **0 aur 1** ki lambi qataron me badal diya jata hai. Ek 0-ya-1 ko **bit** kehte hain. Aath bits mil kar ek **byte** bante hain.
</Ur>
</Tr>
</BigIdea>

## At a glance

<Glance>
<What>
<Tr>
<En>

Inside a computer are billions of tiny **switches**. Each switch is either **off** or **on**. We write off as **0** and on as **1**.

- One switch = one **bit** (0 or 1).
- Eight switches in a row = one **byte**, like `01000001`.

By agreeing what each pattern means, a row of switches can store a number, a letter, or one dot of colour in a photo.

</En>
<Ur>

Computer ke andar arbon chhote chhote **switches** hote hain. Har switch ya to **off** hota hai ya **on**. Off ko hum **0** aur on ko **1** likhte hain.

- Ek switch = ek **bit** (0 ya 1).
- Aath switches ek qatar me = ek **byte**, jaise `01000001`.

Agar sab maan lein ke har pattern ka kya matlab hai, to switches ki ek qatar number, letter, ya photo ka ek rangeen nukta (dot) rakh sakti hai.

</Ur>
</Tr>
</What>
<Why>
<Tr>
<En>

You'll meet bits and bytes **everywhere** in IT:

- file sizes and internet speeds (MB vs Mb)
- colours on websites (`#ff5733`)
- file permissions on servers (`chmod 755`)
- IP addresses and networks
- password and key strength ("256-bit encryption")

</En>
<Ur>

IT me aap ko bits aur bytes **har jagah** milenge:

- file ka size aur internet speed (MB aur Mb)
- websites ke rang (`#ff5733`)
- servers par file permissions (`chmod 755`)
- IP addresses aur networks
- password aur key ki mazbooti ("256-bit encryption")

</Ur>
</Tr>
</Why>
<When>
<Tr>
<En>

Whenever you:

- wonder why your "1 TB" disk shows 931 GB
- choose a colour in CSS
- set permissions on a Linux file
- plan a network, or read a hash or a security key

</En>
<Ur>

Jab bhi aap:

- sochein ke "1 TB" disk 931 GB kyun dikhati hai
- CSS me rang chunein
- Linux file par permissions lagayen
- network plan karein, ya koi hash ya security key parhein

</Ur>
</Tr>
</When>
<How>
<Tr>
<En>

Each extra bit **doubles** how many different patterns you can make:

- 1 bit → 2 patterns (0, 1)
- 2 bits → 4 patterns (00, 01, 10, 11)
- 8 bits → **256** patterns

That's why one byte can hold any number from **0 to 255**.

</En>
<Ur>

Har nayi bit patterns ki ginti ko **dugna** kar deti hai:

- 1 bit → 2 patterns (0, 1)
- 2 bits → 4 patterns (00, 01, 10, 11)
- 8 bits → **256** patterns

Isi liye ek byte me **0 se 255** tak koi bhi number aa sakta hai.

</Ur>
</Tr>
</How>
</Glance>

## Picture it

<Tr>
<En>

Imagine a row of **light bulbs**. Each bulb is off (0) or on (1). With 8 bulbs you can make 256 different on/off patterns. Now everyone agrees: "pattern number 65 means the letter **A**". Suddenly your row of bulbs can store a letter. A computer does exactly this, with billions of bulbs.

Why only two states? Because "clearly on" and "clearly off" are **easy to tell apart**, even when the electricity is a little noisy. Ten different levels (for 0–9) would cause many more mistakes.

</En>
<Ur>

**Bulbs** ki ek qatar sochein. Har bulb off (0) hai ya on (1). 8 bulbs se 256 alag on/off patterns ban sakte hain. Ab sab maan lete hain: "pattern number 65 ka matlab letter **A** hai". Achanak bulbs ki qatar ek letter rakh sakti hai. Computer bilkul yahi karta hai, arbon bulbs ke saath.

Sirf do halatein kyun? Kyunke "saaf on" aur "saaf off" me **farq karna aasaan** hai, chahe bijli thori upar neeche ho. Das alag levels (0–9 ke liye) se ghaltiyan bohot zyada hoti.

</Ur>
</Tr>

<Step title="More bits, many more patterns">

<Tr>
<En>
Every extra bit **doubles** the number of different values. Let's see it:
</En>
<Ur>
Har nayi bit alag values ki ginti ko **dugna** kar deti hai. Dekhte hain:
</Ur>
</Tr>

```javascript
for (const bits of [1, 2, 4, 8, 16, 32]) {
  console.log(`${bits} bit(s) → ${2 ** bits} possible values`);
}
```

```text output
1 bit(s) → 2 possible values
2 bit(s) → 4 possible values
4 bit(s) → 16 possible values
8 bit(s) → 256 possible values
16 bit(s) → 65536 possible values
32 bit(s) → 4294967296 possible values
```

<Happened>
<Tr>
<En>

- `2 ** bits` means "2 multiplied by itself `bits` times" (2 to the power of bits).
- 8 bits → 256 values. That's why one byte holds 0 to 255.
- 32 bits → about **4.3 billion**. That's why there are only about 4.3 billion old-style (IPv4) internet addresses, and the world ran out of them.

</En>
<Ur>

- `2 ** bits` ka matlab: "2 ko `bits` dafa khud se zarb do" (2 ki power bits).
- 8 bits → 256 values. Isi liye ek byte me 0 se 255 tak aata hai.
- 32 bits → taqreeban **4.3 arab**. Isi wajah se purane (IPv4) internet addresses sirf 4.3 arab hain, aur duniya me ye khatam ho gaye.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="How binary counting works">

<Tr>
<En>

You already know decimal: in `345`, the 3 means **3 hundreds**, the 4 means **4 tens**, the 5 means **5 ones**. Each place is worth **10 times** the place to its right.

Binary works the same way, but each place is worth **2 times** the place to its right: 1, 2, 4, 8, 16, 32, 64, 128.

</En>
<Ur>

Decimal aap pehle se jaante hain: `345` me 3 ka matlab **3 sau**, 4 ka matlab **4 dahaiyan**, 5 ka matlab **5 ikaaiyan**. Har jagah apne right wali jagah se **10 guna** qeemat rakhti hai.

Binary bhi bilkul aise hi kaam karta hai, bas har jagah apne right wali se **2 guna** hoti hai: 1, 2, 4, 8, 16, 32, 64, 128.

</Ur>
</Tr>

```text
Decimal 345:
  3 × 100 = 300
  4 × 10  =  40
  5 × 1   =   5
            ───
            345
```

```text
Binary 11001000:
  1 × 128 = 128
  1 × 64  =  64
  0 × 32  =   0
  0 × 16  =   0
  1 × 8   =   8
  0 × 4   =   0
  0 × 2   =   0
  0 × 1   =   0
            ───
            200
```

<Callout type="analogy">
<Tr>
<En>
Think of paying with **coins of 128, 64, 32, 16, 8, 4, 2 and 1**, where you can use each coin **once or not at all**. To pay 200: take 128 (72 left), take 64 (8 left), skip 32 and 16, take 8 (0 left). Write 1 for each coin you took and 0 for each you skipped: **11001000**. That's 200 in binary.
</En>
<Ur>
Socho aap ke paas **128, 64, 32, 16, 8, 4, 2 aur 1 ke sikke** hain, aur har sikka **ek dafa ya bilkul nahi** istemal ho sakta hai. 200 dene ke liye: 128 lo (72 bache), 64 lo (8 bache), 32 aur 16 chhor do, 8 lo (0 bache). Jo sikka liya us ke liye 1, jo chhora us ke liye 0 likho: **11001000**. Yahi binary me 200 hai.
</Ur>
</Tr>
</Callout>

</Step>

<Step title="Let the computer convert for you">

<Tr>
<En>
You don't have to do conversions by hand. JavaScript can write any number in binary, octal or hex, and read it back:
</En>
<Ur>
Conversions haath se karne ki zaroorat nahi. JavaScript kisi bhi number ko binary, octal ya hex me likh sakta hai, aur wapas parh bhi sakta hai:
</Ur>
</Tr>

```javascript
const n = 200;
console.log("decimal:", n);
console.log("binary: ", n.toString(2));
console.log("octal:  ", n.toString(8));
console.log("hex:    ", n.toString(16));

console.log(parseInt("11001000", 2), parseInt("ff", 16), parseInt("755", 8));
console.log(0b11111111, 0o755, 0xff);
```

```text output
decimal: 200
binary:  11001000
octal:   310
hex:     c8
200 255 493
255 493 255
```

<Happened>
<Tr>
<En>

- `n.toString(2)` writes the number in base 2 (binary). `16` gives hex, `8` gives octal.
- `parseInt("ff", 16)` does the opposite: it reads hex text and gives a normal number (255).
- In code, you can also write numbers directly with a prefix: `0b` for binary, `0o` for octal, `0x` for hex.
- All of these are the **same number**, just written differently, like "twelve" and "12".

</En>
<Ur>

- `n.toString(2)` number ko base 2 (binary) me likhta hai. `16` se hex, `8` se octal.
- `parseInt("ff", 16)` ulta kaam karta hai: hex text parh kar aam number (255) deta hai.
- Code me number seedha prefix ke saath bhi likh sakte hain: binary ke liye `0b`, octal ke liye `0o`, hex ke liye `0x`.
- Ye sab **ek hi number** hain, bas alag tareeqe se likhe hue, jaise "barah" aur "12".

</Ur>
</Tr>
</Happened>

<Tr>
<En>
The same in the terminal (Bash):
</En>
<Ur>
Yahi kaam terminal (Bash) me:
</Ur>
</Tr>

```bash
printf 'hex of 255: %x\n' 255
printf 'octal of 8: %o\n' 8
echo "ff in decimal: $((16#ff))"
echo "1010 in decimal: $((2#1010))"
```

```text output
hex of 255: ff
octal of 8: 10
ff in decimal: 255
1010 in decimal: 10
```

</Step>

<Step title="Why programmers love hexadecimal">

<Tr>
<En>

Binary is **long** and hard to read: `111111111100100000011110`. Hex is a short way to write the same thing.

The trick: **one hex digit = exactly 4 bits**. So one byte is always exactly **2 hex digits**. Hex uses 0–9 and then the letters a–f for 10–15.

</En>
<Ur>

Binary **lamba** aur parhne me mushkil hai: `111111111100100000011110`. Hex usi cheez ko chhota likhne ka tareeqa hai.

Raaz ye hai: **ek hex digit = bilkul 4 bits**. To ek byte hamesha bilkul **2 hex digits** ka hota hai. Hex 0–9 aur phir 10–15 ke liye a–f letters istemal karta hai.

</Ur>
</Tr>

```text
binary:   1111 1111   1100 1000   0001 1110
hex:        f    f      c    8      1    e
```

<Tr>
<En>
A web colour is **three bytes**: red, green and blue, written in hex. Let's split one apart:
</En>
<Ur>
Website ka rang **teen bytes** ka hota hai: laal (red), hara (green) aur neela (blue), hex me likha hua. Chalein ek rang ko tukron me todte hain:
</Ur>
</Tr>

```javascript
const hex = "#1e40af";
const [r, g, b] = [1, 3, 5].map((i) => parseInt(hex.slice(i, i + 2), 16));
console.log(`red=${r} green=${g} blue=${b}`);
```

```text output
red=30 green=64 blue=175
```

<Happened>
<Tr>
<En>

- `#1e40af` is three pairs: `1e`, `40`, `af`.
- Each pair is one byte (0–255): red 30, green 64, blue 175. That's a dark blue.
- You'll also see hex in hashes, network card (MAC) addresses and error codes.

</En>
<Ur>

- `#1e40af` teen joron se bana hai: `1e`, `40`, `af`.
- Har jora ek byte hai (0–255): red 30, green 64, blue 175. Ye gehra neela rang hai.
- Hex aap ko hashes, network card (MAC) addresses aur error codes me bhi milega.

</Ur>
</Tr>
</Happened>

<Tr>
<En>
Even text is just bytes. This shows the bytes of the word "Hi" in hex:
</En>
<Ur>
Text bhi asal me bytes hi hai. Ye lafz "Hi" ke bytes hex me dikhata hai:
</Ur>
</Tr>

```bash
printf '%s' "Hi" | od -An -tx1
```

```text output

```

<Tr>
<En>
`48` is "H" and `69` is "i" (72 and 105 in normal numbers).
</En>
<Ur>
`48` matlab "H" aur `69` matlab "i" (aam numbers me 72 aur 105).
</Ur>
</Tr>

<Step title="Octal and Linux file permissions">

<Tr>
<En>

On Linux, every file has permissions: who can **read** it (r), **write** (change) it (w), and **execute** (run) it (x). These are given to three groups: the **owner**, the **group**, and **everyone else**.

Each permission has a number: **r = 4, w = 2, x = 1**. Add them up for each group, and you get one digit from 0 to 7 (that's octal). So `755` means:

- owner: 7 = 4 + 2 + 1 = read, write, run
- group: 5 = 4 + 1 = read, run
- everyone else: 5 = read, run

</En>
<Ur>

Linux par har file ki permissions hoti hain: kaun use **parh** sakta hai (r), **likh/badal** sakta hai (w), aur **chala** sakta hai (x). Ye teen groups ko di jati hain: **owner (maalik)**, **group**, aur **baqi sab**.

Har permission ka ek number hai: **r = 4, w = 2, x = 1**. Har group ke liye inhe jor dein, to 0 se 7 tak ek digit milta hai (yahi octal hai). To `755` ka matlab:

- owner: 7 = 4 + 2 + 1 = parhna, likhna, chalana
- group: 5 = 4 + 1 = parhna, chalana
- baqi sab: 5 = parhna, chalana

</Ur>
</Tr>

```javascript
const toRwx = (digit) => (digit & 4 ? "r" : "-") + (digit & 2 ? "w" : "-") + (digit & 1 ? "x" : "-");
for (const mode of ["755", "644", "600", "777"]) {
  console.log(mode, "=", [...mode].map((d) => toRwx(Number(d))).join(""));
}
```

```text output
755 = rwxr-xr-x
644 = rw-r--r--
600 = rw-------
777 = rwxrwxrwx
```

<Happened>
<Tr>
<En>

- `644` is normal for files: the owner can read and write; everyone else can only read.
- `600` is for secrets: **only** the owner can read or write.
- `777` lets **everyone** do everything. It's almost always a mistake.

</En>
<Ur>

- `644` aam files ke liye: owner parh aur likh sakta hai; baqi sab sirf parh sakte hain.
- `600` raaz (secrets) wali files ke liye: **sirf** owner parh ya likh sakta hai.
- `777` **sab ko** sab kuch karne deta hai. Ye taqreeban hamesha ghalti hoti hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="KB vs KiB: why a 1 TB disk shows 931 GB">

<Tr>
<En>

There are **two ways** to count big sizes:

- **KB, MB, GB, TB** go up in steps of **1000** (used by disk makers and internet companies).
- **KiB, MiB, GiB, TiB** go up in steps of **1024** (used by Windows, Linux and Kubernetes).

Your "1 TB" disk has 1,000,000,000,000 bytes. Windows divides by 1024 three times and shows **931 GB**. Nothing is missing.

And internet speeds are in **bits**, not bytes. 100 **Mb**ps divided by 8 ≈ 12.5 **MB** per second.

</En>
<Ur>

Bare sizes ginne ke **do tareeqe** hain:

- **KB, MB, GB, TB** **1000** ke qadmon me barhte hain (disk banane wali aur internet companies istemal karti hain).
- **KiB, MiB, GiB, TiB** **1024** ke qadmon me barhte hain (Windows, Linux aur Kubernetes istemal karte hain).

Aap ki "1 TB" disk me 1,000,000,000,000 bytes hain. Windows teen dafa 1024 se taqseem karke **931 GB** dikhata hai. Kuch ghaib nahi hua.

Aur internet speed **bits** me hoti hai, bytes me nahi. 100 **Mb**ps ko 8 se taqseem karo ≈ 12.5 **MB** har second.

</Ur>
</Tr>

```javascript
const disk = 1e12;                         // "1 TB" on the box
console.log("1 TB in GiB:", (disk / 1024 ** 3).toFixed(1));
const mbps = 100;                          // internet plan in megabits per second
console.log(`${mbps} Mbps ≈ ${mbps / 8} MB per second`);
```

```text output
1 TB in GiB: 931.3
100 Mbps ≈ 12.5 MB per second
```

| Steps of 1000 | Bytes | Steps of 1024 | Bytes |
| --- | --- | --- | --- |
| 1 KB | 1,000 | 1 KiB | 1,024 |
| 1 MB | 1,000,000 | 1 MiB | 1,048,576 |
| 1 GB | 1,000,000,000 | 1 GiB | 1,073,741,824 |

</Step>

<Step title="When a number is too big for its box (overflow)">

<Tr>
<En>

Sometimes a number is stored in a box with a **fixed number of bits**. If the number gets too big, it **wraps around to the start**, like a car's distance counter going from 99999 back to 00000. This is called **overflow**.

</En>
<Ur>

Kabhi number aise dabbe me rakha jata hai jis me bits ki **ginti fix** hoti hai. Agar number bohot bara ho jaye to wo **wapas shuru par chala jata hai**, jaise gaari ka meter 99999 se 00000 par aa jaye. Isay **overflow** kehte hain.

</Ur>
</Tr>

```javascript
const oneByte = new Uint8Array([255]);
oneByte[0] += 1;
console.log("255 + 1 in one byte =", oneByte[0]);

const int32 = new Int32Array([2147483647]);
int32[0] += 1;
console.log("max 32-bit int + 1 =", int32[0]);
```

```text output
255 + 1 in one byte = 0
max 32-bit int + 1 = -2147483648
```

<Happened>
<Tr>
<En>

- One byte can only hold up to 255, so 255 + 1 wraps to **0**.
- A 32-bit number (which can also be negative) wraps from its biggest value to a **huge negative** one.
- Real bugs: database IDs that stop working after 2.1 billion rows, and money totals that suddenly become negative.

</En>
<Ur>

- Ek byte sirf 255 tak rakh sakta hai, isliye 255 + 1 ghoom kar **0** ho jata hai.
- 32-bit number (jo manfi bhi ho sakta hai) apni sab se bari qeemat se ghoom kar **bohot bara manfi** number ban jata hai.
- Asal bugs: database IDs jo 2.1 arab rows ke baad kaam karna chhor dete hain, aur paison ke totals jo achanak manfi ho jate hain.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Why 0.1 + 0.2 is not exactly 0.3">

<Tr>
<En>

Some simple decimals, like **0.1**, can't be written exactly in binary. It's the same reason **1/3** can't be written exactly in decimal (0.3333… goes on forever). So the computer stores a value that's **very, very close**, and tiny errors appear.

For money, this matters. The safe way: store amounts as **whole numbers of the smallest unit** (cents), and only turn them into decimals for display.

</En>
<Ur>

Kuch aasaan decimals, jaise **0.1**, binary me bilkul theek nahi likhe ja sakte. Wajah wahi hai jis wajah se **1/3** decimal me poora nahi likha ja sakta (0.3333… khatam hi nahi hota). To computer **bohot qareeb** wali value rakhta hai, aur chhoti chhoti ghaltiyan aa jati hain.

Paison ke liye ye bohot ahem hai. Mehfooz tareeqa: raqam ko **sab se chhoti unit ke poore numbers** (cents) me rakhein, aur sirf dikhate waqt decimal me badlein.

</Ur>
</Tr>

```javascript
console.log(0.1 + 0.2);
console.log(0.1 + 0.2 === 0.3);
const priceCents = 10 + 20;                 // store money as whole cents
console.log("$" + (priceCents / 100).toFixed(2));
```

```text output
0.30000000000000004
false
$0.30
```

<Happened>
<Tr>
<En>

- `0.1 + 0.2` gives `0.30000000000000004`, so comparing it with `0.3` says `false`.
- Adding **10 + 20 cents** gives exactly 30, and we only divide by 100 at the end to show `$0.30`.

</En>
<Ur>

- `0.1 + 0.2` ka jawab `0.30000000000000004` aata hai, isliye `0.3` se mawazna `false` deta hai.
- **10 + 20 cents** jorne se bilkul 30 aata hai, aur dikhane ke liye aakhir me hi 100 se taqseem karte hain: `$0.30`.

</Ur>
</Tr>
</Happened>

</Step>

## Common mistakes

<Compare>
<Bad title="Mixing up bits and bytes">

<Tr>
<En>"My 50 Mbps internet should download 50 MB every second."</En>
<Ur>"Mera 50 Mbps internet har second 50 MB download karega."</Ur>
</Tr>

</Bad>
<Good title="Divide by 8">

<Tr>
<En>50 Mbps ÷ 8 ≈ **6 MB** per second. Small **b** = bits, big **B** = bytes.</En>
<Ur>50 Mbps ÷ 8 ≈ **6 MB** har second. Chhota **b** = bits, bara **B** = bytes.</Ur>
</Tr>

</Good>
</Compare>

<Compare>
<Bad title="Decimals for money">

```javascript
let total = 0.1 + 0.2;   // 0.30000000000000004
```

</Bad>
<Good title="Whole cents">

```javascript
let totalCents = 10 + 20;   // 30, exactly
```

</Good>
</Compare>

<Compare>
<Bad title="Thinking hex hides secrets">

<Tr>
<En>Writing a password in hex (`70617373`) doesn't protect it. Anyone can turn it back into text in one second.</En>
<Ur>Password ko hex (`70617373`) me likhne se wo mehfooz nahi hota. Koi bhi use ek second me wapas text bana sakta hai.</Ur>
</Tr>

</Bad>
<Good title="Hex is just another way to write bytes">

<Tr>
<En>To protect secrets you need **encryption** (a later lesson), not a different way of writing them.</En>
<Ur>Secrets bachane ke liye **encryption** chahiye (agla lesson), sirf likhne ka tareeqa badalna kaafi nahi.</Ur>
</Tr>

</Good>
</Compare>

<Compare>
<Bad title="chmod 777 to 'fix' a permission error">

<Tr>
<En>Gives **everyone** on the server permission to change or run the file.</En>
<Ur>Server par **har kisi** ko file badalne ya chalane ki ijazat de deta hai.</Ur>
</Tr>

</Bad>
<Good title="Give only what's needed">

<DeepDive title="Hands-on in the terminal: bytes, hashes and random tokens">

```bash
# 1. Bytes of a word as hex
printf '%s' "DevGuide" | od -An -tx1

# 2. Conversions in Bash
for n in 10 255 1024; do printf '%5d = hex %-4x = octal %-5o\n' "$n" "$n" "$n"; done

# 3. A SHA-256 hash: 256 bits = 32 bytes = 64 hex characters
h=$(echo -n "hello" | sha256sum | cut -d' ' -f1)
echo "$h"
echo "length: ${#h} hex characters"

# 4. Random secret: 16 bytes = 128 bits
token=$(head -c 16 /dev/urandom | od -An -tx1 | tr -d ' \n')
echo "token length: ${#token} hex characters"
```

```text output

  255 = hex ff   = octal 377

2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
length: 64 hex characters
token length: 32 hex characters
```

- A SHA-256 hash is always 256 bits, which is 64 hex characters, whatever you hash.
- 16 random bytes (128 bits) is a strong secret token: 2¹²⁸ possibilities.

<DeepDive title="Real world: planning a cloud network with binary">

You create a private network (VPC) on AWS with the range `10.0.0.0/16`. What does `/16` mean?

1. An IPv4 address is 32 bits, written as four bytes: `10.0.0.0`.
2. `/16` says the first 16 bits are fixed (the network); the remaining **16 bits** are yours.
3. 16 bits give 2¹⁶ = **65,536** addresses.
4. You split it into `/24` subnets: 8 host bits each, so 256 addresses (AWS reserves 5 per subnet, leaving 251 usable).

Without binary you copy numbers from a tutorial; with it you can plan how many subnets, servers and Kubernetes pods your network can hold. You'll do exactly this in the Networking and Cloud topics.

</DeepDive>

<DeepDive title="Security lens">

- **Key and token strength is measured in bits.** A 128-bit random token has 2¹²⁸ possible values, far beyond brute force. A 6-digit PIN has only 1,000,000 (about 20 bits): easy to brute force without rate limiting.
- **Hex and Base64 are encodings, not protection.** Credentials "hidden" as hex in a config file or front-end code are exposed.
- **Integer overflow** has caused real vulnerabilities: a length check overflows, a small buffer is allocated, and an attacker writes past it. In business logic, overflow can turn a huge quantity into a negative price.
- **Bit flags.** Permissions are often stored as bit fields. Setting one wrong bit (`chmod 777` instead of `755`) gives write access to everyone.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="How many values can be represented with 8 bits? With 32 bits?">
n bits represent 2ⁿ values. 8 bits give 256 values (0–255 unsigned). 32 bits give 2³² ≈ 4.29 billion, which is why IPv4, a 32-bit address space, ran out of addresses and IPv6 uses 128 bits.
</QA>

<QA q="Why do developers use hexadecimal instead of binary?">
One hex digit maps exactly to four bits, so every byte is exactly two hex digits. It is far shorter and easier to read than binary, but converts to binary instantly, unlike decimal. That's why hashes, colours, memory addresses and MAC addresses are shown in hex.
</QA>

<QA q="Why does 0.1 + 0.2 not equal 0.3 in JavaScript, and how do you handle money?">
JavaScript numbers are IEEE 754 64-bit floats. 0.1 and 0.2 have no exact binary representation, so the stored values are tiny approximations and the sum is 0.30000000000000004. For money, store integer amounts of the smallest unit (cents), or use a decimal type such as PostgreSQL NUMERIC, and format only for display.
</QA>

<QA q="What does chmod 640 mean?">
Each digit is an octal number made of read (4), write (2) and execute (1) bits for owner, group and others. 6 = read and write for the owner; 4 = read for the group; 0 = no access for others. It's a common mode for files holding secrets that one service group needs to read.
</QA>

<QA q="What is the difference between 1 GB and 1 GiB?">
1 GB is 10⁹ bytes (decimal, used by disk vendors and networking). 1 GiB is 2³⁰ = 1,073,741,824 bytes (binary, used by operating systems and Kubernetes Gi). The difference is about 7% and grows with each prefix.
</QA>

</DeepDive>
