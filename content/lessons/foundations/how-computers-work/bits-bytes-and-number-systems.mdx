<Callout type="tip" title="In one minute">
A **bit** is a single 0 or 1. Eight bits make a **byte**, which can hold 256 different values (0–255). Computers count in **binary** (base 2); humans read binary more easily as **hexadecimal** (base 16), where one hex digit is exactly four bits. You will see these everywhere: file permissions (`755`), colours (`#FF5733`), IP addresses and subnet masks, hashes, memory addresses and file sizes.
</Callout>

## What is it?

A computer is built from billions of tiny electronic switches (transistors). Each switch is either **off** or **on**. We write those two states as **0** and **1**. One such value is a **bit** (short for *binary digit*).

One bit can only say yes or no. Group bits together and the number of possible patterns doubles with every bit you add:

| Bits | Possible patterns | Example use |
| --- | --- | --- |
| 1 | 2 | true / false |
| 4 | 16 | one hexadecimal digit |
| 8 (1 byte) | 256 | one ASCII character, one part of an IPv4 address |
| 16 | 65,536 | number of TCP/UDP ports |
| 32 | about 4.29 billion | an IPv4 address |
| 64 | about 18 quintillion | integers and memory addresses on modern CPUs |
| 128 | 3.4 × 10^38 | an IPv6 address, a UUID |

The rule: **n bits give 2ⁿ patterns.**

A **byte** is 8 bits. It is the smallest unit most systems read and write, which is why file sizes, memory and network data are measured in bytes.

### Number systems

A number system (or **base**) is how many different digits you have before you "carry" to the next position.

| System | Base | Digits | Written as | Where you see it |
| --- | --- | --- | --- | --- |
| Decimal | 10 | 0–9 | `255` | Everyday numbers |
| Binary | 2 | 0, 1 | `0b11111111` | What hardware actually stores |
| Octal | 8 | 0–7 | `0o377` | Linux file permissions (`chmod 755`) |
| Hexadecimal | 16 | 0–9, A–F | `0xFF` | Colours, hashes, memory addresses, MAC addresses |

All four lines in that table are the **same number**: 255.

## Why does it matter?

You will rarely do binary arithmetic by hand, but you will constantly read things that only make sense if you understand it:

- **Networking:** a subnet like `192.168.1.0/24` means "the first 24 bits are the network". You cannot understand CIDR without binary.
- **Linux:** `chmod 640 file` is three octal digits, each one a group of three permission bits.
- **Security:** hashes (`sha256`), keys and tokens are shown in hex. "128-bit key" tells you how many guesses brute force needs.
- **Web:** colours (`#1C1B18`), Unicode code points (`U+00E9`) and URL encoding (`%20`) are hex.
- **Cloud and DevOps:** memory limits (`512Mi`), disk sizes and bandwidth bills are all byte units — and getting `MB` vs `MiB` wrong causes real mistakes.
- **Bugs:** integer overflow, floating-point rounding (`0.1 + 0.2`) and "my number got corrupted" bugs all come from how numbers are stored in bits.

## When and where do you use it?

- Reading `ls -l` output or setting permissions with `chmod`.
- Working out how many hosts fit in a subnet when designing an AWS VPC.
- Reading a SHA-256 hash to verify a download, or a Git commit ID (which is a hex hash).
- Setting Kubernetes resource limits (`memory: 256Mi`).
- Debugging a hex dump of a network packet in Wireshark.
- Generating a secure random token (`32 bytes → 64 hex characters`).

## How does it work?

### Positional notation

In decimal, each position is worth 10 times the one to its right:

```text
  2       5       5
  ×100    ×10     ×1      = 200 + 50 + 5 = 255
```

Binary works the same way, but each position is worth **2 times** the one to its right:

```text
bit value:  128  64  32  16   8   4   2   1
bits:         1   1   1   1   1   1   1   1   = 255
bits:         1   1   0   0   0   0   0   0   = 128 + 64 = 192
bits:         0   0   0   0   1   0   1   0   = 8 + 2 = 10
```

**Binary → decimal:** add the values of the positions that hold a 1.

**Decimal → binary:** subtract the largest power of 2 that fits, mark a 1, and repeat.

```text
200 → 128 fits (1), 72 left
 72 →  64 fits (1),  8 left
  8 →  32 no (0), 16 no (0), 8 fits (1), 0 left
  0 →  4 no (0), 2 no (0), 1 no (0)
200 = 11001000
```

### Why hexadecimal exists

Binary is long and hard to read. One hex digit represents **exactly 4 bits**, so a byte is always exactly two hex digits:

```text
binary   1100 1000
hex         C    8      → 0xC8 = 200
```

| Hex | Binary | Decimal |
| --- | --- | --- |
| 0 | 0000 | 0 |
| 7 | 0111 | 7 |
| 9 | 1001 | 9 |
| A | 1010 | 10 |
| C | 1100 | 12 |
| F | 1111 | 15 |

That is why a SHA-256 hash (256 bits = 32 bytes) is always **64 hex characters** long.

### Why octal still shows up: Linux permissions

Linux permissions are three groups of three bits: read (4), write (2), execute (1).

```text
       owner   group   others
bits   r w x   r - x   r - x
       1 1 1   1 0 1   1 0 1
octal    7       5       5       → chmod 755
```

One octal digit is exactly three bits, which matches each permission group perfectly.

### Units: KB vs KiB

There are two systems, and they are often mixed up:

| Decimal (SI) | Bytes | Binary (IEC) | Bytes |
| --- | --- | --- | --- |
| 1 KB | 1,000 | 1 KiB | 1,024 |
| 1 MB | 1,000,000 | 1 MiB | 1,048,576 |
| 1 GB | 10^9 | 1 GiB | 1,073,741,824 |

Disk manufacturers and network speeds use decimal. Operating systems and Kubernetes (`Mi`, `Gi`) use binary. A "1 TB" disk shows as about 931 GiB — nothing is missing; the units are different.

Also note: **bits vs bytes**. Network speeds are in **bits** per second (`100 Mbps`); file sizes are in **bytes**. A 100 Mbps connection downloads at most about 12.5 MB/s.

### Negative numbers and overflow

With a fixed number of bits, numbers have a limit. An 8-bit unsigned value holds 0–255. Add 1 to 255 and it **wraps around** to 0. Signed integers use a scheme called **two's complement**, where the top bit marks negative numbers; a signed 8-bit value holds −128 to 127.

This wrap-around is called **integer overflow**, and it has caused real security bugs and crashes.

### Floating point: why 0.1 + 0.2 is not 0.3

Decimal fractions such as 0.1 cannot be written exactly in binary, just like 1/3 cannot be written exactly in decimal (0.3333…). Most languages, including JavaScript, store numbers as 64-bit **IEEE 754 floating point**, so tiny rounding errors appear.

The practical rule: **never store money as floating-point numbers.** Store the smallest unit (paisa, cents) as an integer, or use a decimal type in your database (`NUMERIC` in PostgreSQL).

## Hands-on

Run this in the playground — it shows every conversion from this lesson.

```javascript
// Converting between bases
const n = 200;
console.log("binary:", n.toString(2));       // 11001000
console.log("octal: ", n.toString(8));       // 310
console.log("hex:   ", n.toString(16));      // c8

console.log(parseInt("11001000", 2));        // 200
console.log(parseInt("ff", 16));             // 255
console.log(0b1111_1111, 0o755, 0xff);       // 255 493 255

// How many values fit in n bits?
for (const bits of [1, 4, 8, 16, 32]) {
  console.log(bits + " bits ->", (2 ** bits).toLocaleString(), "values");
}

// Pad to 8 bits so bytes line up
const toByte = (x) => x.toString(2).padStart(8, "0");
console.log("192 =", toByte(192), " 168 =", toByte(168));

// Floating point surprise — and the integer fix
console.log(0.1 + 0.2);                       // 0.30000000000000004
console.log((10 + 20) / 100);                 // store paisa/cents as integers instead

// Linux permissions: 755 in octal is three 3-bit groups
const perms = 0o755;
const group = (shift) => {
  const v = (perms >> shift) & 0b111;
  return (v & 4 ? "r" : "-") + (v & 2 ? "w" : "-") + (v & 1 ? "x" : "-");
};
console.log("755 =", group(6) + group(3) + group(0)); // rwxr-xr-x

// Overflow in a fixed-size integer
const bytes = new Uint8Array([255]);
bytes[0] += 1;
console.log("255 + 1 in one byte =", bytes[0]); // 0
```

And on a Linux terminal:

```bash
# See a file's bytes as hex
echo -n "Hi" | xxd
# 00000000: 4869                                     Hi

# A SHA-256 hash is 256 bits = 64 hex characters
echo -n "hello" | sha256sum
# 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824  -

# 32 random bytes as hex — a typical secret token
openssl rand -hex 32
```

## Real-world example

You are designing a VPC on AWS and choose the range `10.0.0.0/16`. What does `/16` mean?

1. An IPv4 address is 32 bits, written as four bytes: `10.0.0.0`.
2. `/16` says the first 16 bits are fixed (the network); the remaining **16 bits** are yours.
3. 16 bits give 2¹⁶ = **65,536** addresses.
4. You split it into subnets of `/24`: 8 host bits each, so 256 addresses (AWS reserves 5 per subnet, leaving 251 usable).

Without binary you are copying numbers from a tutorial. With it you can plan how many subnets, servers and Kubernetes pods your network can hold — and you will do exactly this in the Networking and Cloud tracks.

## Common mistakes

- **Confusing bits and bytes.** "My 50 Mbps connection should download 50 MB per second" — no, about 6 MB/s.
- **Mixing MB and MiB** when setting memory limits; a container limited to `500M` vs `500Mi` gets different amounts.
- **Using floats for money.** Rounding errors become wrong invoices. Use integers of the smallest unit or `NUMERIC`.
- **Reading `chmod 777` as "seven hundred seventy-seven".** It is three separate octal digits: full access for owner, group and everyone.
- **Thinking hex is encryption.** Hex is just another way to write the same bytes. Anyone can decode it.

## Security lens

<Callout type="security">
Key sizes, token entropy, integer overflows and "encoding is not encryption" are all binary concepts. Attackers think in bytes; defenders need to as well.
</Callout>

- **Key and token strength is measured in bits.** A 128-bit random token has 2¹²⁸ possible values — far beyond brute force. A 6-digit PIN has only 1,000,000 (about 20 bits) — trivial to brute force without rate limiting.
- **Hex and Base64 are encodings, not protection.** Credentials "hidden" as hex in a config file or front-end code are exposed.
- **Integer overflow** has caused real vulnerabilities: a length check overflows, a small buffer is allocated, and an attacker writes past it. In business logic, overflow can turn a huge quantity into a negative price.
- **Bit flags.** Permissions are often stored as bit fields. Misreading or mis-setting one bit (`chmod 777` instead of `755`) gives write access to everyone.

## Interview questions

<QA q="How many values can be represented with 8 bits? With 32 bits?">
n bits represent 2ⁿ values. 8 bits give 256 values (0–255 unsigned). 32 bits give 2³² ≈ 4.29 billion — which is why IPv4, a 32-bit address space, ran out of addresses and IPv6 uses 128 bits.
</QA>

<QA q="Why do developers use hexadecimal instead of binary?">
One hex digit maps exactly to four bits, so every byte is exactly two hex digits. It is far shorter and easier to read than binary, but it converts to binary instantly in your head, unlike decimal. That is why hashes, colours, memory addresses and MAC addresses are shown in hex.
</QA>

<QA q="Why does 0.1 + 0.2 not equal 0.3 in JavaScript, and how do you handle money?">
JavaScript numbers are IEEE 754 64-bit floats. 0.1 and 0.2 have no exact binary representation, so the stored values are tiny approximations and the sum is 0.30000000000000004. For money, store integer amounts of the smallest unit (cents or paisa), or use a decimal type such as PostgreSQL NUMERIC, and format only for display.
</QA>

<QA q="What does chmod 640 mean?">
Each digit is an octal number made of read (4), write (2) and execute (1) bits for owner, group and others. 6 = 4 + 2 = read and write for the owner; 4 = read for the group; 0 = no access for others. It is a common mode for files holding secrets that one service group needs to read.
</QA>

<QA q="What is the difference between 1 GB and 1 GiB?">
1 GB is 10⁹ bytes (decimal, used by disk vendors and networking). 1 GiB is 2³⁰ = 1,073,741,824 bytes (binary, used by operating systems and Kubernetes `Gi`). The difference is about 7% and grows with each prefix.
</QA>

## Key terms

<Terms>
  <Term name="Bit">A single binary digit: 0 or 1.</Term>
  <Term name="Byte">8 bits; 256 possible values.</Term>
  <Term name="Binary">Base-2 number system, digits 0 and 1.</Term>
  <Term name="Hexadecimal">Base-16 number system, digits 0–9 and A–F. One digit equals 4 bits.</Term>
  <Term name="Octal">Base-8 number system. One digit equals 3 bits; used for Linux permissions.</Term>
  <Term name="KiB / MiB / GiB">Binary units: powers of 1,024.</Term>
  <Term name="Integer overflow">When a value exceeds the maximum for its size and wraps around.</Term>
  <Term name="Floating point">A way of storing fractional numbers in binary that can introduce small rounding errors.</Term>
  <Term name="Entropy">How unpredictable a value is, measured in bits. More bits, harder to guess.</Term>
</Terms>
