<Callout type="tip" title="In one minute">
A computer stores everything — text, photos, passwords, IP addresses — as **bits**: tiny switches that are either **0** (off) or **1** (on). 8 bits make a **byte**, which can hold 256 different values (0–255). Humans count in **decimal** (base 10); computers use **binary** (base 2); programmers write long binary numbers more compactly in **hexadecimal** (base 16, digits 0–9 and a–f). Linux permissions use **octal** (base 8). Sizes: 1 KB = 1000 bytes, 1 KiB = 1024 bytes.
</Callout>

## Start from zero

### Why only 0 and 1?

Inside a computer there are billions of tiny electronic switches (transistors). A switch has two states: **off** or **on** — no electricity or electricity. We write these two states as **0** and **1**.

<Callout type="analogy">
Imagine a row of **light bulbs**. Each bulb can only be off (0) or on (1). With 1 bulb you can show 2 different patterns. With 2 bulbs: 4 patterns (off-off, off-on, on-off, on-on). With 8 bulbs: 256 patterns. If everyone agrees "pattern number 65 means the letter A", a row of bulbs can store a letter. That is all a computer does — with billions of bulbs.
</Callout>

Two states are used because they are **reliable**: it is easy to tell "clearly on" from "clearly off", even with electrical noise. Ten different voltage levels (for 0–9) would be far more error-prone.

### Words you need first

| Word | Simple meaning | Example |
| --- | --- | --- |
| **Bit** | One binary digit: 0 or 1 | `1` |
| **Byte** | A group of 8 bits | `01000001` |
| **Binary** | Counting with only 0 and 1 (base 2) | `101` = 5 |
| **Decimal** | Normal counting with 0–9 (base 10) | `255` |
| **Hexadecimal (hex)** | Counting with 0–9 and a–f (base 16) | `ff` = 255 |
| **Octal** | Counting with 0–7 (base 8) | `755` |
| **Base** | How many different digits a number system has | binary is base 2 |
| **Encoding** | An agreed meaning for bit patterns | 65 = "A" |

## What is it?

- A **bit** is the smallest piece of information: 0 or 1.
- A **byte** is 8 bits. It is the basic unit computers use to store and count data.
- **Number systems** are different ways of writing the same quantity. 255 (decimal) = 11111111 (binary) = ff (hex) = 377 (octal) — all the same number.

| Name | Base | Digits | Written in code as | Example: 200 |
| --- | --- | --- | --- | --- |
| Decimal | 10 | 0–9 | `200` | 200 |
| Binary | 2 | 0, 1 | `0b11001000` | 11001000 |
| Octal | 8 | 0–7 | `0o310` | 310 |
| Hexadecimal | 16 | 0–9, a–f | `0xc8` | c8 |

## Why does it matter?

- **Everywhere in IT:** IP addresses and subnets (networking), file permissions like `755` (Linux), colours like `#ff5733` (web), hashes and keys (security), memory addresses (debugging).
- **Sizes and speeds:** disk space, RAM, network bandwidth (megabits vs megabytes), cloud bills.
- **Bugs:** money calculations that are off by a tiny amount, counters that suddenly become negative, "my 1 TB disk shows 931 GB".
- **Security:** key lengths (128-bit, 256-bit), random tokens, hex dumps in malware analysis.

## When and where do you use it?

| You will see | Number system | Example |
| --- | --- | --- |
| Subnet masks, IP math | Binary | `255.255.255.0` = 24 ones |
| Colours in CSS | Hex | `#1e40af` |
| Hashes, tokens, MAC addresses | Hex | `2cf24dba…`, `00:1a:2b:…` |
| Linux permissions | Octal | `chmod 644` |
| File and disk sizes | Bytes, KiB/MiB/GiB | `4.0K`, `1.2G` |

## Concepts one by one

### 1. Bits and bytes

<Explain>
<What>
A **bit** is one 0-or-1 value. A **byte** is 8 bits side by side.
</What>
<Why>
One bit can only say yes/no. Grouping 8 bits gives 256 combinations — enough for a letter, a small number, or one colour channel.
</Why>
<When>
Every piece of data is measured in bytes: files, memory, network traffic.
</When>
<Where>
File sizes, RAM, disk space, data limits, network speeds.
</Where>
<How>
Each extra bit **doubles** the number of possible values: n bits give 2ⁿ values.
</How>
</Explain>

```javascript
for (const bits of [1, 2, 4, 8, 16, 32]) {
  console.log(`${bits} bit(s) → ${2 ** bits} possible values`);
}
```

```text output
1 bit(s) → 2 possible values
2 bit(s) → 4 possible values
4 bit(s) → 16 possible values
8 bit(s) → 256 possible values
16 bit(s) → 65536 possible values
32 bit(s) → 4294967296 possible values
```

- `2 ** bits` means "2 to the power of bits".
- 8 bits → 256 values: that is why a byte holds 0–255.
- 32 bits → about 4.3 billion: that is why there are only about 4.3 billion IPv4 addresses.

### 2. How positional number systems work

<Explain>
<What>
In every number system, a digit's value depends on its **position**. Each position is worth the base times the position to its right.
</What>
<Why>
Once you understand this for decimal (which you already use), binary, hex and octal work exactly the same way.
</Why>
<When>
Whenever you convert between number systems.
</When>
<Where>
Networking (subnets), permissions, debugging.
</Where>
<How>
Decimal positions are 1, 10, 100, 1000… (powers of 10). Binary positions are 1, 2, 4, 8, 16, 32, 64, 128… (powers of 2). Multiply each digit by its position value and add.
</How>
</Explain>

```text
Decimal 345:            Binary 11001000:
  3 × 100 = 300           1 × 128 = 128
  4 × 10  =  40           1 × 64  =  64
  5 × 1   =   5           0 × 32  =   0
            ───           0 × 16  =   0
            345           1 × 8   =   8
                          0 × 4   =   0
                          0 × 2   =   0
                          0 × 1   =   0
                                    ───
                                    200
```

<Callout type="analogy">
Binary is like paying with notes of **128, 64, 32, 16, 8, 4, 2 and 1 rupees**, and you may use each note **once or not at all**. To pay 200: take 128 (72 left), take 64 (8 left), skip 32 and 16, take 8 (0 left). The notes you took are the 1s: `11001000`.
</Callout>

### 3. Converting between number systems

<Explain>
<What>
Changing how a number is written without changing its value.
</What>
<Why>
Different tools show the same value differently: a subnet in binary, a colour in hex, a permission in octal.
</Why>
<When>
Reading permissions, subnets, colours, hex dumps.
</When>
<Where>
Programming languages, the terminal, calculators.
</Where>
<How>
In JavaScript: `n.toString(2)` writes a number in binary (16 for hex, 8 for octal); `parseInt("ff", 16)` reads it back. In Bash: `printf '%x\n' 255` and `$((16#ff))`.
</How>
</Explain>

```javascript
const n = 200;
console.log("decimal:", n);
console.log("binary: ", n.toString(2));
console.log("octal:  ", n.toString(8));
console.log("hex:    ", n.toString(16));

console.log(parseInt("11001000", 2), parseInt("ff", 16), parseInt("755", 8));
console.log(0b11111111, 0o755, 0xff);
```

```text output
decimal: 200
binary:  11001000
octal:   310
hex:     c8
200 255 493
255 493 255
```

The same in Bash:

```bash
printf 'hex of 255: %x\n' 255
printf 'octal of 8: %o\n' 8
echo "ff in decimal: $((16#ff))"
echo "1010 in decimal: $((2#1010))"
```

```text output
hex of 255: ff
octal of 8: 10
ff in decimal: 255
1010 in decimal: 10
```

### 4. Why hexadecimal exists

<Explain>
<What>
A base-16 system using digits 0–9 and letters a–f (a = 10 … f = 15).
</What>
<Why>
Binary is very long and hard to read. One hex digit represents **exactly 4 bits**, so one byte is always exactly 2 hex digits. It is a compact, readable way to write binary.
</Why>
<When>
Whenever raw bytes are shown to humans.
</When>
<Where>
Colours (`#ff8800`), hashes, MAC addresses, IPv6, memory addresses, hex dumps.
</Where>
<How>
Split the binary into groups of 4 bits and replace each group with one hex digit.
</How>
</Explain>

```text
binary:   1111 1111   1100 1000   0001 1110
hex:        f    f      c    8      1    e
```

```bash
printf '%s' "Hi" | od -An -tx1
```

```text output
 48 69
```

`od -An -tx1` shows the bytes of the text "Hi" in hex (`xxd` does the same on systems that have it): `48` is "H" and `69` is "i" in hex (72 and 105 in decimal).

A web colour is three bytes — red, green, blue — written in hex:

```javascript
const hex = "#1e40af";
const [r, g, b] = [1, 3, 5].map((i) => parseInt(hex.slice(i, i + 2), 16));
console.log(`red=${r} green=${g} blue=${b}`);
```

```text output
red=30 green=64 blue=175
```

### 5. Octal and Linux permissions

<Explain>
<What>
Base 8 (digits 0–7). Each octal digit represents exactly **3 bits**.
</What>
<Why>
Linux permissions are three groups of three bits — read, write, execute for owner, group and others — so one octal digit fits each group perfectly.
</Why>
<When>
Setting permissions with `chmod`.
</When>
<Where>
Linux, macOS, Docker, deployment scripts.
</Where>
<How>
r = 4, w = 2, x = 1. Add them per group: rwx = 7, r-x = 5, r-- = 4. So `755` = `rwxr-xr-x`.
</How>
</Explain>

```javascript
const toRwx = (digit) => (digit & 4 ? "r" : "-") + (digit & 2 ? "w" : "-") + (digit & 1 ? "x" : "-");
for (const mode of ["755", "644", "600", "777"]) {
  console.log(mode, "=", [...mode].map((d) => toRwx(Number(d))).join(""));
}
```

```text output
755 = rwxr-xr-x
644 = rw-r--r--
600 = rw-------
777 = rwxrwxrwx
```

### 6. Size units: KB vs KiB

<Explain>
<What>
Two ways to count large amounts of bytes: **decimal** units (KB, MB, GB = powers of 1000) and **binary** units (KiB, MiB, GiB = powers of 1024).
</What>
<Why>
Disk makers use 1000; operating systems often use 1024. That is why a "1 TB" disk shows about 931 GB in Windows.
</Why>
<When>
Buying disks, reading `df -h`, setting memory limits in Docker/Kubernetes, cloud pricing.
</When>
<Where>
Everywhere sizes appear.
</Where>
<How>
1 KB = 1,000 B; 1 KiB = 1,024 B. 1 GB = 1,000,000,000 B; 1 GiB = 1,073,741,824 B. Network speeds use **bits**: 100 Mbps ≈ 12.5 MB/s (divide by 8).
</How>
</Explain>

| Decimal unit | Bytes | Binary unit | Bytes |
| --- | --- | --- | --- |
| 1 KB | 1,000 | 1 KiB | 1,024 |
| 1 MB | 1,000,000 | 1 MiB | 1,048,576 |
| 1 GB | 1,000,000,000 | 1 GiB | 1,073,741,824 |
| 1 TB | 10¹² | 1 TiB | 1,099,511,627,776 |

```javascript
const disk = 1e12;                         // "1 TB" on the box
console.log("1 TB in GiB:", (disk / 1024 ** 3).toFixed(1));
const mbps = 100;                          // internet plan in megabits per second
console.log(`${mbps} Mbps ≈ ${mbps / 8} MB per second`);
```

```text output
1 TB in GiB: 931.3
100 Mbps ≈ 12.5 MB per second
```

### 7. Overflow: when the number does not fit

<Explain>
<What>
When a value is too big for the number of bits reserved for it, it **wraps around** — like a car's odometer going from 99999 back to 00000.
</What>
<Why>
Fixed-size numbers are everywhere (databases, network protocols, older systems). Overflow causes wrong totals, negative IDs and security bugs.
</Why>
<When>
Counters, IDs, timestamps, sizes in fixed-width fields.
</When>
<Where>
Database integer columns (`INT` max ≈ 2.1 billion), the year-2038 problem for 32-bit timestamps, C/C++ code.
</Where>
<How>
In one byte the maximum is 255; adding 1 gives 0. A signed 32-bit integer's maximum is 2,147,483,647; adding 1 gives −2,147,483,648.
</How>
</Explain>

```javascript
const oneByte = new Uint8Array([255]);
oneByte[0] += 1;
console.log("255 + 1 in one byte =", oneByte[0]);

const int32 = new Int32Array([2147483647]);
int32[0] += 1;
console.log("max 32-bit int + 1 =", int32[0]);
```

```text output
255 + 1 in one byte = 0
max 32-bit int + 1 = -2147483648
```

### 8. Decimals in binary: why 0.1 + 0.2 ≠ 0.3

<Explain>
<What>
Computers store decimal fractions in binary **floating point**. Many simple decimal fractions (like 0.1) cannot be written exactly in binary — just as 1/3 cannot be written exactly in decimal (0.3333…).
</What>
<Why>
Tiny rounding errors appear in calculations — and in money, tiny errors add up and break comparisons.
</Why>
<When>
Any calculation with fractions: prices, percentages, measurements.
</When>
<Where>
JavaScript, Python, Java, databases with `FLOAT` columns.
</Where>
<How>
For money, store **whole numbers of the smallest unit** (paisa, cents) or use a decimal type (`DECIMAL` in SQL). Round only for display.
</How>
</Explain>

```javascript
console.log(0.1 + 0.2);
console.log(0.1 + 0.2 === 0.3);
const pricePaisa = 10 + 20;                 // store money as whole paisa
console.log("Rs", (pricePaisa / 100).toFixed(2));
```

```text output
0.30000000000000004
false
Rs 0.30
```

## Real-world example

You are designing a VPC on AWS and choose the range `10.0.0.0/16`. What does `/16` mean?

1. An IPv4 address is 32 bits, written as four bytes: `10.0.0.0`.
2. `/16` says the first 16 bits are fixed (the network); the remaining **16 bits** are yours.
3. 16 bits give 2¹⁶ = **65,536** addresses.
4. You split it into subnets of `/24`: 8 host bits each, so 256 addresses (AWS reserves 5 per subnet, leaving 251 usable).

Without binary you are copying numbers from a tutorial. With it you can plan how many subnets, servers and Kubernetes pods your network can hold — and you will do exactly this in the Networking and Cloud tracks.

## Common mistakes

- **Confusing bits and bytes.** "My 50 Mbps connection should download 50 MB per second" — no, about 6 MB/s.
- **Mixing MB and MiB** when setting memory limits; a container limited to `500M` vs `500Mi` gets different amounts.
- **Using floats for money.** Rounding errors become wrong invoices. Use integers of the smallest unit or `NUMERIC`.
- **Reading `chmod 777` as "seven hundred seventy-seven".** It is three separate octal digits: full access for owner, group and everyone.
- **Thinking hex is encryption.** Hex is just another way to write the same bytes. Anyone can decode it.

## Security lens

<Callout type="security">
Key sizes, token entropy, integer overflows and "encoding is not encryption" are all binary concepts. Attackers think in bytes; defenders need to as well.
</Callout>

- **Key and token strength is measured in bits.** A 128-bit random token has 2¹²⁸ possible values — far beyond brute force. A 6-digit PIN has only 1,000,000 (about 20 bits) — trivial to brute force without rate limiting.
- **Hex and Base64 are encodings, not protection.** Credentials "hidden" as hex in a config file or front-end code are exposed.
- **Integer overflow** has caused real vulnerabilities: a length check overflows, a small buffer is allocated, and an attacker writes past it. In business logic, overflow can turn a huge quantity into a negative price.
- **Bit flags.** Permissions are often stored as bit fields. Misreading or mis-setting one bit (`chmod 777` instead of `755`) gives write access to everyone.

## Interview questions

<QA q="How many values can be represented with 8 bits? With 32 bits?">
n bits represent 2ⁿ values. 8 bits give 256 values (0–255 unsigned). 32 bits give 2³² ≈ 4.29 billion — which is why IPv4, a 32-bit address space, ran out of addresses and IPv6 uses 128 bits.
</QA>

<QA q="Why do developers use hexadecimal instead of binary?">
One hex digit maps exactly to four bits, so every byte is exactly two hex digits. It is far shorter and easier to read than binary, but it converts to binary instantly in your head, unlike decimal. That is why hashes, colours, memory addresses and MAC addresses are shown in hex.
</QA>

<QA q="Why does 0.1 + 0.2 not equal 0.3 in JavaScript, and how do you handle money?">
JavaScript numbers are IEEE 754 64-bit floats. 0.1 and 0.2 have no exact binary representation, so the stored values are tiny approximations and the sum is 0.30000000000000004. For money, store integer amounts of the smallest unit (cents or paisa), or use a decimal type such as PostgreSQL NUMERIC, and format only for display.
</QA>

<QA q="What does chmod 640 mean?">
Each digit is an octal number made of read (4), write (2) and execute (1) bits for owner, group and others. 6 = 4 + 2 = read and write for the owner; 4 = read for the group; 0 = no access for others. It is a common mode for files holding secrets that one service group needs to read.
</QA>

<QA q="What is the difference between 1 GB and 1 GiB?">
1 GB is 10⁹ bytes (decimal, used by disk vendors and networking). 1 GiB is 2³⁰ = 1,073,741,824 bytes (binary, used by operating systems and Kubernetes `Gi`). The difference is about 7% and grows with each prefix.
</QA>

## Key terms

<Terms>
  <Term name="Bit">A single binary digit: 0 or 1.</Term>
  <Term name="Byte">8 bits; 256 possible values.</Term>
  <Term name="Binary">Base-2 number system, digits 0 and 1.</Term>
  <Term name="Hexadecimal">Base-16 number system, digits 0–9 and A–F. One digit equals 4 bits.</Term>
  <Term name="Octal">Base-8 number system. One digit equals 3 bits; used for Linux permissions.</Term>
  <Term name="KiB / MiB / GiB">Binary units: powers of 1,024.</Term>
  <Term name="Integer overflow">When a value exceeds the maximum for its size and wraps around.</Term>
  <Term name="Floating point">A way of storing fractional numbers in binary that can introduce small rounding errors.</Term>
  <Term name="Entropy">How unpredictable a value is, measured in bits. More bits, harder to guess.</Term>
</Terms>
