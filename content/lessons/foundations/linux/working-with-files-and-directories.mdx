## At a glance

<Glance>
<What>
<Tr>
<En>

- `mkdir -p a/b`: create folders
- `touch file`: create an empty file
- `cp from to`: **copy** (`-r` for folders)
- `mv from to`: **move or rename**
- `rm file`: **delete** (`-r` for folders), permanently
- `ln -s target link`: create a **shortcut**
- `nano file`: edit text
- `du -sh`: size, `diff`: compare, `tar -czf`: pack into one file

</En>
<Ur>

- `mkdir -p a/b`: folders banao
- `touch file`: khaali file banao
- `cp kahan-se kahan`: **copy** (folders ke liye `-r`)
- `mv kahan-se kahan`: **move ya rename**
- `rm file`: **delete** (folders ke liye `-r`), hamesha ke liye
- `ln -s target link`: **shortcut** banao
- `nano file`: text edit karo
- `du -sh`: size, `diff`: muqabla, `tar -czf`: ek file me pack

</Ur>
</Tr>
</What>
<Why>
<Tr>
<En>

- **Deploying** an app is mostly copying, moving and linking files.
- **Problems** often need: free some disk space, back up a setting before changing it, go back to an old version.
- **Mistakes are permanent**: one wrong `rm -rf` can take a site down.

</En>
<Ur>

- App **deploy** karna zyada tar files copy, move aur link karna hai.
- **Masail** me aksar ye chahiye: disk ki jagah khali karo, setting badalne se pehle backup lo, purane version par wapas jao.
- **Ghaltiyan hamesha ki hain**: ek ghalat `rm -rf` site band kar sakta hai.

</Ur>
</Tr>
</Why>
<When>
<Tr>
<En>

- preparing folders for an app
- backing up a config before editing it
- renaming and organising files
- cleaning up old builds and logs
- packing a folder to move it to another server

</En>
<Ur>

- app ke liye folders tayyar karte waqt
- config edit karne se pehle backup lete waqt
- files ka naam badalte aur tarteeb dete waqt
- purani builds aur logs saaf karte waqt
- folder pack kar ke doosre server par le jate waqt

</Ur>
</Tr>
</When>
<How>
<Tr>
<En>

Three safety habits:

1. **Preview** with `ls` before deleting.
2. **Back up** before editing (`cp file file.bak`).
3. Add `-i` to be **asked** before overwriting or deleting, and `-v` to **see** what happened.

</En>
<Ur>

Teen hifazati aadaten:

1. Delete se pehle `ls` se **dekh** lein.
2. Edit se pehle **backup** lein (`cp file file.bak`).
3. Overwrite ya delete se pehle **poochne** ke liye `-i`, aur kya hua **dekhne** ke liye `-v` lagayen.

</Ur>
</Tr>
</How>
</Glance>

## Picture it

<Tr>
<En>

Think of **paper files in an office**:

- `mkdir` buys a new **folder**.
- `touch` puts a **blank sheet** in it.
- `cp` **photocopies** a sheet.
- `mv` **carries** a sheet to another folder, or writes a **new label** on it (renaming).
- `rm` puts it through the **shredder**. There's no recycle bin: once shredded, it's gone.

</En>
<Ur>

Office me **kaghazi files** ka socho:

- `mkdir` naya **folder** khareedta hai.
- `touch` us me ek **khaali safha** rakhta hai.
- `cp` safhe ki **photocopy** karta hai.
- `mv` safha doosre folder me **le jata** hai, ya us par **naya label** likhta hai (rename).
- `rm` use **shredder** me daal deta hai. Recycle bin nahi: ek dafa shred hua, to khatam.

</Ur>
</Tr>

## Learn it step by step

<Walkthrough>

<Step title="mkdir: create folders">

<Tr>
<En>

`mkdir` = **m**a**k**e **dir**ectory. Add `-p` and it:

- creates any **missing parent** folders along the way
- does **not** complain if the folder already exists (perfect for scripts)

`{a,b}` (brace expansion) creates several at once.

</En>
<Ur>

`mkdir` = **m**a**k**e **dir**ectory. `-p` lagayen to ye:

- raste me jo **parent** folders na hon unhe bhi bana deta hai
- folder pehle se ho to **shikayat nahi** karta (scripts ke liye behtareen)

`{a,b}` (brace expansion) ek saath kai banata hai.

</Ur>
</Tr>

```bash
mkdir shop
mkdir shop 2>&1 | sed 's/^mkdir: //'   # second time: error
mkdir -p shop/src/components shop/{logs,config}
mkdir -p shop/src            # already exists: no error with -p
find shop -type d | sort
```

```text output
cannot create directory ‘shop’: File exists
shop
shop/config
shop/logs
shop/src
shop/src/components
```

<Happened>
<Tr>
<En>

- The second plain `mkdir shop` fails: "File exists".
- `mkdir -p` created `src/components`, `logs` and `config` in one go.
- `mkdir -p shop/src` again: no error, because `-p` is happy if it already exists.
- `find shop -type d` lists every folder we now have.

</En>
<Ur>

- Doosri dafa saada `mkdir shop` fail hota hai: "File exists".
- `mkdir -p` ne `src/components`, `logs` aur `config` ek hi baar me bana diye.
- Dobara `mkdir -p shop/src`: koi error nahi, kyun ke `-p` ko pehle se mojood folder par koi aitraaz nahi.
- `find shop -type d` hamare saare folders ki list dikhata hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="touch: create empty files">

<Tr>
<En>

`touch file` creates an **empty** file (or, if it exists, just updates its "last changed" time). For a file **with** content, use `echo "text" > file`.

</En>
<Ur>

`touch file` ek **khaali** file banata hai (ya agar mojood ho, to sirf us ka "aakhri tabdeeli" ka waqt badalta hai). Mawad **wali** file ke liye `echo "text" > file` istemal karein.

</Ur>
</Tr>

```bash
touch shop/.env shop/logs/app.log
echo "PORT=3000" > shop/config/app.conf
ls -A shop shop/logs | sed '/^$/d'
```

```text output
shop:
.env
config
logs
src
shop/logs:
app.log
```

<Happened>
<Tr>
<En>`ls -A` shows hidden files like `.env` too (but not `.` and `..`). We now have an empty `.env`, an empty `app.log`, and `app.conf` containing `PORT=3000`.</En>
<Ur>`ls -A` `.env` jaisi chhupi files bhi dikhata hai (lekin `.` aur `..` nahi). Ab hamare paas khaali `.env`, khaali `app.log`, aur `PORT=3000` wali `app.conf` hai.</Ur>
</Tr>
</Happened>

</Step>

<Step title="cp: copy (and why backups matter)">

<Tr>
<En>

`cp from to` copies. Useful options:

- `-r`: copy a whole **folder**
- `-i`: **ask** before overwriting
- `-v`: show what was copied
- `-a`: keep permissions and dates

Important: if a file with the same name already exists, `cp` **replaces it without asking**. That's why you back up first.

</En>
<Ur>

`cp kahan-se kahan` copy karta hai. Kaam ke options:

- `-r`: poora **folder** copy
- `-i`: overwrite se pehle **poochho**
- `-v`: dikhao kya copy hua
- `-a`: permissions aur tareekhen bachao

Ahem: agar usi naam ki file pehle se ho, to `cp` use **baghair pooche badal deta hai**. Isi liye pehle backup.

</Ur>
</Tr>

```bash
cp -v shop/config/app.conf shop/config/app.conf.bak
cp -r shop shop-copy && echo "folder copied: $(find shop-copy -type f | wc -l) files"
echo "PORT=9999" > new.conf
cp new.conf shop/config/app.conf                 # silently OVERWRITES
echo "app.conf now: $(cat shop/config/app.conf), backup still: $(cat shop/config/app.conf.bak)"
```

```text output
'shop/config/app.conf' -> 'shop/config/app.conf.bak'
folder copied: 4 files
app.conf now: PORT=9999, backup still: PORT=3000
```

<Happened>
<Tr>
<En>

- First we made a backup: `app.conf.bak`.
- `cp -r` copied the whole `shop` folder (4 files).
- Then `cp new.conf shop/config/app.conf` **silently replaced** our setting with `PORT=9999`.
- The backup saved us: it still says `PORT=3000`.

</En>
<Ur>

- Pehle hum ne backup banaya: `app.conf.bak`.
- `cp -r` ne poora `shop` folder copy kiya (4 files).
- Phir `cp new.conf shop/config/app.conf` ne **chupke se** hamari setting `PORT=9999` se badal di.
- Backup ne bacha liya: us me abhi bhi `PORT=3000` hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="mv: move and rename">

<Tr>
<En>

`mv` does two jobs:

- `mv old.txt new.txt`: **rename** (same folder, new name)
- `mv file folder/`: **move** into another folder

Like `cp`, it overwrites without asking: add `-i` (ask) or `-n` (never overwrite). On the same disk, `mv` is **instant**, even for huge folders.

</En>
<Ur>

`mv` do kaam karta hai:

- `mv old.txt new.txt`: **rename** (wahi folder, naya naam)
- `mv file folder/`: doosre folder me **move**

`cp` ki tarah ye bhi baghair pooche overwrite karta hai: `-i` (poochho) ya `-n` (kabhi overwrite nahi) lagayen. Ek hi disk par `mv` **foran** hota hai, bohot bare folders ke liye bhi.

</Ur>
</Tr>

```bash
mv shop/config/app.conf.bak shop/config/app.conf.original
mv new.conf shop/
mv shop-copy shop-old
ls shop/config; ls -d shop*
```

```text output
app.conf
app.conf.original
shop
shop-old
```

<Happened>
<Tr>
<En>

- The backup was **renamed** to `app.conf.original`.
- `new.conf` was **moved** into `shop/`.
- The folder `shop-copy` was **renamed** to `shop-old`.

</En>
<Ur>

- Backup ka naam badal kar `app.conf.original` **rename** hua.
- `new.conf` `shop/` me **move** hui.
- Folder `shop-copy` ka naam `shop-old` **rename** hua.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="rm: delete (carefully!)">

<Tr>
<En>

- `rm file`: delete a file
- `rm -r folder`: delete a folder and **everything inside**
- `rm -i`: ask before each one
- `rm -f`: force, no questions
- `rmdir folder`: delete only if **empty** (a safe choice)

The safe routine: **preview with `ls`** using the same pattern, **then** delete.

</En>
<Ur>

- `rm file`: file delete
- `rm -r folder`: folder aur us ke **andar ki har cheez** delete
- `rm -i`: har ek se pehle poochho
- `rm -f`: zabardasti, koi sawal nahi
- `rmdir folder`: sirf **khaali** ho to delete (mehfooz intekhab)

Mehfooz tareeqa: usi pattern ke saath **pehle `ls` se dekhein**, **phir** delete karein.

</Ur>
</Tr>

<Callout type="danger" title="There is no recycle bin">
<Tr>
<En>`rm -rf` deletes immediately and permanently, without asking. One space in the wrong place (`rm -rf / tmp/build` instead of `rm -rf /tmp/build`) can wipe a whole server. Preview with `ls`, check `pwd`, and never run `rm -rf` with a variable you haven't checked.</En>
<Ur>`rm -rf` foran aur hamesha ke liye delete karta hai, baghair pooche. Ghalat jagah ek space (`rm -rf /tmp/build` ki jagah `rm -rf / tmp/build`) poora server mita sakti hai. `ls` se dekhein, `pwd` check karein, aur kabhi aise variable ke saath `rm -rf` na chalayen jo aap ne check na kiya ho.</Ur>
</Tr>
</Callout>

```bash
touch shop/logs/old-{1..3}.log
ls shop/logs/old-*.log                 # 1. preview
rm -v shop/logs/old-*.log              # 2. delete exactly that
rmdir shop/src 2>&1 | sed 's/.*: //'   # refuses: not empty
rm -r shop-old && echo "shop-old removed"
```

```text output
shop/logs/old-1.log
shop/logs/old-2.log
shop/logs/old-3.log
removed 'shop/logs/old-1.log'
removed 'shop/logs/old-2.log'
removed 'shop/logs/old-3.log'
Directory not empty
shop-old removed
```

<Happened>
<Tr>
<En>

- `ls old-*.log` showed **exactly** which 3 files the pattern matches.
- `rm -v` deleted those same 3 and told us about each one.
- `rmdir shop/src` **refused**, because the folder isn't empty. That's its safety feature.
- `rm -r` removed the `shop-old` folder and everything in it.

</En>
<Ur>

- `ls old-*.log` ne **bilkul** dikhaya ke pattern kin 3 files se milta hai.
- `rm -v` ne wahi 3 delete kin aur har ek ka bataya.
- `rmdir shop/src` ne **inkaar** kiya, kyun ke folder khaali nahi. Yahi is ki hifazat hai.
- `rm -r` ne `shop-old` folder aur us ki har cheez hata di.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="ln -s: shortcuts (symlinks)">

<Tr>
<En>

A **symbolic link** is a tiny file that points to another path, like a desktop shortcut. It lets one fixed name point at something that changes: `current → releases/v42`.

`ln -s TARGET LINKNAME`: **target first**, then the name of the shortcut. `ln -sfn` replaces an existing link.

</En>
<Ur>

**Symbolic link** ek chhoti si file hai jo doosre path ki taraf ishara karti hai, desktop shortcut ki tarah. Is se ek tay naam badalne wali cheez ki taraf ishara kar sakta hai: `current → releases/v42`.

`ln -s TARGET LINKNAME`: **pehle target**, phir shortcut ka naam. `ln -sfn` mojooda link ko badal deta hai.

</Ur>
</Tr>

```bash
mkdir -p releases/v1 releases/v2
ln -s releases/v1 current && echo "current → $(readlink current)"
ln -sfn releases/v2 current && echo "current → $(readlink current)"
ls -l current | awk '{print $1, $(NF-2), $(NF-1), $NF}'
```

```text output
current → releases/v1
current → releases/v2
lrwxrwxrwx current -> releases/v2
```

<Happened>
<Tr>
<En>

- `current` first pointed at `releases/v1`; one command switched it to `v2`. That's how many deployments switch to a new version in an instant.
- In `ls -l`, the `l` at the start means "link", and `->` shows where it points.

</En>
<Ur>

- `current` pehle `releases/v1` ki taraf tha; ek command ne use `v2` par kar diya. Kai deployments isi tarah ek pal me naye version par jati hain.
- `ls -l` me shuru ka `l` matlab "link", aur `->` dikhata hai ke ishara kahan hai.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Editing files with nano">

<Tr>
<En>

`nano` is a simple text editor that shows its shortcuts at the bottom. `^` means the **Ctrl** key.

- **Ctrl+O** then Enter = **save**
- **Ctrl+X** = **exit**
- **Ctrl+W** = search
- **Ctrl+K** = cut a line, **Ctrl+U** = paste it

For system files, use `sudo nano /etc/...`.

</En>
<Ur>

`nano` ek saada text editor hai jo apne shortcuts neeche dikhata hai. `^` ka matlab **Ctrl** key.

- **Ctrl+O** phir Enter = **save**
- **Ctrl+X** = **bahar niklo**
- **Ctrl+W** = dhoondo
- **Ctrl+K** = line kaato, **Ctrl+U** = chipkao

System files ke liye `sudo nano /etc/...` istemal karein.

</Ur>
</Tr>

```text
  GNU nano 7.2                    app.conf
PORT=3000
NODE_ENV=production

^G Help    ^O Write Out   ^W Where Is   ^K Cut    ^X Exit
                             (^ means the Ctrl key)
```

<Tr>
<En>**Survival guide for vim** (it opens by surprise in places like `git commit`): press `i` to start typing, `Esc` to stop, then type `:wq` + Enter to save and quit, or `:q!` + Enter to quit without saving.</En>
<Ur>**vim ke liye bachao ka tareeqa** (ye `git commit` jaisi jagahon par achanak khul jata hai): likhna shuru karne ke liye `i`, rokne ke liye `Esc`, phir save kar ke bahar nikalne ke liye `:wq` + Enter, ya baghair save kiye bahar nikalne ke liye `:q!` + Enter.</Ur>
</Tr>

</Step>

<Step title="du: how big is it?">

<Tr>
<En>

- `du -sh folder`: total size of a folder, in human units (K, M, G)
- `du -h --max-depth=1 | sort -rh | head`: the biggest sub-folders
- `df -h`: how full each **disk** is

"Disk full" is one of the most common server problems.

</En>
<Ur>

- `du -sh folder`: folder ka kul size, insani units me (K, M, G)
- `du -h --max-depth=1 | sort -rh | head`: sab se bare andar ke folders
- `df -h`: har **disk** kitni bhari hai

"Disk full" server ke sab se aam masail me se ek hai.

</Ur>
</Tr>

```bash
mkdir -p sizes/{a,b}
head -c 3000000 /dev/zero > sizes/a/big.bin
head -c 200000 /dev/zero > sizes/b/small.bin
du -sh --apparent-size sizes/a sizes/b | sort -rh
```

```text output
2.9M	sizes/a
196K	sizes/b
```

</Step>

<Step title="diff: what changed?">

<Tr>
<En>

`diff -u old new` compares two files line by line. Lines starting with `-` were **removed**, lines with `+` were **added**. It's the same format Git uses, so learning it now pays off later.

</En>
<Ur>

`diff -u old new` do files ko line ba line milata hai. `-` se shuru hone wali lines **hatayi gayin**, `+` wali **shamil ki gayin**. Ye wahi format hai jo Git istemal karta hai, isliye abhi seekhna baad me kaam aata hai.

</Ur>
</Tr>

```bash
printf 'port=3000\nhost=localhost\ndebug=true\n' > old.conf
printf 'port=8080\nhost=localhost\ndebug=false\n' > new.conf
diff -u old.conf new.conf | tail -n +3
```

```text output
@@ -1,3 +1,3 @@
-port=3000
+port=8080
 host=localhost
-debug=true
+debug=false
```

<Happened>
<Tr>
<En>The port changed from 3000 to 8080, and debug from true to false. `host=localhost` (with a space in front) didn't change.</En>
<Ur>Port 3000 se 8080 hua, aur debug true se false. `host=localhost` (aage space ke saath) nahi badla.</Ur>
</Tr>
</Happened>

</Step>

<Step title="tar: pack a folder into one file">

<Tr>
<En>

`tar` packs many files into one, usually compressed (`.tar.gz`). The letters:

- **c** = create, **x** = extract, **t** = list
- **z** = compress with gzip
- **f** = the file name comes next
- `-C folder` = extract into that folder

So: `tar -czf backup.tar.gz folder/` to pack, `tar -xzf backup.tar.gz` to unpack.

</En>
<Ur>

`tar` kai files ko ek me pack karta hai, aam taur par compressed (`.tar.gz`). Letters:

- **c** = banao, **x** = nikalo, **t** = list dikhao
- **z** = gzip se compress
- **f** = agla lafz file ka naam hai
- `-C folder` = usi folder me nikalo

Yani: pack ke liye `tar -czf backup.tar.gz folder/`, kholne ke liye `tar -xzf backup.tar.gz`.

</Ur>
</Tr>

```bash
tar -czf shop.tar.gz shop
tar -tzf shop.tar.gz | sort | head -4
mkdir -p restore && tar -xzf shop.tar.gz -C restore
diff -r shop restore/shop && echo "restored copy is identical"
```

```text output
shop/
shop/.env
shop/config/
shop/config/app.conf
restored copy is identical
```

<Happened>
<Tr>
<En>

- We packed `shop` into `shop.tar.gz`, listed what's inside, and unpacked it into `restore/`.
- `diff -r` compared both folders completely and found **no difference**: the backup works.
- Always test that you can **restore** a backup, not just create it.

</En>
<Ur>

- Hum ne `shop` ko `shop.tar.gz` me pack kiya, andar ki list dekhi, aur `restore/` me khola.
- `diff -r` ne dono folders poore milaye aur **koi farq nahi** mila: backup kaam karta hai.
- Hamesha test karein ke backup **wapas** aa sakta hai, sirf banana kaafi nahi.

</Ur>
</Tr>
</Happened>

</Step>

</Walkthrough>

## Common mistakes

<Compare>
<Bad title="rm -rf with an unchecked variable">

```text
rm -rf "$APP_DIR/"     # if APP_DIR is empty, this becomes rm -rf /
```

</Bad>
<Good title="Fail if it's empty">

```text
rm -rf "${APP_DIR:?APP_DIR is not set}/"
```

<Tr>
<En>`${VAR:?}` stops the script with an error if the variable is empty.</En>
<Ur>`${VAR:?}` variable khaali ho to script ko error ke saath rok deta hai.</Ur>
</Tr>

</Good>
</Compare>

<Compare>
<Bad title="Editing a config with no backup">

<Tr>
<En>You change `nginx.conf`, the site breaks, and you can't remember what it was before.</En>
<Ur>Aap `nginx.conf` badalte hain, site toot jati hai, aur yaad nahi ke pehle kya tha.</Ur>
</Tr>

</Bad>
<Good title="One second of safety">

```text
sudo cp -a nginx.conf nginx.conf.bak
```

</Good>
</Compare>

<Compare>
<Bad title="Unquoted wildcards in find">

```text
find . -name *.log
```

<Tr>
<En>The shell expands `*.log` **before** `find` sees it, so it searches for the wrong thing.</En>
<Ur>Shell `find` ke dekhne se **pehle** hi `*.log` phaila deta hai, isliye ghalat cheez dhoondi jati hai.</Ur>
</Tr>

</Bad>
<Good title="Quote the pattern">

```text
find . -name "*.log"
```

</Good>
</Compare>

## Try it yourself

<Challenge title="A safe config change, then tidy up">

<Tr>
<En>

```bash
mkdir -p ~/files-lab && cd ~/files-lab

mkdir -p etc-demo && printf 'listen 80;\nserver_name old.example.com;\n' > etc-demo/site.conf
```

## Remember

<Takeaways>
<Tr>
<En>

- `mkdir -p` creates folders (and doesn't fail if they exist).

- `rm` is **permanent**. Preview with `ls`, check `pwd`, then delete.
- `rmdir` deletes only empty folders; `rm -r` deletes everything inside.
- `ln -s target link`: target first.
- **Back up before editing**: `cp file file.bak`.
- `nano`: Ctrl+O save, Ctrl+X exit. vim: `Esc` then `:wq`.
- `du -sh` sizes, `diff -u` changes, `tar -czf` / `tar -xzf` pack and unpack.

<DeepDive title="All commands in one table">

| Task | Command | Example |
| --- | --- | --- |
| Create folder(s) | `mkdir -p` | `mkdir -p app/logs` |
| Create empty file / update time | `touch` | `touch .env` |
| Copy | `cp` (`-r` for folders) | `cp -r site/ site-backup/` |
| Move / rename | `mv` | `mv old.txt new.txt` |
| Delete file | `rm` | `rm temp.log` |
| Delete folder | `rm -r` / `rmdir` (empty only) | `rm -r build/` |
| Link | `ln -s` | `ln -s /var/www/shop current` |
| Edit | `nano`, `vim` | `nano config.yml` |
| Size | `du -sh` | `du -sh /var/log` |
| Compare | `diff` | `diff old.conf new.conf` |
| Pack | `tar -czf`, `zip -r` | `tar -czf site.tgz site/` |

More gotchas: `cat` on a huge log floods the terminal (use `less`, `head`, `tail` or `grep`), and `rsync --delete` with the wrong trailing slash mirrors the wrong level and deletes files on the target. Always try `--dry-run` first.

</DeepDive>

<DeepDive title="Real world: uploads failed yesterday">

A support ticket says "uploads failed yesterday afternoon". On the server:

```bash
# 1. Which errors, and when?
grep -n "upload" /var/log/app/error.log | tail -n 20
# → 2026-11-09 15:42:11 ENOSPC: no space left on device

# 2. Which disk is full, and why?
df -h
sudo du -xh /srv --max-depth=2 | sort -h | tail
# → /srv/app/uploads/tmp 41G

# 3. What is in there?
find /srv/app/uploads/tmp -type f -mtime +1 | head
find /srv/app/uploads/tmp -type f -mtime +1 | wc -l
# → 180,000 abandoned chunk files from failed resumable uploads

# 4. Clean safely, then prevent it
find /srv/app/uploads/tmp -type f -mtime +1 -print | head        # check
find /srv/app/uploads/tmp -type f -mtime +1 -delete               # delete
# add a daily cron job / systemd timer doing the same, and a disk usage alert
```

</DeepDive>

<DeepDive title="Security lens">

`find` and `grep` are the incident responder's best friends, and the attacker's. Use them to find what shouldn't be there before someone else does.

- **Hunt for secrets** before attackers do: `grep -rEn "(password|secret|api[_-]?key|BEGIN [A-Z]+ PRIVATE KEY)" /srv /home 2>/dev/null`. Also check `.env`, backups and `.git` folders accidentally deployed to web roots.
- **Find web shells** among uploads: script files in upload folders (`find /var/www/uploads -name "*.php"`), recently changed files in the web root (`find /var/www -mtime -2 -type f`).
- **World-writable files** are escalation risks: `find / -xdev -perm -0002 -type f 2>/dev/null`.
- **Backups are sensitive data:** `.tar.gz` archives of app folders contain `.env` files and keys. Encrypt them, restrict permissions, and never leave them in a web-served folder (`site.com/backup.zip` is a common real finding).
- **Deleting is not secure erasure:** `rm` removes the name; the data may remain on disk. Use encrypted volumes.
- **Zip Slip:** extracting archives from untrusted sources can write files outside the target folder through `../` paths. Use up-to-date tools and validate archive contents.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="How would you find all files larger than 1 GB on a server?">
Use find with a size filter, staying on one file system: `find / -xdev -type f -size +1G -exec ls -lh {} + 2>/dev/null`. Combine with `du -h --max-depth=1 | sort -h` to see which directories are largest overall.
</QA>

<QA q="What is the difference between scp and rsync?">
Both copy files over SSH. scp copies everything every time. rsync compares source and destination and only transfers changed parts, can resume interrupted transfers, preserves permissions and timestamps, supports a dry run, and can mirror directories with --delete. rsync is preferred for deployments, backups and large directories.
</QA>

<QA q="How do you follow a log file in real time and show only errors?">
`tail -f /path/to/app.log | grep --line-buffered -i error`. tail -f keeps the file open and prints new lines as they are written; grep filters them, and --line-buffered makes grep output each match immediately. For systemd services, `journalctl -u service -f` does the same.
</QA>

<QA q="What does tar -czf do?">
It creates (c) a gzip-compressed (z) archive written to the file (f) named next. For example `tar -czf backup.tar.gz /srv/app` bundles the directory into one compressed file. Use -x to extract, -t to list contents and -C to choose an extraction directory.
</QA>

<QA q="How do you avoid deleting the wrong files with rm -rf?">
Check the exact path or glob with ls first, then reuse it for rm; use -i for interactive confirmation in risky cases; never run it with unchecked variables (use `${VAR:?}` and set -u in scripts); and keep backups or snapshots before bulk deletions on production.
</QA>

</DeepDive>
