<Callout type="tip" title="In one minute">
`mkdir -p a/b` creates folders, `touch file` creates an empty file, `cp src dest` copies (`-r` for folders), `mv src dest` moves **or renames**, `rm file` deletes (`-r` for folders) — **permanently, no recycle bin**. Use `-i` to be asked before overwriting/deleting, and `-v` to see what happened. `ln -s target link` creates a shortcut. Edit text with `nano`. Check sizes with `du -sh`, compare with `diff`, pack folders with `tar -czf`.
</Callout>

## Start from zero

### Doing with commands what you do with a mouse

Everything you do in a file explorer — new folder, copy, paste, cut, rename, delete, zip — has a short command. On a server without a desktop, these commands are the only way.

<Callout type="analogy">
Think of **paper files in an office**: `mkdir` buys a new folder, `touch` puts a blank sheet in it, `cp` photocopies a sheet, `mv` carries a sheet to another folder (or writes a new label on it — renaming), and `rm` puts it through the **shredder**. There is no recycle bin: once shredded, it is gone.
</Callout>

### Words you need first

| Word | Simple meaning | Example |
| --- | --- | --- |
| **Source** | The thing you copy or move | `report.txt` in `cp report.txt backup/` |
| **Destination** | Where it goes | `backup/` |
| **Recursive (`-r`)** | Including everything inside folders | `cp -r src/ src-copy/` |
| **Overwrite** | Replace an existing file with the same name | `cp` does it silently by default |
| **Symlink** | A shortcut pointing to another path | `current → releases/v2` |
| **Archive** | Many files packed into one | `site.tar.gz`, `site.zip` |
| **Editor** | A program to change text files | `nano`, `vim` |

## What is it?

| Task | Command | Example |
| --- | --- | --- |
| Create folder(s) | `mkdir -p` | `mkdir -p app/logs` |
| Create empty file / update time | `touch` | `touch .env` |
| Copy | `cp` (`-r` for folders) | `cp -r site/ site-backup/` |
| Move / rename | `mv` | `mv old.txt new.txt` |
| Delete file | `rm` | `rm temp.log` |
| Delete folder | `rm -r` / `rmdir` (empty only) | `rm -r build/` |
| Link | `ln -s` | `ln -s /var/www/shop current` |
| Edit | `nano`, `vim` | `nano config.yml` |
| Size | `du -sh` | `du -sh /var/log` |
| Compare | `diff` | `diff old.conf new.conf` |
| Pack | `tar -czf`, `zip -r` | `tar -czf site.tgz site/` |

## Why does it matter?

- **Deployments** are mostly copying, moving and linking files.
- **Incidents** often need: free up disk space, back up a config before editing, restore a previous version.
- **Mistakes are permanent:** one wrong `rm -rf` or `cp` over the wrong file can cause an outage. Safe habits matter.

## When and where do you use it?

- Preparing folders for an app (`mkdir -p /var/www/shop/{releases,shared}`).
- Backing up a config before editing (`cp nginx.conf nginx.conf.bak`).
- Renaming and moving uploaded files.
- Cleaning old builds and logs.
- Packing a folder to download or move to another server.

## Concepts one by one

### 1. `mkdir` — creating folders

<Explain>
<What>
**M**a**k**e **dir**ectory: creates one or more folders.
</What>
<Why>
Apps, logs, backups and releases all need their own folders.
</Why>
<When>
Setting up projects and servers, in scripts.
</When>
<Where>
Anywhere you have write permission.
</Where>
<How>
`mkdir name`. `-p` creates missing parent folders and does **not** fail if the folder already exists — ideal for scripts. Brace expansion makes several at once.
</How>
</Explain>

```bash
mkdir shop
mkdir shop 2>&1 | sed 's/^mkdir: //'   # second time: error
mkdir -p shop/src/components shop/{logs,config}
mkdir -p shop/src            # already exists: no error with -p
find shop -type d | sort
```

```text output
cannot create directory ‘shop’: File exists
shop
shop/config
shop/logs
shop/src
shop/src/components
```

### 2. `touch` — creating empty files

<Explain>
<What>
Creates an empty file if it does not exist; if it exists, updates its "last modified" time.
</What>
<Why>
Quick way to create placeholder files (`.env`, `.gitkeep`, log files) or mark a time.
</Why>
<When>
Creating empty files, testing permissions, scripts.
</When>
<Where>
Anywhere.
</Where>
<How>
`touch file1 file2`. For files with content, redirect output instead: `echo "PORT=3000" > .env`.
</How>
</Explain>

```bash
touch shop/.env shop/logs/app.log
echo "PORT=3000" > shop/config/app.conf
ls -A shop shop/logs | sed '/^$/d'
```

```text output
shop:
.env
config
logs
src
shop/logs:
app.log
```

### 3. `cp` — copying

<Explain>
<What>
Copies files or folders from a source to a destination.
</What>
<Why>
Backups before changes, duplicating templates, preparing deploys.
</Why>
<When>
**Always** before editing an important config.
</When>
<Where>
Everywhere.
</Where>
<How>
`cp file dest`. `-r` for folders, `-i` asks before overwriting, `-v` shows what was copied, `-p` (or `-a`) keeps permissions and timestamps. If the destination is an existing folder, the copy goes **inside** it.
</How>
</Explain>

```bash
cp -v shop/config/app.conf shop/config/app.conf.bak
cp -r shop shop-copy && echo "folder copied: $(find shop-copy -type f | wc -l) files"
echo "PORT=9999" > new.conf
cp new.conf shop/config/app.conf                 # silently OVERWRITES
echo "app.conf now: $(cat shop/config/app.conf), backup still: $(cat shop/config/app.conf.bak)"
```

```text output
'shop/config/app.conf' -> 'shop/config/app.conf.bak'
folder copied: 4 files
app.conf now: PORT=9999, backup still: PORT=3000
```

The backup saved us: `cp` replaced `app.conf` without asking.

### 4. `mv` — moving and renaming

<Explain>
<What>
Moves files or folders to another place, or renames them (renaming is moving to a new name in the same folder).
</What>
<Why>
Organising files, renaming uploads, switching versions.
</Why>
<When>
Reorganising, renaming, deploying (`mv new current`).
</When>
<Where>
Everywhere.
</Where>
<How>
`mv old new` (rename), `mv file folder/` (move into a folder). Like `cp`, it overwrites silently — use `-i` or `-n` (never overwrite). Within one disk, `mv` is instant and atomic, even for huge folders.
</How>
</Explain>

```bash
mv shop/config/app.conf.bak shop/config/app.conf.original
mv new.conf shop/
mv shop-copy shop-old
ls shop/config; ls -d shop*
```

```text output
app.conf
app.conf.original
shop
shop-old
```

### 5. `rm` — deleting (carefully!)

<Explain>
<What>
**R**e**m**ove: deletes files; with `-r`, folders and everything inside.
</What>
<Why>
Freeing space, removing old builds and temporary files.
</Why>
<When>
Only after checking **exactly** what will be deleted.
</When>
<Where>
Everywhere — and that is the danger.
</Where>
<How>
`rm file`, `rm -r folder`, `rm -i` (ask each time), `rm -f` (force, no questions, no error if missing). `rmdir` deletes only **empty** folders — a safe choice. First run `ls` with the same pattern to preview.
</How>
</Explain>

<Callout type="danger" title="There is no recycle bin">
`rm -rf` deletes immediately and permanently, without asking. A space in the wrong place — `rm -rf / tmp/build` instead of `rm -rf /tmp/build` — can wipe a server. Preview with `ls`, double-check `pwd`, and never run `rm -rf` with an unchecked variable.
</Callout>

```bash
touch shop/logs/old-{1..3}.log
ls shop/logs/old-*.log                 # 1. preview
rm -v shop/logs/old-*.log              # 2. delete exactly that
rmdir shop/src 2>&1 | sed 's/.*: //'   # refuses: not empty
rm -r shop-old && echo "shop-old removed"
```

```text output
shop/logs/old-1.log
shop/logs/old-2.log
shop/logs/old-3.log
removed 'shop/logs/old-1.log'
removed 'shop/logs/old-2.log'
removed 'shop/logs/old-3.log'
Directory not empty
shop-old removed
```

### 6. `ln -s` — symbolic links (shortcuts)

<Explain>
<What>
A symbolic link is a small file that points to another path, like a desktop shortcut.
</What>
<Why>
Lets one stable path point at changing targets: `current → releases/v42`, `sites-enabled/shop → sites-available/shop`.
</Why>
<When>
Deployments, enabling configs, version switching.
</When>
<Where>
`/etc/nginx/sites-enabled/`, `/usr/bin/python3 → python3.12`, release folders.
</Where>
<How>
`ln -s TARGET LINKNAME` (target first!). `ln -sfn` replaces an existing link. `ls -l` shows `link -> target`; `readlink` prints the target.
</How>
</Explain>

```bash
mkdir -p releases/v1 releases/v2
ln -s releases/v1 current && echo "current → $(readlink current)"
ln -sfn releases/v2 current && echo "current → $(readlink current)"
ls -l current | awk '{print $1, $(NF-2), $(NF-1), $NF}'
```

```text output
current → releases/v1
current → releases/v2
lrwxrwxrwx current -> releases/v2
```

The `l` at the start of the permissions marks a link.

### 7. Editing files with nano

<Explain>
<What>
`nano` is a simple terminal text editor with its shortcuts shown at the bottom of the screen.
</What>
<Why>
On servers you edit configs in the terminal.
</Why>
<When>
Changing configs, writing small scripts.
</When>
<Where>
Most distros include it; `vim` is always available too (more powerful, steeper to learn).
</Where>
<How>
`nano file` (or `sudo nano /etc/…` for system files). Type to edit. **Ctrl+O** then Enter = save, **Ctrl+X** = exit, **Ctrl+W** = search, **Ctrl+K** = cut line, **Ctrl+U** = paste.
</How>
</Explain>

```text
  GNU nano 7.2                    app.conf
PORT=3000
NODE_ENV=production

^G Help    ^O Write Out   ^W Where Is   ^K Cut    ^X Exit
                             (^ means the Ctrl key)
```

Survival guide for **vim** (it opens by default in some places, like `git commit`): press `i` to type, `Esc` to stop typing, then `:wq` + Enter to save and quit, or `:q!` + Enter to quit without saving.

### 8. `du` and `df` — how big?

<Explain>
<What>
`du` (disk usage) shows how much space files and folders use. `df` (disk free) shows how full each disk is.
</What>
<Why>
"Disk full" is one of the most common server problems.
</Why>
<When>
Before big copies, during disk-full incidents, cleaning up.
</When>
<Where>
`/var/log`, `/var/lib/docker`, home folders, `node_modules`.
</Where>
<How>
`du -sh folder` (total, human sizes), `du -h --max-depth=1 | sort -rh | head` (biggest subfolders), `df -h` (disks).
</How>
</Explain>

```bash
mkdir -p sizes/{a,b}
head -c 3000000 /dev/zero > sizes/a/big.bin
head -c 200000 /dev/zero > sizes/b/small.bin
du -sh --apparent-size sizes/a sizes/b | sort -rh
```

```text output
2.9M	sizes/a
196K	sizes/b
```

### 9. `diff` — what changed?

<Explain>
<What>
Compares two files line by line and shows the differences.
</What>
<Why>
Before replacing a config, see exactly what will change; after an incident, see what someone changed.
</Why>
<When>
Reviewing config changes, comparing backups, checking deploys.
</When>
<Where>
Configs, scripts, any text.
</Where>
<How>
`diff -u old new` shows a "unified" diff: lines starting with `-` were removed, `+` were added — the same format Git uses.
</How>
</Explain>

```bash
printf 'port=3000\nhost=localhost\ndebug=true\n' > old.conf
printf 'port=8080\nhost=localhost\ndebug=false\n' > new.conf
diff -u old.conf new.conf | tail -n +3
```

```text output
@@ -1,3 +1,3 @@
-port=3000
+port=8080
 host=localhost
-debug=true
+debug=false
```

### 10. Archives: tar and zip

<Explain>
<What>
Packing many files into one file, usually compressed: `.tar.gz` (Linux standard) or `.zip` (common with Windows users).
</What>
<Why>
Moving, downloading, backing up or sending whole folders.
</Why>
<When>
Backups, transfers between servers, releases.
</When>
<Where>
Everywhere.
</Where>
<How>
Create: `tar -czf archive.tar.gz folder/`. List: `tar -tzf archive.tar.gz`. Extract: `tar -xzf archive.tar.gz` (add `-C dest/` to choose where). Letters: **c**reate, e**x**tract, lis**t**, **z** = gzip, **f** = file name, **v** = verbose.
</How>
</Explain>

```bash
tar -czf shop.tar.gz shop
tar -tzf shop.tar.gz | sort | head -4
mkdir -p restore && tar -xzf shop.tar.gz -C restore
diff -r shop restore/shop && echo "restored copy is identical"
```

```text output
shop/
shop/.env
shop/config/
shop/config/app.conf
restored copy is identical
```

## Hands-on

```bash
mkdir -p ~/files-lab && cd ~/files-lab

# A safe config change routine
mkdir -p etc-demo && printf 'listen 80;\nserver_name old.example.com;\n' > etc-demo/site.conf
cp etc-demo/site.conf etc-demo/site.conf.$(date +%F).bak 2>/dev/null; cp etc-demo/site.conf etc-demo/site.conf.bak
sed -i 's/old.example.com/shop.example.com/' etc-demo/site.conf
diff etc-demo/site.conf.bak etc-demo/site.conf

# Organise files by extension
touch photo1.jpg photo2.jpg notes.txt data.csv
for f in *.*; do ext="${f##*.}"; mkdir -p "$ext"; mv "$f" "$ext/"; done
for d in jpg txt csv; do echo "$d/: $(ls "$d" | tr '\n' ' ')"; done

# Clean up
cd ~ && rm -rf ~/files-lab && echo "lab removed"
```

```text output
2c2
< server_name old.example.com;
---
> server_name shop.example.com;
jpg/: photo1.jpg photo2.jpg 
txt/: notes.txt 
csv/: data.csv 
lab removed
```

Plain `diff` (without `-u`) uses `<` for the old file and `>` for the new one; `2c2` means "line 2 changed".

## Real-world example

A support ticket says "uploads failed yesterday afternoon". On the server:

```bash
# 1. Which errors, and when?
grep -n "upload" /var/log/app/error.log | tail -n 20
# → 2026-11-09 15:42:11 ENOSPC: no space left on device

# 2. Which disk is full, and why?
df -h
sudo du -xh /srv --max-depth=2 | sort -h | tail
# → /srv/app/uploads/tmp 41G

# 3. What is in there?
find /srv/app/uploads/tmp -type f -mtime +1 | head
find /srv/app/uploads/tmp -type f -mtime +1 | wc -l
# → 180,000 abandoned chunk files from failed resumable uploads

# 4. Clean safely, then prevent it
find /srv/app/uploads/tmp -type f -mtime +1 -print | head        # check
find /srv/app/uploads/tmp -type f -mtime +1 -delete               # delete
# add a daily cron job / systemd timer doing the same, and a disk usage alert
```

## Common mistakes

- **`rm -rf` with an unchecked path or an empty variable.** Check with `ls` first; in scripts use `"${VAR:?}"`.
- **Forgetting that `cp`/`mv` overwrite** without asking.
- **Unquoted `find -name *.log`** — the shell expands `*.log` before `find` sees it. Write `-name "*.log"`.
- **`cat` on a huge log file** floods the terminal. Use `less`, `head`, `tail` or `grep`.
- **`rsync --delete` with the wrong trailing slash** — mirrors the wrong level and deletes files on the target. Use `--dry-run` first.
- **Editing config without a backup.** `cp -a nginx.conf nginx.conf.bak` takes one second.

## Security lens

<Callout type="security">
`find` and `grep` are the incident responder's best friends — and the attacker's. Use them to find what should not be there before someone else does.
</Callout>

- **Hunt for secrets** before attackers do: `grep -rEn "(password|secret|api[_-]?key|BEGIN [A-Z]+ PRIVATE KEY)" /srv /home 2>/dev/null`. Also check `.env`, backups and `.git` folders accidentally deployed to web roots.
- **Find web shells** among uploads: script files in upload directories (`find /var/www/uploads -name "*.php"`), recently modified files in the web root (`find /var/www -mtime -2 -type f`).
- **World-writable files and directories** are escalation risks: `find / -xdev -perm -0002 -type f 2>/dev/null`.
- **Backups are sensitive data:** `.tar.gz` archives of app folders contain `.env` files and keys. Encrypt them, restrict permissions and never leave them in a web-served directory (`site.com/backup.zip` is a common real finding).
- **Deleting is not secure erasure:** `rm` removes the name; the data may remain on disk. Use encrypted volumes so old data is unreadable.
- **Zip Slip:** extracting archives from untrusted sources can write files outside the target folder through `../` paths. Use up-to-date tools and validate archive contents.

## Interview questions

<QA q="How would you find all files larger than 1 GB on a server?">
Use find with a size filter, staying on one file system: `find / -xdev -type f -size +1G -exec ls -lh {} + 2>/dev/null`. Combine with `du -h --max-depth=1 | sort -h` to see which directories are largest overall.
</QA>

<QA q="What is the difference between scp and rsync?">
Both copy files over SSH. scp copies everything every time. rsync compares source and destination and only transfers changed parts, can resume interrupted transfers, preserves permissions and timestamps, supports a dry run, and can mirror directories with --delete. rsync is preferred for deployments, backups and large directories.
</QA>

<QA q="How do you follow a log file in real time and show only errors?">
`tail -f /path/to/app.log | grep --line-buffered -i error`. tail -f keeps the file open and prints new lines as they are written; grep filters them, and --line-buffered makes grep output each match immediately. For systemd services, `journalctl -u service -f` does the same.
</QA>

<QA q="What does tar -czf do?">
It creates (c) a gzip-compressed (z) archive written to the file (f) named next. For example `tar -czf backup.tar.gz /srv/app` bundles the directory into one compressed file. Use -x to extract, -t to list contents and -C to choose an extraction directory.
</QA>

<QA q="How do you avoid deleting the wrong files with rm -rf?">
Check the exact path or glob with ls first, then reuse it for rm; use -i for interactive confirmation in risky cases; never run it with unchecked variables (use `${VAR:?}` and set -u in scripts); and keep backups or snapshots before bulk deletions on production.
</QA>

## Key terms

<Terms>
  <Term name="Recursive (-r)">Applies an operation to a directory and everything inside it.</Term>
  <Term name="Glob">A wildcard pattern like *.log expanded by the shell.</Term>
  <Term name="tar">Tool that bundles many files into one archive.</Term>
  <Term name="gzip">Compression format, usually combined with tar as .tar.gz.</Term>
  <Term name="rsync">Efficient file synchronisation tool that sends only changes.</Term>
  <Term name="scp">Secure copy of files over SSH.</Term>
  <Term name="tail -f">Follows a file and prints new lines as they are written.</Term>
  <Term name="find">Searches the file tree by name, type, size, time, owner and more.</Term>
  <Term name="grep">Searches text for lines matching a pattern.</Term>
</Terms>
