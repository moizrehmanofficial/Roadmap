<Callout type="tip" title="In one minute">
Create with `mkdir -p` and `touch`; read with `cat`, `less`, `head`, `tail -f`; copy with `cp -r`, move/rename with `mv`, delete with `rm` (there is **no recycle bin**). Find files with `find`, text inside files with `grep -r`, sizes with `du` and `df`. Bundle and compress with `tar -czf`, copy between machines with `scp` or `rsync`. Before any `rm -rf`, run `ls` with the same path first.
</Callout>

## What is it?

The core toolkit — memorise the first column, look up the rest when needed:

| Task | Command | Useful options |
| --- | --- | --- |
| Make a directory | `mkdir dir` | `-p` create parents, no error if it exists |
| Make an empty file / update timestamp | `touch file` | |
| Show a whole file | `cat file` | `-n` number lines |
| Read a long file page by page | `less file` | `/word` search, `G` end, `q` quit |
| First / last lines | `head file`, `tail file` | `-n 50`; `tail -f` follows a growing log |
| Copy | `cp src dest` | `-r` directories, `-a` keep permissions/times, `-i` ask before overwrite |
| Move or rename | `mv src dest` | `-i` ask before overwrite, `-n` never overwrite |
| Delete files | `rm file` | `-r` directories, `-f` no questions, `-i` ask each time |
| Delete an empty directory | `rmdir dir` | |
| Find files by name/size/time | `find path -name "*.log"` | `-type f`, `-size +100M`, `-mtime -1` |
| Find text inside files | `grep -rn "text" path` | `-i` ignore case, `-l` file names only |
| File type | `file thing` | |
| Sizes | `du -sh dir`, `df -h` | `du -h --max-depth=1` |
| Create an archive | `tar -czf out.tar.gz dir` | `-c` create, `-z` gzip, `-f` file |
| Extract an archive | `tar -xzf in.tar.gz` | `-C target/` |
| Zip / unzip | `zip -r out.zip dir`, `unzip in.zip` | |
| Copy to another machine | `scp file user@host:/path` | `-r` directories |
| Sync directories (local or remote) | `rsync -av src/ dest/` | `--delete`, `-n` dry run |
| Links | `ln -s target linkname` | |
| Edit text | `nano file` (easy), `vim file` (powerful) | |

## Why does it matter?

- **Full-stack:** uploading builds, editing `.env` files on a server, reading logs, cleaning `node_modules`.
- **DevOps:** every Dockerfile `COPY`, every backup job, every log rotation and every CI artefact is file manipulation; `rsync` and `tar` are the backbone of many deployment and backup scripts.
- **Cloud:** copying data to and from instances, unpacking releases, finding what fills an EBS volume.
- **Security:** finding recently modified files, files owned by unexpected users, large unexplained archives, web shells hidden among uploads — incident response is `find` and `grep` at heart.

## When and where do you use it?

- Watching a live log while you reproduce a bug: `tail -f /var/log/nginx/error.log`.
- Finding which config file sets a value: `grep -rn "client_max_body_size" /etc/nginx/`.
- Cleaning disk space: `find /var/log -name "*.gz" -mtime +30 -delete`.
- Backing up an app directory before an upgrade: `tar -czf app-$(date +%F).tar.gz /srv/app`.
- Deploying static files: `rsync -av --delete dist/ deploy@server:/var/www/site/`.

## How does it work?

### Copying and moving

```bash
cp notes.txt backup/                 # copy into a directory (keeps name)
cp notes.txt notes.bak               # copy with a new name
cp -r src/ /tmp/src-copy/            # directory, recursively
cp -a /srv/app /srv/app.bak          # archive mode: keeps permissions, owners, times, links

mv old.txt new.txt                   # rename
mv report.pdf ~/Documents/           # move
mv -i a.txt b.txt                    # ask before overwriting b.txt
```

`cp` and `mv` **silently overwrite** an existing destination unless you use `-i` or `-n`.

### Deleting — there is no undo

```bash
rm file.txt
rm -i *.log                          # confirm each one
rm -r old-folder/                    # directory and everything inside
rm -rf build/                        # no questions asked
```

Safe habit: **run `ls` with the exact same path first**, then press ↑ and replace `ls` with `rm`.

```bash
ls  /srv/app/releases/2024-*         # check what matches
rm -rf /srv/app/releases/2024-*      # same path, now delete
```

The classic disaster is a variable that is empty: `rm -rf "$BUILD_DIR/"` becomes `rm -rf /` if `BUILD_DIR` is not set. In scripts use `"${BUILD_DIR:?}"` (fails if empty) and `set -u` (covered in "Writing Safe Scripts").

### Reading files

```bash
cat package.json                     # short files
less /var/log/syslog                 # long files: / to search, n next match, q quit
head -n 20 access.log                # first 20 lines
tail -n 100 error.log                # last 100 lines
tail -f error.log                    # follow new lines live (Ctrl+C to stop)
tail -f error.log | grep --line-buffered "500"
wc -l access.log                     # count lines
```

### Finding files: `find`

```bash
find . -name "*.env"                          # by name (quote the pattern!)
find /srv -type f -name "*.log" -size +100M   # big log files
find /var/www -type f -mtime -1               # changed in the last 24 hours
find /tmp -type f -user www-data              # owned by a given user
find . -name node_modules -type d -prune      # list node_modules folders
find /var/log -name "*.gz" -mtime +30 -delete # delete old compressed logs
find /srv/app -type f -exec chmod 644 {} +    # run a command on every match
```

### Finding text: `grep`

```bash
grep "ERROR" app.log                  # lines containing ERROR
grep -i "timeout" app.log             # case-insensitive
grep -rn "DATABASE_URL" .             # recursive, with file and line numbers
grep -rl "TODO" src/                  # just file names
grep -v "health" access.log           # lines NOT matching
grep -c " 500 " access.log            # count matching lines
grep -E "error|fatal" app.log         # extended regex: either word
```

(`grep`, `sed` and `awk` get a full lesson in the Shell module.)

### Sizes and space

```bash
df -h                                 # free space per file system
du -sh /srv/app                       # total size of a directory
du -h --max-depth=1 /var | sort -h    # biggest sub-directories, sorted
ls -lhS                               # files in this folder, largest first
```

### Archives and compression

```bash
tar -czf backup.tar.gz /srv/app            # create (c) gzip (z) file (f)
tar -tzf backup.tar.gz | head              # list (t) contents without extracting
tar -xzf backup.tar.gz -C /tmp/restore/    # extract (x) into a directory
tar --exclude=node_modules -czf src.tgz .  # skip a folder

zip -r site.zip dist/
unzip site.zip -d site/
```

A `.tar` file is a bundle (many files in one); `.gz` is compression. `.tar.gz` / `.tgz` is both.

### Copying between machines

```bash
scp app.tar.gz deploy@203.0.113.10:/tmp/           # to a server
scp deploy@203.0.113.10:/var/log/app.log ./        # from a server

rsync -avz --dry-run dist/ deploy@server:/var/www/site/   # preview
rsync -avz --delete dist/ deploy@server:/var/www/site/    # mirror (deletes extra files!)
```

`rsync` only sends what changed, can resume, and preserves permissions. **Trailing slash matters:** `dist/` copies the *contents* of dist; `dist` copies the folder itself.

### Editing on a server

- `nano file` — on-screen help; **Ctrl+O** save, **Ctrl+X** exit.
- `vim file` — press `i` to type, **Esc** to stop typing, `:wq` save and quit, `:q!` quit without saving.
- `sudoedit /etc/nginx/nginx.conf` — edit a root-owned file safely with your own editor settings.

## Hands-on

Build a small practice area and run through everything:

```bash
mkdir -p ~/lab/{logs,app/src,backup} && cd ~/lab
for i in 1 2 3; do echo "line $i: ERROR something" >> logs/app.log; done
echo "line 4: INFO all good" >> logs/app.log
echo "DATABASE_URL=postgres://localhost/db" > app/.env
touch app/src/index.js app/src/util.js

tree ~/lab 2>/dev/null || find ~/lab
cat -n logs/app.log
grep -c ERROR logs/app.log
grep -rn DATABASE_URL .

cp -a app backup/app-copy
mv backup/app-copy backup/app-$(date +%F)
ls -la backup

tar -czf app.tar.gz app && tar -tzf app.tar.gz
find . -name "*.js" -newer logs/app.log
du -sh * | sort -h

# Watch a log grow: run this, then in a second terminal append lines to logs/app.log
tail -f logs/app.log

# Clean up — check first, then delete
ls -d ~/lab && rm -rf ~/lab
```

## Real-world example

A support ticket says "uploads failed yesterday afternoon". On the server:

```bash
# 1. Which errors, and when?
grep -n "upload" /var/log/app/error.log | tail -n 20
# → 2026-11-09 15:42:11 ENOSPC: no space left on device

# 2. Which disk is full, and why?
df -h
sudo du -xh /srv --max-depth=2 | sort -h | tail
# → /srv/app/uploads/tmp 41G

# 3. What is in there?
find /srv/app/uploads/tmp -type f -mtime +1 | head
find /srv/app/uploads/tmp -type f -mtime +1 | wc -l
# → 180,000 abandoned chunk files from failed resumable uploads

# 4. Clean safely, then prevent it
find /srv/app/uploads/tmp -type f -mtime +1 -print | head        # check
find /srv/app/uploads/tmp -type f -mtime +1 -delete               # delete
# add a daily cron job / systemd timer doing the same, and a disk usage alert
```

## Common mistakes

- **`rm -rf` with an unchecked path or an empty variable.** Check with `ls` first; in scripts use `"${VAR:?}"`.
- **Forgetting that `cp`/`mv` overwrite** without asking.
- **Unquoted `find -name *.log`** — the shell expands `*.log` before `find` sees it. Write `-name "*.log"`.
- **`cat` on a huge log file** floods the terminal. Use `less`, `head`, `tail` or `grep`.
- **`rsync --delete` with the wrong trailing slash** — mirrors the wrong level and deletes files on the target. Use `--dry-run` first.
- **Editing config without a backup.** `cp -a nginx.conf nginx.conf.bak` takes one second.

## Security lens

<Callout type="security">
`find` and `grep` are the incident responder's best friends — and the attacker's. Use them to find what should not be there before someone else does.
</Callout>

- **Hunt for secrets** before attackers do: `grep -rEn "(password|secret|api[_-]?key|BEGIN [A-Z]+ PRIVATE KEY)" /srv /home 2>/dev/null`. Also check `.env`, backups and `.git` folders accidentally deployed to web roots.
- **Find web shells** among uploads: script files in upload directories (`find /var/www/uploads -name "*.php"`), recently modified files in the web root (`find /var/www -mtime -2 -type f`).
- **World-writable files and directories** are escalation risks: `find / -xdev -perm -0002 -type f 2>/dev/null`.
- **Backups are sensitive data:** `.tar.gz` archives of app folders contain `.env` files and keys. Encrypt them, restrict permissions and never leave them in a web-served directory (`site.com/backup.zip` is a common real finding).
- **Deleting is not secure erasure:** `rm` removes the name; the data may remain on disk. Use encrypted volumes so old data is unreadable.
- **Zip Slip:** extracting archives from untrusted sources can write files outside the target folder through `../` paths. Use up-to-date tools and validate archive contents.

## Interview questions

<QA q="How would you find all files larger than 1 GB on a server?">
Use find with a size filter, staying on one file system: `find / -xdev -type f -size +1G -exec ls -lh {} + 2>/dev/null`. Combine with `du -h --max-depth=1 | sort -h` to see which directories are largest overall.
</QA>

<QA q="What is the difference between scp and rsync?">
Both copy files over SSH. scp copies everything every time. rsync compares source and destination and only transfers changed parts, can resume interrupted transfers, preserves permissions and timestamps, supports a dry run, and can mirror directories with --delete. rsync is preferred for deployments, backups and large directories.
</QA>

<QA q="How do you follow a log file in real time and show only errors?">
`tail -f /path/to/app.log | grep --line-buffered -i error`. tail -f keeps the file open and prints new lines as they are written; grep filters them, and --line-buffered makes grep output each match immediately. For systemd services, `journalctl -u service -f` does the same.
</QA>

<QA q="What does tar -czf do?">
It creates (c) a gzip-compressed (z) archive written to the file (f) named next. For example `tar -czf backup.tar.gz /srv/app` bundles the directory into one compressed file. Use -x to extract, -t to list contents and -C to choose an extraction directory.
</QA>

<QA q="How do you avoid deleting the wrong files with rm -rf?">
Check the exact path or glob with ls first, then reuse it for rm; use -i for interactive confirmation in risky cases; never run it with unchecked variables (use `${VAR:?}` and set -u in scripts); and keep backups or snapshots before bulk deletions on production.
</QA>

## Key terms

<Terms>
  <Term name="Recursive (-r)">Applies an operation to a directory and everything inside it.</Term>
  <Term name="Glob">A wildcard pattern like *.log expanded by the shell.</Term>
  <Term name="tar">Tool that bundles many files into one archive.</Term>
  <Term name="gzip">Compression format, usually combined with tar as .tar.gz.</Term>
  <Term name="rsync">Efficient file synchronisation tool that sends only changes.</Term>
  <Term name="scp">Secure copy of files over SSH.</Term>
  <Term name="tail -f">Follows a file and prints new lines as they are written.</Term>
  <Term name="find">Searches the file tree by name, type, size, time, owner and more.</Term>
  <Term name="grep">Searches text for lines matching a pattern.</Term>
</Terms>
