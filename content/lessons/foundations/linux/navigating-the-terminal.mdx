## At a glance

<Glance>
<What>
<Tr>
<En>

- The **prompt** (`alex@web-1:~$`) tells you **who** you are, **which machine**, and **which folder**.
- A command has three parts: `command -options arguments`, like `ls -la /etc`.
- `pwd` shows where you are, `cd` moves you, `ls` lists what's in a folder.
- `cat`, `less`, `head` and `tail` show what's inside a file.

</En>
<Ur>

- **Prompt** (`alex@web-1:~$`) batata hai aap **kaun** hain, **kaun si machine**, aur **kaun sa folder**.
- Command ke teen hisse hain: `command -options arguments`, jaise `ls -la /etc`.
- `pwd` batata hai aap kahan hain, `cd` le jata hai, `ls` folder ka saman dikhata hai.
- `cat`, `less`, `head` aur `tail` file ke andar ka mawad dikhate hain.

</Ur>
</Tr>
</What>
<Why>
<Tr>
<En>

- Servers usually have **no desktop**, so the terminal is the only way in.
- Checking logs, editing settings, restarting apps, deploying: it all starts here.
- Once you know the moves, you're much faster than with a mouse, and you can turn them into scripts.

</En>
<Ur>

- Servers ke paas aam taur par **desktop nahi hota**, isliye terminal hi wahid raasta hai.
- Logs dekhna, settings badalna, apps restart karna, deploy karna: sab yahin se shuru hota hai.
- Ye chalein aa jayen to aap mouse se kahin tez hote hain, aur inhe scripts bhi bana sakte hain.

</Ur>
</Tr>
</Why>
<When>
<Tr>
<En>

- every time you log in to a server
- looking at logs when the site is down
- running Git, npm, Docker and almost every developer tool

</En>
<Ur>

- har dafa server me login karte waqt
- site band ho to logs dekhte waqt
- Git, npm, Docker aur taqreeban har developer tool chalate waqt

</Ur>
</Tr>
</When>
<How>
<Tr>
<En>

The five habits that make you fast:

- **Tab** completes names.
- **↑** brings back the last command.
- **Ctrl+R** searches old commands.
- **Ctrl+C** stops a command.
- `command --help` or `man command` shows help.

</En>
<Ur>

Paanch aadaten jo aap ko tez banati hain:

- **Tab** naam mukammal karta hai.
- **↑** pichli command wapas lata hai.
- **Ctrl+R** purani commands dhoondta hai.
- **Ctrl+C** command rokta hai.
- `command --help` ya `man command` madad dikhata hai.

</Ur>
</Tr>
</How>
</Glance>

<Tr>

Using a **file explorer** is like walking around a building and pointing at things.

The **terminal** is like **phoning a very fast assistant** standing inside the building. You say "go to the 3rd floor", "tell me what's in this room", "copy that file to the store room", and the assistant does it instantly and reports back.

You have to learn the **words**, but once you do, you're much faster, and you can write your instructions down as a script.

</En>
<Ur>

**File explorer** istemal karna aisa hai jaise building me ghoom kar cheezon ki taraf ishara karna.

**Terminal** aisa hai jaise building ke andar khare ek **bohot tez assistant ko phone karna**. Aap kehte hain "teesri manzil par jao", "batao is kamre me kya hai", "wo file store room me copy karo", aur assistant foran kar ke batata hai.

Aap ko **alfaz** seekhne parte hain, lekin ek dafa aa jayen to aap kahin tez hote hain, aur apni hidayat script ki shakal me likh bhi sakte hain.

## Reading the prompt

```text
alex@web-1:~/projects$ ls -la src
└┬─┘ └─┬─┘ └────┬────┘ │ └┬┘ └┬┘ └┬┘
 │     │        │      │  │   │   └ argument (what to work on)
 │     │        │      │  │   └ options (how)
 │     │        │      │  └ command
 │     │        │      └ $ = normal user   (# = root — be careful!)
 │     │        └ current folder (~ = home)
 │     └ machine name (host name)
 └ your user name
```

<Tr>
<En>Before you run anything important, **read the prompt**: are you on the right machine, as the right user, in the right folder? A `#` at the end means you're **root**, the all-powerful admin, so be extra careful.</En>
<Ur>Koi ahem cheez chalane se pehle **prompt parhein**: kya aap sahi machine par, sahi user ke taur par, sahi folder me hain? Aakhir me `#` ka matlab hai aap **root** hain, sab se taqatwar admin, isliye khaas ehtiyat karein.</Ur>
</Tr>

## Words you'll see

<Tr>
<En>

| Word | What it means | Example |
| --- | --- | --- |
| **Option / flag** | Changes **how** a command works; starts with `-` or `--` | `-l`, `--all` |
| **Argument** | **What** the command should work on | `/etc` |
| **Working directory** | The folder you're "in" right now | `/home/alex` |
| **Absolute path** | A full address from `/` | `/var/log/syslog` |
| **Relative path** | An address from where you are now | `logs/app.log` |
| **Home** | Your personal folder, written `~` | `/home/alex` |

</En>
<Ur>

| Lafz | Matlab | Misaal |
| --- | --- | --- |
| **Option / flag** | Command **kaise** kaam kare ye badalta hai; `-` ya `--` se shuru | `-l`, `--all` |
| **Argument** | Command **kis cheez** par kaam kare | `/etc` |
| **Working directory** | Wo folder jis me aap is waqt "hain" | `/home/alex` |
| **Absolute path** | `/` se poora pata | `/var/log/syslog` |
| **Relative path** | Jahan aap abhi hain wahan se pata | `logs/app.log` |
| **Home** | Aap ka zaati folder, `~` likha jata hai | `/home/alex` |

</Ur>
</Tr>

## Learn it step by step

<Walkthrough>

<Step title="How a command is built">

<Tr>
<En>

A command line is: the **command**, then **options** that change how it behaves, then **arguments** it works on, separated by spaces.

- Short options use **one** dash and can be joined: `-l -a` = `-la`.
- Long options use **two** dashes and full words: `--all`.

</En>
<Ur>

Command line ye hai: **command**, phir **options** jo us ka andaz badalte hain, phir **arguments** jin par wo kaam karti hai, spaces se alag.

- Chhote options **ek** dash ke saath aur jore ja sakte hain: `-l -a` = `-la`.
- Lambe options **do** dash aur poore alfaz ke saath: `--all`.

</Ur>
</Tr>

```bash
mkdir -p demo && touch demo/a.txt demo/.hidden
ls demo
ls -a demo
ls --all demo
```

```text output
a.txt
.
..
.hidden
a.txt
.
..
.hidden
a.txt
```

<Happened>
<Tr>
<En>

- `ls demo` shows only `a.txt`.
- `ls -a demo` and `ls --all demo` mean the **same** thing: "show hidden things too". Now you also see `.hidden`, plus `.` (this folder) and `..` (the folder above).

</En>
<Ur>

- `ls demo` sirf `a.txt` dikhata hai.
- `ls -a demo` aur `ls --all demo` ka matlab **ek hi** hai: "chhupi cheezen bhi dikhao". Ab `.hidden` bhi nazar aata hai, saath `.` (yahi folder) aur `..` (upar wala folder).

</Ur>
</Tr>
</Happened>

</Step>

<Step title="pwd: where am I?">

<Tr>
<En>

`pwd` = **P**rint **W**orking **D**irectory. It shows the full address of the folder you're in. Use it whenever you're unsure, and **always before deleting anything**.

</En>
<Ur>

`pwd` = **P**rint **W**orking **D**irectory. Ye us folder ka poora pata dikhata hai jis me aap hain. Jab bhi shak ho istemal karein, aur **kuch bhi delete karne se pehle hamesha**.

</Ur>
</Tr>

```bash
cd /etc && pwd
cd /var/log && pwd
```

```text output
/etc
/var/log
```

</Step>

<Step title="cd: moving around">

<Tr>
<En>

`cd` = **C**hange **D**irectory. The moves you'll use every day:

- `cd /full/path`: go there
- `cd ..`: go **up** one folder
- `cd` (alone) or `cd ~`: go **home**
- `cd -`: go **back** to the previous folder

</En>
<Ur>

`cd` = **C**hange **D**irectory. Roz istemal hone wali chalein:

- `cd /poora/path`: wahan jao
- `cd ..`: ek folder **upar** jao
- `cd` (akela) ya `cd ~`: **ghar (home)** jao
- `cd -`: pichle folder par **wapas** jao

</Ur>
</Tr>

```bash
cd /usr/share
echo "1: $PWD"
cd ..
echo "2: $PWD (went up one level)"
cd -  > /dev/null
echo "3: $PWD (cd - went back)"
cd
echo "4: home → $([[ $PWD == "$HOME" ]] && echo yes)"
```

```text output
1: /usr/share
2: /usr (went up one level)
3: /usr/share (cd - went back)
4: home → yes
```

<Happened>
<Tr>
<En>

- `$PWD` always holds the current folder.
- `cd ..` took us from `/usr/share` up to `/usr`.
- `cd -` jumped back to `/usr/share`.
- `cd` on its own took us home.

</En>
<Ur>

- `$PWD` me hamesha mojooda folder hota hai.
- `cd ..` hamein `/usr/share` se upar `/usr` le gaya.
- `cd -` wapas `/usr/share` le gaya.
- Akela `cd` hamein ghar le gaya.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Full addresses vs directions from here">

<Tr>
<En>

- An **absolute** path starts with `/` and works from **anywhere**, like a **full postal address**.
- A **relative** path starts from where you are now, like "**two doors down, turn left**". It only works if you know where you're standing.

Use relative paths while typing; use absolute paths in **scripts** and scheduled jobs.

</En>
<Ur>

- **Absolute** path `/` se shuru hota hai aur **kahin se bhi** kaam karta hai, jaise **poora daak ka pata**.
- **Relative** path wahan se shuru hota hai jahan aap abhi hain, jaise "**do darwaze aage, baayen mur jao**". Ye tabhi kaam karta hai jab pata ho aap kahan khare hain.

Likhte waqt relative paths istemal karein; **scripts** aur scheduled jobs me absolute paths.

</Ur>
</Tr>

```bash
mkdir -p ~/shop/src/components ~/shop/config
cd ~/shop/src/components
echo "here:                  $(pwd | sed "s|$HOME|~|")"
echo "../../config resolves: $(cd ../../config && pwd | sed "s|$HOME|~|")"
echo "./ is the same folder: $(cd . && pwd | sed "s|$HOME|~|")"
```

```text output
here:                  ~/shop/src/components
../../config resolves: ~/shop/config
./ is the same folder: ~/shop/src/components
```

<Happened>
<Tr>
<En>

- We're in `~/shop/src/components`.
- `../../config` = "up one (`src`), up again (`shop`), then into `config`".
- `.` means "this same folder".

</En>
<Ur>

- Hum `~/shop/src/components` me hain.
- `../../config` = "ek upar (`src`), phir upar (`shop`), phir `config` me".
- `.` ka matlab "yahi folder".

</Ur>
</Tr>
</Happened>

</Step>

<Step title="ls: what's here?">

<Tr>
<En>

`ls` lists a folder. Its most useful options:

- `-l` long details (permissions, size, date)
- `-a` show hidden files too
- `-h` human sizes (`2.0K` instead of `2048`)
- `-t` newest first
- `-S` biggest first
- `-r` reverse the order

Combine them: `ls -lah`, `ls -lt`.

</En>
<Ur>

`ls` folder ki list dikhata hai. Is ke sab se kaam ke options:

- `-l` lambi tafseel (permissions, size, tareekh)
- `-a` chhupi files bhi
- `-h` insani size (`2048` ki jagah `2.0K`)
- `-t` naya pehle
- `-S` bara pehle
- `-r` tarteeb ulti

Inhe jorein: `ls -lah`, `ls -lt`.

</Ur>
</Tr>

```bash
mkdir -p lsdemo && cd lsdemo
printf '%.0s.' {1..2048} > big.log
echo hi > small.txt
touch -d '2026-01-01' old.txt
touch -d '2026-11-09' big.log
touch -d '2026-11-10' small.txt
ls -l --time-style=+%F | awk 'NR>1 {print $1, $5, $6, $7}'
echo "--- newest first:"; ls -t
echo "--- biggest first:"; ls -S
```

```text output
-rw-r--r-- 2048 2026-11-09 big.log
-rw-r--r-- 0 2026-01-01 old.txt
-rw-r--r-- 3 2026-11-10 small.txt
--- newest first:
small.txt
big.log
old.txt
--- biggest first:
big.log
small.txt
old.txt
```

<Happened>
<Tr>
<En>

- We made three files with different sizes, and `touch -d` gave them fixed dates so the result is predictable.
- `ls -l` shows: permissions, size in bytes, date, name.
- `ls -t` put the newest (`small.txt`, 10 Nov) first; `ls -S` put the biggest (`big.log`, 2048 bytes) first.

</En>
<Ur>

- Hum ne alag size ki teen files banayin, aur `touch -d` ne unhe tay tareekhen den taa ke nateeja pehle se maloom ho.
- `ls -l` dikhata hai: permissions, bytes me size, tareekh, naam.
- `ls -t` ne sab se nayi (`small.txt`, 10 Nov) pehle rakhi; `ls -S` ne sab se bari (`big.log`, 2048 bytes) pehle.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Tab completion and wildcards">

<Tr>
<En>

Press **Tab** after a few letters and the shell finishes the name for you. Press it twice to see all choices. Tab only completes names that **really exist**, so it also prevents typos.

**Wildcards** match many names at once:

- `*` = any characters: `*.log` = every file ending in `.log`
- `?` = exactly one character: `file?.txt` matches `file1.txt`, `fileA.txt`

</En>
<Ur>

Chand letters ke baad **Tab** dabayen aur shell aap ke liye naam mukammal kar deta hai. Do dafa dabayen to saare ikhtiyar dikhte hain. Tab sirf wo naam mukammal karta hai jo **waqai mojood** hain, isliye typos se bhi bachata hai.

**Wildcards** ek saath kai naam pakarte hain:

- `*` = koi bhi characters: `*.log` = har file jo `.log` par khatam ho
- `?` = bilkul ek character: `file?.txt` `file1.txt`, `fileA.txt` se milta hai

</Ur>
</Tr>

```bash
mkdir -p wild && cd wild && touch app.log error.log notes.txt file1.txt file2.txt
echo "*.log    → $(echo *.log)"
echo "file?.txt → $(echo file?.txt)"
echo "*        → $(echo *)"
```

```text output
*.log    → app.log error.log
file?.txt → file1.txt file2.txt
*        → app.log error.log file1.txt file2.txt notes.txt
```

</Step>

<Step title="Reading files: cat, less, head, tail">

<Tr>
<En>

- `cat file`: print **all** of it (good for short files).
- `less file`: scroll through a long file. Space = next page, `/word` = search, `G` = jump to end, **`q` = quit**.
- `head -n 5 file`: the **first** 5 lines.
- `tail -n 20 file`: the **last** 20 lines.
- `tail -f file`: keep showing **new** lines as they're written (Ctrl+C to stop).

</En>
<Ur>

- `cat file`: **sab** print karo (chhoti files ke liye achha).
- `less file`: lambi file me scroll karo. Space = agla page, `/lafz` = dhoondo, `G` = aakhir par jao, **`q` = bahar niklo**.
- `head -n 5 file`: **pehli** 5 lines.
- `tail -n 20 file`: **aakhri** 20 lines.
- `tail -f file`: **nayi** lines likhte hi dikhate raho (rokne ke liye Ctrl+C).

</Ur>
</Tr>

```bash
seq 1 100 | sed 's/^/log line /' > app.log
echo "--- head -n 3:"; head -n 3 app.log
echo "--- tail -n 2:"; tail -n 2 app.log
echo "--- lines containing '5' at the end, counted: $(grep -c '5$' app.log)"
```

```text output
--- head -n 3:
log line 1
log line 2
log line 3
--- tail -n 2:
log line 99
log line 100
--- lines containing '5' at the end, counted: 10
```

<Happened>
<Tr>
<En>

- `seq 1 100` made 100 lines: "log line 1" … "log line 100".
- `head -n 3` showed the first three; `tail -n 2` the last two.
- `grep -c '5$'` counted lines **ending** in 5 (5, 15, 25 … 95): ten of them.

</En>
<Ur>

- `seq 1 100` ne 100 lines banayin: "log line 1" … "log line 100".
- `head -n 3` ne pehli teen dikhayin; `tail -n 2` ne aakhri do.
- `grep -c '5$'` ne wo lines ginin jo 5 par **khatam** hoti hain (5, 15, 25 … 95): das.

</Ur>
</Tr>
</Happened>

<Tr>
<En>Watching a log **live** while you repeat a problem is one of the most useful habits in operations:</En>
<Ur>Masla dobara karte waqt log ko **live** dekhna operations ki sab se kaam ki aadaton me se ek hai:</Ur>
</Tr>

```text
$ sudo tail -f /var/log/nginx/error.log
2026/11/10 14:31:02 [error] 812#812: *41 connect() failed (111: Connection refused) while connecting to upstream ...
                ↑ new lines appear here as they happen — press Ctrl+C to stop
```

</Step>

<Step title="History and keyboard shortcuts">

<Tr>
<En>

The shell **remembers** your commands. `history` lists them, and `!!` repeats the last one: `sudo !!` = "the last command again, but with sudo".

</En>
<Ur>

Shell aap ki commands **yaad** rakhta hai. `history` unki list dikhata hai, aur `!!` pichli command dohrata hai: `sudo !!` = "pichli command dobara, lekin sudo ke saath".

</Ur>
</Tr>

<Tr>
<En>

| Keys | What it does |
| --- | --- |
| **↑ / ↓** | Previous / next command |
| **Ctrl+R** | Search history (type part of a command; Ctrl+R again for older ones) |
| **Tab** | Complete names |
| **Ctrl+C** | Stop the running command |
| **Ctrl+L** | Clear the screen |
| **Ctrl+A / Ctrl+E** | Jump to the start / end of the line |
| **Ctrl+U / Ctrl+K** | Delete to the start / end of the line |
| **Ctrl+W** | Delete the previous word |
| **Ctrl+D** | Exit the shell (log out) |

</En>
<Ur>

| Keys | Kya karti hain |
| --- | --- |
| **↑ / ↓** | Pichli / agli command |
| **Ctrl+R** | History me dhoondo (command ka hissa likhein; purani ke liye dobara Ctrl+R) |
| **Tab** | Naam mukammal karo |
| **Ctrl+C** | Chalti command roko |
| **Ctrl+L** | Screen saaf karo |
| **Ctrl+A / Ctrl+E** | Line ke shuru / aakhir par jao |
| **Ctrl+U / Ctrl+K** | Shuru / aakhir tak mitao |
| **Ctrl+W** | Pichla lafz mitao |
| **Ctrl+D** | Shell se bahar (log out) |

</Ur>
</Tr>

</Step>

<Step title="Getting help">

<Tr>
<En>

Nobody remembers every option. Knowing **how to look things up** matters more than memorising:

- `command --help`: a quick summary
- `man command`: the full manual (`q` to quit, `/word` to search)
- `type command`: what a command really is

</En>
<Ur>

Koi bhi har option yaad nahi rakhta. **Cheezen dhoondne ka tareeqa** jaanna ratne se zyada ahem hai:

- `command --help`: mukhtasar khulasa
- `man command`: poora manual (`q` se bahar, `/lafz` se dhoondo)
- `type command`: command asal me kya hai

</Ur>
</Tr>

```bash
type cd | sed 's/ is a shell builtin/: built into the shell itself/'
type ls | grep -q 'aliased\|/usr/bin/ls\|/bin/ls' && echo "ls: a separate program (or an alias for it)"
ls --help | head -1
```

```text output
cd: built into the shell itself
ls: a separate program (or an alias for it)
Usage: ls [OPTION]... [FILE]...
```

<Happened>
<Tr>
<En>

- `cd` is built **into** the shell; `ls` is a separate program on disk.
- In the help line, `[ ]` means **optional** and `...` means "**can be repeated**". So `ls` works alone, or with any number of options and files.

</En>
<Ur>

- `cd` shell ke **andar** bana hai; `ls` disk par alag program hai.
- Help line me `[ ]` ka matlab **ikhtiyari** aur `...` ka matlab "**dohraya ja sakta hai**". Yani `ls` akela bhi chalta hai, ya jitne chahein options aur files ke saath.

</Ur>
</Tr>
</Happened>

</Step>

<Step title="Be careful when the prompt shows #">

<Tr>
<En>

A prompt ending in `#` means you're **root**. As root, one typo can delete the whole system, and the terminal has **no recycle bin**.

- Work as a normal user and put `sudo` in front of single commands that need it.
- Before any `rm -r`, run `pwd` and `ls` first.

</En>
<Ur>

`#` par khatam hone wala prompt matlab aap **root** hain. Root ke taur par ek typo poora system mita sakta hai, aur terminal me **recycle bin nahi hota**.

- Aam user ke taur par kaam karein aur sirf zaroori commands se pehle `sudo` lagayen.
- Kisi bhi `rm -r` se pehle `pwd` aur `ls` chalayen.

</Ur>
</Tr>

</Step>

</Walkthrough>

## Common mistakes

<Compare>
<Bad title="Not reading the prompt">

<Tr>
<En>Running a command on **production** instead of staging, or as root instead of your own user.</En>
<Ur>Staging ki jagah **production** par command chala dena, ya apne user ki jagah root ke taur par.</Ur>
</Tr>

</Bad>
<Good title="Check, then run">

<Tr>
<En>Glance at user, machine and folder in the prompt before anything risky. Run `pwd` before deleting.</En>
<Ur>Koi khatarnak kaam karne se pehle prompt me user, machine aur folder dekh lein. Delete se pehle `pwd` chalayen.</Ur>
</Tr>

</Good>
</Compare>

<Compare>
<Bad title="; in deploy commands">

```text
git pull ; npm run build ; pm2 restart app
```

<Tr>
<En>If the build fails, the app still restarts with broken code.</En>
<Ur>Agar build fail ho jaye, app phir bhi toote code ke saath restart ho jati hai.</Ur>
</Tr>

</Bad>
<Good title="&& stops at the first failure">

```text
git pull && npm run build && pm2 restart app
```

<Tr>
<En>Each step runs **only if** the one before it worked.</En>
<Ur>Har qadam **sirf tab** chalta hai jab pichla kamyab ho.</Ur>
</Tr>

</Good>
</Compare>

<Compare>
<Bad title="Spaces without quotes">

```text
cd My Documents
bash: cd: too many arguments
```

</Bad>
<Good title="Quote names with spaces">

```text
cd "My Documents"
```

</Good>
</Compare>

## Try it yourself

<Challenge title="A guided tour">

<DeepDive title="Real world: 502 errors at 2 a.m.">

The API returns 502 errors. An engineer who knows the terminal:

```bash
ssh deploy@api-01                               # check the prompt: right server?
systemctl status app --no-pager                 # is the service running?
journalctl -u app -n 50 --no-pager              # last 50 log lines
# → "Error: connect ECONNREFUSED 127.0.0.1:5432"
systemctl status postgresql --no-pager          # database stopped?
df -h /var                                      # → 100% — disk full, Postgres crashed
sudo du -xh /var --max-depth=2 | sort -h | tail # → /var/log/app grew to 30G
```

Six commands, five minutes, root cause found. The same investigation through a cloud console and an SFTP client would take far longer, and on many servers isn't possible at all.

</DeepDive>

<DeepDive title="Security lens">

Your shell history and your prompt are both security tools, and both can leak secrets.

- **History stores secrets:** `mysql -p'Secret123'`, `export AWS_SECRET_ACCESS_KEY=...` or `curl -H "Authorization: Bearer ..."` end up in `~/.bash_history`. Attackers read it first. Prefer prompts or protected files. In bash, a command starting with a **space** isn't saved when `HISTCONTROL=ignorespace` (Ubuntu's default `ignoreboth` includes it).
- **History is also evidence:** in incident response, `~/.bash_history` of a hacked account often shows exactly what the attacker ran (unless they cleared it, which is itself a signal).
- **Command-line arguments are visible** to other users through `ps`. Never pass passwords as arguments.
- **Paste-jacking:** web pages can show one command and copy another to your clipboard. Paste into an editor first if in doubt.
- **Know who you are:** `id` and a `#` prompt tell you that you're root.

</DeepDive>

<DeepDive title="Interview questions">

<QA q="What is the difference between a terminal and a shell?">
The terminal (emulator) is the program that displays text and captures keyboard input. The shell is the command interpreter running inside it (bash, zsh, sh), which parses what you type, expands variables and wildcards, and starts programs. You can run different shells in the same terminal.
</QA>

<QA q="What is the difference between && and ; when chaining commands?">
With a semicolon, the next command runs regardless of whether the previous one succeeded. With &&, the next command runs only if the previous one exited with status 0. Deployment and build steps should use && so they stop at the first failure.
</QA>

<QA q="Why do single and double quotes behave differently in bash?">
Inside double quotes, the shell still expands variables, command substitution and escapes, but keeps spaces together as one argument. Inside single quotes, nothing is expanded; the text is passed literally. Use double quotes around variables in scripts to avoid word splitting, and single quotes for literal strings.
</QA>

<QA q="A command says 'command not found' but you know it is installed. What do you check?">
Check whether its directory is in $PATH (echo $PATH, and which or command -v to locate it), whether you are in the right shell or environment (for example nvm, a virtualenv or a different user with sudo), and whether the shell needs reloading after installation (hash -r or a new shell).
</QA>

<QA q="How can shell history become a security problem?">
Commands containing passwords, tokens or keys are saved to ~/.bash_history in plain text, where attackers or other administrators can read them. Avoid putting secrets on the command line, use prompts or protected files, configure HISTCONTROL/HISTIGNORE, and treat history files as sensitive.
</QA>

</DeepDive>
