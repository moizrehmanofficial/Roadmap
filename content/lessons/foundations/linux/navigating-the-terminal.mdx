<Callout type="tip" title="In one minute">
A **terminal** is the window; the **shell** (bash, zsh) is the program inside it that reads what you type and runs it. Every command has the shape `command -options arguments`. Move with `pwd`, `ls`, `cd`; get help with `--help`, `man` and `tldr`; save keystrokes with **Tab completion**, **↑ history**, **Ctrl+R** search and `!!`. On servers you will often have nothing but a shell over SSH, so these habits pay off every day.
</Callout>

## What is it?

| Term | Meaning | Examples |
| --- | --- | --- |
| **Terminal (emulator)** | The window that shows text and sends your keystrokes | Windows Terminal, VS Code terminal, iTerm2, GNOME Terminal |
| **Shell** | The program that interprets commands | `bash` (default on most servers), `zsh` (macOS default), `sh`/`dash`, `fish`; PowerShell on Windows |
| **Prompt** | The text that shows the shell is waiting | `moiz@server:~/app$` |
| **Command** | A program, a shell builtin, an alias or a function | `ls` (program), `cd` (builtin) |
| **CLI** | Command-line interface: interacting by typing commands | `git`, `docker`, `aws`, `kubectl` |

### Reading the prompt

```text
moiz@web-01:/var/log$
 │     │       │     └── $ = normal user   (# = root — be careful)
 │     │       └──────── current directory (~ means your home)
 │     └──────────────── hostname — which machine you are on
 └────────────────────── your username
```

Always glance at the prompt before running something destructive: **which machine, which user, which folder**.

### Anatomy of a command

```text
ls  -l -a  --human-readable  /var/log
│   │      │                 └── argument (what to act on)
│   │      └──────────────────── long option (double dash, full word)
│   └─────────────────────────── short options (single dash, one letter; can be combined: -la)
└─────────────────────────────── the command
```

## Why does it matter?

- **Servers have no GUI.** When you SSH into an EC2 instance or a Kubernetes node, the shell is all you get.
- **Every DevOps tool is a CLI:** `git`, `docker`, `kubectl`, `terraform`, `aws`, `gcloud`, `az`, `helm`.
- **Automation:** anything you can type, you can put in a script or a CI pipeline. The GUI cannot be automated; the shell can.
- **Speed:** with history, completion and pipes, tasks that take 20 clicks take one line.
- **Security work** — log analysis, incident response, pentesting — is overwhelmingly terminal work.

## When and where do you use it?

- Every deployment, every SSH session, every Docker or Kubernetes command.
- GitHub Actions `run:` steps — they execute in bash.
- Reading logs during an outage.
- Running Kali tools, Nmap and Burp's CLI helpers in security work.
- On Windows: in **WSL** for Linux commands, or PowerShell for Windows ones (note that PowerShell commands differ).

## How does it work?

### What the shell does with a line you type

```text
you type:   ls -l $HOME/*.txt | grep notes > out.txt
  1. split into words and operators ( |  > )
  2. expand:  $HOME → /home/moiz,   *.txt → a.txt notes.txt
  3. set up redirection and pipes (> out.txt, | grep)
  4. find each command: alias? function? builtin? else search $PATH
  5. start the program(s), wait, show the exit code in $?
```

Steps 2 and 4 explain many surprises: a `*` is expanded by the **shell**, not by `ls`; and a command "not found" means it is not in any directory listed in `$PATH`.

### Moving around

| Command | Does |
| --- | --- |
| `pwd` | Print working directory — where am I? |
| `ls` | List the current directory |
| `ls -la` | Long format, including hidden files |
| `ls -lh /var/log` | Long format with human sizes, of a given path |
| `ls -lt` | Sort by modification time (newest first) |
| `cd /etc/nginx` | Go to an absolute path |
| `cd logs` | Go into a relative path |
| `cd ..` | Up one level |
| `cd` or `cd ~` | Go home |
| `cd -` | Go back to the previous directory |
| `tree -L 2` | Show a directory tree two levels deep (install `tree`) |

### Getting help

| Way | Example | Good for |
| --- | --- | --- |
| `--help` | `ls --help` | Quick option list |
| `man` | `man ls` (q to quit, / to search) | The full manual |
| `tldr` | `tldr tar` | Practical examples (install `tldr`) |
| `type` | `type cd` | Is it a builtin, alias or file? |
| `which` | `which python3` | Where does a command live? |
| `apropos` | `apropos copy` | Find commands by keyword |

### History and keyboard shortcuts

| Keys / command | Action |
| --- | --- |
| **Tab** | Complete a command, path or filename; **Tab Tab** shows options |
| **↑ / ↓** | Previous / next command |
| **Ctrl+R** | Search history backwards — type part of an old command |
| `history` | Show numbered history |
| `!!` | Repeat the last command (`sudo !!` = last command with sudo) |
| `!$` | The last argument of the previous command |
| **Ctrl+C** | Cancel the running command |
| **Ctrl+D** | End of input; exits the shell |
| **Ctrl+L** or `clear` | Clear the screen |
| **Ctrl+A / Ctrl+E** | Jump to start / end of the line |
| **Ctrl+U / Ctrl+K** | Delete to start / end of the line |
| **Ctrl+W** | Delete the previous word |
| **Ctrl+Z**, then `bg` / `fg` | Pause a job, resume it in background / foreground |

### Quoting — the most common beginner bug

| You type | The shell passes | Why |
| --- | --- | --- |
| `echo $HOME` | `/home/moiz` | Variables expand |
| `echo "$HOME"` | `/home/moiz` | Double quotes: variables still expand, spaces kept |
| `echo '$HOME'` | `$HOME` | Single quotes: nothing expands |
| `cd My Files` | two arguments | Space separates arguments → error |
| `cd "My Files"` or `cd My\ Files` | one argument | Quote or escape spaces |

Rule: **put double quotes around variables and paths** unless you have a reason not to.

### Running multiple commands

| Syntax | Meaning |
| --- | --- |
| `a ; b` | Run a, then b, regardless |
| `a && b` | Run b only if a succeeded (exit code 0) |
| `a \|\| b` | Run b only if a failed |
| `a &` | Run a in the background |

`npm ci && npm run build && npm start` stops at the first failure — exactly what you want in deploy steps.

### Aliases and your shell config

Shortcuts go in `~/.bashrc` (bash) or `~/.zshrc` (zsh):

```bash
alias ll='ls -lah'
alias gs='git status'
alias k='kubectl'
```

Reload with `source ~/.bashrc`.

## Hands-on

Do this in WSL or any Linux shell, in order:

```bash
whoami && hostname && pwd
ls -la ~
cd /var/log && pwd
ls -lht | head -n 5          # five most recently changed logs
cd -                          # back to where you were
cd /etc/ss<Tab>               # completes to /etc/ssh/
cd                            # home

# Help, three ways
ls --help | head -n 15
man ls                        # press / then type "sort", Enter, then q to quit
type cd ls ll

# History
history | tail -n 5
# press Ctrl+R and type "var" — find the cd /var/log command, press Enter

# Quoting
mkdir -p "My Files" && cd "My Files" && pwd && cd ..
echo "home is $HOME" ; echo 'home is $HOME'

# Conditional chaining and exit codes
ls /nope && echo "found"     # nothing echoed
echo "exit code was $?"      # 2 = error
ls /tmp && echo "found"

# Make an alias permanent
echo "alias ll='ls -lah'" >> ~/.bashrc && source ~/.bashrc && ll
```

### On Windows: PowerShell vs Linux shell

You will switch between them, so know the mapping:

| Task | bash (Linux/WSL) | PowerShell |
| --- | --- | --- |
| Where am I | `pwd` | `pwd` / `Get-Location` |
| List | `ls -la` | `ls` / `Get-ChildItem -Force` |
| Show a file | `cat file` | `cat file` / `Get-Content file` |
| Delete folder | `rm -rf dir` | `Remove-Item -Recurse -Force dir` |
| Env var | `echo $HOME` | `echo $env:USERPROFILE` |
| Find text | `grep -r "x" .` | `Select-String -Path * -Pattern "x"` |

## Real-world example

It is 2 a.m. and the API returns 502 errors. An engineer who knows the terminal:

```bash
ssh deploy@api-01                               # check the prompt: right server?
systemctl status app --no-pager                 # is the service running?
journalctl -u app -n 50 --no-pager              # last 50 log lines
# → "Error: connect ECONNREFUSED 127.0.0.1:5432"
systemctl status postgresql --no-pager          # database stopped?
df -h /var                                      # → 100% — disk full, Postgres crashed
sudo du -xh /var --max-depth=2 | sort -h | tail # → /var/log/app grew to 30G
```

Six commands, five minutes, root cause found. The same investigation through a cloud console and SFTP client would take far longer — and on many servers is simply not possible.

## Common mistakes

- **Not checking the prompt** and running a command on production instead of staging, or as root instead of your user.
- **Typing paths instead of using Tab** — slow and error-prone.
- **Spaces in filenames without quotes**, especially in scripts.
- **Copy-pasting multi-line commands from the web** without reading them; a hidden newline can run a command before you meant to.
- **Pressing Ctrl+S** in some terminals freezes output; **Ctrl+Q** unfreezes it.
- **Using `;` instead of `&&`** in deploy commands, so later steps run even after a failure.

## Security lens

<Callout type="security">
Your shell history and your prompt are both security tools — and both can leak secrets.
</Callout>

- **History stores secrets:** `mysql -p'Secret123'`, `export AWS_SECRET_ACCESS_KEY=...` or `curl -H "Authorization: Bearer ..."` end up in `~/.bash_history`. Attackers read it first. Prefer prompts, files with tight permissions or environment files; in bash, a command starting with a **space** is not saved when `HISTCONTROL=ignorespace` (Ubuntu default is `ignoreboth`, which includes it).
- **History is also evidence:** in incident response, `~/.bash_history` of compromised accounts often shows exactly what an attacker ran (unless they cleared it — which is itself a signal).
- **Command-line arguments are visible** to other users through `ps`. Never pass passwords as arguments.
- **Paste-jacking:** web pages can show one command and put another on your clipboard. Paste into an editor first if in doubt.
- **Know who you are:** `id` and a `#` prompt tell you that you are root. Use a normal account and `sudo` for individual commands.

## Interview questions

<QA q="What is the difference between a terminal and a shell?">
The terminal (emulator) is the program that displays text and captures keyboard input. The shell is the command interpreter running inside it — bash, zsh, sh — which parses what you type, expands variables and wildcards, and starts programs. You can run different shells in the same terminal.
</QA>

<QA q="What is the difference between && and ; when chaining commands?">
With a semicolon, the next command runs regardless of whether the previous one succeeded. With &&, the next command runs only if the previous one exited with status 0. Deployment and build steps should use && so they stop at the first failure.
</QA>

<QA q="Why do single and double quotes behave differently in bash?">
Inside double quotes, the shell still expands variables, command substitution and escapes, but keeps spaces together as one argument. Inside single quotes, nothing is expanded; the text is passed literally. Use double quotes around variables in scripts to avoid word splitting, and single quotes for literal strings.
</QA>

<QA q="A command says 'command not found' but you know it is installed. What do you check?">
Check whether its directory is in $PATH (echo $PATH, and which or command -v to locate it), whether you are in the right shell or environment (for example nvm, a virtualenv or a different user with sudo), and whether the shell needs reloading after installation (hash -r or a new shell).
</QA>

<QA q="How can shell history become a security problem?">
Commands containing passwords, tokens or keys are saved to ~/.bash_history in plain text, where attackers or other administrators can read them. Avoid putting secrets on the command line, use prompts or protected files, configure HISTCONTROL/HISTIGNORE, and treat history files as sensitive.
</QA>
